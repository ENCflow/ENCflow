# test/slide — 瞬時流動化(f_release)と斜面安定判定(f_slide)の疎通と保存則

[English](en/README.md)

地滑り型の土砂流動の 2 つの発生機構と、流動化のときの間隙水の扱いの検定です
(developer.md §28.1、§28.9、§28.17、§28.19)。

1. **瞬時流動化 f_release**(`param.txt`): 崩壊深分布 `fn_dbinit` を与え、
   指定時刻 `db_reltime` に一斉に流動化する(地滑り型の初期条件)。
   転換は hs += (1 − λ)D、z −= D、sd −= D で固体台帳が構造的に閉じ、
   間隙水 λ·relsat·D が地表水になる。
2. **斜面安定判定 f_slide**(`param_fs.txt`、`param_fs2.txt`): 無限長斜面の
   安全率 Fs = (c′ + (γt sd − γw hw) cos²θ tanφs)/(γt sd sinθ cosθ) を
   セルごとに評価し、Green-Ampt 浸透で間隙水圧が上がって Fs < 1 に
   なったセルを全層流動化する(sd = 0 = 岩盤露出)。`f_slide = 2` は
   診断のみ(Fs を出力するが流動化しない危険度マップ)。
3. **保持水の授受 f_dbwet = 3 と初期地下水 gw_sat0**(`param_wet.txt`): 地下水計算と併用した
   瞬時流動化で、土と一緒に動く保持水 w_r = λ − sy0 を授受する。飽和した土層(gw_sat0 = 1)が
   流動化すると、保持水 w_r·D と地下貯留から出る sy0·D を合わせた λ·D の水が出て、濃度 C* の
   混合体になる。水の総量は Σh + Σhg + w_r·Σ(z − z0) の形で保存される。
4. **斜面安定判定の選択子**(`make_fs.py` が書く `p_fs_*.txt`): 浸透力を全水頭の勾配で入れる安全率
   `f_slide_seep`、判定・流動化する深さの上限 `slide_dmax`、間隙水圧で起きる崩壊に限る `f_slide_wet`、
   濃い混合体が載るセルを判定しない `f_slide_noflow`(2 は、載っている土砂が薄いセルを判定する)。
   一様な勾配の平面の斜面で、安全率の出力を式の値と比べる。

reference 比較ではなく `Check_slide.py` の自己検定(保存則・水収支・
活性・危険度出力の整合)で合否を決めます。

## 構成

共通: slope_break 地形(tanθ = 0.4 の斜面 → x = 30 m から平坦)、
60 m × 20 m(Δx = 1 m)、クーロン + マニング合成抵抗、低速凝集で停止。

構成 5〜8 の地形は、勾配が一様な平面 z = 30 − 0.30 x − 0.25 y(40 m × 30 m、Δx = 1 m)です。最急勾配は
tanθ = 0.3905 で、向きは格子の 8 方向のどれとも合いません。y の向きにも傾くので、MPI の帯の境界を
またいで近傍を読みます。地下水計算は Green-Ampt(浸透能はほぼ 0)で、層1の初期飽和度 `gw_sat0` が
飽和厚 hw = gw_sat0·sd を決めます。地形の更新は 1 秒ごとで、判定だけのケースは 1 回目の更新の安全率
`Fs0001`(bil = 単精度の 2 進)を読みます。平面の地形と平面の土層厚では全水頭 H = (z − sd) + hw も平面
なので、その最急降下勾配 J が解析的に決まり、安全率を式の値と直接比べられます。

- **構成 5**(`f_slide_seep`)。Fs = [c′ + (γt d − γw hw) cos²θ tanφs] / [cos²θ {(γt d − γw hw) tanθ + γw hw J}]。
  - `_u0`・`_u1`: 土層厚が一様(1 m)、飽和度 0.6。J = tanθ なので、0 と 1 が同じ値(従来の式)になる。
  - `_g0`・`_g1`: 土層厚が下流へ厚くなる平面(1 + 0.08 x + 0.06 y m)、飽和度 0.5、c′ = 2 kPa。
    J = 0.4405 > tanθ で、1 は従来の式より 3 % 小さい。
  - `_l0`・`_l1`: 土層厚 1 m・飽和。下流側のおよそ 1/3 を静水の湖(水位 19 m)にする。湖の下は J = 0 で、
    1 は Fs = tanφs/tanθ = 1.194、0 はその (γt − γw)/γt 倍の 0.578(従来の式の過小評価)。陸の側は
    どちらも 0.578。
  - `_lq1`・`_le1`: `_l1` の飽和度を 1 − 2.5×10⁻⁴ と 1 − 10⁻⁶ にする(地下貯留が容量にわずかに届かない)。
    地表水の水頭は、貯留が容量の 99.9 % から 100 % までの間で 0 から 1 へ連続につながる(つながり κ。
    全水頭は H = (z − sd) + hw + κ h)ので、湖の下は J = (1 − κ) tanθ。`_lq1` は κ = 0.75 で Fs = 0.943、
    `_le1` は κ = 0.999 で Fs = 1.193(静水の値より 0.1 % 小さい)。容量に届いたかどうかの 2 値で
    つなぐ実装では、どちらも従来の式の値 0.578 まで下がる。
  - `_m1`・`_m0`: 流動中の土砂が載ったセルの水頭。`_m1` は `_l1` の湖の下の 5 × 6 セルを、深さ 0.5 m だけ
    瞬時に流動化する(`fn_dbinit`、t = 1 s。`f_dbwet = 3` で、崩れた層の水の全部が流れへ出る)。
    流動化したセルは地盤が 0.5 m 下がり、水 0.2 m と土砂 0.3 m が載って、流動面 z + h + hs は湖の水位の
    まま。`_m0` は、同じ形にはじめから掘って清水を張ったケース。全水頭を流動面で読めば
    (H = (z − sd) + hw + κ (h + hs))、どちらも湖の下は J = 0 で、2 つの安全率は同じになる。水深 h だけで
    読む実装では、流動化したセルの水頭が hs = 0.3 m 下がり、その隣の安全率が最大 45 % 違う。
  - `_gdyn`: `_g1` を流動化あり(`f_slide = 1`)で 5 秒。固体と水の保存と、MPI の一致を見る。
- **構成 6**(`slide_dmax`)。上から d = 0.5 m だけを判定する。その中の飽和厚は
  max(0, hw − (sd − d)) = 0.3 m。`_d1` は更新 1 回で、標高がちょうど 0.5 m 下がり、土層が 1.5 m 残り、
  残った土層の容量を超える地下貯留(0.09 m)が地表へ出る。
- **構成 7**(`f_slide_wet`)。φs = 20° では乾いていても Fs = tanφs/tanθ = 0.93 < 1(幾何的な不安定)。
  1 は流動化せず、0 は全層を流動化する。φs = 25°(乾いた Fs = 1.19)で飽和した `_w2` は、間隙水圧で
  Fs = 0.58 になるので 1 でも流動化する。
- **構成 8**(`f_slide_noflow`)。1 回目の更新で 0.5 m が流動化し、濃い混合体(hs = 0.3 m)が載る。
  1 は 2 回目の更新でそのセルを判定しないので土層は 1.5 m のまま、0 はもう 0.5 m 流動化して 1.0 m。
  2 も、自分の流動化した土砂(堆積に直して 0.5 m。判定する厚さと同じ量)が載っている間は判定せず、
  状態が 1 と一致する(`_n2`)。
  - 薄い膜の下の不安定な層(`_f*`・`_k*`。developer.md §28.24)。土層厚 2 m、飽和度 0.8 では、上から
    0.5 m の中の飽和厚が 0.1 m で、はじめは安定(Fs = 1.07)。1 回目の更新の終わりに全面を薄く流動化する
    (`fn_dbinit`)と、地下水面が地表に近づいて不安定になり(深さ 0.1 m で Fs = 0.95、0.3 m で 0.70)、
    流動化した土砂が膜として載る。2 回目の更新で、1 は判定しないので流動化しない(`_f1`。土層 2 m)。
    2 は、膜が判定する厚さの 0.2 倍(`_f2`)なら判定して 0.5 m を流動化し、3 回目は自分の土砂の下なので
    判定しない(1.5 m)。0.6 倍(`_k2`)なら判定しない(2 m)。0 はどちらも 2 回目と 3 回目に流動化する
    (`_f0`・`_k0`。1.0 m)。判定を外す下限の比(本体の定数 0.5)が 0.2 と 0.6 の間にあることを見る。
    膜は水を含まない土砂なので、2 回目の更新の侵食・堆積で斜面に戻る(判定はその前)。

## 実行

```bash
make
./Run.sh          # dbinit 生成 → 8 構成(構成 4 は飽和と乾燥の 2 つ、構成 5〜8 は 18 ケース)を実行し Check。すべて PASS で PASS(10 秒ほど)
./Run_MPI.sh 4    # MPI。state.dat と出力ファイル(Fs9999・Fs0001 等)が逐次とバイト一致
python3 Fig.py    # figs/release.png, figs/fslide.png(引数 en で英語版を en/figs/ に)
```

- 流動化の発火は時刻交差判定で 1 回だけで、リスタート後も再発火しません
  (§28.1)。放出間隙水の水収支が 6 桁で一致します。
- f_slide は gwflow の浸透進行が発生時刻を決めるセル独立の判定
  (側方支持なし = SHALSTAB 系と同水準)で、堆積で sd が再生すれば再判定
  (進行性崩壊)されます。統計出力(Fs9999 等)は save に入らないため、
  ランク数不変の検証は出力ファイルで行います(`Run_MPI.sh` が恒常化)。
- 流体力 F9999 = (h + hs)V² は混合体密度込みで、τ_y ケースで ρm/ρw ≈ 2 倍に
  なることを確認しています(§28.9)。
- 構成 4 の水台帳は、保持水の項 w_r·Σ(z − z0) を入れて初めて閉じます(項の大きさは 17〜18 m³で、
  許容 1e-9 の 10 桁上)。飽和した土層(構成 4 の飽和)は地下貯留から sy0·D、保持水から w_r·D の
  水を出し、地下水計算なしの構成 1(λ·relsat·D)と同じ量の水を持って流れ出すので、崩壊域の低下と
  域外の堆積が構成 1 とほぼ同じになります。乾いた土層(構成 4 の乾燥)は保持水だけを持って
  濃い混合体になり、堆積のときに一部のセルで保持水が足りなくなります。その不足(0.09 m³)を
  台帳に数えると、残差は機械精度に戻ります(§28.17)。
- 構成 5 の湖のケースは、従来の式(斜面に平行な浸透)が静水の下の飽和した斜面の安全率を
  (γt − γw)/γt = 0.48 倍に見積もることを数値で示します。`f_slide_seep = 1` は陸の側(地表水がなく、
  全水頭の勾配が地形の勾配に等しい)では従来の式と同じ値のままです。
- 構成 5 の `_lq1`・`_le1` は、地表水の水頭が飽和帯へ連続につながることを確かめます。側方の地下水流の
  ある計算では、湖の下のセルの地下貯留が 1 ステップごとに容量の 10⁻⁶ ほど欠けます。その大きさの欠けで
