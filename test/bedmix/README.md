# test/bedmix — 混合粒径(f_bedmix)の検定

[English](en/README.md)

developer.md §84.19、docs/mixed_sediment_plan.md §6。掃流砂を粒径階に分け、河床の粒度を交換層 1 枚と
下層 1 枚で持つ計算(Hirano 型)を、極限の一致・理論値・式の再計算・収支で検定する。

水路は幅 5 セル(dx = dy = 1 m)・長さ 60 セルの直線水路で、乾いた高い河岸が挟む。西端の区間流入は
Manning の等流水深の単位幅流量 × 幅、東辺は自由流出(n = 0.03)。入力は make_init.py が型ごとに作る:

| 型 | 勾配 | 等流水深 | 河床の土層厚 | 河岸 | 下流端の 4 列 |
|---|---|---|---|---|---|
| std | 0.002 | 0.5 m | 1 m | 高さ 2 m、土層厚 0 | 土層厚 0(侵食しない床) |
| deep | 0.001 | 1.0 m | 0.5 m | 高さ 2 m、土層厚 0 | 土層厚 0 |
| free | 0.002 | 0.5 m | 1 m | 高さ 2 m、土層厚 0 | 動く床(開境界の流出を見る) |
| bank | 0.002 | 0.5 m | 1 m | 高さ 1 m、土層厚 1 m(動く河岸) | 土層厚 0 |

## 構成

| 構成 | 設定 | 検定 |
|---|---|---|
| single | std、単一粒径 3 mm、容量給砂 | equal との比較基準 |
| equal | std、3 粒径階がすべて 3 mm(割合 0.2・0.3・0.5)、交換層厚 5 m(土層より厚い = 交換層が柱全体)、容量給砂 | 河床が single と一致(最大差 < 1e-10 m)、組成が初期値のまま(< 1e-12)、開境界の正味の流出の合計が single と一致(相対 1e-8)。等移動度の極限 |
| single_te → equal_te | single・equal に芦田・道上の有効掃流力(`f_taupart = 2`。developer.md §121)を足した構成 | 河床が互いに一致(< 1e-10 m)、開境界の正味の流出の合計が一致(相対 1e-8)し、有効掃流力なしより小さい(粒径階の d_m で求めた係数 (u*e/u*)³ が単一粒径の係数と同じに効く) |
| single_tp → equal_tp | single に急勾配礫床の抵抗分割(`f_taupart = 1`、`fluv_d84` = 3 mm)を足した構成と、equal に抵抗分割を足して `fluv_d84` を与えない構成(D84 を交換層の組成からセルごとに求める。developer.md §122) | 河床が互いに一致(< 1e-10 m)、開境界の正味の流出の合計が一致(相対 1e-8)し、抵抗分割なしより 0.1 % 以上小さい(3 mm・水深約 0.1 m では係数 φ ≈ 0.985) |
| tpmix1 → tpfix1、tpmix → tpfix | hide1(0.5・2・8 mm)に抵抗分割(`f_taupart = 1`)を足し、D84 を組成から求める構成(tpmix)と、初期の組成の D84(粒径の対数の補間で 3.8193664156 mm。17 桁)を `fluv_d84` で固定した構成(tpfix)。1 ステップ(0.1 s)と 100 s | 1 ステップ目の河床が一致(< 1e-10 m。組成が初期のまま)し、`fluv_d84` が検定の式の値と一致。100 s 後は河床が違い(> 1e-6 m)、組成から求めた側の流出が小さい(粗粒化で D84 が大きくなる) |
| single_su → equal_su | 単一粒径 0.5 mm の掃流砂と浮遊砂(`f_suspend = 1`)と、3 粒径階がすべて 0.5 mm で組成 1・0・0 の混合粒径 + 浮遊砂(粒径階 1 が浮遊砂。developer.md §122)。std、容量給砂 | 河床と浮遊砂 hs が互いに一致(< 1e-10 m)、組成が粒径階 1 だけのまま(< 1e-12)。浮遊砂の結合の単一粒径の極限 |
| susp | free、0.3・2・8 mm(0.3・0.4・0.3)、粒径階 1 が浮遊砂、給砂なし(清水の流入)、プローブ 2 点(record_susp.txt) | 粒径階ごとの河床の収支(粒径階 1 は浮遊砂へ出た分を含む)と浮遊砂の収支(在庫・交換・開境界の流入と流出)の残差 < 1e-10 m³、交換を河床の側と浮遊砂の側で数えた値が一致(相対 1e-10)、組成が 0〜1 で和が 1、プローブの最後の列が Dm(mm)で、最初と最後の記録が組成から求めた値と 1e-5 mm 以内 |
| suw | susp の水路の中央の行をサブグリッド河道幅 0.6 m にした構成(rw_suw.txt・width_suw.txt) | 河道平面積率の重みが掛かっても、粒径階ごとの収支と浮遊砂の収支が閉じ(< 1e-10 m³)、交換の両側が一致 |
| armor | deep、1 mm と 20 mm を 0.5 ずつ、遮蔽なし、給砂なし(粗粒は限界以下で動かない) | 上流端の列の低下量が静的アーマーの理論値 L_a F_0 / (1 − f_sub) に一致(< 1e-6 m)し、そこの細粒が抜けきる(< 1e-6)、細粒の割合が単調に減る、細粒の割合の減衰率が、出力の水理量から求めた 1 セルの式 dF/dt = −(1 − f_sub) Q F / L_a の率と 3 % 以内 |
| hide1 → hide2 | free、0.5・2・8 mm(0.3・0.4・0.3)、修正 Egiazaroff(既定)。100 s で保存して 160 s まで続ける | 100〜160 s に下流端の開境界を出た粒径階ごとの量(台帳)が、下流端のセルの水深・流速・組成から芦田・道上(1972)式 (31)・(32) で求めた値と 0.5 % 以内 |
| bcfeed | std、3 粒径階、容量給砂 | 流入セルの河床と組成が変わらない(< 1e-12)、下流の河床は動く |
| bank | bank、3 粒径階、側岸侵食・安息角崩落、合計 1e-3 m³/s の給砂 + 一定の組成 0.2・0.5・0.3 | 粒径階ごとの収支(在庫の初期と最終・給砂・開境界の正味の流出)の残差 < 1e-10 m³、給砂が合計 × 組成 × 時間に一致(相対 1e-9)、交換層・下層の組成が 0〜1 で和が 1(< 1e-12)、河岸が動いている |
| qbmix | std、粒径階ごとの給砂の時系列(qbmix.txt) | 台帳の給砂が時系列(区分線形)の積分と 0.2 % 以内、収支が閉じる(< 1e-10 m³) |
| rt1 → rt2 | bank を 150 s で分割 | state.dat と geomorph_bedmix.dat が bank とビット一致 |
| surt1 → surt2 | susp を 80 s で分割 | state.dat と geomorph_bedmix.dat が susp とビット一致 |
| nofrac | 合計の給砂だけで組成の指定がない | 初期化で止まる(給砂の組成は与件なので既定を置かない) |
| su_d50 | susp に `susp_d50` = 1 mm(粒径階 1 の 0.3 mm と違う) | 初期化で止まる |
| su_wash | susp に斜面浸食 `f_wash = 1` | 初期化で止まる(斜面浸食の組成の運び方は未決) |

検定の数値は、たとえば equal と single の河床の差 5e-15 m、equal_te と single_te の河床の差 4e-15 m
(流出は有効掃流力なしの 0.19 倍)、equal_tp と single_tp の河床の差 9e-15 m(流出は抵抗分割なしの 0.998 倍)、
tpmix1 と tpfix1 の河床の差 0(1 ステップ)、tpmix と tpfix の差 4.5e-5 m、
equal_su と single_su の河床の差 1e-14 m・浮遊砂の差 3e-17 m、susp の粒径階ごとの残差 7e-14 m³・浮遊砂の残差
1e-14 m³(粒径階 1 から浮遊砂へ 0.513 m³)、プローブの Dm の差 2e-6 mm、armor の低下量 0.02197 m(理論値と同じ)、
減衰率 0.04934 と 0.04946 /s、hide2 の流出の比 1.0002、bank の残差 1e-13 m³ 程度。

## 実行

```
make
./Run.sh            # 逐次。Check_bedmix.py + 初期化で止まる構成(nofrac・su_d50・su_wash)+ リスタートの cmp
./Run_MPI.sh 2      # MPI(np=2)。逐次の save とのビット一致も確認
```

入力 zinit_*.txt / hinit_*.txt / sdinit_*.txt / qbmix.txt / rw_suw.txt / width_suw.txt は make_init.py が
生成する(追跡外)。
reference は持たず、合否は Check_bedmix.py の解析的な検定と、逐次・MPI・リスタートのビット一致で決める。
