# ENCflow

[![CI](https://github.com/ENCflow/ENCflow/actions/workflows/ci.yml/badge.svg)](https://github.com/ENCflow/ENCflow/actions/workflows/ci.yml)
[![DOI](https://img.shields.io/badge/DOI-10.5281%2Fzenodo.22042847-blue)](https://doi.org/10.5281/zenodo.22042847)

**地表の水に関わる現象を、ひとつの格子の上でシームレスに解く**
— 洪水・高潮・津波の遡上から、降雨流出・地下水・土砂・水質・積雪融雪・
氷河・地形変化まで、単一の Fortran プログラムで。

ENCflow が目指すのは、

1. **地球表層のプロセス連鎖を一つのモデルとして表現すること**
2. **気になった現象をすぐ数値実験できる「実験室」であること**
3. **研究者や学生が専門の隣へ最初の一歩を踏み出しやすくすること**

個々の分野の専用モデルを置き換えることは目的ではありません。

## ENCflow とは

ENCflow は、平面2次元の浅水方程式を核に、地表面の水の流れに関連する
多くのプロセスを同じラスタ格子の上で同時に計算するシミュレーション
プログラムです。格子には独自の八近傍連結コロケート格子
([Tada, 2026](https://doi.org/10.3178/hrl.25-00052))を用い、斜め方向を
含む8方向の流れで、格子方向に依存する偽くぼ地や流れの遮断を抑えて
います。ENC という名前はこの格子に由来します。

ふつう、洪水氾濫・流域水文・土砂輸送・水質・雪氷はそれぞれ別のソフトで
計算し、結果を受け渡して組み合わせます。ENCflow はこれらを1つの
プログラム・1つの入力体系で扱います。使わないプロセスはただ
「有効化しない」だけ。設定ファイルを1枚置くごとに、モデルが1段ずつ
賢くなっていきます。

ENCflow はまた、専門外の現象にも「まず一度計算してみる」ことを
容易にすることを目指しています。河川の研究者が地下水を、地形の
研究者が洪水を、水文の研究者が土砂や水質を試したいとき、新しい
ソフトウェア体系を一から習得する必要はありません。同じ格子・同じ
入力体系のまま、必要なプロセスを1つずつ足すだけです。

**必要なものは Fortran コンパイラ1つだけ。** 外部ライブラリはゼロ。
学生のノートパソコンでも、研究室のワークステーションでも、
スーパーコンピューターでも、同じソースコードがそのまま動きます。
ノート PC では OpenMP がコアを自動で使い切り、大型計算機では
OpenMP×MPI のハイブリッド並列でノードをまたいでスケールします。

## 5分で最初の計算

```bash
git clone https://github.com/ENCflow/ENCflow.git
cd ENCflow/src && make install
cd ../test/wave && ./Run.sh
```

インストールなしで試すこともできます。ブラウザだけで動く
[Colab ノートブック](https://colab.research.google.com/github/ENCflow/ENCflow/blob/main/docs/colab_quickstart.ipynb)
を用意しています。Windows で Unix がはじめての方は
[Windows での使い方](docs/windows.md) へ。

最初の例題は「水面に立てた水の山が崩れて広がる」だけの計算です。
入力は数十行の[テキストファイル1枚](tutorials/wave/param_step1.txt)。ここから、降雨を足す、地形を
実データにする、河道を通す、地下水を足す、と1行ずつ設定を足して
成長させていくのが ENCflow の使い方です
([チュートリアル](docs/tutorial.md))。

## こんなことができます

どの項目も同じ入力・同じ格子・同じ実行方法で、好きな組み合わせを同時に
有効化できます。降雨から融雪・流出・侵食・氾濫へと連なる現象も、1つの
計算の中で互いに影響し合います。興味のある行だけ読んでください。

- **洪水・氾濫**: 川からあふれた水の広がり、破堤、ポンプ・樋門・ダムの
  操作が浸水に与える効果。
- **高潮・津波の遡上**: 高潮・津波の陸への遡上と、河川洪水・豪雨が重なる
  複合災害。押し流される材木や、壊れた家屋の瓦礫の行方も概算できます。
- **沿岸の波浪**: 防波堤や島の陰を含む沿岸の波高の分布、波による水位の
  上昇と沿岸流、河口での波と流れのせめぎ合い、浜の侵食と回復。
- **地震による津波**: 断層運動による津波の発生から伝播・遡上まで、地震に
  よる隆起・沈降と低地の浸水。川を遡る津波の分裂や地滑り津波のような、
  分散性が効く波も。
- **降雨流出・流域水文**: 降った雨の行方(樹冠での遮断、蒸発散、浸透、
  地下水からの基底流)。山地斜面の流出応答、井戸の揚水による地下水位の
  低下も。
- **海水浸入・塩水くさび**: 沿岸の帯水層への海水の浸入と後退、淡水レンズ、
  揚水による井戸の塩水化、高潮・津波で陸に上がった海水の行方。
- **都市の内水**: 下水道があふれる内水氾濫。雨水枡の呑み込み、マンホール
  からの噴出、吐口と排水機場まで。岩盤の割れ目・カルスト・暗渠・カナートの
  水も。
- **土砂・斜面災害**: 河床の侵食と堆積、斜面の侵食と崩壊、土石流、蛇行
  河道の発達と短絡、流木。変わった地形がそのまま流れを変えます。危険度の
  地図と土壌雨量指数も。
- **火山災害**: 山体崩壊・火砕流・火山泥流とその堆積、天然ダムの形成と
  決壊、降雨による二次泥流。崩れた土塊が湖や海に突っ込む地滑り津波まで。
- **溶岩流**: 噴火口から流れ出た溶岩の流下・停止・固化と、新しい溶岩原の
  上を流れる雨水・洪水・土砂。
- **水質・物質輸送**: 汚濁負荷の流出と輸送、減衰・沈降、蓄積と洗い出し、
  重金属など吸着性の物質、地下水を通る移動、貯水池での混合。下水の噴出の
  衛生リスクや放射性物質の流出の評価にも。
- **積雪・融雪**: 標高で変わる積雪と融雪、凍った地面の上を流れる融雪
  出水、雪崩の到達範囲と堆積。
- **氷河**: 氷河の涵養・流動・融解と融解水の流出、氷河による侵食と、
  カールなどの地形の形成。
- **長期地形変化**: 風化・隆起と繰り返す出水による、千年スケールの地形の
  発達。

使わないプロセスはメモリも計算時間も消費せず、設定ファイルも要りません。
最小構成なら、ENCflow はただの速くて素直な2次元洪水モデルです。

現象から機能の組み合わせと設定の要点を引くには
[用途集](docs/users_guide/usecases.md) を、複数プロセスを連鎖させる設定の
見本は [examples の「複数プロセスの連鎖の例」](examples/README.md#複数プロセスの連鎖の例)
を見てください。[AI エージェントと使う](docs/ai_guide.md) なら、現象の言葉で
指示して模式ケースの作成から始められます。

## できないこと(設計上の非対象)

ENCflow は、深さ平均・密度一定の平面2次元の世界に意図的に
踏みとどまっています。次のものは原理的に対象外で、専用モデルの
領域です([他モデルとの比較](docs/comparison.md))。

- **波浪推算と短周期波の位相解像** — 風による波の発達と、1波ずつの
  水面の上下を解く計算はできません。上記の沿岸の波浪は、沖の波を与件と
  する位相平均・代表周期1個の概算です。
- **火砕サージ・噴煙・降灰の大気輸送** — 圧縮性・3次元の大気現象で、
  浅水近似の外です。降灰の堆積分布を前処理で地形・土層に与えれば、
  降雨による二次泥流は解析できます。
- **水温** — エネルギー収支を解かないため、水温は予測できません。
- **密度流・成層の力学** — 運動方程式は密度一定で、鉛直構造も解きません。
  淡塩の2層を鋭利界面で近似するほかは、混合・連行・内部波・貯水池の
  水温成層は再現できません。
- **下水道管網の個別管路・制御運転** — 管路1本1本の追跡や、運転規則で
  動く制御構造物を含む管網解析は、1次元管路網モデルの領域です。市街地の
  下水道は面的な連続体として扱うので、どのマンホールから噴出するかは
  特定できず、幹線1本が支配する系にも向きません。
- **深部地下水** — 地下水は流出解析のための浅い2層です。広域の被圧
  帯水層や井戸孔単位の水理は扱いません。

## ENCflow を選ぶ理由

- **ゼロ依存の絶対的ポータビリティ** — 依存は言語標準と OpenMP/MPI の
  標準規格のみ。GeoTIFF の読み書きも圧縮展開も自前実装です。
  「ビルドできない」で挫折することがありません。
- **ノート PC からスパコンまで単一ソース** — パソコン単体でも OpenMP の
  スレッド並列が、何も設定しなくてもマルチコアをそのまま活用します。
  ワークステーション・スパコンでは make の設定1行で OpenMP×MPI の
  ハイブリッド並列に切り替わり、同じ入力ファイルのまま大規模計算に
  スケールします。
- **結果が再現する** — 同じ実行ファイル・入力・計算環境なら、スレッド数・
  MPI ランク数を変えてもビット単位で同じ答えになることを並列化の規律とし、
  回帰試験で確認しています。リスタートは中断なし実行と厳密一致。研究の
  再現性・実務の説明責任にそのまま応えます。
- **段階的に精緻化する設計** — 「とりあえず動く」最小パラメータから、
  入手できるデータに合わせて1段ずつ精緻化。全機能がこの思想で
  作られています。
- **専門の隣へ踏み出す入口** — まず簡潔なモデルで「このプロセスは
  効きそうか」を見積もり、効くと分かってから必要に応じて各分野の
  専門モデルへ進む。ENCflow はその最初の一歩のための共通基盤でも
  あります。
- **入出力は単純なテキスト** — 行列テキスト・namelist・CSV と、実務用に
  GeoTIFF。GIS でも Python でも Excel でも、好きな道具で前後処理
  できます。
- **スクリプト自動化との高い親和性** — パラメータファイルがプレーン
  テキストなので、sed や Python でケースを機械生成して一括実行し、
  テキスト出力を diff・集計する自動化がシェルスクリプトだけで組めます。
  感度分析・キャリブレーション・多数シナリオの一括計算に向きます。
- **AI エージェントによる高度な自動化** — 同じ性質は AI による高度な
  自動化にも直結し、AI エージェントがケース生成・実行・検証・結果解析
  までを直接操作できます。ENCflow 自体の開発・検証の多くが AI
  エージェントとの協働で行われており、このプロジェクトがその実証です。
- **全ソース公開** — 中身を確かめられ、検証できます。計算コードは
  すべて書き下ろしで、第三者のコードを一切含みません。依存ゼロは、
  著作権の出所が明確ということでもあります。Apache-2.0 で商用利用も
  可能です。
- **出典と検証で説明できる** — 各モデル・基礎式・パラメータの
  出典を可能な限り明記し、文献によらない独自の簡略化はそう書きます。
  解析解や保存則のある挙動は、基準結果との回帰とは別に、合否を自分で
  判定する検定スクリプトで確かめます。「なぜこの結果になるのか」を
  第三者が遡れる状態を保つことを、全ソース公開と並ぶ基本方針に
  しています([docs/developer.md](docs/developer.md) §0。英訳は
  [docs/en/developer.md](docs/en/developer.md))。
- **プロジェクトとしての持続性** — 設計判断の理由と経緯
  ([docs/developer.md](docs/developer.md))から全体像
  ([docs/architecture.md](docs/architecture.md))までが文書化され、
  変更の正しさは回帰テストと CI が機械的に検証します。開発の知識が
  リポジトリ自体に外在化されているため、全ソース公開と合わせて、
  現在の開発主体が継続しない場合でも第三者による開発の継続が可能です。

## 外部連携(BMI)

ENCflow は CSDMS の [Basic Model Interface (BMI) 2.0](https://bmi.csdms.io/)
に対応し、公式適合性テスト bmi-tester に合格しています。モデル全体が
ひとつの BMI component となり、initialize / update / get_value /
set_value という共通の操作で外部から制御できます。

- **Python から直接駆動** — 追加ツールは不要で、numpy だけで動きます。
  計算を任意の間隔で止めて水深・水位・流速などの分布を取り出せるので、
  計算しながら結果を順次表示したり、条件を変えた多数のケースを
  スクリプトで回したりする使い方ができます。
- **他のモデルと組み合わせる** — BMI は、世界中の水文・地形・海洋・
  雪氷などのモデルが採用している「モデル同士をつなぐ共通の差し込み
  口」です。これは ENCflow の限界を超えるための扉です。単体では対象外の
  深部の3次元地下水や風による波の発達などを、その分野の専用モデルと
  状態をやり取りしながらひと続きに解く。あるいは逆に、外部のシステムが
  ENCflow の氾濫水理をエンジンとして呼び出す。大陸規模の水文モデルが
  危険な流域だけ ENCflow に高解像度の氾濫を解かせる、観測データを
  取り込みながら走る予測システムの部品になる、といった使われ方です。
- **単体でも、部品としても** — ENCflow は多くのプロセスを備えた単体で
  完結するモデルですが、有効化しない機能はメモリも CPU も消費せず、
  そのためのパラメータファイルも要りません。浅水流だけ、地下水だけ、
  といった最小構成で軽く動くので、他のモデルに足りないプロセスを補う
  小さな部品として呼び出す使い方にも向いています。これは CSDMS が BMI で
  目指す「モデルを部品として組み合わせる」という考え方に沿うものです。
- **本体は不変** — BMI は `bmi/` の optional アダプタとして実装されて
  おり、通常のビルドは従来どおり外部依存ゼロのままです。

使い方・公開変数・適合性確認の再現手順は [bmi/README.md](bmi/README.md)、
設計の経緯と全体計画は [docs/bmi_plan.md](docs/bmi_plan.md) へ。

## 想定ユーザー

- **学生・教育** — コンパイラだけで動く・入力がテキスト1枚・
  結果がすぐ図にできる。水理学・水文学の演習教材として。
- **研究者** — 崩壊から土石流・河道閉塞・氾濫へ、風化から土層・侵食へ
  といったプロセス間の相互作用を単一モデルで。条件を揃えた実行のビット
  再現性により数値実験が厳密に比較できます。
- **実務技術者** — 氾濫解析・構造物操作・土砂災害・水質と、案件ごとの
  ツール切替なしに同じ入力体系で。スパコンでの大規模計算にも
  そのまま移行できます。
