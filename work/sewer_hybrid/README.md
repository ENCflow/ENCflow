# sewer_hybrid — 幹線1本(線)+枝管網(面)の同一インスタンス模式実験

設計議論(幹線ハイブリッド vs 単一インスタンスのセル別不均質)の
実証実験。管路連続体層(f_gwconduit)1 インスタンスに、セル別マップ
(cap/cnd/zbot)だけで幹線(D=1.0 m, 埋設 5 m のセル列)と枝管網
(D=0.4 m, 埋設 2 m の面)を同居させ、降雨 60 mm/h×1 h の応答を見る。
コード変更なし。

## ラン構成

| ラン | 幹線 | gwc_sy | 意味 |
|---|---|---|---|
| A | あり | 0.0314(枝管 D=0.4 に整合) | 幹線の水頭応答が約 2.9 倍過大 |
| B | あり | 0.0911(幹線セルに整合) | 枝管の水頭応答が約 2.9 倍過小 |
| C | なし | 0.0314 | 幹線の効果の対照 |

## 実行方法

```
python3 gen_data.py            # 管諸元→cap/cnd/sy の幾何換算+マップ生成
../../bin/encflow param_A.txt  # 各約 100 秒(B, C も同様)
python3 plot_sewer.py          # sewer_hybrid_result.png
```

## 結果(2026-08-23)

- 質量保存: S_total(降雨後) = 積算雨量 61.0 mm(全ラン、丸め 1e-13)
- 最終地表氾濫量: C 21.6 mm > A 18.2 mm > B 10.2 mm
- 吐口の排出ピーク: 0.16〜0.22 m³/s(幹線の満管能力 1.7 m³/s に対し
  オリフィス+地表水頭で律速)
- 降雨後も管内に 43〜51 mm が被圧のまま残留(排水できない)

## 設計議論への含意(段階案 1〜3 の必要性)

1. **幾何→パラメータ換算(項目1)は前処理で足りる**: gen_data.py の
   pipe_params() がそのまま実演。コード変更不要。
2. **開放吐口(項目2)は必要**: 吐口が「被圧時オリフィス」のみのため、
   幹線能力の 1/8 しか吐けず、降雨後は管内水が抜けない(閉領域で
   吐口上に湛水が乗る効果も混在するが、自由排水機構の欠如が支配)。
3. **sy のセル別化(項目3)は必要**: A↔B の差(最終氾濫 8 mm、1.8 倍)は
   幹線自体の効果(C−A=3.4 mm、C−B=11.4 mm)と同程度。スカラー sy の
   選び方が答えを支配する。
4. 幹線+枝管の同一インスタンス同居は**機構的には成立**(min 規約で
   枝管→幹線の取り付けが自然に表現され、幹線が氾濫を確かに減らす)。
   多重インスタンスはこの用途には不要(下水道×岩盤の併用専用)。

## 追加の知見

- **陽解法の硬直性**: 幹線の通水能(エッジ 24 m³/s)で dt 上限が
  0.061 s(幹線なしなら 0.24 s)。物理的に妥当な小さい slot_sy は
  さらに厳しく、幹線ハイブリッドの設計では時間積分の扱い
  (局所陰解法・サブステップ等)が論点になる。
- **緩い slot_sy の副作用**: dt との折り合いで slot_sy=0.03 とした
  結果、被圧側の「幻の貯留」が管容量の 3〜5 倍に達し(図パネル c)、
  その分だけ地表氾濫が過小評価される。sy をセル別化するなら
  slot_sy も同時にセル別化する必要がある。
- **fn_gwc_bot の負値拒否**: 管底標高マップの読込検査が負値を
  データ不良として停止する(read_map_scatter の検査が cap/cnd/inlet と
  共通のため)。海抜下の管底を持つ実都市で問題になる小修正候補。
  本実験は基準面を +6 m して回避した。

## 制約(結論に影響しない範囲)

- 全周閉境界のため吐口の排出水が領域内(東端)に湛水し、吐口の
  排出をやや絞る。氾濫分布も東端の湛水が支配的。
- 一様勾配のため「どの街区が浸水するか」の空間パターンの検証には
  向かない(総量・時系列の比較が目的)。
