# チュートリアル 1: wave — 静水に広がる波

静水面に立てた「水の山」が崩れ、同心円状の波となって広がる —
ENCflow の最小構成の例題です。地形も降雨もない正方形の水槽ひとつで、
次のことを学びます。

- **Step 1**: 実行のしかた、出力の読み方、パラメータファイルの構造
- **Step 2**: 時間刻みと精度、適応的ルンゲクッタ法(ENC パラメータ)
- **Step 3**: 境界条件の設定(壁面と長波放射)
- **Step 4**: ENC 格子ならではの壁の性質(不透過壁と半透過壁)

コンパイラの準備は [インストールガイド](../../docs/install.md) を
参照してください。結果の可視化には gnuplot を使います(インストール
方法は同ガイドの 2 章)。以降の作業はすべてこのディレクトリ
(`tutorials/wave`)の中で行います。

> `test/wave` にも同名のケースがありますが、あちらは開発用の回帰テスト
> (基準値との自動比較)です。チュートリアルはこの `tutorials/` 以下で
> 行います。

## Step 1: はじめの一歩

### 準備

まず、いまいる場所を確認します。チュートリアルはリポジトリの
`tutorials/wave` ディレクトリで行うので、そこまで移動します:

```bash
pwd     # 現在地を表示
ls      # いまの場所のファイル一覧(ls .. で「ひとつ上」の一覧)
```

インストール直後(`test/wave` で `./Run.sh` を実行した直後)なら
`cd ../../tutorials/wave` で移動できます。別の場所にいる場合も、
`ls` で確かめながら `cd` で `tutorials/wave` までたどってください。
**移動したら `pwd` で確認**する癖をつけておくと、場所違いによる
失敗を避けられます:

```bash
pwd     # → .../ENCflow/tutorials/wave にいれば OK
```

このディレクトリで

```bash
make
```

と実行すると、実行ファイル `encflow` へのシンボリックリンクが作られます
(まだビルドしていない場合は、先に `src/` でのビルドが自動で走ります)。

### パラメータファイルの中身

ここで、パラメータファイルの中身を見てみましょう。内容は以下に
転載しますが、**ぜひ実物の `param_step1.txt` を自分で開いてください**。
Windows(WSL)の方は、エクスプローラーで `tutorials/wave` を開き、
メモ帳などで開くのが手軽です
([Windows での使い方](../../docs/windows.md)の
「ファイルの閲覧・編集」の節)。以降の Step でも、新しいパラメータ
ファイルが出てきたら同じように開いて、本文と見比べながら進めて
ください。

```
!======================================================================
! システムパラメータ設定
!======================================================================
&list_sysparam
  dt = 0.01                 ! 時間刻み (s)
  !dt = 0.05                 ! 時間刻み (s)
  tt = 8.0                  ! 計算終了時刻 (s)
  dt_disp = 1.0             ! 画面表示時間刻み (s)
  dt_file = 1.0             ! ファイル出力時間刻み (s)
  f_out_e = 1               ! 水位分布ファイル出力
  fn_geoinfo = "-"          ! 地理情報設定ファイル
  fn_initial = "-"          ! 初期条件設定ファイル
/

!======================================================================
! 地理情報設定
!======================================================================
&list_geoinfo
  lx = 100.0, ly = 100.0    ! 計算領域の大きさ (m)
  nx = 350, ny = 350        ! 計算格子数
/

!======================================================================
! 初期条件設定
!======================================================================
&list_initial
  h0 = 1.0                       ! 初期水深固定値 (m)
  f_user_routine = "wave_hump"   ! ユーザールーチン識別名(円形コサイン型の初期水位)
/
```

パラメータファイルは Fortran の namelist 形式で、`&グループ名` から
`/` までがひとまとまり、`!` 以降はコメントです。ここでは3つの
グループを使っています。

- `&list_sysparam` — 時間刻み・終了時刻・出力間隔などのシステム設定と、
  各機能の設定ファイル名。`fn_geoinfo` などのファイル名パラメータに
  `"-"` を指定すると「**同じファイルの中から読む**」という意味になり、
  この例題では全設定を1枚にまとめています(実務では地形データなどを
  別ファイルに分けられます)。
- `&list_geoinfo` — 計算領域と格子。100 m 四方を 350×350 格子
  (格子幅約 29 cm)で覆います。
- `&list_initial` — 初期条件。水深 1 m の静水に、ユーザールーチン
  `wave_hump` が円形コサイン型の水位の山を重ねます。

時間刻みを5倍にしたため、Cn_max 列のクーラン数が 0.15 前後から

| dt = 0.01 | dt = 0.05 |

`dt = 0.01` では波の頂部がなめらかな円環ですが、`dt = 0.05` では
頂部がギザギザに波打ち、全体に高くなっています。画面表示の最終行でも
h_max が 1.1967 m から 1.2281 m へ **3% 過大**になっています。
波面を拡大して 0°方向(x 軸沿い)と 45°方向(対角線沿い)の水位分布を
比べると、崩れ方がさらにはっきりします。

![波面の拡大比較(dt = 0.05)](figs/step1_profile.png)

`dt = 0.01`(灰色)では波形はどの方向でも同じ = きれいな同心円ですが、
`dt = 0.05` では波面に数値振動が生じ、その形が 0°方向(青)と
45°方向(赤)で 4 cm ほど食い違い、頂部は基準より 2〜3 cm 高く
出ています。同心円のはずの波形が、計算格子の向きに依存して崩れ、
波高も過大評価されているということです。

このような誤差を減らすには、時間刻みを小さくするか、時間積分を高次
スキームに変更することが正攻法ですが、いずれも計算コストの増加が
避けられません。ENCflow の ENC 計算モジュールには、少ない計算コストで
精度の低下を最小限に抑える**適応的ルンゲクッタ法**が実装されています。
次の Step で試してみましょう。

## Step 2: ENC パラメータの設定

### 適応的ルンゲ・クッタ法の適用条件を変更する

適応的ルンゲクッタ法は、1回のタイムステップをまず陽的オイラー法で
計算し、流速の変動率が閾値を超えたセルだけを4段ルンゲクッタ法で
再計算する手法です。全セルをルンゲクッタ法で計算するよりも大幅に
計算量を減らせますが、選択的な適用のため精度は完全なルンゲクッタ法
には及びません — 「必要な場所にだけ高次精度を投入する」方式です。

この閾値を変更するには、まず ENC 計算モジュールのパラメータファイルを
読み込む設定を追加します。`&list_sysparam` の中の `fn_geoinfo` や
`fn_initial` が書かれている場所に、次の行を追加します。

```
  fn_enc = "-"              ! ENCパラメータ設定ファイル
```

ファイル名として `"-"`(同じファイルから読む)を指定したので、
同じファイルの末尾に次の内容を追加します。

```
!======================================================================
! ENC計算条件
!======================================================================
&list_enc
  p_adprunge_thresh = 1.1        ! 適応的ルンゲクッタの閾値 (1.1 ~)
/
```

`p_adprunge_thresh = 1.1` は、1回のタイムステップで流速が 1.1 倍以上
または 1/1.1 倍以下に変動したセルをルンゲクッタ法で再計算することを
指定します。無指定のときのデフォルト値は 1.5 です。つまり、より小さな
変動に対してもルンゲクッタ法を適用するように設定したことになります。

これらの変更を適用したパラメータファイルが `param_step2.txt` として
作成済みです(時間刻みは `dt = 0.05` のまま)。実行してみましょう。

```bash
./encflow param_step2.txt
```

クーラン数はほとんど変わっていませんが、Runge 列のルンゲクッタ適用率が
13〜16% から最大 41.2% へと大きく増加し、最終行の h_max(1.1986 m)・
V_max(0.5875 m/s)が `dt = 0.01` の値(1.1967 m・0.5774 m/s)に
近付いています。3D 表示で 3 つを並べると効果は明らかです。

| dt = 0.01 | dt = 0.05 | dt = 0.05、閾値 1.1 |
|---|---|---|
| ![3D 水位(dt = 0.01)](figs/step1_dt001_3d.png) | ![3D 水位(dt = 0.05)](figs/step1_dt005_3d.png) | ![3D 水位(閾値 1.1)](figs/step2_adprunge_3d.png) |

`dt = 0.05` で崩れていた頂部のギザギザが消え、波高も `dt = 0.01` と
同じ高さに戻っています。波面を拡大してみると:

![波面の拡大比較(閾値 1.1)](figs/step2_profile.png)

0°方向と 45°方向の食い違いが 4 cm から 1 cm に縮んで同心円に戻り、
`dt = 0.05` で 2〜3 cm 過大だった頂部の高さも `dt = 0.01`(灰色)に
揃っています。**方向依存性と波高の過大評価の両方が改善**されました。
時間刻みは5倍のまま、再計算はセルの半分以下 — これが適応的
ルンゲクッタ法の狙いです。

一方で、よく見ると波の先端(r ≈ 38 m)が `dt = 0.01` より 0.1〜0.2 m
手前にあり、頂部がやや鈍っています。再計算の対象になった先端付近の
セルは、オイラー法より滑らかな(減衰の大きい)解に置き換わるため、
鋭い先端ほどわずかに遅れます。これは選択的に高次精度を投入する方式の
代償で、閾値を下げれば消えるものではありません。

適応的ルンゲクッタ法の本来の目的は、**ごく一部の極端な場所(急な波面や
乾いた地盤に乗り上げる前縁など)のためだけに時間刻みを細かくして、
領域全体の計算コストが上がるのを防ぐ**ことです。この例題は効果を
見せるために閾値を極端に下げていますが、再計算の割合が 41% にも
なるのは、本来は時間刻みが粗すぎるという信号です。実務では Runge 列が
数 % 〜 10% 程度に収まるように時間刻みを選ぶのが本筋で、適応的
ルンゲクッタ法はその上で残る局所的な問題を受け持たせる、と考えて
ください。

![閉じた壁での反射(t = 14 s)](figs/step2_tt14.png)

ENCflow の計算領域の外縁は、デフォルトでは**不透過の壁**です
(S 列が一定のままなのはこのためで、水は領域から一切出ていません)。
水槽の計算ならこれが正しい挙動ですが、広い水面の一部を切り出した
計算では、波にはそのまま領域の外へ出ていってほしいところです。
これが次の Step のテーマです。

## Step 3: 境界条件の設定

### 四周の壁面を透過条件に設定

境界条件を設定するには、`&list_sysparam` に境界条件設定ファイルの
読み込みを追加し(ここでも `"-"` = 同じファイルから読む)、

```
  fn_boundary = "-"         ! 境界条件設定ファイル
```

ファイル末尾に、計算領域外縁の4辺それぞれの境界条件型を指定する
`&list_bound_edge` を追加します。

```
!======================================================================
! 辺境界条件: 計算領域外縁の4辺それぞれの境界条件型
!   0: 不透過(壁面。既定)
!   1: 自由流出(洪水氾濫向け)
!   2: 長波放射(津波・波動伝搬向け)
!   方角と格子添字の対応(ラスタの行順=北→南):
!     西 = i=1(左端)、東 = i=nx(右端)、
!     北 = j=1(上端)、南 = j=ny(下端)
!======================================================================
&list_bound_edge
  f_bc_w = 2
  f_bc_e = 2
  f_bc_n = 2
  f_bc_s = 2
/
```

型 `2`(長波放射)は、境界に達した長波を反射させずに領域外へ逃がす
条件です。この例題のような波の伝搬には放射条件が適し、洪水氾濫計算で
氾濫水を領域外へ流し去るには型 `1`(自由流出)を使います。4辺は
それぞれ独立に指定できます。

これらの変更を適用したパラメータファイルが `param_step3.txt` として
作成済みです(`tt = 14` も適用済み)。実行してみましょう。

```
time, progress, S(m), Runge, ex_flux, Cn_max, h_max(m), V_max(m/s)
  0:00:11.00  78.6%    1.0210  38.2%      0    0.6851    1.1777    0.5210
  0:00:12.00  85.7%    1.0187  32.3%      0    0.6783    1.1685    0.5242
  0:00:13.00  92.9%    1.0112  25.2%      0    0.6742    1.1603    0.5107
  0:00:14.00 100.0%    1.0026  20.4%      0    0.6677    1.1533    0.4846
```

今度は t = 12 s 以降も h_max は跳ね上がらず、代わりに S 列の全水量が
減り始めました — 波が境界を抜けて領域外へ出て行き、その分の水が
系から失われていることが S 列で追えます。可視化して比べてみましょう。

| 不透過(既定)| 長波放射 |
|---|---|
| ![閉じた壁](figs/step2_tt14.png) | ![放射境界](figs/step3_radiation.png) |

壁での反射がなくなり、波はそのまま領域外へ流れ去っています。

## Step 4: ENC 格子の特性を確認

最後に、ENCflow の名前の由来でもある **ENC 格子(八近傍連結
コロケート格子)**ならではの性質を見てみます。ENC 格子では、
セルは上下左右の4方向に加えて**斜め4方向**ともつながっており、
8方向のリンクで水をやり取りします。このことは、壁や堤防のような
線状の障害物をラスタ格子で表現するときに、4方向連結のモデルには
ない性質として現れます。

`param_step4.txt` は、`&list_geoinfo` のユーザールーチンで
計算領域を斜め 45° に横切る壁(地盤高 1.5 m・計算対象外のセル)を
置きます。

```
&list_geoinfo
  lx = 100.0, ly = 100.0    ! 計算領域の大きさ (m)
  nx = 350, ny = 350        ! 計算格子数

  ! ユーザールーチン識別名(未指定なら障害物なし)
  f_user_routine = "wave_solid_wall"   ! 斜めの不透過壁(2セル厚)
  !f_user_routine = "wave_leaky_wall"   ! 斜めの半透過壁(1セル厚)
/
```

### 不透過となる壁面

まず **2セル厚**の壁 `wave_solid_wall` のまま実行してみましょう。

```bash
./encflow param_step4.txt
```

開始表示の `number of valid cells` が 122500 から 121976 に減っています —
壁にしたセルは計算対象から外れ、メモリも計算時間も消費しません。

![不透過壁(2セル厚)](figs/step4_solid.png)

波は壁で完全に遮られ、反射しながら壁の手前側だけに広がります。
壁の向こう側は静水のままです。

### 半透過となる壁面

次に `param_step4.txt` のユーザールーチンを **1セル厚**の壁
`wave_leaky_wall` に入れ替えて(コメントの `!` を入れ替えて)
実行してみましょう。

![半透過壁(1セル厚)](figs/step4_leaky.png)

壁は同じ場所にあるのに、今度は波が壁を**透過**して向こう側にも
広がっています。

これが ENC 格子の8方向連結の現れです。斜め 45° の壁を1セル厚で
並べると、壁セルどうしは角と角で接します。ENC 格子にはこの角を
横切る**斜め方向のリンク**があるため、壁の両側の水セルが対角方向に
つながったままになり、水が通り抜けるのです。2セル厚にすれば角を
横切るリンクは存在せず、壁は不透過になります(x・y 軸に平行な壁は
1セル厚でも不透過です)。

堤防・防波堤のような細い線状の構造物を地形データで表現するときは、
この性質に注意してください — **斜めの区間は2セル厚以上でラスタ化する**
のが確実です。なお実務の河川堤防・海岸堤防には、セルの太らせを
必要としない専用の仮想壁面機能(`fn_bank` / `fn_seawall`)も
用意されています。

## 補足: 波面の振動の正体 — 格子の細分と物理分散

Step 1・2 で見た波の先端のギザギザは、**数値分散**(離散化による
位相誤差)です。数値拡散(なまり)とは逆向きの誤差で、ここで少し
掘り下げておきます。計算は重くなるので、本文の手順とは別にしてあります
(図は `./Fig_supp.sh` で再生成。4 コアのノート PC で 30 分前後)。

### 何が起きているか

初期の水の山は高さ 1 m、水深も 1 m です。浅水方程式(静水圧)では、
水深と同程度に高い波は進むにつれて前面が切り立ち、やがて段波
(不連続)になります。離散化はこの急な前面を数セルで表すしかなく、
そこでは短い波長の成分が本来と違う速さで伝わるため、前面の背後に
細かい振動が現れます。時間刻みが粗いほど位相誤差が大きく振動も大きい、
というのが Step 1 の `dt = 0.05` の図でした。`dt = 0.01` でも
よく見ると頂部に小さな行き過ぎ(1.195 m、r = 37.6 m)が残っています。

### 格子を細かくすると

格子数を 350 → 700 → 1400 と倍にし、時間刻みもクーラン数が
変わらないように 0.01 → 0.005 → 0.0025 s と比例して縮めます
(`nx, ny` と `dt` を書き換えるだけ)。

![格子の細分(静水圧)](figs/supp_grid.png)

前面は細かくなるほど鋭く立ち、頂部の行き過ぎは 1.195 → 1.184 →
1.181 m と縮みます。振動の幅はいつもセル幅の数倍で、格子と一緒に
縮んでいく — 数値分散の特徴です。代償は計算量で、格子を倍にすると
セル数 4 倍 × ステップ数 2 倍 = 8 倍(この例では 18 s → 134 s →
981 s)。

Step 2 で見た `dt = 0.05` + 閾値 1.1 の遅れ(緑の破線)も、この図で
位置づけられます。前面の中腹(e = 1.1 m)の位置は r = 37.8 m で、
`dt = 0.01` の 38.1 m、nx = 1400 の 38.2 m より手前です。
格子と時間刻みを細かくした側へ近いのは `dt = 0.01` の方で、
閾値 1.1 の遅れは再計算の数値減衰が鋭い前面を鈍らせた分だけ
静水圧方程式の解から離れている、ということです。

### 現実には物理分散が生じる

ここまでの振動は離散化の誤差でしたが、現実の水にも、別の理由で段波に
ならない仕組みがあります。順に追います。

1. 前面が水深と同程度まで急になると、水は水平に動くだけでなく上下にも
   加速されます。**鉛直方向の加速度が無視できなくなる**のです。
2. 鉛直加速度があると圧力は静水圧からずれ、波長によって進む速さが
   変わる**周波数分散**が働きます(短い波ほど遅く進む)。前面を切り立たせ
   ようとする非線形と、崩そうとする分散が釣り合って、前面はなだらかな
   形(やがて波列)に落ち着きます。
3. 静水圧の浅水方程式は、圧力を静水圧と仮定して鉛直加速度を**落として
   います**。だから格子をいくら細かくしても、収束するのは段波であって、
   現実の前面には近づきません。前節の nx = 1400 の結果は「方程式の正しい
   解」ではあっても「現実」ではない、ということです。
4. この物理分散を再現するために、ENCflow には **1 層非静水圧補正**が
   あります(鉛直加速度を 1 層で近似して圧力を補正する。
   [ユーザーガイド](../../docs/users_guide/swflow.md)の非静水圧補正の項)。
5. 使うには `&list_enc` に 1 行足すだけです。

```
  fn_enc = "-"              ! ENCパラメータ設定ファイル
  ...
&list_enc
  f_nonhydrostatic = 1           ! 1 層非静水圧補正
/
```

![非静水圧補正との比較](figs/supp_nh.png)

前面はなだらかな丘になり、振動は消えます。頂部は高く(1.22 m)
後ろ(r ≈ 34.7 m)へ、裾は前(r ≈ 39.3 m)へ伸び、静水圧の段波とは
形そのものが違います。nx = 350 と 700 の結果が重なっているので、
この格子で既に収束しています(非静水圧補正の目安は Δx ≲ H/2。
計算時間は同じ格子の静水圧の 1.5〜2 倍)。もっと長く走らせると前面は
先頭から波列(undular bore)に分裂していきます(test/nhbore)。

### まとめ: 数値の収束が先、物理の追加はその後

この補足で見たことを、対処の順序として整理します。

- **粗い格子・粗い時間刻みで静水圧の浅水方程式を解くと**、数値分散の
  振動が大きく発達します。最大波高を過大に評価したり(Step 1 の
  `dt = 0.05` で h_max が 3% 過大)、同心円のはずの波面が 0°方向と 45°方向で
  4 cm 食い違う異方性が目立ったり、最悪の場合は計算が破綻します。
- **正攻法は格子を細かくし、それに合わせて時間刻みも縮める**ことです。
  nx = 350 → 700 → 1400 で振動は格子とともに縮み、方程式の正しい解
  (前面 r ≈ 38.2 m の段波)に近づきました。ただしコストは格子を倍に
  するごとに 8 倍(18 s → 134 s → 981 s)です。
- **適応的ルンゲ・クッタ法**(Step 2)は、振動が大きくなったステップだけを
  細かく再計算するので、少ないコストで振動を抑え、破綻を避けられます。
  一方で再計算の数値減衰が鋭い前面を鈍らせ、閾値 1.1 の遅れた前面
  (r = 37.8 m)のように、正しい解から離れる方向にも働きます。
- **方程式の正しい解が現実に近いかどうかは、また別の問題**です。前節の
  とおり、静水圧方程式の収束解は段波で、現実の前面(分散あり)は中腹で
  r ≈ 37.1 m、裾は 39.3 m まで伸びたなだらかな丘です。閾値 1.1 の
  遅れた前面が位置だけは非静水圧に近く見えますが、理由の違う偶然の
  一致で、形(切り立ち)は静水圧のままです。**数値の設定で物理を真似
  しようとしない**こと。
- したがって順序は、**まず格子と時間刻みで数値を収束させる → それでも
  残る差が物理の欠落なら、その物理を足す**、です。
- 前段では、コストとの兼ね合いで適応的ルンゲ・クッタ法を活用します
  (細かくできない格子で振動と破綻を抑える道具であって、収束の代わり
  ではありません)。後段では非静水圧補正を加えることになりますが、
  こちらも計算時間が 1.5〜2 倍になるので、適用条件を見極める必要が
  あります。分散が効くのは前面の幅が水深と同程度のときだけで、この例題は
  水深 1 m に半径 15 m・高さ 1 m の山なので前面で効きますが、背後の
  斜面(r < 32 m)は全ケースが重なっています。沖合の津波(波長数十 km、
  水深数 km)や洪水氾濫のように前面の幅が水深よりはるかに広い計算では、
  物理分散は働かないので静水圧の収束解が正解です。そこで前面に振動が
  見えたら、それは数値分散(離散化の誤差)であって物理ではないので、
  非静水圧補正を足すのではなく、格子と時間刻み(と適応的ルンゲ・クッタ法)で
  消すべきものです。非静水圧補正の適用条件と設定は [ユーザーガイド](../../docs/users_guide/swflow.md) の
  非静水圧補正の項を参照してください。
