# 境界条件(m_boundary)再設計プラン (boundary_plan.md)

計算領域外縁4辺の境界条件、辺上区間の流入・流出境界、領域内部の
湧き出し・吸い込みを指定可能にするための設計検討。
**本書は実装前の議論用ドラフト**であり、合意した決定事項は
developer.md へ転記し、本書は実装の進行に合わせて消し込む
(handoff.md と同じ運用)。

現行の湧き出しモデル(m_boundary / list_boundary)との互換性は
無視してよい(発注者合意済み)。

---

## 1. 現状の正確な把握

### 1.1 暗黙の境界条件の実体(コード根拠)

外縁の境界処理は明示的には存在せず、次の2つの機構の重ね合わせで
「結果的に不透過」になっている。

1. **x 番兵**: `g%x(0:nx+1, 0:ny+1)` が領域外=0 で初期化され、
   カーネルは近傍セルの `x <= 0` でフラックス計算をスキップする。
   これにより格子枠の外へのフラックスは常にゼロ(不透過は保証される)。
2. **添字ガード**: momentum(calc_kth_momentum)、continuous、
   restore_uvmn の3箇所に同型の
   `if (in <= 1 .or. in >= g%nx .or. jn <= 1 .or. jn >= g%ny)` があり、
   **近傍セルが最外周リング(i=1, i=nx, j=1, j=ny)にあるエッジ**を遮断する。

このガードは近傍側の添字のみを見るため、エッジ所有規則
(k=1..4 =「東・北側のセルが西・南向きエッジを所有」)と合成すると
**W/S 辺と E/N 辺で非対称**な状態になっている:

- **列 i=1・行 j=1**: 完全に孤立。エッジ (1,j)-(2,j) の所有者 (2,j) から
  見た近傍が in=1 でガードに掛かるため、内部と一切交換しない。
- **列 i=nx・行 j=ny**: 部分的に接続。エッジ (nx-1,j)-(nx,j) の所有者は
  リング側の (nx,j) で、その近傍 in=nx-1 はガードに掛からないため
  **このエッジは生きている**。ただしリング内の相互接続(列 nx の縦
  エッジ、行 ny の横エッジ)は遮断される。具体的には列 nx のセルは
  k=1(斜め), k=4(横) の2本のみ、行 ny のセルは k=1,2,3 の3本のみで
  内部と接続する。
- さらに boundary_h は窓内の全有効セルに降雨を加えるため、
  **孤立した列 i=1・行 j=1 のセルには降雨が蓄積し続け、貯留量 S にも
  計上される**(現状の観察。実害は小さいが把握しておくべき挙動)。

まとめ: 「不透過」自体は成立しているが、境界面の位置が
W/S(リングの内側の面)と E/N(リングの外側の面)で異なり、
最外周セルの扱いも辺によって違う。**4辺の境界条件を定義する前に、
この非対称の解消(境界面の正規化)を行うべき**(§4.3)。

### 1.2 接線方向の扱い(slip/nonslip)

現状は壁面に接線方向の拘束を与えていない(壁面摩擦なし)。
最外周に沿う流れは通常のセル間交換で計算され、壁を横切る斜め
フラックスだけが遮断されるので、実質は「斜め成分を欠いた free-slip」
に相当する。厳密な slip/nonslip の指定は、8近傍コロケート格子の
斜めフラックス配分(仮想8角形の辺長 l8x/l8y)を境界セルで可変に
する必要があり、**当面のスコープ外とする**(発注者方針)。
簡易不透過=「境界面を横切る全フラックス(斜め含む)をゼロ」で確定。

### 1.3 現行 m_boundary の構造(残すべき分業)

現行の湧き出しモデルは書き直すが、**階層の分業は良い形**なので継承する:

- **list_boundary**: namelist を読むだけ(層契約。developer.md §12)。
- **m_boundary**: 解釈・検証・時系列補間。makebdc が毎ステップ
  「現時刻の値」(b%srcq)を用意する = **データ供給者**。
- **m_swflow_XX**: 場への適用(boundary_h が h1 に加算)= **適用者**。
  スキーム固有の離散化はスキーム側が持つ。

この「m_boundary = スキーム非依存のデータ供給、m_swflow = 離散化適用」
の分業は、辺境界でも同じ形が成立する(§4.4)。

### 1.4 方角と添字の対応(正本の確定が必要)

m_georef の正本は「北西隅セル外縁」(yul)で、緯度計算
`phi = yul - 0.5*ny*csy` から **j の増加方向は地理的に南向き、
つまり j=1 が北端行、j=ny が南端行**(ラスタの行順のまま格納)。
一方 m_parallel などのコメントは小さい j 側を「南」と呼んでおり、
これは**添字方向の比喩であって地理方位と逆**。

ユーザー向けの「東西南北」ラベルを採用するなら、正本定義を
**西= i=1、東= i=nx、北= j=1、南= j=ny** として developer.md に明記し、
既存コメントの「南北」は添字比喩である旨の注記を添える
(コメントの一括改稿はしない。誤解しやすい箇所だけ)。

## 2. 要件の整理と段階

| 段階 | 内容 | モデル |
|---|---|---|
| Phase 0 | 境界面の正規化(§1.1 の非対称解消) | — |
| Phase 1 | 4辺独立の 不透過(壁面)/ 透過(流出)指定+湧き出しの再編 | 簡易流出(段落ち) |
| Phase 2 | 流出の高度化 | 長波近似の放射(透過)境界 |
| Phase 3 | 辺上の区間流入境界(複数区間、流量時系列 Q(t)) | 体積ソース注入 |
| Phase 4 | 辺上の区間流出境界(複数区間、水位時系列 η(t)) | 水位規定(ゴースト水位) |

- slip/nonslip 指定はスコープ外(§1.2)。
- 内部湧き出し・吸い込みは Phase 1 で再編(複数点対応・負値=吸い込み
  を許す設計にしておく)。
- 検証規準は既存規律のまま: **Phase 1 以降は「機能無効時に既存
  reference とビット一致」が合否判定**。Phase 0 のみ挙動変更を含む
  (§4.3)。

## 3. 機能族の整理(設計の土台)

境界条件は性格の異なる **3つの機能族** に分かれる:

1. **辺境界(edge)**: 4辺それぞれに1つの型(wall / outflow / …)。
   位置指定は不要(辺全体)。時系列は当面不要(放射境界の基準水位で
   将来必要になりうる)。適用はフラックス離散化の内側。
2. **区間境界(segment)**: 辺+区間 [a1, a2] +時系列(Q(t) または η(t))。
   複数区間を独立指定。適用は「セル集合への注入」(流入)または
   「ゴースト水位の規定」(流出)。
3. **内部ソース(source)**: セル集合+時系列 Q(t)(負値=吸い込み)。
   現行湧き出しの再編。

重要な観察: **区間流入(Q(t) 指定)は内部湧き出しの一般化**である
(どちらも「セル集合に体積を配る」。違いは位置の指定方法だけ)。
一方、**区間流出(η(t) 指定)は場を規定する別種**で、辺境界の
放射モデルに近い。したがって実装の共有関係は
「source ≒ segment流入」「edge放射 ≒ segment流出」となり、
この2系統を意識して型と手続きを設計する。

## 4. 設計論点と選択肢

### 4.1 モジュール構成

- **案A: 単一モジュール**(現 m_boundary を再編し、3族を1ファイルに)
  - 利点: 配線が今のまま(m_main は t_boundary 1個)。族間で共有する
    時系列補間(現 get_srcval)を自然に共用できる。
  - 欠点: Phase 4 まで進むと1ファイルが肥大する。
- **案B: 前面+族別モジュール**(gwflow 様式の通常モジュール分割)
  - m_boundary は前面(t_boundary の器と init/makebdc/dispose の配線)。
    族の実装は m_boundary_edge / m_boundary_segment /
    m_boundary_source が持ち、t_boundary は族別派生型
    (t_bound_edge 等)を成分に持つ。
  - 利点: 族ごとに独立に成長できる。gwflow(前面+モデル実装)と
    同じ流儀で読み手に馴染む。
  - 欠点: Phase 1 時点ではファイル数だけ増える。
- **案C: submodule 分割**
  - **不採用**。submodule ペアは「同一インターフェースの排他切替を
    Makefile で選ぶ」ためのイディオム(developer.md §12)。3族は
    排他でなく**加算的な重ね合わせ**であり、切替の必要がない。
    CLAUDE.md の様式論でも「加算的なプロセス群は独立フラグの
    重ね合わせ方式」に該当する。

**推奨: Phase 1 は案A で開始し、型だけ族別に分けておく**
(t_boundary の成分を t_bound_edge / t_bound_source に分離)。
Phase 3 で segment 族が入る時点で案B のファイル分割に移行する。
型を最初から族別にしておけば、分割はルーチンの引っ越しだけで済む。

### 4.2 namelist 構成

- **案a: 単一グループ &list_boundary に全部**
  - 欠点: 族ごとに意味の違う変数が混ざり、将来の変数追加のたびに
    1グループが膨らむ。不採用。
- **案b: 1ファイル(fn_boundary)+族別グループ**(推奨)
  - `&list_bound_edge`、`&list_bound_source`、将来
    `&list_bound_inflow`、`&list_bound_outflow` を同じファイルに書く。
  - 前例あり: fn_gwflow の &list_gwflow + &list_gwflow_bucket
    (共通+固有グループの同居。読まれないグループは無視される)。
  - **グループ不在=その族なし**とする。namelist の探索失敗は
    iostat<0(EOF)で検出できるので、「不在は正常、構文エラー
    (iostat>0)は par_stop」で区別する。この判定を list_boundary の
    共通ヘルパーに一本化する。
- **案c: 族ごとに別ファイル(fn_bound_edge 等)**
  - t_sysparam の fn_* が増殖し、param.txt も散らかる。不採用。
  - なお fn_boundary 1本のままなので t_sysparam の変更は不要。

複数区間・複数点の指定方式は、**配列添字方式**
(`bd_val(:,k,iseg)` のような3次元 namelist 配列+有効数の番兵判定)
を推奨する。namelist グループの繰り返し出現(同名グループを
ループで順読みする)でも書けるが、プロジェクト内に前例がなく、
処理系依存の挙動(グループ探索の巻き戻し)を検証するコストに
見合わない。現行 list_boundary・list_precip(prval)と同じ
添字方式が読み手にも書き手にも馴染む。

### 4.3 Phase 0: 境界面の正規化(挙動変更を含む)

§1.1 の非対称を放置したまま「4辺の境界条件」を定義すると、
「壁がリングの内側にある辺と外側にある辺」が混在し、流出辺の
定義位置も辺ごとに変わってしまう。先に境界面を統一する:

- **添字ガード(3箇所)を撤廃し、遮断は x 番兵に一本化する。**
  境界面の定義は「有効セルと x=0(領域外・無効)セルの間の面」となり、
  格子枠上では 4 辺とも「最外周セルの外側の面」に統一される。
- 配列範囲の安全性は確認済み: エッジ配列は (0:nx) を確保しており
  i=1, nx のエッジ添字は範囲内。近傍参照は x 番兵(0:nx+1 確保)が
  先にガードするため h/z の帯外読みも起きない。
  ただし**確保範囲に触れる認識で -fcheck np>=2 を最適化ビルドより
  先に回す**(規律3)。
- **これは挙動変更**(これまで死んでいた列 i=1・行 j=1、リング内
  相互接続エッジが生きる)であり、**等価変換とはコミットを分ける**
  (規律4)。有効域が格子枠に接していないケース(nodata 縁のある
  実地形)はビット不変のはずで、枠まで有効な合成地形ケース
  (wave 等)は結果が変わりうる。reference 不一致が出た場合は
  規律1に従い報告・停止し、人間の目視確認後に基準更新する。
- 代替案(不採用): ガードを保ったまま辺ごとに現状の面位置で BC を
  定義する。実装は最小だが、非対称仕様が恒久化し、区間境界
  (Phase 3/4)の位置定義も辺ごとに歪む。負債が複利で増えるだけ。

### 4.4 適用アーキテクチャ(データ供給と離散化適用の分業)

§1.3 の分業を全族に拡張する:

- **m_boundary(データ供給者)**: namelist の解釈・検証、位置解決
  (区間→セル集合。初期化ゾーン2の全域マスクで解決)、時系列補間。
  makebdc が毎ステップ「現時刻の値」を t_boundary に用意する。
  スキーム(ENC/STG)には依存しない。
- **m_swflow_enc(適用者)**: t_boundary の記述子を読んで離散化を
  適用する。辺タイプはスキームの他の f_* フラグと同様に init で
  モジュール変数へ写す(ホットループでの間接参照を避ける)。

ENC カーネルの改修点(Phase 1、辺境界):

- **wall(既定)**: Phase 0 後の状態そのもの。追加コードなし。
  既定値で全カーネルが Phase 0 とビット一致すること(合否判定)。
- **outflow(簡易)**: 開いた辺の最外周セルの「外向き面」に流出
  フラックスを与える。離散化は2案:
  - **案(i) シンク方式**: boundary_h の中で、開辺セルの h1 から
    流出量を直接減算する(エッジ配列に触れない)。
    - 利点: カーネル3箇所に一切触れない。実装最小。
    - 欠点: 流出がセル平均流速 u,v・流量 m,n・record のフラックス
      測線に現れない。放射境界(Phase 2)はエッジの uv が必要に
      なるため、いずれ案(ii) に作り直すことになる。
  - **案(ii) エッジフラックス方式**(推奨): momentum の後に専用の
    境界パス(境界セルのみの小ループ)で外向き面の uv/mn1 を書き、
    continuous / restore_uvmn の近傍スキップ条件に「枠外近傍でも
    開辺なら取り込む」分岐を追加する。
    - 外向き面のエッジ格納スロットは既存配列に存在する
      (例: 東面 k=5 は ke=4, (ie,je)=(i,j) に格納)ので確保変更は不要。
    - 利点: 流出が通常のフラックスとして u,v,m,n・水収支・record に
      乗る。Phase 2 の放射境界は境界パスの式の差し替えだけで済む。
    - 注意: **momentum / continuous / restore_uvmn の3箇所の条件を
      必ず同時に整合させる**(restore_uvmn の不整合はリスタートの
      ビット一致検証で検出できる)。機能無効時は追加分岐が評価
      されないよう、無効時は現行と同一の経路になる形で書く。
- **簡易流出の式**: 段落ち(自由越流)式を推奨。
  `uve = (2/3)^{3/2} sqrt(g h)`, `mne = uve h`。
  f_rivermouth_drop(rivermouth_drop)と同型で実績があり、
  ゴースト状態を持たない。適用は面の法線方向のみ
  (E/W 辺は k=4/5 面、N/S 辺は k=2/7 面)とし、**斜め面は
  wall と同じくゼロのまま**(簡易モデルの定義として明記)。
  勾配ゼロ(ゴースト)方式は緩流時に反射が小さい利点があるが、
  ゴースト状態の導入が必要で、どうせ Phase 2 の放射境界が
  その役割を担うため、Phase 1 では採らない。
- **開辺の最外周セルの降雨蓄積**(§1.1)は Phase 0/1 では触らない
  (壁辺は従来どおり。開辺は流出面から抜けるので自然に解消する)。

Phase 2(放射境界)の腹案: 長波近似の特性線から
`uve = sqrt(g/he) (η - η_out)`(η_out は基準水位。namelist 指定、
将来は時系列)。境界パスの select case に1肢足す形で入る。
潮位(m_tide、未実装)と意味が重なるため、実装時に
「η_out の供給源を m_tide に置くか m_boundary に置くか」を再論する。

Phase 3(区間流入)の腹案: m_boundary が区間をセル列に解決し、
Q(t) を面積按分した体積を boundary_h の湧き出しと同じ口から注入する
(source 族と同じ適用機構。§3 の観察どおり)。
Phase 4(区間流出)の腹案: 区間のゴースト水位を η(t) で規定し、
境界パスが水位差から面フラックスを計算する(放射境界の一般化)。

### 4.5 STG の扱い

STG は比較検証用に凍結(developer.md §7)。**辺タイプが既定
(全辺 wall)以外なら STG は init で par_stop** する明示ガードを置く
(「黙った劣化」の防止)。Phase 0 の正規化は ENC のみに適用し、
STG のカーネルには触れない(STG の暗黙境界は現状のまま)。
→ 論点: Phase 0 で ENC と STG の既定挙動が枠際で微差を持つことを
許容するか(比較は有効域が枠に接しないケースで行う運用で回避可能)。

### 4.6 MPI 設計

- 適用は全て owner-compute(場を変更する処理は所有ランクがローカルに
  適用。developer.md §11)。**時間ループ内に新たな collective は
  発生しない**。
  - E/W 辺: 全ランクが自帯行で適用。
  - N/S 辺: 行 j=1 / j=ny を所有する端ランクのみ適用(判定は
    dcp%js/je との交差で書く。全ランクが同じコードを実行し、
    交差が空なら自然に no-op)。
  - 区間・ソースのリスト構築と検証は全ランク冗長(初期化ゾーン2の
    全域マスクで位置解決。現行 srccell と同じ)。
- 境界パスが書く外向き面のエッジ行は自帯範囲内(N/S 辺は端ランクの
  je/js 行)なので、par_edge_merge の対象行(js-1, je 界面)への
  影響は「行 je が北端 ny の場合」だけ確認が要る。esync マスクは
  dje 由来で変更なし。
- 検証は規律どおり: np=1,2,4 が逐次 reference に ULP=0、
  確保・範囲に触れる Phase 0 は -fcheck np>=2 を先に(規律3)。

### 4.7 水収支・記録(将来の宿題として明記)

流出辺・区間流出は領域の貯留 S を減らす。m_record の水収支
(未実装の ss/ss0)を実装する際、境界流出の積算は
**par_sum_rows 型の決定的総和**で集約対象リスト(developer.md §4)に
加える。Phase 1 では Log の S が減ることの物理的妥当性確認のみ行う。

## 5. 推奨案の全体像

### 5.1 型スケッチ(Phase 1 時点)

```fortran
! 辺境界の型コード(m_boundary が公開する定数)
integer, parameter :: e_bc_wall = 0      ! 不透過(既定)
integer, parameter :: e_bc_outflow = 1   ! 簡易流出(段落ち)
! 将来: e_bc_radiation = 2               ! 長波放射

type t_bound_edge                ! 辺境界(4辺ぶんを配列で保持)
```

## 8. Phase 0 実施記録(2026-08-02)

Phase 0 を実施した(コミット2件: TVD ±2 ステンシルの枠外読み修正、
添字ガード撤廃)。検証環境: gfortran 13.3 / OpenMPI(apt 版 MPICH は
developer.md §3 既知の PMI 不整合バグを par_init のアサーションが
検出したため OpenMPI に切替。記録どおりの症状と対処)。

- **-fcheck=all np=2 を最適化ビルドより先に実施**(規律3):
  chichibu・wave・wave(TVD有効)とも境界検査エラーなし。
- **既存 reference への影響なし**: wave・chichibu とも逐次および
  np=1,2,4 で変更前とバイト一致(chichibu は有効域が枠に接しない、
  wave は 8 秒では波が枠に達しないため)。**reference 更新は不要**。
- **新挙動の直接検証(120 秒 wave。既存回帰は枠を励起しないため追加)**:
  - 変更後: 120 秒完走。4辺の枠セル全てが流動に参加し(最終水深
    0.92〜1.27 m)、S は全表示行で 1.02101897412350 に不変
    = **不透過性(質量保存)が 15 桁で厳密に維持**。
  - 変更前: 波が枠に到達した t≈13 s から **S が増加(1.0210→1.0302、
    境界で質量創生)**し、t=15.25 s に発散して異常終了
    (h_max 111 m、流速 250 m/s 超)。
  - 原因は §1.1 の非対称そのもの: E/N 枠エッジは momentum が
    フラックスを計算する(所有者=リング側セル)一方、内側セルの
    continuous は添字ガードで受け取りを拒否するため、リングセルの
    水だけが増えて内側セルの水が減らない=質量が創生され、
    水位差の増幅で発散に至る。
  - つまり Phase 0 は境界面の正規化であると同時に、**「水が東・北の
    格子枠に到達すると質量保存が破れて発散する」実バグの修正**である。

未決事項 1(Phase 0 の実施可否)はこれで解消(旧挙動の温存に
合理性はない)。TVD 修正コミットが直した ±2 ステンシルの枠外読みも
同根の潜在バグ(ガードが近傍±1 しか制限せず、±2 参照が確保範囲を
外れる)で、TVD 有効かつ枠際が湿潤のケースで発現しうるものだった。
