# 津波の一方向ネスティング設計案(nesting_plan.md)

**状態(2026-10-08): 設計案。実装前。** 要合意事項は §12。合意後に
実装し、規約の正本は developer.md の新節へ、利用者向けは
users_guide/boundary.md・record.md と utils/nest_bc/README.md へ移す。
本書は設計解説と実績の記録として残す(bedmotion_plan.md と同じ運用)。

## 0. 結論(要約)

- 目的: 深海の断層・地滑りによる発生から沿岸の局所的な遡上までを、
  粗い親格子と細かい子格子の **一方向ネスティング**(親 → 子)で
  つなぐ。親は広域を粗く、子は湾や市街地を細かく解く。
- **同一プロセス内の複数インスタンス化は行わない**(理由は §1)。
  親と子は **別ランの連鎖**(逐次でも MPI でも)で、親が子の境界に
  必要な水位・流速の時刻歴をファイルに書き、子がそれを境界条件として
  読む。必要なコード変更は次の 3 点に集約される。
  1. **子側の境界条件**: 既存の長波放射境界(`e_bc_radiation`)を
     Flather 型の「入射+放射」境界に一般化する。境界セルごとに外部状態
     (η_e, u_e, v_e)(t) を与え、面フラックスを
     `u_n = u_n,e + √(g/h)·(η − η_e)` で決める。外部状態が一定・
     流速ゼロなら現行の放射境界と同じ式に退化する。
     設定は fn_boundary の新しい族 `&list_bound_nest`。
  2. **親側の出力**: 指定セル群の e・u・v を一定間隔で書く記録
     (fn_record の `fn_nest_cell`・`dt_nest`)。
  3. **前処理ユーティリティ utils/nest_bc**: 子格子の地理参照から
     「親のどのセルを記録すべきか」を求め(prep)、親の出力を子の
     境界セル列へ空間補間して子の入力ファイルにする(make)。
     親 ↔ 子 の再サンプリングは前処理側に置く(方針 11・12)。
- 無効時はゼロ追加(配列未確保・分岐 1 個)。有効時の追加コストは
  境界セル数のオーダー。通信なし(全ランク冗長読み)。私有状態の save は
  不要(時刻だけの関数)。
- 双方向ネスティングと BMI によるオンライン結合は対象外(§2・§10)。
  本案の `&list_bound_nest` の配列は、将来 BMI の入力変数にそのまま
  昇格できる(物理を変えずに結合経路だけ足せる)。

## 1. 位置づけと方針適合

### 1.1 なぜ複数インスタンス化をしないか(2026-10-08 の議論の記録)

- 単一インスタンスなのは m_main の `enc` だけではない。developer.md §12 の
  慣習(状態は `xx_mod` 系モジュール変数、private 手続きは引数で受ける)
  どおり、物理モジュールの私有状態はほぼ全てモジュール変数である:
  m_swflow_enc の約 100 個(フラグ群・`sx_mod`・堤防・破堤・河道幅・NH)、
  submodule の `tx_mod` / `td_mod` / `nh_mod` / 境界配列、gwflow 系の
  `gwb/gwc/ga/glt/gl2/gp/fro`、geomorph の `crp/flv/dbr/spl/bsl/wrk`、
  glacier・lavaflow・saltwater・intercept、m_ffactor のテーブル、
  m_output の `wk_out`。並列層の `dcp`(帯分割)もモジュール変数で、
  親子は ny が違うため分割・ハロ・par_sum_rows・gather の全てを
  インスタンス別にしなければならない(MPI_COMM_WORLD 直書きの段4課題も
  同時に顕在化する)。
- 共有ライブラリを同一プロセスに 2 回ロードしても同じグローバルを
  共有するため、BMI 側の工夫だけでは複数インスタンスにならない。
- 全モジュール状態を派生型に包む改修は等価リファクタ(ULP=0 で検証
  可能)だが規模が全コード改修級で、ホットループのモジュール変数が
  派生型成分参照に変わるため性能の再確認が要る。developer.md §13 が
  記録する flang の型記述子・private ホスト結合の不具合は、まさに
  「状態を型に包む」箇所で出ている。
- ネスティングに必要なのは格子間の **データ経路** であって **プロセスの
  共有** ではない。一方向結合では親の dt が子より大きく、境界リングの
  時系列はファイルで十分小さい。逐次ランの連鎖で物理的に同じ結果になる。
- 結論: 方針 6(過度に複雑化しない)に照らし、複数インスタンス化は
  「必要になってから」のまま(bmi_plan.md §6 段4)。§12 の規約と m_main の
  `t_encflow` で入口は確保されており、モジュールを触るついでに
  `xx_mod` を `t_*` 成分へ漸進移設する(t_swflow の手続きポインタ・
  sp の t_state 統合と同じ流儀)のは安価で価値があるが、一斉改修は
  しない。

### 1.2 方針 §0 との整合

- 方針 2(ラスタ純化): 境界セル列は「セル番号の一覧」、時刻歴は
  「時刻 × セルの行列」で、ベクトル表現を持ち込まない。
- 方針 5(水平は SWE まで): Flather 条件は長波の特性線そのもの。
- 方針 7・8: 有効化は `&list_bound_nest` の有無。無効時ゼロ追加。
- 方針 11・12: 親格子 → 子格子の再サンプリング(地理参照・双線形補間)
  は前処理ユーティリティに置き、本体は「自分の格子のセル別時刻歴」を
  読むだけ。bedmotion の「変位は前処理 fault2disp、本体は時刻歴を読む」と
  同じ線引き。
- 方針 9(単一ソース): 親も子も通常の encflow / encflow_mpi。ランク数は
  それぞれ独立に選べる(MPMD 不要)。

### 1.3 既存の道具との関係

- boundary_plan.md §14 は「津波の入射はフラックス規定でなく、将来の
  『入射+放射』境界(または §7 のネスティング型)で扱う」としていた。
  本案がその将来枠を埋める。
- stage 族(水位規定セル群 = 造波板)は規定セルの水位を固定するため
  反射波が境界で再反射する。ネスティング境界には使わない。
- 現行の放射境界の基準水位 `bc_eta_cell`(セル別・静的)は、本案では
  「時間変化する外部状態」の特殊形になる。コードもその形で一般化する。

## 2. スコープ

含む:
- 親 → 子の一方向(子の結果は親へ戻さない)。
- 子の外縁 4 辺のうち放射型(`f_bc_* = 2`)の辺上のセル。一辺の一部だけ
  の指定も可(残りは従来の静的基準水位)。
- 外部状態は水位 η_e(必須)と流速 u_e, v_e(任意。東・北が正の
  物理座標系)。
- 親の記録は指定セル群の e・u・v(セル中心量)を一定間隔で書く。
- 前処理は Fortran の独立プログラム(utils/。libencflow.a の m_georef・
  m_fileio を使う)。

含まない(§10 も参照):
- 双方向ネスティング、子の境界での質量・運動量の親へのフィードバック。
- 同一プロセス内の親子同時実行(§1.1)。
- 親子の時間軸のずれ(t0 は同一とする)。
- STG(辺境界条件は凍結方針で非対応)。
- 海セル(sw > 0、潮位強制)上の境界セル。子の境界は「解く海」
  (f_htype = 2 等)で置く。

## 3. 定式: Flather 型「入射+放射」境界

### 3.1 連続系

境界の外向き法線 **n** について、長波の特性線から(Flather 1976)

    u_n = u_n,e + √(g/h) · (η − η_e)

- η: 子の境界セルの水位(z + h)、h: 子の水深、u_n: 境界面の外向き
  法線流速(子が決める未知量)。
- η_e, u_n,e: 外部(親)の水位と外向き法線流速。
- 子の解が親の解と一致していれば u_n = u_n,e(親のフラックスをそのまま
  通す)。子の内部で生じた擾乱(η − η_e)は放射で外へ抜ける。
- u_n,e = 0、η_e = const は現行の長波放射境界そのもの。

η_e だけを与え u_n,e = 0 とすると、進行波は境界で振幅がおよそ半分に
なる(境界の関係式が入射波と放射波を区別できないため)。**津波の
ネスティングでは流速も与えること**を利用者向け文書に明記する。流速なしの
使い方は、潮位のようにゆっくり変わる基準水位の指定に限る。

### 3.2 ENC 配置への適用(既存の放射境界の拡張)

現行(m_swflow_enc_bc の put_bc_faces、`e_bc_radiation` 分岐):

    wn   = max(n8(k)·r, 0)                 ! 面 k への射影(r = 辺の外向き法線。幅河道の終端は河道の流向)
    uve1 = √(g / max(h, dv)) · (z + h − η_r) · wn
    mne1 = uve1 · h(σ 有効時は断面積換算)

を、nest 族が有効な境界セルでは

    une  = u_e · nsx + v_e · nsy             ! 外部流速の辺の外向き法線成分(内部座標系。v は j 増加 = 南が正)
    uve1 = (une + √(g / max(h, dv)) · (z + h − η_e)) · wn

とする(括弧の内側で和をとってから射影する。3 面の Σ l8·wn = dx なので
面合計のフラックスは (une + …)·h·dx = 自然幅あたり)。

- 角の斜め面・開口の規則(法線+斜め = 辺全長、両辺 open、後に処理される
  N/S 辺が有効)は既存のまま。
- 乾いたセル(h < dd)は現行どおりフラックスゼロ(§10 の割り切り)。
- 過大流出の抑制(体積ベース)・σ 断面換算・河道幅係数は既存の
  共通処理をそのまま通す。
- 無効時は既存の式がそのまま走る(分岐 `if (have_nest)` の外側は不変)。
  nest 有効でも、一覧にないセルは静的な `bc_eta_cell` を使う。

### 3.3 NH(非静水圧)との関係

`nh_bc_margin`(強制境界から静水圧のままにするセル数)は辺境界型で
判定している。nest 族は放射辺の上に乗るので追加の扱いは不要。実装時に
nh の境界判定が辺型だけを見ていることを確認する。

## 4. 入力形式(子側: fn_boundary の `&list_bound_nest`)

```
&list_bound_nest
  fn_nest_cell = "nest/cells.txt"     ! 境界セル一覧(i j。dir_data 相対)。必須
  fn_nest_eta  = "nest/eta.txt"       ! 水位 η_e の時刻歴行列 (m)。必須
  fn_nest_ux   = "nest/ux.txt"        ! 流速 x 成分(東が正。m/s)。任意
  fn_nest_uy   = "nest/uy.txt"        ! 流速 y 成分(北が正。m/s)。任意(ux と対で指定)
  f_nest_interp = 1                   ! 時間補間 (1: 線形, 0: 階段)
  nest_tscale = 1.0                   ! 時刻列の単位 (s。60 で分)
/
```

- グループ不在 = 族なし(他の族と同じ iostat < 0 判別)。
- **セル一覧**: 1 行に `i j`(read_cell_file2 と同じ書式)。各セルは
  外縁上(i = 1 / i = nx / j = 1 / j = ny)にあり、属する辺の型が
  放射(`f_bc_* = 2`)でなければ par_stop。角セルは属する 2 辺の両方に
  登録する(inflow 族の「角セルは辺ごとに複製」と同じ)。x <= 0 や
  sw > 0 のセルは par_stop(§2)。
- **時刻歴行列**: 先頭の `#` 行は注釈として読み飛ばす。データ行は
  `t v_1 v_2 … v_N`(N = セル数、列順 = 一覧の順)。t は nest_tscale
  単位で昇順。列数不一致は par_stop。表の最初の時刻より前は先頭の値、
  最後より後は末尾の値を保持(interp_series・bedmotion と同じ)。
- 3 ファイルの時刻列は同一でなければならない(make が同時に書く。
  本体は行ごとに t の一致を検査する)。
- 単位は SI、水位は z と同じ標高基準。流速は物理座標系(東・北が正)で、
  内部の v(j 増加 = 南が正)への符号変換は本体の init で 1 回だけ行う
  (BMI §60 と同じ「向きの吸収は翻訳層の責務」)。

## 5. 離散化・時間補間・並列規約・restart(子側)

### 5.1 データ供給(m_boundary)

- `t_bound_nest`(t_boundary の新成分。§13 のデフォルト初期化):
  ncell、cell(1:2, ncell)、side(ncell)(角は複製)、現時刻の
  eta(ncell)・une(ncell)(外向き法線流速。ux/uy 未指定ならゼロ)、
  時刻歴は **直前・次の 2 行をストリーム読み**(ta, va / tb, vb。
  bedmotion の da/db と同じ)。行列全体はメモリに持たない(数千セル ×
  数万行でも定数メモリ)。
- `m_boundary_makebdc` が毎ステップ現時刻の eta・une を線形補間する
  (全ランク冗長。O(ncell)。collective なし)。
- **init 時に t0 で補間初期化しておく**(stage 族の落とし穴と同じ:
  swflow init の cold start が boundary_uvmn を 1 回呼ぶ時点で makebdc は
  未実行)。
- une は side ごとに符号付きで前計算する(W: −ux、E: +ux、N: −uy_int、
  S: +uy_int。uy_int = −uy は内部座標系の v)。

### 5.2 適用(m_swflow_enc_bc)

- bc_init: have_nest = (b%nnest > 0)。有効時のみ `bc_une_cell(idx, sd)` を
  確保し、`bc_eta_cell` の該当エントリを nest が毎ステップ上書きする
  印(`bc_nest_cell(idx, sd)`、logical)を立てる。
- boundary_uvmn の節 1 の冒頭で、have_nest なら b%nest の現時刻値を
  `bc_eta_cell` / `bc_une_cell` へ写す(ncell 回の代入。全ランク同値)。
- put_bc_faces の放射分岐で `bc_nest_cell(idx, sd)` なら §3.2 の式。

### 5.3 MPI

- 全ランクが同じファイルを冗長に読み、同じ値を持つ(精度・順序が同一
  なのでビット同値)。東西辺の共有行 js−1 の冗長書きも同じ値から
  計算されるため、ランク数不変性は現行の放射境界と同じ論法で成立する。
- collective は増えない。実行判定(have_nest)は全ランク同値。

### 5.4 restart

- 私有状態は save しない(時刻だけの関数)。restore 時は init が表を
  復元時刻まで読み進める。restart 往復のビット一致が検証項目。

### 5.5 無効時

- `t_bound_nest` の配列は未確保、boundary_uvmn の追加は logical 1 個の
  分岐のみ。既存 reference とビット一致が合否。

## 6. 親側の出力(fn_record の nest 記録)

```
&list_record
  ...
  fn_nest_cell = "nest/parent_cells.txt"   ! 記録するセル一覧(親格子の i j。dir_data 相対)
  dt_nest = 5.0                            ! 記録間隔 (s。dt の整数倍に丸めて表示)
/
```

- 出力は `result/nest/` に `eta.txt`・`ux.txt`・`uy.txt` と、一覧の
  コピー `cells.txt`。書式は §4 の行列と同一(`#` ヘッダに nx, ny, dx, dy,
  地理参照、t0、列数、セル一覧の由来を書く)。t の単位は秒。
- 値は e = z + h(乾いたセルでは z)、u・v はセル平均流速で、uy は
  北正へ符号変換して書く(BMI の get_value と同じ規約)。
- 実装は m_record の点集約イディオム(全ランクが所有セルを埋める →
  par_reduce_points で rank0 → rank0 が書く)。セル数は動的確保
  (probe の ncellmax = 1000 に縛られない)。
- 記録開始・終了は probe と同じ `ist_recd/iet_recd` の窓に従う。
  ファイルは probe と同じ `status='replace'`(restart で上書き。
  連結は利用者側。既存の probe と同じ扱い)。
- 無効時(fn_nest_cell 未指定)は配列未確保・呼び出しなし。

## 7. 前処理ユーティリティ utils/nest_bc

Fortran の独立プログラム(fault2disp と同じ建て付け。libencflow.a の
m_georef・m_fileio を使う)。2 つのサブコマンド。

- `nest_bc prep <parent.hdr|tif> <child.hdr|tif> [--open w,e,n,s]`
  - 子格子の外縁のうち開く辺(既定: 4 辺)の境界セル列を作る
    → `child_cells.txt`。
  - 各子境界セル中心を親格子座標に写し、双線形補間に要る親セル 2×2 と
    重みを求める → `map.txt`。親に記録させるセルの和集合 →
    `parent_cells.txt`(親の fn_nest_cell)。
  - 子の境界が親の領域の内側(マージン ≥ 2 親セル)にあることを検査。
- `nest_bc make <parent result/nest/> <map.txt> <out dir>`
  - 親の eta/ux/uy を読み、map の重みで子境界セルへ補間して
    `eta.txt`・`ux.txt`・`uy.txt` を書く(時刻列はそのまま)。
  - 親側で乾いた(h < dd 相当)セルが補間点に含まれる場合は警告
    (境界を恒常に湿った水域に置く指針)。
- 座標系: 両格子とも同じ投影座標系(m)であること。地理参照は hdr /
  GeoTIFF から(m_georef)。地理参照がない格子は `--origin` で与える。

## 8. 実行手順(利用イメージ)

```
# 0. 親・子の地形(親 500 m、子 100 m)を用意。子の領域は親の内側
nest_bc prep parent/z.hdr child/z.hdr --open e,n,s        # parent_cells.txt, child_cells.txt, map.txt
# 1. 親ラン(fn_record に fn_nest_cell = parent_cells.txt, dt_nest = 5)
cd parent && ./encflow param.txt
# 2. 親の記録を子の境界へ
nest_bc make parent/result/nest map.txt child/data/nest
# 3. 子ラン(fn_boundary に &list_bound_nest。東・北・南は f_bc_* = 2、西は壁)
cd child && ./encflow param.txt
```

指針(利用者向け文書に書く):
- 格子比は 3〜5(COMCOT 等の慣例)。子の dt は独立に CFL で決める。
- 子の開く辺は恒常に湿った水域に、急な海底勾配・海岸線から離して置く。
- dt_nest は対象波の周期の 1/20 以下(線形補間の誤差)。
- 親は子の領域を含んで粗く解く(一方向なので親の海岸反射が親の解に
  含まれ、それが子へ入る。双方向でないことの既知の性質)。

## 9. 検証計画(CLAUDE.md の規律)

1. **無効時**: wave・chichibu の逐次ビット一致、MPI np = 1, 2, 4 一致、
   BMI ドライバ完走(本体のインターフェース変更なし)。
2. **-fcheck=all np = 2** を nest 有効ケース(静的データあり)で最初に
   通す(新規確保: bc_une_cell・bc_nest_cell・t_bound_nest)。
3. **退化の確認**: 一覧の全セルに一定 η = η_ref、流速ファイルなしの
   nest 入力を与えたランが、放射境界のみのランと Log 一致(une = 0 と
   η_e = η_ref で式が一致。±0 の符号差が出る可能性があるため ULP=0 で
   なく Log の印字一致を合否とする)。
4. **自己ネスティング**(格子比 1:1): 親の部分領域を同じ解像度で切り
   出した子を親の記録で駆動し、子内部のプローブが親と数 % 以内で一致。
   さらに格子比 1:5 で同じ比較(解像度差の分だけ違う)。
5. **ランク数不変**: nest 有効ケースで np = 1, 2, 4 がビット一致。
6. **restart 往復**: 子ランの save → restore がビット一致。
7. **親側**: fn_nest_cell を指定したランの Log が無指定とビット一致
   (記録は純診断)。np = 2 で出力が逐次と一致。

## 10. 既知の割り切り

- 乾いた境界セルはフラックスゼロ(現行の放射境界と同じ)。親が
  潮間帯や遡上域に境界を置く使い方は非対応。将来必要なら inflow 族の
  限界水深床(he = max(h, (q²/g)^{1/3}, dv))の考えを転用する。
- 一方向のみ。子の反射・遡上は親へ戻らない。
- η のみ(流速なし)の入力は振幅がおよそ半分になる(§3.1)。
- 時間補間は線形(階段も可)。dt_nest を十分細かくとるのは利用者の責務。
- 親子の t0 は同一。表の時刻は t0 からの相対。

## 12. 要合意事項

1. 境界条件の型: **Flather 型(η_e と u_n,e の両方)**で、流速は任意
   指定(未指定は u_n,e = 0)。推奨どおり。
2. 名称: 子側 `&list_bound_nest`(fn_nest_cell / fn_nest_eta / fn_nest_ux /
   fn_nest_uy / f_nest_interp / nest_tscale)、親側 `&list_record` の
   `fn_nest_cell` / `dt_nest`。

   bedmotion と同じ「tscale 付きの秒」を津波系の既定とする)。

5. 親側の記録は m_record に置く(点集約イディオムの再利用)。
6. 前処理は Fortran の utils/nest_bc(方針 10 の対象外だが、道具を一つの
   言語・一つのビルドに揃える)。Python 版は作らない。
7. 乾いた境界セルはゼロフラックスのまま(§10)。
8. 複数インスタンス化は見送り、§1.1 を developer.md に記録する。
