# 津波の多段ネスティング設計案(nesting_plan.md)

**状態(2026-10-08 改訂 v2): 設計案。実装前。** 要合意事項は §12。
v1(同日)は「別ランのファイル連鎖による一方向ネスティング」を推奨して
いたが、要件の見直し(§1)を受けて **同一プロセス内の多格子・双方向・
多段ネスティング**を基盤に据える案へ改めた。合意後に実装し、規約の正本は
developer.md の新節へ、利用者向けは users_guide の新章へ移す。本書は設計
解説と実績の記録として残す(bedmotion_plan.md と同じ運用)。

## 0. 結論(要約)

- 目的: 深海の発生から沿岸の局所的な遡上まで、粗い親格子と細かい子格子
  (孫・ひ孫 … 任意の深さ、一つの親に複数の子)を**同一ランで同時に**
  解く。親子の結合は**一方向・双方向を選択**でき、津波分野で使われている
  接続手法(JAGURS・COMCOT・TUNAMI 型の境界帯 Dirichlet、GeoClaw 型の
  湿潤判定付き平均と保存修正、NEOWAVE 型の非静水圧圧力の Dirichlet、
  MOST 型の一方向、Flather 型の放射)を**同じ骨格の上の選択肢**として
  順次実装できる構造にする(§2 で各手法を「基本操作」に分解した)。
- **連結アルゴリズムはすべて ENCflow 本体(Fortran)の m_nest が担う**。
  BMI ドライバ(Python)は格子間の結合に関与せず、ネスト系全体を
  **1 つの BMI component**として扱う(§3.9)。ファイル経由の結合はしない。
- そのために、**同一プロセス内の複数インスタンス化**を基盤として先に
  実施する(§3.2)。v1 で見送った理由(モジュール変数の私有状態が多い)
  は、§12 の「状態は型・private 手続きは引数」を完成させる「所有の明示」を
  主とし、ホットパスがホスト結合で読む 3 モジュールだけ「文脈の付け替え
  (bind)」とすることで解消する(§3.2)。全 MPI ランクが全格子の帯を持つ JAGURS 型の配置とし、親子の
  逐次依存でランクが遊ばない。並列層のコミュニケータは従来のまま
  (段4 の par_comm 抽象化は不要)。
- **受入基準を先に決める**: 格子比 1:1・時間比 1 の自己ネスト(子 =
  親の部分領域)で、子の内部が親とビット一致すること(一方向・双方向
  とも)。補間と帯の設計が ENC の 8 方位ステンシルを完全に覆っている
  ことの証明になる(§9)。
- 段取りは Phase 0(複数インスタンス化=等価リファクタ)→ 1(一方向・
  同一 dt)→ 2(双方向)→ 3(時間サブステップ)→ 4(手法の拡充: Flather・
  保存修正・NH・スカラー場)→ 5(BMI の多格子公開)。各段で CLAUDE.md の
  規律(無効時ビット一致、-fcheck np≥2、np=1,2,4 一致、restart 往復)。

## 1. 要件と判断の変更(v1 → v2)

### 1.1 要件(2026-10-08 合意)

1. 結合はオンライン(ファイル経由は量の点で不可)。将来は双方向。
2. ネストは任意の深さ・一つの親に複数の子。
3. 連結アルゴリズムは ENCflow 側(Fortran)に持ち、BMI ドライバから
   呼べる形にする。Python の保守対象を増やさない。
4. BMI も複数格子・複数インスタンスに備える。
5. 津波分野で使われているネスティング手法を基本的に全て実装できる構造。

### 1.2 なぜ「同一プロセス内の複数インスタンス」に転じたか

v1 §1.1 の事実(物理モジュールの私有状態がモジュール変数、dcp も
グローバル、共有ライブラリの二重ロードは不可)は変わらない。変わった
のは要件であり、代替案はすべて要件 1〜5 のどれかに反する。

| 案 | 評価 |
|---|---|
| A. 別ラン+ファイル(v1) | 一方向のみ。双方向にできない。量が多い。却下 |
| B. 別プロセス+BMI ドライバが配列を運ぶ | 結合の時間順序・補間・平均を Python が担う(要件 3 違反)。逐次版で格子ごとにプロセス。却下 |
| B'. MPMD(格子ごとにランク群)+ 本体内のカプラ(inter-communicator) | 親子は逐次依存(親が 1 歩 → 子が r 歩 → 親へ戻す)なので、どちらかのランク群が常に遊ぶ。逐次ビルドでネストできない。段4 の par_comm 抽象化が前提。却下 |
| C. 同一プロセス内の多格子(全ランクが全格子の帯を持つ) | JAGURS・NEOWAVE・GeoClaw と同じ配置。遊ぶランクがない。逐次でもノート PC で動く。BMI は 1 component。**採用** |

C の代償は複数インスタンス化の工事である。v1 では「全モジュール状態を
派生型に包みカーネルの参照を書き換える」規模を懸念したが、§3.2 の
大半のモジュールは §12 準拠(状態の参照が公開入口に集中)で、状態を型の
成分に移して引数で渡す「所有の明示」が小さな差分で済む。ホットパスが
ホスト結合で多数の変数を読む m_swflow_enc 等 3 モジュールだけを「文脈の
付け替え(bind)」とし、カーネルに触れない(いずれも等価リファクタとして
ULP=0 で検証できる)。developer.md §12 が既に「複数インスタンス化にも
開いた構造」「submodule のモジュール変数は将来派生型に包む改修が要る」と
記しており、その改修を最小形で行うものである。

## 2. 津波モデルのネスティング手法の調査と基本操作への分解

### 2.1 手法カタログ(2026-10-08 調査。ソースを読んだものは「実装確認」)

| モデル | 構造 | 親 → 子 | 子 → 親 | 時間 | 備考 |
|---|---|---|---|---|---|
| **JAGURS**(JAMSTEC。`mod_nest.f90` 実装確認) | gridfile で親子木。多段・複数子。全ランクが全ドメインを分割 | 子の境界帯(ゴースト 2 列+境界 1 列)へ親の **水位 hz とフラックス fx, fy** を 2 点線形補間 | 重なる海域で **fx, fy を点コピー**(c2p_all=0)または **3×3 箱平均**(c2p_all=1。hz も)。境界列は除外。nest_1way=1 で抑止 | 既定は全ドメイン同一 dt。timenest=1 で各ドメイン dt、親の n→n+1 を 1/比 刻みで線形補間 | 分散項(Boussinesq)は c2p_all=1 必須。比は 3 が慣例 |
| **COMCOT 1.7**(Cornell/GNS。`all_grids.f90` 実装確認) | 親子木。12 段までの入れ子ループ | 子の接続 4 辺の **体積フラックス M, N** を親から補間(JNQ)。サブステップ 2 以降は親の運動方程式で n+1 のフラックスを予測し時間線形補間(NEWQ) | 子の **水位 Z を r×r の湿潤セル平均**で親に置換(JNZ。湿潤数が半分超のセルのみ。偶数比では 2 時刻平均) | 時間比は任意整数。順序: 親 MASS → 子(JNQ/NEWQ → MASS → 孫 … → MOMENT → 中間で JNZ) → 親 MOMT | 比 3 が標準 |
| **GeoClaw**(Clawpack。`filval.f90`/`update.f90` 実装確認) | Berger–Oliger AMR(動的パッチ) | 粗セルの h を **η に直してから** min-mod 勾配で補間し η − b で水深へ戻す(well-balanced、乾き処理) | r×r の **湿潤セルの η と h の平均**から h_c = min(h_av, max(η_av − b_c, 0))、運動量は同比率で縮小 | 粗が先、細はサブステップ、時空間補間でゴースト充填 | 保存修正(reflux)は amrclaw の機構。GPU 版は津波では影響小として省略 |
| **NEOWAVE**(Hawaii。Yamazaki+2010 IJNMF、2023 ASCE 多段) | 望遠鏡型・双方向・多段 | 境界で **η・水平流速・非静水圧圧力の Dirichlet** | 双方向(平均) | — | 分散波・段波が格子をまたぐ |
| **MOST**(NOAA/ComMIT) | A/B/C 3 段 | 内側格子は外側格子から境界条件 | **なし(一方向)** | 比 3〜 | 接続境界付近の反射が実務上の注意点 |
| **TUNAMI-N2**(東北大。IOC Manuals and Guides 35, 1997) | 1350 → 450 → 150 → 50 m 等の 1/3 接続。双方向 | 粗の水位を線形補間して細の境界へ | 細の水位・流量を粗へ | 領域ごとに dt | 原典 PDF は本環境から取得できず、接続式の細部は未確認 |

一致点: (a) 親が先に進み、子はその間を補間して追う。(b) 親 → 子は
**境界帯への Dirichlet**(水位、フラックス、またはその両方)。(c) 子 →
親は**重なり領域の面積平均(または点コピー)による置換**で、乾いたセルは
除く。(d) 比は整数(3 が慣例)、時間比も整数。(e) 一方向はその抑止。
相違点は「どの量を渡すか」「平均の取り方」「保存修正の有無」「非静水圧の
扱い」に集約される。

### 2.2 基本操作(primitive)への分解

ENCflow に実装するのは次の 7 つの基本操作で、各手法はその組み合わせ
(モード)として表す。

| 記号 | 基本操作 | 手法との対応 |
|---|---|---|
| P1 | 親子木(親 id、複数子、任意深さ) | 全モデル |
| P2 | 幾何(整数比 r、子の原点が親セル境界に整列、子の窓が親の内側にマージン付きで収まる) | 全モデル |
| P3 | 時間(整数比 r_t、親先行、子サブステップ、親の n と n+1 の間の線形補間) | COMCOT・JAGURS(timenest)・GeoClaw |
| P4 | 親 → 子: 境界帯(幅 nb)の **セル量**(η→h, m, n, u, v)と **エッジ量**(uv, mn)の空間補間と Dirichlet 適用。選択肢: 水位のみ / 水位+エッジ量 / Flather 面フラックス / スポンジ | JAGURS(hz+fx,fy)、COMCOT(M,N)、TUNAMI(水位)、MOST、Flather |
| P5 | 子 → 親: 重なり領域(境界帯を除く)の **面積平均による置換**。h(体積厳密)/ 湿潤判定付き η(GeoClaw)/ m, n / 保存修正(界面エッジ流量の総和で親の界面を置換) | JAGURS(c2p_all)、COMCOT(JNZ)、GeoClaw(update+reflux) |
| P6 | 乾湿の扱い(平均は湿潤セルのみ、過半条件、well-balanced 補間 = η 基準で補間し h = max(η − z, 0)) | GeoClaw・COMCOT |
| P7 | 一方向スイッチ(P5 の抑止)、格子ごとの線形/非線形・NH の有効化 | JAGURS nest_1way、MOST |

## 3. アーキテクチャ

### 3.1 インスタンスモデル

- **1 プロセス = 1 つのネスト系**(格子木)。各格子は「従来の 1 ラン分の
  状態」= `t_encflow` 1 個で、木の全格子を `enc(1:ng)` に持つ。
- **全 MPI ランクが全格子の帯を持つ**(JAGURS 型)。各格子は従来どおり
  j 方向の帯分割で、帯の切り方は格子ごとに独立(§3.7 の整列条件を除く)。
  コミュニケータは全格子で共通(MPI_COMM_WORLD のまま)。逐次ビルドでは
  1 ランクが全格子を順に進める。
- 格子ごとに**独立のパラメータファイル**(fn_sysparam 相当)を持ち、
  地形・物性・各 fn_* ・出力先(dir_result)も格子ごと。ネスト系の定義は
  ルート格子のパラメータに `fn_nest` で指定する一覧ファイル(§3.3)。
  CLI は従来どおり `encflow param_root.txt`。
- 「有効化しなければゼロ追加」: fn_nest がなければ ng = 1 で、時間ループ
  も配列も従来と同一(無効時ビット一致が合否)。

### 3.2 複数インスタンス化の機構(Phase 0。等価リファクタ)

#### 方針: 「所有の明示」を主、「文脈の付け替え(bind)」を従(2026-10-08 改訂)

複数インスタンス化は 2 つの手段を**モジュールの性格で使い分ける**。
判断基準は人間にとっての可読性で、隠れた文脈(「いま束縛されている格子」
という暗黙の状態)を持つモジュールを最小限に抑える。

| 手段 | 内容 | 可読性への効果 | 適用先 |
|---|---|---|---|
| **A. 所有の明示** | モジュール変数だった私有状態を、そのモジュールの公開型 `t_*` の成分(allocatable。無効時は未確保)に移し、公開入口から private 手続きへ**引数で渡す**。§12 の「状態の実体は型、private 手続きは引数で受ける」をそのまま完成させる形 | **上がる**。依存が署名から読め、隠れた文脈がない。現状 private 手続きがモジュール変数を直接読んでいる箇所(§12 違反)も是正される | §12 準拠(または準拠に直せる)モジュール: 下表の A 群 |
| **B. 文脈の付け替え(bind)** | 私有状態はモジュール変数のまま使い続け、格子を切り替えるときに `move_alloc`(配列。O(1))と代入(スカラー)で文脈型 `t_*_ctx` へ退避・復帰する。カーネルも公開 API も不変 | **下がる**(暗黙の文脈+宣言と鏡写しの定型コード)。そのぶん適用先を絞り、§3.2 末尾の規律で固定する | ホットパスが多数のモジュール変数をホスト結合で直接読む m_swflow_enc(+submodule)、ホットパスの関数 m_ffactor、並列層の dcp |

#### モジュール別の分類(2026-10-08 実査。参照箇所の所在で判定)

| 群 | モジュール(状態) | 実査結果 | 作業 |

| 不要 | m_precip, m_meteo, m_evap, m_snow, m_swi, m_wq, m_driftwood, m_bldgdebris, m_bedmotion, m_tide, m_boundary 本体, m_state, m_geoinfo, m_sysparam, m_record | 私有状態なし(`t_*` が既にインスタンス。m_record の暗黙 SAVE 1 件は 0a で是正) | なし |
| A-1 | m_gwflow_bucket(gwb), _greenampt(ga), _lateral(glt, lay1), _layer2(gl2), _pump(gp), m_geomorph(crp, flv, dbr, spl, bsl, wrk), m_intercept_fixed(icf) | 参照は**公開入口のみ**(private 手続きは引数で受けている) | 変数を `t_gwflow` / `t_geomorph` / `t_intercept` の allocatable 成分へ移し、入口で渡す。参照の書き換えは入口の数行 |

#### m_main と `t_encflow`

- `t_encflow` は従来の 20 成分に加え、B 群の文脈(`t_enc_ctx`,
  `t_ffactor_ctx`, `t_decomp`)と A-2 の `t_output` を持つ。A 群の状態は
  既存成分(`gw`, `gm`, `gl`, `lv`, `sl`, `ic`, `b`)の中に入るので
  `t_encflow` の見た目はほとんど変わらない。
- m_main は `enc(:)` と `enc_bind(k)` を持つ。bind の対象は B 群だけ
  (3 モジュール)。**ng = 1 では bind を呼ばない**。
  (実装名〔0c〕: `encs(:)` + 現在を指すポインタ `enc`、
  `m_main_instances_alloc(n)`、`m_main_select(k)`。本書の `enc(:)`・
  `enc_bind` はこれらを指す)
- 従来の run_step・run_init・run_close は不変(引数に `enc(k)` の成分を
  渡すだけ)。

#### bind の規律(developer.md 新節に書く)

1. bind を呼ぶのは m_main の `enc_bind` だけ。ステップの外(格子の切替
   時)でのみ呼び、物理手続きの内側では呼ばない。
2. B 群の 3 モジュールの**宣言部にはヘッダ注記**を置き、「この変数群は
   格子ごとの文脈で、追加時は `t_*_ctx` と bind にも登録する」ことを
   明示する。登録漏れは静的検査スクリプト(§13.3)で止める。
3. 新しいモジュールは A(所有の明示)で書く。B を新たに増やすのは、
   ホットパスのホスト結合参照が多数ある場合に限り、developer.md に理由を
   記す。
4. 「束縛中の格子」の概念は architecture.md §3(状態の所有)に 1 行で
   明記する: *dcp と m_swflow_enc の私有状態・m_ffactor のテーブルは
   「現在 m_main が束縛している格子」のもので、ng = 1 では常に唯一の
   格子である*。

  型記述子・private ホスト結合の不具合を避ける)。allocatable 成分と
  move_alloc は F2003 の基本機能で、対象コンパイラ(gfortran / ifx /
  nvfortran / flang / NEC)全てで実績がある。

#### 性能

- A 群: 入口で渡す引数が 1 つ増えるだけ。tick 系の引数追加もループの
  外側(手続き単位)で、カーネル内のアクセスは `glw%x` のまま。
- B 群: bind の切替は配列 1 本につき記述子の移動だけで、ステップあたり
  格子数 × 3 モジュール分。無視できる。カーネルのコード生成は不変。
- m_swflow_enc の派生型への束ね(B の付随作業)はモジュール変数の
  派生型成分参照になるが、変数自体がモジュールスコープに留まる(ダミー
  引数にしない)ので静的にアドレスでき、aliasing の仮定も変わらない。
  ULP=0 と実行時間の計測で確認する。

### 3.3 格子木と幾何(P1・P2)

- ルートのパラメータに `fn_nest`(一覧ファイル。空 = ネストなし)。
  一覧は JAGURS の gridfile と同じ「1 行 1 格子」:

  ```
  # id  parent  param_file              [r  r_t]
  1     1       param_root.txt
  2     1       bay/param_bay.txt       5  5
  3     2       town/param_town.txt     5  5
  4     1       port/param_port.txt     5  5
  ```
  r(空間比)・r_t(時間比)は省略可(地理参照と dt から導出し、整合を
  検査)。**実装(Phase 1)**: `id parent param_file [r r_t [i0 j0]]`。子は
  i0 j0(子セル (1,1) が整列する親セル)を必須とし、地理参照からの導出は
  未実装(Phase 2 以降。j は北から南へ増える = ファイルの行順)。
- **整列条件**(init で検査、違反は par_stop): 子の dx = 親の dx / r
  (r は正の整数。3 または 5 を推奨)、子の原点が親のセル境界上、子の
  窓が親の内側に **nb + 1 親セル以上のマージン**で収まる、親の dt = r_t
  × 子の dt。格子の地理参照は既存の m_georef(hdr / GeoTIFF / 明示)で
  得る。
- 子の外縁は**境界帯(幅 nb。既定は自動 = スキーム 1 で 2、運動量保存形移流
  〔f_advection_scheme ≥ 2〕で 3。帯 2 では風上 2 本目のエッジが子の壁面に
  掛かる。Phase 1 の恒等テストで確定)**で、帯のセルは親から与えられる(§3.5)。帯の外向き面は壁のまま
  (f_bc_* は 0 を要求。他を指定したら par_stop)。
- 親側では子の窓に対応する矩形(iw1..iw2, jw1..jw2)を保持し、
  子 → 親の置換はその内側(帯を除く部分 = 子の計算内部)に限る。
- 兄弟(同じ親の子ども)の窓は重ならないこと(重なりの優先規則を
  持ち込まない。必要なら 1 つの子にまとめる)。

### 3.4 時間進行(P3)

ルートが 1 歩進む `advance(root)` の再帰(Berger–Oliger / COMCOT と同順):

```
advance(g):
  bind(g); 子がいれば、子の帯に必要な g の窓の値を t^n で保存(§3.5 の送り元)
  step(g)                           ! g を t^n → t^{n+1}(従来の run_step 1 回分)
  子がいれば g の窓の値を t^{n+1} で保存
  for each child c of g:
    for k = 1 .. r_t(c):
      prolong(g → c, t^n + (k−1)·dt_c)  ! サブステップ開始時刻の帯(親の n と n+1 の線形補間。
                                        !   k=1 は t^n の実値 = 親が同じ更新に使った入力)
      advance(c)                        ! 再帰(c の子はこの中で進む)
    if (双方向) restrict(c → g)     ! c の内部を g の窓へ平均置換(t^{n+1})
  halo exchange of g(置換した場合)
```

- r_t = 1 なら JAGURS の既定(全格子同一 dt)と等価。
- 帯の値は「サブステップ開始時刻」の親の値を線形補間して与える
  (JAGURS timenest と同じ。COMCOT の n+1 予測は採らない: ENC は
  親が実際に n+1 を計算済みなので実値で補間できる)。
- 各格子の step(g) は従来の run_step 1 回分そのもの(降水・地下水・
  地形変化・NH … すべてその格子で独立に走る)。格子間で交換するのは
  §3.5・§3.6 の量だけ。
- ネスト系の「1 ステップ」= ルートの 1 歩。BMI の update もこれ(§3.9)。
- 終了判定・エラー判定(ierror、CFL)は格子ごとに集約し、どれかが
  エラーなら全体を止める(全ランク同一判定)。

### 3.5 親 → 子(P4・P6)

- **送り元**: 親の窓(子の帯の足元 = 子の窓を親セルで囲んだ矩形)の
  セル量 h, e(= z + h), m, n, u, v と、その矩形内のエッジ量 uv, mn
  (8 方位 4 スロット)。t^n と t^{n+1} の 2 枚を保持。
- **補間**: η(= e)を基準に双線形補間し、子の帯セルで
  `h = max(η − z_child, 0)`(well-balanced。GeoClaw・§6 の乾湿規則)。
  m, n, u, v は双線形。エッジ量は同方位の親エッジ量を位置補間(法線
  2 方位・対角 2 方位を別々に)。r が奇数なら子ブロックの中央セルが
  親セル中心に一致するので補間が簡潔になる(奇数比を推奨)。
- **適用**: 帯の全セルのセル量を置換し、**帯セルに接する全エッジ**
  (帯セル間、帯と内部の間、枠上セルの外向き面スロット)のエッジ量を
  置換する。これで内部セルの更新に要る入力(セル 2 つ先までとその
  エッジ)が全て親由来になり、§9 の恒等テストが成立する。
- **モード**(`nest_bc`):
  1. 水位のみ(TUNAMI 型。帯の h だけ置換。エッジ量は子が計算)
  2. **水位+エッジ量(既定。JAGURS 型の ENC 版)**
  3. Flather 面フラックス(v1 §3 の式。帯幅 0 で外向き面に放射条件。
     一方向向け。設計案は §15。fn_boundary の放射境界の一般化として実装)
  4. スポンジ(帯を広く取り、内部へ向かって緩和。将来)
- **帯の乾湿はセル単位で判定する(境界が海岸線を横切るのは前提)**。
  遡上域を子として切り出す以上、子の側方境界は必ず海岸線を横切り、陸側
  境界は陸上にある。JAGURS(親が湿っている所だけ hz を補間)・COMCOT
  (親の両セルが湿っている所だけフラックスを与える)と同じく、交換は
  セルごとに切り替える:
  1. 親(補間に使う 2×2 セル)が湿っている → η を双線形補間し
     h = max(η − z_子, 0)(z_子 > η の子セルは乾く = 海岸線の細部は子の
     地形が決める)。
  2. 親が乾いている → 子の帯セルは h = 0(乾き)にする。子の自前の遡上が
     帯に達していた場合はそこで水が消える(側方境界の陸上部の既知の
     近似。双方向なら親が子の湿りを受け取り次ステップで整合に向かう)。
  3. 帯のエッジ量は、受け側の子セルが dd 未満ならゼロ(momentum の乾燥
     ガードと同じ規則)。
  利用者への指針は「陸側境界は最大遡上高より上に置く(水が届かない)。
  側方境界は海岸線を横切ってよいが、その付近 nb·r セル程度の遡上は
  信頼しない」。
- エッジ量は m_swflow_enc の私有(sx)なので、窓の書き出し・帯の
  書き込みは m_swflow_enc の公開フック(`m_swflow_enc_nest_export` /
  `_import`)を通す。STG は非対応(par_stop)。

### 3.6 子 → 親(P5・P6)

- **領域**: 子の計算内部(帯を除く)に対応する親セル。
- **既定(nest_fb=2。GeoClaw 型の湿潤判定付き平均)**: r×r の子セルの
  うち湿っているものの η と h を平均し、h_c = min(h_av, max(η_av − z_c, 0))。
  親セルの地盤 z_c が η_av より高ければ親は乾く(海岸線をまたぐ親セルの
  陸側に薄膜が立たない)。m, n は湿潤セルの総和を同じ比率で縮小、u, v は
  m/h・n/h から再構成(h > dd のとき)。e = z + h を回復し、ハロ交換。
  置換領域に海岸線が含まれるのが津波の主用途なので、これを既定にする。
- **選択肢**(`nest_fb`): 0 = なし(一方向。MOST 型)、1 = h・m・n の単純
  面積平均(水柱体積が厳密に保存される。置換領域が全て水域のときだけ
  意味がある)、2 = 既定、3 = 2 + **保存修正**(子の内部/帯の界面を横切るエッジ流量の
  サブステップ総和で、親の対応する界面エッジ流量を置換。親の界面の
  外側セルの質量を整合させる。GeoClaw の reflux に相当。Phase 4)。
- 親のエッジ量(sx)は置換領域の内部では更新しない(次ステップで
  再計算され、領域全体が再び置換される)。界面だけが保存修正の対象。
- 一方向(nest_fb=0)のときは子の反射・遡上は親へ戻らない。

### 3.7 MPI 設計と決定性

- **親の窓の共有**: 親の窓(子の足元矩形)は小さい(子の nx/r × ny/r)
  ので、各ランクが自帯の行を埋めたゼロ初期化配列を `par_allreduce_sumr`
  (1 要素 1 寄与 = ビット決定的。§11 の例外規定)で全ランクに配る。
  各ランクは自分の子帯の行だけを補間する(通信なし)。
- **子 → 親の所有権の整列**: 親セル 1 個の r×r 子ブロックが 1 ランクに
  収まるよう、**子格子の帯境界を r の倍数行に整列**する(par_decomp_init
  に整列引数を追加。ng = 1 のときは従来と同一の分割)。これで平均は
  1 ランクで閉じ、親への配布は再び「ゼロ初期化+1 要素 1 寄与の
  allreduce」で決定的。
- collective の実行判定は全ランク同一の量(木の構造・ステップ番号)
  だけで行う(§5)。
- エッジ量の窓も同じ経路。規模は窓あたり O(nx_c·ny_c / r²) × 数量で、
  格子あたり毎親ステップ 2 回(t^n, t^{n+1})+置換 1 回。数十ランクまでは
  十分。大規模では alltoallv 型(JAGURS の USE_ALLTOALLV)へ置換できる
  ように、通信は m_nest の 2 手続き(`nest_gather_window` /
  `nest_scatter_window`)に閉じ込める。

### 3.8 非静水圧・他プロセス・スカラー場

- NH(§69)は格子ごとに独立に解く。帯は静水圧のまま(既存の
  `nh_bc_margin` を「帯の幅」に合わせる)。NEOWAVE 型の φ の Dirichlet
  (親の φ を帯へ補間)は Phase 4 の選択肢(φ は現在状態から再構築する
  設計なので送り元は窓の φ)。
- 降水・地下水・遮断・蒸発散・積雪・水質 … は各格子で独立。格子間で
  交換しない(地下水の帯間流動などは対象外。必要になったら P4/P5 の
  場の表に追加する)。
- 移流されるスカラー場(hs, cq, hd, hbd)は P4/P5 の「場の表」に追加
  するだけで同じ機構に載る(Phase 4)。
- z を変える過程(bedmotion・geomorph・glacier・lavaflow)は各格子で
  独立。bedmotion は同じ変位表を各格子の解像度で読むので親子で整合する。
  geomorph の侵食を親へ戻すか(z の restriction)は未定(Phase 4 以降)。
- 建物・流木・瓦礫は子格子(高解像度)でのみ有効化する使い方を想定。
  親で有効なら各格子で独立に動く。

### 3.9 BMI

- ネスト系全体が **1 つの BMI component**。`initialize(config)` の
  config はルートのパラメータファイル(fn_nest を含む)。`update()` =
  ルートの 1 歩(子はその中でサブステップ)。`get_time_step` = ルートの dt。
- **格子は BMI の grid id で区別**(BMI は多格子を仕様として持つ:
  `get_var_grid(name)` が grid id を返し、`get_grid_*` は id ごと)。
  grid 0 = ルート、1.. = 一覧の順。
- 変数名: BMI は 1 変数名 = 1 格子なので、非ルート格子の変数は名前で
  区別する(例: `surface_water__depth` はルート、`surface_water__depth@2`
  は格子 2。接尾辞の形式は実装時に決める。pymt/Landlab 側が名前を
  文字列として扱うだけなので互換)。入出力変数表は格子数に応じて
  動的に生成する(§59 の動的変数リストの設計と合流)。
- `set_value` は格子ごとに同じ受理条件(§56・§57)。
- MPI 版 BMI(§58)の規約(全ランク collective・rank0 有効)は不変。
- 副産物: `t_encflow` の配列化と bind により、**独立な複数モデルの
  同一プロセス実行**(handle 方式)も m_main のインスタンス番号で
  実現できる。bmi_encflow_c の `model` を配列にすれば Python から
  複数ハンドルを扱える(需要が出てから)。

### 3.9.1 ドライバを Fortran で持つ(2026-10-08 追記)

- BMI が規格化しているのは **プロセス内のコンポーネント呼び出し規約**
  (initialize / update / get / set …)であり、プロセスの起動・分配・
  プロセス間通信は規格外である。したがって「別プロセスを BMI で制御する」
  形は規格の外に出るが、本案(§3.1)は結合をプロセス内で閉じるので、
  ドライバに必要なのは規格内の呼び出しだけになる。
- よって **ドライバは Fortran で書けて、bmi/ の保守対象に含められる**。
  既存の `bmi/test_bmi.f90` がその最小形(逐次・MPI 両対応の時間ループ)
  で、これを `bmi/driver_encflow.f90` として育てる: 引数で設定ファイルと
  終了時刻を受け、`class(bmi)` 総称で任意の bmif_2_0 コンポーネントを
  駆動し、必要なら複数コンポーネント間の get/set による交換(例: 地形
  進化モデルとの z の往復)を Fortran 側で行う。Python ラッパ
  (bmi/python)は「外から使う人のため」に残すが、ENCflow の機能は
  Python なしで全て動く。
- ネスティング自体はドライバの仕事ではない(§3.9: ネスト系 = 1 component、
  結合は m_nest 内)。CLI の `encflow` がそのまま多段ネストを走らせる。
- 同一プロセスで ENCflow を 2 つ以上(独立なモデル同士の結合、
  アンサンブル)を Fortran ドライバから扱う場合は、§3.2 の複数
  インスタンス化がそのまま効く: `encflow_bmi` 型にインスタンス番号を
  持たせ、m_main の `enc(:)` の該当要素を bind して呼ぶ(handle 方式)。
  これも Phase 0 の副産物で、Phase 5 で BMI 層に出す。

### 3.10 出力・記録・restart

- 各格子は自分の dir_result に従来どおり出力(分布・プローブ・測線・
  Log)。ルートの Log にネスト系の要約(格子一覧、比、交換の統計、
  置換した体積の収支)を加える。
- restart は格子ごとの save ディレクトリに従来の形式で保存し、
  ルートの restore が全格子を復元する。m_nest 自体に私有状態はない
  (窓の 2 枚は毎ステップ再構築)。save_version の更新は不要。

## 4. 入力形式

ルートのパラメータ(list_sysparam):

```
  fn_nest = "nest.txt"      ! 格子一覧(§3.3)。空 = ネストなし
```

格子一覧(nest.txt): `id parent param_file [r r_t]`(§3.3)。

子格子のパラメータに `&list_nest`(fn_nest を持つのはルートだけ。
子の設定は子のパラメータファイルに書く):

```
&list_nest
  nest_bc = 2        ! 親→子 (1: 水位のみ, 2: 水位+エッジ量〔既定〕, 3: Flather 面, 4: スポンジ)
  nest_fb = 1        ! 子→親 (0: なし=一方向, 1: h/m/n の面積平均〔既定〕, 2: GeoClaw 型湿潤平均, 3: +保存修正)
  nest_nb = 2        ! 境界帯の幅(セル。既定 2)
/
```

## 5. 連結モジュール m_nest の構成

```
m_nest(ネスト系の木・幾何・時間進行・交換)
  t_nest_tree   : 格子一覧、親子、r、r_t、窓(親座標)、整列検査の結果
  nest_init     : 一覧の読み込み、各格子の初期化(enc_bind を切替えつつ従来の initialize)、整列検査
  nest_advance  : §3.4 の再帰(ルート 1 歩)
  nest_prolong  : §3.5(窓の gather → 補間 → 帯の書き込み)
  nest_restrict : §3.6(平均 → 窓の scatter → 親の置換 → ハロ)
  nest_finalize : 逆順の dispose
m_swflow_enc の公開フック: m_swflow_enc_nest_export(窓のエッジ量) / _import(帯のエッジ量)
m_parallel: par_decomp_bind / par_decomp_init の整列引数 / 窓の allreduce は既存 par_allreduce_sumr
m_main: enc(:)・enc_bind(B 群 3 モジュールのみ)・ng=1 の従来経路
```

m_nest は m_main より下、物理モジュールより上の層(状態の所有は各
`t_encflow`、m_nest は参照して交換するだけ)。

## 6. 乾湿・保存・反射についての規則(利用者向け文書に書く)

- 子の側方境界が海岸線を横切るのは前提(§3.5)。陸側境界は最大遡上高
  より上に置き、水が届かないようにする。側方境界付近(nb·r セル程度)の
  陸上の遡上は近似が粗いので、注目地点から離す。
- 一方向(nest_fb=0)では子の反射が親へ戻らず、親の反射(粗い海岸)
  が帯から子へ入る。双方向ではこの不整合が解消される。
- 既定の子 → 親(湿潤判定付き平均)は親の地盤より上に水を置かない代わりに
  体積を厳密には保存せず、界面を横切る流量も親子で異なる(JAGURS・
  COMCOT・GeoClaw-GPU と同じ)。全域水域なら nest_fb=1 で体積厳密、
  厳密性が要る研究用途は nest_fb=3。
- 比は 3 または 5(奇数)を推奨。dt は各格子で CFL から決め、r_t = r が
  標準。帯の幅 2 は ENC の移流ステンシルに必要な最小。

## 7. 位置づけと方針適合

- 方針 1・4(統一表現・複数プロセスの同時概算): 全プロセスが各格子で
  そのまま動く。格子間交換は浅水流の状態量に限って始め、場の表で広げる。
- 方針 6(徐々に精緻化): Phase ごとに「対応済みのモード・モジュール」を
  表にし、未対応の組合せは init で par_stop する(黙って動かさない)。
- 方針 8(無効時ゼロ): fn_nest なしで ng=1、bind は恒等、配列未確保。
- 方針 9・10(単一ソース・Fortran のみ): 逐次でもノート PC で多段ネスト
  が動く。MPI は従来のコミュニケータのまま。
- 方針 11・12(入出力は単純、物理量は直接): 一覧ファイルは 1 行 1 格子の
  テキスト。親子の再サンプリングはモデル内の基本操作(前処理に出さない。
  オンライン結合の本質)。
- comparison.md: 「ネスト格子」の行を ○ にする(双方向・多段)。

## 9. 検証計画(CLAUDE.md の規律)

1. **無効時**: fn_nest なしで wave・chichibu ほか全 test/ の逐次ビット
   一致、MPI np=1,2,4 一致、BMI ドライバ完走(Phase 0 の bind 恒等、
   Phase 1 以降の分岐追加のたびに)。**ビット一致の判定は、変更前後の
   バイナリを同一環境・厳密 IEEE フラグ(-O2、fast-math/LTO/march なし)・
   OMP_NUM_THREADS=1 で作って Log を比較する**(0b の記録。-Ofast では
   等価なソースでも最終桁が動く)。reference との比較(Run.sh)は別途 PASS を
   確認する。
2. **twin テスト(Phase 0 の合否)**: 同一ケースの 2 インスタンスを
   1 ステップずつ交互に進め(bind を切替)、それぞれの Log が単独ランと
   ビット一致。文脈に入れ忘れた変数があれば必ず破れる。異なるケース
   (wave と chichibu)の交互実行でも同様。
3. **-fcheck=all np=2** をネスト有効ケースで最初に通す(帯の整列・窓・
   新規確保)。
4. **格子比 1:1・r_t=1 の自己ネスト恒等(Phase 1・2 の合否)**: 子 =
   親の部分領域(同解像度)。一方向で子の内部が親の同領域とビット一致、
   双方向で親全体が単独ランとビット一致(置換が恒等になる)。静水圧・
   拡散なし・NH なしの条件(非局所項を含まない。NH を含めるときは OpenMP
   reduction の非決定性を避けて単一スレッドで。§11 の 0a 記録)。**wave 系(湿潤水域)、
   tsunami_coast 系(海岸線を横切る側方境界と陸側境界を含む遡上)、
   chichibu 系(降雨あり・乾湿あり・サブグリッド河道あり)の 3 つで行う**。
   親子で z が同一なので乾湿の判定も一致し、§3.5 のセル単位規則のもとで
   恒等が成立するはずで、これが規則の正しさの検証になる。後二者が通れば、
   乾いた帯・濡れ乾きの横断・河道セルを含む補間の完全性が同時に保証され、
   陸上利用(§14)の土台になる。
5. **ランク数不変**: ネスト有効ケースで np=1,2,4 がビット一致(整列
   した帯分割・決定的な allreduce)。
6. **restart 往復**: ネスト系の save → restore がビット一致。
7. **物理検証**(Phase 2・3): (a) 一様水深の孤立波/ガウス波が界面を
   通過するときの反射率(振幅比)を r=3, 5 で計測し一様細格子と比較。
   (b) tsunami_coast の湾を子にした例題で、一様 100 m 格子との遡上高の
   差。(c) 2 段(5 → 1 m 相当)の深いネストの完走。
8. **親側のみの無効**: 子だけが新機能を使う(建物・流木)場合も親は
   従来とビット一致。

## 10. 既知の割り切り

- 側方境界の陸上部で、子の自前の遡上が帯に達すると親の乾きで消える
  (§3.5 の規則 2)。陸側境界に水が届く設定は非対応(利用者の指針)。
- 一方向では親の粗い反射が子へ入る(§6)。
- 既定の置換は系全体の質量を厳密には保存しない(nest_fb=3 で修正)。
- NH の φ は帯で 0(Phase 4 で Dirichlet の選択肢)。
- 移流スカラー・z の交換は Phase 4 以降。

## 14. 陸上(流出・洪水氾濫)への転用(2026-10-08 追記)

### 14.1 結論

津波向けの実装は、水の供給源を問わない機構(格子木・親先行の再帰・
帯 Dirichlet・面積平均の置換)であり、各格子で降雨・浸透・地下水・遮断
などが従来どおり独立に走るので、**清水の流出・洪水氾濫にも骨格はそのまま
使える**。ただし陸上では次の 3 点が本質になるため、津波の
実装を次の 3 原則で書き、陸上対応を Phase 4 の**選択肢の追加**(書き直し
ではなく)に収める。

1. **補間は水位 η 基準を既定にする**(h = max(η − z_子, 0)。親が乾けば
   子も乾く)。GeoClaw が「水深で補間すると静水に偽の波が立つ」と報告
   している点でもある。
2. **交換する量は「場の表」で持つ**(§3.8)。h, e, m, n, u, v, エッジ量に
   始まり、hg・hs・cq … を行として足せる構造にする。
3. **置換(子 → 親)はモード選択式にする**(nest_fb)。

### 14.2 陸上で追加になる 3 点(Phase 4)

| 項目 | 内容 | 根拠 |
|---|---|---|
| 乾湿を跨ぐ界面 | セル単位の乾湿規則と湿潤判定付き平均は津波の遡上域に必要なので**津波段階で既定として実装する**(§3.5・§3.6)。陸上で追加になるのは、帯の降雨が上書きで捨てられることへの対処: 子の水収支(calcstat)は帯を除いて集計し、Log に帯の置換体積を別記する | 流出・氾濫では帯のほとんどが乾き、濡れ乾きが常時界面を横切る(津波の側方境界と同じ状況が全周に広がる) |
| サブグリッド河道セルの体積整合 | 親 → 子は η 基準の補間で自然に「河道セルは湿り、堤内地は乾く」になる。子 → 親は、子セル群の水量の総和を親セルの河道幾何(wfrac・σ の sect_v の逆関数)で矩形換算の h に戻す「体積整合置換」を河道セル専用モードにする | 親の河道セルの h は矩形換算の意味を持ち、単純平均では河道水位がずれる(§26・§68.27) |
| 地下水の連続 | hg(必要なら hg2・hgc)を場の表に加え、帯で親の値を Dirichlet し、置換で平均する。地表水と同じ機構 | 帯で上書きするのが地表量だけだと、斜面から谷底への地下水の側方流入が界面で途切れる |

### 14.3 陸上で有利な点

- 比 1:1 の自己ネスト恒等(§9-4)は chichibu 系(降雨・乾湿・河道あり)
  でも成立するので、乾湿と河道を含む補間の完全性を**津波の実装と同時に**
  ビット一致で検証できる。難しいのは比 3 以上での 14.2 の 1・2 である。
- 洪水は摩擦支配で遅く、帯での反射は問題にならない。時間比 1 でも十分。
- サブグリッド河道により山地側の親格子を粗くでき、ネスティングの効果が
  津波と同様に大きい。

### 14.4 位置づけ

標準的な河川氾濫(谷底平野に閉じた氾濫原、上流端が数断面の流量、下流端が
水位既知)は既存の区間流入(土砂濃度付き)と水位規定による事後接続で
足り、ネスティングは不要。陸上でネスティングが意味を持つのは、界面が
数断面に還元できない(扇状地・網状河川・デルタ・低平地・破堤位置を固定
しない破堤氾濫)、双方向性が効く(背水・氾濫原貯留・還流・内外水)、
水以外の連鎖を切りたくない(土砂・流木・土石流・地下水)、複合災害
(海側境界と山側境界の同居)、長期地形変化、の場合に限る。ENCflow は
方針 2 により CommonMP 型の「河道ノードでの接続」を持たないため、面的
接続 = ネスティングがラスタ純化された唯一の接続手段である点が、他モデル
との違いである。

## 15. Flather 放射(nest_bc = 3)の設計(2026-10-10 起案・合意・F1/F2 実装)

Phase 4 で保留した nest_bc = 3 の設計案。Phase 0〜5 が完了し、帯 Dirichlet
(nest_bc = 1・2・4)と双方向(nest_fb = 1〜3)が揃った上で、**一方向で子の
自前の擾乱を外へ抜く**選択肢として位置づける。

### 15.1 目的と位置づけ

- 帯 Dirichlet(nest_bc = 2)は「親の解を子の帯に置く」ので、子の内部で
  生じた擾乱(子の細かい海岸の反射・遡上の戻り)が帯に達すると親の値で上書き
  され、**一方向(nest_fb = 0)では子の中に閉じ込められて反射する**。双方向
  では親が子の状態を受け取り次ステップで整合に向かうため実害は小さい
  (Phase 2 の例題: 反射率 < 0.5%)。Flather 条件は長波の特性線そのもので、
  親から来る入射波を通しつつ子の擾乱を放射する(Flather 1976)。
- 用途: (a) 一方向ネスト(親を既に走らせた結果で子だけを回す運用。MOST 型)、
  (b) 親の解像度が粗く子の反射を親に戻しても意味がない場合、(c) 子の境界が
  恒常に湿った水域にある津波・高潮。陸上(海岸線を横切る側方境界)には向かず、
  そこは帯 Dirichlet のまま(§3.5 の乾湿規則)。
- 方針適合: 方針 5(水平は SWE まで)の特性線条件。既存の長波放射境界
  (`f_bc_* = 2`。η_e = 基準水位、u_e = 0)の**一般化**であり、新しい境界の
  種類ではない。

### 15.2 定式(v1 §3 を引き継ぐ)

境界の外向き法線 **n** について

    u_n = u_n,e + √(g/h) · (η − η_e)

- η = z + h: 子の境界セルの水位、h: 子の水深、u_n: 境界面の外向き法線流速。
- η_e, u_n,e: 外部(親)の水位と外向き法線流速(子の境界セル中心での値)。
- 子の解が親と一致すれば u_n = u_n,e(親のフラックスをそのまま通す)。子の
  内部で生じた擾乱 η − η_e は放射で外へ抜ける。u_n,e = 0・η_e = const は
  現行の放射境界そのもの。
- **η_e だけを与え u_n,e = 0 とすると進行波は境界で振幅がおよそ半分になる**
  (入射と放射を区別できない)。ネストでは必ず両方を与える(nest_bc = 3 は
  常に両方。ファイル供給〔15.6〕で流速を省いた場合は文書で明記)。

ENC 配置への適用(m_swflow_enc_bc の put_bc_faces、`e_bc_radiation` 分岐):

    現行:  uve1 = √(g / max(h, dv)) · (z + h − η_r) · wn
    拡張:  uve1 = (u_n,e + √(g / max(h, dv)) · (z + h − η_e)) · wn
           (wn = max(n8(k)·r, 0)。括弧の内側で和をとってから射影する。
            3 面の Σ l8·wn = dx なので面合計は (…)·h·dx = 自然幅あたり)

角の斜め面・開口の規則、乾いたセル(h < dd)のフラックスゼロ、過大流出の
抑制、σ 断面換算、河道幅係数は既存の共通処理をそのまま通す。無効時は
既存の式がそのまま走る(分岐 1 個の外側は不変)。

### 15.3 構成: 「外部データ付き放射境界」は fn_boundary の 1 族

Phase 4 で「ネスト専用でなく fn_boundary の 1 族として設計するのが筋」と
した理由を実装構成に落とす。**適用の式はデータの出所に依らない**ので、
m_boundary に「境界セルごとの外部水位・外向き法線流速」を保持する族を 1 つ
置き、供給者(provider)を差し替える:

| 層 | 役割 | 変更 |
|---|---|---|
| m_boundary(データ供給) | 新成分 `t_bound_ext`(名称は要合意): ncell、cell(1:2,:)、side(:)(角は辺ごとに複製 = inflow と同じ)、現時刻の eta(:)・une(:)(外向き法線流速。符号は辺ごとに前計算)、provider 種別。供給者 (A) ネスト: m_nest が各サブステップの開始時に書く。(B) ファイル(15.6。将来)。供給者が書いた値を makebdc は触らない | `t_boundary` に成分追加(§13 のデフォルト初期化)。init で境界セルの検査(外縁上・属する辺が放射型・x > 0・sw = 0) |
| m_swflow_enc_bc(適用) | bc_init: `have_ext` と `bc_ext_idx(1:max(nx,ny), 1:4)`(0 = 静的基準水位、>0 = ext の添字)。boundary_uvmn の冒頭で ext の現時刻値を bcs 側へ写す(ncell 回。全ランク同値)。put_bc_faces の放射分岐で idx > 0 なら 15.2 の拡張式 | 放射分岐に if 1 個。他は不変 |
| m_nest(供給者 A) | nest_bc = 3: 帯なし(nb = 0・ns = 0)。setup で子の開いた辺(f_bc_* = 2)の外縁セルを列挙して `b%ext` に登録(角は 2 辺に複製)。prolong(α) は帯の置換の代わりに、各境界セル中心で親の窓から η・u・v を双線形補間(時間は α の線形補間。窓は現行の足元 ±1 親セルで足りる)し、辺の外向き法線成分 u_n,e = u·n_x + v·n_y(内部座標系。v は j 増加 = 南が正)を `b%ext%eta/une` に書く | interp_cell の「値を返す」変種(現行は s へ書く)を切り出す。export/import フックは不要 |
| m_main / nest_advance | 変更なし(prolong の呼び出し位置は同じ: サブステップ開始時刻の値) | — |

MPI: 境界セル一覧は全ランク共通で小さい(周長 O(nx+ny))。親の窓は全ランク
同値(§3.7)なので、**全ランクが全セルの値を冗長に計算する**(通信なし・
ビット決定的)。東西辺の共有行の冗長書きは現行の放射境界と同じ論法。

NH: `nh_bc_margin` は辺境界型(放射)で強制境界を判定するので、Flather 辺は
自動的に静水圧の縁に入る(v1 §3.3。実装時に nh の判定が辺型だけを見ている
ことを確認)。

### 15.4 nest_bc = 3 の子格子の条件と細則

- 子の開いた辺は `&list_bound_edge` で `f_bc_* = 2`(放射)にする。0(壁)の
  辺はそのまま壁(陸側境界を最大遡上高より上に置く運用はこれで表せる)。
  1(自由流出)と流入区間は不可(par_stop)。nest_bc = 1・2・4 は従来どおり
  全辺壁を要求する(帯が外向き面を持つ)。
- 帯幅 nb = 0(nest_nb の指定は無視し、通知)。スポンジ(nest_ns)は不可。
- 子→親の置換領域: 帯がないので nin = 0 になるが、**境界セルを含む親セルは
  置換から外す(nin ≥ 1)**。Flather の境界セルは親と一致しない量(放射で
  抜ける擾乱)を持つため。双方向(nest_fb > 0)との併用は許す(置換は内側のみ)。
- 乾湿: 親の補間 2×2 に乾きがあれば、そのサブステップはその境界セルの
  フラックスを 0(壁)にする(§3.5 の規則 2 と同じ扱い)。子の境界セルが
  乾いていれば現行どおりフラックス 0(境界からの再湿潤はしない = §10 の
  割り切り)。利用者指針:「nest_bc = 3 の開いた辺は恒常に湿った水域に置く」。
- 時間比 r_t > 1: 窓 2 枚の線形補間(帯と同じ α)。
- 場の表(浮遊砂・水質等)と地下水: 帯がないので交換しない(境界面からの
  流入の濃度は既存の `csin`/清水の規則。将来の課題として記録)。
- restart: ext は時刻の関数(窓から毎回再構築)で私有状態なし。save_version 不変。

### 15.5 検証計画

1. **無効時**: reference 全ケース PASS、厳密フラグ 38 ケースのビット一致
   (放射分岐の if 1 個と t_boundary の成分追加だけが共通経路に触れる)。
2. **退化の恒等**: ext に η_e = 基準水位・u_n,e = 0 を与えた子単独ラン
   (ネストなし。試験ドライバまたはファイル供給〔15.6〕)が、現行の放射境界
   (`f_bc_* = 2`)の結果と**ビット一致**すること(拡張式は u_n,e = 0 で
   現行式に一致する。和の順序を `une + sqrt(...)*(...)` にして 0 + x = x を
   使う)。
3. **静水の不変性**: 親子とも静水(η = const、u = 0)で、nest_bc = 3 の子が
   全ステップ静水のまま(フラックス厳密 0)。
4. **透過**: examples/nest_reflect に一方向(nest_fb = 0)の r3t3 を bc = 2 と
   bc = 3 で追加し、(a) 子の内部の誤差(一様細格子基準)、(b) 通過後の残差
   (子に残る擾乱 = 帯の反射の指標。Phase 3 では bc = 2 で入射振幅の
   1.4〜2.8%)、(c) 親側の反射率、を比較する。期待: bc = 3 は (b) を下げる。
   加えて**子の内部で発生させたガウス波**(親は静水)が子の境界から外へ抜け、
   子に残る残差が現行の放射境界単独(子だけ・親なし)と同程度であること。
5. **MPI**: np = 1, 2, 4 で Log がランク数不変(境界セル値は全ランク冗長計算)。
6. **-fcheck**: -O0 -fcheck=all の MPI ビルドで 3・4 のケースが完走。

### 15.8 要合意事項(**2026-10-10 全項目合意済み**)

1. Flather は **fn_boundary の放射境界の一般化(外部データ付き放射)として
   実装**し、nest_bc = 3 はその供給者の一つとする(ネスト専用コードは
   m_nest の供給部だけ)。
2. 族の名称: `t_bound_ext` / `&list_bound_ext`(「外部データ付き放射」)。
   v1 の `&list_bound_nest` は同一プロセスのネスト(fn_nest)と紛れるため
   使わない。
3. nest_bc = 3 の子は開いた辺を `f_bc_* = 2` で宣言する(壁の辺は壁のまま。
   自由流出・流入区間は不可)。帯なし(nb = 0)、スポンジ不可、置換は境界セルを
   含む親セルを除く。
4. 親の補間 2×2 に乾きがあればその境界セルのフラックスは 0(壁)。子の乾きも
   フラックス 0(現行どおり)。開いた辺は恒常に湿った水域に置く指針。
5. nest_bc = 3 は η_e と u_n,e の両方を必ず与える(水位のみの Flather は
   ファイル供給の選択肢としてのみ残し、振幅半減を文書に明記)。
6. 段取りは F1 → F2(→ F3 は保留)。F1 の退化の恒等(u_n,e = 0 で現行の放射
   境界とビット一致)を F2 の前提にする。
7. 場の表・地下水は nest_bc = 3 では交換しない(境界面の流入濃度は既存規則)。
