# ENCflow 開発者向けメモ (developer.md)

コードから読み取れない「なぜ」を記録する。形式は「決定事項+理由+落とし穴」。
設計判断をしたら、記憶が新しいうちにここへ追記すること。

---

## 1. 実数精度の方針

- **精度はソースでなくコンパイルフラグで指定する**(ifx `-r8` / gfortran
  `-fdefault-real-8 -fdefault-double-8` / nvfortran `-Mr8` / flang `-r8`)。
  理由: リテラル定数の精度落ち(`x = 0.1` が単精度になる罠)をクラスごと根絶
  できる。kind 方式では `_wp` の付け忘れが残る。
- **精度は make.inc の `PREC = double|single` で切り替える**(MODE と同じ流儀)。
  各コンパイラブロックが倍精度化フラグを `R8` に定義し、FFLAGS は `$(RFLAG)`
  を参照する(コンパイラ固有知識をブロック内に閉じる)。既定は double。
  single はメモリ半減のための選択肢: 主用途(河川工学・水文学)では入力
  データの不確実性が大きく、数値安定性の問題を除けば結果に倍精度は不要。
- **単精度の結果は倍精度 reference と比較できない**(累積丸めが印字桁に出る。
  ULP=1 でも不整合)。単精度の検証は解析解ベンチマーク+同一バイナリの
  ビット再現で行う。単精度で収束判定が破綻するパターンは §13
  (「和を作ってから比較する」)を参照。
- **フラグ方式の例外: 診断集約の総和は real(real64) を明示指定する**
  (calcstat の hsum/hsum_j/hgsum/hgsum_j と par_sum_rows の引数。
  2026-07-31)。単精度ビルドでも総和の桁落ちを防ぐ(全国級で 1e7 セルの
  総和は単精度だと有効桁を数桁失う)。状態量・出力量は PREC のまま =
  「状態は PREC、診断集約は常に real64」の線引き。倍精度ビルドでは
  real64=既定 real なので単一実装・従来とビット同一で、総称や二重実装は
  不要。par_sum_rows の MPI 通信型も MPI_WP でなく MPI_REAL8 固定
  (バッファ型と常に一致するため安全。§2 の MPI_WP 規約の例外)。
- 代償: `.mod`/ABI 互換のため、src と utils/rerecord 等は**PREC を含めて必ず
  同一の FFLAGS** でビルドする(make.inc に一元化済み。スタンプ
  `.mode_<MODE>_<MPIID>_<PREC>` が不整合を検出する)。
- gfortran は `-fdefault-real-8` 単独だと double precision が16バイトに昇格する。
  **`-fdefault-double-8` を必ず併用**すること。
- 実行時の精度は停止・警告でなく**報告・宣言**とする: run_main がプロセス数・
  スレッド数と並べて `real precision : NN bit` を par_info で表示する
  (stdout 行なので回帰比較対象の result/Log.txt には入らない)。

## 2. 単一ソース MPI 方式

- serial(OpenMP)版と MPI 版は**別コードにしない**。並列層を `m_parallel`
  モジュールに隔離し、`m_parallel_serial.f90` / `m_parallel_mpi.f90` の
  2実装を Makefile(`MODE=serial|mpi`)で差し替える。
- **両ファイルの公開手続きインターフェースは常に一致させる**(保守ルール)。
  MPI_WP のような MPI 版固有の公開は例外的に許す(通信コードは MPI 版にしか
  書かれないため)。
- 通信の実数データ型は `MPI_REAL` でも `MPI_DOUBLE_PRECISION` でもなく
  **必ず `MPI_WP` を使う**。MPI_WP は par_init が `storage_size(1.0)` から
  実行時に確定する(PREC=double なら MPI_REAL8、single なら MPI_REAL4)。
  固定値や MPI_REAL 直書きは、-r8 昇格や PREC と MPI ライブラリの解釈の
  不整合により、エラーにならず値が化ける最悪の壊れ方をする。
- OpenMP 併用のため `MPI_Init_thread(MPI_THREAD_FUNNELED)`。MPI 呼び出しは
  マスタースレッドのみが前提。
- 実行コンテキスト(nrank, nproc, is_root, 領域分割情報 dcp)は m_parallel が
  **protected 属性で公開**する(他モジュールは読めるが書けない)。
- 初期化は二段階: par_init(MPI_Init、main 冒頭、引数解析より前)→
  格子サイズ確定後に **par_decomp_init(nx, ny)**(m_geoinfo_init の直後、
  collective)。par_init 時点では nx/ny が未知のため分割は決められない。

## 3. ビルドシステム

- `.mode_$(MODE)_$(MPIID)_$(PREC)` スタンプ: MODE 切替・MPI 実装切替
  (ラッパーの -show 出力のハッシュ)・実数精度(PREC)切替を検出し、
  混成オブジェクトを防ぐため全再ビルドする。
- `$(OBJS): ../make.inc` の依存により、**make.inc の編集は自動で全再ビルド**
  される(-flto の付け外し等も手動 clean 不要)。
- **残る手動 clean は「serial モードでのコンパイラ本体切替(ifx⇄gfortran 等)」
  のみ**。MPIID の計算は MPI モード限定 — serial でハッシュを取っては
  ならない。非ラッパーでも nvfortran は -show を認識し、出力に一時ファイル名
  (毎回変化)を含むため、serial でハッシュを取ると make のたびにスタンプ名が
  変わり全再ビルドが繰り返される(実発生)。
- Run スクリプトは実行前に `make -s print-stamp MODE=...` で期待スタンプ名を
  問い合わせ、**モード・MPI 実装・精度(PREC)がビルド時と一致しているかを
  検証する**(Check_mode.sh。ロジックは Makefile 側に一元化。PREC は
  make.inc の現行値で照合されるため、Run スクリプト側の変更は不要)。
  「module を切り替えたのに再ビルドし忘れ」を実行前に堰き止める。
- ビルドと実行の実装一致は `ldd a.out` でも事後確認できる(不一致だと
  MPICH バイナリ + mpirun.openmpi = 全ランクがシングルトン化し
  「全プロセスがランク0」になる等の症状)。
- シングルトン化は実装の混用だけでなく、**同じ MPICH でもパッケージの
  PMI 方式と起動側が不整合なら起きる**: Ubuntu 24.04 の apt 版 mpich は
  PMIx 有効ビルドなのに同梱 hydra が PMIx 非対応で、同梱 mpiexec でも
  全プロセスがランク0になる既知バグ(Debian #1066735。26.04 は修正済み)。
  対処はソースビルドの MPICH を /opt/mpi に置くか、そのマシンでは
  OpenMPI に寄せる。
- **シングルトン化は結果を壊さず並列だけを静かに殺す**(全プロセスが同一の
  逐次計算を実行し、同一の Log を多重に書くため回帰テストが PASS してしまう)。
  防御として par_init に期待ランク数アサーションを実装済み:
  Run_case.sh が `ENCFLOW_EXPECT_NP=$NP` を輸出し、par_init が nproc と照合、
  不一致なら起動直後に MPI_Abort する(環境変数未設定なら検査しない)。
- 静的ライブラリのアーカイバはコンパイラと LTO の有無で自動選択(make.inc):
  ifx(-ipo)→ oneAPI の llvm-ar / gfortran+-flto → **gcc-ar**(llvm-ar 不可)/
  flang 系+-flto → llvm-ar / それ以外 → ar。
  間違えると「アーカイブは作れるがシンボル索引が空 → リンクで未解決」という
  沈黙型の失敗になる。
- IPO/LTO 相当: ifx `-ipo`、gfortran `-flto=auto`、AOCC flang `-flto`。
  **nvfortran には相当機能がない**(-Mipa は HPC SDK 23.3 で無効化)。
  submodule 境界を跨ぐホットコール(adv_edge 等)のインライン化は nvfortran
  だけ効かない点に注意。
- `-g` は最適化ビルドにも常時付ける(性能への害なし。バックトレースと
  プロファイルに必須)。ただし **nvfortran は `-g` 単独で -O0 を暗黙適用する
  歴史があるため `-gopt` を使う**。

## 4. エラー処理・メッセージ出力

- 4分類のラッパー(m_parallel)を使う。生の print は使わない:
  - `par_info` : 進捗・情報。ランク0のみ、stdout。
  - `par_warn` : 局所警告。検出ランクがランク番号付き、stderr、停止しない。
  - `par_stop` : **決定的エラー**(設定不正など全ランクが同時に検出するもの)。
    **collective — 必ず全ランクが揃って呼ぶこと**。一部ランクだけが呼ぶと
    Barrier でデッドロックする。ランク0が表示し finalize を通して stop 1。
  - `par_abort`: 局所的な致命的エラー。検出ランクだけが呼んでよい。MPI_Abort。
- エラー・警告は stderr に出す(意図的)。`tee` で作る Screen.log や
  result/Log.txt(回帰テストの比較対象)にエラー文言を混ぜないため。
- namelist の read は `iostat=` `iomsg=` で捕捉し par_stop に渡す。
  ランタイム任せにすると全ランクがメッセージを出す。ファイル open も同様
  (m_fileio に集約済みのため、入口数箇所の iostat 化で全読み込みに効く)。
- 時間ループのエラー処理: **判定は全ランクで同一に行い、exit は全ランクが
  同時に実行する**。print だけ is_root。ランク0だけが exit すると他ランクが
  回り続け finalize で整合しなくなる。`error stop` は dispose/par_finalize を
  素通りするので使わない — ierror を返し、finalize 後に stop 1。
- 領域分割後の集約対象(判定・出力の直前に allreduce/gather が要るもの):
  **ierror(swflow の発散検出はランク局所値になる)、s%cnmax、
  s%hmean(二段総和の行部分和)、s%sp の各成分(表示区間内最大値)**。
  m_record の水収支 ss/ss0 も実装時は総和として同リストに入る。

## 5. is_root ガードの規約

- **出力専用ルーチンは入口で自衛する**(`if (.not. is_root) return`)。
  run_main 層に is_root を書かない。呼び出し側の is_root ブロックは
  「後から collective 呼び出しが紛れ込む」デッドロックの温床になる。
- ガード節が許されるのは**副作用(ファイル・画面出力)しか持たないルーチン
  だけ**。out 引数や関数値で結果を返すルーチンに付けると、ランク0以外で
  未定義値が返る時限爆弾になる。
- **collective(par_stop)を is_root ガードの内側で呼ばない**。ランク0だけが
  Barrier に入り、他ランクが永久待ちになる(m_record init で発見した違反 →
  par_abort に変更済み)。ガード内のエラー停止には par_abort を使う。
- init/dispose は対にする(init がランク0限定なら dispose も。未割付
  deallocate 防止)。

## 6. 文字列・メッセージの組み立て

- 固定長バッファへの**代入**は黙って切り詰める(write と違いエラーにならない)。
- 規約: 連結で組めるものは `character(:), allocatable`。数値入りは
  m_util の `itoa`/`rtoa` で連結(`call par_stop("... "//itoa(n))`)を優先。
  write が必要なら作業バッファは `character(len=1024)`(ケチらない)+ trim。
  itoa 方式は contained 手続きの msg シャドーイング警告(fortls)も根治する。
- 幅なし `i` 書式は ifx 拡張で規格外(gfortran はエラー)。`i0` を使う。
  並び出力 `write(msg,*)` は空白が処理系依存なので比較対象の出力に使わない。

## 7. 状態変数の時刻規約(m_swflow_enc)

- **無印 = 時刻 n(ステップ中は読み取り専用)、接尾辞 1 = 時刻 n+1 の
  書き込み先、ステップ末尾でコミット**(h/h1 が模範)。
- 例外: uv は自エッジの read-then-write のみで他エッジの旧値を参照しないため
  単一バッファで安全(この理由をコード側にもコメント)。
- mn は h と同じ二重バッファ方式に移行済み(2026-xx): **無印 mn = 時刻 n
  (読み取り専用の正準状態)、mn1 = 書き込みバッファ、complete でコミット**。
  コミットは行並列ループ(エッジ行 js-1..je)で行う。エッジの書き込み集合は
  セル窓より i, j とも1行外(die/dje=-1)に張り出すため、**エッジのコミット・
  交換をセルループに畳み込んではならない**(縁の格納位置が漏れる)。
  移行時に旧 mn0 コピーの「窓縁エッジの取りこぼし」も修正された。
- リスタートの保存先は **p%dir_save(既定 "save"。dir_result から独立)**。
  読込元=保存先なので、リスタート連鎖(保存→復元→保存)がパラメータ
  編集なしで回る。ファイル構成:
  - `save_info.txt` — メタデータ(namelist &save_info)。**書き手は m_state
    ただ一人**(m_state_dispose は dispose 列の最後の saver。全ファイル完成後
    に書くので完成マーカーを兼ねる)。内容: save_version(**仕様変更日の
    日付文字列**。形式を変えたら m_state の save_version_cur を更新)、
    nx, ny, precision_bits, n_state, t, it。
  - `state.dat` — m_state の5成分(h, z, rsh, hg, sd の連結。2026-08-07)。
  - `swflow_enc.dat` — sx%uv, mn(エッジ状態。力学状態は厳密に復元される)。
  - `gwflow_<モデル名>.dat` — 内部状態を持つ地下水モデルの私有ファイル。
- **保存対象の線引き: 質量はスキーム非依存の共有状態として m_state が保存し、
  運動量表現はスキーム私有として m_swflow_XX が保存する**(ENC: uv/mn、
  STG なら M/N)。u, v, m, n, vv, qq, e は純粋な導出量として保存せず、
  復元時に再導出する(実行中も complete が毎ステップ導出しており、
  保存系と実行系で同じ原則になる)。gwflow の契約(柱状換算 s%hg は
  m_state、モデル内部状態はモデル私有)と同じ構図。
- **STG は restart 非対応**(運動量 M/N を保存していない)。
  f_state_restore>0 で STG を選ぶと init が par_stop する。STG での
  f_state_save は止めないが、生成される save は STG では復元できず、
  ENC での復元も swflow_enc.dat 欠如で門番に止められる(黙って不完全な
  復元にはならない)。
- **STG は比較検証用に凍結する(方針)**: 新機能(save/restore、gwflow 連携、
  record 拡張等)は原則 STG 非対応とし、機能追加のたびに個別判断はしない。
  ただし非対応が「黙った劣化」になる場合(restart のような)は par_stop 等の
  明示ガードを置く。例外的に STG へ対応させる場合は、その判断と理由を
  本書に明記する。
- **save の実体ファイルはゼロ抑制 RLE で圧縮する**(m_fileio の
  fileio_write_rle / fileio_read_rle。1配列=1ストリーム:
  [n_total, nrun](int64)→ ラン表(ゼロ連長, リテラル連長)→ 詰めデータ)。
  全国 250m 級では大半が海域・乾燥域・乾燥エッジのゼロで、5GB 級の save が
  数百 MB になり I/O 時間も短縮される。純 Fortran 実装
  (外部ライブラリ不使用。gzip(sysdep_compress)は execute_command_line の
  NEC VE での問題と単スレッド速度から不採用)。
  - 可逆(ビット保存)で往復ビット一致の検証と両立する。**圧縮対象は
    全ビット 0(+0.0)のみ** — 値比較 `a == 0.0` は -0.0 も真になり、
    -0.0 が +0.0 として復元されてビット一致が壊れるため、既定 real と
    同サイズの整数への transfer によるビット比較で判定する(PREC 連動)。
  - カウント類は int64(100m 全国はエッジ配列が 1.4e9 要素で 2^31 に迫る)。
  - 各ストリームは要素数を自己記述し、復元時に展開先サイズと照合して
    不一致は par_abort(復元の読み込みは rank0 のみが実行するため、
    collective の par_stop でなく局所の par_abort を使う。§5)。
- 版の日付を**同日に複数回変更した場合は英字サフィックス**で区別する
  ("2026-07-31b" 等)。
- **restore の門番は m_state(check_save_info)**: 全ランクが save_info.txt を
  冗長に読み、版・格子・精度・成分数を検証して不一致は par_stop(判定は
  全ランク同一 → collective 安全)。後段のモジュール(swflow_enc、内部状態を
  持つ gwflow モデル)は**自ファイルの有無のみ確認し、無ければ par_stop**
  (黙ってスキップしない。内部状態を持たないモデルはファイル無しが正常)。
  m_state_init が swflow/gwflow の init より先に走る初期化順序が門番の前提。
- **導出量は保存せず復元時に再計算する**: m_swflow_enc の restore は
  uv/mn の復元後、restore_uvmn で s%u,v,m,n,vv,qq,e を再導出する
  (vv は摩擦項が complete より前に読む、qq は t=0 の出力・計測が読む。
  未導出だと再開直後の摩擦が不正確・流量出力が 0 になる実不具合)。
  再導出は continuous とセルループの範囲・スキップ(sw/x/域端)・重み・
  総和順を完全一致させる=保存時の値とビット一致する。continuous の
  乾燥エッジ条件(h<dd 両セル)の複製は**不要**: momentum が同条件の
  エッジの uv/mn1 を 0 に零化済みで、無条件総和でも寄与 0 で同値
  (この非自明な根拠は restore_uvmn のヘッダにも記載)。
- 時刻(t, it)はメタデータに**記録するが継続しない**(復元は「保存状態を
  初期条件に使う」意味論。開始時刻は param の t0)。時刻継続は別の検討事項。
- 最大値統計(hmax 系)・qcum・sp(表示区間統計)は対象外で、リスタート後
  ゼロから再集計される(意図的な仕様)。精度不一致の restore は停止
  (変換復元が必要になったらメタデータ駆動で追加できる)。

## 8. OpenMP の決定性

- **RK の他エッジ参照は必ず無印 mn(前ステップ確定値)を読む**。更新中の
  mn1 を読むとスレッドタイミング依存のデータ競合になる(2026-xx に修正した
  実バグ。当時の応急処置 mn0 は mn1 方式への移行で吸収済み)。
- scatter 型の書き込み(atomic/critical で隣接セルへ加算)は使わない。
  エッジは所有セルが一意に書く gather 型を維持する。
- 自動配列を部分初期化のまま参照しない(ulm/vlm の実バグ)。
  **`-finit-real=snan` は派生型成分には効かない**ので検出を過信しない。
- 総和リダクションはスレッドの終了順で結合順が変わり、同一条件でも最終ビット
  が揺れる(S 列の ULP=1)。決定化したい診断量は「行ごと部分和 → 逐次固定順
  結合」の二段総和にする(calcstat の hsum_j で実装済み)。max/min は順序
  不変なので reduction のままでよい。部分和・結合は PREC によらず real64 で
  行う(2026-07-31。§1 の例外項を参照)。
- 現状の到達点: 同一バイナリならスレッド数・実行によらず S 以外はビット一致。
- ThreadSanitizer は libgomp 非対応のため OpenMP コードに偽陽性を量産する。
  本気の競合検査は LLVM 系(libomp/Archer)で。valgrind --track-origins は
  未初期化読みに有効(逐次・短縮ケースで)。

## 9. コンパイラ間の既知の差(仕様であってバグではない)

- fast-math(-Ofast / -fp-model fast / AOCC も同類)の下では、定数除算の逆数
  乗算化や FMA 縮約がコンパイラごとに異なり、**閾値判定(適応 RK トリガ)の
  境界すれすれで判定が反転**する。Runge 列(事象カウント)はその最鋭敏な
  検出器で、コンパイラ間比較では ULP=2 程度揺れる → SKIPCOLS=4 で除外。
  トリガの除算は maglim_inv の乗算に置換済み(完全解ではない)。
- 書式出力の「ちょうど半分」の丸め(6.25 → 6.2/6.3)は処理系定義。
  ログは書式の RN(round='nearest' 相当)で統一済み。
- 回帰テストの規準: **同一バイナリ=完全一致(ULP=0)、コンパイラ・マシン・
  ランク数跨ぎ= ULP=1**。ULP は印字の最終桁を単位とした許容誤差で、列ごとの
  書式から自動決定される(Compare_ref.sh)。

## 10. 回帰テスト運用

- reference は環境依存(ビット一致基準)なので gitignore。**make clean では
  消さない**(clean 後の初回実行が未検証の結果を黙って新基準にする事故を防ぐ)。
  更新は明示的に `./Run.sh -u`。作成・更新時に env/BUILDINFO.txt へ実行環境
  (ホスト・module・ldd・ビルドモード)を自動記録する。
- param.txt は正規化(コメント除去)して比較し、不一致なら SKIP(比較不能)。
- 基準を更新したら、その結果の妥当性をプロットで一度は目視確認する。
- **np=2 以上の -fcheck=all ビルド実行を検証階段の必須段とする**。確保縮小
  後は帯外アクセスと引数の要素数不足が実行時に名指しで検出される
  (get_diff_v1 の並び結合バグはこの段で捕捉できた種類。§12 参照)。
- **確保範囲を変える変更の後は、最適化ビルドより先に -fcheck np>=2 を回す**。
  帯外のゴミ読みは結果を「少しだけ」壊す(落ちずに、もっともらしい値のまま
  最終数桁が狂う)ので、回帰テストの不一致から遡るより境界検査の方が早く
  正確に原因を指す。n_valcells の sw 帯外読み(S がセル1個分の定数比で
  ずれた)がこの型の実例。静的データを実際に使うケース(実地形+粗度+
  河道)で回すこと。wave(固定値 z0/rn0)はこの検査の感度が低い。
- 計測(m_record)付きケースでは FILES に record CSV を加えて比較する
  (例: `FILES="Log.txt fluxes/flux0001.csv"`)。点集約方式は
  ランク数によらず CSV がビット不変なので ULP=0 で比較できる。
  測線がランク境界を跨ぐ配置を意図的に含めること(点集約の急所)。
- benchmark 系(解析解あり)はいずれ環境非依存の解析解ベーステストに昇格させ、
  CI に載せる(CI のランナーではローカル reference は使えない)。
- **record・出力・save 等のファイル形式を変更したら utils/ の該当ツールを
  確認する**。utils/ は一部(rerecord 等)を除き読み書きを独立実装しており、
  回帰テストの網の外にあるため、形式変更に黙って取り残される。libencflow を
  リンクするツールも再ビルドが必要(形式は共有するが自動追従はしない)。

## 11. MPI 化の設計原則(分割実装の基準)

- **静的データは「初期化は全域・時間ループは帯」の二相で保持する**
  (下記「静的データの帯化」参照)。地形・マスク類(z, x, sw, rw)は
  初期化中は全ランクが全域を冗長構築するため、境界・湧き出し・プローブの
  位置解決は従来どおり手元の全域情報で完結する(冗長計算=配布機構)。
  **物性係数(rn, gv, bb, lm, rscap, lu)は方式2**: rank0 のみが全域を
  構築し、par_scatter_cell で各ランクの帯+ハロへ配布する(2026-07-31。
  非 root の一過性メモリピーク削減の第1段。第2段=ゾーン2の rank0 化は
  handoff の道標参照)。
- 数千ランク級で open 集中が問題化した場合の逃げ道は m_fileio の内側だけの
  改修(rank 0 が読んで Bcast。意味論は不変)。読み込みの入口は m_fileio に
  集約されているのでこれが単一差し替え点。ただし装置番号を外に出す un 系
  API は Bcast 化と相性が悪いので**新規利用を増やさない**。
- 初期化(namelist 含む)は全ランクで冗長実行が基本。検証も全ランクで行い、
  報告だけランク0(par_stop)。構造体の配布ルーチンは書かない
  (書かないコードが一番バグらない)。例外は方式2の大配列のみ:
  rank0 だけが構築する経路(m_geoinfo の係数読み込み・user フック)では
  **par_stop が collective として成立しないため、エラーは par_abort**(§5)。
- **場を変更する処理は所有ランクがローカルに適用**(湧き出し、潮位境界)。
  **場を読むだけの診断・出力は gather して rank 0 で**(ファイル出力、
  プローブ、フラックス測線)。この二分法が判定基準。
  m_tide(未実装)は実装時に前者に該当する。分布ファイルは m_fileio 経由に。
- user_geoinfo / user_initial フックは「全域添字で書く」契約。
  **user_geoinfo は rank0 のみが実行する**(方式2: 係数は rank0 しか
  持たないため)。フックが地形・マスク類を変更した可能性に備え、実行後に
  z, x, sw, rw を rank0 から再 bcast する(フック無指定なら通信なし)。
  フック内のエラーは par_abort(par_stop は collective 不成立)。
  user_initial(ゾーン2)は従来どおり全ランク冗長実行。
- **ハロ交換の設計(第一段として実装・検証済み 2026-xx)**: 案A =
  「素の状態だけ交換し、導出量はハロ行で再計算」を採用。
  - 帯分割: par_decomp_init → build_band_table(m_parallel_mpi)が構築する
    帯境界表(js_tab/je_tab)が正本で、band_range は表を引くだけ。
    既定は**重み付き分割**(行ごとの有効セル数 rowwork の累積和を等分する
    位置に境界を置く。2026-08 導入)。rowwork 省略時・総重みゼロ時は従来の
    均等行数分割(余りは若いランクへ)。**各帯は最低2行**(不足は par_stop。
    重みの目標位置より優先し、残りランクに2行ずつ残す上限で頭打ち)。
    gather の counts/displs も同じ正本から導く。重みは m_main が
    m_geoinfo_row_ncells(x>0 のセル数=カーネルの計算対象と同じ基準)で
    数えて渡す。全ランクが同一マスクから同一の表を決定的整数演算で得る
    ため通信は不要。分割位置によらず結果はビット同一(検証は規律2の
    np=1,2,4 vs 逐次 ULP=0 がそのまま合否判定になる)。
  - ステップ頭の交換: h, u, v, vv をセル幅2(移流項の連鎖 taxy←ulm/vlm←u,v
    と TVD の±2参照が幅2の源)、mn をエッジ幅1(共有行 js-1, je は界面補完
    済みのため、RK が要る js-2 / je+1 のみ)。
  - taxy / ulm / vlm は交換せず、adv_prepare の範囲を担当帯±1 / ±2 に
    拡張してハロ行で再計算する(移流アルゴリズムを変えても通信層は不変)。
  - momentum 後の**界面エッジ行の成分補完**(par_edge_merge): エッジ行
    js-1 / je には自ランクと隣ランクの所有成分が k 別に同居するため、
    dje 由来のマスク(esync_s/esync_n。dje を変えたら必ず更新)で相手所有
    成分を取り込む。同一エッジのフラックスを南北で共有することで
    **質量保存がビットレベルで厳密**になる(独立再計算方式は不採用)。
  - 集約: hmean は par_sum_rows(行部分和を rank0 が j 昇順に組み立てて
    一括総和 → Bcast。**ランク数に依存しない決定的総和**)。max 系は順序
    不変なので allreduce。事象カウントは整数和。ierror は swflow_calc 直後に
    全ランク最大(これでエラー判定の全ランク同一性が回復)。
    実数和の allreduce(par_allreduce_sumr)は例外的に「各要素の寄与
    ランクがちょうど1つ(他ランクは 0)」の使い方に限り許す:
    x+0=x は浮動小数でも厳密なので加算順に依存せずビット決定的
    (帯所有ランクだけが埋めるゼロ初期化ベクトルの全ランク共有=
    allgather の代用。区間流入の重み共有が使用例)。
  - 場の gather は出力・計測(dt_file / dt_recrd)の直前のみ。**gather は
    collective なので、実行判定は全ランクで同一に評価してから分岐する**
    (is_root ガードの内側に置くとデッドロック)。
  - save/restore: gather → rank0 書き / rank0 読み → 配布。
  - 検証: 1, 2, 4 ランク+スレッド数変更で同一 reference にビット一致(達成)。
- **第二段(確保の縮小)実装・検証済み(2026-xx)**: MPI 版のみ
  jsh/jeh = 担当帯±nhalo に縮小(逐次版は全域確保のまま=縮小の複雑さを
  MPI 側に閉じ込め、np=1 の MPI が縮小版の検証役)。要素:
  - 初期化: 全域一時状態 ts(h,u,v のみ確保)上で set_h / restore /
    user フック / fill_depression を全ランク冗長実行し、最後に帯+ハロを
    切り出す。**user フックのシグネチャと全域添字契約は無変更**。
  - 出力: output_matrix が collective 化(par_gather_to → rank0 の全域
    スクラッチ wk_out → 書き出し)。スクラッチは source=0 確保で帯外行が
    恒久ゼロとなり、逐次出力とバイト一致する。静的・全域保持の g%z だけは
    gather せず rank0 直接書き(output_matrix_full)。
  - save/restore: 全域バッファへ gather → rank0 書き(レコード構成は旧形式と
    バイト互換)/ 復元の配布は2方式が混在(過渡期):
    **エッジ(swflow_enc の uv/mn)は rank0 のみ全域一時に読み
    par_scatter_edge で帯配布**(2026-08-04。非 root は全域一時を持たない)。
    セル成分(m_state の h/z/rsh/hg)は全ランク同形の全域一時 ts に
    Bcast → 帯切り出しのまま(ts は新規初期化も使うため、scatter 化は
    初期化第2段(a)= ts の rank0 化と同時に行う。handoff の道標)。
    rank0 の全域一時は残る(RLE ストリームが先頭からの逐次展開のため。
    解消するなら展開しながら帯を送るストリーミング配布)。
  - prtype3: 全域一時配列に読んで帯を切り出す(全ランク冗長読み)。
  - **par_bcast_cell/edge は全ランク同形の配列(全域一時)専用**。帯確保の
    配列に使うとランク毎にサイズが異なり Bcast が破綻する。
- **m_record の MPI 対応(点集約方式)実装・検証済み(2026-xx)**:
  計測ロジックは rank0 上の逐次コードのまま維持し、セル値の取得だけを
  点集約バッファ経由に差し替える。全ランクが所有セル
  (dcp%js <= iy <= dcp%je。**ハロ行を含めると二重計上**)の値を格納し、
  par_reduce_points(総和)で rank0 へ。各要素の所有者はちょうど1ランク
  なので総和=所有値+0=ビット厳密の点 gather となり、フラックスの総和順も
  逐次と同一 → record CSV はランク数不変で ULP=0 比較可能。
  リスト構築・測線分解は全ランク冗長、ファイル open/ヘッダのみ rank0。
  計測量の追加手順はモジュール冒頭コメントに明記(格納1行+次元+1+読替)。
- **静的データの帯化(方式a: 2点縮小)実装・検証済み(2026-xx)**:
  初期化は3ゾーンのライフサイクルで進む(m_main がそのまま文書になる):
  - ゾーン1(m_geoinfo_init 内)= 地形・マスク類は全ランク全域、
    物性係数は rank0 のみ全域(方式2。2026-07-31)。地理データの読み込み・
    導出(adjust_rw の河道掘り込み等)・user フック・窓計算・n_valcells
    カウントの住所。**係数を使う全域前処理は必ずここ(rank0 実行部)に
    書く**。係数と地形の両方に触れる処理(adjust_rw)は、係数への書き込み
    だけを is_root で分岐する(set_rn の定型)。
  - par_decomp_init → m_geoinfo_scatter_coeffs: 物性係数
    (rn, gv, bb, lm, rscap, lu)を rank0 から帯+ハロへ配布
    (par_scatter_cell)。旧 shrink_coeffs の置き換えで、配布後の確保
    範囲・値はともに旧方式と同一(非 root が全域を経由しなくなっただけ)。
    帯+ハロは隣接ランクと重なるため MPI_Scatterv でなく rank0 からの
    個別送信。確保範囲の規則は band_range_h(m_parallel)が正本。
  - ゾーン2(boundary/state/record/precip/swflow の init)= 地形と
    マスク類(z, x, sw, rw)のみ全域。fill_depression(sw/rw を全域窓で
    参照)、user_initial、record/boundary の検証がこの範囲で動く。
  - m_geoinfo_band_shrink: x(番兵ごと)、sw, rw を帯へ。**z は rank0 のみ
    全域を恒久保持**(Z 出力の直接書き。将来の浸食計算の初期地形の正本)。
  - 時間ループ = すべて帯。±1 の近傍参照(momentum の gv、rivermouth の
    rw/sw、adv の lm)はハロ幅2の余白内に収まることを監査済み。
  - 縮小はハロ交換不要(静的=更新されないため、切り出し1回で完結)。
    ヘルパーは move_alloc 方式(shrink_band_r/_i)で、逐次では確保範囲が
    一致し自然に no-op(単一ソース)。wx, wy は微小なので恒久全域。
  - **縮小グループの割り当ては「どのゾーンの誰が読むか」の監査で決める**。
    根拠となった実バグ: n_valcells カウントが帯縮小済みの sw を全域添字で
    読み、np=2 で有効セルを1個誤除外して S が定数比 (n/(n-1)) でずれた。
    fill_depression の sw/rw 参照も同監査で発見し、遅い縮小組へ移した。
  - 初期化中の一過性ピークは方式2の第1段(係数の rank0 化)で
    非 root から係数6配列ぶんを削減済み(2026-07-31)。残るのは
    地形・マスク類(z, x, sw, rw)と ts(m_state の全域一時)で、
    ゾーン2の冗長処理(fill_depression, user_initial, record/boundary の
    検証)が使うため未対策。第2段の計画は handoff の道標を参照。
- **計算標高の動的状態化(s%z。浸食計算の土台。2026-xx)**:
  - s%z は h と同じ動的状態(帯確保、ts で全域初期化→切り出し)。
    fill_depression は ts%z を埋める(g は intent(in) 化)。
    momentum の重力項(±1 の近傍参照)は帯+ハロの範囲内で、現在は
    z が時間不変のためハロ交換は不要。
  - **役割分担: g%z = 入力地形(掘り込み後・窪地処理前)、
    s%z = 計算地形(窪地処理後、将来は浸食で時間発展)**。
    Z ファイル出力は s%z の gather 経路に変更(内容は従来どおり窪地処理後。
    ただし全域窓の外の行はゼロになる点だけ旧全域書きと異なる)。
    rank0 の g%z 全域保持は Z 出力の消費者を失い、現在は「入力地形の
    記録」のためだけに残している(不要と判断したら例外ごと削除してよい)。
  - プローブは z を計測量に追加(点集約バッファ 6 成分)。m_record の
    「計測量の追加手順」の初適用例であり、浸食後は地形の時間変化を
    プローブで直接観測できる。
  - save/restore は h, u, v, z, rsh の5成分(リスタート形式の変更)。
    **成分を足すときは save の write 並びと restore の read 並びを必ず
    同時に更新する**(z 追加時に read 側の更新漏れ+ts%rsh 未確保で
    復元が壊れた実バグ。読み並びコメントを restore に明記済み)。
  - **浸食(s%z の時間発展)を導入する時の必須 TODO**:
    (1) ステップ頭の交換リストに par_halo_cell(s%z) を追加(現在は
    時間不変のため省略中。忘れるとハロの地形が古び、重力項が壊れる)。
    (2) 時間発展地形の出力を output_matrix で新設。
    (3) stg は init 時コピーのため浸食非対応(コード内に明記済み)。
- 負荷分散: セル数重み付き分割を実装済み(2026-08。上記「帯分割」参照。
  全国級で行あたり有効セル数の偏りが大きいことによる決定)。2パス構造や
  分割の記録ファイルは不採用: 分割決定に必要な情報(全域マスク)は
  par_decomp_init の時点で全ランクが持っているため不要で、記録ファイルは
  地形差し替え・np 変更との不整合という新しい失敗モードを持ち込むだけ。
  MPI_Init を最初に置く習慣も維持(MPI_Init 前に許される処理は規格上
  ほぼ保証がない)。乾湿の時間変動が支配的な場合は静的分割では捉えられ
  ない点に注意(実行中の再分割は複雑さに見合わないため不採用。まず
  ランク別時間を計測して残余不均衡を確認してから考える)。
- 同期は明示的に取らない。ハロ交換のデータ依存が必要な同期を内在する。
  MPI_Barrier は時間計測とデバッグの区切りにのみ使う(par_barrier)。
- 検証の柱: 冗長計算段階で「ランク数によらず逐次版とビット一致」を確認して
  から分割に進む。分割後はランク数不変性(1,2,4,8ランクで同一 reference に
  PASS)を回帰テストで担保する。
- FPE トラップと MPI: UCX は初期化・通信中に良性の invalid 演算を行うため、
  inv トラップと共存できない。nvfortran+HPC-X では `-Ktrap=divz,ovf` に
  落とすか、単一ノードでは `MPIRUN_OPTS="--mca pml ob1 --mca btl self,sm"`
  で UCX を回避する。
- ハイブリッド実行のバインド: OpenMPI は既定でコアにバインドするため、
  OMP スレッドが1コアに積み重なる。`--bind-to none` または
  `--map-by l3cache:pe=$OMP_NUM_THREADS` を指定。ランク数>コア数は
  `--oversubscribe`(MPICH は既定で非バインドなので不要)。
  実測(2026-xx, 285/9960X): OpenMPI 既定のまま np=1×20 スレッドで
  CPU 使用率1コア分のまま逆に減速(全スレッドが1コアに積層)。
  `--report-bindings` で確認できる。modulefile の MPIRUN_OPTS で恒久化。

## 12. モジュール設計の規約

- 状態の実体はモジュール変数として保持し(命名は `xx_mod` 等で引数と区別)、
  **プライベートルーチンは引数で受け取る**。依存が署名から読め、OpenMP の
  shared/private 判断が局所化し、複数インスタンス化にも開いた構造になる。
  直接参照してよいのは不変の小定数(die/dje 等)のみ。
- 例外: **実行コンテキスト(is_root, nrank, nproc, dcp)は use 直接参照して
  よい**(protected により書き込みはコンパイル時に禁止される)。ただし
  **dcp の直接参照はフェーズの入口まで。計算カーネルには範囲(js, je 等)を
  引数で渡す**(カーネルを「任意の部分範囲で動く一般手続き」に保つ)。
- **帯確保の配列を手続きに渡す場合、ダミーは assumed-shape+下限指定を
  必須とする**(例: `real :: u(1:, dcp%jsh:)`)。明示形状 `(1:nx,1:ny)` で
  受けると並び結合(先頭からの詰め直し)で行が jsh-1 ずれて読まれる
  (get_diff_v1 で実発生: np=1 は帯=全域で偶然無害、np=2 で波形が歪んだ)。
  **静的配列も帯化後は同じ規則に従う**(get_diff_v1 の x(0:, dcp%jsh-1:) が
  適用第1号)。恒久全域が保証されるのは wx, wy と rank0 の z のみで、
  それ以外を明示形状で受けてはならない。
- 公開ルーチンは実体の受け渡しのみ、変更はプライベート側 — 同一実体の
  二重可視(エイリアシング)による未定義動作を規律で回避する。
- **格子幾何(nx, ny, dx, dy)の正本は g(t_geoinfo)**。p(t_sysparam)側は
  移行期間中の導出値(g からの単純転記。特に dx/dy の導出計算は m_geoinfo に
  限定し、実数のビット同値を保つ)。参照は触るついでに g へ漸進置換中で、
  参照ゼロになったら p から削除する。t_sysparam には最終的に実行制御と
  数値スキーム設定だけが残る。
- 表示用統計 sp は t_state に統合済み(モジュール変数から昇格。2026-xx)。
  成分は型定義のデフォルト初期化でゼロ保証。
- 実験機構は3段で使い分ける: 小さな変種は**実行時フラグ**(param で A/B 比較
  可能、回帰テストに条件が記録される)/ アルゴリズム単位の差し替えは
  **submodule ペア**(m_parallel と同じ「同一インターフェース+Makefile 選択」
  イディオム。内部状態を submodule に隠蔽できる)/ 骨格レベルの実験は
  ブランチ(マージか破棄で決着するもの)または _dev 全複製(同一バイナリで
  実行時 A/B が必要な場合のみ)。
- 出力層は m_output に分離(m_main は時間ループと配線に専念)。
  output_state / output_summary / output_matrix は collective
  (内部で par_gather_to → rank0 の全域スクラッチ wk_out へ)なので、
  呼び出し判定は全ランクで同一に行うこと。
- m_swflow の手続きポインタは t_swflow の成分に移設済み(2026-xx。
  API と実体の不一致=グローバル状態の解消。abstract interface +
  pointer, nopass 成分。未初期化ハンドルでの calc は par_stop)。
- submodule のモジュール変数は単一インスタンスのグローバル状態。将来ネスト
  格子等で多重化する場合は派生型に包む改修が要る。
- **user フック(user_geoinfo / user_initial)は識別名方式**(2026-08-04)。
  param では `f_user_routine`(文字列。trim 後の完全一致、snake_case
  推奨)で指定する。旧 `f_user_routine_id`(整数)は廃止(実運用前の
  ため互換入力なしで移行。旧 param は namelist 読込エラーになる)。
  親モジュールへの公開面は入口のみ(user_*_defined / names / run)で、
  分岐は submodule 内の resolve(識別名→手続きポインタ。
  abstract interface + procedure pointer)に一元化。**ルーチンの追加は
  user_*.f90 内で完結する**(雛形 *_template の複製+routine_names への
  登録+resolve への分岐1行)。
  geoinfo フックは rank0 のみで実行されるため、名前の検証(defined)は
  呼び出し側が全ランクで行い(par_stop の collective 性)、フック内の
  エラーは par_abort を使う(m_geoinfo_init のコメント参照)。

## 13. Fortran の落とし穴(実際に踏んだもの)

- **宣言時初期化(`integer :: n = 0`)は暗黙 SAVE**。block 構文内でも同じ。
  再入時に前回値から始まる。宣言と代入は分ける。
- 派生型の成分は `-finit-*` の対象外。早期 return 経路の初期化漏れは
  型定義のデフォルト初期化(`integer :: nsrcc = 0`)で型レベルで防ぐ
  (b%nsrcc 未初期化の実バグ: 最適化レベル・MPI 実装でゴミが変わり
  ランダムに segfault)。
- `open(newunit=un, ...)` に対して `close(1)` のような固定番号 close をしない。
- `use, intrinsic :: iso_fortran_env` は **only 句必須**(only なしだと
  NUMERIC_STORAGE_SIZE が取り込まれ、-fdefault-real-8 と矛盾する警告が出る)。
  only は他モジュールでも推奨(m_fileio の裸 use を only 化済み)。
- 標準出力の flush は `flush(output_unit)`(iso_fortran_env)。`flush(6)` は
  慣習依存、`call flush(6)` は規格外。nvfortran はパイプ先で行バッファしない
  ため、ラッパー内の明示 flush が診断可能性を保証する(「ハングに見えて
  出力滞留」の再発防止)。
- **全配列代入でコピーを作る配列は、コピー元の確保形状に追随させる**。
  コピー元が後から帯化されると形状不一致になる(stg の H/GV/DN/BB で
  実発生: コピー元 s%z, g%gv/rn/bb の帯化に確保が追随せず、np>=2 で
  破綻。逐次は帯=全域で一致するため気づけない)。コピー元がどのゾーンで
  縮小されるかも確認すること(X/R のコピー元 sw/rw はゾーン2では全域)。
- シェルのヒアドキュメントは `<< 'EOF'`(引用符付き)。裸の EOF は `$1` や
  `$var` が作成時に展開されて消える。
- **make の ifeq ブロック内の変数代入を行頭タブで書くと、直前ルールの
  レシピに化けてシェル実行される**(エラー127)。条件ブロック内の字下げは
  スペースで。変数名と := の間のタブは無害(行頭のみが罠)。
- **init に早期 return 経路がある派生型は、全成分のデフォルト初期化を
  必須とする**。b%nsrcc、pr%prtype(makepre の門番が未定義値で素通り)と
  同型のバグが2度実発生した一般則。-finit-* は成分に効かず、症状は
  最適化レベル・MPI 実装・ビルドでランダムに変わる。
- gfortran の -Wuninitialized は「全成分デフォルト初期化済みの派生型を
  intent(inout) の init に渡す」形(m_main の t_boundary b →
  m_boundary_init)で「'b' is used uninitialized」の誤検知を出すことがある
  (2026-08 実測: gfortran 15.2.0 で発生、13.3 / 14.2 では同一フラグ
  -Ofast+-fcheck=all で非再現。m_main の変更前後で共通=コード起因でない)。
  規格上、デフォルト初期化を持つ派生型は宣言時点で定義済みであり実害はない。
  警告消しのためのダミー代入等はしないこと。
- **nvfortran は submodule から親モジュールの private 実体へのホスト結合に
  不具合がある**(TPR #27323 系。規格上は見えるべき)。実発生は
  **module 手続きの contained 内側からの二段ホスト結合**(din 等が
  「未宣言」エラー)で、手続き本体レベルの単段参照(adv と同形)は
  解決できる。対処: submodule 内では contained を使わず、補助手続きは
  引数渡しの submodule レベル手続きに昇格させる(§12 の「プライベート
  ルーチンは引数で受け取る」とも整合)。共有定数は定数モジュールに
  切り出して両者が use する。submodule が use 経由の名前(dcp 等)を
  親から継承するのも避け、submodule 側で直接 use する。
- fortls は .mod を読めないため mpi_f08 を "not found" と警告する。
  対処は使用範囲だけの interface スタブを ext_source_dirs に置く
  (コンパイル対象には絶対に入れない)。
- **「和を作ってから比較する」収束判定は単精度で破綻する**
  (fill_depression の実バグ)。許容差なしの水位比較 `z+h > z'+h'` は、
  収束条件が水位のビット一致要求になる。倍精度は10進 cm 解像度の地形
  データに対し実質厳密なので偶然収束するが、単精度は ulp(z+h) ~ 0.1mm
  級の不一致が恒久残存し、3000 回上限まで回って初期充填水が残り、直後の
  流れ計算が破綻する。物理的に無意味な差を許容する tol(1mm)で修正。
  同時に発見した第2分岐の `max(en,·)` は `max(ec,·)` のタイポで、
  厳密算術では無意味な再代入により丸めノイズを毎スイープ注入していた。
  差を直接とる形(重力項の `z(in,jn)-z(i,j)` 等)は安全。危ないのは
  和→比較のパターンのみ。

## 14. 性能に関するメモ

- 9960X(4ch DDR5, 4×CCD): 浅水陽解法は帯域律速で 15–20 スレッドで飽和。
  SMT 域の微増はレイテンシ隠蔽。chichibu 100m は L3(128MB)にほぼ載る
  キャッシュ常駐ケースなので、コンパイラ差が大きく見える(帯域律速の
  大ケースでは縮む)。性能結論は問題サイズ2点で確認する。
- コンパイラ比較(chichibu 100m, OpenMP 48スレッド, 9960X, 2026-xx):
  AOCC 10–11s < nvfortran 12–13s < ifx 15s。ただし ISA 指定(-xHost /
  -march=native)を揃える前の計測であり、揃えた再計測と大ケースでの確認が
  結論の前提。AOCC は Zen 系で有力なため本気の開発環境に採用(-flto 込み)。
- Core Ultra 285 は異種コア(8P+16E)+2ch メモリ。等分割 MPI とは相性が
  悪く、性能測定には使わない(機能・可搬性検証用)。
- 9960X は既定 UMA なので first touch 問題はない(BIOS の NPS/L3-as-NUMA を
  有効にした場合と、スパコンの多 NUMA ノードでは効く)。ハイブリッドで
  「1ランク=1 NUMA/CCD」に束縛すれば first touch への依存自体が減る。
- **実運用機の構成規約: LX406Rz-2(2ソケット Xeon)は「1ランク=1 NUMA
  ドメイン」(ソケットごと、SNC 有効時はサブドメインごと)にバインドして
  走らせる**。各ランクの帯配列(jsh:jeh)が丸ごと自ドメインに載り、
  タッチ順序が無関係になる(first touch への依存が消える)。
  SX-Aurora TSUBASA は VE 内がフラットメモリで NUMA 距離がなく、対策不要。
- allocate+source を自前の並列初期化ルーチンに置き換える first touch 対策は
  不採用と決定(2026-08)。理由: (1)主要計算ループが schedule(dynamic) で
  スレッド→行の対応がステップごとに変わるため、初期化時の配置は実行時の
  アクセス元と一致せず効果が原理的に出ない(dynamic は窓幅の行間変動への
  負荷分散として必要)。(2)実運用機では上記の構成規約で問題自体が消える。
  (3)source= は意味のある初期値(gv=1.0, bb=1.e10, lm=1.0 等)も担っており、
  自前ルーチン化は「配列追加時の初期化登録漏れ」という §13 系バグの入口を
  全確保箇所に新設する。NUMA 起因のボトルネックが実測で出た場合も、最初に
  触るのは該当ループのスケジュール方針+バインドであり、確保方法ではない。
- ハイブリッドの性能評価は「バインド適正化 + 合計スレッド数をコア数以下 +
  chichibu 級以上のケース」で行う。小ケースは毎ステップの集約
  (par_sum_rows + allreduce×2 + ierror)のレイテンシ比率が高く、帯域律速の
  この計算では np×threads を増やしても総帯域は増えないため、みかけ上
  MPI が遅く見える(wave での serial 比 1.5〜2 倍は主にこれ)。
  オーバーヘッドが実測で問題化したら集約頻度の間引きを検討する。
- 出力による rank 0 の遅延は、ハロ交換導入後は全体を律速しうる。対処は
  測ってから: (1)気にしない → (2)非同期 gather / I/O スレッド → (3)MPI-IO。
- 第二段後のメモリの読み方: 見るべきは RES(実ページ)で、確保縮小の成果は
  RES に出る(wave 8p で 80→40MB を実測)。**VIRT は増えるが実害なし**:
  一時配列の確保・解放(ts, wk_out, record の wk 等)に応じて glibc が
  malloc アリーナ(1個 64MB のアドレス空間予約)を増やすためで、実ページは
  伴わない。`pmap -x` で 65404KB 級の匿名領域として見える。
  MALLOC_ARENA_MAX で消せるが得るものはない。
- 小ケースの多ランク時 RES は静的データ+MPI ランタイムの固定費
  (30–40MB/ランク)が支配し、1/nproc には下がらない。場の配列が支配する
  全国級で初めて縮小の効果が体感される。

## 15. 境界条件(外縁4辺・内部ソース)

設計検討の全文は docs/boundary_plan.md(消し込み予定)。以下は正本の要約。

- **境界面の定義は x 番兵に一本化**(2026-08-02)。旧実装の添字ガード
  (`in <= 1 .or. in >= nx ...`)は、エッジ所有規則(k=1..4)と合成すると
  W/S 辺と E/N 辺で非対称になり、**E/N 枠では momentum がフラックスを
  計算するのに continuous が受け取らず質量が創生されて発散する実バグ**
  だった(120 秒 wave で S が 1.021→1.030 に増加後 t=15s で発散を実証)。
  遮断は x=0(領域外・無効セル)への面のスキップだけが担う。
- **方角と添字の正本: 西= i=1、東= i=nx、北= j=1(ラスタ上端)、
  南= j=ny**(m_georef の北西隅原点・行順に一致)。m_parallel 等の
  コメントの「南北」は添字方向の比喩で**地理方位とは逆**なので、
  ユーザー向け文言には使わない。
- **階層の分業: m_boundary =スキーム非依存のデータ供給**(namelist 解釈・
  検証・位置解決・時系列補間。makebdc が毎ステップ現時刻値を用意)、
  **m_swflow_XX =離散化適用**。namelist は fn_boundary 1ファイルに
  族別グループ(&list_bound_edge / &list_bound_source。将来
  &list_bound_inflow / &list_bound_outflow)。**グループ不在=その族なし**
  (iostat<0 で判別)。旧形式 &list_boundary は検出して par_stop。
- **境界条件の適用層は submodule m_swflow_enc_bc に分離**(2026-08-02。
  bc_init / boundary_h / boundary_uvmn / bc_open_face / bc_dispose)。
  m_swflow_enc_adv と同じ「親の私有状態(重み・エッジ状態・方位定数)
  へのホスト結合を活かしたコード分割」で、§12 の排他切替イディオムとは
  別用途。親に残るのはホットパスが読む have_open_bc(bc_init が設定)
  のみ。nvfortran の TPR #27323 は contained 内側からの二段ホスト結合
  で実発生した(§13)。submodule 内の補助手続きは contained にせず
  引数渡しの submodule レベル手続きにする。
- **boundary_uvmn = エッジの uv/mn1 への強制条件の汎用適用点**
  (momentum → par_edge_merge → boundary_uvmn → continuous の位置で
  毎ステップ無条件に呼ぶ。強制条件の族を追加するときはルーチン内に
  節を足し、**有効判定は節の内側**で行う — 呼び出し側は判定しない。
  現在の節は外縁4辺の辺境界のみ。将来候補: 区間流入・流出、
  カルバート出入り口等)。さらに **init でも cold start 時に1回呼ぶ**:
  complete の mn1→mn コミットに乗せ、初回ステップの RK が読む
  「前ステップの境界流量」を内部エッジの初期化(init_enc_status)と
  同格にする。**restore 時は呼ばない** — 保存された uv/mn に境界面の
  値が含まれており、復元後の h から再計算すると保存時の値と食い違って
  厳密復元が破れる。辺境界の節の契約:
  - 境界面スロット(枠上セルの外向き面。既存エッジ配列内に存在)の
    **書き手は boundary_uvmn のみ**。開いた辺の面は乾燥時も 0 を
    毎ステップ書く(前ステップ値の残留防止)。壁辺の面には触れない
    (初期値 0 のまま)。
  - **開いた辺のモデルは2種で、統一しない(設計判断)**: 外側が
    「落ち込み(排水すべき)」か「静水面の続き(保持すべき)」かは
    計算状態から区別できず、参照状態の指定=利用者の意図だから。
    - **自由流出(e_bc_outflow=1。洪水向け)**:
      `uve = max(セル流速の面法線成分, 段落ち速度)`。前進する氾濫流は
      自速度のまま通過(段落ち式単独だと射流を絞って堰き止める)、
      滞留水は自由越流で抜ける。max により流入は構造的に起きない。
    - **長波放射(e_bc_radiation=2。津波向け)**:
      `uve = √(g/he)·(z+h − η_ref)`。静水では厳密にフラックスゼロ、
      波の水位偏差だけを透過し、引き波の流入(負値)も許す。乾いた
      セルはゼロ(境界からの再湿潤はしない簡易化)。検証: 静水 30 秒で
      S がビット不変、波の透過で残留 h_max 偏差 ~2e-4(120 秒後)。
    - **放射の基準水位 η_ref は境界セルごとに保持し、未指定なら初期
      条件から自動導出する**(m_boundary_set_etaref。m_state_init の
      直後に m_main が呼ぶ)。優先順位: (1) bc_eta_* の明示指定
      (一様)、(2) 初期条件が水位固定(s%ini%f_htype=2)なら一様 e0、
      (3) それ以外は境界セルの初期水位 s%e。(3) は初期条件と厳密に
      整合し t=0 の放射フラックスが全境界セルで厳密ゼロ。restore 時は
      復元状態から再導出する(「保存状態を初期条件に使う」意味論と
      整合。波が境界を通過中の保存では基準がずれる既知の制約)。
      MPI: 各ランクは帯+ハロの行だけ埋める(共有行は両隣が同じ s%e
      から冗長導出=通信不要)。
  - **開口は辺を横切る法線+斜めの3方位**(合計=辺全長)。法線のみだと
    dx=dy で開口 41.4%(lp = 1−p_diagratio)しかなく過小流出になる。
    角セルの斜め面は bc_open_face が「両辺 open」を要求(壁の水密性)。
    角の斜め面は複数辺のループが書く(条件が同型なら同値。異なる辺が
    接する角は後に処理される N/S 辺の式が有効)。
  - 符号: スロットの正準向きは k=1..4 所有者基準。sign_e(k) を乗じて
    格納する(東・南辺は負値格納。continuous が読むと外向き正)。
  - **MPI: 東西辺はスロット行 js-1..je(mn コミット範囲と同一)を書き、
    共有行 js-1 / je は隣接両ランクがハロの h から同値を冗長計算する**。
    par_edge_merge は境界面スロットを運ばない(北隣の対応スロットは
    所有セルが枠外=誰も書かない)ため、この冗長書きが RK の他セル面
    参照のランク数不変性の条件。検証は「開辺 + RK 発動条件で np=1,2,4
    ビット一致」。
  - **continuous / restore_uvmn の取り込み条件(bc_open_face)は必ず
    同時に更新する**。restore 側の不整合はリスタート往復ビット一致で
    検出できる。
  - 流量指定型の境界(将来の区間流入)では mn1 を先に確定し
    uv1 = mn1/he で戻す。he は外縁内側セルの水深(+ dv 床)。質量は
    mn1 だけで厳密、uv1 は診断・移流参照用の同階層近似。
- **区間流入(inflow 族)**: 外縁に接するセル区間の法線面に流量
  Q(t) を規定する(boundary_uvmn 節2。mn1 = −Q/開口幅で指向性の流入。
  h1 加算の湧き出しと違い運動量を持ち、u,v,m,n・record に乗る)。
  Q は区間全体の総量。按分は重みの正規化で行うため、どの配分モード
  でも総量は開口率(lp≈0.41)に非依存で厳密。
- **湧き出しの空隙率換算(2026-08-03 修正)**: boundary_h の湧き出しは
  q/gv を加える(降雨 pre·dt/gv と同じ扱い)。修正前は q をそのまま
  加えており、gv < 1(家屋占有)のセルでは注入体積が Q を下回っていた。
  gv=1 のケースはビット不変(x/1.0 = x は厳密)。
- **区間流入の配分モード inflow_dist(2026-08-03)**: 0=開口幅で均等
  (既定。単位幅流量一様)、1=水深按分(重み h。wet セルで流入流速
  一様)、2=通水能按分(重み h^{5/3}。マニング則の等勾配断面)。
  重みは前ステップの s%h で毎ステップ更新。dist=1,2 は均等按分と
  連続ブレンドして適用する(2026-08-03b): fr = u_max/sqrt(g·h_max)
  (最深セルに全面按分したときの流速比)、α = clamp(2(1−fr), 0, 1)、
  qw = α·重み按分 + (1−α)·均等按分。配分が現在の h の連続関数に
  なるためモード切替の不連続・振動が原理的になく、記憶する状態も
  ない(リスタート往復も厳密)。α·fr = 2fr(1−fr) <= 1/2 なので
  最深セルの配分流量は常に限界流量の半分以下(薄膜断面への流量集中
  →ダム崩壊流→発散、の実発生挙動への安定化を兼ねる。当初実装の
  二値ガード+wet 率過半条件は、低水時に澪筋(wet 率 ~10%)だけが
  wet の断面=本モードの主用途で均等按分に落ちて乾いた河川敷に
  流量を撒く欠陥があり、閾値ヒステリシス案(状態の記憶が必要で
  save/restore の版更新を伴う)より連続ブレンドを採用して撤去)。MPI: 重みの水深ベクトルは「所有ランクだけが埋める
  ゼロ初期化ベクトル+par_allreduce_sumr」で全ランクに共有
  (§11 の項参照)。共有行 js-1 の冗長書きも同一ベクトルから同値になる。
  津波の入射をフラックス規定で扱う案は見送り(引き波の符号付き
  フラックスと反射波の再反射の設計が必要。当面は stage 族=造波板
  +他辺放射で代替し、将来「入射+放射」境界で扱う。boundary_plan.md)。乾床への流入は he = max(h, 限界水深 (q²/g)^{1/3}, dv) の床で
  uv の発散を防ぐ(ネスティングが水深も渡す事情の簡易代替)。
  面型はセル別配列 bt_cell(辺の型を初期値に流入面を上書き)で解決し、
  bc_open_face が参照する。流入は非負のみ(流出は stage / source)。
  同一セルへの流量と水位の同時規定は過剰決定になる(クランプが
  mn1 の質量を捨てる)ため不可 — ネスティング型の両立(境界行 stage
  +内側面の流量規定)は将来の内部面上書し機構で(boundary_plan.md)。
- **初期条件は解釈済みの t_initial(s%ini)として t_state が保持する**
  (list_initial の生値は m_state_init が解釈して写す。set_z/set_h/
  set_uv・user フック・他モジュール(η_ref 導出)は s%ini を参照)。
  f_htype: 0=水深固定 h0 / 1=水深ファイル / 2=水位固定 e0
  (h = max(e0−z, 0)) / 3=水位ファイル。分布ファイル(fn_hinit)は
  f_input_mode の形式で全ランク冗長の全域読み(ゾーン2)。
- **水位規定セル群(stage 族)**: セル集合の水深を毎ステップ
  `h1 = max(η(t) − z, 0)` に強制する(boundary_h の最後=同一セルでは
  湧き出しより優先)。流域抽出計算の出口(η を河床より低く=完全
  排水口。従来の「周囲を海で囲む+段落ち」トリックの置き換え)と
  背水・感潮域(η 時系列)が用途。規定セルは通常セルのままなので、
  周囲との面フラックスは momentum が規定水位の作る勾配から通常計算し、
  u,v,m,n・record に自然に乗る(edge 族のような uv/mn 強制は不要)。
  クランプは双方向(水位維持のための補給も起きる)。
  - **落とし穴(実際に踏んだ)**: swflow init の boundary_h はクランプを
    適用するが、その時点で makebdc は未実行。η の現在値は init_stage が
    t0 で補間初期化しておくこと(怠ると型既定値 0 で初期クランプされ、
    規定セルが t=0 に不正排水→段差ダム崩壊で発散する)。
  - 規定セルと周囲の水位差が大きい設定は局所ダム崩壊流になり CFL(dt)
    の見直しが要る(wave の dt=0.05 は既定で Cn_max≈0.9 と余裕がなく、
    5cm の規定でも波との重畳で発散した。dt 半減で安定を確認)。
- **STG は辺境界条件非対応**(凍結方針 §7)。既定(全辺不透過)以外の
  指定は init で par_stop。
- 検証階段: 機能無効(fn_boundary 無指定/全辺既定)で既存 reference と
  ビット一致 → -fcheck np>=2(開辺ケース含む)→ 開辺で np=1,2,4 の
  逐次ビット一致 → 開境界リスタート往復ビット一致。
- **init での boundary_h 呼び出しが restore 安全である根拠(3前提)**:
  (1) 降雨: s%pre は 0 確保で、makepre は run_main が初期化完了後に
  初めて呼ぶ(swflow init 時点では構造的に +0)。(2) ソース: makebdc
  未実行のため q=0。(3) ため池転送: 保存状態は最終ステップの
  boundary_h 適用後なので冪等(保存 h>0 はため池満杯時のみ、余力が
  あるなら h=0)。**makepre の呼び出し順序を変える・pre を初期条件化
  する等の変更はこの前提を崩す**ので、m_swflow_enc_init の該当
  コメントと併せて要再検討。
- 落とし穴(既存仕様): **user_initial フックは restore の後に実行される**
  (§11 の初期化順序)。リスタート検証で復元運転側のフックを無効化
  しないと、初期水面(wave の山など)が復元状態に再加算されて
  「復元が壊れた」ように見える(実際に踏んだ)。

## 16. 地下水モジュール(m_gwflow)の設計(2026-08-05 決定)

設計の物理的背景・側方流動の定式化は docs/handoff_gwflow_tani.md が正本。
本節はパラメータ体系と geoinfo/gwflow の責務分担の決定事項を記す。

- **パラメータ体系は単一ファイル**: fn_gwflow の1ファイルに全 namelist を
  収める(複数ファイル案は不採用: fn_* は1モジュール1ファイルの慣習、
  共有パラメータの置き場が割れる、"-" での sysparam 畳み込みと両立しない)。
  - `&list_gwflow`(制御)に**2つの独立選択子** `f_gwvertical`
    (0:なし, 1:バケツ, 2:Green-Ampt)/ `f_gwlateral`(0:なし=鉛直のみ。
    1以降は予約・未実装)を置く。両方 0 で fn を書いたまま一時無効化。
  - モデル固有グループ `&list_gwflow_<モデル名>` は選択されたモデルの
    init が同じファイルから自分で読む(m_gwflow_bucket 契約)。namelist は
    自グループ以外を無視するため、グループを書いたまま選択子 0 で
    無効化して A/B 比較ができる。
- **f_gwlateral=0(既定)のとき側方流動の資源は一切確保しない**
  (束縛・専用配列・par_halo_cell(s%hg)・save 項目のいずれも)。検証は
  「機能追加=無効時ビット一致」をそのまま適用する。
- **土層厚 sd と比湧水量 sy0 は geoinfo が所有**(rn, rscap と同類の
  静的物性)。境界規則: モデル非依存の土地固有量(sd, sy0)= geoinfo /
  モデル固有の輸送係数(K_sv, psi_f, 将来の K_sh)= fn_gwflow の
  モデル私有グループ。初期地下水面深度などの初期条件は geoinfo に
  入れない(fn_initial / リスタート系の管轄)。
- **g%sd の3状態ライフサイクル**(カーネルは常に配列 g%sd(i,j) を参照し、
  分布/一様の分岐を持たない):
  1. gwflow 無効(fn_gwflow 未指定)→ 未確保(メモリゼロ)。
     f_sdtype=1 が書かれていても読み込みをスキップ(通知の上)
  2. f_sdtype=0(固定値)→ sd を要するモデルを選んだときだけ
     m_gwflow_init が `m_geoinfo_require_sd` を呼び、帯+ハロを
     sd0 で埋めて遅延確保(確保コードの所有者は geoinfo)
  3. f_sdtype=1(ファイル)→ rank0 が読み込み+scatter_coeffs で
     帯配布(方式2)。データ健全性(負値)は geoinfo、可用性
     (モデルが sd を要するか)は m_gwflow init が検証
  - 実行判定 g%sd_dist は namelist 由来で全ランク同一(collective 安全)
- **sy0 は当面スカラーのみ**(S_y = n_e の統一。handoff §6.1 案1。
  鉛直/側方の結合点の質量保存が構造的に成立する)。分布が必要になったら
  f_sytype を sd と同じ3状態方式で追加する。
- **モデル calc には実効時間刻み dts = p%dt × idt_gwflow を渡す**
  (dt_gwflow による間引き時の実効レート整合。従来 bucket は p%dt を
  使っており間引き時に浸透が 1/N になっていた。2026-08-05 修正)。
- greenampt の **F ≡ s%hg 恒等**: 排水・側方流出を持たない現段階では
  累積浸透深 F は s%hg と恒等なので私有状態を持たない(リスタートも
  m_state の hg 保存で整合)。側方流動の導入で恒等が崩れたら F を
  私有状態に昇格し契約5(gwflow_greenampt.dat)で save/restore する。

### 16.1 側方流動(m_gwflow_lateral)の設計(2026-08-05 決定)

- **線形 Darcy 案は不採用(棚上げ)**: エッジ状態レス+陽解法では
  非線形 Boussinesq とのコスト・メモリ差が実質なく、「CFL が実行前に
  確定する」利点も h_gw <= sd の構造的上界(D <= K_sh*max(sd)/sy0)に
  より Boussinesq 側でも static に成立するため(init で検査し超過は
  par_stop)。詳細は handoff_gwflow_tani.md §3.2。
- **側方は単一モデル直接呼び出し**: 選択子 f_gwlateral(0:なし,
  1:Boussinesq)の外部界面は維持しつつ、内部の abstract interface +
  ポインタ束は作らない(1モデルでは死んだ柔軟性)。第2の側方モデルが
  実在した時点でポインタ束へ昇格する(等価リファクタとして逐次ビット
  一致で検証可能)。鉛直側のポインタ束方式は従来どおり。
  第2モデルの導入予定がないため、モジュール名・namelist グループ名も
  m_gwflow_lateral / &list_gwflow_lateral に短縮した(2026-08-05 改名。
  旧名 m_gwflow_lateral_boussinesq / &list_gwflow_lateral_boussinesq)。
- **離散化は8近傍 FV・エッジ流量4成分の2ループ構造**(2026-08-05 変更。
  初版の4近傍・セル中心・冗長両側計算から置換): ループ1で各セルが所有
  するエッジ成分 k=1..4 のフラックスを計算し、ループ2で計算済みエッジ
  流量から連続式+飽和超過の引き渡しを行う。din/djn/die/dje/ke/sign_e の
  規約と通過幅配分(gw_diagratio。既定は m_swflow_enc の p_diagratio と
  同値 2/(2+√2)だが独立の namelist 変数。ENC 側の設定に依存しない)は
  m_swflow_enc と同一。対角結合により格子方向バイアスが減り、斜め谷筋の
  収束流(handoff §3.2.2)を表現できる。
- **全水頭 H = (s%z - sd) + s%hg/sy0 [+ s%h]**(handoff §3.2.3)。
  s%h の寄与は飽和セル(s%hg >= sd*sy0。超過引き渡しのクランプと
  同一式)のみ。不飽和セルの湛水は鉛直浸透の駆動力であって側方流の
  駆動力ではない。
- **エッジ配列は一時作業領域(「永続エッジ状態レス」に原則を精密化)**:
  フラックスは無履歴なので、エッジ流量 q(1:4, 0:nx, jsh-1:jeh) は calc 内で
  書いて読み切るスクラッチ。二重バッファなし・save/restore 対象外・
  par_halo_edge / par_edge_merge 不要(§4a の効果は全て維持)。
  乾湿で変わるエッジは書き手が毎回 0 を含めて必ず代入し、マスク起因で
  書かれないエッジは確保時 0 のまま恒久無フラックス(x マスクは静的)。
- **界面エッジの冗長計算**: 帯界面のエッジ成分(行 je の k=1..3)は
  書き手ループをハロ行 je+1 まで延長して自ランクでも計算する。エッジの
  格納向きが正準に定まるため、南北の両ランクは同一のセルハロ入力・
  同一の式・同一の向きからビット厳密に同じ値を得る(§11 の
  「冗長計算=配布機構」の実例第2号。初版の「c/n 入れ替えでビット同値に
  なる式形」の技巧は正準向きの導入で不要になった)。
- **通信は側方 calc 冒頭の par_halo_cell(s%hg) と par_halo_cell(s%h) の
  2本のみ**。冒頭に置く理由: 鉛直モデルと超過引き渡しが帯のみを更新
  するため、末尾交換では次回呼び出しまでに古くなる。s%z のハロは
  m_swflow_enc のステップ頭交換に依存(呼び出し順 swflow→gwflow→
  geomorph が前提。順序を変えるなら側方でも交換を足すこと)。
- 2ループ分離により**時刻 n の s%hg の退避(初版の wk)は不要**
  (ループ1は更新前の hg/h のみを読む)。飽和超過分の地表流への
  引き渡しはループ2に畳み込む(ループ1が時刻 n の s%h を読み終えて
  いるため安全)。
- **境界条件**: 領域外・海域セルとは無フラックス(海への地下水流出は
  当面扱わない。必要になったら要設計)。
- **Green-Ampt の F := s%hg 閉包**(側方併用時): F は「累積浸透深」で
  なく「現在の貯留量」になるが、現在の水分状態に吸引項が依存する
  Green-Ampt 変種として意図的に採用(側方排水で浸透能が回復。私有
  状態・契約5の保存が不要になり、リスタートは s%hg だけで閉じる)。
- **バケツモデルは側方流動と組めない**(2026-08-06 決定): バケツの容量は
  gw_capacity の直接指定(geoinfo 非依存の抽象貯留=依存ゼロの実験用・
  契約見本という存在価値)であり、側方の飽和判定 sd*sy0 と二重定義に
  なるため、f_gwvertical=1 + f_gwlateral=1 は init で par_stop。
  「土層厚×比湧水量を容量とする定数浸透能の鉛直モデル」は greenampt の
  gw_psif=0 縮退で表現できるため、バケツの sd 必須化は不採用。

## 17. 堤防(仮想壁面)モデルの設計(2026-08-06 決定)

河道セル(rw>0)と堤内地セル(rw=0 の陸)の間の全エッジ(**対角含む**)に
仮想壁を立て、堤内地からの排水機能をモード切替する。ENC 専用
(STG は対象外)。実装は m_geoinfo(setup_bank)+ m_swflow_enc
(calc_kth_momentum 内の bank_wall フック。rivermouth_drop と同型)。

- **有効化は fn_channel の fn_bank / bank0 の有無**(2026-08-06 に
  list_geoinfo から fn_channel(&list_channel)へ移行。§18)。無効時は
  zbank を確保せずホットパスの分岐も通らない(無効時ビット一致で検証)。
  fn_bank は河道セル位置の「堤防高さ」分布で、**-900 以下は堤防なし**。
  bank0 は全河道セル一律の固定値(fn_bank と排他)。
  堤防には fn_rw が必須(init で par_stop)。
- **内部表現はセルごとの天端絶対標高 g%zbank**(河道セル持ち。
  番兵 zbank_none、有効判定は zbank > zbank_min)。エッジ配列でなく
  セル配列にした理由: メモリ 1/4、堤内地 DEM ノイズの影響の抑制、
  rivermouth_drop と同じ「マスク+セル値のその場判定」で実装が閉じる
  (2026-08-06 ユーザー決定)。天端はエッジの両側のうち**河道側セルの値**
  を使う。河道幅1セルでは左右岸が同値になり、幅2以上では岸ごとの
  河道セルに別値を与えられる。左右岸の大域判定は持たない(蛇行・
  分合流で破綻するため)。
- **堤防高さの基準 f_bank_datum は領域一様**(0:河床(掘込後 z)基準,
  1:堤内地セル標高基準, 2:絶対標高)。3基準とも init で絶対標高に
  変換され、時間ループに基準の違いは残らない。セル別の基準指定は
  不採用: どの基準も絶対標高ファイルに前処理で変換できるため表現力が
  増えない。datum=1 では天端が隣接エッジごとに異なりうるため、
  セル外周の堤防エッジにわたり **f_bank_aggr(0:平均, 1:最小, 2:最大)**
  で1値に集約する(平均=ノイズ抑制の既定。最小=越流開始の物理に忠実、
  最大=堤防機能の安全側)。datum=0/2 では集約は恒等。
  注意: 幅1河道の datum=1 は左右岸の入力値が同じでも集約前の天端が
  岸ごとに異なる(集約で1値に潰す仕様)。
- **天端は静的**(絶対標高)。geomorph による z の変化には追従しない。
- **水理モード f_bank_mode は &list_channel(領域一様。2026-08-06 に
  list_enc から移行)**。0:越流のみ
  (単純堤防。双方向とも天端まで不透過、超えたら堰越流)、1:樋門
  (逆止弁。堤内水位≧河道水位なら壁なしの通常計算で逆向き成分のみ
  0 にクリップ、河道水位が高ければ天端まで不透過+越流)、2:強制排水
  (天端以下では河道水位によらず堤内地の全水深で段落ち=rivermouth と
  同式。水位が天端を超えたらモード0と同じ双方向堰越流に切替)。
  排水工学の通用語(自然排水=樋門の重力排水)との混同を避けるため
  「自然排水」の名は使わない。セル別モードが必要になったら zbank と
  同様のセル配列で拡張する(内部はその場判定なので互換拡張)。
- **越流は本間公式**(自由: q=0.35·h1·√(2g·h1)、潜り:
  q=0.91·h2·√(2g·(h1−h2))、切替 h2/h1=2/3 で連続)。両側水位が
  天端を超えて水位差が小さい状況で段落ち式(限界流)を使うと過大流量で
  振動するため。流向は水位の高い側→低い側。上書き後の過大流出は
  既存の f_exflux_reduction が抑制する。
- **海(sw)が絡むエッジは対象外**(rivermouth_drop の管轄。河道—海は
  f_rivermouth_drop、河道—堤内地は bank)。
- **MPI**: zbank は方式2(rank0 が全域構築 → scatter_coeffs で帯+ハロ配布)。
  構築は掘り込み(adjust_rw)と user フックの後。実行判定 bank_active は
  namelist 由来で全ランク同一(collective 安全)。ホットパスの近傍参照は
  ±1 でハロ幅2に収まる(sw/rw/gv と同じ監査枠)。
- **河床の掘り込みの分布指定 fn_depth_rw** を同時に追加(河道セルの
  掘り込み深さ分布。負値は 0 扱い。無指定なら従来の一様 depth_rw)。
  z は全ランクが全域保持のため、z 系ファイルと同様に全ランクが読む。
- 既知の制約: (1) 天端はセル1値なので同一セルのエッジごとの天端差は
  表現できない(必要なら霞堤等は該当セルの値を下げて表現)。
  (2) 越流部の幅はエッジの開口幅 l8 で決まり、実堤防の越流幅は
  考慮しない。(3) 樋門・ポンプの容量(流量上限)は未実装(必要に
  なったらモード別パラメータで拡張)。特に強制排水(f_bank_mode=2)は
  排水能力が無制限のため、全河道への一括適用のような極端な設定では
  流域全体の出水が河道に集中し、急勾配区間の河道内で非現実的な
  水深・流速に至り得る(chichibu 派生の合成ケースで確認。既存の
  発散ガード 250 m/s で停止する)。容量制限を導入するまで、適用は
  排水機場が実在する区間に限ることを推奨。

## 18. 河道水理モデル(fn_channel: 開口補正・サブグリッド河道幅)の設計(2026-08-06 決定)

セルサイズ未満の川幅の通水能と、河道内水位の上昇による氾濫を、
**別ソルバの 1D 河道を導入せず ENC カーネル内のサブグリッド幾何**として
モデル化する。LISFLOOD-FP subgrid(Neal et al. 2012)と同思想の連続退化
型で、**川幅が途中でセルサイズを跨いでもモデルの切替が存在しない**
(W ≥ 面長で全係数がちょうど 1 となり、解像河道=掘り込み+§17 壁の
表現とビット厳密に一致する)。RRI 型の1セル2水位(斜面+河道)は不採用:
河道セルの水位は河道内水位の1本で、セル内の非河道部の貯留は表現しない
(ユーザー決定)。ENC 専用(STG は init の par_stop で明示ガード)。

- **namelist の線引き(改定)**: セルの地形・物性を作る量(fn_rw、
  depth_rw / fn_depth_rw、rn0_rw)= list_geoinfo /
  **エッジの通水構造と水理モード= fn_channel(&list_channel)**。
  fn_channel は fn_* 慣習(未指定なら完全に不活性)で、fn_rw が必須。
  段階構造: fn_bank または bank0 → 堤防(§17)+開口補正 /
  fn_width → サブグリッド幅(fn_bank / bank0 無指定なら
  **高さ0・堤内地セル標高基準の堤防を自動有効化**。壁の存在が
  開口補正・幅キャップの整合条件のため)。
  旧配置(list_geoinfo の fn_bank / f_bank_datum / f_bank_aggr、
  list_enc の f_bank_mode)は実運用前のため互換入力なしで移行
  (旧 param は namelist 読込エラーで検出される)。
- **開口補正 f_bank_opening(既定 1)**: 堤防壁で恒久的に塞がれた
  斜め開口の通過幅シェアを、同じ横断方向の河道—河道「法線」エッジ
  (成分2, 4)へ振り替える(成分4: (lpy+nb·ldy)/lpy、nb = エッジ両側
  セルの塞がり本数の平均 0〜2)。根拠: 直線の幅1セル河道は斜め開口が
  壁で死に、通過幅が法線開口 lp ≈ 0.414 に縮退する(**壁がなくても
  隣接セルが乾いた高地なら実質同じ過小通水が現行から存在する**)。
  斜めエッジ(蛇行のショートカット)と壁エッジ(越流の敷幅)は不変。
  横断方向の開口合計は面全長で厳密に保存され、塞がりゼロ(広い解像
  河道の内部)は係数1で現行と厳密一致。**壁なしでの静的補正は作らない**
  (堤内地が湿潤化すると斜めが復活して二重計上になるため。自然河岸は
  高さ0堤防で表現するのが正: 越流も本間式になり物理的にも適切)。
  旧挙動との A/B は f_bank_opening=0。
- **サブグリッド河道幅 fn_width**(河道セル属性 W。矩形断面。0 以下は
  幅情報なし=解像扱い。方式2で rank0 読み+scatter):
  - **通水**: 河道—河道エッジの通過幅係数に q = min(W_e/面長, 1) を重畳
    (W_e = 両セルの正の幅の最小値=狭窄側支配。面長: 成分4= dy、
    成分2= dx、斜め= √(dx·dy)。dx=dy なら屈曲部でも横断合計が厳密に
    W_e になる。dx≠dy の斜めは幾何平均の近似)。
  - **貯留**: セル平面積率 wfrac = min(W·L_ch/(dx·dy), 1) で水深換算を
    除算補正(gv と同じ意味論の静的版。下限 min_gv)。
    **L_ch = 河道隣接8近傍への半距離 w8dr/2 の総和**(直線 x 河道で
    dx。屈曲・合流・異方格子が1つの定義で閉じる。孤立セルは
    min(dx,dy))。適用箇所は質量換算の6箇所(momentum の dh、RK 内
    ループ、continuous、bc の降雨・湧き出し・境界面抑制)で、
    **運動量の建物項(gve, bb)には触れない**(河道の岸は分布抗力体
    ではない)。降雨はセル全面の雨が河道断面へ集中する(pre·dt/gv/wfrac。
    gv の建物集中と同じ意味論)。
  - エッジ係数 frw・平面積率 wfrac は init 構築の静的テーブル
    (重み定数と同格の読み取り専用。無効時は未確保+スカラー分岐のみ)。
    **構築系と bank_wall は submodule m_swflow_enc_channel に分離**
    (2026-08-06。bc/adv と同じコード分割用途)。ただし bc と違い
    **状態(frw/wfrac/cwx/cwy と有効フラグ)は親モジュールに置く**:
    ホスト結合は submodule→親の一方向で、これらを読むのは親カーネルの
    ホットパスだから。係数の乗除算(6箇所)も親カーネルにインラインの
    まま。bank_wall はエッジ毎のホットコールが submodule 境界を跨ぐ
    (インライン化は nvfortran だけ効かない。adv_edge と同じ受容。§3)。
    構築は rw/sw/x(ゾーン2で全域)+ zbank/wrw(帯+ハロ)から
    各ランクが冗長実行(通信不要。§11)。**エッジ行は jsh..jeh-1 まで**
    (成分2の両セル読みが帯上端を超えないこと。-fcheck np=2 で実際に
    捕捉した境界バグ)。
  - **f_channel_advection**(1:通常(既定)、0:河道セルを含むエッジで
    移流項を落とす)。強い幅不均質下での安定化オプション(実行時
    フラグ=A/B 可能)。既定値は等流ベンチマーク整備後に再検討。
- **破堤(&list_channel_breach。2026-08-06 実装)**: サイト=隣接する
  河道セル (ic,jc)・堤内地セル (il,jl) の対(=エッジ1本。幅1セル河道の
  左右岸は堤内地セル側で自動区別)。実効天端
  zeff(t) = zgnd0 + f(t)·(zcrest0 − zgnd0)(f: 時系列 0〜1、1=天端高、
  0=堤内地盤高。線形補間・端値保持。f>=1 / f<=0 は端値に厳密固定=
  無破堤・全破堤とのビット一致条件)。f=0 は当該エッジの「高さ0堤防」
  =地盤高の本間堰に退化(破堤流量の堰式計算は実務標準どおり)。
  実装はサイトリスト+**行バケット**(行ごとのサイト範囲表): bank_wall は
  サイトのない行を整数比較1回で素通りし、ある行だけ数件を照合する
  (エッジ配列・セルマスクの追加なし。zbank へのフラグ埋め込みは
  PREC=single の精度と有効判定の可読性を壊すため不採用)。
  zeff は毎ステップ全ランクが冗長計算(t の純関数=通信不要)。
  zcrest0/zgnd0 はセル対を帯内に持つランクだけが評価(bank_wall が
  当該エッジに触れるランクの十分条件)。検証は全域データ分は全ランク
  冗長、zbank 有効性は帯所有ランク+par_allreduce_maxi → collective に
  par_stop(§11)。履歴状態なし= save/restore 対象外(save_version 不変)。
  基準地盤 zgnd0 は init 時の s%z で静的(侵食に追従しない。天端と同じ)。
  開口補正 frw は不変(破堤エッジは静的テーブル上「壁」のままで、
  堰式が流量を律するため二重計上なし=越流と同じ整理)。
  複数セル区間の決壊は複数サイトで指定(決壊幅はエッジ開口幅の粒度)。
- **新規の保存状態はゼロ**(W・係数とも静的)。save_version 不変、
  リスタートは既存機構のまま閉じる(restore_uvmn は continuous と
  同一の係数を読む=復元ビット一致の条件。§7)。
- **検証階段(実施済み 2026-08-06, gfortran/OpenMPI)**:
  無効時ビット一致(wave/chichibu、逐次+np)/ -fcheck np=2 を最適化
  より先に(規律3)/ bank0=一様分布ファイルとビット一致 /
  f_bank_opening=0 が厳密数学ビルドで変更前とビット一致 /
  **W ≥ 面長で堤防のみとビット一致(退化性)** / 幅有効 np=1,2,4 が
  逐次と ULP=0。注意: -Ofast 下では**等価コードでも再コンパイルで
  FMA 縮約が変わり最終桁が揺れる**(§9)。等価性の判定は厳密数学
  ビルド(-O2)で行った。
- **既知の妥協・制約**(設計合意済み):
  (1) 河道セル内の堤内水位・非河道部の貯留は非表現(あふれた水も雨も
      隣接セルへ。氾濫域が最大1セル外側へずれる近似)。
  (2) 蛇行によるセル内河道長の延長は非表現(必要なら将来 L_ch 乗数)。
  (3) 摩擦の径深は広幅近似 R=h のまま(矩形断面補正は将来フラグ)。
  (4) 樋門モード(f_bank_mode=1)の堤内→河道透過時は斜めエッジが
      過渡的に生き、横断合計が面長を僅かに超えうる(排水方向のみ)。
  (5) 境界条件(§15)の辺開口・区間流入の幅は未補正(河道が外縁に
      接するケースは将来課題)。
  (6) 並列河道セル(ラスタ化で角が2セル太りした箇所)は各セルが W を
      主張し局所的に過大通水になる。**河道マスクは単線4連結を前提**
      とし、保証は前処理側の責務(init の検出警告は将来課題)。
  (7) 幅データの W が極端に小さいと wfrac 下限(min_gv)まで水深換算が
      増幅され dt 制約が厳しくなる(現行の彫り込みセルと同種)。
- **u, v の正規化(vv 正規化。2026-08-06 実装)**: 幅キャップは
  セル平均 u, v を河道内流速の W/面長 倍に縮めるため、摩擦・植生等の
  抗力・移流が読む流速(vv ← u,v)が系統的に過小になる。これを
  セルの方向別通水率 **cwx/cwy =(幅キャップ後の開口和)/(キャップ前の
  開口和)** による除算で正規化する(continuous / restore_uvmn の2箇所。
  完全一致=復元ビット一致の条件)。比の形なので W ≥ 面長では
  分子=分母となり厳密に 1.0(退化性がビット一致で保たれる)。
  壁エッジは u,v に寄与しないため和から除外する(含めると比が 1 に
  希釈される)。**m, n は正規化しない**: m, n は「流量をセル幅に
  塗り広げたセル平均」であり、m_record のフラックス測線
  Q = Σ(m,n)·n̂·ℓ が河道セルを完全横断する測線で実流量を厳密に
  復元する条件(m_record 冒頭コメントと対)。u,v(出力・プローブ)は
  河道内流速、qq は塗り広げ量、という読み分けになる。
  **測線は河道セルを完全に横断させること**(部分横断は ℓ/セル幅 倍
  しか計上されない。§10 の測線配置の注意に追加)。
- **河道内植生の抵抗(gv/bb の河道セル適用)との両立(2026-08-06 確認)**:
  gv/bb は河道セルでもマスクされず全項に有効(コード変更不要)。
  貯留は /gv/wfrac の直列除算=実効貯留面積 (W·L_ch)·gv で「河道内に
  植生が立つ」の正確な合成(二重計上なし)。運動量の植生スケーリング
  (×gve、抗力 (1−gve)h/bbe)は wfrac と独立に作用する。注意:
  (1) 河床粗度は rn(rn0_rw)・植生群落は gv/bb+Cd に分担し二重計上
  しない(データ準備の指針)。(2) 岸エッジでは河道の植生 gv と堤内地の
  建物 gv が平均される(bank 有効時は壁/堰支配で実害僅少)。
  (3) Cd(cd)・付加質量係数 cm は領域一様のまま(植生と建物で
  別値が必要になったらセル別化を検討)。(4) 実効貯留率は gv×wfrac まで
  下がるため dt 制約に注意。

## 19. 地形変化モジュール(m_geomorph)の実装(2026-08-07)

河床変動・斜面浸食の設計検討の全文は docs/geomorph_plan.md(F1 以降の
設計はそちらが正本。実装完了とともに本節へ移して消し込む)。本節は
実装済みの決定(F0: クリープ+加速係数)を記す。

- **加速係数 morfac(MORFAC 方式)**: 地形更新だけを morfac 倍する。
  実装は gwflow と同じ実効時間刻みの供給
  (dts = dt × idt_geomorph × morfac を calc が各プロセスに渡す)。
  **全プロセス共通の1個**(プロセス別にすると「地形の時間」が分裂し、
  斜面供給と河床変動の同時性が壊れる)。解釈: 1回の計算 = morfac 回の
  同一イベントぶんの地形変化。検証は morfac=N と morfac=1×(N倍時間)の
  等価性ベンチマーク(test/creep に実装済み。線形拡散では時間離散化の
  O(dts) 差のみ)。
- **クリープ(f_creep)は4近傍の保存形フラックス(5点ラプラシアン)**:
  等方線形拡散 D∇²z に厳密整合し、ガウス丘の解析解と直接比較できる。
  斜め成分の枠(cw(1), cw(3)=0)は構造として確保してあり、8近傍化は
  重み定義の変更で閉じる。ただし**8近傍化の際は実効拡散係数が D と
  一致する重みの正規化が必須**(gwflow_lateral の l8/w8dr 流用では
  実効 D が (lp+√2·ld) 倍にずれる。解析解ベンチが検出器になる)。
- **2ループ構造・エッジスクラッチは m_gwflow_lateral の複製**
  (ループ1: エッジ流量、帯界面はハロ行 je+1 の冗長計算=ビット厳密な
  配布 / ループ2: 反対称集計で発散。土砂体積は機械精度で保存)。
  スクラッチ q(1:4, 0:nx, jsh-1:jeh) はモジュール私有(t_geomorph は
  calc に intent(in) で渡るため。単一インスタンス前提 §12)。
- **陽解法の安定条件は init で静的検査**: D·dts·(1/dx²+1/dy²) ≤ 1/2。
  D・格子・dts が全て namelist 由来なので実行前に確定し、超過は
  par_stop(判定は全ランク同一 = collective 安全)。
- **境界**: 領域外(x=0)・海(sw>0)とは無フラックス(海域の地形は
  不変。gwflow_lateral と同じ整理)。
- **s%z のハロ交換は calc 末尾の1回**(§11 の浸食 TODO(1) の解消。
  初回呼び出しのハロは初期化の帯+ハロ切り出しで有効。クリープの
  ±1 参照と流れの重力項の両方をこの1回で賄う)。

### 19.2 掃流砂 Exner(f_fluvial。F1b。2026-08-07 実装)

- **平衡流砂量による河床変動**: (1−λ)∂z/∂t = −∇·q_b。掃流砂の適応距離は
  局所(格子スケールで平衡が成立)という物理区分が「掃流=平衡 Exner、
  浮遊=輸送方程式(F2)」の実装段階分けと一致する(geomorph_plan.md §5.4)。
- **エッジ水理量は両セル平均、流向はセル平均流速のエッジ法線射影**
  (2026-08-07 ユーザー決定)。エッジ流量 mn は swflow_enc 私有であり、
  経験式の平衡流砂量に mn の厳密整合は不要のため、t_state の公開量
  (u, v, vv, h)で閉じる。τ* = n²V²/(s·d50·h^{1/3})(マニング閉じ。
  g は相殺)。流砂量式は f_qbform(1: 芦田・道上, 2: MPM)。
- **2ループ構造は gwflow_lateral と同型**(エッジスクラッチは creep と
  共有の wrk%q。各プロセスのループ1は対象セルの4成分を 0 込みで必ず
  上書きする契約)。
- **【実バグ】calc 冒頭の par_halo_cell(h, u, v, vv) は必須**:
  swflow・gwflow は帯のみを更新するため、ステップ頭交換のままでは
  ハロ行の流速・水深が前ステップの値に古びる。界面エッジの冗長計算が
  隣接ランクと異なる入力から同一エッジを計算し、反対称性=土砂体積保存が
  壊れる(np=2 の保存則検定で Σdz が 1.7e-3 に飛んで検出。修正後は
  4.6e-16)。gwflow_lateral の「冒頭に置く理由」と同じ構図。
- **クランプ3層**: (1) エッジ別の可動層クランプ(風上セルの sd を
  このエッジ単独で超えない。lateral の過大流出抑制と同型)、
  (2) エッジ別の dzmax ガード(地形波 CFL 相当。クリップは流量段階=
  保存則を保つ。発動数は dispose で par_warn)、(3) ループ2の岩盤床
  クリップ(複数エッジ同時流出の僅かな超過の最終防衛。失う体積は
  vleak に計上し dispose で par_warn — 黙らない)。
- **sd 共動更新と gwflow 結合**: z と sd に同じ Δz を適用(帯水層底
  z−sd 不変)。gw_active 時は容量 sd·sy0 が現在の s%hg を下回った分を
  s%h へ引き渡す(飽和表土の水が地表に出る)。検証: 飽和薄土層
  (sd0=0.03, ksv 大)+浸食で引き渡しを発火させ、S_grnd→S_surf の
  移動を確認、S_total は 14 桁不動。
- **クリープは当面 sd に触れない**(土層のない理想地形ベンチマークを
  保つ。実地形でクリープを使う段になったら sd 共動+クランプを追加)。
- **制約ガード**: STG は par_stop(init 時コピーのため)。
- **サブグリッド河道幅(fn_width)併用対応(2026-08-07 実装)**:
  swflow_enc の have_width/have_frw/frw/wfrac を **protected 公開**にし
  (読み取り専用の口。書き手は swflow_enc と channel submodule のみ)、
  掃流砂はエッジ流量に frw(水と同じ開口・幅キャップ)、Δz 換算に
  1/wfrac(河道底のみ変動=改訂2の決定)を乗じる。可動層・dzmax
  クランプも供給側セルの 1/wfrac で河道底厚さに換算。
  **浮遊砂は移流・E-D とも無修正で整合**(移流は continuous のミラーで
  自動、E-D は hs・Δz とも河道断面あたりの量で wfrac が相殺)。
  **堤防(§17)エッジ=河道—非河道の境界では掃流砂を運ばない**
  (掃流砂は河道内に閉じる。越流時の土砂は浮遊砂が壁込みの実フラックス
  mn1 で運ぶ、という輸送形態の分担)。

### 19.3 浮遊砂(f_suspend。F2。2026-08-07 実装)

- **責務の分業**: 移流 = m_swflow_enc のステップ内輸送(s%sed_active
  フラグ。s%gw_active と同じ通知様式)、浸食・沈降(E-D)= m_geomorph の
  calc_suspend(dt_geomorph 間隔)。状態は s%hs(浮遊砂柱状量 [m]。
  濃度 C = hs/h は導出量)。
- **移流カーネルはスカラー非依存の汎用手続き advect_scalar**
  (geomorph_plan.md §2.6。栄養塩・汚染物質輸送の将来共用を想定した
  利用者第1号)。continuous と同一のエッジ流量 mn1・通過幅係数 fw・
  平面積率逆数 winv・空隙率 gv・乾燥エッジ条件で風上輸送するため、
  「一様濃度は一様のまま」が式の形で保証される。時刻 n の h と hs が
  必要なため continuous 直後(complete 前)に置き、コミット
  (hs1→s%hs)は complete が行う(h1→h と同じ意味論)。
  開境界からの流入は清水(C=0)、流出は内部濃度で自然流出。
- **【実バグ】sx%hs1 は確保時に s%hs の複製で初期化する**(mn1 = mn と
  同じ流儀)。init 末尾の complete は移流を経ずにコミットするため、
  0 のままだと restore 済みの hs を消す(リスタート往復ビット一致で
  実検出。cold start は hs=0 なので複製で挙動不変)。
- **E-D 交換**(calc_suspend): E = w_f・C_eq(可動層 sd でクランプ)、
  D = w_f・β・C(浮遊量 hs でクランプ)。C_eq は f_esform で選択:
  1 = 超過掃流力線形(簡易式)、**2 = 板倉・岸(2026-08-07 追加。
  典拠: 実践河川水理学(iRIC)第4章 式(3)-(5)、原典: 板倉(1984)。
  K=0.008, α*=0.14, B*=0.143, η0=0.5 は原式固定で namelist にしない。
  ceq = max(q_su, 0)/w_f。Ω の Gauss 積分比は e^{−a'²}/(√π erfc(a'))、
  a' > 20 は erfc アンダーフロー域なので 0 打ち切り(その域では
  q_su < 0 が保証される)。自己整合性: τ*→0 で漸近相殺により Ω→0)**。
  w_f は susp_wf 直接指定か Rubey 式導出。
  乾燥セル(h <= dd)は浮遊分を全量河床へ繰り入れ(水のない浮遊砂を
  残さない)。z と sd の共動更新・gwflow 容量引き渡しは fluvial と同一。
- **MORFAC の台帳分離**: 水柱側(hs)は水理時間 dtw、河床側(z, sd)は
  ×morfac。morfac=1 では交換が厳密に反対称で、固体総量
  Σhs + (1−λ)Σ(z−z0) が機械精度保存(test/suspend が検定。実測 2.2e-15)。
- **ハロ**: s%hs は swflow_enc のステップ頭交換に追加(sed_active 時のみ。
  E-D による帯の更新は前ステップの geomorph なので、移流直前の交換で
  最新)。E-D はセル内交換のみでエッジ・ハロ不要。
- **save/restore**: state.dat を6成分に拡張(h, z, rsh, hg, sd, hs。
  save_version = "2026-08-07b")。
- **既知の挙動**: 強い乾燥化では h1 同様に hs1 も僅かに負になり得る
  (f_exflux_reduction=1 で緩和。handoff 項9と同種)。
- **検証(2026-08-07, gfortran/OpenMPI, -O2 厳密数学)**: 無効時
  ビット一致(wave / gwflow ケース / creep / fluvial)、-fcheck np=2
  先行、np=1,2,4 の state.dat 逐次バイト一致、固体総量保存 2.2e-15、
  共動更新恒等 1.6e-14、gwflow 併用の S_total 14桁不動、リスタート往復
  (hs 復元)の逐次・np=2 バイト一致(上記 hs1 初期化バグを捕捉)。
- **残(次段)**: 定常巻き上げ・沈降の解析解ベンチマーク、浮遊砂の
  境界流入濃度(plan §2.7 の 2)、区間流入の Qs(t)(同 3)。

### 19.5 斜面浸食(f_wash。F3。2026-08-07 実装)+ submodule 分割

### 19.6 プロセスの適用セル範囲と加速係数の共通性(2026-08-07 Q&A の記録)

- **適用セル範囲は非対称**(「河道限定」なのは wash の遮断だけ):

  | 掃流砂 f_fluvial | ○ | ○(堤防有効時は河道—非河道エッジで遮断) |
  | 浮遊砂 f_suspend(移流・E-D) | ○ | ○ |
  | 斜面浸食 f_wash | ×(スキップ) | ○ |
  | クリープ f_creep | ○ | ○(rw を見ない) |

  - 浮遊砂の全域有効は必須(越流土砂の氾濫原堆積と、斜面供給の河道への
    輸送は、非河道セル上の移流+沈降そのもの)。
  - 掃流砂の全域有効は「τ*c が実質のセレクタ」という整理(氾濫原の薄い
    流れは通常不活性。堤防有効時は境界エッジの遮断で河床材料が河道内に
    閉じる)。fn_rw 未指定なら全セル rw=0 = wash は全陸セル・遮断なし。
  - **既知の重なり**: 非河道セルでは浮遊砂の E(沖積床の平衡巻き上げ)と
    wash の kf 項(土壌の面状剥離)が概念的に重複し、両方有効だと二重
    計上の余地がある(係数校正で管理する前提)。役割分担は「E = 平衡
    巻き上げ概念が有効な沖積床 / wash = その概念が成り立たない斜面の
    剥離」。必要になったら「E-D を河道セル限定にする(斜面の供給は
    wash に一本化)」オプションを追加できる(小変更)。
- **加速係数 morfac は全プロセス共通の1個**(§19 冒頭・plan §4 の決定の
  再確認)。プロセス別に加速を変えると「地形の時間」が分裂し、斜面から
  の供給量と河道の堆積量の対応が崩れるため。適用は、掃流砂・クリープ=
  実効時間刻み dts に乗算 / 浮遊砂・wash = 河床側(z, sd)のみ ×morfac
  (水柱側は水理時間。台帳分離)。
  **プロセス別の実効加速の逃げ道**: クリープ(creep_d)と wash
  (wash_kr, wash_kf)は線形の率係数を持つため、係数の N 倍がその
  プロセスだけの morfac×N と数学的に等価。物理式で率が決まる掃流砂・
  浮遊砂にはこの自由度がなく、共通 morfac が唯一の時間軸になる
  (共通 morfac = 地形時間の定義、係数スケーリング = プロセス別の
  感度調整、という使い分け)。

## 20. 運動方程式の拡散項(f_diffusion_term。2026-08-07 実装)

平地氾濫や湾内流動で渦動粘性による運動量拡散を入れたいケースに応える
加算的オプション項。有効化は &list_enc の f_diffusion_term
(0=無効(既定)、1=定数モデル、2=ゼロ方程式モデル)。
既定は無効で、無効時は既存 reference とビット一致(検証済み)。

- **渦動粘性のモデル**:
  - モデル1(定数): ν = p_diffusion_nu [m2/s](> 0 必須)。
  - モデル2(ゼロ方程式・Elder 型): ν(i,j) = ν0 + α·u\*·h。
    u\* は Manning 則の摩擦速度 u\* = √g·n·|V|·h^(−1/6)
    (n = g%rn、|V| = s%vv)なので ν = ν0 + α·√g·n·|V|·h^(5/6)。
    α = p_diffusion_alpha(既定 0.41/6 ≈ 0.0683 = カルマン定数/6。
    対数則+放物線渦粘性分布の鉛直平均。Nays2DH 等と同流儀)。
    横断混合を強めたい場合は 0.1〜0.6 程度で校正(Fischer らの実測
    レンジ)。ν0 = p_diffusion_nu は加算のバックグラウンド粘性
    (既定 0 = 純粋なゼロ方程式。静穏域で ν が消えるのを避けたい
    湾内流動などで使う)。粗度 n=0 のケースでは α 項が恒等的に 0 に
    退化する(wave がこれ)。
- **定式化(エッジフラックス発散形の9点ラプラシアン)**: セル中心で
  `∇·(ν∇f)|(i,j) = (1/(dx·dy)) Σ_{k=1..8} l8(k)·ν_e·(f_k − f_0)/w8dr(k)`
  (ν_e = 両セルの ν の算術平均)を評価する。変係数でも保存形
  (エッジフラックスがセル対で反対称)。既存の通過幅 l8 と近傍距離
  w8dr の組は、**任意の p_diagratio・任意の dx≠dy で fxx, fyy の係数が
  厳密に 1、fxy と奇数次モーメントが 0** になる(整合な9点ラプラシアン)。
  証明はテイラー展開のペア和(f_k + f_{9-k} − 2f_0 = r_k²·∂²f/∂s_k²)に
  l8 の定義(lp + 2·ld = 1 の設計)を代入すると両係数がちょうど 1 に
  落ちる。対角2方向を等重みで足すことで fxy が相殺するため、メッシュ
  フリー法のモーメント行列(7×7)は不要(勾配が SSPH と一致する性質の
  2階微分版)。pd ∈ [0,1] で全重みが非負 = M 行列で離散最大値原理が
  成立(拡散が新たな極値を作らない)。定数 ν では ν∇²f に厳密に退化。
- **中心を通らない行・列の2回微分は使わない**: 3×3 の外側行・列の
  2回微分を等重みで混ぜる案は fxxyy(Mehrstellen)項を持ち込むだけで
  なく、軸方向近傍の重みが負になり(対角シェア 4/3 相当)単調性が
  破れるため不採用。
- **実装(m_swflow_enc_diff。移流項 adv と同型の submodule)**:
  diff_prepare がセル中心で td(1:2) = (∇·(ν∇u), ∇·(ν∇v)) を事前計算し、
  momentum のエッジでは両側セル平均を n8x/n8y で法線投影して移流項 tae に
  加算(独立フラグの重ね合わせ方式)。td はハロ行 js−1/je+1 でも再計算
  (案A)。ν 場はモデル1では init で静的に充填、モデル2では毎ステップ
  ハロ幅2(js−2..je+2)まで再計算(td が±1近傍の ν を読むため。
  rn は帯+ハロ2、h/vv は交換幅2で手元にある)。いずれも
  **ステップ頭のハロ交換リストへの追加はなし**(§11)。海域(sw>0)
  セルは ν = 0(境界エッジの ν_e が半減する=移流の taxy=0 と同格)。
- **wet/dry と再正規化**: 近傍が無効(x≦0)または移動限界未満
  (h<dd)のエッジは和から欠落させ、**勾配計算(get_diff)と違って
  残りの重みで再正規化しない**。FV 形では欠けたエッジ=拡散フラックス
  ゼロの no-flux 閉鎖であり、それが物理的に正しく保存的。乾湿遷移で
  前ステップ値が残らないよう td は毎ステップ全セルでクリアしてから
  計算する(taxy は cycle 時に旧値が残る流儀だが新規コードでは残さない)。
- **lm(付加質量)の扱い**: 拡散項は粘性力なので lm は乗じない。
  エッジの dtl = dt/lme の除算(付加質量による力の減衰)を重力項と
  同様にそのまま受ける。移流項の lm 乗算(v1 の u·lm 微分 / v2 の
  ·lm)は「輸送は力でないため減衰を相殺する」流儀であり、拡散とは
  扱いが異なる(実装コメントにも明記)。
- **安定条件**: 陽解法なので Gershgorin 上界による目安
  ν_max = 1/(dt·Σ_k l8(k)/(w8dr(k)·dx·dy))(等方格子で ~dx²/(4·dt)
  相当)を用いる。モデル1は init で検査し超過時は警告表示(停止は
  しない=発散は momentum の 250 m/s チェックが捕捉する)。モデル2は
  ν が時空間変動するため、prepare がセルごとに ν を ν_max でクランプし、
  初回発生時のみ警告を表示する(実用条件では u\* ~ 0.3 m/s・h ~ 10 m
  でも ν ~ 0.2 m2/s に対し ν_max は dx=100 m・dt=0.1 s で ~10^4 m2/s
  なのでまず発動しない)。氾濫解析の格子では通常重力波 CFL の方が厳しい。
- **検証(2026-08-07, gfortran 13.3/OpenMPI)**: -fcheck=all の np=2 を
  最適化ビルドより先に実行(規律3): chichibu 機能無効 = reference に
  完全一致 PASS、wave/chichibu モデル1・wave モデル2 = 範囲検査・FPE
  トラップともエラーなし。-Ofast 逐次: wave/chichibu 機能無効 =
  reference に ULP=0 PASS。モデル1(ν=0.1, wave)は質量 S がビット
  厳密に保存、円形初期条件の4回対称性を出力精度で厳密維持、流速・
  水深ピークの平滑化(拡散の定性挙動)を確認。保存形への統一実装後も
  モデル1は印字精度で同値。モデル2は n=0(wave 素)で厳密に不活性、
  n=0.02 で平滑化を確認。安定条件超過の警告(モデル1 init)と
  パラメータ検証の par_stop も動作確認。chichibu のモデル2
