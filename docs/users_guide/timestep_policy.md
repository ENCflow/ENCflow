# 時間刻みの設計方針 — 陽解法・固定刻み・必要な精度(時刻の管理の補足)

[時刻の管理へ戻る](time.md) | [ユーザーガイド目次へ](../users_guide.md) | [入門: クーラン数と時間刻みの決め方](courant.md)

ENCflow が地表流の時間積分をどう設計しているか — なぜ陽解法を主体とし、
なぜ基本時間刻み `dt` を固定し、可変時間刻みやサブサイクルとどう
向き合い、どこまでの精度を求めるか — を、実装に興味のある中級〜上級の
利用者と開発者向けにまとめます。クーラン数の初歩と `dt` の決め方は
[入門ページ](courant.md)に、時間積分スキームの式は
[ENC 格子と時間積分の解説](encgrid.md) §6–7 にあります。本ページは
その間を埋める「設計判断とその理由」の記録です。

<a id="design-policy"></a>

## 1. ENCflow が大切にしていること

ENCflow は、さまざまな地表面のプロセスを、同じ計算基盤の上で組み合わせ、
気軽に数値実験できることを重視しています([developer.md §0](../developer.md)
の基本方針)。そのため、すべての計算で数値解析上の精度を限界まで追求する
のではなく、**目的に必要な精度を確認したうえで、計算の速さ、設定の
分かりやすさ、新しいプロセスの追加しやすさとのバランスを取る**方針です。

これは「精度を気にしなくてよい」という意味ではありません。計算が安定して
いること、水や物質の収支に説明できない誤差がないこと、時間刻みや格子を
変えても注目する結果や結論が大きく変わらないことは、引き続き確認します。
一方、目的に対して十分な精度に達しているなら、さらに桁数を増やすため
だけに計算を重くするよりも、入力条件の不確かさ、複数のシナリオ、
プロセス間の相互作用を調べることに計算資源を使います。

**精度を捨てるのではなく、何に対する精度が必要かを先に決める。** これが、
この文書の基本的な考え方です。

<a id="explicit-method"></a>

## 2. なぜ陽解法を主体としているのか

ENCflow の地表流計算は、陽的な時間発展を基本としています。既定では
エッジごとの陽的オイラー計算を行い、流量が急変したエッジだけを多段計算で
再評価します(適応的ルンゲクッタ)。ただし摩擦項は半陰的に扱うため、
「すべての項を完全な陽解法で解く」という意味ではありません。非静水圧補正を
有効にした場合は、空間的に結合した補正量を反復計算(共役勾配法)で
求めます。[^encgrid][^nh]

開発上の主な理由は、**実装が比較的容易で、異なるプロセスの追加と
組み合わせを進めやすいこと**です。また、これまで対象としてきた地表流計算
では、開発者の経験上、陽解法で精度と計算時間のバランスを取りやすかった
ことも理由です。これは、あらゆる現象・格子・計算期間で陽解法が最速である
という主張ではありません。

陰解法を採れば、陰的に扱った項に由来する安定性制約を緩め、より大きな
時間刻みを使える場合があります。一方、空間的に結合した未知量を扱う陰的
計算では、連立方程式や反復解法、その収束判定などが必要となり、多くの
プロセスを強く連成させるほど実装・保守の負担が増えます。大きな時間刻みで
計算が安定していても、時間変化を十分に表現できるとは限りません。[^sundials]

ENCflow の立場は、陰解法を否定することではなく、通常の地表流計算には
軽い陽的計算を使い、必要性が明確な処理には、その性質に適した方法を選ぶ
というものです(摩擦の半陰形、非静水圧補正の反復解法、管路連続体層の
サブサイクルがその例です)。

<a id="fixed-time-step"></a>

## 3. 基本時間刻みは固定している

### 固定時間刻みと可変時間刻み

**現在の ENCflow は、地表流を進める基本時間刻み `dt` を計算中に
自動変更しません。** 設定した `dt` を使い、計算時刻を次のように
進めます。[^time]

```math
t_n = t_0 + n\,\Delta t
```

例えば `dt = 1`(秒)なら、基本ステップは 0、1、2、3、…秒です。

これに対し、可変時間刻みでは、計算途中の状態などを調べて、その都度、次の
時間刻みを選びます。例えば CFL 条件を使う方式では、流速や波速の増加に
合わせて刻みを小さくし、制約が緩んだときには大きくします。局所的な
時間積分誤差を推定して調整する方式もあります。CFL による制御と誤差による
制御は、同じものではありません。[^sundials][^clawpack]

**「陽解法か陰解法か」と「固定刻みか可変刻みか」は別の選択です。**
陽解法でも可変時間刻みを使えますし、陰解法でも固定時間刻みを使えます。[^sundials]

### 固定時間刻みの利点と制約

固定刻み・整数ステップに基づく時刻管理には、次の利点と制約があります。

| 観点 | 固定時間刻みで扱いやすいこと | 制約・可変時間刻みで改善できること |
|---|---|---|
| 実装とプロセス連成 | 共通の時刻列で、計算順序・更新周期・交換量を管理しやすい | 可変刻みでは、時刻同期や各プロセスの更新間隔の再設計が必要になる |
| 試行・比較・再開 | 同じ時刻列でケースを比較しやすく、再開処理の時刻管理も単純になる | 可変刻みでも適切に実装すれば再現可能。固定刻みだけで再現性が保証されるわけではない |
| 計算量の見通し | 計算期間と `dt` から基本ステップ数を事前に求められる | 適応的ルンゲクッタや内部サブサイクル等があるため、各ステップの実行時間まで一定とは限らない |
| 穏やかな期間 | 同じ設定と処理手順のまま計算できる | 許容刻みが大きくなる期間にも、小さい固定刻みを使い続けるため無駄が生じ得る |
| 急変する期間 | `Cn_max` の変化から、同じ刻みに対して制約が厳しくなる様子を追いやすい | 急な流速・水深の増加に自動で追随しない。設定した刻みが不適切になれば、見直しが必要になる |

可変時間刻みは、平常時と出水時で許容される刻みが大きく異なる計算などで、
総ステップ数を大きく減らせる可能性があります。また、自動調整によって
ユーザーが手動で刻みを調整する負担を軽くできる場合もあります。[^sundials][^clawpack]

一方、ENCflow に導入するなら、単に `dt` を計算し直すだけでなく、異なる
周期のプロセス、出力時刻(整数ステップで判定する `dt_disp`・`dt_file`・
`dt_recrd` と時間窓)、外力の更新、再開データとの整合を取る必要が
あります。ステップの棄却・やり直しを行う設計なら、各モジュールの状態と
累積収支も一緒に元へ戻す必要があります。これは実現不可能という意味では
なく、現行の固定刻み構造を変更する際の開発上の課題です。[^time][^clawpack]

固定刻みは、基本構造を単純に保ち、多くのプロセスを同じ枠組みで扱いやすく
します。一方、可変刻みによる高速化の余地は残っています。**固定刻みが
常に最速というわけではありません。**

### 適応的ルンゲクッタ・サブサイクルとの違い

ENCflow の「適応的ルンゲクッタ法」は、基本時間刻み `dt` を自動で増減する
機能ではありません。同じ基本ステップの中で、流量が急変するエッジを選んで
多段計算に切り替える機能です。画面の `Runge` 列は、その再計算率の
表示区間内最大です。[^encgrid]

また、**固定の基本刻みと、モジュール内部のサブサイクルは両立します。**
例えば、地表流を 1 秒ごとに進めながら、より細かい刻みが必要な処理だけを
0.1 秒で 10 回進める、という構成です。この数値は説明用の例であり、
全モジュールの実際の更新周期を示すものではありません。

現行 ENCflow では、例えば管路連続体層の側方通水が、必要に応じて内部
サブサイクルを行います(初期化時に「subcycles = N」と表示。上限
`gwc_nsubmax`)。ただし、すべてのモジュール・すべての交換項が自動的に
細分されるわけではありません。[^gwflow]

サブサイクルは、速い処理のために地表流も含めたすべての計算を細かく
しなくてよい、という利点があります。ただし内部計算を細かくしても、地表流
との情報交換の間隔を粗いままにすれば、連成の誤差は残ります。強い相互作用が
あるケースでは、基本刻みやモジュール間の交換間隔についても確認が必要です。

## 4. 固定刻みだからこそ Cn_max を監視する

既定の CFL 監視では、ENCflow のセルごとのクーラン数は次のように
定義されます。[^encgrid]

```math
C_n = \frac{\left(|\mathbf{V}| + \sqrt{g h}\right)\,\Delta t}{\min(\Delta x, \Delta y)}
```

ログの `Cn_max` は、セル間の最大値を、さらに前回の表示後から今回の表示
までの間で最大にした値です。開始時には初期状態の値を表示します。集計は
`src/m_state.f90` の `m_state_calcstat`(各ステップの領域最大)と
`m_state_printstate`(表示区間最大の出力とリセット)に対応します。[^state]
基本刻みが固定されていても、流速や水深が増えれば `Cn_max` は増加します。
開始時に小さかったからといって、その後も安全とは限りません。例えば、
最初は乾いている降雨流出計算では、出水・湛水が進んだ時点の状態を含めて
評価します。

既定の `f_check_cfl = 1` は、クーラン数が 1 を超えると停止する監視です。
自動的に `dt` を小さくして再計算する機能ではありません。また、1 以下で
あればあらゆる設定で安定・高精度になる、という保証でもありません。現行
ガイドは、乾湿前縁・段波・急勾配を含む計算では 0.5 以下を一つの目安と
しています。[^encgrid]

`Cn_max` は計算の健康診断に役立ちますが、単独での合格証ではありません。
`Runge`、`ex_flux`、水深・流速の分布、水や物質の収支、時間刻みを変えた
比較も合わせて確認します。`Runge` と `ex_flux` のログ値も、表示区間内の
最大です(`ex_flux` は 1 ステップあたりの検出回数の最大)。[^encgrid][^state]

固定刻みでは、`Cn_max` の上昇を、同じ刻みに対して流れの条件が厳しく
なったこととして読み取れます。可変刻みを用いる計算法でも、`Cn_max` と
実際の `dt`、流速・水深等を併記すれば同様の診断ができます。

<a id="accuracy-and-purpose"></a>

## 5. 方程式を正確に解くことと、現実を正確に再現すること

### 二つの「正確さ」は同じではない

数値シミュレーションでは、現実の現象をそのまま計算機に入れるわけでは
ありません。まず、現象を表す方程式やモデルを選び、地形・降雨・粗度などの
入力条件を与え、そのモデルを格子と時間刻みを使って数値的に解きます。

したがって、次の二つは区別する必要があります。[^verif][^valid]

| 確認すること | 具体的な問い |
|---|---|
| 方程式を十分な精度で解けているか | 時間刻みや格子による誤差は小さいか。実装に誤りはないか |
| その方程式・モデル・入力が現象を適切に表しているか | 必要な物理が含まれているか。観測・実験と、目的に応じた範囲で一致するか |

時間刻みや格子を細かくすることは、主として前者の改善です。それだけで、
省略した物理が追加されたり、入力データの誤りが直ったりするわけでは
ありません。

### wave チュートリアルの例

[wave チュートリアルの補足](../../tutorials/wave/README.md#補足-波面の振動の正体--格子の細分と物理分散)では、
静水圧の浅水方程式を細かい格子と時間刻みで解くと、数値的な振動が縮み、
その方程式が表す段波の解へ近づく様子を示しています。[^wave]

![静水圧計算の格子細分比較](../../tutorials/wave/figs/supp_grid.png)

*図1　wave チュートリアルの計算結果(再掲)。格子と時間刻みの変更によって、同じ方程式の数値解がどう変わるかを調べています。*

一方、鉛直加速度による物理分散が重要になる条件では、静水圧モデルが省略
している効果を考える必要があります。非静水圧補正を加えた計算との違いは、
単なる数値精度の違いではなく、**解いているモデルの違い**です。[^wave]

![静水圧計算と非静水圧補正を加えた計算の比較](../../tutorials/wave/figs/supp_nh.png)

*図2　wave チュートリアルの計算結果(再掲)。物理モデルの違いによって波形が変化します。非静水圧計算も近似モデルの数値解であり、この比較自体が実験・観測による検証を意味するわけではありません。*

重要なのは、数値減衰によって波面がなまった結果が、別のモデルや観測と偶然
似て見えても、それを物理的に正しく再現したとは判断しないことです。
**数値誤差を、欠けている物理の代用品にしない**という原則は変わりません。[^wave][^verif][^valid]

### 必要な精度で止める

ENCflow では、すべての計算を、可能な限り細かい格子と時間刻みで実行する
ことを標準にはしません。まず、計算によって知りたい量を明確にします。
例えば、流量ピークと到達時刻、最大浸水深、浸水範囲、土砂収支、プロセスを
追加したときの違いなどです。

次に、代表的なケースについて `dt` を半分にするなどの比較を行い、注目する
量や結論への影響を調べます。必要なら格子や連成間隔についても同様に確認
します。一度の比較で十分な収束が証明されるわけではありませんが、過大な
誤差を見逃さないための入口になります。[^verif]

その差が目的に対して十分小さいと確認できたら、それ以上の高精度化より、
入力条件の不確かさやモデルの選択、複数のシナリオを調べることを優先
できます。逆に、結論が時間刻みや格子によって変わる場合は、まだ数値精度の
確認が不足しています。入力の不確かさが大きいことだけを理由に、数値誤差を
未評価のまま放置しないでください。

許容できる差は、目的によって異なります。概要を把握する試行と、閾値付近の
浸水判定や波の位相を研究する計算とでは、必要な精度は同じではありません。
一律の「数 % ならよい」という基準にはしません。[^valid]

**計算が安定すること、方程式を十分正確に解くこと、現象を目的に応じて
再現すること。この三つを区別したうえで、必要な精度と高速性・利便性の
両立を目指します。**

<a id="practical-notes"></a>

## 6. 計算を行うときの確認

時間刻みは、対象の計算法と現象に応じた目標クーラン数から概算し、試行計算で
確かめます。乾湿前縁・段波・急勾配を含む地表流では、クーラン数 0.5 以下を
一つの目安とし、必要に応じてさらに小さくします。初期推定は安定性や精度の
保証ではありません。具体的な手順と計算例は、
[クーラン数と時間刻みの決め方](courant.md#choose-dt)を参照してください。[^encgrid]

時間刻みを小さくしても異常な水深・流速・波形が改善しないときは、境界条件、
地形、入力、物理モデル、別プロセスの安定条件も見直します。水が異常に
溜まっているケースで `dt` だけを縮めても、溜まる原因は取り除けません
([chichibu チュートリアル Step 1](../../tutorials/chichibu/README.md#窪地除去はなぜ必要か)の
「水深が増える → 波速が増す → 安定条件の破綻」の連鎖)。

厳密な継続再開 `f_state_restore = 1` では、保存時の `t0` と `dt` をそろえる
必要があります。時間刻みを変更する試行は、原則として同じ初期条件から
行います。保存状態を別の計算の初期条件として使う場合は、時刻・外力・収支の
扱いを含めて、[中断と再開](restart.md)を確認してください。[^time]
