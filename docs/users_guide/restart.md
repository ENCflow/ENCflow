# 中断と再開

[ユーザーガイド目次へ](../users_guide.md)

長時間の計算を区切って実行する、途中の状態から複数のシナリオを
分岐させる — そのための状態保存(save)と復元(restore)の機能です。
`&list_sysparam` の2つのフラグで制御します。

| パラメータ | 既定値 | 意味 |
|---|---|---|
| f_state_save | 0 | 1: 計算終了時に状態を dir_save(既定 `save/`)へ保存する |
| f_state_restore | 0 | 1: 保存状態から**再開**(時刻継続)/ 2: 保存状態を**初期条件として利用**(新しい時間軸) |
| dir_save | "save" | 保存・復元に使うディレクトリ |

保存されるのは水深・地形などの場の状態と、力学の内部状態(エッジの
流速・流量)、内部状態を持つモジュールの私有状態です。ファイルはゼロ
抑制の可逆圧縮で書かれ、広域計算でも現実的なサイズに収まります。

## 再開する(f_state_restore = 1)

中断したランの続きを実行します。**時間軸は継続**し、時刻・ステップ
番号・出力ファイルの通し番号まで中断なしランと同一になります。

使い方は「元のパラメータファイルに `f_state_restore = 1` を足すだけ」
です。計算を延長したいときは、あわせて `tt` を増やします。

```
  f_state_save = 1          ! 保存側のラン: 終了時に save/ へ保存
```
```
  f_state_restore = 1       ! 再開側のラン: save/ から継続
  tt = 172800.0             ! (延長するなら終了時刻を伸ばす)
```

- **結果は中断なしランとビット単位で一致します**(ENCflow の再開は
  「だいたい同じ」ではなく厳密に同じです)。
- 保存先=読込元なので、保存→再開→保存…の**リスタート連鎖**が
  パラメータ編集なしで回ります(1周期ずつ回す長期計算向け)。
- `t0` と `dt` は保存時と一致している必要があります(不一致は停止。
  dt を変えた再開はできません)。
- 復元時には版・格子数・実数精度が検査され、合わないファイルは
  明示エラーで停止します(別のケースの save を誤って読む事故は
  起きません)。

**再開で継続しないもの**: 最大値統計(H9999 系)と積算流量は保存
対象外で、再開ラン内でゼロから再集計されます(再開区間のみの統計に
なります)。通し統計が必要な場合は分布出力から後処理してください。

## 初期条件として利用する(f_state_restore = 2)

保存された**場だけ**を引き継ぎ、新しい時間軸(新しい `t0`・暦
`date0_c`、**dt の変更も可**)を最初のステップから開始します。
典型的な用途は**助走(ウォームアップ)**です:

1. 平水流量などで長めに流して場を安定させ、保存する
2. その場を初期条件に、複数の洪水シナリオを新しい基準日時で回す

モード 1 と違い「中断なしランとの厳密一致」の契約はありません
(初期条件の生成が目的のため)。また、潮位・境界流入・降雨などの
**時系列強制は新しい時間軸の先頭から読まれる**ので、シナリオ先頭の
強制値を保存状態と整合させるのは利用者の責務です(食い違っていると
計算初期に段差起因の擾乱が走ります)。

## 制約

- 状態保存・再開は ENC 格子の計算(既定)が対象です。比較用の旧 STG
  スキームでは再開できません(明示エラーで停止します)。
- 実行環境(スレッド数・MPI ランク数)は保存時と変えてかまいません
  (結果は変わりません — [並列実行](parallel.md))。
