# 座標系の管理

[ユーザーガイド目次へ](../users_guide.md)

## 座標系の全体像

ENCflow が計算で用いる座標系は、**m 単位の平面直交座標系**
(投影座標系のスケール)です。その上に、等間隔の計算格子が重なります。
格子はコロケート格子(量はセル中心)で、セルには **1 から始まる番号
(i, j)** が付いています。座標変換・再投影はモデル側では行いません
(GIS 側の仕事です)。

ユーザーが位置を指定したり結果を GIS に載せたりするときの座標系は
二種類です。

- **絶対座標** — 入力データが地理参照を持つ場合。投影座標系(m)
  または経緯度(度)の、地球上の実際の座標。
- **ローカル座標** — 地理参照を持たない場合。領域南西端を (0, 0) と
  する m 単位の座標。x は東向き正・y は北向き正。

どちらの場合も、**計算そのものはつねにローカルな m 格子の上で行われ、
地理参照は計算に一切影響しません**。地理参照の役割は次の3つだけです:

1. 入力ファイルからの格子諸元(nx, ny, dx, dy と原点座標)の取得
2. 計測位置(プローブ・フラックス測線)の絶対座標での指定の解釈
3. 出力への地理参照の付与(GIS でそのまま正しい位置に開ける)

地理参照を教えなくても計算はできます(理想化実験ではそれで十分です)。

### セル番号の規約 — 1 スタート

計測点・構造物・境界などの位置指定に使うセル番号 (i, j) は、
**どこでも 1 スタート**です(Fortran の配列添字の文化に従っています)。
i は西端の列が 1 で東向きに 1..nx、j は北端の行が 1 で南向きに
1..ny です(ラスタの行順=北→南と同じ向き。[入出力の章](io.md))。

**QGIS など GIS ソフトのラスタは行・列番号を 0 から数える**ので、
GIS 上でセル位置を拾って ENCflow に指定するときは**行・列とも +1**
してください。1セルずれの取り違えは、河道セル・堤防セルのように
「そのセルでなければ効かない」指定で気付きにくい誤りになります。

## 入力データと座標系

地理参照は**地盤高ファイル(fn_z)から取得**します。bil なら同じ場所の
`.hdr`(ESRI ヘッダ。GDAL / QGIS / ArcGIS の bil 出力が作るものが
そのまま使えます)が自動で読まれ、GeoTIFF なら位置情報タグが読まれます。
入力の種類ごとの扱いは次のとおりです。

| 入力データ | 座標系 | セルサイズ dx, dy |
|---|---|---|
| txt / hdr なし bil / 位置情報タグなし GeoTIFF | ローカル座標 | namelist で指定必須(dx, dy または lx, ly) |
| **投影座標系**の bil+hdr / GeoTIFF | 絶対座標(m) | 指定不要(データ内の値で補完) |
| **経緯度座標系**の bil+hdr / GeoTIFF | 絶対座標(度) | m 単位の明示指定が必須 |

- hdr / GeoTIFF から補完できる値(nx, ny, dx, dy)は namelist で
  書かなくてよくなります。**両方指定して矛盾していれば停止**します
  (どちらかを黙って優先することはしません)。
- 経緯度か投影かの判別は、GeoTIFF では CRS タグから確定的に、
  hdr(CRS 情報を持たない)ではセル寸法と原点の値域から推測します。

### 経緯度格子(度単位のデータ)を使うとき

国土数値情報などの経緯度格子もそのまま入力できますが、格子間隔の
**度→メートル換算はモデル側では行いません**。計算格子は namelist の
dx, dy(m)で定義され、経緯度情報は位置指定の解釈と出力への付与に
使われます:

- `dx, dy`(メートル)の**明示指定が必須**です(未指定は停止)。
- 指定値は度間隔からの概算値と照合され、大きく食い違う指定は停止、
  慣習的な近似(例: 実寸 100.2 m の格子に 100 m 指定)は受理して
  両方の値を表示します。
- CRS が未指定の場合は WGS84(EPSG:4326)を仮定します(表示つき。
  `epsg` の明示が優先)。

## EPSG コードの働き

`&list_geoinfo` の `epsg` は、格子の CRS を表す**ラベル(メタデータ)**
です。**計算にも座標の解釈にも使われません**。使われる場面は次の
3つだけです:

1. **GeoTIFF 出力への CRS(GeoKey)の埋め込み** — これが主目的です。
   hdr は CRS の欄自体を持たないため、bil 出力には現れません。
2. **GeoTIFF 入力の CRS との整合検査** — GeoTIFF が CRS を持つ場合、
   namelist が未指定(0)ならファイルの値を採用し、両方あれば一致を
   検査します(矛盾は停止)。
3. **経緯度格子の WGS84 仮定の上書き** — 上述のとおり。

```
&list_geoinfo
  epsg = 6677               ! 例: JGD2011 平面直角座標系 IX 系
  ...
```

地理参照のない計算(txt 入力など)で `epsg` だけを指定しても、
位置が分からないため何も起きません。経緯度か投影かの判別にも
使われません(判別は前節のとおりファイル側の情報によります)。

動作確認済みの座標系の例: EPSG:2451(JGD2000 平面直角 IX 系)、
6677(JGD2011 平面直角 IX 系)、6668(JGD2011 経緯度)、
4326(WGS84 経緯度)。

## 出力データと座標系

出力形式の選択そのもの(f_output_mode)は[入出力の章](io.md)を
参照してください。座標系との関係は:

- **地理参照を持たない場合** — txt と、ヘッダなしの bil が使えます。
  GeoTIFF 出力(`f_output_mode` のビット 4)を指定すると初期化時に
  停止します(位置情報のない GeoTIFF を作らないため)。
- **地理参照を持つ場合** — txt(座標系の情報は付きません)、
  bil(GDAL 互換の `.hdr` が併記されます)、GeoTIFF(位置情報が
  埋め込まれ、`epsg` があれば CRS も埋め込まれます)。
  QGIS / ArcGIS でそのまま正しい位置に表示されることを確認済みです。

## 計測での座標指定

計測(プローブ・フラックス測線。[計測の章](record.md))の位置は、
2通りで指定できます。

- **セル番号 (i, j)** — つねに使えます(1 スタート。上述)。
- **実座標** — **x は東向き正・y は北向き正**(投影座標系の慣例と
  同じ)で、座標の解釈は地理参照の有無で自動で切り替わります:
  - **地理参照があるとき** — **絶対座標**として解釈します。投影座標系
    なら m、経緯度格子なら度(経度, 緯度)で、QGIS 上で読んだ座標を
    そのまま書けます(ローカル座標での指定はできません)。
  - **地理参照がないとき** — **領域南西端を (0, 0) とするローカル座標
    (m)** として解釈します。

どちらで解釈されたかと解決されたセル番号は、初期化時に
`probe 1: absolute coordinates -> cell (150,150)` のように表示される
ので、必ず確認してください(取り違えはほとんどの場合、範囲外エラーで
停止します)。セル境界のちょうど上に載る座標は、丸めによって
どちら側のセルにも解決されうるので、セルの内部を指す座標を
使ってください。
