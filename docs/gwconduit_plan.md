## 1. 目的と経緯

本検討の中心の問いは

> 地表水の複合・連鎖現象において、プロセス間の双方向相互作用が予測を支配するのは
> どのような現象・規模・条件か。逆に一方向のモデル連携で十分なのはどこまでか。

である。都市水文はこの問いの「試金石」である:
都市浸水解析は、地表2次元氾濫と下水道管路1次元流を別モデルで解いて受け渡す
二重排水(dual drainage)方式が世界標準であり、「モデル分断」が制度化された分野である。

研究計画は **2階建て** とする(§8):

- **確実層**: 外部管網モデル(SWMM 等)とのオンライン結合を実装し、
  一方向結合(従来実務)との系統比較で「分断が失うもの」を定量化する。
- **挑戦層**: 下水道網を ENCflow 内の連続体層として抽象化し(本メモの主題)、
  単一時間発展での完全連成がどこまで網モデルを代替できるかを検証する。
  失敗しても「統一原理の適用限界の解明」として成果になる。

まずプロトタイプ実装+模式実験1件を先行させ、
「アイディア」を「プロトタイプ実証済み」に格上げするのが最優先タスク。

## 2. 問題の分解: なぜ下水道網はラスタ格子に乗らないか

網が ENC 格子の枠組みに乗らない理由は 3 つに分解でき、扱いが異なる。

1. **位相の非局所性**(条件付きで乗る):
   管路流は格子の隣接セルではなくグラフ上の隣ノードへ流れる。
   ただし枝管が密な市街地では、セル寸法 >> 管路間隔 となり、
   「網の排水能力の空間分布」= 連続体として均質化できる余地がある。
   均質化が成立するか否かは スケール比(セルサイズ/管路間隔) で決まる。
   → これを定量化すること自体が研究(§3 のレジームマップ)。
2. **制御構造物**(絶対に乗らない):
   ポンプ・堰・吐口・CSO は物理則でなく運転規則で動く。
   保存則+勾配駆動という記述形式の外にあり、連続体近似では原理的に扱えない。
   これらが支配する流域は最初から確実層(網結合)に譲る。
3. **圧力流(サーチャージ)**(乗る):
   満管時の圧力流は、数学的には不圧→被圧に切り替わる帯水層と同型。
   Preissmann スロットの連続体版として貯留則で表現できる(§4)。
   m_gwflow の鉛直切替アーキテクチャがそのまま使える。

## 3. 研究の枠組み: 3 段階比較

都市軸では従来の「一方向 vs 全連成」の 2 択が 3 段階になる。

| 記号 | 方式 | 実装 |
|---|---|---|
| (a) | 完全連成 | 管路連続体層(本メモ)。単一格子・単一時間発展 |
| (b) | オンライン網結合 | 外部管網モデル(SWMM 等)と時間ステップごと双方向交換。**参照解** |
| (c) | オフライン一方向結合 | 従来実務。別々に計算し結果を受け渡す |

- (b) を参照解とし、(a) がどこまで (b) を代替できるか、(c) は (b) から何を失うかを測る。
- 成果は「セルサイズ × 管網密度 × 降雨規模」平面上の **手法適用性マップ**。
  「地表水の統一記述はどこで終わり、網モデルへの分断がどこから不可避か」への定量回答。
- 予想される典型結果: 連続体近似は浸水面積・最大浸水深は再現するが、
  個別マンホールからの噴出位置は再現しない。これは失敗ではなく適用性マップの中身。
- 下水道は管網 GIS が完全に既知なので、「網の幾何が完全に分かっている系」で
  連続体近似の成立条件を厳密に検証できる。カルスト(洞窟網が未知)には無い利点。

## 4. 設計: 等価連続体管路層(人工被圧帯水層)

着想: 岩盤水理における 離散亀裂網(DFN) vs 等価多孔質媒体(EPM) の関係を、
下水道網 vs 都市セル に移植する。下水道網:都市セル ≒ 亀裂網:カルスト帯水層。

構成要素は 4 つ。**新しい離散化は一つも要らない**。

### 4.1 貯留則(被圧切替)
- セルごとに管路総体積(下水道 GIS から集計)を貯留容量 cap とする。
- 貯留量が cap を超えたら水頭が急峻に立ち上がる貯留係数に切り替える
  (Preissmann スロットの連続体版 = 人工被圧帯水層)。
- 実装上は m_gwflow_lateral の cap_const と飽和超過機構の拡張:
  現行は超過分を s%h / s%hg へ排出するが、管路層は超過分を
  「圧力水頭の急増」として層内に保持する第 3 の挙動が要る。

### 4.2 通水則(8 方向異方コンダクタンス)
- セル内・セル境界を横切る管路の方向・管径・勾配を、
  8 近傍の各方向別の等価コンダクタンスに射影する(GIS 前処理)。
- 等方的な「等価透水係数」ではなく 8 方向独立の通水能を持てるのは
  ENC 格子の構造的な強み。道路沿い直交網の方向性をラスタ連続体として最大限保持する。
- 流束則は Darcy(線形)ではなく Manning / Darcy-Weisbach 型
  (q ∝ sqrt(ΔH/dr))。乱流管路流の非線形性を連続体で表す
  (MODFLOW-CFP Mode2 の一般化。§5)。

### 4.3 地表との交換
- 雨水枡・人孔の密度をセルごとに集計し、堰式(自由流入)/オリフィス式(圧力噴出)の
  交換フラックスとする。既存の地表‐地下浸透切替と同形式。
- 噴出(管路→地表)は被圧時のみ発生。方向により式を切り替える。

### 4.4 幹線のハイブリッド扱い
- 連続体近似が壊れる幹線(1 本が支配する大口径管)は、セル列に沿った
  「埋設河道」として明示的に扱う。m_swflow_enc_channel(グリッド上の河道)の
  地下版であり、既存機構の再利用を検討する。

## 5. カルスト・岩盤水理との同型性(一般化)

農研機構レビュー(吉本ら 2019, 農研機構研究報告 農村工学部門 3, 13–27)の整理:
カルスト帯水層モデルは (i) EPM(網をセル別透水係数に潰す)、
(ii) パイプフローの水理学的記述(CAVE / MODFLOW-CFP の Darcy-Weisbach 管路網)、
(iii) ハイブリッド、の 3 系統。本設計の管路連続体層は人工管路網に対する (i)+(ii) の融合で、
特に **MODFLOW-CFP Mode2(CFPM2)** — グリッド間水頭差が閾値を超えたら
Darcy 則を Darcy-Weisbach 式に差し替える「乱流則を持つ連続体」— の一般化に当たる。

したがって同じ実装は次へ同型適用できる:
カルスト洞窟網 / 岩盤亀裂網(EPM の非線形拡張)/ 溶岩トンネル /
農地の暗渠排水網 / 森林斜面のソイルパイプ(選択流による間隙水圧上昇 → 崩壊トリガー。
将来、斜面崩壊プロセスと接続しうる)。

**一般化の実装像**: 「層ごとに流束則(Darcy / Forchheimer / Manning・D-W)を選べる連続体層」。
多孔質地下水・カルスト・下水道が同一モジュールの流束則の違いに還元される。

**検証対象の絞り込み(重要)**: カルスト・岩盤は当面の検証対象に
加えない(検証データがない)。同型適用の可能性は展望として一言
触れるに留める: 「都市下水道のために開発する非線形流束則つき
等価連続体層は、カルスト帯水層や岩盤亀裂網、農地暗渠にも同型で
適用できる」。

## 6. ENCflow 実装方針(現行コードとの対応)

参照: src/m_gwflow.f90(切替器)、src/m_gwflow_lateral.f90(層非依存カーネル)、
docs/handoff_gwflow_tani.md、docs/developer.md。

### 6.1 使えるもの
- **m_gwflow 切替器**: 鉛直=手続きポインタ束(abstract interface + nopass)、
  加算的な層追加(f_gwlayer2 の風化基岩層)の前例あり。管路層は第 3 の
  加算的レイヤとして f_gwconduit 等のフラグで有効化(無効時は資源を一切確保しない規約)。
- **lateral_core + t_latlayer**: 「どの層の水をどの係数で動かすか」を
  t_latlayer で受ける層非依存カーネル(2026-08-09 層パラメータ化済み)。
  幾何(rdr, wl)・エッジ作業領域 q(:,:,:) は層間共有(geom_init 冪等)。
  エッジ=スクラッチ(永続エッジ状態レス。§4a)、2 ループ分離(所有エッジ 4 成分
  → 発散)の構造はそのまま使える。
- **安定条件検査**: gwflow_lateral_dtcheck の枠組み(init 時静的検査 → par_stop)。

### 6.2 必要な拡張(現行 t_latlayer では足りない点)
1. **方向別・セル別コンダクタンス**: 現行 t_latlayer は層一様スカラー ksh。
   管路層はセル×8方向(所有エッジ 4 成分)の係数配列が要る。
   → t_latlayer にエッジ係数配列(allocatable)を追加するか、
   管路層専用の t_conduitlayer を切る(lateral_core の引数拡張は
   等価リファクタとして層1・層2の逐次ビット一致で検証。developer.md §16)。
2. **非線形流束則**: q_k = C_k · sqrt(|ΔH| / dr_k) · sign(ΔH) 型。
   流束則を手続きポインタ化するか、層タイプの select case で分岐。
   ビット再現性の規約(スレッド数・ランク数非依存)は維持する。
3. **被圧貯留則**: hg >= cap で貯留係数を疑似スロット値へ切替(§4.1)。
   飽和超過の第 3 の行き先(層内圧力保持)の追加。
4. **地表交換則**: 枡・人孔密度マップによる堰/オリフィス交換(§4.3)。
   既存の s%h との水頭結合(to_surface)とは別式なので独立実装。
5. **安定条件**: 非線形則の dt 上界は現行式と別導出が要る
   (sqrt 則は小 ΔH で実効拡散係数が発散するため、正則化 eps の設計と併せて検討)。

### 6.3 モジュール構成案
- src/m_gwflow_conduit.f90(名称は下水道限定にしない。第一用途が都市下水道)

  スロット幅、交換係数、eps 等)

  枡密度。GIS からの集計は utils/ 側の前処理ツール(別途。Python 可)
- 全成分デフォルト初期化(§13)、リスタート保存はモデル私有(m_gwflow_bucket の契約に倣う)

## 10. 統合設計の検討: 岩盤水理と下水道網を単一モデルにするか(2026-08-18)

> 直交スイッチ)で実装済み。決定事項・定式化・検証記録の正本は
> **developer.md §46**。実装時の設計変更は 1 点のみ — カーネルは
> t_latlayer の拡張ではなく専用 conduit_core を m_gwflow_lateral 内に併設
> (幾何・エッジ規約は共有。相違が多く単一カーネルでは全行が分岐する
> ため。lateral_core 不変 = 層1・層2 のビット一致が構造的に保証される)。
> 実装順序 §10.5 の段 1〜5 が完了(段 2 の閾値切替則 f_gwc_fluxlaw=3 は
> 未実装で将来追加)。残: 段 6(幹線ハイブリッド・GIS 前処理・実都市)と
> test/conduit の reference 承認(人間の目視確認)。

§5 の同型性を「展望の一文」に留めず、岩盤水理(亀裂岩盤・カルスト)と
下水道網の**両方を実装対象**とする場合の設計検討。論点は
「単一の被圧地下水モデルに統合するか、岩盤用と下水道用でインターフェースを
分けるか」。結論を先に書く: **単一モジュール(交換項は直交スイッチ)を推奨**。

### 10.1 相互作用の再整理 — 二分法は構造ではなく典型設定

出発点の整理(チャット検討時の観察):

| | 地下水層(層1・層2)との相互作用 | 地表水との相互作用 |
|---|---|---|
| 岩盤水理 | **あり**(層2 との漏水・涵養) | 表土があれば**なし** |
| 下水道網 | なし | **あり**(枡・人孔) |

しかしこの二分法には、それぞれ重要な反例がある。

- **カルストの地表交換**: ドリーネ・吸込穴(ponor)からの直接流入と
  湧泉からの流出は、まさに下水道の雨水枡・吐口と同型の
  「点的交換口の密度場」である。露岩域(表土なし)では面的な交換もある。
  カルスト水文の集中定数モデルが「速い涵養(点)と遅い涵養(面)」を
  分けるのはこのため。
- **下水道の地下水交換**: 浸入水(infiltration/inflow。老朽管への地下水浸入)は
  実都市で無視できない(晴天時流量のかなりの割合が不明水という系も普通)。
  逆方向の漏水(管から地盤へ)も同じ項の符号違い。§9 の未決事項
  「漏水・浸入水を初期実装に含めるか」は、岩盤の層間交換と**同じ項**である。

つまり「地表交換の有無」「地下水交換の有無」は用途で決まる構造的二値ではなく、
**係数場(枡・穴密度、漏水係数)がゼロか非ゼロか**という設定の連続量である。
実在系は中間(漏る下水道、吸込穴のあるカルスト)を埋めている。

用途間で**真に構造的に異なるのは 1 点だけ**:

- **鉛直スタック内の位置**(水頭底の基準と、交換相手がどの層か)。
  下水道 = 地表直下(埋設深 2〜5 m、層1 より浅いか同深度)、
  岩盤 = 層2(風化基岩)の下。
  これも「水頭底の与え方(dbot)+交換相手の選択子」のパラメータに還元できる。

流束則の違い(下水道 = 乱流 sqrt 則、岩盤 = Darcy↔D-W 閾値切替 = CFPM2)は
§5 の時点で既に「選択制の流束則」として一般化する方針であり、論点ではない。

### 10.2 比較: 案A(単一モジュール) vs 案B(用途別 2 モジュール)

**案A: 単一モジュール m_gwflow_conduit(交換項は直交スイッチ)**
第 3 の加算的レイヤ f_gwconduit を 1 つ設け、
(i) 地表交換 = 枡・穴密度格子 fn_gwc_inlet の指定有無、
(ii) 層間交換 = 選択子 gwc_leak_layer(0:なし/1:層1/2:層2)+係数、
(iii) 流束則 = f_gwc_fluxlaw(1:Darcy / 2:sqrt 乱流 / 3:閾値切替)
の独立な組み合わせで構成する。「下水道」「岩盤」はコード分岐ではなく
namelist のプリセット(§10.3)。

**案B: 用途別 2 モジュール(例: m_gwflow_sewer / m_gwflow_rock)+共通カーネル**
m_gwflow_lateral(層1)と m_gwflow_layer2 が lateral_core を共有する現行方式の
水平展開。各モジュールは自分に要る交換項だけを実装する。

| 観点 | 案A: 単一 | 案B: 分離 |
|---|---|---|
| 物理の表現力 | 交換項の直交性が実在系(漏る下水道・穴のあるカルスト)に合う | 典型で固定。中間例が出るたび他方の項を移植 → 実装が収斂進化して重複 |
| コード量 | 交換項(堰/オリフィス・漏水)・貯留則・保存が 1 系統 | 同上が 2 系統に複製されうる(カーネルだけ共有では足りない) |
| 検証コスト | 模式実験スイート 1 系統+スイッチ組合せ | 2 系統(それぞれ無効時ビット一致・np 一致・リスタート) |
| 同時使用 | 単一インスタンス規約(developer.md §12)の下では下水道と岩盤を同一ランで併用不可 | 各 1 インスタンスで自然に併用可 |
| namelist | 1 グループ。用途に無関係な項は既定値で不可視 | 各グループが最小 |
| save/restore | 私有ファイル 1 本 | 2 本 |
| 研究の主張との整合 | 「同一モジュールの流束則の違いに還元」(§5)の主張そのもの | 主張を自ら弱める |
| 方針 §0 との整合 | 「過度に複雑化せず徐々に精緻化」= 1 実装を段階的に精緻化 | モジュール数が先行して増える |

案B の唯一の実質的優位は**同時使用**(都市×カルストが同一領域に共存する場合)
だが、これは当面のスコープ外で、現実の適用例も稀(必要になるのは
石灰岩地帯の都市の内水氾濫など)。かつ後述のとおり案A からの昇格経路がある。

### 10.3 推奨: 案A(単一モジュール)+将来の多重インスタンス昇格経路

**推奨は案A**。理由の核心は §10.1 の観察 — 相違点とされた相互作用の有無は
係数の値の問題であって構造の問題ではなく、構造的な相違(鉛直位置)も
パラメータに還元できる — にある。用途でインターフェースを分けると、
この誤った二分法をモジュール境界として固定してしまい、
浸入水(下水道側)や吸込穴(カルスト側)を足すたびに境界を壊すことになる。

単一インスタンス制約への手当て: モジュール私有状態は現行の慣習どおり
派生型 1 個(例: t_gwcond)に集約しておく(glt / gl2 と同形)。
将来、同時使用が実際に必要になった時点で、この派生型を配列化し
&list_gwflow_conduit を複数グループ化する**多重インスタンス昇格**を行う。
状態が最初から派生型に閉じていれば、昇格は等価リファクタ
(1 インスタンス時のビット一致)として検証できる。いま作り込まない
(死んだ柔軟性を持たない。§16.1 の「側方ポインタ束を作らない」判断と同型)。

用途プリセット(namelist 設定例。コードに用途分岐なし):

| 設定 | 下水道網 | 岩盤・カルスト | 農地暗渠(将来) |
|---|---|---|---|
| f_gwc_fluxlaw | 2(sqrt 乱流) | 3(Darcy↔D-W 閾値切替) | 1〜2 |
| fn_gwc_inlet(枡・穴密度) | 指定(雨水枡・人孔) | 通常 ""(ドリーネがあれば指定) | "" |
| gwc_leak_layer | 0(将来 1 で浸入水・漏水) | 2(層2 と交換) | 1(土層と交換) |
| 水頭底 | 地表 − 埋設深 | 層2 底 − 岩層厚 | 地表 − 暗渠深 |
| 貯留容量 cap | 管路総体積(GIS 集計) | 亀裂空隙率×層厚 | 管体積 |

### 10.4 モジュール構成(案A の具体化)

現行アーキテクチャへの素直な埋め込み。**新しい構造は何も導入しない**
(加算的レイヤ+層非依存カーネル+契約 5 箇条、すべて前例どおり)。

1. **状態**: `s%hgc`(柱状換算水量 m。確保・更新・保存は m_gwflow_conduit。
   s%hg2 と同じ所有規約)。被圧は独立変数を増やさず、水頭関数の折れ線で表現:

   ```
   H(hgc) = zbot + hgc/sy_c                          (hgc <= cap: 不圧)
   H(hgc) = zbot + cap/sy_c + (hgc − cap)/sy_slot    (hgc >  cap: 被圧)
   ```

   sy_slot << sy_c が疑似スロット(Preissmann スロット連続体版)。
   §6.2-3 の「飽和超過の第 3 の行き先」は、超過分を排出せず hgc に
   持たせたまま水頭だけ立ち上げる、というこの折れ線で実現される
   (lateral_core の cap クランプ+引き渡しを「水頭関数の切替」で置き換える)。

2. **側方カーネル拡張**(m_gwflow_lateral。§6.2-1, 2 の具体化):
   - t_latlayer に allocatable のエッジ係数配列(所有 4 成分。q と同形状
     `(1:4, 0:nx, jsh-1:jeh)`)と流束則選択子・水頭関数パラメータを追加。
     未確保・既定値なら現行コードパスと厳密同一(層1・層2 の逐次
     ビット一致で等価リファクタ検証)。
   - sqrt 則の正則化: |ΔH| < eps_h で q = C·ΔH/√(dr·eps_h) に線形化
     (ΔH→0 の実効拡散係数の発散を抑え、陽解法の dt 上界が
     線形化枝の係数で静的に閉じる)。gwflow_lateral_dtcheck を
     「係数場の max(allreduce_max = 決定的)×線形化枝」で拡張。

3. **交換項**(m_gwflow_conduit 内。lateral とは独立の毎ステップ処理。
   gwflow_layer2_calc の鉛直浸透(1)と同型の反対称適用):
   - 地表交換(fn_gwc_inlet 指定時): 密度場 × 堰式(地表→管路の自由流入)/
     オリフィス式(被圧時の管路→地表噴出)。向きは水頭比較で切替。
     s%h を触るループで s%e = s%z + s%h を回復(契約 2)。
   - 層間交換(gwc_leak_layer > 0 時): 相手層(s%hg / s%hg2)との
     水頭差駆動の双方向漏水。初期実装は定数係数×容量制限の単純形から
     (layer2 の kv 項と同型)。

4. **切替器への組み込み**(m_gwflow):
   - &list_gwflow に f_gwconduit(0/1)を追加。無効時は s%hgc もエッジ係数
     配列も確保せず、呼び出し・ハロ交換もしない(メモリ・CPU ゼロ追加)。
   - calc 順序は 鉛直 → 層1側方 → 層2 → **管路層**(上から下へ。
     実行順序=結合仕様の慣習に従い、地表交換 → 側方 → 層間の順を
     モジュール内で固定)。
   - 層1・層2 が無効でも管路層単独で有効化できること(都市域は不浸透で
     f_gwvertical=0 のまま下水道層だけ使う構成が主用途)。
     needs_sd は管路層単独では要求しない(水頭底は fn/一様深で与える)。
     gwc_leak_layer=2 は f_gwlayer2=1 を要求(init で検証)。
   - S 台帳・画面ログへ hgc を算入(hg2 と同じ「有効時のみ列拡張」)。
   - save は私有 gwflow_conduit.dat(RLE。契約 5)。state.dat 不変。

5. **namelist スケッチ**(&list_gwflow_conduit。list_* は読むだけ、
   解釈・検証は init の規約どおり):

   ```
   f_gwc_fluxlaw   ! 1:Darcy 2:sqrt(Manning/D-W) 3:閾値切替(CFPM2)
   fn_gwc_cond     ! 8方向コンダクタンス格子(所有4成分。GeoTIFF)
   fn_gwc_cap      ! 貯留容量 cap 格子 (m)(一様なら gwc_cap)
   fn_gwc_bot      ! 水頭底標高格子(一様深なら gwc_depth: z − depth)
   gwc_sy          ! 不圧貯留係数
   gwc_slot_sy     ! 疑似スロット貯留係数(<< gwc_sy)
   fn_gwc_inlet    ! 枡・吸込穴密度格子("" = 地表交換なし)
   gwc_cw, gwc_co  ! 堰係数・オリフィス係数
   gwc_leak_layer  ! 層間交換の相手(0:なし, 1:層1, 2:層2)
   gwc_leak_mmh    ! 漏水係数(mm/h)
   gwc_eps, gwc_eps_h  ! 乾燥判定厚・sqrt 則線形化幅
   ```

### 10.6 検証対象の絞り込み(§5・§8 の再確認)

統合設計を採っても、**当面の検証対象は都市下水道のみ**という §5 の結論は
変えない(検証データの理由はそのまま)。変わるのは同型適用の記述の強度
だけ: 「同型で適用できる(見込み)」→「同一モジュールの設定違いで
動く(プロトタイプ確認済み)」。岩盤水理の本格検証(実カルスト流域等)は
別課題の種として温存する。
