00a. **examples/levee_breach(解像堤防の破堤。2026-10-13 新設)で見つかった要確認事項**
   - f_bank_datum の既定がコード(0 = 河床基準)と文書(1)で食い違って
     いた → **コードの既定を 1 に統一(2026-10-13。developer.md §17)**。
   - **運動量保存形の移流(f_advection_scheme = 2, 3)が、区間流入で
     駆動した直線河道(幅 5 セル = 50 m・深さ 4.7 m・両岸が 6〜7 m の
     乾いた壁セル)で 5 分周期・±6 % の流量振動を自励する**。調査結果
     (2026-10-13。再現は examples/levee_breach の param.txt でスキームを
     3 に戻す。破堤なし 90 分の変種は work/ に置いた):
     - 定常スタート(流量・水位一定)からも 50 分頃に成長し(e-folding
       ≈ 7 分)、±6 % で飽和する限界周期。周期 ≈ 5 分は河道長 800 m の
       長波の往復時間。振幅分布は流入端が腹(水位 ±0.34 m)、j ≈ 20 に節、
       水位規定端が節の定在波。
     - 必要条件: 保存形移流(2 でも 3 でも同じ振幅)、**区間流入境界**
       (同じセルに同じ流量を内部ソース &list_bound_source で入れると
       消える)、弱い摩擦(河道粗度 0.05 では消える)。dt(0.5/0.25)、
       流入配分(0/2)、下流端(水位規定/自由流出)、f_exflux_reduction には
       依存しない。スキーム 1 では出ない。
     - **直接の症状は横断方向の 2Δx(市松)モード**: スキーム 3 の 80 分の
       流量場は河道 5 列で [16.1, 9.6, 18.5, 9.6, 16.1] m²/s(j = 2)、
       [15.4, 10.7, 17.2, 10.7, 15.4](j = 10)と列ごとに交互になり、
       スキーム 1 では [14.4, 13.9, 13.6, 13.9, 14.4] と滑らか。保存形の
       側方面は「平行エッジの実流量の c 側・n 側の平均」と「流入側のみ
       隣接エッジの流速、壁・乾床側は u_e」で評価するため、列ごとに交互
       する横断モードに対する運動量交換(減衰)がほぼゼロになり、区間流入
       境界(面ごとの uv 規定)が種を与えると減衰せずに縦断の定在波と
       結合して成長する、というのが現時点の見立て。
     - 河道だけの領域(5 列、壁 = 領域外縁)ではスキーム 2 は安定、
       スキーム 3 だけが流入端の水深低下(2.3 m、Fr > 1)と跳水の振動で
       発散に近い振幅(Q std 210 m³/s)になり、下流端を自由流出にすると
       消える。こちらは MUSCL の面値再構成が流入境界近傍で反拡散に
       働く §69.9 と同系統の可能性。
     - 対策の候補(設計議論が先): (a) 側方面の運動量交換を交互モードにも
       効く形(両側の隣接エッジ流速の平均など)にする、(b) 区間流入面に
       横断方向の平滑化を入れる、(c) 保存形スキームに弱い横断拡散を
       入れる。いずれも test/dambreak・bendloss・chichibu の再検証が要る。
     → **(a) を実装(2026-10-17 副格子結合 §68.36、10-18 片側面の壁面扱い
       §68.37)。levee_breach の param.txt をスキーム 3 にして再計算すると、
       測線 2・3 の 11 分移動平均からの残差はスキーム 1 と同じ 2〜3 %
       (ハイドログラフの形状分)で、5 分周期・±6 % の自励振動は消えた
       (2026-10-18 確認)。**
     → **2026-10-24 完了**: 現行コードで param.txt / param_vwall.txt をスキーム 3 で
       再計算し、破堤完了後 92〜120 分の河道流量(j = 30)の標準偏差 0.6 m³/s
       (スキーム 1 は 0.9)、横断分布は 5 列とも hV = 14.0 m²/s で一様、5 分周期の
       振動なしを確認。両 param から `f_advection_scheme = 1` を外して既定に戻し、
       README の「注意」を書き換え、図・数表・破堤幅表(12 計算)を再生成した
       (users_guide の channel / channel_models / bedmotion の引用数値も日英とも
       追随)。幅表で動いたのは仮想壁面 f_br_diag = 1 の解像比(幅 1・2・3・5 で
       1.51/1.10/0.95/0.85 → 1.66/1.17/1.03/0.98。仮想壁面の河道は破堤口前の水位が
       スキームで 0.1 m 程度動く)。解像堤防・f_br_diag = 0 は 2 % 以内で不変。
     - **河道だけの領域(5 列、壁 = 領域外縁)でスキーム 2・3 が振動する件 →
       2026-10-24 に再現・切り分けし、修正(developer.md §68.40)**: 河道だけの
       領域では流入区間の両端セルが角セルの閉鎖規則(受け口係数 0。§69.9)で閉じ、
       中央 3 列に集中した流入が境界行の移流項と結合する横断モード(奇数幅 3・5・7
       で発生、スキーム 2 でも同じ、スキーム 1 は無振動)。区間流入の法線面を持つ
       外縁セルに接するエッジの移流項を 0 にする(海セル §68.35 と同じ扱い)と
       幅 3・5・7 とも 0.00 % になり、levee_breach 本体は 0.04 m³/s 以内で不変。
       検証・回帰の記録は §68.40。
   - 仮想壁面の破堤(&list_channel_breach)は、サイトにした法線エッジ 1 本
     ずつが本間公式で通水し、堤内地セルの斜めリンクは壁のまま残るため、
     同じ堤底でも解像堤防の破堤より流量が小さい。幅 1・2・3・5 セル(サイト)
     の計測(越流水深 1.7〜1.9 m)で、解像堤防の実効幅 ≈ セル数 × dx、
     仮想壁面 ≈ サイト数 × 0.38 dx(法線シェア 0.414 に一致)、比 2.3〜2.6。
     斜めの隣接対をサイトに加えた計測(README の表): 破堤行内部の斜め
     だけでは解像比 0.72 で頭打ち、両端の外側の斜めまで全部開くと
     n = 1, 2, 3, 5 で解像比 1.51, 1.10, 0.95, 0.85(幅 2〜3 セルで最も
     近く、広いほど堰公式が堤内地側の水位上昇で下回る)。
     追加計測(2026-10-13): (i) 両端の斜めを半分だけ下げる(残存割合 0.5)
     は内部の斜めのみとほぼ同じ(解像比 0.50, 0.72, 0.73, 0.72。半分の
     天端は河川水位より上でほとんど越流しない)。(ii) 実効天端が両側地盤
     以下まで下がったエッジの壁を解除して通常の浅水計算に戻す試作
     (bank_wall で差し替え後に is_wall を再判定。実行時コストはゼロ)は、
     法線のみで解像比 1.99, 1.50, 1.30, 1.14、全斜めで 3.00, 1.96, 1.60,
     1.31 と過大。河床 −3.5 m → 堤内地 −0.5 m の段差エッジを浅水方程式で
     解くと限界流の制御がなく噴流(u ≈ 11 m/s、Fr ≈ 2.7)になるため。
     広頂堰の目安 1.7·B·H^1.5(B = セル数 × dx、H = 河川水位 − 堤底)は
     解像堤防の値(n = 1 で 39 vs 40、n = 5 で 169 vs 154 m³/s)に合う
     ので、堰公式を残したまま斜めを開く方向が妥当。試作は破棄した。
     → **f_br_diag として実装済み(2026-10-13。developer.md §18)**。既定 0 は
     従来とビット一致、1 で法線サイトに触れる斜め(両端の外側を含む)も
     同じ実効天端。examples/levee_breach の比較ケースと文書は 1 に更新。
