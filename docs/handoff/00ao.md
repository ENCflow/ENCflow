   毎 push の ci.yml の逐次のジョブが 30 分の制限で打ち切られていたので、実行時間の長い検定型の 5 ケース(tjunction・
   stairbank・vchannel・bldgdrag・driftwood)を夜間の nightly.yml の verify-serial・verify-mpi へ移した(利用者の決定)。

   (1) **ランナーでの初回の確認**: main に入った後の最初の CI で、逐次・MPI のジョブが合格し、回帰の時間が見込み
       (普通のランナーで逐次 約 13 分、遅いランナーで MPI 約 18 分)に収まることを確かめる。wallpond を含む逐次のジョブが
       最後まで通るのは、これが初めてになる。最初の Nightly で verify-serial・verify-mpi が合格することも確かめる。
   (2) **MPI で回す検定を足すか**(**利用者の判断待ち**): 時間の都合で逐次だけで回していた検定の np = 2 を足すかを
       決める。候補は、wallpond を毎 push の MPI のジョブへ(手元の np = 2・4 は合格。湛水の 7 ケースは 1 ランクと
       バイト一致)、vchannel を夜間の verify-mpi へ(手元の np = 2 は合格。handoff 00ah (6))。毎 push の MPI のジョブには、

       制限を延ばすか、ジョブを分けるかを一緒に決める。

       Python のスクリプトの import を調べるかを決める。
