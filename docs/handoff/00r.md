00r. **貯留関数法の区画流出 fn_sfm(2026-11-11。developer.md §106)の残り**
   - **reference の確定(済 2026-11-12)**: test/sfzone の reference(Log.txt・sfm_zone.csv)は利用者の指示で
     確定した(ファイルは作成時のまま。確定時の main の出力とバイト一致。developer.md §106.4)。
   - **遅れ時間 T_L(2026-11-11 実装。§106.6)**: `sfm_tl_h`(時間)。雨を T_L 遅らせてタンクに入れる形、
     dt の倍数に丸め、開始時は q0 の定常。test/sfzone の reference(T_L = 0 の構成)は変わらない。
     遅れのある計算(param_lag.txt)は Check_sfzone.py の検定だけで、reference には入れていない。
   - **蒸発散(2026-11-11 実装。§106.7)**: fn_evap と併用すると、区画セルに残った要求をその時刻の
     タンクから引く(任意の線形低減 `sfm_elim_mm`)。遅れ時間の間の雨からは引かない。
   - **有効雨量の分離(2026-11-11。§106.8)**: タンクに持たせず降雨遮断で与える(利用者の決定)。初期損失
     モデルに 2 段の遮断率 `ic_alpha_fill`・`ic_alpha_full` を足し、木村の f1・R_sa と「初期損失の後に固定
     遮断率」を表せるようにした。容量は蒸発散でしか回復しない(出水ごとに R_sa を数え直す形ではない)。
   - **拡張(合意済みの範囲外。§106.1)**: 2 価の貯留関数(Prasad 型・星・山岡型)。入れるときは方式
     (t_swflow 型の手続きポインタか独立フラグか)を先に決める。
   - **出典**: 木村(1961)の原典と、P = 0.6 が標準とされる根拠の文献は作業環境の通信の制限で未照合
     (書誌はウェブ検索の結果による。users guide の脚注に明記)。照合できたら脚注と §106.3 を更新する。
   - **例題**: VZ 流出と同じ雨で比べる試算を、examples/source_area の追補「貯留関数法との関係」に
     置いた(2026-11-11。模式の雨で、VZ 流出の土壌柱の逓減の貯留と排水の関係に合わせたタンクを柱の
     排水に重ねる。上の 00q)。観測のある事例で確かめる例題(谷の一連の研究が論じる、貯留関数と
     鉛直浸透の関係)はまだない。examples/vz_tani2023 の事例に区画を並べる形が候補。
   - **共通基盤 m_zonerunoff**: VZ の初期化の全域一時(下の 00h)は区画番号マップの読み込みも含めて
     共通基盤に移った。貯留関数は土層厚を読まないので、区画番号マップの全域一時だけを持つ。
