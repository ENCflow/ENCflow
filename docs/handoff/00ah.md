00ah. **例題 examples/snow_avalanche(2026-11-25 作成。沢を下る流れ型雪崩の走路の雪の連行と誘導堤)の残り**
   (作成と検討の経過は developer.md §126。ここには決まっていないこと・確かめていないことだけを書く)
   - **利用者の判断待ち**: (1) 利用者ガイドの雪崩の項(geomorph_applications.md §5)に、キャリアを雪と一緒に
     授受する組み方(`f_dbwet = 1`・`db_satbed = db_relsat`・`dd` を 0.1 mm)を「走路が長い計算・連行で大きく
     育つ計算」の段落として書き足した。従来の「設定の型」(`db_relsat` 小・`f_dbwet` なし)は残してある。
     型そのものを新しい組み方に替えるか、test/avalanche の構成を替える(または構成を足す)かは決めていない
     (test/avalanche は走路 30 m の検定で、従来の型のまま全量が止まる)。(2) 例題の名前・ケースの組み・
     摩擦係数の選び方(RAMMS の表の 1 行を領域の全体に使う)は作業側の判断。
   - **連行則の改良**(§126.4・§126.5・§126.12。2026-11-25 に試作で比べた。実装は設計の合意のあと): 速度比例連行
     f_dbed = 4 は、連行できる層を全面に置くと取り込む量が限界水深で決まり、取り込んだ質量の運動量を数えない。
     作業用の試作では、Hungr の則 E = E_r h|V|(massflow.md §3 の「今後の課題」)と、流動深の閾値が、限界水深への
     依存を消す(成長率 2.4〜2.55 で一定)。運動量を数える項(半陰の抵抗に ṁ/m を足す)は、一様な斜面の常微分方程式の
     解と 0.4 % で合うが、それだけでは縁の広がりは止まらない。入れる形(Hungr の則を f_dbed の値に足す・運動量の
     スイッチ・閾値を持つか)、既定、例題の基本ケースをどれにするかは未決。検定は、§126.5 の一様な斜面の試験
     (運動量)、一様な流れの体積が exp(E_r x) で増えること(Hungr)、例題の `allsnow` の限界水深への依存(検出器)。
     広がりの種が斜めのエッジの数値拡散かどうか(4 近傍との比較)は確かめていない。
   - **乾燥セルの規則と限界水深**(§126.3): 地表水 h が `dd` を切ったセルの hs を全量固定する規則が、雪崩の
     ようにキャリアの割合が小さい流れでは、流れの縁・先頭の止まり方と時間刻みへの依存を決める。例題は
     `dd` を下げて避けた。規則を流動深 h + hs で判定する形に変えるか(挙動の変更。土石流の既存の結果が
     変わりうる)は未検討。
   - **沢の向きへの依存**(§126.7・§126.11。2026-11-25 に調べた。対策は未決): 45° と 0° の差は流れの頭の形に出て
     (0°・22.5° は厚く短い頭、45° は薄く長い頭)、格子を 1.25 m まで細かくしても縮まらない(30 秒の先頭が 0° で
     872 → 831 → 798 m、45° で 935 → 972 → 1011 m)。連行・雪の帯・先頭の辺の扱いは原因でなく、運動量の移流項の
     横断方向の輸送(側方面は 1 次風上。数値拡散が向きで 2 倍違う)と、Voellmy 則が横断方向の応力を持たないことで
     決まっている(物理の粘性 50 m²/s を足すと向きの差が消える)。細かい格子で 0° が遅くなる理由は分かっていない。
     対策の候補: (a) 土砂流動に横断方向の応力(面内のせん断)を入れる、(b) 移流項の側方面の高次化(簡単な試作は
     効かなかった)、(c) 対策を入れずに幅を明記する。例題の README は「仕組みは未調査」のままなので、決まったら
     書き直す(頭の形・最大流動深・到達時刻は向きで変わり、胴体と堆積の先端は変わらない)。
   - **誘導堤**(§126.6): 堤ののり尻の脇で最大流速が堤のない場合より大きく出る仕組み、斜めの衝撃波の理想化した
     検定(一様な射流と斜めの壁。浅水流の射流の流入境界がないので、組み方から)、堤の高さ・向きの系統的な
     計算はしていない。
