00al. **移流項の側方面の扱いが河道の堤防の仮想壁面(fn_bank)を見ない: 壁の向こうの堤内地が水につかると河道が減速する(2026-11-26 発見。developer.md §131.12)** — 例題 confluence_backwater の粗い格子で、越水の時期に合流点の本川の水位が細かい格子より 0.2 m 高く、堤内地の水量が 1.4〜1.6 倍になる原因を調べて見つけた。2026-11-26 に、作業用の版(src は変えていない)で設計の下準備をした。**設計の合意待ち**(下の「決まっていないこと」)。
   - **仕組み**: m_swflow_enc_adv が隣のセルの状態を読む判定(cell_ok・wet_weight)は、有効なセルか・海でないか・水深が
     dd 以上かだけを見て、仮想壁面を見ない。堤内地が乾いていれば壁と同じに働くが、濡れると、壁の向こうの淀んだ水と、
     流速 0 の壁のエッジが、河道の辺の流向面の風上の供給元・側方面の平行リンク・斜めエッジの開口率に入って河道を減速する。
     逆向きに、堤防沿いの堤内地の辺が、壁の向こうの河道の速い流れを平行リンクに使うこともある。利用者ガイドの移流項の
     スキーム §4.4 の「壁・乾床は運動量を供給しない」が、仮想壁面では成り立っていない。test/wetbank(§110.25)の濡れた岸に
     よる減速の、仮想壁面の版。00w(濡れた谷壁の辺の減速)とは別の件。
   - **検定の形(作業用)**: 直線の河道(勾配 1/1000、粗度 0.03、1,000 m³/s、長さ 4 km、川幅 200 m で等流水深 2.55 m)の
     両側に幅 300 m の水平な堤内地。堤内地を「計算しない(マスクの外)・仮想壁面 + 乾いた堤内地・仮想壁面 + 湛水 1.5 m・
     解像した堤防(1 セル)+ 湛水」の 4 通り、格子を「Δx = 100 m・河道 2 セル(解像)・Δx = 20 m・10 セル・Δx = 100 m・
     1 セルのサブグリッド河道(W = 80 m)」の 3 通り。3 時間で定常。区間の中ほど(40〜60 %)の水深と水面勾配から、
     マニングの式で通水の幅を逆算して川幅と比べる。
   - **わかったこと**:
     - 修正前は、仮想壁面 + 湛水だけが通水の幅 ÷ 川幅 = 0.919(Δx = 100 m)・0.936(20 m)で、河道の水位が最大
       0.19 m・0.13 m 高い。ほかの 10 ケースは 1.000。直線の 1 セルのサブグリッド河道は湛水でも 1.000(影響しない)。
     - 案 A2(下記)で 0.919 → 1.000、0.936 → 1.000。湛水のケースの河道の水位は、乾いた堤内地・解像した堤防のケースと
       出力の桁(0.1 mm)まで一致する。仮想壁面を使わない・乾いた堤内地の 10 ケースは修正前とビット一致。
     - 案 A(MUSCL の 2 つ先のセルの判定 far_ok にも壁を見せる)は、乾いた堤内地の計算まで変わる(far_ok は水深を見ない
       静的な判定で、乾いたセルも数えるため。Δx = 20 m で 0.1 mm の桁が 10〜72 セル)。§131.12 の部分修正(lateral_u_j と
       open_rep だけ。案 B)は 0.942・0.955 で足りない。
     - 破堤(例題 levee_breach の補足の仮想壁面のケース。f_br_diag = 1)では、破堤サイトを元の天端で壁と数え続ける
       案 A2 は、破堤口の最大流量 137 → 125 m³/s・氾濫量 38.1 → 34.0 万 m³ と、解像した堤防(138・36.2)から離れる。
       破堤サイトを実効天端(breach_crest)で判定する案 A2b は 134 m³/s・36.5 万 m³(浸水面積 68.6 → 69.2 ha、解像 69.4。
       最大浸水深 0.95 → 0.91 m、解像 1.13。最大流量の時刻 109 → 120 分、解像 120)。破堤のない計算では A2b と A2 は
       ビット一致。
   - **案 A2b(推奨。合意待ち)**: 規則「仮想壁面のエッジ(bank_edge = bank_wall の対象判定と同じ。破堤サイトは実効天端で
     判定)を挟む 2 つのセルは、移流項の中で互いを運動量の供給元・平行リンク・開口に数えない(乾いたセルと同じ扱い)。
     水位によらない(越流中も数えない)」。壁のエッジの流量は堰の式で決まり運動量の式を通らない。解像した堤防なら天端の
     セルの薄い越流水で、側方面の代表性 R' でほとんど数えられない。
     - 入れる所(m_swflow_enc_adv): 流向面の風上の供給元(adv_prepare_mc・neumann_cell_faces の各 2 か所)、側方面の
       平行リンク(lateral_u・lateral_u_w・lateral_u_j・lateral_u8)、斜めエッジの開口率(axis_open の 3 つの分岐・open_rep・
       axis_open8)、屈曲の規則の供給元(bend_face の 2 か所)。判定は 1 つの関数(have_bank が偽ならすぐ偽)。bank_edge を
       pure にして共用し、破堤の実効天端は移流の側だけで重ねる(bank_edge を使う適応的ルンゲクッタと非静水圧の判定は、
       破堤サイトも bank_wall が上書きするエッジなので、元の天端のままでよい)。
     - 入れない所: MUSCL の遠いセル(far_ok。解像した堤防の乾いた天端のセルと同じ扱いのまま)、流量で重みを付ける規則
       (lateral_flux・lateral_join・path_value・stream_share。壁のエッジの流量は 0 なので、もともと壁の向こうを数えない)。
     - 作業用の版は既定の設定が通る所だけで、lateral_u_w・lateral_u8・axis_open の f_advection_donor = 3 の分岐は直して
       いない(既定以外の設定で使う)。
