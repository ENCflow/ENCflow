00ak. **例題 examples/confluence_backwater(2026-11-26 作成。合流点の背水による支川の氾濫と、粗い格子・合流の形の確かめ)の残り**
   (作成と検討の経過は developer.md §131。ここには決まっていないこと・確かめていないことだけを書く)
   - **解像した合流の損失の格子依存**(§131.2): 本川 10 セル・支川 5 セルの直角・鈍角の合流で、合流の損失は
     1 次元の運動量の理論の 3〜5 割(p = 0.33・0.46)、格子を半分にすると 5〜9 割(0.46・0.88)。収束の確認
     (Δx = 2.5 m など)と、水路実験(Weber ら 2001 の 90°・等幅、Hsu ら 1998 の 30〜60°、Gurram ら 1997)との
     比較はしていない。移流項の規則(f_advection_lateral など)を変えるなら挙動の変更なので設計の議論が先。
   - **利用者ガイドへの限界の追記**: 解像した合流の損失の過小と格子依存(移流項のスキーム §4.4・1 セル幅の河道と
     移流項の風上供給元 §7)、粗い格子の 2 セル幅の湾曲部の階段で本川の水位が上がること(河道の解説 §2 の精度の
     限界。§131.8 の切り分けで湾曲だけ +0.44 m)、セル幅の倍数でない川幅を並列のサブグリッドのセルに等分すると
     通水が過大になること(§18.y)、斜めの区間の通水の不足(粗い格子の帯で 1〜6 割、川幅 6〜10 セルでも 2〜9 %。
     §131.9)を、章に書くかどうかは決めていない(いまは例題の README だけ)。
   - **川幅 1〜2 セルの斜めの川の表し方**(§131.8〜§131.10・§18.y): 「解像したセル + 残りの幅のサブグリッドのセル」は
     軸に沿う区間と 45° の区間でしか合わない。18.4°〜33.7° の向きでは、粗い格子の帯の「くびれ」(横に並んだ数セルの
     区間どうしが 1 セルの重なりか角だけでつながる所)で通水が 1〜6 割不足する。段の所で隣り合う列に中心線に近い
     2 行を共有させると(make_coarse.py の THICK = 2 と同じ規則)、川幅 2 セルの川は通水が戻り(0.95〜1.11)、例題の
     湾曲部の差も消える(+0.44 → +0.02 m。§131.10)。決まっていないこと:
     - 例題の粗い格子の既定を THICK = 2 にするか(洪水のケースと README の補足 1 の数値・図が変わる)。
     - 太らせても洪水のケースで越水の時期に残る差(合流点の水位 +0.2 m、堤内地の水量 1.4〜1.6 倍)の原因。合流部・
       支川の口・堤内地の粗い格子での表し方が候補(未解析)。
     - 川幅 1〜1.5 セルの斜めの川の表し方(太らせると面積が 2 倍近くになり、通水が 1.6〜1.9 倍)。単線のサブグリッド
       河道(1 セル幅の階段)との比較は未着手。
     - 川幅をセルへ割り付ける前処理の道具(ラスタ化の端の同値の扱い・段の太らせを含む)。残りのセルの貯留の膨らみ
       (L_ch が横の河道セルまで数える。0° で川幅の 1.3 倍)も未対処。§18 の制約や河道の長さの規則を変えるなら設計の
       議論が先。幅の変わる区間での確かめもしていない。
   - **定常の背水曲線の検定**: サブグリッド河道の支川の背水曲線を 1 次元の漸変流の式と比べる検定は test/ にない
     (例題の plot_results.py の数表だけ。差は解像 0.004 m・サブグリッド 0.018 m)。検定にするなら、例題より小さな
     直線の本川と支川の構成で、reference と Check_*.py を作る(reference の確定は人の目視が要る)。
   - **確かめていないこと**: 例題を MPI(np = 2・4)で回していない。英語版 README の図(en/figs)は plot_results.py en
     で描いたもので、内容の確認は日本語版と同じ計算の結果に基づく。
