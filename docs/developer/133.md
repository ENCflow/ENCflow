## 133. ダムの量の BMI 公開と外部運転(f_dam_mode = 6): ダムの点の格子と目標放流量の set(2026-11-26 設計合意・実装。無効時はビット一致)

利用者向けは bmi/README.md「ダム(貯水池)の量と外部運転」、users_guide/structure.md「外部運転(モード 6)」と
hydraulics.md §4(いずれも日英)。検定は test/bmi_dam(bmi/python/test_dam.py)、見本の制御器は
bmi/python/dam_control.py。残りの作業は handoff 1i。運転則の拡張の前段は §132、BMI の set の区分は §76・§77、
多格子の公開は §73。

### 133.1 経緯と決定(利用者の選択)

利用者の依頼は「BMI でダムの量を取得し、操作できるようにしたい」。§132.1 で先送りした「ダムの量を BMI で公開して
外から運転する案」にあたる。§132.1 の棚卸しのとおり、前の状態を覚える規則(放流量の増減の速さの制限・ゲート操作の
間隔・ピーク後の一定量)、予測雨量を使う事前放流、複数ダムの統合運用、他モデルとの結合は、履歴を持たない組み込みの
運転則では表せない。BMI はこれらを呼び出し側のプログラムに書かせる口になる。ユーザールーチンと違い、計算本体
(Fortran)に利用者の規則を入れず、リビルドも要らない(方針の「計算本体は Fortran のみ」を保ったまま、規則は
呼び出し側の Python 等に置く)。

会話で比較と推奨を示し、利用者は 3 点とも推奨案を選んだ。

1. **外から運転するのは、外部運転と宣言したダムだけ**: f_dam_mode = 6 を新設する。目標放流量の set を受けるのは
   モード 6 のダムだけで、ほかのダムの要素は無視する。代案は「どのダムでも set で運転則を上書きする」だったが、
   (a) 設定ファイルを見ても運転が分からなくなる、(b) 同じ量の与え方は一つ(§76 の F 区分は「外部」を宣言した
   ときだけ受理。降水の set もパラメータ駆動の降水と併用しない)に反する、(c) BMI なしで実行したときの挙動が
   あいまいになる、ので採らない。
2. **ルート格子のダムだけを公開する**: 子格子のダムは載せない。ネストの子にダムを置く例はまだなく、載せるときは
   grid id = 格子数 + k、名前は §73 の `~grid<k>` 修飾で足せる形にしておく(bmi_encflow.f90 のヘッダに記録)。
3. **文書の範囲**: bmi/README.md とユーザーガイドの記述、検定(test/bmi_dam)、見本の制御器(dam_control.py)。
   教材(tutorials/bmi)の段は足さない。

### 133.2 仕様

**変数**(bmi_encflow.f90 の名前表。内部名 dam_* は m_main が解釈する)

| CSDMS Standard Name | 内部名 | 単位 | 内容 | set |
|---|---|---|---|---|
| reservoir_water_surface__elevation | dam_h | m | 貯水位(dh) | 不可 |
| reservoir_water__volume | dam_v | m3 | 貯水量(dv) | 不可 |
| reservoir_water~incoming__volume_flow_rate | dam_qin | m3 s-1 | 流入(dqin = 捕捉帯の吸収 ÷ dt) | 不可 |
| reservoir_water~outgoing__volume_flow_rate | dam_qout | m3 s-1 | 放流(dqout = 実際の運転の放流 ÷ dt。スピルを含まない) | 不可 |
| reservoir_water~spilled__volume_flow_rate | dam_qsp | m3 s-1 | スピル(dqsp) | 不可 |
| reservoir_water~outgoing~target__volume_flow_rate | dam_qtgt | m3 s-1 | 目標放流量(モード 6 は qext、ほかはその運転則の dqout) | 可(F 区分) |

- 名前は CSDMS Standard Names の文法(object~adjective__quantity)で作った独自の名前で、standard_names
  パッケージの文法検査を通る(§76 の造語と同じ扱い)。
- 存在条件(m_main の var_state): ダムの量 5 つはルート格子(kcur == 1)にダムが 1 つ以上あるとき、目標放流量は
  モード 6 のダムが 1 つ以上あるとき。ないときは 4(機能なし = 未知の名前と同じエラー。§76)。
- 値は診断値 dh・dv・dqin・dqout・dqsp(par_sum_rows の後で全ランク同値。§132.1 の棚卸し)で、最後に終わった
  歩の値。initialize の直後の流量は 0。ダム CSV の H・V・Qin・Qout・Qspill と同じ量(test_dam.py の E で照合)。
  追加の放流工(dam_lake)の水位・貯水量は参照先の湖沼の値で流入は 0、水位固定湖沼は水位 = 固定水位・貯水量 0・
  流入 = 消失量(dam_draw・dam_sink の診断のまま)。

**ダムの点の格子**

- 種類は "unstructured" で、節点数 = ダムの数、辺の数 = 面の数 = 0(点の集合)。bmi-tester 0.5.10 は格子の種類
  "points" を受け付けず、"vector" では test_grid_x が通らないので、節点だけの unstructured にした(BMI の
  unstructured 格子で辺と面を 0 にする使い方は独自の選択。bmi-tester は rank 2 の x・y を検査して合格)。
- grid id = ラスタの格子数(m_main_get_ngrids。ネストなしでは 1)。get_grid_shape・spacing・origin は
  BMI_FAILURE(形を持たない)、get_grid_x・y は代表点の座標、edge・face の数は 0 で成功。ラスタの格子への
  非構造格子の問い合わせは従来どおり BMI_FAILURE / NotImplementedError。
- 節点 k = &list_struct_dam の k 番のダム(init_dam は番号 1..ndam を構造物の連番に順に置くので、構造物の配列で
  e_struct_dam を数えた k 番目と一致)。代表点 = 捕捉集合の先頭のセル(cin(:,1))の中心、捕捉集合のない
  追加の放流工は放流セルの先頭(cout(:,1))。座標はラスタの格子と同じ系: x = x0 + (i − 0.5) dx、
  y = y0 + (ny − j + 0.5) dy(j = 1 が北。grid_origin の左下隅が基準)。

**外部運転(モード 6)と目標放流量の set**

- init_dam: qext = dam_q0(省略時 0。負は停止)。起動時に「外から運転する、set までは dam_q0 を放流する」の
  note を出す。dam_tadashigaki はモード 4・5 と同じく停止(放流が規則の外から与えられるので但し書きのランプは
  掛けない)。dam_h_init の省略時はモード 4 と同じく空虚から始まる note。dam_lake の追加の放流工もモード 6 を
  使える(参照の禁止はモード 5 だけ)。HV は必須(素通しはモード 2・rate 1.0 だけ)。
- dam_operate・dam_draw: `case (6): vt = qext · dt`。以後はほかのモードと同じ式で、
  vrel = min(vt, max(vnow − vfl, 0))(vfl = Vmin。dam_hlim はモード 1・2 だけ)、
  vspill = max(vnow − vrel − vmax, 0)。死水の下限とスピルはモデルが守るので、目標が大きすぎても水は作られない。
- set は §76 の **F 区分**(持続する強制。「外部」を宣言したとき = モード 6 のダムがあるときだけ受理)。値は
  set の時点で qext に入れ(保留しない)、次の update の歩から放流に効く。set の直後の get は設定値を返す。
  外部運転でないダムの要素は無視する(m_boundary_dam_set_target はモード 6 のダムだけ書き換える)。
- MPI: set の配列は rank 0 のものを使う(BMI アダプタの規約。§58)。rank 0 が長さ(不一致は 1)と負値(3)を
  検査して par_allreduce_maxi で判定を全ランクにそろえ、受理なら par_allreduce_sumr で配列を配る(rank 0 以外は
  0 を足す)。判定も配布も全ランクが同じ経路を通る(collective を is_root の内側に置かない。§5)。
- 保存しない: qext は save / restore の対象外(save_version は変えない)。再開すると dam_q0 から始まる。rn の
  外部上書き(§77)と同じく、外から与えた指示は呼び出し側が持ち、再開の直後に set し直す。
- BMI を使わずに encflow で実行すると、モード 6 のダムは dam_q0 の一定量放流になる(note で分かる)。

**静的ドライバ test_bmi.f90**: 格子の種類で分岐し、ダムの点の格子では節点・辺・面の数、x・y、shape が失敗する
こと、nbytes、ダムの量の get を検査する。目標放流量が入力表にあれば、初めから 1 歩ずつ進め、各歩の前に決定的な
制御(目標 = max(0, 流入 + (V − V0)/τ)、τ = 1800 s)を set する(MPI の np によらず結果が一致することの検査用)。
負の目標の set が失敗することも検査する。

**見本の制御器 dam_control.py**: 目標 = clip(流入 + (V − V_target)/τ, 0, qmax) を、前の歩の目標から rate × dt
以内に抑える。前の歩の目標を覚える(履歴)ので、組み込みの運転則では表せない規則の見本になる。見本であり、実際の
ダムの操作規則を表すものではない(式は独自)。

### 133.3 出典と独自の部分

- BMI 2.0 の仕様(CSDMS。bmi/vendor/bmi.f90)の get/set・格子の関数をそのまま使う。点の集合を節点だけの
  unstructured 格子で表すこと、変数の名前、目標放流量の F 区分への当てはめは本プロジェクトの選択(独自)。
- 制御器の式は見本として独自に置いたもの(貯水量の偏差の比例と流入のフィードフォワードと、変化の速さの制限)。
  文献の操作規則ではない。

### 133.4 検証(2026-11-26。gfortran 13.3、Open MPI 4.1.6、Intel Xeon(AVX-512))

- **既存の経路のビット一致**(変更前のソース d943cf3 から作った実行ファイルとの比較): test/damops・test/damwq と
  §132 の臨時のケース(モード 1〜5・素通し・水位固定・追加の放流工)の CLI の全出力がバイト一致。test/wave の BMI
  静的ドライバ(set あり)の Log が CLI と一致、bmi_vars・bmi_nest の Run.sh が合格、wave の bmi-tester は変更前と
  同じ 128 passed / 11 skipped。
- **新しい検定 test/bmi_dam**(4 基。詳細は README): ダム 2(外部運転で、ダム 1 = モード 4 と同じ段状の放流量を毎歩
  set)の CSV がダム 1 と全 121 行一致。ダム 3(見本の制御器。rate 0.0004 m3/s/s は洪水の流入の立ち上がり
  1.5/3600 m3/s/s より遅い)は目標の変化の制限が 7199/7200 歩で効き、水位は 104 m ± 0.0508 m、実際の放流 = 目標。
  ダム 1・4 へ set した 999 は無視される。get と同時刻の CSV の差は印字の桁の範囲(最大 5.0e-5)。閉じた系の体積
  (Log の S)の差 1.6e-13 m。外部運転のダムのない設定での再 initialize で目標放流量が表から消え、set は BmiError。
  dam_control.py のコマンド実行でダム 2・3 の最終水位が 104 m ± 10 cm。静的ドライバが完走。bmi-tester は
  190 passed / 18 skipped(test_set_value 等は入力変数の set を「危険」として飛ばすので、set の検査は test_dam.py)。
- **MPI**: 静的ドライバ(make MODE=mpi の test_encflow_bmi_mpi)の np = 1, 2, 4 が逐次の静的ドライバとダムの CSV・
  分布出力・Log でバイト一致(行の重み付き分割で、np = 2 ではダム 1・2 と 3・4 が別のランク、np = 4 では捕捉帯が
  ランク 0・1・2 に分かれ〔ランク 2 にダム 3・4〕、捕捉帯のないランク 3 も揃って set を受ける)。
- **-Og -fcheck=all**(作業用の複製で。src・bmi とも同じフラグ): 逐次の静的ドライバと test_dam.py が実行時エラー
  なしで合格、MPI の np = 2, 4 が debug 逐次とバイト一致。gfortran 13.3 では -fcheck=all(recursion を含む)で
  bmi_encflow.o のリンクが `is_recursive.N` の未定義参照で失敗する(変更前のソースでも同じ。コンパイラの問題)ので、
  bmi は -fcheck=all,no-recursion にした。LTO を使わないフラグで共有ライブラリを作るときは src も -fPIC が要る
  (bmi/Makefile の注記どおり。付け忘れると R_X86_64_PC32 の再配置エラー)。nightly の debug ジョブは src だけを
  -fcheck=all で作るので影響しない。
- トップレベルの make(utils のリンク)が通り、bin/encflow は make の前後で同じ。test/bmi_dam は nightly の bmi
  ジョブに登録した(bmi-tester の入った venv で Run.sh)。

### 133.5 できないこと・精度の限界

- 子格子のダムは公開しない(133.1 の 2)。
- 目標放流量は保存されない。再開後は呼び出し側が set し直す。外から与えた放流の決め方(規則)は ENCflow の出力に
  残らないので、規則のプログラムは結果と一緒に保存するよう利用者向け文書で案内した(方針 13)。
- 呼び出し側が判断に使えるのは、最後に終わった歩のダムの量だけ。下流の基準点の水位・流量や流域雨量はダムの量と
  してはない(水位・流速の場は従来の変数で get できるが、基準点の選び方と集計は呼び出し側の仕事)。捕捉帯への
  直接降雨が流入に入るのは 1 歩遅れ(§132.1)。
- Python から使う共有ライブラリは逐次版だけ(bmi/README.md「MPI で使う」)。MPI の計算を外から運転するには
  Fortran から BMI を呼ぶ(静的ドライバが見本)。
- 共有ライブラリ経由の計算は CLI とビットまでは一致しないことがある(BMI 全体の既知の制約)。
