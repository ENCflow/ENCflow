## 106. 貯留関数法の区画流出 m_sfm(fn_sfm。2026-11-11 合意・実装)と区画流出の共通基盤 m_zonerunoff

**経緯**: 利用者の依頼「鉛直不飽和浸透(VZ)流出と同様の構造で、貯留関数法のモジュールを作りたい。区画番号
ラスタで共有貯留タンクを指定する。VZ の土層厚の様なセル単位のパラメータは無く、同一の区画番号のラスタは全て
同じ流出となる。出口の指定も基底流の仕組みも VZ と同じ」。

### 106.1 決定事項(2026-11-11 合意。利用者が 4 項目とも推奨案を選択)

1. **式の形**: 木村(1961)の基本形 S = K·q^P(1 価、1 段のタンク)だけを入れる。区画に降った雨は全量がタンクに
   入り(損失なし)、流出 q は出口へ瞬間的に移す(VZ と同じ近似)。不採用: 木村の完全形(遅れ時間 T_L と、一次
   流出率 f1・飽和雨量 R_sa による有効雨量の分離。非有効分は系外への損失)、2 価の貯留関数(Prasad 1967 型・
   星・山岡 1982 型 S = k1·q^p1 + k2·d(q^p2)/dt)。いずれも後段の拡張として handoff に記録(方針 6)。
   → 同日、遅れ時間 T_L を追加した(§106.6)。
2. **VZ との共通部は共通基盤に昇格**(§16.1 の「第 2 モデルが実在した時点で昇格」): 区画番号ラスタの検査・
   雨の回収と入力群ごとの集約・出口・基底流を m_zonerunoff に移し、VZ を等価リファクタしてから貯留関数を
   その上に作る(§106.2)。不採用: m_vzflow を変えずに新モジュールへ複製(約 600 行の重複)。
3. **既定値**: P = 0.6(貯留関数法で標準的に使われてきた値。Manning 則の運動波の定常解の S ∝ q^{3/5} に当たる。
   §106.3)、K は必須(流域ごとに桁で変わり、根拠を示せる一般の既定がない。方針 13)、初期の流出強度
   q0 = 0.1 mm/h(VZ と同じ経験値。§87.7)。採用値は "(default)" 付きで表示する(§62)。
4. **VZ との併用**: 区画のセルが重ならず、出口が相手の区画セルにない限り併用できる(初期化で検査して停止)。
   その他の併用制限は VZ と同じ(地下水・積雪・氷河・地形変化・水質・淡塩・ネスト・STG)。

方針との関係: タンクは鉛直方向の水の動きを 1 つの貯留量に概念化したもので、方針 5(鉛直は抽象化・概念化)の
範囲に入る(VZ のような方針の例外は要らない)。区画番号ラスタはラスタ表現(方針 2)、有効化は fn_sfm(方針 7)、
無効時は確保・呼び出し・通信なし(方針 8)。

### 106.3 実装(m_sfm・list_sfm)

- **モデル**: 区画 g のタンク(単位面積あたり)dS/dt = r − q、S [mm] = K·q[mm/h]^P。SI では q = c·S^m
  (m = 1/P、c = (1000/K)^m / 3.6×10⁶、S [m]、q [m/s])。P は 0 < P ≤ 1 に限る(P > 1 は q′(S) が S → 0 で発散し、
  検定もしていないので停止)。初期条件は初期の流出強度 q0 で与え、S0 = K·q0^P(q0 = 0 は乾いた状態)。区画に
  入力群 = 区画(区画ごとに 1 つのタンク。VZ の柱の共有に当たる仕組みは置かない: セルごとの量がないので、
  1 つのタンクを複数の出口に分けるのは出口の配分率で表せる)。
- **P = 0.6 の根拠**: 一様な斜面(長さ L、勾配 i)の定常な面状流を Manning 則の運動波で表すと、q(x) = r·x =
  h^{5/3} i^{1/2}/n から h ∝ x^{3/5}、斜面の平均水深(単位面積の貯留)は S = (n r L / i^{1/2})^{3/5}/1.6 で、
  単位面積の流出強度 q = r に対して S ∝ q^{3/5}(導出。独自の説明)。P = 0.6 は貯留関数法の実務で標準的に
  使われてきた値で、木村(1961)に由来するとされる(原典は作業環境から取得できず未照合。書誌はウェブ検索の
  結果で確かめた)。
- **解法(独自の選択)**: 後退 Euler S1 + h·q(S1) = S0 + h·r を、区間 [0, S0 + h·r] の二分法で保護した Newton
  法で解く(q は S の増加関数なので解は一意。P = 1 は直接解く)。時間誤差はステップ二分比較(粗い 1 歩と細かい
  2 歩の貯留の差)で、|S_fine − S_coarse| ≤ sfm_tol·P·(S_fine + 10⁻⁹ m) を受理の条件とする(貯留の相対誤差は
  流出強度の相対誤差の P 倍)。受理した歩は局所外挿 2·S_fine − S_coarse(2 次精度)を採り、[0, S0 + h·r] を
  外れたら細かい枝を採る。刻みの増減は 0.2〜2 倍(安全率 0.9)、区間端で切った刻みは提案を広げない。流出量は
  S0 + h·r − S1 で定義するので、タンクの収支は構造的に閉じる(丸めを除く)。負の入力は停止する。
- **同期**: dt_sfm の既定は 0(毎ステップ)。タンクはスカラーで費用が無視できるため(VZ の 60 s は柱の費用に
  よる。§87.2)。通信は同期ごとに区画の入力を揃える 1 回(厳密一致: max の allreduce、面積平均: 行部分和の
  par_sum_rows)。
- **台帳**: s%sfstore(Σ S_g·A_g/(dx·dy)。real64)と s%sfp(回収済み・未同期の雨)を calcstat が S_grnd に算入
  する(VZ の後の別枝。無効時は既存の演算に触れない)。
- **出力**: result/sfm_zone.csv(dt_recrd 間隔。直近の同期時刻の値): 区画ごとの直近ステップの雨 (mm/h)、
  流出強度 q (mm/h)、貯留 S (mm)、累積の vin・vstore・vdrain・vsurface・vexternal・residual (m³)、基底流を
  与えた区画があれば vbase。初期化時の区画確認表(セル数・面積・K・P・初期の q と S・出口・基底流)。
- **保存・復元**: 私有ファイル sfm.dat(save_version = 20261111)。区画のタンクの貯留・次の試行刻み・刻みの
  数・直近の雨・累積の診断・出口の繰越。構成の識別は区画数・出口数と区画のセル数・K・P。区間の途中で保存する
  ときは dispose で残りを同期してから書く(VZ と同じ)。無効なのに sfm.dat があれば停止する。
- **呼び出し位置**: init は m_vzflow_init の直後(VZ の zr を受け取って重なりを検査する)。calc は m_vzflow_calc
  の直後(区画が重ならないので順序は結果に影響しない)。record は do_recd、dispose は m_vzflow_dispose の後
  (m_state の save より前)。
- **併用の理由の文言**: 地形変化は「雨による侵食が、雨をタンクに取られたセルに働く」(VZ の理由「土層厚が
  変わる」は当てはまらないため書き換えた。制限の範囲は VZ と同じ)。

### 106.5 できないことと精度の限界(users guide にも記載)

- 2 価の貯留関数を持たない。有効雨量の分離(f1・R_sa)はタンクに持たせず降雨遮断で与える(§106.8)。蒸発散による
  貯留の減少は §106.7 で追加。雨はすべてタンクに入り、
  いつか流出する(長期の水収支には損失を別に考える必要がある)。遅れ時間 T_L は §106.6 で追加した(時間の
  ずらしだけで、波形の変形はしない)。
- 区画内の空間分布(どこで流出が生じるか)を表さない。区画の流出は出口へ瞬間的に移り、出口の背水は解かない。
- 区画のセルに上流から流れ込んだ地表水(run-on)はタンクに入らない(一方向。VZ と同じ)。
- K・P は流域ごとの校正量で、出力の妥当性は観測との比較でしか確かめられない。

### 106.6 遅れ時間 T_L(sfm_tl_h。2026-11-11 合意・実装)

**経緯**: 利用者の依頼「遅れ時間を導入したい」。4 項目とも推奨案で合意した。

- **遅れの位置**: 雨を T_L 遅らせてタンクに入れる(dS/dt = r(t − T_L) − q)。木村の q_l(t) = q(t + T_L)
  (タンクの流出が T_L 後に流域末端に現れる)とは、初期状態が定常なら出口の流出の時系列が同じになる
  (時不変の系の時間のずらしは入力側と出力側で入れ替えられる)。採った理由: sfm_zone.csv の q が出口に
  届く流出強度そのものになる、雨は区分一定の区間で持っているので遅れ列を区間の並び(連長圧縮)で持て、
  メモリが dt に依らない、保存 → 再開と同期区間の途中でも素直に扱える。不採用: 流出を遅らせる(字面
  どおりだが、ステップごとの流出の遅れ列と、タンクの流出と出口の流出の 2 系統の出力が要る)。
- **入力**: `&list_sfm_zone` の `sfm_tl_h(z)`(時間。省略時 0 = 遅れなし)。不採用: 分(基底流の時刻と
  揃う)。実務の T_L は時間で与えることが多く、K も mm/h で与えているため。
- **端数**: T_L を dt の整数倍 nlag = nint(T_L/dt) に丸め(誤差 dt/2 以下)、採用値を画面に表示する
  (丸めたときは元の値も)。不採用: 割り切れなければ停止、端数を 2 ステップへ線形配分(波形がわずかに
  平滑化される)。
- **初期状態**: 遅れ列を初期の流出強度 q0 の定常で満たす(区間 1 つ = 雨 q0 が nlag ステップ。移動中の
  水 q0·T_L が初期の貯留に入る)。出口の流出は開始直後から q0 で連続する。不採用: 空(0)。
- **実装**: t_sfmtank に遅れ列(区間の雨 qr [m/s] とステップ数 qn。合計 nlag)。同期ごとに、共通基盤が
  作った区間の区分一定の雨(segl [s]・segr)をステップ数に直して末尾に足し(直前の区間と同じ雨なら
  継ぎ足す)、先頭から区間と同じステップ数を取り出してタンクの入力にする(lag_shift)。区間の数は雨の
  変化の数で決まる。移動中の水 vlag = A_g·Σ qr·qn·dt を台帳(s%sfstore = Σ (A_g·S + vlag)/(dx·dy)。
  S_grnd)と sfm_zone.csv の vlag 列(遅れのある区画があるときだけ。residual の後、vbase の前)に出し、
  収支残差は (vstore + vlag) − vstore0 − vin + vdrain(vstore0 は初期の移動中の水を含む)。T_L = 0 の
  区画は遅れ列を持たず、従来と同じ呼び出しと式で進む(残差の式も従来のまま。初稿の
  `(vstore + vlag) − …` は -Ofast の並べ替えで残差の列の最終桁が変わったので、遅れのある区画だけ
  vlag を後から足す形にした)。基底流は出口で与える量なので遅らせない。sfm_zone.csv の rain は
  地上の雨(タンクへはその T_L 後に入る)。
- **保存・復元**: sfm.dat に区画ごとの遅れ列(区間数と中身)を足し、構成の識別に nlag を加えた
  (dt を変えて再開すると nlag が変わり停止する)。save_version = 2026111102(同日の 2 回目の形式変更。
  §7 の文字列の版の "b" に当たる。整数の版なので日付の後に 2 桁の通し番号を付けた)。
- **検証**(test/sfzone の param_lag.txt。区画 1・2・3 に 0.5・1・0.2501 h。区画 3 は 0.25 h = 180
  ステップに丸めて表示): 雨を遅らせた入力(開始前は q0)に対し、線形貯留の厳密解と相対 2.8e-7、
  RK4 の参照解と貯留 4.4e-8・流出強度 1.1e-7。vlag = 直近 T_L の雨(と開始時の定常分)× 面積が
  相対 4e-16、区画の収支残差は 3.7e-14、Log の S_total の収支 5e-15 m、入力 vin は遅れなしと一致。
  sed で作る 6 h の保存 → 再開が連続計算とビット一致。dt_sfm = 60 s(区間の途中で遅れ列の区間を分ける)は
  参照解と 1.3e-5(sfm_tol = 1e-4 の範囲)、同期区間の途中(21625 s)の保存 → 再開が連続計算と 6e-9。
  T_L = 0 の全構成(sfzone の全変種と examples/source_area の param_sfm・param_sfm_r30)が変更前の
  main のバイナリと全出力でバイト一致(違うのは形式を変えた sfm.dat だけ)、reference の Log.txt・

  先の浅水流が担う)。区画内のどこに降った雨も同じ T_L で遅れる。

### 106.7 蒸発散をタンクから引く(sfm_elim_mm。2026-11-11 合意・実装)

**経緯**: 利用者の問い「蒸発散による貯留の減少はタンクから引きたいが、遅れ時間との整合が大変?」。
答え: 遅れ時間を「雨を遅らせる」形で入れた(§106.6)ので、タンクの貯留はその時刻の値で、蒸発散は
その時刻のタンクから引けば済む。木村の式(タンクは雨を遅れなく受け、流出が T_L 後に末端に現れる)と
厳密に揃えるには蒸発散の要求も T_L 遅らせることになるが、ENCflow の PET は暦日ごとの一定値なので、
差は日の変わり目の T_L の間だけ(日々の差 1 mm/day・T_L 2 h で約 0.08 mm)。3 項目とも推奨案で合意した。

- **時刻**: その時刻にタンクから引く。遅れ列の雨(移動中の水)からは引かない。不採用: 要求も T_L
  遅らせる(要求の速さの遅れ列。水ではないので台帳には入らないが、保存ファイルと実装が増える)。
  不採用(検討のみ): 雨と要求の差 r − e を遅れ列に入れる(移動中の水が負になりうる)。
- **乾燥による抑制**: 区画ごとの任意の `sfm_elim_mm`(mm)。S が S_lim より少ないとき
  E·min(1, S/S_lim) に減らす(地下水の evap_hglim と同じ線形低減。§27.2)。未指定なら供給制限のみ。
  不採用: 供給制限のみ。
- **要求の受け渡し**: m_evap_calc の優先順位(樹冠 → 地表水 h → hrs → 地下水 hg)の後に段 (5) を足し、
  残りの要求を gv 面積の水深からセル面積の水深に直して s%sfe(セル配列。fn_sfm と fn_evap の両方が
  有効なときだけ m_sfm_init が確保)に積む。m_main は m_evap_calc の直後に m_sfm_evap を呼び、区画ごとに
  行部分和 → par_sum_rows(決定的)で集めた面積平均の要求 d を、その時刻のタンクから引いて s%sfe を 0 に
  戻す(ステップをまたぐ未処理の要求を残さない = 保存 → 再開が素直)。区画外のセルの要求は従来どおり
  捨てられる。地下水の段で引いた量を要求から差し引く 1 行(`dem = dem - w`)を足したが、以後 dem は
  s%sfe にしか使わないので既存の計算は変わらない。
- **引く量**: tank_et_draw(real64)。el = 0 は min(S, d)、el > 0 は dS/dt = −E·min(1, S/el) をステップ内で
  E 一定として厳密に解いた減少量(hg_draw と同じ式と級数。タンクの状態は real64 なので real64 で書いた)。
- **台帳と出力**: 累積 vevap(区画、m³)を sfm_zone.csv の列(vlag の後、vbase の前。fn_evap と併用時
  だけ)と収支残差(+ vevap。遅れなし・蒸発散なしの区画の残差の式は従来のまま = 蒸発散があるときだけ
  後から足す)に入れる。evap.csv の列は変えない(m_evap が引いた量だけ。利用者ガイドに書いた)。
  s%sfstore は引いた後に更新する。
- **保存・復元**: sfm.dat の区画の行に vevap を足し save_version = 2026111103(同日 3 回目)。
- **順序の影響**: 1 ステップで「タンクを進めてから引く」ので、一定の雨 r と E の定常で記録時刻の q は
  r − E より相対 7e-5 ほど小さい(引いた直後の貯留で q を評価するため。時間刻み 5 s、test/sfzone)。
- **検証**(test/sfzone の param_et.txt: PET 48 mm/day = 2 mm/h、区画 1 は供給制限のみ、区画 2 は
  sfm_elim_mm = 5、区画 3 は 20 と遅れ時間 0.25 h): ステップごとに「タンクを進める → 蒸発散を引く」を
  なぞった Python の参照解と、貯留が相対 3.5e-7、累積の蒸発散が 2.8e-8 以内。収支残差(移動中の水と
  蒸発散を含む)は 5e-14、Log の S_total = S0 + 雨 − (系外流出 + evap.csv の ev_total + Σ vevap)/全面積が
  9e-12 m(evap.csv の印字桁による)。param_et_steady.txt(雨 10 mm/h を 48 h)で区画 1・2 の q が
  r − E = 8 と 6.7e-5・8.7e-5、区画 3(S_lim = 100 mm)が r = q + E·S/S_lim の解と 3.5e-5。sed で作る
  6 h の保存 → 再開がビット一致。MPI np = 1・2・4 の Run_MPI.sh が合格(sfm_zone.csv・Log・evap.csv が
  np = 1 とバイト一致)。夜間 CI の debug 層と同じフラグで Run.sh と Run_MPI.sh 2 が合格。fn_evap を
  使わない構成は reference の Log.txt・sfm_zone.csv とビット一致。m_evap を変えたので test/icevap・
  evapdry の Run.sh と evapdry の Run_MPI.sh 2 を回し、合格(evap.csv も reference とビット一致)。
- **限界**: タンクの貯留 S は流出に関わる貯留で、土壌水分そのものではない(蒸発散の取り方は概念的)。
  深部浸透の損失は持たない。

### 106.8 有効雨量の分離は降雨遮断で: 初期損失モデルの 2 段の遮断率(2026-11-11 合意・実装)

**経緯**: §106.7 の議論で、木村の一次流出率 f1・飽和雨量 R_sa による有効雨量の分離は、タンクに持たせず
降雨遮断(fn_intercept)を使うよう誘導すると利用者が決めた。既存の遮断モデルでは、固定遮断率が一定の f1
(R_sa = ∞)、初期損失が f1 = 0 の R_sa に当たり、0 < f1 < 1 で R_sa が有限の組は表せなかった。作業中に
利用者から「初期損失の後に固定遮断率」というモードの提案があり、木村の f1・R_sa は順序が逆(R_sa までは
一部を失い、以後は全量流出)であることを示して、次の形で合意した(推奨案)。

- **形**: 初期損失モデル(f_icmodel = 2)に任意の 2 つの率を足す: 満杯までの遮断率 a1(`ic_alpha_fill`。
  既定 1)と満杯後の遮断率 a2(`ic_alpha_full`。既定 0)。満杯まで雨の a1 を遮断して樹冠に蓄え(満杯に
  要る雨は残容量/a1)、満杯の後は雨の a2 を損失として取り除く(固定遮断率モデルと同じく蓄えない)。
  分布ファイル `fn_icalpha_fill`・`fn_icalpha_full`(read_smax_map と同型の read_ratio_map)。
  - 初期損失 → 固定遮断率(提案の形): a1 = 1、a2 = α。初期損失と固定遮断率を順に当てる組み立ては独自
    (同じ形の損失モデルは流出計算の実務にあるが、文献は照合していない)。
  - 木村の f1・R_sa: a1 = 1 − f1、smax = (1 − f1)·R_sa、a2 = 0(満杯に要る累積雨量 smax/a1 = R_sa)。
  不採用: 提案どおり 1 つの率(満杯後の遮断率)だけ(木村の形が表せない)。
- **既定と互換**: どちらも与えなければ従来の初期損失そのもので、従来の手続き(従来の式のループ)を通る。
  与えたときだけ別の手続き step_two_phase を通る。既定値の表示も、与えたときだけ 2 つの採用値を出す
  (従来の最小入力の画面と test/icevap の "(default)" の数 3 を変えない)。保存の形式(樹冠貯留 st)は不変。
- **1 ステップの式**: 雨 R = P·dt、残容量 C = max(smax − st, 0)、R_f = C/a1。R ≤ R_f なら ΔS = a1·R・
  損失 0、R > R_f なら ΔS = C・損失 a2·(R − R_f)、C = 0 なら損失 a2·R。通過率 (R − ΔS − 損失)/R で
  s%pre・s%prh を同率に減じる(契約1)。範囲は 0 < a1 ≤ 1、0 ≤ a2 ≤ 1(分布は使用セルで検査)。
- **限界**: 容量は蒸発散(fn_evap の draw)でしか回復しないので、出水ごとに R_sa を数え直す木村の方法とは
  出水の間の回復の仕方が違う。遮断した水は系外への損失(S_total に入らない。蓄えた分は蒸発散で
  evap.csv の樹冠の列に出る)。
- **検証**(test/sfzone の param_ic.txt。全セル一様): 木村の f1 = 0.5・R_sa = 40 mm で、区画の入力が
  Python でなぞった有効雨量 × 面積と相対 2e-14、累積の有効雨量 81.015278 mm が閉じた形
  (1 − a1)·min(R, R_f) + (1 − a2)·max(R − R_f, 0) と一致(R = 101.015 mm)。有効雨量に対するタンクの
  参照解と 3.1e-7 以内、Log の S_total = S0 + 有効雨量 − 系外流出 が 4.9e-15 m。sed で作る初期損失
  10 mm の後に遮断率 0.3 も同じ検定に合格(累積 63.710694 mm)。同じ値の分布ファイルが一様指定と
  sfm_zone.csv・Log でビット一致、ic_alpha_fill = 0 は停止、6 h の保存 → 再開が連続計算とビット一致。
  MPI np = 1・2・4 の Run_MPI.sh が合格(一様と分布ファイルの計算が np = 1 とバイト一致)。夜間 CI の
  debug 層と同じフラグで Run.sh と Run_MPI.sh 2 が合格。test/icevap の Run.sh と Run_MPI.sh 2 が合格
  (既定の初期損失は従来と同じ)。固定遮断率だけを使う test/chichibu_icmap は変更の対象外。
