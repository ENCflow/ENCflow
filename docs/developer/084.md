### 84.1 段 0 (1): 掃流砂の保存型供給量制限(2026-10-17 実装。挙動変更)

- **問題**: ループ 1 のエッジ別可動層クランプは「このエッジ単独」の上限
  なので、複数エッジが同時に流出するセルでは合計が sd を超え、ループ 2 の
  岩盤床クリップ(保存則の破れ = vleak)に落ちていた。長期の蛇行計算では
  この漏れが累積する(plan §3.1)。
- **実装**(calc_fluvial のループ 1.5): 自帯の各セルで総流出要求
  vout = Σ_k max(sign_e(k)·q_k, 0) を集計し、供給可能量 vcap =
  sd/(dts·ainv·winv·poroi)(流量換算)を超えるセルに縮小率
  fdon = vcap/vout(sd=0 なら 0)を立てる(`gm%flv%fdon`。帯±ハロ、
  有効時のみ確保、初期値 1)。**par_halo_cell(fdon) を 1 回**行い、
  ループ 2 で各エッジ流量に風上セルの fdon を乗じて集計する(風上が
  域外 = 開境界からの流入は縮小なし。近傍の fdon 読みは x 番兵ガードの
  内側で — §12)。両側のセルが同じ fdon(風上セルの値)を読むので
  反対称性 = 土砂体積保存は保たれる。bedslide のドナー律速(§61)と同型。
- **不変性**: 発動しないセルは fdon = 1.0 の乗算で結果は厳密に不変。
  既存のエッジ別クランプ(sd=0 の早期打ち切り)と dzmax ガードは残し、
  岩盤床クリップは丸め誤差の最終防衛として残す(以後 vleak > 0 は
  「設定の誤り」の意味)。発動セル数 nlim は dispose で par_warn
  (ランク局所)。
- **挙動変更なので単独コミット**(規律 4)。既存 reference への影響は
  §84.1 末尾の検証記録に記す。
- **検証(2026-10-17。gfortran 13.3 / Open MPI 4.1、Ubuntu 24.04)**:
  - 厳密数学(-O2 -ffp-contract=off): 制限が発動しないケース(test/fluvial、
    乾いた河岸付き水路)で変更前後の state.dat がバイト一致。
  - -Ofast(既定ビルド): 地形変化を使う 16 ケースの回帰で reference 比較は
    全 PASS、変更前の出力とのバイト比較は test/fluvial の state.dat だけが
    最終桁で変わる(ループ 2 の集計式に乗算が入ったことによる再結合差。
    §28.3 の既知挙動。検定値 Σ(z−z0) = −4.6e-17 は不変)。
  - 発動するケース(test/fluvial の土層を 1 mm / 0.5 mm に): 変更前は岩盤床
    クリップで 0.032 / 0.080 m³ が消え Σ(z−z0) = 5.4e-2 / 1.3e-1 m·cell、
    変更後は Σ(z−z0) = −5.0e-17 / −7.2e-18 で vleak = 0。
  - MPI: np = 1, 2, 4 の state.dat が逐次と一致(発動あり・なしの両方)。
    -fcheck=all np=2 正常(新配列 fdon とハロ読み)。

### 84.2 段 0 (2): 河岸面の掃流遮断(2026-10-17 実装。挙動変更)

- **問題**: エッジ水理量が両セル平均のため、湿潤セル c と乾いた高い
  セル n(z_n ≥ c の水面)の間でも vve = vv_c/2, hhe = h_c/2 > dd なら
  流砂が計算され、流向次第で「水面より上の乾いたセルに掃流砂が堆積する」
  「乾いたセルが見かけの τ* で削られる」。確認(幅 10 セルの直線水路、
  両岸 +2 m の乾いたセル、Q = 8 m³/s・120 s、変更前のバイナリ):
  乾いたセルの |Δz| 最大 3.9 cm、合計 0.21 m·cell。
- **規則**(ループ 1 で gq の符号が決まった直後、クランプの前):
  (R1) 風上(供給)セルが乾燥(h ≤ dd)なら供給しない。
  (R2) 受け手の地盤が供給セルの水面(z + h)以上なら運ばない。
  R2 が「河岸面」の定義で、河岸面の交換は側岸侵食(段 2 の f_berode)
  だけが担う。両セルが湿潤で受け手の地盤が低い(段落ち・滝)方向は
  従来どおり通す。開境界面(一方側値)は変更なし。
- **f_berode の有無によらず既定挙動とする**(plan §7-4 の合意)。
  全セル湿潤のケース(test/fluvial)では発動せずビット一致。
- **検証(2026-10-17)**: 厳密数学で全湿潤の test/fluvial は変更前と
  state.dat バイト一致。test/bankface(新設。乾いた河岸付き水路のダム破壊流):
  乾いた河岸の max|Δz| が 0(変更前 0.39 mm)、土層 0.5 mm では供給量制限の
  下で Σ(z−z0) = 5.4e-13(変更前は 0.57 m³ 消失)。MPI np = 2 の
  state.dat が逐次と一致、-fcheck=all np=2 正常。

### 84.3 段 1: 掃流砂の方向補正 — 河床勾配項と平衡二次流項(2026-10-17 実装。機能追加)

- **定式**(plan §3.2。合意 §7-2): 流砂ベクトル q⃗_b = q_b (t̂ + r n̂ − γ∇z)、
  エッジ流量 gq = q_b·wl(k)·(q⃗_b/q_b · ê_k)。t̂ = (ū, v̄)/vve(両セル平均の
  流速と、既存の vve = 両セルの |V| の平均 — 補正なしは従来の ue/vve に
  厳密に戻る)、n̂ = (−v̄, ū)/vve(左法線)。
  - 河床勾配項 `fluv_slope=1`: γ = √(τ*c/(μs μk τ*))(長谷川型。Nays2DH の
    河床勾配補正と同形)。射影 dirp に効くのは ∇z のリンク方向成分だけ
    なので、**エッジをまたぐ直接差分 (z_n − z_c)/d_k で評価する**
    (2026-10-17 改訂。初版は両セルの中央差分勾配の平均だったが、中央差分は
    2 セル周期の市松モードを見ない = 減衰せず、examples/meander の長時間
    計算で河床に市松が育った(rms 0.34 m)。直接差分は市松を拡散で抑え
    (0.17 m)、test/bendsed の外岸−内岸の差も −0.098 → −0.224 m と明瞭に
    なった。河岸面の段差は、§84.2 の遮断でそのエッジに流砂が立たないので
    自然に除外される。初版で検出した「河岸の段差を勾配に入れると河岸沿いが
    3.9 m 洗掘」の問題も同時に消える)。
  - 平衡二次流項 `f_secflow=1`: r = N* h κ、κ = (u² v_x − v² u_y +
    u v (v_y − u_x))/|V|³(水深平均流速場の幾何学的流線曲率。κ n̂ は曲率
    中心向きなので r n̂ は常に湾曲内側 = 行順(北→南)や左手系によらない。
    test/bendsed の left/right 鏡像で確認)。**4 近傍がすべて有効な湿潤セル
    のときだけ中央差分で評価**し、河岸沿い・開境界列・水際は r = 0
    (片側差分や乾いた近傍の u = 0 を使うと偽の曲率が立ち、横断流砂の
    発散で穴が育つ — 自由流出列で 4.8 m の穴を実検出)。評価は h > dd かつ
    |V| > sec_vmin、|r| ≤ sec_rmax。r はセル配列 `flv%rsec` に自帯で評価し
    par_halo_cell で交換、エッジ値は両セル平均(fdon と同じ型)。
  - 入口条件を `ue /= 0` から「補正後の射影 dirp /= 0」に移した(水の
    法線流速がゼロのエッジでも横断流砂が通る)。τ* の評価を入口条件の前に
    出したが、補正なしでは同じ量を同じ順序で計算するので結果は不変。
  - 有効掃流力 `fluv_taufac`(τ*_grain = f_τ τ*。既定 1.0 = 分離なし。
    1.0 の乗算は厳密に不変)。
- **係数の既定を置かない**(合意 §7-8): N*、μs、μk は式固有の係数だが、
  本環境から原著(Engelund 1974、長谷川 1981、Nays2DH Solver Manual)に
  到達できず照合できなかったため、**有効時は明示指定を必須**にした
  (未指定は par_stop)。利用者ガイドには記憶上の文献値(N* = 7、μs = 1.0、
  μk = 0.45)を「照合待ち」と明記して載せ、照合が済んだら §62 方式の既定に
  昇格する(handoff に記録)。
- **検証(2026-10-17。gfortran 13.3、-O2 厳密数学)**:
  - 無効時: test/fluvial・test/bankface の state.dat が段 0 の結果とバイト
    一致(fluv_slope = f_secflow = 0、fluv_taufac = 1)。-Ofast では
    test/fluvial の state.dat が最終桁で動く(ループ 1 の τ* と射影の評価順を
    入れ替えたことによる縮約・再結合差。§28.3)。地形変化を使う 11 ケースの
    回帰は reference 比較・自己検定とも PASS、他はバイト一致。
  - MPI: test/bendsed left_on の np = 2, 4 の state.dat が逐次と一致、
    -fcheck=all np=2 正常(新配列 rsec と曲率・勾配の近傍読み)。
    トップレベル make(utils の追随)OK。
  - test/bendsed(新設): 幅 10 セル・半径 25 m の 90° 湾曲、Q = 6 m³/s、
    600 s。補正あり = 円弧区間の外岸側が内岸側より平均 0.22 m 深く削れる
    (外岸洗掘・内岸堆積の向き。中央差分の初版では 0.10 m。2026-10-24 の現行
    コードでは 0.075 m: 既定 f_opening_dynamic = 2 で旧既定 1 の円弧全体の
    数値的低下が消えたため。§68.38 末尾)、補正なし
    (対照)= 内岸側が多く削れる(符号が逆。水深平均流の内岸加速)。
    left/right の鏡像差は補正なし 2.3e-11、補正あり 2.2e-5(形態の正帰還で
    丸めが増幅。許容 1e-4)。乾いた河岸は 4 構成とも厳密に不変。
  - 直線水路(test/bankface 地形)に補正を入れた場合の最大変動は補正なしと
    同程度(0.29 m 対 0.38 m)で、暴走しない。
- **残(段 1)**: 横断勾配の平衡値 ∂z/∂n ≈ r/γ の定量ベンチ(固定岸の長時間計算)、
  格子 45° 回転の傾向比較。係数の文献照合と既定化は 2026-10-21 に完了(§84.12)。

### 84.4 段 2: 側岸侵食 f_berode と安息角崩落 f_repose(2026-10-17 実装。機能追加)

- **構成**: submodule m_geomorph_bank.f90。側岸侵食は calc_fluvial の
  ループ 1 の直後に呼ばれる**エッジパス**(bank_edge_pass)で、河岸面エッジ
  (湿潤セル w と、その水面以上の地盤をもつ隣接セル b。§84.2 で掃流砂を
  遮断した面そのもの)に河岸 b → 脚部 w の固体流量を共有スクラッチ wrk%q に
  **加算**し、既存の apply_edge_flux(供給量制限 → 発散)で適用する。
  安息角崩落は fluvial の後に独立の 2 ループ(calc_repose)で wrk%q を
  上書きし、同じ apply_edge_flux で適用する(その前に z・sd のハロを
  最新化。splash と同じ理由)。
- **側岸侵食の定式**(plan §3.3): E_b = K_b·max(τ*_w/τ*c,b − 1, 0)^m [m/s]。
  τ*_w は脚部セル w のセル値(近傍流速の代理。河岸面と河床面の違いは K_b に
  吸収)。水没河岸高 min(z_b − z_w, h_w) は河岸面の定義 z_b ≥ z_w + h_w から
  常に h_w。エッジの固体流量 q = E_b·h_w·wl(k)/poroi(wl の 8 リンク合計は
  周長以下なので河岸長を過大評価しない。plan §3.3)。b は乾燥でも冠水でも
  よい(洪水時の冠水河岸)。堤防エッジ(bank_active 時の rw 不一致)は
  河岸侵食も遮断 = 築堤・護岸区間の表現。1 エッジ・1 更新の河岸の低下量は
  fluv_dzmax で頭打ち(流量段階 = 保存則を保つ)。f_fluvial=1 が必須。
  **K_b に既定を置かない**(校正値。文献の標準値がない。合意 §7)。
- **安息角崩落の定式**: 隣接セル間の高さ差 |z_c − z_n| が tanφ_r·dist_k を
  超えた分 excess について、1 更新に relax·excess/2/8 の高さを高い側から
  低い側へ移す(8 方向同時でも合計は relax·excess_max/2 以下 = 行き過ぎ
  なし。relax ≤ 1)。乾湿を問わない。1 更新 1 スイープ(崩落は地形時間で
  1 セルずつ伝播 — 反復コストを避ける。plan §3.3)。x ≤ 0 に向く面
  スロットは 0 に上書き(fluvial の開境界書き込みの残りを消す)。
  fluvial なしでも動く(dzmax・スクラッチ・fdon を init_bank が整える)。
  φ_r の既定は 30°(slide_phi と同じ慣用値。§62)。
- **土砂プロセスの共有設定**(poroi・setup_sd・末尾の sd ハロ)の条件に
  f_repose を加えた(f_berode は f_fluvial 必須なので自動)。
- **検証(2026-10-17。gfortran 13.3 / Open MPI 4.1)**:
  - 無効時: test/bankface・bendsed・fluvial・suspend・wash・creep の出力が
    リファクタ後(bd622ec)とバイト一致(-Ofast)。
  - test/berode(新設。bankface 地形 + f_berode、K_b と 2K_b): Σ(z−z0) =
    4.6e-13 / −6.4e-13、水路に接する河岸 120 セルだけが削れ(接しない
    河岸は厳密に 0)、損失体積の比 1.998(侵食則の線形性)。
  - test/repose(新設。45° の乾いた砂山): Σ(z−z0) = 1.8e-14、終端の最大
    勾配(軸・対角)が tan30° に 1e-7 で収束、頂上 3.00 → 2.08 m。
  - MPI: berode・repose とも np = 2, 4 の state.dat が逐次と一致、
    -fcheck=all np=2 正常(河岸パスの近傍読み・崩落の面スロット書き)。
- **残(段 2)**: K_b の分布ファイル(護岸区間 = 0。plan §3.3 (i))、
  河岸脚部の被覆効果、水中/陸上で安息角を分ける repose_phi_wet、
  幅河道(fn_width)併用時の崩落の面積換算。段 3(定着)は examples/meander
  (段 4 の例題)で「拡幅で止まるか」を見てから。

### 84.5 段 4: 例題 examples/meander・examples/meander_cutoff と所見(2026-10-17)

- **【実バグ】浮遊砂の E-D で土層を使い切ると sd が丸めで負になる**
  (calc_suspend のクランプ fx = sd/(morfac·poroi) と dzb = −fx·morfac·poroi の
  往復で sd + dzb = −1e-22)。負の sd は calc_fluvial の可動層クランプ
  `gq*(sdup/dze)` で流砂の符号を反転させ、その後の FPE(-ffpe-trap)で停止した
  (examples/meander_cutoff の岩盤露出帯で実検出)。修正: suspend 側は
  dzb < −sd のとき dzb = −sd で厳密に 0 に止める、fluvial 側は sdup ≤ 0 を
  「供給なし」(gq = 0)とし、供給量制限の vcap も max(sd, 0) で評価する。
  岩盤露出のないケースは厳密数学でバイト一致(test/suspend・wash)。
- **examples/meander**(正弦波状の初期河道、幅 20 m、振幅 10 m、波長 200 m、
  氾濫原 +1 m、Q = 15 m³/s 一定、morfac 50 で地形時間 100 h。非粘着性
  (f_repose 32°)と粘着性(f_berode K_b = 3e-5・τ*c,b = 0.5 + f_repose 35°)の
  2 構成): 外岸の淵(−1〜−2 m)と内岸の砂州ができ、河岸面は安息角に張り付いて
  1 セル(2 m)後退するが、**蛇行振幅の成長には至らない**(外岸の淵が 2 m 前後で
  平衡し、崩落土砂が脚部を埋めて後退が止まる)。plan §3.3 が予想した
  「拡幅で終わる」状態の実証。分かった限界(README に記録): (1) 階段状の
  乾いた河岸に接するセルの流速が河道中央の 0.6〜0.8 倍で、脚部の τ* を
  駆動力にする側岸侵食則では外岸・内岸の差が出ない、(2) 運動量保存形移流
  (スキーム 2・3)の斜め副格子モード(§68.36)が河床に転写されて 2 セル周期の
  縞になる(例題はスキーム 1 を使う)、(3) 内岸砂州は供給セルの水面までしか
  堆積せず(§84.2)一定流量では陸地にならない、(4) 河岸の凸角セルの局所洗掘、
  (5) 無給砂の河床低下波。試行で踏んだ罠: 上流端の非侵食帯の終端にナック
  ポイント穴が育ち CFL 停止 → 土層厚のランプで岩盤に当てて止める。出口を
  斜めに東辺へ抜くと自由流出面で加速して CFL 停止 → 直線で抜く。
- **examples/meander_cutoff**(正弦波生成曲線 ω = 105° の 2 波長、幅 20 m、
  氾濫原は近傍の河床 +1.6 m、頸部 +0.95 m、安息角 40°、sec_rmax = 0.3、
  dt = 0.1 s、morfac 10。Q = 15 → 40(1 h)→ 15 m³/s): 出水で頸部が越流し、
  ループの付け根を結ぶ新流路が刻まれ、出水後は流れが新流路に集中して旧河道
  (ループ)は滞水域になり、その出入口に堆積が始まる = **頸部短絡と三日月湖化の
  入口まで、特別な処理なしに現れる**(plan §3.5 の方針どおり)。Q = 25 では頸部が
  越流せず短絡しない。試行で踏んだ罠: 氾濫原の高さを「最寄り河道の路長」で
  決めると蛇行度の高い下流の氾濫原が上流の水面より低くなり出水前から溢れる
  → 近傍(半径 24 m)の河床の最大値 + 河岸高で与える。浮遊砂(f_suspend、
  0.2 mm)を併用すると無給砂の河床が懸濁で急速に低下する(給砂濃度を与えても
  平衡濃度に届かない)ため、この例題では掃流砂のみ。鋭い湾曲(R/W = 3)では
  r = N* h κ が h とともに増えて淵が 3 m 以上に育つので sec_rmax = 0.3 で
  偏角を抑える。

### 84.8 段 3b: 定着の植生効果 — 浮遊砂の捕捉と動的粗度(2026-10-17 実装。機能追加)

**動機**(§84.7 末尾): 掃流砂の堆積は供給セルの水面で頭打ちになるので、砂州は
出水ピークの水位より高くならない(緩い減水期でも 0.76 m 対 0.86 m と逆効果)。
実河川で砂州を氾濫原の高さに育てるのは、植生の生えた砂州の上で流れが遅く
なり浮遊砂(細粒分)が沈む垂直堆積である。f_fixation は本ブランチで新設した
機能なので定義を広げた(plan §3.4b。合意 2026-10-17)。

- **浮遊砂の再浮上抑制**(calc_suspend): 浸食項(平衡濃度 ceq)だけを定着度で
  減らし、沈降項 β c は変えない。f_esform = 1 は τ*c,s (1 + c_τ a) で ceq を
  再評価、2(板倉・岸。τ*c を持たない)は ceq/(1 + c_τ a)。同じ c_τ(別の
  係数を置かない)。沈降で上がった z は既存の zref = max(zref, z) で定着面を
  押し上げる。乾燥セルの「浮遊分を全量河床へ」は不変。a = 0 は分岐に入らず
  厳密に不変。f_fixation と f_suspend の併用で自動的に有効(別フラグなし。
  併用する reference はない)。
- **動的粗度**(fix_cn > 0): t_state の柱状量 s%rnv = n (1 + c_n a) を
  geomorph(set_rough。init と update_fixation の末尾、自帯で作ってハロ交換)
  が確保・更新し、m_swflow_enc の calc_kth_flux は allocated(s%rnv) なら
  rne = (rnv_c + rnv_n)/2、未確保なら g%rn(厳密に不変。hb・fx と同じ
  「所有者が確保し利用者は allocated で見る」様式)。流砂の τ*(掃流砂・
  浮遊砂・側岸侵食)は g%rn のまま: 植生の抵抗は形状抵抗で粒子にかかる
  せん断ではない(fluv_taufac の有効掃流力の分離と同じ考え)。流速が落ちる
  分だけ τ* は自然に下がる。a の純関数なので save せず、restore 後は
  init_fixation が復元した a から作り直す(リスタート往復がビット一致する
  条件)。既存の抗力項(p%cd・gv)で表す案は、gv が建物の占有率で貯留体積も
  変えるため不採用。
- **namelist**: fix_cn(既定 0 = 粗度に効かせない)。植生の n の目安は Chow の
  表(草地 0.03〜0.035、低木・樹木の氾濫原 0.05〜0.15)から c_n = 1〜3 だが、
  §19.8 の原則で既定値にはしない。
- **test/fixation に追加**: rough(on + c_n = 2: 出水時の砂州上の流速が on の
  0.50 倍、断面流量は Q_in の ±2 %)、susp_off / susp_on / susp_on2(浮遊砂
  0.2 mm、出水時に inflow_cs = 0.002 で給砂。定着なしは砂州が −1.0 cm、定着
  ありは全セル正味堆積で平均 +3.1 cm(f_esform = 1)、+4.2 cm(2))。

  (state.dat・geomorph_fixation.dat がビット一致)。f_out_vv = 1 を全構成に
  追加(速度の検定用)。
- **検証(2026-10-18)**: 無効時(fix_cn = 0・浮遊砂なし)は test/fluvial・
  suspend・wash・sedinflow・bankface・bendsed・berode・repose・wave・uniflow と

    初期河道内の 547 セルが氾濫原の高さ(+1.0 m)を超える(天端 1.71 m)。狙った
    過程(出水時の堆積 → 露出 → 定着 → 氾濫原に同化)は再現されるが過給砂で、
    上流区間 x < 200 m が 50 h までに +0.5 m 堆積して出水時に氾濫原へ溢れ、
    200 h には避難(avulsion)流路ができる。入口の狭い断面で評価した平衡濃度が
    下流の広がった河道の容量を超えるため。倍率 0.5 では逆に河道が −2〜3 m
    低下して砂州は育たない(定着 944、+1.0 m 超 0)。

    の速さで削られ、給砂濃度のわずかな不足が深い低下になる。中間の倍率で
    釣り合わせるのは粒径 1 種の河床の弱点を給砂で補う調整に過ぎないので、
    例題は倍率 1.0 を「過程は再現できるが過給砂」として記録した(README の
    限界 7)。細粒分の河床への保存(混合層・粒径別の土層)が次の課題で、
    段 5 の残(非平衡二次流)より先に要る可能性がある(handoff)。

### 84.10 段 5c: 河床の細粒分の帳簿 f_bedfines(2026-10-18 実装。機能追加)

設計は meander_plan.md §3.6c(合意済み)。§84.9 末尾の試行で、浮遊砂の浸食が
土層 s%sd をそのまま細粒分として巻き上げるため掃流砂の河床(1 mm)が細粒分
(0.2 mm)の速さで削られ、平衡濃度給砂の倍率に極端に敏感になることが分かった。
一般の混合粒径(交換層 × 粒径階。geomorph_plan.md F4)は §0 に照らして採らず、
既存の 2 成分(掃流砂 1 粒径・浮遊砂 1 粒径)の区別を河床側にも持たせる最小の
帳簿にした。

- **状態**: 細粒分の厚さ `s%sf`(m。0 ≤ sf ≤ sd。帯±ハロ。出力 "Sf")。
  初期値は fines_frac0 × sd(一様割合。分布ファイルは要るときに足す)。私有 save
  geomorph_fines.dat(契約 5。restart_write_cell 1 面)。更新は自帯のみで近傍の
  sf は読まない(ハロ交換なし)。無効時は未確保・呼び出しなし。
- **利用可能率** f = min(1, sf/L_a)(L_a = fines_la。交換層に占める細粒分の割合
  とみなす数値的な混合厚)。
- **浮遊砂 E-D**(calc_suspend): 浸食 E = f·w_f·C_eq、浸食量 ≤ sf(sd のクランプと
  並べて書く。sf = sd なら同じ値 = 厳密に不変)、沈降・乾燥時の全量堆積は sd と
  sf を同じ Δz で増やす(sd − sf 不変)。
- **掃流砂・側岸侵食・崩落・容量給砂**(apply_edge_flux。fluvial と bank が共用):
  ループ 1.5 でセルごとに「流出に占める細粒分の割合」ff を作る: 交換層の組成
  min(1, sf/L_a) から始め、細粒分の流出 ≤ sf、粗粒分の流出 ≤ sd − sf を満たす
  範囲に入れる(流出の総厚 ≤ sd は供給量制限が保証するので区間は空でない)。
  fdon と同様にハロ交換。ループ 2 の z・sd は従来の集計式のまま(q の全量)で、
  **細粒分は掃流砂と一緒に動く**(等移動度): sf は流出 ff_own·q を失い、流入は
  供給側の ff_nb·q を得る。域外(開境界 = 容量給砂)からの流入は受け手(流入
  セル)自身の ff の組成(給砂 = 流入セルが出すものと同じ → 入口の z・sf とも
  固定)。浮遊砂との交換は calc_suspend の E-D だけが担う。台帳 vfree(同伴した
  細粒分。dispose で報告)。無効時は既存の集計式
  `dv8 = dv8 + sign_e(k)*(qk*fd)` をそのまま通る(ビット一致。§84.1 の縮約の
  形を変えない注意と同じ)。
  - **実検出 1(設計の修正)**: 当初案は「掃流砂の浸食で解放された細粒分は
    その場で懸濁(sf → hs)、粗粒分だけが隣接セルに届く」。これは浮遊の容量
    C_eq と無関係に hs を増やすため、掃流砂が通過するだけのセルでも毎更新
    ff·q_b が懸濁 → 滞水域に沈降 → また掃流砂が運ぶ、の空回りで細粒分が
    滞水域へ非物理的な速さで汲み上げられ(台帳 7 万 m³/40 分)、morfac = 50 の
    examples/meander(param_fixsuspfines.txt)で 40 分(地形 33 h)に河道が
    +28 m 埋まって発散した。掃流砂への同伴(等移動度)に改めると安定
    (42 分で hs 最大 0.009 m、z の変化 −1.9〜+0.7 m)。
  - **実検出 2**: 当初案では域外からの流入を粗粒(ff = 0)にしていた。すると
    容量給砂(流入セルの正味流出 = 細粒分込み)が出て行く細粒分の分だけ粗粒を
    入れ、入口が 120 s(地形 1.7 h)で +0.76 m 盛り上がる正帰還になった
    (掃流砂のみ・容量給砂の構成では入口は厳密に固定)。給砂を流入セルの組成で
    入れると入口の z・sf とも固定される(test/bedfines の bfeed 構成)。
- **f_wash**: 浸食率に f を乗じ sf から減らす。**f_splash・f_bedslide**: 粗粒
  扱いで sf ≤ sd のクリップのみ(`allocated(s%sf)` ガード)。f_wthr・inflow_qb は
  sd だけが増えるので無修正。f_debris は f_suspend と排他。
- **namelist**(&list_geomorph): `f_bedfines`(f_suspend 必須)、`fines_la`(必須
  > 0)、`fines_frac0`(0〜1。既定 0)。3 つ。
- **ファイル**: m_geomorph_fines.f90(新規 submodule: init/dispose/save/restore)、
  m_geomorph.f90(t_fines、配線)、m_geomorph_suspend/fluvial/wash/splash/bedslide
  のフック、list_geomorph、m_state(sf)、m_output("Sf")、Makefile。
- **限界**: 鉛直の層序なし(sf は柱の合計。埋没した細粒分も利用可能)。掃流砂への
  同伴は等移動度の仮定(粒径選択性なし)。L_a に弱く依存。粗粒側は 1 粒径のまま。
- **検証**(test/bedfines、2026-10-18): all(細粒 100 %、浮遊砂のみ)は off と
  state.dat がビット一致(sf = sd)。mix(掃流砂+浮遊砂、50 %、L_a = 0.05 m)は
  0 ≤ sf ≤ sd、固体総量 Σhs + (1−λ)Σ(z − z0) = 0、細粒分 Σhs + (1−λ)Σ(sf − sf0)
  = −2e-13、Σ(sf − sf0) = −1.47 m·cell(浮遊砂に出た分)。coarse(0 %)は hs・sf
  が厳密に 0 のまま河床が動く(max|Δz| 1.5 mm)。feed(粗粒水路に細粒分を給砂、
  浮遊砂のみ)は min(z − z0) = 0(河床は削られない)、|sf − (z − z0)| = 3e-13
  (在庫 = 堆積)。bfeed(細粒 50 %、L_a = 10 m で ff = 0.5、掃流砂のみ動く、
  容量給砂)は入口列の |Δz|・|Δsf| = 0(給砂が流入セルの組成で入る)、
  max|Δsf| 3.2 cm。rt1→rt2 は state.dat・geomorph_fines.dat ともビット一致。
  off に Sf 出力なし。無効時は suspend・wash・fluvial・sedinflow・bankface・
  bendsed・berode・repose・fixation・sedfeed・uniflow・splash・splashslide・
  bedslide・avalanche・wave・dambreak が PASS(reference 不変)。厳密フラグの
  逐次と MPI np=2, 4 で 6 構成の state.dat・geomorph_fines.dat がビット一致、
  -fcheck=all の np=2 が 6 構成(feed は 300 s)完走。
- **例題**(examples/meander の param_fixsuspfines.txt = param_fixsuspfeed +
  f_bedfines、粗粒だけの河床、平衡濃度給砂の倍率 0.5): 帳簿なしでは河道が
  −2 m 低下した倍率で、河道は −0.1〜+0.2 m のほぼ平衡に留まり、細粒分が定着
  砂州の上に積もって 200 h で初期河道内の 272 セルが氾濫原の高さ(+1.0 m)を
  超える(天端 1.23 m、定着 1,230 セル)。氾濫原への堆積は 193 セル(帳簿なし・

  給砂濃度の調整なしに出る。砂州が氾濫原の高さに達した上流区間からは 125 h
  以降の出水が薄く氾濫原へ溢れ(5〜10 cm)、最初の湾曲でループが広がる =

### 84.12 係数の文献照合(2026-10-21 実施。§19.8 の原則の適用)

利用者が提供した原著 3 本(Hasegawa 1989、Asahi ら 2013、Struiksma ら 1985)で
段 1〜3 の係数を照合した。

- **γ = √(τ*c/(μs μk τ*))(fluv_slope)**: Hasegawa (1989) J. Hydraul. Eng. 115(6)
  式 (6) が q_n = q_s (v/U0 + tan ψ + T ∂η/∂n)、T = √(τ*c/(μs μk τ*0)) として
  同形(Hasegawa 1981 に帰属。η は下向き変位なので +T ∂η/∂n = −T ∂z/∂n で
  本実装 q⃗ = q_b(t̂ − γ∇z) と符号も一致)。Asahi ら (2013) JGR-ES 118 式 (22) が
  同じ式を Hasegawa (1984) に帰属させ、記法表で **μs = 1.0、μk = 0.45** と
  明記。Hasegawa (1989) 本文(p. 749)は桁の見積りに tan θ_k = μk = 0.7、
  μs = 1.0 を用いる(γ は 0.45 の場合の 1/1.25)。→ 既定 μs = 1.0、μk = 0.45 に
  昇格(Asahi ら = Nays2D 系の慣用値)。μk = 0.7 は代替値として文書に残す。
- **N*(f_secflow = 1)**: Asahi ら (2013) 式 (18) u_b^n = u_b^s N* h/r_s、
  「N* = 7.0 [Engelund, 1974]」と明記。r_s は流速場の流線曲率半径(式 (19))で
  本実装の κ と同じ定義。Struiksma ら (1985) J. Hydraul. Res. 23(1) 式 (12) の
  de Vriend 型係数 A = (2/κ²)(1 − √g/(κC)) は C = 50 m^0.5/s で約 10、C = 30 で
  約 7 と、Engelund の 7 と同じ桁(文献で 7〜10 の幅があるという従来の注記の
  根拠)。→ 既定 N* = 7.0 に昇格。
- **定着時間 T_fix・c_τ(f_fixation)**: Asahi ら (2013) §2.4 式 (33) は
  乾いた継続時間 T_dry が T_Land を超えたセルを氾濫原に編入する(二値。水没で
  T_dry = 0 にリセット、編入後は計算領域から外す = 不侵食)。T_Land は実験
  スケールの設定値(Table 2: 10〜400 s)で、意味を持つのは出水の回帰時間との比
  T_Land/T_return(0.025〜0.5 で蛇行が発達して短絡が頻発、1 では蛇行が
  発達せず網状に近づく。Fig. 23)。本実装の連続的な定着度 a と c_τ はこの
  二値処理の緩和版で、c_τ → ∞ が Asahi らの扱いに相当。**標準値は文献に
  ない**ため既定は置かず必須のまま、選び方(T_fix/T_return の比)を利用者

### 84.13 定着の冠水減衰と河岸専用係数(2026-10-21 実装。機能追加)

**動機**(work/delta_notes.md のデルタ試行): 出水と低水を繰り返す流入でデルタの

乾いている間に累積し、湿潤では凍結されるので、定着で非侵食になった砂州は浸食が

### 84.14 非侵食の供給側を崩落・側岸侵食の台帳に数えない(2026-10-21。等価変換)

**現象**(work/delta_notes.md §2.7。dx = 2.5 m のデルタ): 終了時の警告が
「安息角崩落 1.6e7 m³(bulk)、崩落の dzmax クリップ 96,645 回、側岸侵食 2.99e4 m³」と
出た。dx = 5 m の同じ設定では崩落 1.5e4 m³・クリップ 0 回で、千倍の差。
最終地形を調べると、安息角を超えるエッジ 1,531 本はすべて高い側が非侵食の陸地
(sd = 0。河道の両岸 +1.5 m と河床 −1.0 m の段差 2.5 m が、dx 2.5 の限界 1.44 m を
超える。dx 5 の限界 2.89 m は超えない)で、クリップ級の段差(> 3.04 m)は河口の陸地の
角の 1〜2 エッジが毎更新で数えられていた(96,645 ≈ 1.3 本 × 72,000 更新)。

**原因**: calc_repose と bank_edge_pass は、供給側(崩落の高い側・河岸セル b)が
非侵食(sd <= 0)でも流束を計算して台帳(nrep・nrclip・vrep、nbank・nbclip・vbank)に
数え、流束は後段の供給量制限(apply_edge_flux の fdon = 0)で 0 になっていた。
結果(z・sd)は正しいが、警告の体積・回数は「仮想の崩落・侵食」を含む。非侵食の壁が
安息角より急な地形(岩盤の谷壁、非侵食で与えた堤防・陸地)では桁違いに過大になり、
dx を細かくするほど壁の段差が限界を超えやすいので解像度依存に見える。

**処方**: 供給側の sd <= 0 なら最初から飛ばす(流束 0、台帳に数えない)。供給量制限が
fdon = 0 で同じ流束にしていたので状態はビット一致(等価変換)。供給量制限の発動回数
(nlim)も仮想分だけ減る。

**検証**: test/repose・berode(kb1・kb2・fix0・fix1)・bendsed・fixation(全構成)の
save(state.dat・geomorph_fixation.dat の 35 面)が変更前の実行とバイト一致、検定は
すべて PASS。MPI は np = 2, 4 が逐次とバイト一致、-fcheck=all の np = 1, 2 も
境界違反なし(§84.13 の検証と同じ実行)。dx 2.5 のデルタの短縮版(水理 30 分)で state.dat・Z がバイト一致し、
台帳は「崩落 5.46e5 m³・クリップ 324 回、側岸侵食 3,210 m³」→「崩落 0・クリップ 0、
側岸侵食 0」(最初の 100 h の分はすべて仮想だった)、供給量制限 1.34e6 → 1.55e4 回。

**影響**: 2026-10-21 以前の実行で警告に出た崩落・側岸侵食の体積は、非侵食セルに
接する急な段差がある地形では過大。work/delta の定着ケース(delta_fix3)の「側岸侵食
2.99e4 m³」も河道の陸地の壁の仮想分を含む(再計算で確認する)。

### 84.15 波浪による沿岸漂砂 f_wave_longshore(2026-10-22 実装。機能追加。段 1 = wave_plan.md 案 A)

**動機**: デルタの試行(§85、docs/delta_plan.md)でケース単体は鳥趾状、平均は扇状にしか
ならず、弧状・カスプ状を作る沿岸漂砂(波浪卓越型デルタの機構。Nienhuis ら 2015 の
R = Q_r/Q_w)が無かった。設計の比較と不採用案は docs/wave_plan.md §2(放射応力の
沿岸流 = 案 C は波の伝播計算が要るため採らず、方針 §0 の「SWE+1 方程式拡散」の内側で
土砂の過程として与える)。合意(2026-10-22): 時計はスイッチ `wave_clock` で既定 = 地形
時間、段 1(案 A)→ 段 2(案 B 攪拌)→ 段 3(遮蔽)、K₂・γ は文献値を既定に。

**決定・定式**(src/m_geomorph_wave.f90 ヘッダが正本):
- 有効化は `fn_wave`(&list_wave。src/list_wave.f90)。掃流砂の経路に乗るため f_fluvial = 1
  が必須(f_berode と同じ契約)。無効時は配列未確保・呼び出しなし。状態なし(与件と
  地形から毎回作る = save/restore 不要、save_version 不変)。
- 与件: 沖の有義波高 H₀・周期 T・進行方向 φ₀(x 軸から反時計回り。北 = 90°。格子の
  (i, j) 成分は (cos φ₀, −sin φ₀))。固定値または時系列(wave_val。線形補間、端値保持。
  H₀ = 0 は凪)。時系列の時刻は wave_clock = 1 で s%t × morfac(地形時間。波候)、
  0 で s%t(水理時間。嵐)。
- 砕波: H_b = 0.39 g^{1/5} (T H₀²)^{2/5}(Komar & Gaughan 1972)、h_b = H_b/γ(γ = 0.78)。
  砕波帯 = 湿潤で h ≤ h_b の非海域セル。
- 汀線方位: 水深をガウス核(半径 wave_smooth = 1 または 2 セル = ハロ幅の内側。乾いた
  セル・域外は深さ 0。全域の外は核から除く)で平滑化し、中央差分(全域端は片側差分)の
  勾配 ∇h_s の向きを沖向き法線 n̂ とする(ベクトルの汀線を持たない = ラスタ純化)。
  |∇h_s| < wave_smin の平坦部は対象外。
- 露出度(遮蔽の簡易版): 砕波帯より深い湿潤セルを源(1)に、波の風上(−d を 8 方向に
  量子化)の前回値を写す Jacobi 更新 + ハロ交換(1 更新 1 セル伝播。乾いたセルで 0。
  風上が全域の外なら 1 = 開境界の沖、域外マスク x ≤ 0 なら 0 = 陸の陰)。
  掃引順に依らずランク数不変。デルタの陰・入り江・河道内部に波が入らない。回折なし。
- 流束: α を d と岸向き法線 −n̂ のなす角(cos α = −d·n̂、sin α = d·t̂、t̂ = n̂ を +90° 回す)
  として、沖波で書いた CERC 式 Q_s = K₂ H₀^{12/5} T^{1/5} cos^{6/5}α sin α(Ashton & Murray
  2006 式 (2)。K₂ = 0.34 m^{3/5} s^{−6/5}。かさ体積)。cos α ≤ 0(岸から離れる波)は 0。
  単位岸沖幅の固体流束 q = Q_s / W_b / poroi、W_b = max(h_b/|∇h_s|, Δx)。q⃗ = q t̂ を
  両セル平均で ê_k に射影し通過幅を掛けてエッジ流量(掃流砂の dirp と同形)。規則は
  §84.2 R1・R2(供給側が乾いていれば 0、受け手の地盤が供給側の水面以上なら 0 = 乾いた
  浜の後退は安息角崩落の担当)、堤防エッジ遮断、河道幅の係数 frw・fwd。定着の τ*c は
  効かせない(砕波帯は常時湿潤で a = 0)。`gm%wrk%q` を全成分上書きして apply_edge_flux
  (供給量制限・dzmax・保存則)。calc_fluvial の後・calc_repose の前(z・sd のハロを先に
  最新化)。
- MPI: 平滑化・露出度・流束ベクトルは自帯で計算して 4 面のハロ交換、エッジ流束は
  calc_repose と同じ 2 ループ(書き手一意、je+1 行の冗長計算)。collective なし。
  呼び出し前に z・sd に加えて **h のハロも最新化する**: 時間ループ中の h のハロは
  ±1 行しか現ステップの値でなく、平滑化は ±wave_smooth(≤ 2)行を読む(bedslide の
  プランジと同じ扱い)。
- 台帳: エッジを通った固体体積(粗流量)と砕波帯セルの延べ数を dispose で表示。

**検証**(test/wave_shore。2026-10-22):

**段 3 (b) 水没砂州の部分遮蔽 f_wave_shadow(2026-10-22〜23 追加。機能追加。合意 = 案 C)**。
露出度を 0/1 から「透過率 f ∈ [0, 1]」に拡張する。砕波帯より深い湿潤セルは f = 1(源)、
乾燥・河川流のセルは 0 はそのまま。砕波帯のセルは風上の f を受け取り、**岸側の隣が自セルより
深ければ (h/h_岸側)^{5/2} を掛けて伝える**(そのセルを通った波は γh まで。浅水のエネルギー
流束 ∝ H^{5/2})。単調に浅くなる浜では因子が 1 = 従来と同じ(無効時とビット一致)。砂州を
越えると因子の積が (h_天端/h_トラフ)^{5/2} に縮約して岸側の列全体(内側の浜も)に効き、複数の
砂州は積で重なる。流束は q f。一線モデルの離岸堤の透過率 K_t の扱いに相当する。
- 設計の経緯: 最初は「砕波帯のセルを通るたび f = min(f, h/h_b)、流束を r^{5/2}(r = min(1,
  f h_b/h))で減らす」飽和型にしたが、天端 h_c より浅い内側の浜は飽和した砕波帯のまま
  (r = 1)で効果が外側の帯に限られ、離岸堤の例で 1 次元見積りの 1/10(陰の堆積 +28 m³)しか
  出なかった。原因は段 1 の「流束を砕波帯の幅に一様に配る」仮定との不整合(散逸に比例する
  配分なら内側の分は (h_c/h_b)^{5/2} = 2.6 % で、同じ遮蔽が 10 倍効く)。散逸配分は岸沖断面の
  平行移動を崩し断面維持の岸沖輸送が要るので採らず(案 B)、一線式に「陰の列全体を透過率で
  減らす」案 C を採用した。峰の判定を平滑化水深 h_s としきい値(h_b の 5 %)で行う版は、
  σ = 2Δx の平滑化が幅 10 m の砂州を 0.2 → 0.33 m にならして段差がしきい値を下回り、
  何も検出しなかった。生の h の段差に因子を掛けるしきい値なしの形に変えて解決。
- 検証(test/wave_shore bar / bar0。直線汀線の沖 25 m に非侵食の水没砂州 = 離岸堤、長さ

  (4.3 倍)、風下 100 m の侵食 294 対 115 m³(2.6 倍)、風上の堆積 266 対 123 m³。回折が無い
  ので砂は陰の中央でなく風上側の縁に溜まる = 回折なしの一線モデルの離岸堤と同じ型。
  可動の砂州では天端が削れて陰が消えるため非侵食にした。
- 線形理論への影響: 低角は 1.05 → 0.99 倍(無効時とバイト一致はしない: セル規模の段差が
  弱い因子を与える)。高角は 0.86 → 0.64 倍で、成長が 2.5 h 以降に鈍り 33 m の成分が出る。

- 限界: 回折なし(陰の中央に砂が入らない)、風上の 8 方向量子化(陰の柱が波向きに傾かない)、
  砕波帯より深いトラフは源に戻る(砂州の陰が砕波帯の中に収まるときだけ効く)、因子は格子の
  水深段差によるのでセル規模の凹凸も弱く遮蔽する(局所勾配項 β が凹凸を均すので実害は
  小さい)。

### 84.16 湿潤侵食の剥離深の横方向拡散 wet_lw(2026-10-22 実装。機能追加)

**現象**(docs/splash_plan.md §6.8〜6.9。examples/badland_storm 結果 4): 表面流の
面状侵食(f_wash の kf 項)と巻き上げ(f_suspend)はどちらもセル値の τ* に比例し、
流れが 1 セル幅に集まるとそのセルだけが削れてさらに水を集める。この正帰還に
長さスケールがないため、初回の豪雨で 1 セル幅・深さ 3.5〜5 m(Δx に依らない)の
溝が刻まれ、ガリー間隔が 7.8 → 5.6 → 3.7 m(Δx = 2 → 1 → 0.5 m)と格子に
追随して収束しない(乾式の κ の無限波数問題 §48.3 と同じ構造)。安息角崩落
(f_repose)は壁の勾配を揃えるが、幅 = 2·深さ/tanφ が浅い段階で Δx を下回る
ため間隔を決めない(7.8 → 6.1 → 4.9 m)。

**方式**: 各セルで評価した剥離深 e_j(calc_suspend の巻き上げ fx > 0 と calc_wash の
剥離。源セルの可動層クランプ済み、hs は源セルに注入済み)を集積面 gm%wlw%e に
積み、ステップ末尾の spread_wet が spl_lc と同じ 5 点ガウス核(N = 4(ℓ_w/Δmin)²
パス、w ≤ 1/8)で平滑化してから各セルの z・sd から引く(gather 形
Δz_i = −Σ_j K_ij e_j)。沈降(fx < 0)と乾燥セルの繰り入れは従来どおり局所。
「流路の流れは幅 ℓ_w の帯(リル幅)から削り、岸は流路へ崩れ落ちる」の表現で、
ℓ_w は流量に依らない固定幅の近似(Q 依存の幅は第 2 段。splash_plan §6.9)。
- 保存: 核は対称、無効な近傍(範囲外・x = 0・海セル)は自セル値で鏡像 = その
  方向の移動なし、なので Σ_i Δz_i = −Σ_j e_j(test/wetlw で 0.000e+00)。受け側の
  sd が足りない分は岩盤露出として捨て、台帳 vlost に積んで dispose で報告する
  (0 なら厳密保存)。
- MPI: 集積は帯内のみなので最初に e のハロを交換し、各パスの後にも交換する
  (smooth_z と同じ)。パス数は namelist 由来で全ランク同一 = collective 安全。
  gather 形を選んだのは、scatter 形だと逆向きのハロ加算が要るため。
  test/wetlw で np = 2, 4 の state.dat が逐次とバイト一致。
- 無効時(wet_lw = 0): 作業配列を確保せず、calc_suspend・calc_wash の分岐
  (`spread`)に入らない。test/wash・test/suspend の state.dat と
  examples/badland_storm(Δx = 2 m、2 周期)の Z・H が変更前とバイト一致。
- OpenMP: 平滑化は smooth_z と同じ行並列。適用ループの台帳は局所変数で
  reduction(派生型成分は reduction 変数にできない)。
- f_suspend が必須(init_wetlw が検証。剥離を集積するのは suspend と wash)。
  河道セル(rw > 0)も配分の対象に含める(σ 断面の Δz は平面積平均のまま)。

**検証**: test/wetlw(構成 0 = test/wash と同一、構成 l = wet_lw 3 m): 両構成で
固体総量の保存・共動更新恒等(Check_suspend.py)、構成 l で侵食深の格子規模の
凹凸(5 点ラプラシアンの 2 乗和)が構成 0 の半分以下・最大侵食深が小さい・
総侵食量の比が 0.5〜2。examples/badland_storm 結果 5(ℓ_w = 2 m、Δx = 2 / 1 /
0.5 m): 密なガリー網は消えて一様に後退する緩斜面になり、Δx = 1 と 0.5 m で
起伏・平均低下・最大下刻・谷頭が 10〜20 % 以内で一致(格子追随が止まる)。
ℓ_w/Δx ≥ 2 が要る(Δx = 2 m は核が解像されず別の結果)。

### 84.17 段 2b: 崩落土塊による河岸の自己保護 — f_rockfall の河岸モード(2026-10-23 実装。機能追加)

**動機**: main に入った崩落と崖錐 f_rockfall(§48.7)は「落差が限界高さ H_c を
超えた分が崩れ、落下物が崖錐 ht として脚部を覆い、崖錐の除去が後退を律する」
枠組みを持ち、Asahi ら (2013) §2.3 / Parker ら (2011) の slump block(崩落土塊が
脚部を覆い、流れが運び去るまで河岸侵食を止める)と同型である。段 2 の残
「河岸脚部の被覆効果」(meander_plan §3.3)をこの枠組みで実現する。乾式侵食
(f_splash)向けの律速を流水に置き換える結合だけを足し、新しい状態量は持たない。

**設計**(docs/meander_plan.md §3.3b):
- `rf_bank = 1`(list_geomorph。既定 0 = 従来とビット一致): (a) calc_rockfall で
  供給側の地盤が受け手の水面(z + h)より低いエッジ(水面下の段 = 淵の壁)は崩落の
  対象外。河岸面(受け手の水面より高い段)と乾いた段(h = 0)だけが崩れる。
  落差そのもの(z_b − z_w。水面からではない)で H_c を判定するので、淵の洗掘で
  河岸が高くなると崩れる = 粘着性河岸の限界高さの古典形。(b) apply_edge_flux の
  ループ 2 で、calc_rockfall 自身の適用(gm%rf%own)以外のときは、セルの総流出
  (風上の fdon を乗じた正のエッジ流量の和 vo8)の厚さ分だけ崖錐 ht を先に減らす
  (0 でクランプ。流入は崖錐にしない)= 掃流砂・側岸侵食・安息角崩落による土塊の
  搬出。(c) f_fixation があれば供給側の定着度で限界高さを H_c (1 + c_τ,b a)
  (c_τ,b = fix_ctau_bank。§84.13)に上げる。窓版 (1')・段差版 (1) の両方に効く
  (柱の崩落 (1'') の開始判定 face_start は従来の H_c のまま)。
- `berode_hcover`(m。既定 0 = なし。rf_bank = 1 が前提): bank_edge_pass の脚部
  τ* に (1 − ht(iw,jw)/h_cover)⁺ を乗じる。Asahi ら式 (27)〜(28) の armoring
  coefficient K = 1 − A_chunk/(D_chunk B*) の格子版(崖錐の厚さ/土塊の大きさ = 被覆率)。
- 不採用・先送り: 張り出し rf_uc の流水版(脚部の洗掘量 u を fluvial で積む)は、
  H_c の超過が淵の洗掘で自然に起きるため最初の版では入れない。崖錐を安息角崩落
  f_repose が動かしたときの ht の追随(崖錐の「流入」)もしない = 崖錐は搬出で減る
  だけ(ht ≤ 実際の堆積厚を保つ側の近似)。浮遊砂・面状侵食による搬出も数えない
  (土塊は粗い)。
- 無効時ゼロ追加: rf_bank = 0 では apply_edge_flux の分岐 have_ht が偽で既存の式
  のまま、bank_edge_pass は hcover = 0 で乗算なし。

計算は gfortran 13.3(-Ofast -march=native)・1 スレッドで 4 ケースを同時に流した。再計算の途中で
コンテナが再起動して CPU が変わり、-march=native の旧実行ファイルが不正命令(SIGILL)で止まったので、
ビルドし直して全構成を回し直した。もう一度の再起動(同じ CPU 型・同じ命令セット。ターンの間に走って
いる処理がないとコンテナが回収される)で止まった 4 構成は同じ実行ファイルで回し直し、止まる前と最初の
出力(水深・流速・河床)がビット一致することを確かめた。新しい CPU での計算時間は旧 CPU の 1.3〜1.5 倍
程度(README の計算時間の目安は新しい CPU の値)。図は matplotlib(Python 3)。

### 84.19 一般の混合粒径を範囲を限って採る(2026-11-22 合意。方針 6 の例外)

§84.10 で「一般の混合粒径(Hirano 型の交換層 × 粒径階)は方針 6『過度に複雑化しない』に反するので
採らない」と決め、mountain_stream_plan.md §6.2 は「必要になったら、実装の前に方針 4・6 の扱いを議論する」と
していた。その議論を行い、範囲を限って採ることにした。設計の正本は docs/mixed_sediment_plan.md、未完了の
作業は handoff 00ad。

- **きっかけ**: 河道の発達を実測と比べる候補として、国総研の常願寺川 1/100 移動床実験(小橋ら 2026、
  河川技術論文集 32。セグメント 1 の二極化)の公開データを評価した。境界条件(毎秒の流量・粒径集団 3 個の
  給砂)と全面の計測(各通水後の河床高・水位・流速・表層粒度)が揃い、給砂の積算は論文の図 3 と一致した。
  一方、中小出水の給砂の 94〜97 % が 0.57 mm の砂で、平均年最大流量程度の流れでは 3 mm が限界付近、
  6.6 mm がほぼ限界以下になる(ほぼ動かない礫の上を砂が流れる)。代表粒径 1 個では 3 mm でも 0.57 mm でも
  外れる見込みで、論文の主題の二極化(大粒径で静的に安定した側岸が拡幅を抑える)も単一粒径では表せない。
- **判断**: 砂礫の河床の分級とアーマー化は、給砂の変化への応答で結果を一次で左右する(単一粒径では
  アーマー化で早く止まる河床低下を過大に見積もる)。これは精緻化ではなく、概算(方針 4)の一次の効果と
  判断した。交換層 1 枚と一様な下層 1 枚は方針 5 の鉛直の抽象化の範囲に収まり(2 層地下水と同じ考え方)、
  河床材料の粒度は河床材料調査で普通に得られる(方針 6 の「入手可能な情報に合わせて精緻化」)。
- **比べた案**: A 現状維持(単一粒径 + 細粒分の帳簿。例題は限界を示すものになる)、B 砂・礫の 2 分画
  (細粒分の帳簿を掃流でも選択的に動く砂に広げ、砂分で礫の動きやすさが変わる式 Wilcock & Kenworthy 2002 を
  使う)、C 一般の粒径階(範囲を限定)。B はアーマー化に表層と下層の区別が要り、費用の大部分(交換層と
  下層、ほかの過程との組み合わせ、検定、文書)が C と共通なので、粒径階のループを足す分だけの差で応用の
  広い C を採った。礫の中の分級(国総研の 3 mm と 6.6 mm の違い)や下流細粒化は B では表せない。
- **範囲**(方針 6 の例外の条件。policy.md): (1) 鉛直の層序を持たない、(2) 粒径別の流砂量式と遮蔽係数は
  文献の式(既定は芦田・道上 1972 の式 (31) 修正 Egiazaroff と式 (32))、(3) 浮遊砂は 1 粒径のまま、
  (4) 掃流砂以外の過程で動く土砂は組成を保ったまま運ぶか併用を止める、(5) 有効化しなければゼロ追加・
  無効時ビット一致。
- **利用者の条件**: 「有効化しない場合にコストがほとんど増加しないこと」。既存の掃流砂のループに分岐を
  入れず、calc_fluvial の先頭で混合粒径の写しへ分ける(波浪場の掃流砂 calc_fluvial_wfsed と同じ形。
  実行されない分岐でも -Ofast の最終桁が動いた §90.4 の教訓)。無効時は新しい配列の確保・呼び出し・
  ハロ交換がなく、増えるのは手続きの先頭の整数の判定だけ。全 reference の不変と、掃流砂の検定・例題の
  計算時間の比較で確かめる。残るのは開発のコスト(ループ 1 の写しが 3 つになる)で、ヘッダの注と検定
  (無効時の reference、全粒径階を同じ粒径にした極限)で取りこぼしを見つける。
- **既知の危険**: Hirano 型の交換層モデルの悪設定(細かい下層へ掘り込む条件などで双曲型でなくなる。
  Ribberink 1987、Stecca ら 2014、Chavarrías ら 2018)と交換層厚への感度。段 1 は兆候の診断と文書化まで。
- **時期**: 実装は、土砂関係で進行中の作業(handoff 00j。m_geomorph・list_geomorph に触れている)を main に
  取り込んだ後に段 1 から始める。段 0(2026-11-22)は文書だけ: 方針 6 の例外(日英)、本小節、設計文書、
  handoff 00ad、geomorph_plan.md の F4・meander_plan.md §3.6c・mountain_stream_plan.md §6.2 の注。
- **記録として残す記述**: §84.10・§89.1 の 10・§19 の芦田・道上の原典照合にある「採らない」は、それぞれの
  時点の判断の記録として残す(本小節が改める)。comparison.md の「混合粒径は採らない」(山地渓流の行)は
  いまの機能の記述として正しいので、実装の段で書き換える。
