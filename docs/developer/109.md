## 109. 秩父のデータの河道マスクを、標高の落水線に載せ直す(2026-11-13。利用者の指摘と決定)

### 109.1 経緯と決定

既定 f_dry_head_cap を 2 にする準備で test/chichibu の新旧を比べたとき(§108.8)、利用者が「ファイルの
河道セルが、落水線から求めた河道セルと一致しない」ことを指摘した。調べると、河道マスク(国土数値情報の
河川から作られた河道位数データをラスタにしたもの)のセルの 36〜43 % が、標高の落水線から外れた谷壁の
セルだった(§109.3 の表。50・100・200・500 m のどのデータも同じ)。外れたセルは、河道の粗度
(rn0_rw = 0.02)が付いた谷壁のセルで、流下先のセルより中央値で 12〜29 m 高い。逆に、落水線の上で
マスクが切れているセルは斜面の粗度(0.15)になる。利用者ガイドの geoinfo.md は、河道マスクを「河川
中心線を GIS でラスタ化して作る」ことを勧めていて、このずれは、その作り方で線が標高の谷線と 1 セル
ずれる所に出る。

既定 1 と 2 の差の原因ではなかった(マスクを載せ直しても差は同じ大きさで残る。§108.8)。マスクを直す
こと自体の効きは、既定の切り替えより大きい(§109.4)。

利用者の提案(examples/source_area のように、落水線から作ったマスクをファイルに保存して test・tutorials も
それを使う)と決定(2026-11-13): **河道マスクは、全ての解像度で落水線ベースにする。元のファイルは残す。**

| 作り方の案 | 内容 | 判定 |
|---|---|---|
| A(source_area の方式) | 元のマスクのセルを残し、切れ目だけを落水線でつなぐ | 不採用。谷壁のセルが残る(100 m で 3,596 セル) |
| **B(採用)** | 元のマスクの各セルから落水線を終点までたどり、通ったセルだけを河道にする | 元のマスクが示す河道の範囲を保ったまま、谷線に載る |
| C | 落水線の集水面積のしきい値だけで河道を決める(元のマスクを使わない) | 不採用。しきい値を決める根拠が要り、地図の河道の範囲と合わなくなる(100 m で元と同じセル数になるしきい値は 16 セル = 0.16 km²) |

### 109.2 作り方(utils/river_flowline)

- 落水線は、8 近傍の最急勾配(D8。O'Callaghan & Mark 1984)。自分より低い隣がないセル(窪地処理の平坦面)は
  Priority-Flood(Barnes ら 2014)の取り出し順で流下先を決める。examples/source_area の make_catchment.py と
  同じ手続きで、流出先を「領域の最低点 1 つ」でなく「領域の縁のセル」にした点だけが違う(複数の流出先を
  持つ領域でも使える。秩父のデータでは終点は 1 セルで、結果は出口の 1 セルを除いて同じ)。
- 元の河道マスクの各セルから落水線をたどり、通ったセルを河道にする。出発したセル自身は、ほかの河道
  セルからの落水線が通るときだけ河道になる(各河道の最上流の 1 セルは外れる)。
- 平坦面の中で元のマスクのセルを先に取り出す工夫は、試したが入れていない(100 m で、元のマスクと共通の
  セルが 5,985 → 6,000 に増えるだけ)。
- 前処理の道具として utils/river_flowline に置いた(Python と numpy のスクリプト。方針 12「前処理は utils・
  GIS 側に置く」。計算本体の外なので、方針 10 の「Fortran のみ」の対象ではない)。計算本体は変えていない。
  utils のほかの道具は libencflow.a をリンクする Fortran のプログラムで、Python はこれだけ(テキストの
  ラスタだけを読み書きする。bil・GeoTIFF は扱わない)。Fortran に書き直すか、置き場所を変えるかは
  決めていない(handoff 00v)。→ 2026-11-14 に、利用者の決定で Fortran に書き換えた(§109.10。bil・GeoTIFF も
  読み書きする)。

### 109.10 道具を Fortran に書き換える(2026-11-14。利用者の決定)

**決定**: 利用者「utils/river_flowlineはFortranに書き換えて」(2026-11-14。handoff 00v (d) の判断待ちへの答え)。
Python のスクリプト river_flowline.py を外し、Fortran のプログラム utils/river_flowline/river_flowline.f90 に
した(置き場所は変えない)。計算本体は変えていない。マスクのファイルも変えていない(下の検証)。

**形**(utils/lu2mask と同じ流儀):

- `river_flowline parameterfile zfile maskfile riverfile outfile [accfile]`。libencflow.a をリンクし、
  パラメータファイルの `f_input_mode` と `&list_geoinfo` の nx・ny を本体と同じ解釈で読む(m_sysparam_init・
  list_geoinfo_read)。ラスタは本体の fileio_read_matrix で読む(テキスト・bil・GeoTIFF。領域マスクと河道マスクは
  整数、標高は実数)。Python 版はテキストだけで、格子数をファイルから数えていた。引数にパラメータファイルが
  増えた(`--acc ACC` は 6 番目の引数になった)。
- 格子数と地理参照は、元の河道マスクのファイル(bil の hdr・GeoTIFF のタグ)から補う(lu2mask の probe_grid と
  同じ手続きの写し)。出力の hdr・GeoTIFF のタグに引き継ぐ。
- テキストの出力だけは、fileio の text 形式(`i8` で桁をそろえる)でなく、1 行分の値を空白 1 つで区切って
  書く(`(*(i0,:,1x))`)。Python 版の np.savetxt(fmt="%d") と同じ並びで、置いてあるマスクとバイト一致する
  (大きさは 1/4)。本体の読み込みは並び指定なので、どちらも読める。

**手続きを同じ結果にするために合わせた点**(Python 版と 1 セルも違わないことが要件):

- Priority-Flood の取り出し順: Python 版は heapq に (水位, 通し番号, 行, 列) を入れ、同じ水位は先に入れた順に
  出る。Fortran 版は、自前の 2 分ヒープ(配列)で (水位, 通し番号) の辞書式の最小を取り出す。キーが一意なので、
  ヒープの内部の並びによらず同じ順になる。通し番号は、縁のセルを行優先(北から南、西から東)で 0 から振り、
  以後は入れた順(8 近傍は北西から東へ・行ごと)。
- D8: 8 近傍を同じ順で見て、勾配 (zfill 自分 − zfill 隣) ÷ 距離(1・√2)が「これまでの最大より大きい」ときだけ
  置き換える(同じ勾配は先の隣)。勾配は溢れる高さ zfill で測る。
- 無限大を使わない。Python 版は領域外を np.inf にして isfinite で外していた。-Ofast(-ffinite-math-only)の
  下では無限大の判定が保証されないので、領域の論理配列で分ける。
- 集水面積の処理順: Python 版は取り出した順を (zfill, 取り出し順) で並べ替えてから逆にたどる。取り出す水位は
  単調に上がるので、この並べ替えは何も変えない。Fortran 版は取り出した順をそのまま使い、単調でなければ
  止まる検査を入れた。
- 勾配の割り算は、-Ofast だと逆数の掛け算に置き換わることがある(最終桁が変わりうる)。流下先が変わるのは、
  軸の隣の落差と、斜めの隣の落差 ÷ √2 が最終桁まで一致するときだけで、同じ種類の隣どうしは同じ演算なので
  変わらない。下の検証では 1 件も出ていない。
- 表示の「外したセルが流下先より高い分の中央値」は、流下先のないセル(終点)を数えない。Python 版は終点の
  セルで配列の末尾(最後の行・列)の標高を引いていた(表示だけの不備。秩父のデータには該当するセルがなく、
  値は同じ)。

**検証**(gfortran 13.3。既定の倍精度の release ビルド):

- 秩父の 4 つの格子(50・100・200・500 m)で、載せ直したマスクと集水面積のファイルが、Python 版の出力と
  バイト一致し、置いてある `…_river_flowline.txt` ともバイト一致する。表示の数(領域・低い隣のないセル・終点・
  元と載せ直し後・載っていた・外した(中央値)・足した)も同じ。

  バイト一致。hdr は fileio の書き方になる(置いてある hdr は元の河道マスクの hdr の写しで、PIXELTYPE の
  表記(INTEGER / SIGNEDINT)と座標の桁数(fileio は小数 12 桁)が違う)。GeoTIFF: 出力の画素が、置いてある tif・txt と全て同じ(Python の PIL で
  読んで比較。集水面積も Python 版と同じ)。位置のタグ(ModelPixelScale・ModelTiepoint)は元と同じで、
  GeoKey は fileio の書き方(EPSG:4326)。
- 乱数の地形とマスク 420 件(3〜69 × 3〜49 セル。整数の標高 = 同じ高さが多い、斜面 + 雑音、窪地だらけ、
  広い平坦面と段、V 字谷、桁の多い実数。領域マスクはなし・穴あき(85 %)・楕円・まばら(50 %)。河道マスクは 2〜40 %)で、
