「全て推奨で進めてください」)による。添付の例題案 coastal_salinity_recovery(一時的な海水の氾濫 → 浸透 →
排水 → 帯水層の塩水 → 涵養と揚水による回復)が挙げた不足 = 塩水の収支の台帳がない・排水ポンプや

### 140.1 塩水の台帳 salt.csv

- **目的**: 塩水(体積)がどこから入り、どこへ出て、どれだけが整合クランプで消えたかを、記録間隔ごとに
  書く。これまで塩水の体積の増減は Hss・Hgs の分布からしか読めず、クランプで消えた量は見えなかった。
- **持ち方**(水質の台帳 §30.9 と同じ形): 系外との出入りは、書き手が行部分和の記録場 `s%hssx(js:je, 1:8)` に
  積み、m_saltwater_calc がステップの頭で累積 `vrow(js:je, 1:14)` へ移してゼロに戻す。モジュールの中の
  過程(配分・クランプ・海側境界)は vrow へ直接積む。総和は par_sum_rows(決定的)。
  - 輸送カーネル advect_scalar: 記録場が 7 列以上あれば、海セルから入った量を列 7 に分ける(水質の csea と
    同じ列。海セルが量を持つ塩水層は常に入る。7 列未満の浮遊砂の記録場は従来どおり列 1 に符号つき)。
    水質は、海から入る水の濃度が 0 のとき入る量が 0 なので、列の振り分けを変えても値は変わらない。
  - 水位規定セルの置き直し stage_scalar_reset: 列 4・5。
  - boundary_h: 構造物・吸い込みが系外へ運んだ量(列 6。f_salt_struct >= 1)。
  - m_gwflow_pump: 井戸が汲んだ地下の塩水(列 8)。
- **体積の基底**: 地表 = Σ hss × gv × wfrac × A(hss は水深 h と同じ基底)。地下 = Σ hgs × A(Log の S_grnd と
  同じ、セル面積の柱状量)。浸透・湧出の配分は、水の受け渡しと同じ換算(浸透は af/gv、湧出は 1/wfrac。§26)で
  地下の量を増減するので、家屋の空隙率 gv < 1 のセルでは地表の側と地下の側の体積が gv の分だけずれる
  (水そのものの受け渡しにある妥協と同じ)。台帳は、配分の量を地表の側の体積で数え(infil・seep)、地下の側の
  増減との差を gvadj に積む。gv = 1 なら 0 で、地表・地下のそれぞれの収支が丸めの範囲で閉じる。
- **整合クランプ**: 地表(hss > h → h)で消えた体積を lost_surf、地下(hgs > hg → hg、hgs < 0 → 0)で変えた
  体積を lost_gw に積む(負値の切り上げは負の損失)。
- **井戸が汲んだ塩水の数え方**: 井戸(m_gwflow_pump)は、側方流が合計の貯留 hg を動かした後、塩水の輸送
  (m_saltwater の (3))の前に汲む。汲む時点では、そのステップの側方流で入った水が淡水か塩水かが決まって
  いないので、淡水優先の規則(淡水の厚さ hg − hgs で足りない分だけ塩水を減らす)は、入った水を淡水と数える。
  帯水層が塩水だけのとき、汲んだ水は淡水として引かれ、その後に入った塩水が hg を超えて整合クランプに掛かる。
  状態(hgs = hg)は正しいが、台帳では揚水ではなく lost_gw に入ってしまう(検定 gwsea で、井戸が汲んだ
  0.192 m³ が lost_gw に出て、out_pump が 1e-5 m³ だったことで気づいた)。そこで、井戸が「汲んだ時点で淡水と
  数えた分」を記録場 s%gwpf(セルごと。f_salt_gw = 1 のとき m_saltwater_init が確保)に積み、(3) の整合
  クランプが、hg を超えた hgs のうちその分までを out_pump に、残りを lost_gw に数えてゼロに戻す。状態の
  変え方は同じで、変わるのは台帳の振り分けだけ。
- **列**: time_s, vol_surf_m3, vol_gw_m3, in_sea_m3, out_sea_m3, in_edge_m3, out_edge_m3, out_stage_m3,
  infil_m3, seep_m3, in_sea_gw_m3, out_sea_gw_m3, out_pump_m3, out_struct_m3, lost_surf_m3, lost_gw_m3, gvadj_m3。
- **数えないもの**: ネスティングの帯の置換。累積は保存しない(再開すると 0 から。wq.csv・evap.csv と同じ)。
- fn_salt を指定した計算は常に salt.csv を書く(列は固定)。計算そのものは変えない(既存の出力はビット一致)。

### 140.2 構造物・吸い込みによる地表の塩水層の転送 f_salt_struct

- **これまで**: ポンプ・カルバート・分水・内部ソースの吸い込みは、水質だけを水と一緒に運び、塩水層は
  取水側に残した(§30.10 の利用者の選択)。取水口の高さの考え方を決めてから、としていた(handoff 1l・roadmap の
  淡塩2層 (2c))。
- **比べた案**:
  - (a) 底層から先に: 汲んだ水深のうち、塩水層の厚さまでを塩水として運ぶ。取水口(排水機場の吸込槽、
    樋門・カルバートの呑口)は水路の底にあり、鋭利界面で底にあるのは塩水、という見方。地下の井戸の
    「上部の淡水から先に」(浅い井戸のスクリーン)と対になる。浸透の配分(底層から先に。§47.5)とも同じ向き。
  - (b) 混合比で: 汲んだ水のうち hss/h だけを塩水として運ぶ。上下に分かれた水を混ぜて汲む場合。
    湧出の配分の f_salt_exch = 2(§47.9)と同じ位置づけの感度ケース。
  - (c) 表層から先に(越流堰・スキマー): 構造物の族の水理則(水位差で流量が決まるカルバート・分水)は
    取水の高さを持たないので、型ごとの指定が要る。必要が出るまで見送り。
- **決定**: `f_salt_struct`(&list_salt)を足す。0(既定)= 運ばない(これまでと同じ)、1 = (a)、2 = (b)。
  既定を 0 にしたのは、既存の計算の結果を変えないためと、これまでの選択を保つため。排水機場で海水を
  排水する計算(例題 coastal_salinity_recovery)では 1 を指定する。
- **実装**(boundary_h。水質の同率移動 §30.10 と同じ形): 取水セルの次の時刻の塩水層 hss1 から、(a) は
  min(hss1, 汲んだ水深)、(b) は hss1 × 汲んだ水深 / 汲む前の水深 を引き、体積(× gv × wfrac × A)を構造物ごとに
  集計して、水の体積・水質の質量と一緒に 1 回の総和で全ランクに共有し、吐口のセルへ水と同じ等分で足す。
  吐口のない構造物(域外)と吸い込みの分は記録場の列 6(salt.csv の out_struct_m3)。ため池・管路から
  汲む水は塩水を持たない。
- 水の体積と水質の質量の総和は、要素ごとの和なので従来とビット同一(バッファの並びは 水・水質・塩水)。

### 140.3 蒸発散の淡塩配分の扱い

- 蒸発は水だけを抜く。塩水の体積しか持たない淡塩2層では、淡水が尽きた後の蒸発は塩水層を縮める
  (濃くなった塩水・析出した塩は表せない)。配分の規則を新しく足す余地はなく(上から抜ける = 淡水から先、は
  いまの整合クランプが暗黙に行っている)、足りなかったのは、縮んだ体積が見えないことだった。
- **決定**: 物理は変えず、整合クランプで消えた体積を台帳の lost_surf・lost_gw に出す。塩分の濃度・析出・
  再溶解は水質(§139)で追う、とガイドに書く(用途集・salt.md)。

### 140.5 底層重力流の受け側の上限(バグ修正。挙動が変わる)

- **見つけた経緯**: 台帳の検定(test/saltledger の sea = 西端の海から潮位 2 m で乾いた陸を浸す)で、陸の水は
  すべて海から入った塩水なのに、入った塩水 28858 m³ のうち 5743 m³(20 %)が地表の整合クランプ(lost_surf)で
  消えていた。底層重力流を事実上止める(salt_ni = 1e9)と消えない(移流だけなら、同じ面を同じ流束が通るので
  塩水層は水深に一致する)。
- **原因**: 重力流の流束の制限が、エッジごとに「受け側の空き容量 h − hss まで」だった。複数のエッジから
  同時に入ると、合計が空き容量を超える。超えた分は次のステップの整合クランプが消し、送り側には不足
  (hss < h)が残る。全層が塩水の水が水面勾配を持って流れるとき(Φs = (1 + ε)η の勾配で重力流が働く)、
  丸めの大きさの不足(−Ofast のビルドで 1e-13 程度)を種に、不足のあるセルへ周りの 2〜3 本のエッジが
  それぞれ空き容量いっぱいまで塩水を入れ、超過が消えて不足が 2〜3 倍に増える、を毎ステップ繰り返した
  (診断出力で、不足が 1 ステップに約 1 割ずつ指数的に増えるのを確かめた。−O1 のビルドでは塩水層と水深が
  丸めまで一致して種がなく、起きない)。不足は、重力流で海から補えない海岸沿いのセルに集まった。
- **修正**: エッジごとの制限はそのまま残し、その後で、受け側のセルごとに流入の合計を数えて、空き容量を
  超えるセルへの流入を同じ倍率で縮める(ループ 1b)。超えるセルがなければ流量は変えない(従来とビット一致)。
  倍率は行 js−1..je+1 のセルについて求める。そのセルを囲むエッジが要るので、エッジ流量の計算を行
  js−1..je+2 が持つエッジまで広げた(読むのは行 js−2..je+2 = ハロ 2 行の範囲。確保範囲は変えていない)。
  ハロ行のセルの倍率は、その行を担当するランクと同じ値・同じ演算順で求まる。
- **比べた案**: (i) エッジごとの空き容量を 1/8 にする(局所で済むが、1 本のエッジだけが入るときの挙動も
  変わる)。(ii) 全層が塩水のセルどうしでは重力流を止める(原因の一部しか塞がない。部分的に塩水のセルへの
  複数エッジの流入は残る)。(iii) セルごとの上限(採用。塩水が消えていた場合だけ結果が変わる)。
- **検定**: test/saltledger に、海からの流入の 2 ケースを足した。sea(平らな陸。上の構成)と sea2d(地盤高
  0.8〜1.2 m の凹凸のある陸、24 × 16 セル。流れの向きが場所で変わり、MPI の帯の境をまたぐ)。修正の前は
  sea で 5743 m³(流入の 20 %)、sea2d で 15300 m³(流入 55384 m³ の 28 %)が消え、修正の後はどちらも
  1e-10 m³ 以下(丸め)。判定は「整合クランプで消えた量が流入の 1e-6 以下」「陸の塩水層 = 水深」「台帳の
  地表の体積 = 陸の水の体積」。Run_MPI.sh は N ランクと 1 ランクの Log.txt・salt.csv・最後の Hss・Hgs を
  バイト比較する(受け側の倍率が帯の境で同じ値になること)。
- **検証**(修正を入れた最終のツリー。gfortran 13.3.0、Open MPI 4.1.6。reference は更新していない):
  - -Og -fcheck=all(夜間の検査と同じフラグ)の MPI: test/saltledger の 10 ケースが np = 2・4 で合格(Log.txt・
    salt.csv・Hss・Hgs の 33 個が 1 ランクとバイト一致。sea2d は帯の境をまたいで受け側の上限が働く)、test/salt が
    np = 2 でデバッグ版の逐次の結果と一致、test/wqsalt が np = 2 で合格。実行時の検査には掛からない。
  - -Ofast の MPI: salt・tracer・wqbound・wqstruct・kdpart・damwq が np = 1・2・4 で逐次の reference に一致。
    test/saltledger・test/wqsalt の Run_MPI.sh が np = 2・4 で合格。
  - 逐次: test/salt は reference と ULP = 0 のまま(reference のケースでは、受け側の空き容量を超える流入が
    起きていないか、起きても結果を変えていない)。全ケースの回帰は §140.7。
- **残り**: 送り側の「在庫までの制限」も同じくエッジごとで、複数のエッジへ同時に出ると在庫を超えうる
  (hss が負になる。台帳の閉合は保つ)。地下の塩水 zone の側方流にも、エッジごとの同じ形の制限がある
  (検定の構成では lost_gw は丸めの範囲)。どちらも handoff 00aq に残す。

### 140.6 例題 examples/coastal_salinity_recovery

- **ねらい**: 利用者の例題案(一時的な海水の氾濫 → 浸透 → 排水 → 帯水層の塩水 → 涵養と揚水による回復・悪化。
  排水を優先する・井戸を汲み続ける・揚水を一時止める、の比較)を、台帳(§140.1)と構造物の転送(§140.2)を
  使って作った。見せたいのは、地表の浸水の解消と、帯水層の淡水の回復が、別々の時間で進むこと。鋭利界面は
  濃度を持たないので「飲用の基準に戻る日数」は出さず、帯水層の塩水の体積と界面の高さで回復の度合いを
  比べる(案の指摘どおり)。
- **構成**: 40 × 10 セル(dx = 25 m)。海・浜・堤防(天端 3 m)・排水路・低地(2 m)・台地。帯水層の底 −8 m、
  有効間隙率 0.2、側方の透水係数 1e-3 m/s、浸透能 2e-6 m/s、雨 1200 mm/年(全量が涵養)、井戸 0.004 m³/s。
  3 段を再開(f_state_restore = 2)でつなぐ: 津波の前(20 年。時間の圧縮 M = 100)→ 浸水と排水(実時間 8 日、
  dt = 1 s。排水機場 4 m³/s と 0.4 m³/s)→ その後の 8 年(M = 100。津波なし・井戸を継続・井戸を 2 年停止・
  遅い排水の後)。8 本で 1 スレッド約 20 分。保存先と読込元が同じ dir_save なので、Makefile が前の段の
  保存状態を次の段の名前でコピーする。
- **作る途中で決めたこと**:
  - 排水機場の運転則は排水路の水深で与える(0.1 m で停止、0.3 m で全量)。低地の水深で運転する形は、
    排水路が満水のまま止まった。
  - 圧縮した段の 1 年は、出力間隔(1/4 年・1/20 年)が時間刻みの倍数になるように 315600 s に丸める
    (365.25 日 / 100 = 315576 s との差は 0.008 %)。丸めないと、分布の出力の時刻がずれて最後の 1 枚が欠ける。
  - 回復の物差しは、余分の塩水(津波なしとの差)が 2.5 千 m³(速い排水の直後の 1 割)を下回るまでの年数に
    した。ケースごとの 1 割で測ると、3.5 倍の塩水が入った遅い排水のケースが、速い排水と同じ年数に見える。
- **結果**(README の表と同じ値): 堤内に残った海水 22.4 万 m³(速い排水)・20.1 万 m³(遅い排水)のうち、
  地下へしみ込んだのは 2.6 万 m³(12 %)と 9.0 万 m³(45 %)。地表の浸水は 18 時間と 86 時間で消える。
  帯水層の塩水は、津波の前の 5.3 千 m³(海岸のくさび)から 30.2 千・92.5 千 m³ に増え、余分が 2.5 千 m³ を
  下回るのは、井戸を継続で 4.5 年、井戸を 2 年停止で 1.9 年、遅い排水の後で 5.6 年。井戸を汲み続けると、
  井戸の下の界面が 9 か月で 1.5 m 上がる(揚水でできた地下水面のくぼみへ塩水が寄る)。8 年後も井戸の下に
  厚さ 0.5 m の塩水が残る(余分 約 0.5 千 m³)。整合クランプ(lost_surf・lost_gw)は全ケースで 0。
- **読み方の注意**(README の限界に書いた): 井戸は淡水から先に汲むので、この例題では塩水を汲まない
  (out_pump = 0)。「井戸を止めると回復が早い」は、揚水が流れを変える効果だけの結果で、塩水になった井戸水を
  汲み出す効果は入っていない(実際には両方ある。準備の検索では、揚水が有効だった報告と、汲みすぎで
  アップコーニングが起きた報告の両方があった)。しみ込む海水の量は、底層から先に配分し、すぐ帯水層の底に
  置くので、多めの見積もり。
- **圧縮率の確かめ**: 回復の段を M = 50 で計算すると、帯水層の塩水の体積の差は最大 0.07 %。圧縮なしとの
  直接の比較はしていない(handoff 00aq)。
- **再現の確かめ**: README の値と図は、最終のビルドで `make run`(8 本)から回し直して作った。井戸の揚水の
  数え方(§140.1)を入れる前のビルドの結果と、8 本とも salt.csv・Log.txt・最後の Hgs がバイト一致
  (この例題では井戸が塩水を汲まず、整合クランプも働かないので、台帳の値も変わらない)。
- **文献**: 実際の沿岸の記述(スリランカの井戸の被害と回復、仙台平野南部の電気伝導度)は、Web 検索の
  結果の要約で確かめた(2026-11-28。Illangasekare ら 2006、Villholth ら、Vithanage ら 2012、地下水学会誌
  54 巻 1 号)。本文は読めていない。Villholth らの資料は題名と機関だけを書いた(発行年と巻号を確かめられ
  なかった)。README に明記した。
