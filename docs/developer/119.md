## 119. 混合粒径の段 1(f_bedmix。掃流砂の粒径階 × 交換層 1 枚・下層 1 枚)の実装(2026-11-23。§84.19 の合意と docs/mixed_sediment_plan.md §10 の決めごとに沿う。無効時はビット一致)

§84.19 で範囲を限って採ることにした混合粒径の段 1(plan §8)を実装した。利用者の指示は「別ブランチが main に
取り込まれました」(着手の条件 = 土砂関係の作業の合流が満たされたことの連絡)と、それ以前の「有効化しない
場合にコストがほとんど増加しないのであれば C で進めたい」。設計の正本は docs/mixed_sediment_plan.md、
使い方は users_guide/geomorph.md の「混合粒径(f_bedmix)」、式・出典・限界は users_guide/sediment.md の同名の
小節(いずれも日英)。残りの作業は handoff 00ae。

### 119.1 実装の形

- **新しい submodule** src/m_geomorph_bedmix.f90(m_geomorph の submodule。約 1200 行)。初期化
  (init_bedmix。組成・交換層厚の既定・給砂の組成の検証・再開)、掃流砂の 1 ステップ(calc_fluvial_bmix =
  calc_fluvial のループ 1 の粒径階版の写し。側方 Neumann・容量給砂の写し neumann_bed_pass_bmix・
  feed_pass_bmix)、適用(apply_edge_flux_bmix)、区間流入の給砂(apply_bedfeed_bmix)、Hirano の交換
  (bmix_update。純粋手続き)、台帳と私有 save。
- **既存の経路からの入口**(無効時は整数の判定だけ): calc_fluvial の先頭で calc_fluvial_bmix へ分けて戻る
  (calc_fluvial_wfsed と同じ形)、calc_repose の末尾の適用を apply_edge_flux_bmix(.false.) に分ける、
  m_geomorph_calc の給砂を apply_bedfeed_bmix に分ける、init と dispose。既存のループの中には分岐を
  入れていない(plan §4。実行されない分岐でも -Ofast の最終桁が動いた §90.4 の教訓)。
- **状態**: 交換層の組成 s%bmf(帯±ハロ × 粒径階。近傍を読むのでハロを保つ)、平均粒径 s%bmdm(出力 Dm)、
  下層の組成 gm%bmx%fs(自帯だけを読む)、粒径階ごとのエッジ流束 gm%bmx%qk(wrk%q と同じ所有者正準の
  格納)、縮小率 fdk、台帳の行部分和(real64。par_sum_rows で決定的に集計)。どれも有効時だけ確保する。
- **境界**: &list_bound_inflow に inflow_qbfrac(1:N, n)(合計の給砂の一定の組成)と fn_inflow_qbmix(n)
  (粒径階ごとの時系列。行を文字列で読み、値の数がすべての行で同じかを確かめる。plan §3.6 の理由)。
  m_boundary が b%qbink(粒径階ごとの給砂。指定があるときだけ確保)を makebdc で埋める。組成の指定のない
  給砂は init_bedmix が止める(plan §10 の 3)。混合粒径でない構成で inflow_qbfrac・fn_inflow_qbmix・
  f_out_bmix を指定すると止める。
- **公開インターフェースの変更**: m_geomorph_init に境界 b を足した(給砂の組成の検証のため)。トップ
  レベルの make(utils)と BMI のビルドで追随を確かめた(§10)。
- **出力・保存**: Dm(有効時に自動)、f_out_bmix の Fa<k>_(&list_sysparam)。私有 save geomorph_bedmix.dat
  (粒径階の数・粒径・L_a の見出しと、交換層 N 面・下層 N 面。restart_write_cell。§83 の契約 5)。見出しが
  今の設定と違えば再開を止める。state.dat と save_version は変えていない。
- **台帳**(終了時の表示): 粒径階ごとの在庫の初期と最終・区間流入の給砂・開境界の正味の流出(容量給砂は
  負の流出)・残差、粒径階の供給量制限の発動回数、変動上限の発動回数、組成の丸めで動いた体積。

### 119.2 実装で決めたこと(plan からの変更を含む)

1. **粒径階版の可動層クランプ**(ループ 1): エッジ単独の流出を供給側の交換層にある量 L_e F_k で頭打ちに
   する。既存のループ 1 の可動層クランプ(エッジ単独の流出 ≤ sd)の粒径階版。これがないと、全粒径階を
   同じ粒径にした極限(T2)で単一粒径の計算と開境界の流出が 1e-7 の桁でずれた(単一粒径はエッジで
   クランプし、粒径階版はセル単位の制限だけになるため)。交換層厚 > 土層厚なら L_e F_k の和が sd になり、単一粒径と同じ
   規則に戻る。
2. **供給量制限**(ループ 1.5): plan §3.5 の (b) だけにし、上限は L_e F_k(この更新で下層から交換層に
   入る分は数えない保守側)。Σ_k L_e F_k = L_e ≤ sd なので (a)(合計 ≤ sd)は (b) に含まれる。下層から
   入る分を数えると上限が更新の結果に依存して陰的になるので採らなかった。代償として、1 回の更新で
   交換層の中身より多くは動かない(更新が粗いと流出が抑えられる)。発動回数を終了時に表示し、ガイドの
   精度の限界 (3) に書いた。
3. **等移動度の流束の換算**(ループ 1.4): 側岸侵食・安息角崩落の合計の流束(wrk%q)を、更新ループの
   前に供給側の更新前の組成で粒径階の流束に直す。ループ 2 は組成をその場で書き換えるので、近傍の組成を
   ループ 2 で読むと先に更新された組成で流入を数えて保存が破れた(実検出: 河岸のある構成で収支が
   1e-8 m³ ずれた)。
4. **初期の組成だけから決める量**: 交換層厚の既定(D90 の 2 倍)と側岸侵食則の代表粒径(初期の交換層の
   領域平均の d_m)は、namelist の一様値か、読んだ分布と入力の土層厚(静的データ)の面積平均から決める。
   現在の状態(再開なら復元した土層厚)から数えると土層のあるセルの集合が変わって 1 ulp ずれ、再開が
   ビット一致しなかった(実検出)。
5. **初期の在庫は最初の更新の頭で数える**: 河道幅の係数(chn%wfrac)は swflow の init で確保されるので、
   geomorph の init では読めない(実検出: 未確保の参照で異常終了)。河道幅の係数は私有の写しを持つ。
6. **組成の丸め**: bmix_update は丸めで負になった組成を 0 にして和を 1 に正規化し、動いた体積を台帳に
   数える(通常は 1e-16 程度)。
7. **併用を止める過程**(plan §3.7 の段 1 の列どおり): 浮遊砂・斜面浸食・細粒分の帳簿・崩落と崖錐・
   深さ依存クリープ・動く底層・土石流・乾式斜面侵食・風化・溶食・岩盤下刻・波浪による輸送・氷河・溶岩流。
   線形のクリープと隆起は z だけを動かし sd に触れない(calc_creep のループ 2 は z だけを更新する)ので
   組成に触れず、そのまま使える(plan の表のとおり。実装中に確かめた)。抵抗分割(f_taupart = 1)は
   fluv_d84 の指定を必須にした(D84 を粒径階から求めない。plan §3.7)。
8. **式 (31) の分岐の境界**: 実装の後、芦田・道上(1972)の本文(J-STAGE のスキャン)で式 (31) の形を
   確かめた(補助のエージェントによる照合。plan §11)。原典は τci/τcm で書かれ、d_i/d_m < 0.4 で 0.85、
   ≥ 0.4 で対数の形なので、ξ の分岐を r ≤ 0.4 / r > 0.4 から r < 0.4 / r ≥ 0.4 に直した(0.4 ちょうどの
   ときだけ違う。0.85/0.4 = 2.125 と対数の形の 2.108)。検定の結果は変わらない。同じ照合で、交換層厚の
   「D90 の 1〜2 倍」の出典は Parker 2008 ではなく Parker の電子書籍 第 17 章だと分かったので、ガイドの
   引用を直した。
9. **コミットの分け方**: plan §8 は (a) 足場、(b) 計算、(c) 検定、(d) 文書の 4 つに分けるとしていたが、
   コード・検定・文書・翻訳の確認記録を 1 つのコミットにした。理由: (1) 機能追加をコード・検定・文書と
   一緒に 1 コミットにするのがこのリポジトリの慣行で(例: bb68291・62f814c)、分けると途中のコミットが
   CI の文書の検査(params_index・設定例・検証ケースの一覧・翻訳の確認記録)に通らない。(2) (a)〜(d) の
   合否の基準は「機能追加 = 無効時に全 reference とビット一致」で同じで、足場だけの状態は単独でビルド・
   検証していない(後から分けると検証していないコミットができる)。等価変換・既存のバグ修正は混ぜて
   いないので、絶対規律 4 には当たらない。

### 119.3 検証

- **test/bedmix**(新設。Check_bedmix.py、標準ライブラリのみ): 全粒径階を同じ粒径(3 mm)にした計算が
  単一粒径の河床に 5.3e-15 m で一致し組成が変わらない(1.6e-14)、開境界の正味の流出の合計も一致
  (1.049197570 m³ で全桁)。給砂なしの静的アーマー(1 mm と 20 mm)で上流端の低下量 0.021971 m が
  L_a F_0 / (1 − f_sub) と一致し、細粒の割合の減衰率 0.04934 /s が 1 セルの式の 0.04946 /s と 0.24 % で
  合う。修正 Egiazaroff の 3 粒径階で、下流端の開境界を出た粒径階ごとの量が芦田・道上 式 (31)・(32) の
  再計算と比 1.0002 で合う。容量給砂で入口の河床と組成が固定(差 0、5.6e-17)。側岸侵食・安息角崩落・
  合計の給砂と組成の構成で、粒径階ごとの収支の残差 1.3e-13 m³、給砂が合計 × 組成 × 時間と 1.2e-16、
  組成の和が 1 から 2.2e-16、河岸が 0.30 m 動く。粒径階ごとの給砂の時系列の構成で、給砂が時系列の積分と
  相対 9e-5〜8e-4、残差 6.5e-14 m³。組成の指定のない給砂は初期化で止まる。
- **並列・再開**: MPI np = 1・2・4 が逐次とバイト一致(保存の 15 ファイル。最終の実行ファイルで確かめ直した)。gfortran -fcheck=all の
  逐次と np = 2 が合格し、互いにビット一致(静的データの地形・土層厚を使う構成)。リスタート往復
  (150 s で分割)が通しの計算とビット一致。トップレベルの make(src と utils)と BMI のビルドが通る。
- **無効時**: 下の 119.4。

### 119.4 無効時のコスト(利用者の条件「有効化しなければコストがほとんど増えない」)

- **出力の前後比較**: 変更前(main を取り込んだ ac83870)と変更後の実行ファイルで、既存の土砂の検定 23 本
  (fluvial・sedfeed・bendsed・berode・repose・fixation・uniflow・bedfines・suspend・wash・sedinflow・
  bankface・taupart・creep・hillsoil・wetlw・debris・rockfall・splash・bedslide・wfsed・wfswash・slopefric)の
  Run.sh を同じ条件(1 スレッド)で回し、結果と保存の全 4911 ファイルの sha256 を比べた。4691 ファイルが
  バイト一致し、残る 220 ファイルは再開の見出し save_info.txt の 1 行目のコメント(保存した壁時計の時刻)だけが
  違う。23 本とも Run.sh の検定に合格した。式 (31) の分岐の境界を直した最終の実行ファイルは、比べた実行
  ファイルと機械語が 2 バイト(calc_fluvial_bmix の中の比較の命令)だけ違う(ほかの差はシンボル名・デバッグ
  情報・ビルド ID)ので、この比較は最終のコードにも当てはまる。
- **回帰テスト**: CI の一覧の 30 本(wave・dambreak・frost・pump・conduit・salt・vzcol・vzzone・sfzone・
  prmap・wfshoal・wfshadow・wfcurrent・wfsed・wfswash・gwlateral・gwtani・stg・vshaped・bldgdrag・driftwood・
  bankcap・brink・bankspill・chutepool・cascade・tjunction・stairbank・stageside・river_flowline)が最終の
  実行ファイルで合格した。reference を持つケースは Log.txt と分布の比較がすべて identical(ULP = 0)。
  トップレベルの make(src と utils の全部)が通り、リポジトリでビルドした実行ファイルの .text は検証に
  使った実行ファイルとバイト一致した。
- **計算時間**: examples/meander の param.txt を 2400 s(水理 12000 ステップ、地形 2400 回)に縮めた計算を、変更前と
  変更後の実行ファイルで同時に 1 スレッドずつ別のコアに固定して回し、ラウンドごとにコアを入れ替えて 4 回
  測った(壁時計)。変更後 / 変更前 − 1 は −0.60・+0.90・+0.79・+0.64 %、合計で +0.42 %(1275.3 s と 1280.7 s)。
  ラウンド間のばらつき(変更前どうしで 5.6 %)より小さく、0.5 % 程度の増加があるとしても無効時に新しい
  処理は走らないので、リンク時最適化の配置の違いの範囲と見る。出力の 17 ファイルは両者でバイト一致した。
  23 本の検定の時間(上の比較)は 4 本ずつ並べてほかの作業と同時に回したので、比較には使わない。
- **結論**: 利用者の条件「有効化しなければコストがほとんど増えない」は満たされた(出力は不変、計算時間の差は
  測定のばらつきの範囲、メモリは新しい配列を確保しない)。
