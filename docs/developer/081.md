## 81. 第二段 (D1): 常駐の全域配列の窓化(2026-10-16 設計合意・実装)

設計は docs/xwindow_plan.md §7(D1〜D4)。D1 は時間ループ中も rank0 に残る
全域配列 3 つ(入力地形 g%z、出力バッファ wk_out・wk_out_i、降水分布 prmap)を
窓・帯に縮める。合意事項(2026-10-16): g%z の「rank0 が入力地形の正本を
持つ」(§11)をやめる / 窓外の出力値は切替可能で既定 0 / user フックの契約は
D2 で改める。

### 規約

- **出力バッファは窓形** `o%wk_out(ish:ieh, jw1:jw2)`(rank0)。gather は
  `par_gather_win(buf, a)`(buf(dcp%ish:, dcp%jw1:))で窓形へ直接受ける。
  全域バッファへの `par_gather_to` は「窓形へ受けてから写す」ラッパとして残し、
  save(D3 まで)と BMI の get_value(外部 API が全域形)が使う。
- **窓つき書き出し** `fileio_write_window(fname, nx, ny, i1, i2, j1, j2, a, fill, e_fmt[, gr])`
  (m_fileio。real/int)。全域 (nx, ny) の形式のファイルを 1 行バッファで書き、
  窓外の行・列は fill。text は行書き、bil は real32/int の行書き(従来の全域
  一時への変換をやめた)、GeoTIFF は無圧縮単一 strip の行書き
  (`gtif_write_window`)。窓 = 全域・fill = 0 なら従来の書き出しとバイト一致。
- **窓外の値 `out_fill`**(&list_sysparam。既定 0.0。整数ラスタは nint)。
  §79 で「窓外の行は gather されず 0」と述べた挙動を仕様に格上げし、GIS で
  区別したい利用者が `-9999` 等を選べるようにした。X0000(領域マスク)だけは
  全域の実値。窓内のマスク外セルは内部値のまま(変えていない)。
- **g%z は rank0 も帯へ**(band_shrink の例外を外した)。時間ループで全域の
  z を読む処理はない(probe の z・fill_depression・s%z = g%z・conduit の zbot は
  init で、いずれも窓内の全域添字)。
- **prmap(prtype=2)は帯確保** `(ish:ieh, jsh:jeh)`。読み込みは全域一時に
  読んで帯を切り出す(窓読みは D2)。NaN の計数は帯ごと(画面表示のみ)。

### 計測と検証(2026-10-16)

- 埋め込みケース(5600 × 3000、マスク 1/100、30 分 = 720 ステップ、4 スレッド、
  release 逐次。VmRSS を 1 s ごとに採取):

  | | (C) | (D1) |
  |---|---|---|
  | 最大 RSS(初期化ピーク) | 1.43 GB | 1.24 GB |
  | 時間ループ中の RSS | 0.38 GB | 0.059 GB |

  時間ループ中の常駐は rank0 の全域配列 3 つ(g%z 134 MB、wk_out・wk_out_i
  201 MB)が消えて帯配列だけになった(窓の面積に比例)。初期化ピーク 1.24 GB は
  残る全域一時(ts 系 8 枚 ≈ 1.07 GB と text 読み込み)で、D2 の対象。
- 結果の同一性(等価変換): 埋め込みケース・秩父 30 分とも、(C) の結果と Log・
  CSV・全分布ファイルがバイト同一(窓外の列・行は従来も 0 だったので
  out_fill の既定 0 で不変)。MPI np=2(埋め込み)・np=4(秩父)も同一。
- 回帰(規律 2・3): -O0 -fcheck=all の逐次(秩父 30 分・埋め込み)と MPI
  (埋め込み np=2・秩父 np=4。gather_win の受信範囲の検査)が境界エラーなく
  完走し結果同一。release で reference 付き 24 ケース中 23 PASS、
  nest_identity・nest_twin・bmi_nest・bmi_vars・gvchange PASS、MPI np=1, 2, 4
  の 6 ケース PASS。トップレベル make OK(utils の追随漏れなし)。
- **nhshelf だけ release(-Ofast、2 スレッド)で 1 要素が 2 量子(0.0002)
  ずれて FAIL**。(C) のコミットと D1 を同じ厳密フラグ(-O2、LTO・fast-math
  なし)で組み、OMP_NUM_THREADS=1 で実行すると全ファイルがバイト一致
  (同じ実行を繰り返しても一致)。同じ 2 つのバイナリを 2 スレッドで実行する
  と最終桁がずれる = 既出の「NH ソルバは実行間で非決定、ビット比較は
  単一スレッドで行う」(§72 の落とし穴、plan §11 0a)に該当し、D1 の
  変更とは無関係。**reference は更新していない**(規律 1)。
- 変更前後のバイナリ比較は、reference との比較が通らないケースではこの手順
  (同一環境・厳密フラグ・単一スレッドで新旧ソースを組んで全ファイル cmp)を
  正とする(§72 の運用則の再確認)。
