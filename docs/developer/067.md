## 67. 潮位・海面(m_tide)の最小入力(2026-10-01 実装。§62 の展開)

titype 未指定(namelist 既定 0)は従来「1〜4 を指定せよ」で停止していたが、
**1(一様固定潮位 ti0)を採用**して "tide: titype = 1 (default: uniform
fixed tide level ti0 = ... m)" と表示するようにした。ti0(既定 0 = 平均潮位)
と hsea0(既定 1 m。§23)は元から namelist 既定を持つので、**最小入力は
fn_tide + 空の &list_tide**(海域 fn_sw は与件)。海を「水位 0 m の排水先」
にする最簡の使い方(干潮排水・流域の海への出口)が 1 行で書ける。ti0 の 0 は
平均潮位の明示と区別できないため、既定の表示は titype が既定のときに ti0 を
併記する形。tival・fn_timap 等(時系列・分布)は与件のまま。

検証(2026-10-01): test/tide 構成2(空の &list_tide)と構成2'(titype=1・
ti0=0・hsea0=1 を明示)の result(Log.txt と出力場)がバイト一致。構成1
(titype=2 の時系列)は不変で reference PASS。

### 67.1 潮位表 tival の点数の上限を 9999 点に(2026-11-02 決定・実装)

ntimax(tival の最大点数。list_tide)を 999 から 9999 に上げた。小さな水域では潮位表を
細かく与える必要がある(examples/delta の海盆は固有周期 10〜18 分で、既定の 1 分ごとの
階段状の更新と 15.5 分ごとの潮位表で静振が起きた。毎ステップの更新と 4.5 分ごとの潮位表で
除いた。tide.md の「固有周期の短い水域」)。4.5 分ごとでは 999 点で M2 の 6 周期(74.5 h)
までしか与えられず、地形の加速(morfac)を下げた潮汐のケースに要る 12〜40 周期に足りない
(examples/delta 段 7 の morfac の確かめ)。

検討した案と判断(利用者と合意):
- **上限を上げる(採用)**: 意味は変わらない。前例は気温の時系列の nmtmax = 4000(list_meteo)。
  増えるのは namelist の読み込みの作業領域だけ(m_tide_init の局所 list と list_tide_read の
  局所配列。倍精度で各 160 KB。潮位を使わない計算でも m_tide_init の入口で list の既定値の
  初期化が 1 回走る)。計算中の潮位表は従来どおり実点数で確保する。補間(interp_series)は
  表の先頭からの線形探索だが、呼び出しは潮位の更新ごとに 1 回(セルごとではない)なので、
  9999 点でも 1 ステップの浅水流の計算に比べて無視できる。
- **調和定数で与える型(不採用)**: 分潮ごとの振幅・遅角から本体が潮位を合成する型。長さの上限が
  なく滑らかだが、潮位の時系列は直接与えられる量で、分潮からの合成は前処理でできる変換
  (§0 の 12。examples/delta は make_init.py が M2 の正弦から潮位表を作る)。実在の地点の合成には
  日付に依る天文引数と交点補正が要り、本体を複雑にする。年単位の計算などで表では扱えない用途が
  出たら改めて議論する。
- **潮位表のファイル入力(保留)**: 長さの上限がなく直接与える形のままだが、入力の口が増える
  (前例: 区間流入の時系列ファイル fn_inflow_qs・fn_inflow_qb。boundary.md)。9999 点(4.5 分ごとで
  約 60 周期)で足りない用途が出たら検討する。
- **再開で区切り、区間ごとに潮位表を与える(コード変更なし)**: 手間が多く、確かめていない。

検証(2026-11-02): test/tide・coastal_drain・salt・wave の逐次の回帰テストが reference と一致
(Log.txt が完全一致)。examples/delta の tidedom の最初の 1/4 周期は、潮位表を 24 周期 3985 点に
延ばして(1 周期 166 点は不変)、変更前のバイナリと 6 周期 997 点の潮位表で計算した結果と出力 9 種が
ビット一致。この環境に MPI がないため MPI の回帰は未実施(namelist は全ランクがファイルから読み、
通信に関わらない)。
