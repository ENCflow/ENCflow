## 107. ENC の家屋の抗力項の次元の修正(係数に水深を掛けていた誤り。2026-11-12 不具合修正)

**現象**: 流木の集積の検討(docs/woodjam_plan.md §6.8)の試作で、家屋の抗力項の式が ENC と STG で違い、ENC の
式は半陰解法の係数として次元が合わないことに気づいた。利用者の依頼(2026-11-12「ENCflow が間違っている可能性が
あります。検討してください」)で調べ、誤りと確かめた。

**原因**:
- ENC は辺の法線流速を半陰解法 `uve1 = (uve0 + (tae + tge)·dtl)/(1 − tfe·dtl)` で更新する(calc_kth_flux)。tfe は
  単位が 1/s の係数で、マニングの摩擦は −gv·g n²|V|/h^{4/3}。家屋の抗力は
  `tfe = tfe - p%kk * p%cd * hhe / bbe * (1 - gve) * vve / 2` で、水深 hhe (m) が掛かり、単位が m/s になっていた。
- 導出: 平面寸法 B の家屋が単位面積に (1 − gv)/B² 棟あり、1 棟の没水した前面積は B·h なので、単位面積あたりの
  抗力は ½ρ C_D (1 − gv)(h/B)|V|V。流速の式ではこれを水柱の質量 ρh で割るので、減速度は (C_D/2)(1 − gv)|V|V/B に
  なり、水深は消える。h/B が残るのは、流量フラックス M = u h の式の項を流速で書いたとき
  (−(C_D/2)(1 − gv)(h/B)|V|u)だけである。
- 履歴: 初版(72f9647e。2025-12-23)は `p%kk * p%cd / bbe * (1 - gve) * vve / 2` で水深がなく、af151189
  (2026-01-14「ENC抗力項に水深が掛かっていなかったバグを修正」)で hhe が入った。v3.0.0(2026-10-25)にも入って
  いる。STG(流量フラックスの式)は `FC = FC + KK*CD/DC/BBC*SQRT(MMC**2 + NNC**2)*(1 − GVC)`(DC は水深)で、
  係数は KK·C_D(1 − gv)|V|/B と次元が合う。
- この項を通る検定がなかった。fn_bb を与える検定がなく、fn_gv だけなら家屋の寸法は 1e10 m で抗力はほぼ 0 になる。

**影響**(修正前 = 次元の合う式 × 水深 h (m)。水深 1 m で一致し、浅いと弱く、深いと h に比例して強い):
- 効くのは fn_bb を与えた計算だけ。リポジトリでは examples/levee_breach と timberyard(2026-11-08 に fn_bb = 10 m を
  足した)。
- 等流(gv 0.7、B 10 m、n 0.03、勾配 0.002)の水深は、q = 0.3 m²/s で 0.398 m(修正前)対 0.421 m、q = 1 で同じ、
  q = 3 で 5.01 m 対 2.48 m(流速は半分)。計算は、どちらの式でもその式の等流に 0.03 % 以内で一致した。
- 例題(作業用の木での比較。修正前 → 修正後): levee_breach の「越水で破堤」は、堤内地へ入った水 491.8 → 491.7 万 m³、
  住宅地 A の流失 69.0 → 69.4 %、B・C(浸水深 0.6〜0.8 m)の最大流速 −4〜5 %。timberyard の本体は、市街地に入る
  材木 47,954 → 47,347 m³、建物セルの最大流体力の平均 0.098 → 0.127 m³/s²。浸水深が 1 m 前後か、流れが遅いので、
  主な数値はほとんど変わらない。
- 深く速い流れでは大きい。津波の例題 tsunami_town(公開の設定は fn_bb なし)に B = 10 m を足した試算(浸水深
  2.4〜3.7 m)で、建物セルの最大流速の平均 1.28 → 1.45 m/s、最大流体力 hV² の平均 2.14 → 3.80 m³/s²、hV² > 2 の
  セル 39 → 74 %、家屋の破壊率 79.6 → 84.3 %。修正前は流体力を 4 割ほど小さく出していた。

**対策**(2026-11-12。利用者の判断「推奨で」): hhe を外し、係数を (kk·cd/2)(1 − gv)|V|/B にした(1 行)。
- 比べた案: A = 水深だけ外す(採用。初版の形で、抗力の定義 ½ρ C_D A V² の ½ をそのまま持つ)。B = 水深と /2 を
  外して STG と同じ係数にする(不採用。次元の修正に、既定の抗力を 2 倍にする変更が重なる)。
- 既定値(cd = 1.0、kk = 0.5)は変えていない。残る論点は handoff に置いた: (1) 係数の 1/2(ENC は kk·cd/2、STG は
  KK·CD で、初版から 2 倍違う)、(2) 既定の大きさ(洪水浸水想定区域図作成マニュアル(第 4 版)は C_D′ = C_D/L を
  「建物の代表長さ 10 m で 0.383 が目安」とし、ENC の既定 kk·cd/B = 0.05 1/m はその約 1/8。検索で確かめただけで、
  本文は照合していない)。

**検証**:
- 新しい検定 test/bldgdrag(家屋のある水路の等流。長さ 2000 m、Δx = 5 m、勾配 0.01、n = 0.03、幅 4 セル。区間流入・
  自由流出で 90 分。x = 300〜900 m で測る): 理論値は定常の釣り合い
  gv g S = [gv g n²/h^{4/3} + (kk·cd/2)(1 − gv)/B] V²、q = V h の解(二分法)。3 構成(shallow: gv 0.7・B 10 m・
  q 0.4 m²/s、マニングの摩擦が主。deep: 同じ家屋で q 8 m²/s、家屋の抗力が主。dense: gv 0.5・B 20 m・cd 2・q 8 m²/s)で、
  定常(45 分と 90 分の水深の差 1 mm 以内)、水面勾配(±2 %)、断面流量(1e-3)、理論の等流との一致(全行で
  h/h_u・V/V_u が 1 ± 0.5 %)、家屋なしのマニングの水深より深いこと、の 5 項目に合格。実測は 3 構成とも
  h/h_u・V/V_u = 1 ± 0.0001(h_u = 0.2991・2.8969・4.1462 m)。修正前の実行ファイルでは h/h_u が 0.955・2.33・2.99 に
  なり、理論との一致の項目で落ちる(検定が誤りを検出する)。
- 回帰(release の逐次。gfortran 13.3、4 スレッド): reference を持つ 43 ケースの Run.sh が全て合格。32 ケースは
  比較するファイルが reference とバイト一致(identical)。11 ケース(nhbore・nhbottom・nhbreak・nhcurrent・nhshelf・nhsolitary・nhwave・

  同じ 11 ケースを修正前の実行ファイル(同じ計算機・同じフラグ)でも回して切り分けた。
  - 家屋を使わない 9 ケース(nhshelf と wqstruct 以外)は、修正の前後で結果の全ファイルがバイト一致する。reference との

    よる。§90.18 と同種)。
  - nhshelf は、同じ実行ファイルの 2 回の実行でも最終桁と Runge 列が揺れる(§10 に既知として記録されている NH ソルバの
    4 スレッドの実行間非決定)。修正後の 2 回(reference との差 66・67 か所)と修正前の 1 回(56 か所)は、どれも
    ULP=1 で合格。
  - wqstruct(fn_gv だけを与える。家屋の寸法は 1e10 m)は、Log の Runge 列(比較対象外)の 1 行だけが変わる
    (1.2 % → 1.0 %。抗力の項が厳密な 0 でないため)。ほかの 51 ファイル(水質の wq.csv を含む)はバイト一致。
- reference を持たない検定のうち、家屋・流木を使う bldgdebris・gvchange・driftwood と、CI の検定型 prmap・wfswash・

**残りの論点の決定**(2026-11-12。利用者の判断「推奨で」):
- 係数の 1/2: ENC は kk·cd/2 のままにする。利用者ガイドは kk を「家屋群の遮蔽による低減係数」としていて、
  1/2 は抗力の定義 ½ρ C_D A V² の 1/2 にあたるので、ENC の形はこの定義と整合する。STG(旧互換の比較用)は
  変えない。STG の係数が ENC の 2 倍であることを、利用者ガイド encgrid.md §9(日英)に書いた(STG も圧力項・
  摩擦項に gv を掛け、慣性に λm を使うので、違いは抗力の係数だけ)。
- 既定値(cd = 1.0、kk = 0.5): 変えない。洪水浸水想定区域図作成マニュアルの目安(C_D/L)との差は、本文を
  照合してから見直す(handoff 00t)。
- 周知: v3.0.0 の利用者への知らせは、次の版の公開のときに行う(handoff 00t)。
- CI: 毎 push の ci.yml の逐次のジョブに test/bldgdrag を足した(高速な 20 ケース。約 1.5〜2 分)。検定の
  スクリプトは標準ライブラリだけで書いてあり、numpy を読めない Python で動くことを確かめた(§10 の注)。MPI の
  ジョブ(np = 2)には足していない(辺ごとの局所の式で、並列の経路は同じ式を通るだけ。手元の np = 1・2・4 は
  逐次とバイト一致)。
