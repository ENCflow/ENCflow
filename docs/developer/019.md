## 19. 地形変化モジュール(m_geomorph)の実装(2026-08-07)

河床変動・斜面浸食の設計検討の全文は docs/geomorph_plan.md(F1 以降の
設計はそちらが正本。実装完了とともに本節へ移して消し込む)。本節は
実装済みの決定(F0: クリープ+加速係数)を記す。

- **加速係数 morfac(MORFAC 方式)**: 地形更新だけを morfac 倍する。
  実装は gwflow と同じ実効時間刻みの供給
  (dts = dt × idt_geomorph × morfac を calc が各プロセスに渡す)。
  **全プロセス共通の1個**(プロセス別にすると「地形の時間」が分裂し、
  斜面供給と河床変動の同時性が壊れる)。解釈: 1回の計算 = morfac 回の
  同一イベントぶんの地形変化。検証は morfac=N と morfac=1×(N倍時間)の
  等価性ベンチマーク(test/creep に実装済み。線形拡散では時間離散化の
  O(dts) 差のみ)。
- **クリープ(f_creep)は4近傍の保存形フラックス(5点ラプラシアン)**:
  等方線形拡散 D∇²z に厳密整合し、ガウス丘の解析解と直接比較できる。
  斜め成分の枠(cw(1), cw(3)=0)は構造として確保してあり、8近傍化は
  重み定義の変更で閉じる。ただし**8近傍化の際は実効拡散係数が D と
  一致する重みの正規化が必須**(gwflow_lateral の l8/w8dr 流用では
  実効 D が (lp+√2·ld) 倍にずれる。解析解ベンチが検出器になる)。
- **2ループ構造・エッジスクラッチは m_gwflow_lateral の複製**
  (ループ1: エッジ流量、帯界面はハロ行 je+1 の冗長計算=ビット厳密な
  配布 / ループ2: 反対称集計で発散。土砂体積は機械精度で保存)。
  スクラッチ q(1:4, 0:nx, jsh-1:jeh) はモジュール私有(t_geomorph は
  calc に intent(in) で渡るため。単一インスタンス前提 §12)。
- **陽解法の安定条件は init で静的検査**: D·dts·(1/dx²+1/dy²) ≤ 1/2。
  D・格子・dts が全て namelist 由来なので実行前に確定し、超過は
  par_stop(判定は全ランク同一 = collective 安全)。
- **境界**: 領域外(x=0)・海(sw>0)とは無フラックス(海域の地形は
  不変。gwflow_lateral と同じ整理)。
- **s%z のハロ交換は calc 末尾の1回**(§11 の浸食 TODO(1) の解消。
  初回呼び出しのハロは初期化の帯+ハロ切り出しで有効。クリープの
  ±1 参照と流れの重力項の両方をこの1回で賄う)。
- **検証(2026-08-07 実施, gfortran 13.3/OpenMPI, -O2 厳密数学)**:
  無効時ビット一致(wave の Log.txt がバイト一致)/ -fcheck np=2 を
  最適化 MPI より先に(規律3。creep + wave)/ creep の np=1,2,4 の
  プローブ CSV が逐次とビット一致 / wave np=1,2,4 PASS /
  解析解ベンチ(test/creep): 最大誤差 7.8e-5 m(丘高 1m の 0.008%)、
  morfac=2 等価 2.3e-4 m。
- **test/creep は reference 比較でなく解析解比較**(Check_analytic.py。
  許容差 5e-3 m)。環境非依存なので CI 昇格候補(§10)。パラメータ
  (A, σ, D, 中心セル)は param.txt / user_geoinfo の gaussian_hill /
  Check_analytic.py の3箇所で対になっている — 変えるときは同時に。
- **将来(F1a 以降)の注意**: s%sd 導入後は各プロセスの Δz を s%sd にも
  共動適用する(浸食で土層が薄くなる→飽和・流出の早期化の結合。
  geomorph_plan.md §2.5)。calc 内に TODO コメントあり。

### 19.1 土層厚の動的共有状態化(F1a。2026-08-07 実装)

浸食モデルと地下水モデルの結合(表層浸食→土層厚減少→飽和・流出の
早期化)の土台。設計は geomorph_plan.md §2.5。

- **s%sd(動的共有状態)を t_state に追加**。gwflow カーネル(lateral の
  全水頭・飽和判定・容量・安定条件走査、greenampt の容量)は s%sd を
  読む。g%sd は「初期土層厚の入力係数」として存続(f_sdtype 3状態・
  方式2配布・遅延確保口 require_sd は不変)。
- **初期値の転記は m_gwflow_init が require_sd の直後に行う**
  (m_state_init の時点では g%sd が未確保のため、そこでは転記できない
  — この初期化順序が転記位置の決定理由)。将来 geomorph が sd を要する
  場合も同じ規約で転記する(先に転記した方が勝ち、値は同一 g%sd 由来)。
- **restore 時は転記をスキップ**(復元値が勝つ。「保存状態を初期条件に
  使う」意味論。sd の入力係数を差し替えても restore には効かない)。
  ガード: 土層ゼロの save(gwflow 無効時に作成)を sd 必須モデルで
  restore する設定齟齬は par_stop(黙って容量ゼロの地下水になるのを
  防ぐ。判定は maxval+allreduce_max で全ランク同一 = collective 安全)。
- **save/restore: state.dat を5成分に拡張**(h, z, hrs, hg, sd。
  save_version = "2026-08-07")。sd は hg と同じ一律保存(無効時は
  ゼロ面)。utils/ に state.dat の読み手はないことを確認済み(§10 の
  形式変更チェック)。
- **将来(F1b)**: geomorph の各プロセスは Δz を s%sd にも共動適用する。
  z と sd が同じ Δz で動くため帯水層底 (z − sd) は不変(岩盤固定が
  構造的に成立)。堆積で sd が init 時の max(sd) を超えると lateral の
  静的安定条件検査が非保守側になる点に注意(超過の par_warn 監視を
  F1b で入れる)。
- **検証(2026-08-07, gfortran/OpenMPI, -O2 厳密数学)**: コミットA
  (読み替え)= wave と greenampt+lateral 合成ケースの逐次・np=1,2,4 が
  変更前 Log とバイト一致、-fcheck np=2 先行。コミットB(save 拡張)=
  非 restore 実行のバイト一致、リスタート往復(save→restore(tt=0)→save)
  で state.dat / swflow_enc.dat バイト一致、np=2 の save が逐次 save と
  バイト一致、-fcheck np=2 で save/restore 経路、ゼロ土層 restore の
  par_stop 動作。

### 19.2 掃流砂 Exner(f_fluvial。F1b。2026-08-07 実装)

- **平衡流砂量による河床変動**: (1−λ)∂z/∂t = −∇·q_b。掃流砂の適応距離は
  局所(格子スケールで平衡が成立)という物理区分が「掃流=平衡 Exner、
  浮遊=輸送方程式(F2)」の実装段階分けと一致する(geomorph_plan.md §5.4)。
- **エッジ水理量は両セル平均、流向はセル平均流速のエッジ法線射影**
  (2026-08-07 ユーザー決定)。エッジ流量 mn は swflow_enc 私有であり、
  経験式の平衡流砂量に mn の厳密整合は不要のため、t_state の公開量
  (u, v, vv, h)で閉じる。τ* = n²V²/(s·d50·h^{1/3})(マニング閉じ。
  g は相殺)。流砂量式は f_qbform(1: 芦田・道上, 2: MPM)。
- **2ループ構造は gwflow_lateral と同型**(エッジスクラッチは creep と
  共有の wrk%q。各プロセスのループ1は対象セルの4成分を 0 込みで必ず
  上書きする契約)。
- **【実バグ】calc 冒頭の par_halo_cell(h, u, v, vv) は必須**:
  swflow・gwflow は帯のみを更新するため、ステップ頭交換のままでは
  ハロ行の流速・水深が前ステップの値に古びる。界面エッジの冗長計算が
  隣接ランクと異なる入力から同一エッジを計算し、反対称性=土砂体積保存が
  壊れる(np=2 の保存則検定で Σdz が 1.7e-3 に飛んで検出。修正後は
  4.6e-16)。gwflow_lateral の「冒頭に置く理由」と同じ構図。
- **クランプ3層**: (1) エッジ別の可動層クランプ(風上セルの sd を
  このエッジ単独で超えない。lateral の過大流出抑制と同型)、
  (2) エッジ別の dzmax ガード(地形波 CFL 相当。クリップは流量段階=
  保存則を保つ。発動数は dispose で par_warn)、(3) ループ2の岩盤床
  クリップ(複数エッジ同時流出の僅かな超過の最終防衛。失う体積は
  vleak に計上し dispose で par_warn — 黙らない)。
- **sd 共動更新と gwflow 結合**: z と sd に同じ Δz を適用(帯水層底
  z−sd 不変)。gw_active 時は容量 sd·sy0 が現在の s%hg を下回った分を
  s%h へ引き渡す(飽和表土の水が地表に出る)。検証: 飽和薄土層
  (sd0=0.03, ksv 大)+浸食で引き渡しを発火させ、S_grnd→S_surf の
  移動を確認、S_total は 14 桁不動。
- **クリープは当面 sd に触れない**(土層のない理想地形ベンチマークを
  保つ。実地形でクリープを使う段になったら sd 共動+クランプを追加)。
  → 2026-10-27 に creep_hstar > 0 の深さ依存クリープとして実現(§89.8。sd 共動と
  供給量制限は掃流砂と共有。既定 0 は従来どおり sd に触れない)。
- **制約ガード**: STG は par_stop(init 時コピーのため)。
- **サブグリッド河道幅(fn_width)併用対応(2026-08-07 実装)**:
  swflow_enc の have_width/have_frw/frw/wfrac を **protected 公開**にし
  (読み取り専用の口。書き手は swflow_enc と channel submodule のみ)、
  掃流砂はエッジ流量に frw(水と同じ開口・幅キャップ)、Δz 換算に
  1/wfrac(河道底のみ変動=改訂2の決定)を乗じる。可動層・dzmax
  クランプも供給側セルの 1/wfrac で河道底厚さに換算。
  **浮遊砂は移流・E-D とも無修正で整合**(移流は continuous のミラーで
  自動、E-D は hs・Δz とも河道断面あたりの量で wfrac が相殺)。
  **堤防(§17)エッジ=河道—非河道の境界では掃流砂を運ばない**
  (掃流砂は河道内に閉じる。越流時の土砂は浮遊砂が壁込みの実フラックス
  mn1 で運ぶ、という輸送形態の分担)。
  検証: W≥面長の退化性(堤防のみとバイト一致)、狭窄幅 W=0.3m で
  wfrac 加重の体積保存 6.3e-16・変動の河道行集中(×1/wfrac)、
  浮遊砂+幅の加重固体保存 7.7e-17、np=1,2,4 バイト一致。
  【実バグ】堤防エッジ判定で x 番兵ガードより先に g%rw(in,jn) を読み、
  i=0/nx+1 で範囲外(rw は x と違い番兵なし)— -fcheck np=2 が捕捉。
  マスク近傍読みは必ず x ガードの内側で(§12 の帯確保規則の系)。
  既知の妥協: gwflow 併用時の容量 sd*sy0 はセル全面の土層解釈のままで、
  幅セルの sd(河道底の土層)とは近似的な整合。
- **test/fluvial**: 閉領域ダムブレイク型の疎通・保存則検定。
  save/state.dat を Python で RLE 展開し、(1) Σ(z−z0) ≈ 0(実測
  4.6e-16)、(2) (sd−sd0)−(z−z0) ≈ 0(1.2e-14)、(3) 活性(max|Δz|
  1.9mm)を検定。Run_MPI.sh は state.dat の逐次バイト一致も検定する。
- **検証(2026-08-07, gfortran/OpenMPI, -O2 厳密数学)**: 無効時
  ビット一致(wave / gwflow ケース / test/creep)、-fcheck np=2 先行
  (上記ハロバグを捕捉)、np=1,2,4 の state.dat 逐次バイト一致、
  gwflow 併用の S_total 14桁不動(引き渡し発火ケース含む)、
  リスタート往復(sd が発展した状態の save→restore→save)バイト一致。
- **残(次段)**: 等流×給砂平衡の解析解ベンチマーク(境界土砂供給=
  平衡給砂の設計と併せて)、morfac 等価性の fluvial 版、浮遊砂(F2)。

### 19.3 浮遊砂(f_suspend。F2。2026-08-07 実装)

- **責務の分業**: 移流 = m_swflow_enc のステップ内輸送(s%sed_active
  フラグ。s%gw_active と同じ通知様式)、浸食・沈降(E-D)= m_geomorph の
  calc_suspend(dt_geomorph 間隔)。状態は s%hs(浮遊砂柱状量 [m]。
  濃度 C = hs/h は導出量)。
- **移流カーネルはスカラー非依存の汎用手続き advect_scalar**
  (geomorph_plan.md §2.6。栄養塩・汚染物質輸送の将来共用を想定した
  利用者第1号)。continuous と同一のエッジ流量 mn1・通過幅係数 fw・
  平面積率逆数 winv・空隙率 gv・乾燥エッジ条件で風上輸送するため、
  「一様濃度は一様のまま」が式の形で保証される。時刻 n の h と hs が
  必要なため continuous 直後(complete 前)に置き、コミット
  (hs1→s%hs)は complete が行う(h1→h と同じ意味論)。
  開境界からの流入は清水(C=0)、流出は内部濃度で自然流出。
- **【実バグ】sx%hs1 は確保時に s%hs の複製で初期化する**(mn1 = mn と
  同じ流儀)。init 末尾の complete は移流を経ずにコミットするため、
  0 のままだと restore 済みの hs を消す(リスタート往復ビット一致で
  実検出。cold start は hs=0 なので複製で挙動不変)。
- **E-D 交換**(calc_suspend): E = w_f・C_eq(可動層 sd でクランプ)、
  D = w_f・β・C(浮遊量 hs でクランプ)。C_eq は f_esform で選択:
  1 = 超過掃流力線形(簡易式)、**2 = 板倉・岸(2026-08-07 追加。
  典拠: 実践河川水理学(iRIC)第4章 式(3)-(5)、原典: 板倉(1984)。
  K=0.008, α*=0.14, B*=0.143, η0=0.5 は原式固定で namelist にしない。
  ceq = max(q_su, 0)/w_f。Ω の Gauss 積分比は e^{−a'²}/(√π erfc(a'))、
  a' > 20 は erfc アンダーフロー域なので 0 打ち切り(その域では
  q_su < 0 が保証される)。自己整合性: τ*→0 で漸近相殺により Ω→0)**。
  w_f は susp_wf 直接指定か Rubey 式導出。
  乾燥セル(h <= dd)は浮遊分を全量河床へ繰り入れ(水のない浮遊砂を
  残さない)。z と sd の共動更新・gwflow 容量引き渡しは fluvial と同一。
- **MORFAC の台帳分離**: 水柱側(hs)は水理時間 dtw、河床側(z, sd)は
  ×morfac。morfac=1 では交換が厳密に反対称で、固体総量
  Σhs + (1−λ)Σ(z−z0) が機械精度保存(test/suspend が検定。実測 2.2e-15)。
- **ハロ**: s%hs は swflow_enc のステップ頭交換に追加(sed_active 時のみ。
  E-D による帯の更新は前ステップの geomorph なので、移流直前の交換で
  最新)。E-D はセル内交換のみでエッジ・ハロ不要。
- **save/restore**: state.dat を6成分に拡張(h, z, hrs, hg, sd, hs。
  save_version = "2026-08-07b")。
- **既知の挙動**: 強い乾燥化では h1 同様に hs1 も僅かに負になり得る
  (f_exflux_reduction=1 で緩和。§94.1 と同種)。
- **検証(2026-08-07, gfortran/OpenMPI, -O2 厳密数学)**: 無効時
  ビット一致(wave / gwflow ケース / creep / fluvial)、-fcheck np=2
  先行、np=1,2,4 の state.dat 逐次バイト一致、固体総量保存 2.2e-15、
  共動更新恒等 1.6e-14、gwflow 併用の S_total 14桁不動、リスタート往復
  (hs 復元)の逐次・np=2 バイト一致(上記 hs1 初期化バグを捕捉)。
- **残(次段)**: 定常巻き上げ・沈降の解析解ベンチマーク(2026-10-30 に
  §19.11 で整備)、浮遊砂の境界流入濃度(plan §2.7 の 2)、区間流入の Qs(t)(同 3)。

### 19.5 斜面浸食(f_wash。F3。2026-08-07 実装)+ submodule 分割

### 19.6 プロセスの適用セル範囲と加速係数の共通性(2026-08-07 Q&A の記録)

- **適用セル範囲は非対称**(「河道限定」なのは wash の遮断だけ):

  | プロセス | 河道セル(rw>0) | 非河道の陸セル |
  |---|---|---|
  | 掃流砂 f_fluvial | ○ | ○(堤防有効時は河道—非河道エッジで遮断) |
  | 浮遊砂 f_suspend(移流・E-D) | ○ | ○ |
  | 斜面浸食 f_wash | ×(スキップ) | ○ |
  | クリープ f_creep | ○ | ○(rw を見ない) |

  - 浮遊砂の全域有効は必須(越流土砂の氾濫原堆積と、斜面供給の河道への
    輸送は、非河道セル上の移流+沈降そのもの)。
  - 掃流砂の全域有効は「τ*c が実質のセレクタ」という整理(氾濫原の薄い
    流れは通常不活性。堤防有効時は境界エッジの遮断で河床材料が河道内に
    閉じる)。fn_rw 未指定なら全セル rw=0 = wash は全陸セル・遮断なし。
  - **既知の重なり**: 非河道セルでは浮遊砂の E(沖積床の平衡巻き上げ)と
    wash の kf 項(土壌の面状剥離)が概念的に重複し、両方有効だと二重
    計上の余地がある(係数校正で管理する前提)。役割分担は「E = 平衡
    巻き上げ概念が有効な沖積床 / wash = その概念が成り立たない斜面の
    剥離」。必要になったら「E-D を河道セル限定にする(斜面の供給は
    wash に一本化)」オプションを追加できる(小変更)。
- **加速係数 morfac は全プロセス共通の1個**(§19 冒頭・plan §4 の決定の
  再確認)。プロセス別に加速を変えると「地形の時間」が分裂し、斜面から
  の供給量と河道の堆積量の対応が崩れるため。適用は、掃流砂・クリープ=
  実効時間刻み dts に乗算 / 浮遊砂・wash = 河床側(z, sd)のみ ×morfac
  (水柱側は水理時間。台帳分離)。
  **プロセス別の実効加速の逃げ道**: クリープ(creep_d)と wash
  (wash_kr, wash_kf)は線形の率係数を持つため、係数の N 倍がその
  プロセスだけの morfac×N と数学的に等価。物理式で率が決まる掃流砂・
  浮遊砂にはこの自由度がなく、共通 morfac が唯一の時間軸になる
  (共通 morfac = 地形時間の定義、係数スケーリング = プロセス別の
  感度調整、という使い分け)。

### 19.7 区間流入の土砂濃度時系列(inflow_cs。2026-08-07 実装)

- **&list_bound_inflow の各区間に、流量とは別の濃度時系列を付随させる**
  (inflow_cs(1:2,:,区間) = (min, 体積濃度) / ファイル指定 fn_inflow_cs。
  未指定の区間は清水流入)。区間の幾何定義(inflow_cell)は流量と共有。
- **機構**: m_boundary が makebdc で補間し、セル別テーブル b%csin
  (濃度指定区間が1つでもあれば確保。自帯の行のみ書く=ハロ不要)を
  毎ステップ更新。swflow_enc の advect_scalar は任意引数 cbin を受け、
  境界面からの流入(mne<0 で風上が域外)の濃度を cbin(i,j) から取る
  (なければ従来どおり清水 0)。汎用カーネルの「境界流入濃度は所有者が
  渡す」契約(plan §2.6/§2.7)の実現形で、移流・貯留補正・gv 換算は
  水と同一係数のまま。
- **土砂流入量は C(t)・Q(t)**: 流量時系列の変動に自動追随し、区間内の
  按分は水の按分(inflow_dist)と自動連動(どのモードでも総量 = C・Q が
  厳密)。濃度は体積濃度 [m3/m3](mg/L からの換算はユーザー側:
  C_vol = (mg/L) / (ρs[kg/m3]・1000))。
- **新規の保存状態なし**(時系列は入力、注入は無履歴)。save_version 不変。
- **test/sedinflow**: 乾いた閉領域の西辺に Q=5, C=0.001 の一定流入。
  固体総量 Σhs + (1−λ)Σ(z−z0) = C・Q・tt の台帳閉合を検定
  (実測 2.6e-16。流入水量 Σh = Q・tt = 40 m3 も厳密)。
- **検証(2026-08-07, gfortran/OpenMPI, -O2 厳密数学)**: 濃度未指定の
  ビット不変(wave/suspend/wash/開境界)、-fcheck np=2 先行(新配列
  csin/sval)、np=1,2,4 の state.dat 逐次バイト一致。
- 残: 平衡濃度モード・Qs(t) 直接指定(plan §2.7 の 2 残・3)、
  辺境界(放射)の流入への適用。

- **Qs(t) 直接指定(inflow_qs。2026-08-07 追記)**: inflow_cs と区間ごと
  に排他の流砂量時系列(min, m3/s 固体体積)。実装は **cs = Qs(t)/Q(t) の
  等価濃度への還元**で、makebdc が毎ステップ計算して同じ csin テーブルに
  載せる(機構の追加なし)。性質: 按分は水の按分と自動連動、注入総量 =
  Qs・dt が厳密(test/sedinflow の param_qs で台帳閉合 2.6e-16 を検定)、
  Q=0 の間は注入されない(水が運ぶ)。Qs/Q >= 1 はクリップして dispose
  で警告(黙らない)。検証: 濃度モードのビット不変、排他指定の par_stop、
  -fcheck np=2、np=1,2,4 の state.dat 逐次バイト一致。

### 19.8 流砂基礎式の選択制と Nays2DH メニューとの対応(2026-08-07 Q&A の記録)

- **質問**: 掃流砂・浮遊砂の基礎式をフラグ選択制にできるか。式によって
  パラメータが異なることでパラメータファイルが複雑化しないか。
- **回答**: すでに選択制(f_qbform: 1=芦田・道上, 2=MPM /
  f_esform: 1=超過掃流力線形, 2=板倉・岸)。複雑化を防ぐ設計原則を明文化:
  1. **物理パラメータ(d50, τ*c, 空隙率 λ, 水中比重 s)は式によらず共有**。
     式を切り替えても入力項目は変わらない。
  2. **式固有の係数(芦田・道上の 17、MPM の 8、板倉・岸の K=0.008・
     α*=0.14・B*=0.143・η0=0.5)は原式固定でコード内に持つ**。
     namelist には出さない。
  3. 式選択で有無が変わる入力は susp_esa(f_esform=1 のみ必須)の1項目。
     不使用時は無視(サンプルに明記)。
  今後の式追加もこの原則の範囲で行う(選択肢が増えても入力は増えない)。
- **Nays2DH Solver Manual(和文 v4)との対応**(2026-08-07 確認):
  - MPM(式58)= f_qbform=2、芦田・道上(式59)= f_qbform=1。ただし
    当方は平坦床簡略版で、Nays2DH の有効掃流力 τ*e(式61)と河床勾配
    補正 Kc(式62)は未実装(§19.2 に記録済み)。τ*e は h/d と τ* のみ
    で計算でき新パラメータ不要のため、f_qbform=1 の忠実度向上候補
    (挙動変更なのでコミット分離・検証が必要)。
  - **芦田・道上 (1972) の原典照合(2026-10-29。利用者が提供した本文)**: 式 (23)
    Φ = q_B/√((σ/ρ−1)gd³) = 17 τ*e^{3/2}(1 − τ*c/τ*)(1 − u*c/u*)。f_qbform=1 は
    これの u*e = u*(原典が Flat・Antidune 床 = Upper Regime でとる仮定。式 (38)・
    §3(2))の形で、係数 17・指数・閾値の 2 因子が一致する。有効摩擦速度は式 (11)
    U/u*e = 6.0 + 5.75 log10{R/(d(1+2τ*))}(式 (7) の対数則と式 (9) の相当粗度
    ks = d(1 + ατ*)、α = 2)、τ*e = u*e²/((σ/ρ−1)gd)。**τ*e を入れる場合も閾値の 2 因子は
    全 τ*・u* のまま**(Bagnold 型の導出の式 (22) は τ*e・u*e で書かれるが、実験で
    式 (23) に修正した。河床波の剥離渦で乱れが強く砂が動きやすいことを K = 1 に
    含めたため、と原典は説明)。17 = β/μf(β ≈ 8.5、μf ≈ 0.4〜0.5)。混合砂礫の
    平均粒径の τ*cm ≈ 0.05(式 (31) の但し書き)は fluv_tausc の既定 0.05 とも整合。
    混合粒径(修正 Egiazaroff 式 (31)・粒径別流砂量式 (32))は §84.10 の決定どおり
    採らない。τ*e の導入は挙動変更で、既定を置き換えるか選択肢を足すかは議論が先。
  - **今後の課題として記載(2026-10-29。利用者の指示)**: users guide の解説
    sediment.md §3(日英)の末尾に「今後の課題(実装予定): 有効掃流力」を置いた。
    方針は既定を変えない選択肢(新パラメータなし、無効時ビット一致)で、τ*e ≤ τ* の
    頭打ち、対数則の適用範囲外(R/ks が数以下。0.09 未満で式 (11) の分母が 0)の保護、
    fluv_taufac との排他、式 (11) の検定ケースを備える。等流の試算で流砂量は
    n が粒子粗度の約 2 倍の砂床で 0.1〜0.25 倍、礫床で 0.4〜0.65 倍(例題 meander・delta
    は τ*e なしで調整済み)。入れる時期は Nays2DH との比較・砂堆のある砂河川・植生の
    ある氾濫原を扱う段。fix_cn は流砂の τ* を g%rn(元の n)で評価するので、粗度を
    上げると τ* が増える性質の対象は粗度分布で n を上げたセルだけ。
  - 板倉・岸(式97〜99)は f_esform=2 の実装と完全一致を確認
    (K=0.008, α*=0.14, B*=0.143, η0=0.5, a′ の定義とも同一)。
- **保留した式と理由**(いずれも追加時の新規パラメータはゼロ):
  - **江頭式(式60)→ f_qbform=3 候補**: マニュアルに係数 K1, K2, f_d,
    f_f の値がなく「江頭ら(1997)を参照」とのみ記載。文献確認なしで
    記憶から係数を埋め込まない(板倉・岸導入時と同じ方針)。
  - **Lane-Kalinske(式100)→ f_esform=3 候補**: 必要量は u* と w_f
    のみで追加は容易だが、「(単位: ppm)」の注記があり体積濃度への
    換算規約が確定できない。無次元の括弧 ×5.55 をそのまま体積濃度と
    読むと u*/w_f=2 で C_eq≈2.5(250%)となり非物理、ppm(×1e-6)と
    読むと 2.5 ppm で過小。原著(Lane & Kalinske, 1941)か Nays2DH
    ソースコードで換算を確認してから追加する。

### 19.9 クリープの前の z のハロ交換(帯界面の実バグ。2026-10-27 修正)

- **現象**: f_fluvial と f_creep の併用で、同じ MPI バイナリの np = 1 と np = 2 の
  state.dat が一致せず、np = 2 では閉領域の土砂体積 Σ(z − z0) が 2.5e-5 m·cell
  (np = 1 は −6e-18)。差は帯界面の行(test/fluvial の箱で j = 51)に出た。
  山地渓流の計画(docs/mountain_stream_plan.md)の第 2 段でクリープを土層つきに
  拡張する前の確認で検出した。
- **原因**: calc_creep は近傍の z を読み、帯界面のエッジは両ランクがハロ行から
  冗長計算する(§11)。その直前の掃流砂(apply_edge_flux)・浮遊砂・斜面侵食・
  崩落(face 以外)は帯内の z だけを更新し、ハロを交換しない。両ランクが同じエッジを
  「自帯 = 更新後・ハロ = 更新前」の食い違った入力から計算するので、反対称性
  (= 体積保存)とランク数不変が壊れていた。splash の後の交換(§48.1)と同じ構図で、
  クリープの前だけが漏れていた。
- **処方**: calc_creep の前に、先行して z を書くプロセス(fluvial・suspend・wash・
  debris・splash・repose・rockfall)のどれかが有効なときだけ par_halo_cell(s%z)
  (判定は namelist 由来で全ランク同一 = collective 安全)。逐次ではハロ交換が
  何もしないので逐次の結果は不変。
- **検証**: test/fluvial に param_creep.txt(同じ箱 + f_creep、D = 0.01 m²/s)を追加し、
  Run.sh は Check_fluvial.py nosd(体積保存と活性。クリープは sd を動かさないので
  共動更新は対象外)、Run_MPI.sh は逐次の save とのバイト比較を行う。修正前の
  バイナリでは np = 2 が体積保存で FAIL・不一致、修正後は Σ(z − z0) = −6.2e-18 で
  np = 2, 4 が逐次とバイト一致(-Ofast 既定ビルド、OpenMPI 4.1)。逐次は修正前と
  バイト一致。影響を受けていたのは「クリープ + 先行の z 更新」の MPI 実行で、
  test/ にはその組合せの reference はない(examples/mesa・badland_round の MPI 実行は
  影響を受けていた可能性がある。逐次では影響なし)。

### 19.10 クリープが開境界の掃流砂の流出を再集計していた(実バグ。2026-10-27 修正)

- **現象**: 掃流砂(開境界の自由流出あり)にクリープを重ねると、creep_d = 1e-12 m²/s
  (寄与は 1e-7 m 程度)でも東端のセルが掘り下がった(test/sedfeed の nofeed で、300 s で

  山地渓流の第 2 段(深さ依存クリープ)を apply_edge_flux に載せる前の確認で検出した。
- **原因**: 共有スクラッチ wrk%q の「域外(x ≤ 0)の近傍に向く面スロット」(k ≥ 5 は域外

  有効セルの 4 成分だけを書き、面スロットを上書きしないので、ループ 2 の 8 近傍の発散が
  掃流砂の境界流出をもう一度集計していた。apply_edge_flux の書き手の契約(面スロットを
  0 を含めて上書き)を、崩落・側岸侵食・沿岸漂砂は守っていたが、契約より古いクリープは
  守っていなかった。面スロットに 0 以外を書くのは掃流砂だけなので、影響は「クリープ +
  掃流砂 + 開境界」で、間に面スロットを 0 にするプロセス(安息角・側岸侵食・崩落・沿岸漂砂)
  が挟まらない構成。既存の例題・チュートリアルでクリープを使うもの(badland_round・mesa)は
  掃流砂を使わないので影響なし。
- **処方**: calc_creep のループ 1 で、域外の近傍に向く面スロット(k = 5〜8)を 0 で上書きする
  (クリープは領域の外へ運ばない = 四周は壁。閉じた領域や掃流砂なしでは 0 を 0 で上書き
  するので結果は不変)。
- **検証**: test/sedfeed に nofeed_creep(nofeed + creep_d = 1e-30)を追加し、河床が nofeed と
  ビット一致することを Check_sedfeed.py の (6) で検定(修正前は 110 m で FAIL)。
  creep_d = 1e-12 では修正後も 0.16 m 違う。差を生むのはクリープ自身の寄与(1e-7 m 程度)
  だけで(1e-30 でビット一致)、それが河床低下の非線形な発達(dzmax のクリップが
  5741 エッジで発動する構成)で拡大する。このため対照には ULP 未満の値を使う。
  test/sedfeed は -fcheck=all の逐次・np = 2 と -Ofast の逐次・np = 2, 4 で全 6 構成 PASS・
  逐次とバイト一致。test/creep・test/fluvial(param_creep を含む。閉じた領域なので面スロットは
  0 のまま)は修正前と -O2 でバイト一致(save_info.txt の日時を除く)、-fcheck=all の np = 2 と
  -Ofast の np = 1, 2, 4 で PASS・バイト一致。

### 19.11 浮遊砂の巻き上げと沈降の釣り合いの解析検定(2026-10-30。test/suspend 構成 3・4)

§19.3 の残「定常巻き上げ・沈降の解析解ベンチマーク」を、test/suspend の構成 3
(param_eq.txt。平衡濃度式 1)と構成 4(param_eq_ik.txt。板倉・岸式+Rubey の沈降速度)
として加えた。コードの変更はない。

- **設定**: 南北に長い幅 1 セルの直線水路(長さ 1000 m、Δy = 1 m、勾配 0.002、n = 0.03。
  両側は河床 +2 m の乾いた地盤。make_eq.py が書く。test/uniflow の w1 を南北に置いたもので、
  MPI の帯分割が流下方向に入る)。北端の区間流入 Q = 0.469545 m³/s(Manning の等流水深
  0.5 m、V_n = 0.9391 m/s、τ* = 3.03)、南辺は自由流出、流入は清水。河床の変化が流れを
  変えないよう morfac = 1e-8(水柱側の交換は水理時間で進む。§19.3 の台帳分離)。
  dt = 0.2 s、3600 s。Check_suspend.py eq / eq_ik が state.dat の h・hs(倍精度)と流速の
  bil を水路の列で読む。
- **(1) 平衡**: 適応を終えた 250〜350 m で、C = hs/h と、その場の流速・水深から求めた
  C_eq(τ*)/β の比が 1 ± 1.5e-6(許容 1e-5)。C_eq と Rubey の w_f は users guide
  (sediment.md §4)の式を Python で独立に組んだもの(板倉・岸の Ω の erfc の比を含む)。
  構成 3 は C_eq = 5.9606e-3(β = 1.5)、構成 4 は 1.4673e-2(w_f = 0.025281 m/s、β = 1)。
- **(2) 適応**: 清水の流入点から平衡までの不足 hs_eq − hs は、流下方向に一定の比 ρ で減る。
  既定の MUSCL(f_scalar_scheme = 3)では、指数形の分布で van Leer の勾配比が r = 1/ρ で
  一定になり、面値が c_up + (c_dn − c_up)/(1 + ρ) の線形な重みになる。移流(先)と陽的な
  E-D(後)の 1 ステップの定常条件 (1 − b)[1 + 2c(1 − ρ)/(1 + ρ)] = 1(b = w_f β Δt/h、
  c = q Δt/(h Δy))から ρ = (1 − k)/(1 + k)、k = b/(2c(1 − b))(1 次風上なら
  ρ = 1/(1 + 2k))。10〜60 m の減衰率 −ln ρ がこの予測に比 0.999986(構成 3)・
  0.999997(構成 4)で一致した(許容 1e-3)。連続の解 exp(−w_f β Δy/q) より 1.2 %・1.0 %
  速いのは、主に陽的な E-D の時間の分割(1/(1 − b) 倍)による。流入点に近い数セルは、
  境界面と遠い風上のない面(セル 1 → 2)が 1 次風上なので比が違う(10 m から測る)。
- **等流・定常の確認**: 20〜350 m で h/h_n・V/V_n が 1 ± 2.4e-6、2400 s と 3600 s の hs の差は
  相対 3.5e-7 以下。下流端の自由流出の低下背水は 400 m より下流(test/uniflow と同じ)。
  試作で幅 1 列の領域(nx = 1)にすると、南端のセルが領域の角になって自由流出の面の幅が
  欠け、下流端に 0.76 m の堰上げが出た(§68.10 の副次知見と同種の角の制約)ので、両側に
  乾いた列を置いた。
- **MPI**: np = 1, 2, 4 の save_eq*/state.dat が逐次とバイト一致(Run_MPI.sh)。
- 実行時間は構成ごとに 40 秒ほど(1000 × 3 セル、18000 ステップ)。test/suspend は CI の
  対象外なので、CI の時間は増えない。

### 19.12 区間流入の面から掃流砂が流出していた(実バグ。2026-11-03 修正。挙動変更)

- **現象**: examples/delta の段 7 tidedom(川 3 m³/s、固定給砂 inflow_qb = 0.000715 m³/s
  (固体)、M2 潮汐、西辺は壁で区間流入 6 セル、南北は側方 Neumann)を morfac 60 にして
  潮 12 周期(地形 8942 h)を計算すると、給砂の 19 % が領域から失われた(同じ地形時間で
  morfac 120 は 5 %)。終了時の台帳の和(開境界の正味の流出)は 4874 m³(固体。掃流砂と
  一緒に動いた細粒分を含む。給砂 23018 m³ の 21 %)だが、南北の辺の行には砂が届いておらず
  (辺の行の流速は 0.07 m/s 以下)、流入セルの枠外の面について、出力の各フレーム(潮の
  1/4 周期ごと)の流速から同じ式で見積もった流出が給砂の 26 % になった。流入口の近くの
  河道に砂が約 1 m たまり(川が細く、給砂を運びきれない構成)、流入セルで北向き 0.5 m/s の
  流れが生じていた。修正前のコードに、開境界の流出を辺と面の向きで分ける集計を足して、
  この計算を潮 1 周期(13 周期目、地形 8942〜9687 h)続けると、正味の流出 120.5 m³(固体。
  この周期の給砂の 6 %)は全部が流入セルの面からで(北西の斜め面 120.5 m³、西の法線面
  0.004 m³)、南北の辺の行からは 0 だった。
- **原因**: bc_open_face は、区間流入の法線面だけでなく、流入区間の行のゴーストに触れる
  斜め面も開いた面として返す(bt_cell の e_bc_inflow を、その行の辺の型として引くため)。
  掃流砂の開境界面(calc_fluvial・calc_fluvial_wfsed)は、開いた面でセル流速の面法線射影
  ue が正なら容量輸送で流出させる。一方、水は法線面から規定流量で入るだけで(boundary_uvmn の
  節 2)、壁の辺の斜め面は節 1 が書かないので流束が 0 になる(§68.40 の「枠外の斜めリンクを
  欠く」)。流入セルで流れが横に振れて斜め面の ue が正になる(北西の面なら北向きの流速が
  東向きを上回る)と、掃流砂だけが、水の通らない面から領域の外へ出ていた。流入セルの流速が
  西向きになれば、法線面からも出る。容量給砂(fluv_bcfeed = 1)では、この流出も dv に含めて
  補給する(§84.9 の (a))ので入口の河床は固定のままだが、固定給砂(inflow_qb)と無給砂では、
  給砂の一部がそのまま失われる。
- **処方**: m_swflow_enc に bc_inflow_nooutflow(i, j, in, jn) を加え(bt_cell と f_bc_side
  だけを読む純関数。判定は全ランク同値)、区間流入の法線面と、壁の辺で流入区間のために
  開いた斜め面では、掃流砂の流出を計算しない(面スロットには従来どおり毎ステップ 0 を
  書く)。開いた辺(壁でない辺)の斜め面は、節 1 の辺の式で水が出入りするので従来どおり
  流出させる。
  - 容量給砂の feed_pass は変えない。流入面の選び方(面法線流速 < 0 の開面で等分)に斜め面を
    残すので、漏れが起きない計算では等分の丸めも変わらず、流入セルの流速が一時的に西向きに
    なっても給砂が止まらない。斜め面から入れる分も、入るのは同じ流入セルなので、セルの
    収支は面の選び方によらない。流入区間の両端の外側のセル(壁の辺で、斜め面だけが流入区間の
    ゴーストに触れるセル)は、濡れていて斜め面の面法線流速が負なら容量給砂を受ける。水の
    通らない面からの給砂はこの形で残るが、河道の両岸が乾いた地盤なら起こらない
    (test/sedfeed・examples/delta はこの構成)。
- **影響**: 結果が変わるのは、区間流入の面で ue > 0 かつ τ* > τ*c になったときだけで、
  それ以外は条件が一つ増えただけでビット一致する。流入区間と掃流砂を使う例題
  (examples/delta・meander・meander_cutoff・mountain_valley・bedrock_cover・debris_bedrock)の
  うち、再計算したのは delta の段 7(smallq・tidedom と、tidedom の morfac 120・60 の確かめ)と
  段 6 の tide。終了時の台帳の開境界の正味の流出(固体)は、smallq 3557 → 0 m³、tidedom
  15041 → 567 m³(地形 14904 h。給砂の 69 % → 99 % が残る)、morfac 60 4874 → 344 m³ で、
  入口の漏れがなくなった分だけ砂の収支が閉じた。ただし漏れの有無で流れの配分が変わるので、
  morfac 120 の計算は、修正後に干潮の水路が南の辺に届いて給砂の 40 % を辺から出した
  (修正前は 5 %。辺から出る量は計算ごとに大きく違う。README 段 7)。段 6 の tide(川 30 m³/s)は
  全出力が修正前とバイト一致した(入口の河道に砂がたまらず(入口から 25 m の河床の変化は +0.002 m。
  tidedom は +0.84 m)、流入区間の面で漏れの条件が一度も成り立たなかった。台帳の 15969 m³ は南北の
  辺から出た分)。他の例題は再計算していない(handoff)。
- **検定**: test/sedfeed に qbturn を加えた(qb の流入セルの東隣 (2, 8〜10) を +2 m の乾いた
  地盤にして、流入した水を北の 2 行へ曲げる。Check_sedfeed.py の (8))。修正後は台帳
  (1 − λ) Σ(z − z0) A = ∫Qb dt × morfac が相対 9e-13 で閉じ、開境界の流出はない。修正前の
  コードでは、0.412 m³(給砂 6 m³ の 6.9 %)が流入セルの北西の斜め面から出て、台帳の相対差
  −6.9 % で FAIL する。
- **検証**: 流入区間と掃流砂を使う回帰テストのうち、reference のある taupart はビット一致。
  検定だけのテスト sedfeed(qbturn を含む 7 構成)・bedfines・bendsed・wave_river・fixation・
  dbrock・hillsoil・rockinc は PASS。-fcheck=all の逐次で sedfeed の qbturn・feed1 が完走。
  公開インターフェースを足したのでトップレベルの make を通した(utils も OK)。MPI(OpenMPI、
  同じ最適化の MODE = mpi のビルド)では、test/sedfeed の Run_MPI.sh 2・4 が 7 構成すべてで
  逐次の state.dat とバイト一致し、検定も PASS(判定は大域の境界の型だけを読み、通信を足して
  いない)。
