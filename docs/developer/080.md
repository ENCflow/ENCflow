## 80. x 方向の確保範囲 dcp%ish/ieh(第二段 C。2026-10-16 設計合意・実装)

設計の比較(案 C1/C2/C0)と見積りは docs/xwindow_plan.md。採ったのは案 C1 =
帯確保と同じ型で**配列の下限を変えるだけ**(添字は全域のまま)。

### 規約

- `dcp%ish = max(1, iw1 − nhalo)`, `dcp%ieh = min(nx, iw2 + nhalo)`。iw1/iw2 は
  `g%wxg(1:2)` = 全域窓の行 jw1..jw2 にわたる `g%wx(1,j)` の最小・`g%wx(2,j)` の
  最大(calc_wxy が wy と同時に求める)。x は分割しないので全ランク同一。
  par_decomp_init の引数に iw1, iw2 を足した(公開インターフェース変更。
  utils はトップレベル make で追随を確認)。
- 帯配列の確保は `a(dcp%ish:dcp%ieh, dcp%jsh:dcp%jeh)`、ダミーは
  `a(dcp%ish:, dcp%jsh:)`(§12)。番兵つき(g%x, g%sw)は `ish−1..ieh+1`、
  エッジ配列は `(k, ish−1:ieh, jsh−1:jeh)`、ダミーは `a(1:, dcp%ish−1:, dcp%jsh−1:)`。
  全域一時配列(`1:nx, 1:ny`。rank0 の入力・出力バッファ・ts 系)は従来のまま
  で、帯への切り出しは `ts(ish:ieh, jsh:jeh)`。
- **全域バッファ ⇄ 帯配列の受け渡し(並列層)**: 帯の第 1 次元が全域より狭いので
  Gatherv は窓形 `(ish:ieh, jw1:jw2)`(エッジは `(:, ish−1:ieh, jw1−1:jw2)`)の
  受信一時に受け、rank0 が全域バッファへ写す。scatter は rank0 が
  `buf(ish:ieh, jsh_r:jeh_r)` の部分配列を送る(非連続の copy-in。初期化の
  1 回きり)。逐次版は 1 行の部分配列代入。halo 交換・edge_merge は
  `size(a, 1)` を使っていたので不変。
- 時間ループのセルループは従来どおり `g%wx`。初期化・補助の全幅ループ
  (`do i = 1, g%nx`)で帯配列に触るものは `dcp%ish, dcp%ieh` に揃えた
  (nh 31、channel 9、conduit 6 ほか)。全域一時に対する全幅ループは不変。
- ネスト: 子の作業配列 `inband(ilo:ihi, jlo:jhi)`・`ev(2,4, ilo−1:ihi, jlo−1:jhi)`
  (ilo/ihi = 子の ish/ieh)。親側の窓の写し(capture)・置換(restrict)・保存
  修正(reflux)は親の ish..ieh に、子側は子の ilo..ihi に収める(子の足場が
  親のマスク外へ張り出す分は両側ともマスク外なので 0 のまま)。nest_import /
  nh_import は列範囲 ilo/ihi を引数に取る。
- 辺境界(m_boundary)の基準水位の導出は列 1 / nx が確保範囲にあるときだけ
  読む(窓が領域端に達しないマスクでは辺境界に有効セルがない)。

### 窓 = 全幅のとき

ish = 1, ieh = nx で従来と同じ確保。回帰テストの大半はこれに当たり、結果は
ビット一致(等価変換)。窓 ≠ 全幅の検証は埋め込みケース(秩父 560×300 を
5600×3000 に埋め込み。マスクの列 79..498 → ish = 2596, ieh = 3021)と、
マスクが領域端に達しない chichibu(ish = 76, ieh = 501)で行った。

### 計測と検証(2026-10-16)

- 埋め込みケース(5600 × 3000、マスク 1/100、30 分 = 720 ステップ、4 スレッド):

  | | (B) まで | (C) |
  |---|---|---|
  | 最大 RSS(初期化ピーク) | 1.82 GB | 1.43 GB |
  | 時間ループ中の RSS(VmRSS を 1 s ごとに採取) | — | 0.38 GB |
  | 所要時間 | 49 s | 42 s |

  時間ループ中の 0.38 GB の内訳は rank0 の全域配列(入力地形 g%z 134 MB、
  出力バッファ wk_out・wk_out_i 201 MB)が大半で、帯配列は数十 MB。初期化
  ピーク 1.24〜1.43 GB は全域一時(ts 系 8 枚 ≈ 1.07 GB)と text 読み込み。
  **帯配列については目標どおり窓の面積に比例し、残りは第二段 (D)(全域一時と
  rank0 全域配列の窓化)の対象**(xwindow_plan.md §1 の見積りどおり)。
  秩父 30 分(窓 76..501 列)は 83 MB → 64 MB。
- 結果の同一性: 埋め込みケース・秩父とも、(B) までの結果と Log・CSV・分布
  ファイルが同一(Z0000 だけが窓外の列で 0 になる = §79 で行について述べた
  「窓外は gather されずバッファの 0」が列にも及ぶ。窓内は同一)。MPI np=2, 4 の
  埋め込みケースは逐次と全ファイル同一。
- 回帰(規律 2・3): -O0 -fcheck=all の逐次(秩父 30 分・埋め込み・chichibu 6 h・
  nest_identity・nest_twin。make.inc の FFLAGS を変えてドライバも同じフラグで)と
  MPI(秩父 np=2, 4・埋め込み np=2)が境界エラーなく完走。release で reference
  付き 24 ケース、nest_identity・nest_twin・bmi_nest・bmi_vars・gvchange、MPI
  np=1, 2, 4 の 6 ケースと nest_identity np=2 がすべて PASS。トップレベル make
  で utils/rerecord の par_decomp_init 呼び出しの追随漏れを検出し修正した。
- 検証中に見つけた自分の取りこぼし: g%sw の確保は番兵なし (1:nx, 1:ny) なので
  列の縮小範囲は `max(1, ish−1)..min(nx, ieh+1)`(y の規則と同形)。番兵つきと
  同じ `ish−1..ieh+1` を与えて -fcheck が止めた(規律 3 の効用)。
- **実バグ(2026-10-17 発見・修正)**: get_diff_v1(旧移流スキーム 1 の速度勾配。
  m_swflow_enc_adv)と get_diffusion(拡散項。m_swflow_enc_diff)の g%x の
  ダミーが `x(0:, dcp%jsh-1:)` のまま残っていた(248 箇所の機械置換の取りこぼし)。
  g%x は ish−1..ieh+1 で確保されるので、窓が列 1 から始まらないケース
  (流域マスクつきの秩父等)では x(in,jn) が ish−1 列だけ右の値を読み、
  マスク外セルの重みがずれる。スキーム 1 の秩父 200 m(チュートリアル補足の
  `f_advection_scheme = 1`)で測線 4 のピークが 5,714 → 5,952 m³/s(+4 %)に
  変わっていた。上の回帰が見逃した理由: reference 付きケースのスキーム 1 は
  全幅格子(ish = 1 → 0: と一致)しかなく、窓つきケース(chichibu・chichibu_icmap)
  は既定のスキーム 3(get_diff_v1 を通らない)で、-fcheck の検証もその組合せ
  だった。修正は両ダミーを `x(dcp%ish-1:, dcp%jsh-1:)` に揃えるだけで、
  スキーム 1 の秩父 200 m は列窓化直前(47babb9)の結果とビット一致に戻った。
  **教訓: 「全ケース PASS」は reference が覆う経路の範囲でしか意味を持たない。
  確保範囲を変える変更では、-fcheck の検証を既定でない経路(スキーム 1・拡散項・
  NH 等)× 窓つきケースの組合せまで広げること**(規律 3 の対象範囲の明確化)。
- **実バグ(2026-10-22 修正)**: 全域添字 `1:g%nx` を列窓確保の配列へ転記する
  2 箇所が残っていた。m_swflow_enc_nh `zprev(:,j) = s%z(1:g%nx,j)`(f_nh_bottom
  の初期化)と m_bedmotion load_snapshot `d(:,j) = wk(1:g%nx,j)`(全域形の
  スナップショット)。両者とも左辺は ish:ieh で確保されるため、列窓が縮む
  マスクでは形状不一致(-fcheck=all: 「Index '1' … outside of expected range
  (18:783)」)。reference 付きの NH・bedmotion ケースは全幅格子しかなく、上の
  教訓そのものの見逃し。修正は右辺を `s%z(:,j)` / `wk(dcp%ish:dcp%ieh,j)` に
  するだけで、全幅格子ではビット一致(nhbottom の構成 1・3 を旧実行ファイルと
  Log 一致で確認)。検証は test/nhbottom の param / param_bm に両側 20 列の
  領域外マスクを加えた scratch を -fcheck=all で実行(修正前は停止、修正後は
  完走)。MPI 環境がなく np ≥ 2 は未実施(列窓は全ランク同一なので逐次で同じ
  経路)。文書照合(§35.1 の横断チェック)の副産物として発見。
