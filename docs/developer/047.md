## 47. 淡塩2層(鋭利界面)モジュール m_saltwater(fn_salt。2026-08-18 実装)

地表水と浅層地下水(層1)に塩水層を導入し、SWI2(MODFLOW)型の
準静的・鋭利界面近似で塩水くさび・海水浸入・淡水レンズ・塩害を扱う。
設計の正本は docs/swi_plan.md(§8 の推奨は 2026-08-18 に全項承認)。

### 47.1 設計決定

- **簿記**: s%h / s%hg は淡塩合計のまま。塩水層厚 s%hss / s%hgs は
  合計の内数で常に層の最下部(鋭利界面・即時入替規則)。密度 2 値・
  Boussinesq 近似。ε = (ρs−ρf)/ρf は塩水層の駆動水頭にのみ現れる:
  Φf = η、Φs = η + εζ(運動方程式は不変 = 方針 §0「SWE+1方程式拡散が
  上限」の内側。2層運動方程式は双曲性喪失の難点もあり不採用)。
- **完全加算方式**: 2 zone 合計流束 = T∇η + εT_s∇ζ と分解できることを
  利用し、第1項(既存の lateral_core / SWE が計算)には触れず、
  塩水 zone 流束(hgs 更新)とその ε 成分(hg への追加)だけを加算する。
  swflow・gwflow は無変更(swflow は移流フック追加のみ)。
  無効時ビット一致が構造的に成立する。
- **単一モジュール m_saltwater(fn_salt)** が hss・hgs・海側境界・
  リスタートを所有。地表移流は swflow_enc の汎用スカラーカーネル
  advect_scalar に相乗り(salt_active フラグ+分担率 α = share 引数。
  cq/hs と同じ二重バッファ・コミット様式)。
- **海側境界**: 海域セル(sw>0)= 全塩水・水位 = 潮位(s%e。m_tide が
  強制)。地下は規定水頭交換(塩水は双方向で hg・hgs を同時更新、
  淡水は流出のみ。等化量で制限)。地表は「hss(海) = h(海)」の維持
  だけで、遡上・氾濫による塩水輸送は既存の移流フックが自動的に担う。
  追加の交換係数は置かない(帯水層 K が支配。§8 推奨どおり)。
- **地表の底層重力流**: Manning 型 q = (1/n_i)·h_s^{5/3}·√(|ΔΦs|·rdr)
  (|ΔΦ| < eps_h は線形化)。交換流なので h に触れない。安定条件は
  ∂Φ/∂hss = ε の線形化枝で評価し、m_glacier と同じ適応サブサイクリング
  (hss 最大の allreduce → 分割数。決定的)。
- 蒸発散・浸透の淡塩配分は未実装(暗黙に淡水扱い。swi_plan 段 4)。
  整合は calc 冒頭のクランプ(hss ≤ h、hgs ≤ hg)が保証する。
  → 浸透・飽和湧出の配分は 2026-10-29 に f_salt_exch で実装(§47.5)。
  蒸発散・層2・管路層は引き続き暗黙に淡水。

### 47.2 既知の数値特性(実測 2026-08-18)

> 2026-10-29: 次の時間分割誤差は、塩水 zone を側方流の直前の状態で評価する修正
> (§47.7)で解消した(test/salt B で Hgs = Hg = 0.5000)。記録として残す。

- **時間分割誤差(加算方式の代償)**: lateral が先に η を動かし、
  塩水 zone が更新後の η を読む逐次分割のため、急速充填の前線で
  hg − hgs(見かけの淡水)が生じる。**dt に比例する 1 次誤差**で、
  dt 半減で半減することを実測確認(test/salt param_sea: K=0.01 m/s の
  極端ケースで dt=1.0 → 最大 5%、dt=0.25 → 1.5%)。平衡水頭は正しく
  (hg → 解析値 0.500)、誤差は zone 配分のみ・前線局所。実用の K
  (10^-4〜10^-3 m/s)では無視できる。恒久対策が要る場合の代替は
  lateral_core の 2 zone 一体求解版への置換(等価リファクタとして
  淡水のみ極限のビット一致で検証可能)— swi_plan §8 に記録。
- **ガードの単位**: 塩水 zone カーネルの乾燥判定・過大流出抑制は
  lateral_core と同じ**飽和帯厚単位**(b = hgs/sy)で書くこと。柱状量
  単位だと sy 倍保守的になり、前線で塩水輸送だけが削られる系統誤差に
  なる(実装時に実検出・修正)。

### 47.4 初期化順の修正(2026-10-22): tide init を saltwater init より前に

- **症状**: m_saltwater_init(海セルの hss = h)が m_tide_init(海セルの
  h = hsea0)より前に走っていたため、海セルの初期 hss が初期条件の h
  (h0・e0 − 0)になり、潮位の初期適用後は hss ≠ h。ステップ末の維持
  (5)が走るまでの**最初の 1 ステップ**だけ、海セルの供給濃度 hss/h が
  h_init/hsea0 になっていた(海の初期水深 0 なら最初のステップの流入が
  淡水)。1 ステップ限りで実害はほぼないが「海は常に全塩水」の設計と不一致。
- **修正**: m_main の初期化順を tide init → saltwater init に入れ替えた
  (tide init は state より後・swflow より前であればよく、saltwater init は
  gwflow init より後であればよい。両制約を満たす)。
- **検証**(gfortran 13.3 / serial): test/salt 模式実験 A は identical、
  海水浸入ケース(f_salt_surf=0)と test/tide も不変。test/tide に fn_salt
  (f_salt_surf=1)を加えた構成で、開始状態の海セルの Hss0000 が 1.0 = hsea0
  (修正前は h0 = 0.5)になることを確認。

### 47.5 地表—層1 の交換の淡塩配分 f_salt_exch(2026-10-29 設計合意・実装)

swi_plan 段 4 のうち浸透・飽和湧出の淡塩配分。動機は河口堰の例題
(examples/estuary_barrage)で、感潮河川を遡上した塩水くさびが河床から帯水層へ
入り岸の地盤へ広がる経路を表すため(それまでは浸透・湧出が暗黙に淡水で、
河川経由の地盤の塩水化は原理的に出なかった)。

- **規則(ユーザー承認。swi_plan §3.5 の当初案から変更)**:
  浸透は**底層の塩水から先**(fs = min(fx, hss)。地下は即時入替で最下部へ)、
  飽和湧出は**帯水層の上部の淡水から先**(淡水で足りない分だけ塩水が地表の
  底層へ)。§3.5 は「浸透は淡水部分から(全塩水のときだけ塩水)」だったが、
  鋭利界面では河床・地表に接するのは塩水層で、淡水が塩水層を通り抜けて先に
  浸透するのは描像と合わず、遡上海水の塩害を過小にもする。濃度比例(hss/h)案は
  鋭利界面と不整合なので採らない。独自の簡略化として users guide salt.md に明記。
- **有効化**: f_salt_exch(&list_salt)。未指定なら f_salt_surf=1 かつ
  f_salt_gw=1 のとき 1、それ以外は 0。1 の明示に片方の層しかなければ停止。
  既定 1 は両層併用時の挙動変更だが、既存の回帰ケースは片方の層だけ(test/salt
  A = 地表のみ、B = 地下のみ)なので reference は不変。0 は「河川経由なし」の
  比較用に残す。
- **結合(fxg と同型の契約)**: 記録場 s%fxsli(地表→層1 の浸透量。h 基底)を
  鉛直モデル(Green-Ampt・バケツ。河床交換能の置き換えを含む)が書き、
  s%fxslo(層1→地表 の飽和湧出量)を lateral_core のループ2(層1の湧出と、
  層2の超過が層1を経て湧出する連鎖)が書く。m_saltwater が読んでゼロ戻し。
  確保は m_saltwater_init(f_salt_exch=1 のときだけ。無効時は未確保・分岐なし)。
  wq の s%fxg と共用しない(読取とゼロ戻しの順序を 2 モジュールで調整する
  結合を避ける。メモリは有効時だけ 2 面)。
- **配分の時点**: 浸透は calc 冒頭 (0) で配分する。**湧出は塩水 zone の流束
  (3) の連続式の後**で配分する(gw_salt_zone のループ2で、側方流の記録+その場の
  湧出を上限に hg を超えた hgs を地表へ)。冒頭で配分すると、側方流が合計を
  先に溢れさせ、その分の塩水は (3) で後から届くため、配分時点では超過がなく、
  届いた塩水が整合クランプで消える(test/salt C2 の初版で実検出: 全層塩水の
  帯水層からの湧出が Hss = 0 のまま、塩水体積が 15 % 減)。上限を湧出量に
  するのは、層2への浸透・蒸発(暗黙に淡水)で hg が減った分の超過を湧出と
  取り違えないため。
- **既知の数値特性**(users guide に転記):
  1. 即時入替との組では「満潮で塩水が入り、干潮で上部の淡水が出る」片方向の
     交換になり、くさびが乗る河床の直下は全層塩水に向かう(上限側の評価)。
  2. (→ §47.7 で解消)湧出面(地表水のある飽和セルと不飽和セルの境)では、層1の水頭が地表水深の
     分だけ飽和の判定で不連続に切り替わる(§16.5)ため、境のエッジが 2 つの
     水頭状態を往復する。合計(lateral_core、時刻 n の状態)と塩水 zone
     (gw_salt_zone、側方流の更新後の状態)が別の状態で流束を評価するので、
     往復のステップで塩水 zone の流束が合計と逆向きに評価され、整合クランプ
     (冒頭の hgs ≤ hg と連続式の後のクランプ)が塩水を消す。**dt を小さく
     してもほとんど減らない**(test/salt C2 の 2 時間: dt 0.5 / 0.25 / 0.125 /
     0.0625 s で塩水の減少 15.9 / 14.8 / 14.0 / 13.5 %。往復の回数が 1/dt に、
     1 回の誤差が dt に比例するため)。f_salt_exch=0 でも同じ機構で減る
     (同 19.2 %)。冒頭の
     クランプだけを外しても変わらない(連続式の後のクランプが同じ量を消す。
     実測)。恒久対策の候補は §47.2 と同じ「2 zone 一体求解」で、具体的には
     塩水 zone の ∇η 成分を lateral_core のエッジ流量 Q から b_s,e/b_e·Q として
     作り(合計と同じ状態で評価)、ε 成分だけを加算する形への置換。層1の
     エッジ流量を塩水側へ渡す結合(共用スクラッチ glt%q は層2・管路層が上書き
     する)が要るので、設計判断として handoff に記録した(未着手)。
     → 2026-10-29 の追加調査で、塩水 zone の η と飽和判定を側方流の直前の状態の
     写しで評価する方式(式は不変)に修正案を改めた。試作で C2 の損失 16 % →
     0.02 %、§47.2 の分割誤差も消える。例題 estuary_barrage の「交換ありでくさびが
     縮む」結果はこの特性によるもの(修正後は 2.6〜2.9 km まで入る)。詳細は
     §47.7。
  3. 薄膜(h ≲ dd)の湧出が斜面を流れる場所では、地表のスカラー移流が
     hss ≤ h を保たず、冒頭の hss ≤ h クランプで塩水が減る(C2 の初版 = 斜面
     全面からの薄膜湧出で実測。窪地へ湧き出る構成に改めた)。
- **見つかった既存の不具合(→ §47.8 で修正)**: 地表の底層重力流
  (surf_gravity_current)は河道の堤防(fn_bank / bank0)・海岸堤防の仮想壁を
  見ない。test/gwbed の構成(堤防で隔てた堤内地と河道)に塩水を置くと、
  堤内地の地表の塩水が 1 ステップで半分、壁を越えて河道へ移る(実測)。
  浅水流の移流はフラックス経由なので壁を守る。修正には swflow の壁判定を
  m_saltwater へ公開する結合が要る(現状 zbank を読むのは m_swflow_enc の
  サブモジュールだけ)。河口堰の例題は堰・岸を地形で与えるので影響しない。
- **検証(gfortran 14.2 / OpenMPI 4.1)**:
  - test/salt 模式実験 C1(param_exch_in.txt: 平坦閉領域、h 1.0 のうち塩水
    0.4、空の帯水層容量 0.3): 終状態 H 0.7・Hss 0.1・Hg 0.3・Hgs 0.3 を
    倍精度の保存状態で相対 6e-16 以内(Hgs と Hg はビット一致)、
    Hss + Hgs = 0.4 を全桁で保存(Check_exch.py)。f_salt_exch=0 なら
    Hss 0.4・Hgs 0 のまま。
  - 模式実験 C2(param_exch_out.txt: 斜面の全層塩水の帯水層が窪地へ湧出):
    窪地の地表水の Hss/H = 0.19(f_salt_exch=0 では 0。dt を小さくすると
    0.24 / 0.28 / 0.30 と増える)。塩水体積の減少は上の数値特性 2。
  - MPI: C1・C2 の np=1, 2, 4 が逐次と Log.txt・state.dat・saltwater.dat まで
    バイト一致。gfortran -Og -fcheck=all(snan・invalid トラップ)の np=2 で
    C1・C2 と、河道マスク+河床交換能+塩水の構成(test/gwbed の地形に
    塩水を置いたもの。§47.6)がクリーン完走。
  - 無効時(既存ケース)の逐次回帰は §47.6 の検証と合わせて記録。
  - 例題 examples/estuary_barrage(実装当初の数値。§47.7〜47.9 の修正後の数値は
    §47.10。3.6 km × 0.96 km・40 m 格子・M2 ±0.6 m・
    K_sh 1e-2 m/s・20 日。堰 = 河口から 500 m の天端 +1.0 m の地形):
    帯水層の塩水量は 交換なし 37(堰なし)/ 34(堰あり)千 m³ = 海岸からの浸入だけで
    堰の効果が出ない、交換あり 554 / 267 千 m³。堰なしでは河床下が河口から
    1.16 km まで全層に近く塩水になり岸へ 200 m ほど広がる。堰ありでは堰の下流に
    留まり、上流の河床下は 1.7 %(帯水層の底に沿って堰の下を 0.56 km くぐる舌)。
    交換ありでは河床からの浸透がくさびの塩水を取り込み、堰なしの河道の底層塩水が
    524 → 66 千 m³、くさびの先端が河口から 2.5〜2.8 km → 0.2〜1.0 km に縮む
    (K_sv = 1e-4 m/s を河床にも与えた模式設定。目詰まりした河床では小さい)。

### 47.6 河床交換能の上限を塩水 zone の流束にも(2026-10-29 合意・実装。挙動変更)

§16.5 の河床交換能 k_bed は層1の lateral_core(合計の ∇η 成分)だけに上限を
かけ、塩水 zone は対象外だった。全層塩水の帯水層では塩水 zone の流束が合計と
同じ大きさになるはずなのに、塩水側だけ K_sh の Darcy 流量で流れるため、
河道との境で合計と塩水が食い違い、整合クランプで塩水が消えていた。

- **修正**: gw_salt_zone のエッジ流量に、河道・非河道間のエッジだけ
  |q_s| ≤ k_bed(河道側セル)· l_k · b_s,e(界面の塩水飽和帯厚)の上限をかけ、
  ε 成分 qb にも同率を適用する(lateral_core の k_bed·l_k·h_e と同型。全層
  塩水なら合計の上限と一致)。無効時(s%kbed 未確保)は分岐に入らない。
- **検証**(test/gwbed の地形・k_bed = 1e-5 m/s・堤内地の帯水層を全層塩水、
  地表は淡水、1800 s): 堤内地から出た塩水 0.0038 m(上限の積算 0.0075 m 以内)。
  修正前は 0.1998 m(全量)が出て、河道の帯水層に届いたのは 0.0089 m(残りは
  クランプで消滅)。
- f_gwbed と f_salt_gw の併用は既存の回帰ケースにないため reference は不変。

### 47.7 塩水 zone を合計と同じ状態・同じ組成で評価する(2026-10-29 合意・実装。挙動変更)

§47.5 の数値特性 2(湧出面で塩水が消える)と §47.2 の時間分割誤差の恒久対策
(利用者承認の修正案 1)。どちらも、合計(lateral_core)と塩水 zone(gw_salt_zone)を
**別の状態・別の厚さ**で評価して流束が食い違い、整合クランプが差を塩水で埋めて
いたことが原因。

- **同じ状態(写し)**: gwflow_lateral_calc がハロ交換の直後に hg・h を写し
  (s%hgsnap・s%hsnap。f_salt_gw=1 のときだけ確保。帯+ハロ)、gw_salt_zone は η と
  飽和の判定(+h)をこの写しで評価する。式は不変。それまでは側方流が動かした後の
  状態で評価していたため、飽和の判定で水頭が地表水深ぶん切り替わる湧出面では
  塩水 zone の流束が合計と逆向きになるステップがあった
- **calc 冒頭の hgs ≤ hg のクランプを外す**: 側方流が先に動かした合計に対応する
  塩水を、直後の塩水 zone が運ぶ前に消していた。連続式の後のクランプは残す
- **同じ組成(界面厚)**: 合計の界面飽和帯厚は両セルの全厚の算術平均を上流側で
  キャップ、塩水は両セルの塩水厚の平均を上流側でキャップしていたため、全層塩水の
  セルが淡水を含む隣へ流れると塩水の流束が合計より小さく、無いはずの淡水の流出が
  生じた(試作の検定 C4a で実検出: 下部 4 割が塩水の帯水層から窪地へ湧く構成で
  2 時間に 9.5 %)。合計と塩水が同じ向き(η と Φs の上流側が同じセル)のときは
  b_s,e = h_e ×(上流側セルの塩水割合)とする = セルから出る水はそのセルの組成。
  逆向き(海水浸入の先端)は従来の形。流束は K·b_s,e·∇Φs の形のままなので、Φs が
  水平なら流束 0 の平衡は保たれる。全層塩水が上流側なら η と Φs の向きは必ず一致
  する(ζ = η なので)ことも確認した
- **dt_gwflow との同期**: 地下の塩水の処理(塩水 zone・湧出の配分・海側境界)は
  側方流が走ったステップだけ同じ実効刻み(s%gw_dts。m_gwflow_init が設定)で実行
  する(s%gw_lat_done を gwflow_lateral_calc が立て m_saltwater が下ろす)。安定
  条件の検査も実効刻みで行う。それまでは毎ステップ dt で非同期だった
- **却下した案**: 塩水 zone の ∇η 成分を lateral_core のエッジ流量 Q から
  (b_s/b)·Q で作る分率形。塩水が淡水流に逆らって入る前線で上流側の取り方が合計と
  食い違い、平衡も崩す。写しと界面厚の整合だけで足りた
- **検証**: test/salt B が Hgs = Hg = 0.5000(1.5 % の不足が消えた)、C2 の塩水の
  減少 16 % → 0.02 %・窪地の Hss/H 0.19 → 0.999、C3(dt_gwflow = 2 s)同等、
  C4a・C4b が相対 7e-14 で保存。test/salt A は reference とビット一致(地表のみ)。
  np=1, 2, 4 が逐次とバイト一致、-fcheck=all の np=2 がクリーン。例題
  estuary_barrage の結果は §47.10

### 47.8 地表の底層重力流の敷居(2026-10-29 合意・実装。挙動変更)

§47.5 末尾の不具合(重力流が堤防・海岸堤防の仮想壁を見ない)の修正(修正案 2)。

- 各エッジの**敷居** = 両セルの高い方の河床。河道と堤内地の境は堤防の天端
  (g%zbank。河道セル持ち)、海側と陸の境は海岸堤防の天端(g%zswall。陸側セル
  持ち)でも上げる(浅水流の壁と同じセル対)。越えられるのは上流側の塩水層のうち
  敷居より上の部分だけ。敷居が上流側の河床より高いときだけ厚さを削るので、平坦・
  下り勾配のエッジは従来とビット一致(test/salt A で確認)
- 壁の天端は geoinfo の静的データ(scatter_band_r 後は帯+ハロ)で足り、swflow との
  新しい結合はない。破堤(list_channel_breach)の天端の時間低下は追わない(破堤口の
  水は移流で塩水を運ぶので、止まるのは底を這う分だけ。users guide に記載)。
  f_bank_mode(フラップ等)は重力流では区別しない(天端までは不透過)
- 地形の段(固定堰の天端など)にも効き、越える厚さを天端より上の分に限る
- **検証**: test/salt D1(堤防)・D2(海岸堤防): 陸の全層塩水(界面 +1.2 m)と淡水の
  河道・海側(天端 +2 m)。陸 Hss = 1.2・河道/海側 Hss = 0・H 不変を全桁で保つ
  (修正前は約 98 % が壁を越えた)。np=1, 2, 4 がバイト一致、-fcheck=all の np=2 が
  クリーン

### 47.9 f_salt_exch=2: 湧出を混合比で配分する感度ケース(2026-10-29 合意・実装)

§47.5 の数値特性 1(即時入替による片方向の交換で河床直下の塩水化が上限側)に対する
任意案。湧出量に湧出前の塩水の割合 hgs/(hg + 湧出量) を掛けた分を地表の底層へ移す
(浸透した塩水が沈む前に混ざって戻る極限)。浸透の配分は 1 と同じ。新しい状態はなく、
数行の分岐。既定 1 との幅で河川経由の塩水化の大きさを示すために使う。
- **検証**: test/salt C4a(=1)・C4b(=2)はどちらも塩水体積を相対 7e-14 で保存し、
  窪地の水の塩水割合は 0.051 < 0.075(混合して湧く分、塩水が地表へ戻る)
