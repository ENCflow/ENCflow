## 45. 氷河モジュール m_glacier(fn_glacier。2026-08-16 実装)

設計・定式・初期条件論・既知の妥協の正本は **docs/glacier_plan.md**。
ここには他 § と関わる規約だけを書く。

- **構成**: 独立モジュール(fn_glacier / &list_glacier)+内部は加算的
  フラグの重ね合わせ(G1 質量収支=常時、G2 SIA 流動 f_glflow、G3 滑動
  f_glslide・侵食 f_glero、G4 雪崩 f_glava)。気温(fn_meteo)と積雪
  (fn_snow。涵養源)が必須。積雪の有効判定は allocated(s%swe)で行う
  (プロセス層どうしの use を避ける)。STG 非対応(geomorph と同じガード)。
- **状態**: s%hi(m 氷柱。有効時のみ確保)。場出力 Hi。リスタートは私有
  ファイル glacier.dat(契約5)。S 台帳には水当量(×s%gl_ir)で算入
  (swemean と同じ扱い。m_state の himean)。
- **実行順序**(§2.2 の結合仕様に追加): snow_calc の後・boundary/swflow の
  前に glacier_calc。毎ステップ=氷面度日融解(水は dt×1 で h へ、氷は
  ×morfac)。dt_glacier tick =雪崩→氷化→SIA 流動→侵食の順(ヘッダが
  契約)。侵食は s%z・s%sd を共動更新し、e 回復と z/sd のハロ交換まで
  自分で行う(geomorph_calc と同じ契約)。
- **morfac は全プロセス共通の1個**: m_geomorph_init が s%geo_morfac を
  通知し、m_glacier_init が gl_morfac との同値を検査(不一致は par_stop)。
  氷⇄水の交換は MORFAC 台帳分離(§19.3 と同型。glacier_plan.md §2.1)。
- **SIA の陽解法は適応サブサイクリング**: tick 内で D_max の
  allreduce_max から分割数を動的決定(全ランク同一 = collective 安全)。
  サブサイクルごとに hi のハロ交換。エッジ流量はドナー律速
  (1エッジ ≤ ドナー氷体積の 1/4)で hi>=0 を構造的に保証。
- **【実バグ】.and. の短絡評価は保証されない**: `g%x(in,jn) > 0 .and.
  g%sw(in,jn) <= 0` は g%sw(0 縁取りなし)を範囲外で読み得る
  (-fcheck np=2 で実検出)。近傍検査は g%x(0 縁取りあり)を先に、
  g%sw をその内側で入れ子にする(calc_creep と同じ流儀)。
- **m_meteo の拡張**: tempofs(長周期 ΔT 系列。t_cycle で折り返さない
  実時間軸)と f_prec_lapse(降水の標高倍率。m_precip_makepre が mt を
  受けて更新時に乗じる — 更新のたび元データから作り直すため二重適用は
  ない)。無効時はビット互換。makepre の引数追加に伴い utils 追随は
  トップレベル make で確認済み(§10)。
- **検証**(gfortran 13.3/OpenMPI): 無効時=全回帰ケースがビット一致
  (逐次+np=1,2,4)。有効時= test/glacier の Halfar 相似解(平均誤差
  1.2% H0・体積保存 1.8e-15。2026-11-03 の §45.1 の修正後は 0.16%)+カール
  形成スモーク。-fcheck=all np=2 クリーン。詳細は glacier_plan.md §7。
- **侵食の結合長**(gl_lc。§45.3): 侵食の τb を、駆動応力のベクトルを氷の中で
  ガウス核で平均したものにする(既定 max(500 m, 2Δx)。§45.4。0 で局所の τb)。
  局所の τb の千年規模の侵食は格子規模の溝・穴が育って止まる。

### 45.1 SIA の拡散係数を勾配の大きさで評価する(格子の向きによる歪みの修正。2026-11-03 挙動変更)

- **現象**: 平坦床の Halfar ドーム(test/glacier 構成 1)で、氷が格子軸の方向へ
  偏る。修正前のコードでは、斜めの方向の扇形の氷の体積が格子軸の方向より 5.7% 少なく
  (同じ分け方の解析解では 0.3%)、氷縁から 2 セルより内側の誤差が −8.9〜+6.0 m で
  格子軸の方向と斜めの方向で符号が逆の模様になり、中心は解析解より 4.7 m 厚い。
  円錐山体(構成 2 から雪崩を外したもの)では、山頂から 1000 m の円周上で格子軸の
  方向の氷厚が斜めの方向より 19% 厚く、侵食深は 42% 深い(カールの図の 4 方向の筋)。
  溶岩流の同じ型の歪み(§51.4)を直したとき、氷河に残る項目として handoff に
  記録していた。
- **原因**: エッジの拡散係数 D = (Γ H⁵ + As(ρi g)³ H⁴)|∇s|² の |∇s|² に、エッジの
  法線方向の勾配の 2 乗 (Δs/dist)² だけを使っていた(Mahaffy 型の簡略版)。氷面が格子に
  対して 45° に傾くと、各エッジの法線勾配は |∇s|/√2 に見えるので D が 1/2 になり、
  斜めの方向の流量が半分になる(landslide_tsunami_plan.md §11 が「SIA なら対角の D が
  1/2」と予告していた歪み)。
- **修正**: D の |∇s|² を、法線勾配 Sn = Δs/dist と接線勾配 St の 2 乗和 Sn² + St² に
  する。エッジの向きは線形項(流量 = D・Sn・通過幅)にだけ使う。接線勾配の取り方は
  §51.4 と同じ規約(m_glacier の edge_tslope・cell_tslope・ice_cell): エッジ両側の
  セルのうち氷のある(hi > 0)セルについて、エッジに沿う方向の氷面 z + hi の差分を
  求めて平均する。差分は、その方向の両隣が氷のある有効セル(領域内・海でない)なら
  中心差分、片方なら片側差分、なしなら 0。サブサイクル数を決めるパス A の D も同じ式で
  求める。
- **決定の理由**:
  - §51.4 と同じ考え(4 近傍のまま、係数だけをエッジの勾配の大きさで評価する。
    Mahaffy (1976) がスタガード点で両成分から |∇s| を作るのと同じ考えの 4 近傍版。
    接線勾配の取り方は本プロジェクト独自)。8 近傍化は landslide_tsunami_plan.md §11 の
    別項目として残す。
  - 接線勾配に氷のないセルの地盤高を使わない点は、Mahaffy の通常の形(氷のないセルも
    氷面 = 床面として使う)と異なる。谷氷河では谷壁が氷のないセルになり、通常の形では
    壁の勾配が谷に沿う流れの係数を大きくする。溶岩流(§51.4)と同じ理由でこちらを選んだ。
    平坦床のドームでは両者の違いは氷縁だけに出る。
  - 既定を切り替え、旧方式に戻すスイッチは置かない(§0-6。§51.4 と同じ)。
  - 侵食(tick_erosion)の τb は、もとからセル中心の中央差分の勾配の大きさで評価して
    いて、この歪みはない。雪崩再配分(tick_avalanche)は 8 近傍の最急降下の 1 方向へ
    送る別の方式で、今回は変えていない(下の「残る限界」)。
- **ステンシルと並列**: §51.4 と同じ。接線勾配は東西のエッジ(パス A・B の k=4)で
  行 j±1 を読むので、書き手の行 je+1 では je+2 まで読む(ハロ幅 2 の内側。全域端の
  外は x = 0 で読まない)。帯界面のエッジは両ランクが同じ入力から同じ式で冗長計算する
  のでビット一致する。
- **計算量**: Halfar(4 スレッド)で 1.2 s → 1.4 s。サブサイクル数は係数が変わるため
  Halfar 296 → 265(中心が解析解どおり薄くなり D が小さくなる)、カール 121 → 123。
- **検証**(gfortran 13.3 / Open MPI 4.1.6、Ubuntu 24.04):
  - **Check_halfar.py に等方性の検定 (4) を追加**: セル中心の方位角で格子軸の方向
    (±22.5° 以内)と斜めの方向(45° ± 22.5° 以内)の扇形に分け、氷の体積比
    (斜め/軸)を同じ分け方の解析解の比と比べて差 2% 未満。修正前のコードで −5.49%
    (FAIL。検出器として働く)、修正後 +0.59%(PASS)。
  - Halfar: 平均絶対誤差 2.35 → 0.32 m、中心誤差 4.72 → 0.13 m、最大誤差(氷縁)
    38.6 → 12.5 m、氷縁から 2 セルより内側の誤差 −8.9〜+6.0 → −0.8〜+0.4 m。氷体積の
    保存は機械精度のまま。カール(雪崩あり): max Hi 103.6 → 96.1 m、最大侵食深
    0.0172 → 0.0133 m、系外排出 1.703 → 1.636×10⁵ m³(Check_cirque.py の基準
    「侵食 0.01 m 超」は満たす)。雪崩なしでは、山頂から 1000 m の円周上で方位による
    氷厚の差 0.04%・侵食深の差 0.7%(修正前は 19%・42%)。
  - -fcheck=all(-Og)の MPI np=2・np=4 で Halfar・カールがクリーン。
  - -O2 厳密数学ビルドで、逐次 = MPI np=1, 2, 4 の全出力が Halfar・カールでバイト一致。
    リスタート往復(Halfar: 43200 s で save → restore → 86400 s)も、最終の Hi と save の
    全ファイルがフル計算とバイト一致。通常の -Ofast ビルドでも Run_MPI.sh の np=2・4 が
    逐次とバイト一致。既定値の同値検定(構成 3)も PASS。
  - 氷河を使わないケースは計算の経路が変わらない。CI の高速セット 16 件が逐次で PASS。
  - 新規コンパイル警告なし。
- **残る限界**: 1 セル幅の細い氷舌では、接線方向の両隣に氷がなく、法線勾配だけの評価に
  戻る。流束は 4 近傍(5 点)のまま。雪崩再配分 f_glava は雪を 8 近傍のうち最急降下の
  1 方向へ送るので、滑らかな斜面では格子軸と斜めの 8 方向に放射状の筋ができる
  (test/glacier のカールの図。雪崩を止めると筋は消える)。→ 同日に送り先を D∞ に
  変えて解消した(§45.2)。

### 45.2 雪崩再配分の送り先を D∞ にする(格子の向きによる筋の修正。2026-11-03 挙動変更)

- **現象**: 雪崩再配分(f_glava)で、雪が格子軸と斜めの 8 方向の線に残り、その間の
  向き(22.5° + 45° の倍数)で減る。円錐山体に一様な雪(SWE 1000 mm)を置いて雪崩だけを
  1 日(24 回の再配分)動かすと、山頂から同じ距離(800〜1600 m)の円周上で SWE が方向に
  よって 5〜9 倍違う(変動係数 0.23〜0.35)。§45.1 の修正後もカール形成テストの図に残った
  8 方向の放射状の筋の原因(雪崩なしでは筋は出ない)。
- **原因**: (a) 送り先が 8 近傍のうち最急降下の 1 セル(D8)なので、流れが 8 方向の
  平行な筋になり、方向の境目(22.5° + 45° の倍数)で流れが分かれる。(b) 限界勾配との
  比較と移送率に使う勾配が 8 方向の中の最急勾配で、8 方向の間の向きでは真の勾配より
  最大 8%(cos 22.5°)小さい。限界勾配に近い斜面では移送率が方向で 2 倍違う(この円錐で
  0.078〜0.167)。
- **修正**: 送り先と勾配を D∞(Tarboton, D. G. (1997): A new method for the determination
  of flow directions and upslope areas in grid digital elevation models. Water Resources
  Research, 33(2), 309–319)で決める(ava_dir)。セルと、軸方向の隣・斜めの隣で作る 8 つの
  三角形の面のうち最も急な下りの面を採り、面の中の最急降下の向き r と勾配(平面なら真の
  勾配の大きさ)を求める。向きを挟む軸方向の隣と斜めの隣へ、角度の比(斜めの隣へ
  r/α、α = atan(d2/d1))で分けて送る。移送率 min(1, (tanθ − tanθc)/tanθc) は変えない。
  2 つの送り先への分配は、和が移送量と厳密に一致するように、大きい方を積、小さい方を
  差で求める(大きい方は移送量の 1/2 以上なので、差は Sterbenz の補題により丸めなし)。
  送り手は移送量そのものを引き、受け手は同じ値を足すので、D8 と同じ意味で保存的。
- **決定の理由**(2026-11-03、利用者と合意):
  - 3 案を Python の試作(現行の規則を再現し、Fortran の結果と対称軸上を除いて一致することを
    確かめた)で同じ条件で比べた。円周上の変動係数(800〜1600 m): D8 0.23〜0.35、D∞
    0.02〜0.05、下りの隣すべてへ勾配×輪郭長の比で分ける MFD 0.04〜0.10(Quinn, P., Beven, K.,
    Chevallier, P. and Planchon, O. (1991): The prediction of hillslope flow paths for
    distributed hydrological modelling using digital terrain models. Hydrological Processes,
    5(1), 59–79 の型)。
    送り先は D8 のまま勾配だけ真の値にする案は、原因 (a) が残るので筋は消えない。
  - D∞ を採った理由: 平面なら向きも勾配も格子の向きによらない。MFD は横への広がり
    (分散)が大きい(Tarboton が D∞ を作った動機)。雪崩は谷筋に集まって流れることが多いので、
    分散の小さい方が実際に近いと判断した。
  - 領域外・海のセルを含む面は使わない。使える下りの面がなければ(領域の端・海岸)、
    8 近傍の最急降下の 1 セルへ送る(D8。それまでの方式)。内部では、下りの隣が 1 つでも
    あれば正の勾配の面が必ずある(軸方向の隣が低ければその面、斜めの隣だけが低ければ
    面の縁に沿う向き)ので、D8 に戻るのは使える面がない場合だけ。
  - dx ≠ dy の格子でも Tarboton の式を辺の長さ d1・d2 でそのまま使う。
  - 既定を切り替え、旧方式に戻すスイッチは置かない(§0-6。§45.1・§51.4 と同じ)。
- **ステンシルと並列**: 8 近傍だけを読むので、パス 1 の冗長計算の範囲(帯±1 行)と
  ハロの読み(帯±2 行)は変わらない。パス 1 が送り先 2 つ(ad・ad2)と量(am・am2)を
  決め、パス 2 は自帯のセルについて、8 近傍の送り先が自セルを指す量を決まった順で足す。
  作業配列 am2・ad2 を追加(f_glava = 1 のときだけ確保)。
- **検証**(gfortran 13.3 / Open MPI 4.1.6、Ubuntu 24.04):
  - **test/glacier に構成 4 を追加**(param_ava.txt。円錐山体・一様な SWE 1000 mm・
    雪崩だけ・1 日。Check_ava.py)。検定: (1) 半径 800・1000・1200・1400・1600 m の円周上の
    SWE の変動係数 < 0.08、(2) 半径 400 m の平均 SWE が初期の 90% 未満(再配分が働いて
    いること)、(3) 水当量の保存(相対 1e-12 未満)。修正前のコードで変動係数
    0.230〜0.350(FAIL。検出器として働く)、修正後 0.017〜0.042(PASS)。水当量は表示
    全桁で不変。
  - カール形成テスト(雪崩あり): 円周上の変動係数が氷厚 0.012〜0.030 → 0.001〜0.004、
    侵食深 0.073〜0.088 → 0.008〜0.018。max Hi 96.1 → 92.7 m、最大侵食深 0.0133 →
    0.0121 m、系外排出 1.636 → 1.599×10⁵ m³(Check_cirque.py の基準「侵食 0.01 m 超」は
    満たす)。Halfar(雪崩なし)は変わらない。
  - -fcheck=all(-Og)の MPI np=2・np=4 で構成 1・2・4 がクリーン(最適化ビルドの計算より
    先に実行。絶対規律 3)。
  - -O2 厳密数学ビルドで、逐次 = MPI np=1, 2, 4 の全出力が構成 1・2・4 でバイト一致。
    リスタート往復(構成 4: 43200 s で save → restore → 86400 s)も最終の SWE と save の
    全ファイルがフル計算とバイト一致。通常の -Ofast ビルドでも Run_MPI.sh の np=2・4 が
    逐次とバイト一致。
  - 氷河を使わないケースは計算の経路が変わらない。CI の高速セット 16 件が逐次で PASS。
  - 新規コンパイル警告なし。
- **残る限界**: D∞ でも円錐の円周上の変動係数は 0.02〜0.04 残る。完全に対称な円錐では、
  対称軸の上と山頂のセルで同じ勾配の面が並び、先の面を採る規則が対称性を崩す(最終の
  SWE は鏡映・90° 回転に対して最大 36 mm 非対称)。試作で、同じ勾配の 2 面が隣を共有する
  ときはその隣へ全量を送る規則を試したが、軸の上に雪が残って変動係数は悪化した
  (0.026〜0.079)。斜めの 1 回の移動が √2 倍遠いことの補正も、差を減らさなかった。原因の
  切り分けは済んでいない。1 回の再配分で雪が進むのは 1 セルだけで、雪崩の走行距離や
  速さは表さない(従来どおり)。

### 45.3 侵食の結合長 gl_lc(格子規模の侵食の集中を止める。2026-11-04 機能追加)

- **現象**: 千年規模の侵食の試計算(handoff 1q の「カール形成の長期実証ラン」を試した
  もの。作業用の場所で実行し、ケースはリポジトリに置いていない)で、侵食がセル単位に
  集中して計算が止まった。条件は年平均の一定気候(雨雪の閾値 0 ℃ 単一 = 雪線が平衡線)、
  gl_ddfi = 6、滑動・侵食は既定(gl_as = 1e-13、gl_kg = 1e-4、l = 1)、dt = 30 s、
  dt_glacier_c = 1 ステップ、gl_morfac = 2×10⁵(1 回の更新 = 地形時間 0.19 年)。
  - V 字谷(20 km × 8 km、谷底の勾配 0.08、谷壁 0.35、肩の台地と支谷つき、平衡線
    2700 m、Δx = 200 m): 谷の軸の 2 セルだけが溝状に掘れ(1500 年で 80 m、隣は 17 m)、
    1500〜2000 年の間に SIA のサブサイクル数が 1 回の更新で 100 万を超えて停止。
    1000 年時点で Δx = 100 m の軸の侵食は 62 m(200 m では 48 m)で、細かい格子ほど
    中央が狭く深い。
  - 東西の稜線と両斜面の谷(14 km × 12 km、平衡線 2850 m、Δx = 200 m): 氷河の帯の中の
    セルに穴が育ち(3500 年で 104 m)、3500〜4000 年の間に同じく停止。
- **原因**: 局所の τb = ρi g H |∇s| では侵食 ∝ (H|∇s|)^{3l} で、氷が厚い所ほど削れ、
  削れた所ほど氷が厚くなる。谷を横切る方向では氷面がほぼ平らで |∇s| は共通なので、
  最も深い列に侵食が集まる。SIA は氷柱どうしの応力の受け渡し(谷壁の抵抗・流れの方向の
  押し引き)を持たないので、この正のフィードバックを止める長さがなく、集中は格子間隔まで
  縮む(f_splash の κ の「無限波数問題」§48.3 と同じ型)。谷の断面計算で SIA だと V 字が
  残り U 字化には谷壁のせん断が要ること(Seddik et al. 2009, arXiv:0901.1177)、元の SIA が
  氷の下に深く細い峡谷を作ること(Liebl et al. 2023, GMD 16: 1315–1343 の iSOSIA との比較)
  と整合する。
  - 当初は、侵食の勾配(中央差分)に氷のない隣の地盤高が入る「氷の崖」を疑った。侵食の
    勾配を氷のあるセルだけで取る(§45.1 の cell_tslope)形を試すと、test/glacier の全出力は
    不変(カールのテストは全セルが氷に覆われ縁がない)、V 字谷は 1500 年で最大 0.18 m の差、
    稜線は同じ時期に停止した。最深の穴 6 つはどれも 4 近傍がすべて氷のセルだった。主因では
    ないので、局所の経路には入れず、下の平滑化の中だけで使う(縁の段は「残る限界」)。
- **修正**: &list_glacier に gl_lc(m。既定 0)を加えた。gl_lc > 0 なら、侵食(tick_erosion)
  の前に smooth_tau が、氷のある有効セル(ice_cell)の駆動応力のベクトル τ = ρi g H ∇s
  (勾配は cell_tslope = 氷のあるセルだけ)を、氷のあるセルの中だけで標準偏差 gl_lc の
  ガウス核で平均する。正規化畳み込み: τx·m、τy·m、m(m = 氷のある有効セル 1、ほか 0)を
  同じ核でならし、tick_erosion が |⟨τ m⟩| / ⟨m⟩ を τb として us = As τb³、
  ė = Kg us^l を求める。核は spl_lc と同じ 5 点核の反復(パス数 N = 4(ℓ/Δmin)²、重み
  w = ℓ²/(2NΔ²)、上限 1/8)。gl_lc = 0 の経路は変更前と同じ演算(字下げのみ)。
- **決定の理由**(方向 = 侵食の安定化は 2026-11-04 に利用者と合意。細部は試計算の比較で
  決めた):
  - 物理の根拠を持つ長さにする: Kamb & Echelmeyer (1986) J. Glaciol. 32: 267–284 は、氷河の
    流れが流れの方向に沿った氷厚と表面勾配の重みつき平均に従い、その結合長が谷氷河で氷厚の
    1〜3 倍(Variegated・Blue 氷河の実測への当てはめで ℓ/h ≈ 2)であることを示した。谷を
    横切る方向にも同じ長さを当てること、指数核の代わりにガウス核を使い、その標準偏差を
    結合長に当てること、駆動応力のベクトルを平均することは独自の簡略化。
  - 平滑化する量は駆動応力(τb)にした: 谷の横断面だけの玩具モデル(Python。流量一定で
    氷面を合わせ、谷壁は安息角 35° で崩す)で、局所の侵食則は崩落なしで溝、崩落ありで
    安息角の V 字。τb を ℓ = 800〜1200 m、または滑動速度を ℓ = 400〜800 m でならすと、
    どちらも底の丸い谷になり Δx = 100 m と 50 m が一致した。滑動速度の平均は同じ効果に
    短い ℓ で足りるが、結合長の理論は駆動応力(氷厚と勾配)の平均なので τb を採った。
  - ベクトルで平均する: 大きさで平均すると、氷の分水嶺の両側の逆向きの応力が足し合わされ、
    動かない分水嶺の下で侵食が出る。
  - 勾配を氷のあるセルだけで取る: 縁のセルの中央差分に氷の崖が入ると、平均するベクトル場の
    縁が外向きに大きくなる(構成 5 の gl_lc = 0 の縁の段)。
  - 流動には使わない: 検証済みの SIA の流動(Halfar・等方性)と氷体積の保存を変えない。
    集中を起こすのは侵食則の H³ への感度で、流動の拡散は自分では集中しない。
  - 既定 0(番兵の既定値・"(default)" 表示なし): 0 が「平滑化なし」の明示で、lv_wsol・
    lv_tauy(§66)と spl_lc(§48.3)の前例と同じ。gl_lc = 0 で変更前とビット一致。既定で
    有効にするかは利用者の判断に残した。→ 同日、利用者と合意して既定を max(500 m, 2Δx)
    に変えた(§45.4)。
  - 薄い縁の氷の侵食を弱める厚さの重みは入れない(パラメータを増やさない。残る限界)。
- **ステンシルと並列**: smooth_tau は自帯の τx・τy・m を 0 込みで上書きしてからハロを
  交換し、各パスは自帯のセルだけを 5 点核で更新して 3 成分のハロを交換する(spl_lc と同じ
  鏡像の規約: 領域外 x = 0 と配列範囲外の近傍は自セル値。近傍の配列は g%x の内側で読む)。
  パス数は namelist 由来で全ランク同一(collective 安全)、各ランクは自帯だけを書くので
  ランク数によらずビット一致。作業配列 tx・ty・tm(帯±ハロ)と tw(3 成分 × 自帯)は
  f_glero = 1 かつ gl_lc > 0 のときだけ確保(無効時ゼロ追加)。リスタートの内容は変わらない
  (毎回求め直す診断量)。
- **計算量**: 侵食の更新ごとに N 回の 5 点核(3 成分)と 3N 回のハロ交換。test/glacier
  構成 5(30 × 20 セル、N = 16、24 回の更新)は 2 秒程度。
- **検証**(gfortran 13.3 / Open MPI 4.1.6、Ubuntu 24.04):
  - gl_lc = 0 は変更前とビット一致: test/glacier の構成 1〜4(Halfar・カール・雪崩・
    既定値の最小入力)を f_state_save = 1 にして変更前のビルドと比べ、result の全ファイルと
    save の全ファイル(state.dat・snow.dat・glacier.dat ほか)がバイト一致。
  - **test/glacier に構成 5 を追加**(param_lc・lc2・lc0・lc02。Check_lc.py)。V 字谷
    (6000 m × 4000 m、谷底の勾配 0.03、谷壁 0.4)を深さ 250 m の氷で満たし、−30 ℃・降水
    なしで 10 年(侵食係数は既定の 100 倍)。谷を横切る侵食(x = 2〜4 km の平均)の
    Δx = 200 m と 100 m の差は相対 L1 で gl_lc = 400 m なら 0.003、gl_lc = 0 なら 0.196
    (検出器として働く)。侵食が最大値の半分を超える幅は 1200 m 対 400 m、氷のある範囲の
    平均/最大は 0.82 対 0.52。gl_lc = 400 m では谷の軸から氷の縁へ単調に減り、gl_lc = 0 では
    縁のセルが一つ内側より深い(−0.47 m 対 −0.37 m)。
  - -fcheck=all(-Og)の MPI np=2・np=4 で、gl_lc を与えたカールのテスト(gl_lc = 150 m、
    36 パス)と稜線の試計算(gl_lc = 600 m、60 年)がクリーン(最適化ビルドの計算より先に
    実行。絶対規律 3)。同じデバッグビルドで np = 1, 2, 4 の全出力がバイト一致。
  - 通常の -Ofast ビルドで test/glacier の Run.sh が PASS、Run_MPI.sh の np = 1, 2, 4 で
    構成 5 の 4 つを含む 7 つの result が逐次とバイト一致。
  - 氷河を使わないケースは計算の経路が変わらない。CI の高速セット 16 件が逐次で PASS。
    トップレベルの make(utils の追随)も通る。新規コンパイル警告なし。
  - 長期の試計算(上の現象と同じ条件): V 字谷は gl_lc = 600 m で 3000 年を完走し、最大の
    侵食は 2700 年で 38 m、時間に比例して増えるだけで溝はない。稜線は gl_lc = 400 m で
    5000 年を完走し、4500 年で最大 7 m の滑らかな帯状の侵食(穴なし)。V 字谷の Δx = 200 m と
    100 m(gl_lc = 600 m)は 1500 年まで比べ、氷の量は同じ(900 年 8.54・8.55 km³、1500 年
    8.60・8.60 km³)、谷を横切る氷厚の差は相対 1.8%(1500 年)とほぼ同じ氷河になる。侵食の
    形(幅・位置)はそろい、領域の最大の侵食は 1500 年で 19.7 m 対 20.4 m。x = 10〜14 km で
    平均した横断形の差は相対 L1 で 0.12(900 年・1500 年とも。広がらない)で、谷の軸の侵食は
    100 m のほうが 2 割ほど大きい(1500 年で 13.5 m 対 15.9 m)。侵食が応力の 3 乗に比例して
    氷厚・勾配の小さな格子差を増幅するため。局所の τb では同じ比較で、溝の幅が格子に合わせて
    狭まり、軸の侵食は 1000 年で 48 m 対 62 m。
- **残る限界**: gl_lc は谷壁の抵抗そのものではなく、侵食が最大になるのは谷の軸のまま
  (U 字の横断形は保証しない。谷壁の抵抗による滑動の横分布 = 谷の軸での極小(Harbor 1992
  GSA Bull. 104: 1364–1375)は表さない)。氷の縁や末端の薄い氷の下にも内側から平均した応力で
  侵食が及ぶ。氷が薄く格子が粗い(2H < 2Δx)ときの gl_lc は物理の結合長でなく数値の正則化
  の意味になる。gl_lc = 0 の局所の経路には、縁のセルの「氷の崖」による段(上)が残る。
  千年規模の実験でも、長い波長の侵食の不均一(谷の深掘れなど)は残るし、それは表すべき
  ものである(MacGregor et al. 2000 の段・懸谷)。

### 45.4 gl_lc の既定値を max(500 m, 2Δx) にする(2026-11-04 挙動変更)

- **動機**: §45.3 の既定 0 のままでは、侵食を使う長期の実験が既定の設定で格子規模の
  溝・穴を育てて止まる。推奨値を既定にすることを利用者と合意した(2026-11-04)。
- **試計算による感度**(§45.3 の現象と同じ条件。Δx = 200 m。作業用の場所で実行):
  - V 字谷(氷厚 約 250 m)、1500 年: gl_lc = 0・200・400・600・1000 m で、侵食の総量
    1473・1218・996・823・614 百万 m³(gl_lc = 0 に対する比 1・0.83・0.68・0.56・0.42)、
    最大の侵食 105・56・29・20・10 m、セル規模の凹凸(3×3 平均からのずれの平均)/ 平均の
    侵食 0.27・0.10・0.04・0.02・0.01。gl_lc > 0 はすべて 3000 年を完走(200 m = 1Δx も)。
  - 稜線の氷河(氷厚 30〜60 m)、3500 年: gl_lc = 0・100・200・400 m で、総量 439・239・
    172・91 百万 m³(比 1・0.54・0.39・0.21)、最大 104・23・13・5 m、凹凸 / 平均 0.79・
    0.40・0.22・0.17。gl_lc > 0 はすべて 5000 年を完走(100 m = 0.5Δx も。ただし凹凸は
    ゆっくり育つ。4500 年で 4.1 m)。
  - 結論: gl_lc は数値の安定化の長さではなく侵食則の一部(侵食の大きさを変える)。格子
    間隔の 1 倍でセル規模の凹凸の大半が消え、2 倍で格子によらない(§45.3 の構成 5)。
- **決定**: 未指定(番兵 −9999)なら gl_lc = max(500 m, 2·max(Δx, Δy)) を採用し、
  "(default)" 付きで表示する(§65 の param_default。f_glero = 1 のときだけ)。
  0 < gl_lc < 2·max(Δx, Δy) を指定したら rank 0 が警告する(全ランク同じ内容)。0 の明示で
  局所の τb(変更前の既定)を選べる。
- **決定の理由**:
  - 500 m: Kamb & Echelmeyer (1986) J. Glaciol. 32: 267–284 の実測への当てはめで、谷氷河の
    結合長は Blue 氷河 450 m・Variegated 氷河 625 m(論文の平均化の長さ 1.8・2.5 km は
    三角窓の長さ 4ℓ。ℓ/h ≈ 2)。その間の丸めた値。既定の gl_kg(1e-4)も Variegated 氷河の
    実測(Humphrey & Raymond 1994)なので、侵食則の既定が同じ氷河の値の組になる。gl_kg は
    実測の滑動速度(実際の氷河で応力の受け渡しによってならされた速度)から決めた値なので、
    ならした τb と組むほうが出典と整合する。
  - 2Δx の下限: 格子間隔が 250 m より粗いとき、格子規模の集中を止めるため(上の感度)。
    粗い方向の max(Δx, Δy) で測る。
  - 格子間隔の倍数だけを既定にする案は採らない: gl_lc が侵食の大きさを変えるので、格子を
    変えると侵食が変わる。
  - 氷厚に合わせて自動で決める案(ℓ = 2H(x))は、カールと谷氷河を同じ設定で扱える点で
    物理として最もよいが、平滑化の幅を場所ごとに変える拡張が要る。将来の精緻化に残す
    (handoff 1q)。
- **既知の不一致**: 既定の 500 m は厚さ 200〜300 m 程度の谷氷河向け。カール・稜線の氷河
  (氷厚 100 m 以下)には大きすぎ、侵食を数分の一に見積もる(上の稜線で 100 m → 400 m の
  比 0.54 → 0.21)。氷帽には短い(Kamb & Echelmeyer は氷床で氷厚の 4〜10 倍)。細かい格子では
  計算量が増える(格子 50 m で更新ごとに 400 パス)。
- **テストの扱い**:
  - test/glacier 構成 2(カールのスモーク)は gl_lc = 0 を明示した(局所の τb のまま。結果は
    変更前とバイト一致)。既定の 500 m では最大の侵食が 0.0121 → 0.0087 m に下がって
    Check_cirque.py の基準(1 cm)を割るが、基準は変えない。構成 2 は局所の τb に格子の向きの
    歪みが出ないかの検出器(円周上の変動係数。§45.1・§45.2)を兼ね、平滑化(格子 50 m で
    10Δx)はその歪みを隠すため。平滑化の検定は構成 5、既定値の経路は構成 3 が受け持つ。
  - 構成 3(既定値の最小入力)は gl_lc も省略し、"(default)" は 4 → 5 行。構成 3' に
    gl_lc = 500 を明示。構成 5 は gl_lc をすべて明示しているので不変。
- **検証**(gfortran 13.3 / Open MPI 4.1.6、Ubuntu 24.04):
  - test/glacier の Run.sh が PASS(構成 3 と 3' の save・Log がバイト一致、"(default)" 5 行)。
    構成 1・2・4 の result は変更前とバイト一致。
  - Run_MPI.sh の np = 1, 2, 4 で 7 つの result が逐次とバイト一致。既定の経路の構成 3
    (格子 50 m・400 パス)も np = 2 で result と save が逐次とバイト一致。
  - 配列の確保範囲は変えていない。氷河を使わないケースは計算の経路が変わらない。
