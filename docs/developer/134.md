## 134. 移流項の近傍の判定に河道の堤防の仮想壁面を見せる: 壁の向こうの湛水が河道を減速させない(handoff 00al。2026-11-26 設計合意・実装。仮想壁面を使わない計算と、壁の向こうが乾いている計算はビット一致)

利用者向けは users_guide/advection.md §4.4 と channel_models.md §1(いずれも日英)。検定は test/wallpond。発見の経緯は
§131.12(例題 confluence_backwater の粗い格子の、越水の時期の差の原因の調査)。設計の下準備(作業用の版での比較)は
handoff 00al に書いていたもので、本節に移して 00al は消した。

### 134.1 問題

m_swflow_enc_adv の移流項は、隣のセルの状態を読んで、そのセルを運動量の供給元・平行リンク・開口に数えるかを決める
(cell_ok = 有効・海でない・水深 dd 以上、wet_weight = min(1, h/dd))。この判定は河道の堤防の仮想壁面(fn_bank)を
見なかった。壁の向こうの堤内地が乾いていれば無効と同じに働くが、濡れると、壁の向こうの淀んだ水の流速と、流速 0 の壁の
エッジが、河道の辺の
- 流向面の風上の供給元(線 k の上流のセル)、
- 側方面の平行リンク(lateral_u・lateral_u_w・lateral_u_j・lateral_u8)、
- 斜めエッジの開口率(axis_open・open_rep・axis_open8)、
- 屈曲直後の辺の規則の供給元(bend_face)と「線が続く」判定(path_value)、
- スキーム 1 のセル中心の勾配(get_diff_v1)
に入り、河道を人工的に減速させる。逆向きに、堤防沿いの堤内地の辺が、壁の向こうの河道の速い流れを平行リンクに使うことも
ある。利用者ガイドの移流項 §4.4 の「壁・乾床は運動量を供給しない」(§68.8)が、仮想壁面では成り立っていなかった。
test/wetbank(§110.25)の濡れた岸による減速の、仮想壁面の版。解像した堤防では、河道の隣は乾いた堤防のセルなので
起きない。

作業用の検定(直線の河道。勾配 1/1000、粗度 0.03、1,000 m³/s、長さ 4 km、川幅 200 m で等流水深 2.55 m。両側に幅
300 m の水平な堤内地。堤内地を計算しない・仮想壁面 + 乾いた堤内地・仮想壁面 + 湛水 1.5 m・解像した堤防 + 湛水の 4 通り)
で、等流の水深と水面勾配から逆算した通水の幅 ÷ 川幅:

| 格子 | 計算しない | 壁 + 乾いた | 壁 + 湛水 | 解像した堤防 + 湛水 |
|---|---:|---:|---:|---:|
| Δx = 100 m・河道 2 セル | 1.000 | 1.000 | 0.919 | 1.000 |
| Δx = 20 m・河道 10 セル | 1.000 | 1.000 | 0.936 | 1.000 |
| Δx = 100 m・1 セルのサブグリッド河道(W = 80 m) | 1.000 | 1.000 | 1.000 | 1.000 |

湛水のケースだけ河道の水位が最大 0.19 m(Δx = 100 m)・0.13 m(20 m)高い。直線の 1 セルのサブグリッド河道は影響を
受けない。45° の 4 連結の 1 セルの階段の河道(test/wallpond の dg1)では、湛水で水位が最大 0.14 m 高い(既定の構成)。

### 134.2 決定(利用者の合意。案 A2b)

会話で 4 案を比較し、推奨の A2b で合意した(2026-11-26)。

| 案 | 中身 | 作業用の版の結果 |
|---|---|---|
| A | 隣のセルを読む判定すべてに壁を見せる(MUSCL のさらに風上のセルの判定 far_ok も) | 湛水は直るが、乾いた堤内地の計算まで変わる(far_ok は水深を見ない静的な判定で乾いたセルも数えるため。Δx = 20 m で 0.1 mm の桁が 10〜72 セル) |
| A2 | A から far_ok を外す | 湛水は 1.000 に戻る。壁なし・乾いた堤内地はビット一致。ただし破堤口の流量が下がる(下) |
| **A2b** | A2 で、破堤サイトを実効天端で判定する(開いた破堤口は壁と数えない) | A2 と同じ性質 + 破堤の例題で解像した堤防に最も近い |
| B | 既定の側方面の 2 規則だけ(lateral_u_j・open_rep。§131.12 の作業用の修正) | 0.942・0.955 で足りない |

決めたこと(括弧は理由):
1. **規則**: 仮想壁面のエッジを挟む 2 つのセルは、移流項の中で互いを運動量の供給元・平行リンク・開口に数えない(乾いた
   セルと同じ扱い)。壁かどうかは bank_wall の対象判定 bank_edge(天端が両側の地盤より高いエッジ)と同じ。
2. **水位によらない**(越流中・水没中も数えない。壁のエッジの流量は堰の式で決まり、運動量の式を通らない。解像した堤防なら
   天端のセルの薄い越流水で、側方面の代表性 R' でほとんど数えられない。両側の水位が天端より低い間だけ壁とする代案は、
   越水の時期に減速が戻るので採らない)。
3. **破堤サイトは実効天端で判定する**(breach_crest。天端が地盤まで下がって開いた破堤口は壁と数えない)。例題 levee_breach
   の補足の仮想壁面のケース(f_br_diag = 1)で、破堤サイトを元の天端で壁と数え続ける A2 は破堤口の最大流量 137 → 125 m³/s・
   氾濫量 38.1 → 34.0 万 m³ と解像した堤防(138・36.2)から離れ、A2b は 134 m³/s・36.5 万 m³(作業用の版。最終版の数は
   §134.7)。
4. **MUSCL のさらに風上のセル(far_ok)には入れない**(解像した堤防の乾いた天端のセルと同じ静的な扱い。far_ok は行 j ± 3 まで
   読むので確保範囲の外に出る。h を見ないのはランク境界で判定を変えないため = §69.9 のコメント)。
5. **流量で重みを付ける規則には入れない**(lateral_rep・lateral_flux・lateral_join・path_value の流入・stream_share・
   donor_share は、面を横切るリンクの実流量で重みを付ける。壁のエッジの流量は 0 か越流の分だけなので、もともと壁を越える
   水だけを数える。越流で入る水の運動量の不足は、合流の不足分として数えるのが物理的にも正しい)。
6. **仮想壁面を使わない計算への追加**: 近傍の参照ごとに have_bank の論理値 1 つ(方針の「無効時はメモリ・CPU ゼロ追加」の
   範囲として認めた。測った限りばらつきの中)。仮想壁面を使う計算は約 1 割遅い(作業用の版の測定。下)。まず表なしで
   実装し、問題になったら初期化時のセルごとの壁の向きの表(8 ビット。破堤と地形変化で更新)にする。
7. **海岸堤防(list_seawall)の仮想壁は対象外**(海側のセルが sw でない fn_seaside だけのとき同じ形の問題を持ちうるが測って
   いない。handoff 00am で同じ形の検定で測ってから決める)。
8. 検定 test/wallpond を新設する(下)。

### 134.3 実装

- **等価変換(コミットを分けた)**: bank_edge を pure にし、m_swflow_enc_channel の補助手続きだった breach_crest を
  bank_edge の隣へ移して pure の module function にした(m_swflow_enc の引用仕様に宣言)。移流項(別の submodule)から
  呼ぶため。堤防と破堤を使う計算が修正前と全ファイル一致。
- **m_swflow_enc_adv**:
  - サブモジュールの水準の pure 関数 `vwall_between(g, s, ai, aj, bi, bj)`: have_bank が偽ならすぐ偽。8 近傍でない・確保範囲
    (s%z の列の範囲と jsh..jeh)の外・無効のセルを含む組は偽。bank_edge が真で、破堤サイトがあれば breach_crest の実効天端で
    is_wall をやり直す。読む行は 2 セルの行だけ(breach_crest の照合も、2 セルの行に限られる。破堤サイトの照合は行 jc ± 1 を
    走査するが、一致しうるのは 2 セルの行だけ)。
  - 3 つの内部手続きの塊(adv_prepare_mc・adv_neumann_mc・adv_bend_mc)に `walled`(両方を mirror_cell で鏡像に寄せて
    vwall_between)と `ok_from(ri, rj, oi, oj)`(cell_ok に壁を足したもの)、adv_prepare_mc に `wet_from`(wet_weight に壁を
    足したもの)を置き、判定を置き換えた: 流向面の風上の供給元(adv_prepare_mc・neumann_cell_faces の各 2 か所)、平行リンク
    (lateral_u・lateral_u8 の 6 か所、lateral_u_w・lateral_u_j の 6 か所)、開口率(axis_open の 3 つの分岐と axis_open8。
    f_advection_lateral = 1 の分岐は open_rep の値をリンクごとに 0 にする: c 側は c と角のセル、n 側は n と角のセルの間)、
    bend_face の 2 か所、path_value の「線が続く」判定。
  - スキーム 1(adv_prepare_v1): 壁の向こうの隣のセルの勾配の重みを 0 にする(get_diff_v1 は重みの和で割るので、乾いた
    セルと同じに外れる)。
  - 平行リンクの組の判定は「面のセル c と平行リンクの始点」「面のセル n と平行リンクの終点」の 2 組。平行リンクそのものが
    河道—堤内地のエッジのときも、片方の組が壁になるので外れる。
- 壁の向こうが乾いていれば cell_ok・wet_weight が偽・0 で、壁の判定は結果を変えない(ok_from は cell_ok が真のときだけ、
  wet_from は重みが正のときだけ壁を見る)。

### 134.5 出典と独自の部分

規則は ENCflow 独自の取り決め。運動量保存形の移流(Stelling & Duinmeijer 2003 の 8 方向への拡張。§68.6)の「壁・乾床は運動量を
供給しない」(§68.8)を、仮想壁面で区切られた隣のセルにも当てはめたもの。文献の式の変更ではない。

### 134.6 できないこと・精度の限界

- **深く水没した堤防**: 壁かどうかは水位によらないので、堤防が深く水没して両岸が一つの流れになる状態でも、壁を越える横の
  運動量の受け渡し(河道と堤内地の流れの間のせん断)を数えない近似になる。水の出入りは堰の式(越流の追い越し上限を含む。
  §68.29)で数える。
- **壁の向こうの池が流れているとき**: MUSCL のさらに風上のセルは壁の向こうでも数える(勾配制限の比に入るだけで、1 次への
  切り替えには使わない)。乾いたセル・静かな池(流速 0)とは同じだが、流れている池では乾いたセルと厳密には同じでない。
- **樋門の水理モード(f_bank_mode = 1)で堤内の水位が高いとき**: bank_wall はそのエッジを通常の運動方程式で通すが、移流項は
  そのエッジを挟むセルを互いに数えない(エッジ自身の流向面の供給元は線の上流のセルなので影響は小さい)。
- **海岸堤防の仮想壁**: 対象外(handoff 00am)。
- **計算時間**: 仮想壁面を使う計算は約 1 割遅い(§134.2 の 6)。

### 134.9 海岸堤防の仮想壁も同じに扱う: 移流項の近傍の判定と、開口の動的な振り替え(handoff 00am。2026-11-26 設計合意・実装。海岸堤防を使わない計算はビット一致)

§134.2 の 7 で対象外にした海岸堤防の仮想壁(seawall_wall。海側マスク ssw = fn_seaside ∪ sw のセルと、天端 zswall を持つ
陸側セルの間のエッジ。§17.1)を、test/wallpond と同じ形で測った(handoff 00am に書いていた下準備。本節に移して 00am は消した)。

**測定**(海側セル(fn_seaside。sw でない通常のセル)の帯を流し、両側の陸に海岸堤防(越流しない)を立てる。軸に沿う解像
2 セルの帯で、等流の水深と水面勾配から逆算した通水の幅 ÷ 帯の幅):

| 陸 | 修正前 | 移流項だけ直す(試作 P1) | 移流項 + 開口の振り替え(P12 = 採用) |
|---|---:|---:|---:|
| 乾いている | 0.919 | 0.919 | 1.000 |
| 湛水 1.5 m | 0.822 | 0.919 | 1.000 |

陸を計算しない構成(マスクの外)と、1 セルの解像した堤防の向こうに湛水する構成は 1.000。原因は 2 つ:
1. 移流項が海岸堤防の壁を見ない(§134 と同じ形)。湛水 − 乾いたの水位の差は最大 0.354 m(軸に沿う帯)・0.133 m(45° の
   1 セルの階段)・0.073 m(スキーム 1)。
2. 海岸堤防には開口の振り替えがない。河道の堤防は静的な開口補正(f_bank_opening = 1。build_channel_frw)が壁で塞がれた
   斜めの開口を軸のエッジへ回し、動的な振り替えの塞がり率 sblk は二重に返さないよう壁の向こうを 0 と数える。海岸堤防の

### 134.10 側方面の規則の合流の判定が、壁の向こうの隣の水深を読んでいた(2026-11-26 修正。例題 examples/coarse_channel で見つけた。仮想壁面を使わない計算と、壁の向こうが乾いている計算はビット一致)

**問題**: 例題 examples/coarse_channel の「河道の脇の水」で、26.6°(勾配 1:2)の直線の河道(川幅 200 m)を、段で 2 行を
共有するように太らせた解像セルの帯(Δx = 100 m)で表し、仮想壁面の向こうの堤内地に水深 1.5 m の池を置くと、河道の水位が
乾いた堤内地より 4〜7 cm 高くなった(区間の平均 +4.4 cm。等流の水深と水面勾配から逆算した通水の幅 1.013 → 0.991)。
test/wallpond の形(軸に沿う 2 セルの帯・45° の 1 セルの階段)では出ない。移流項の構成を 1 つずつ変えた切り分け: スキーム 1、
f_advection_donor = 0、f_advection_lateral = 0 では差 0。lateral = 1・2 で差が出る(donor = 3 でも同じ 4.4 cm、bend = 1 では
−1.9 cm と符号が変わる、f_dry_head_cap = 3 でも同じ)。

**原因**: 側方面の規則の合流の不足分 Δ(lateral_join。f_advection_lateral = 1・2。§110.25)は、側方面を横切って入る水の
入る先のセル X に「この辺の線に沿う流れがある度合い」ω_X を join_share = donor_share(X, 線の上流側の隣)で数える。
donor_share は、線の上流の隣からの流入が小さくても、その隣が深ければ(水深が X の ε 倍以上)1 を返す例外を持つ(§102)。
面の風上の供給元としての呼び出し(adv_prepare_mc・adv_bend_mc)は ok_from で壁の向こうを除いてから呼ぶが、join_share は
線の上流側の隣をそのまま渡す。隣が壁の向こうの池だと、その深さで ω_X = 1 になり(乾いていれば流入 0 で ω_X = 0)、帯の段で
横から入る河道の水を「合流」と数えて減速していた。§134 で壁を見せた判定の漏れ(§134.3 の一覧に donor_share の水深の例外が
なかった)。

**修正**(§134.2 の合意の範囲「仮想壁面の向こうのセルは、濡れていても乾いたセルと同じに数える」の適用漏れの修正として
実装した。新しい設計判断はない): adv_prepare_mc の donor_share の水深の例外で、供給元が壁の向こう(walled。仮想壁面が
あるときだけ調べる)なら水深を 0 と数える。面の供給元の呼び出しは壁の向こうを渡さないので値は変わらない。adv_bend_mc の
写しは面の供給元の呼び出しだけで使い(呼び出し側が ok_from で確かめる)、join_share を持たないので変えていない。

**検証**(gfortran 13.3、-Ofast):

  雨 20 mm/h で壁の向こうに 16 cm たまる構成も、通水の幅は 1.013 で同じ。

  湛水の 2 ケース。MPI のバイト比較に ob2_wet を足した)を足した: 修正前の実行ファイルでは湛水 − 乾いたが 42 mm で判定 (1)
