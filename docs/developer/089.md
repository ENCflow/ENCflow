## 89. 山地渓流の地形発達: 流水による岩盤下刻 f_rockinc(第 1 段)と深さ依存クリープ(第 2 段)(2026-10-27 合意・実装)

§88 = 降雨分布の時間の単位が入ったため)。それ以前のコミットメッセージの §88.x は本節の §89.x を指す。

### 89.1 決定事項(2026-10-27 合意。plan §8 の 10 項目)

1. 第 1 段 = 剥離・被覆・薄層の利用可能率・研磨(任意項)・基準面(fn_uplift)。
2. 岩 → 土砂の換算は **1:1**(剥離した岩の厚さ = 可動層の厚さ。z は剥離で動かない)。
   風化(§32)・基岩の崩落 rf_bedrock(§48)と同じ規約。膨張係数を入れるときは 3 過程に
   共通の係数 1 個で(既定 1 = ビット一致)。
3. 剥離の駆動量は超過せん断応力の比形 E_p0 = f_r k_p (τ_b/τ_c − 1)^m
   (τ_b = ρ_w g n² V² / h_e^{1/3}。掃流砂と同じ Manning 閉じ)。
4. k_p・β は既定なし(0 = その項なし。少なくとも一方は正)、H* と τ_c(剥離を使うとき)は
   必須、m の既定は 1(berode_m と同じ)。
5. 研磨の生成物は系外の細粒分として台帳に記録する(被覆を作らない)。
6. f_rockinc の有効時は、掃流砂の流出(供給側セル)に F_s = 1 − exp(−sd/H*) を掛ける。
7. 名称: f_rockinc・rock_*・fn_rock・fn_uplift・creep_hstar。
8. 裸岩は土層厚 0 の分布ファイルで与え、restore の「全域で sd ≤ 0 なら停止」だけを
   f_rockinc の有効時に緩める(一様値 sd0 = 0 は §64 の番兵と衝突するので許さない)。
9. 第 2 段の深さ依存クリープは f_creep のオプション(creep_hstar)。
10. 一般の混合粒径は §84.10 の決定どおり採らない。

実装はコミットを分ける(plan §8 の段取り): (1) 剥離・利用可能率・台帳と T1〜T7・T9
(本節 89.2〜89.4)、(2) 研磨と T3 の山形(89.5)、(3) fn_uplift と T8(89.6)、(4) restore の
ガードの緩和(89.7)、(5) 例題・文書の仕上げ(89.9)。第 2 段の深さ依存クリープは 89.8。

### 89.2 実装(第 1 コミット: 剥離・被覆・利用可能率)

- 構成: submodule m_geomorph_rockinc(init_rockinc・calc_rockinc・dispose_rockinc・
  save/restore・rock_avail・read_cellmap)、親に t_rockinc(gm%rk)と f_rockinc、
  list_geomorph に f_rockinc・rock_kp・rock_tauc・rock_m・rock_hstar・fn_rock、
  m_state に s%ri(累積下刻)、m_output に出力 Ri、Makefile に登録。
- 呼び出し順: m_geomorph_calc の apply_bedfeed(区間流入の給砂)の後・calc_fluvial の前。
  上流から入った土砂の被覆を先に見て、剥離物を同じ更新の掃流砂で運ぶ(一次の演算子分割)。
  calc_rockinc はセル局所(自セルの h・vv・rn・sd だけを読む = 冒頭のハロ交換なし)で、
  末尾に par_halo_cell(s%sd)(続く calc_fluvial が近傍の sd を読む。判定は namelist 由来で
  全ランク同一)。
- 時間積分: 水理を更新の頭で固定し、露出率を厳密に積分する
  B_p = H* ln(1 + (E_p0 dts/H*) e^{−H/H*})(calc_wthr と同じ伝播子)。ln(1 + x) は
  x < 0.01 で y = x/(2 + x) の artanh 級数(1 + x の丸めに頼らないので -Ofast の再結合でも
  崩れない)。安全弁(D の rock_dRmax)は置かず、max(B/H*) と薄層の排出率 × dts の最大
  L·dts(L = q_b/(Δ(1 − λ)H*)、q_b はセルの掃流砂容量)を dispose で報告する
  (L·dts > 0.5 なら注意を表示)。
- 利用可能率: calc_fluvial のループ 1 で、河岸面の遮断・定着の後、通過幅係数・可動層
  クランプの前に、供給側(gq の符号で決まる風上)セルの rock_avail(sd) を掛ける。開境界の
  流出(自セルが供給側)にも掛ける。区間流入の給砂・容量給砂・側岸侵食・安息角・崩落・
  沿岸漂砂には掛けない(plan §4.3)。rock_avail は x = sd/H* < 0.01 で 6 次の級数。
  **f_rockinc の有効時は、岩盤下刻が起きないセルでも薄い沖積層の掃流砂の輸送が変わる**
  (無効時は分岐の判定だけで演算は不変)。
- 台帳: 剥離のかさ体積の行部分和(real64)→ par_sum_rows(決定的)。dispose の表示は
  「rock incision: plucked … m3 (bulk, into the mobile layer sd)」(es16.8。rtoa の小数
  5 桁では小さい体積が 0 に見えるため)。
- 状態と再開: s%ri(帯±ハロ)は f_rockinc の有効時に常に確保する(plan §4.8 は「要求時
  のみ」としていたが、私有 save で継続する状態なので常時にした。無効時は確保しない)。
  私有 save geomorph_rockinc.dat(restart_write_cell の 1 面。契約 5・§83)。restore 時に
  ファイルがなければ停止(f_dissol と同じ)。
- 侵食性倍率 fn_rock: rank0 が全域を読み par_scatter_cell で帯±ハロへ配る(方式 2。
  read_solmap と同じ経路の汎用版 read_cellmap)。負値・非数は par_allreduce_max で全ランクに
  集約してから停止(collective 安全)。未指定なら配列を確保しない。
- 併用の検査(init。namelist 由来で全ランク同一): f_fluvial 必須。f_debris・f_bedslide、
  fn_width、fn_nest、f_wave_longshore とは停止(plan §4.7)。f_suspend で f_bedfines が
  ないとき・単精度ビルドのときは注意を表示。
- 出力名: 累積下刻は Ri(既存の出力名と重複しない。Ht は崖錐と最大水深時刻で既に 2 系統
  あるので避けた)。

### 89.4 落とし穴と記録

1. **急勾配の等流で、セル流速の Manning 閉じの τ_b が釣り合いより大きい(T9)**。
   幅 5 セルの水路(Δx = 1 m、等流水深 0.3 m、n = 0.04)の中央列で、
   τ_b / ρ g h tanθ = 1.014(S = 0.01)、1.070(0.05)、1.141(0.1)、1.291(0.2)。
   中央の V / V_Manning(h) = 1.007〜1.136。粗度(n = 0.04〜0.15)・フルード数によらず
   勾配だけで決まり、時間刻み・勾配補正 f_gravity_correction・移流スキームを変えても
   ほぼ不変、p_diagratio = 0 では 1.0001 に一致した。原因は既定の動的振り替え
   f_opening_dynamic = 2(§68.14)で、塞がり率 s = clamp((z_n − z_c)/h_c, 0, 1) が一様斜面の
   上流側の斜め先の地盤を部分的な壁と数え(S = 0.2、h = 0.28 m で s = 0.71)、斜めの
   通過幅を軸へ振り替えて流れを速くする。f_opening_dynamic = 0 では中央列が 1.025
   (= 1.012²)だが、壁際の列の通水能が落ちる(V が中央の 0.8 倍。§68.38 の動機)。
   幅 41 セル・浅い流れ(h = 0.08 m、Δz/h = 2.6)では内部で 1.40。s は Δx·S/h で決まる
   ので、粗い格子・浅い流れの急勾配で大きい。§68.38 の既定化は勾配 0.002 の uniflow
   (s ≈ 0.004)で確認されていた。**水理の設計判断なので本作業では直さず記録する**
   (候補: 塞がり率から一様勾配の分 Δx·S を差し引く、流向に沿った水面で判定する等。
   handoff)。岩盤下刻・掃流砂は同じ閉じを使うので、急勾配の渓流では k_p・τ_c・
   流砂量の校正にこの偏りが入る。
2. **fluv_diagratio ≠ p_diagratio のとき掃流砂の軸エッジに fwd が掛かる**: calc_fluvial は
   水の動的振り替えの表 fwd(水の斜め配分 p_diagratio から作る)を掃流砂のエッジ流量に
   掛ける(§68.14)。掃流砂の通過幅を fluv_diagratio = 0(4 近傍)にすると、1 セル幅の水路で
   軸の容量が 1/(1 − p) = 2.41 倍になる(水と土砂の配分が違うのに水の振り替えを掛ける)。
   既定(fluv_diagratio = p_diagratio)では整合する。test/rockinc の T3 で検出(5 セル幅の
   試行で検定が閉じない原因の一つ)。1 セル幅の pluck を fluv_diagratio = 0 にした試行で、
   内部エッジの容量を 2.414 倍にした漸化式が 1.1e-3 で一致した(倍率なしでは 59 % ずれる。
   開境界の面には fwd が掛からない)。fluv_diagratio を変える利用者向けの注意として handoff に
   記録(修正は振り替えの設計を含めて議論する)。
3. **T3 の水路を 1 セル幅にした理由**: 5 セル幅では壁際の列の通水能が内部と違い(上の 1・2)、
   列ごとに下刻速度が違うので横断方向に河床の差が育ち、内側へ流れが集まる正帰還で準定常に
   ならなかった(V が 1.19 → 1.26 m/s に増え続けた)。1 セル幅では斜めの開口がすべて河岸で
   塞がれ(s = 1)、動的振り替えで水も掃流砂も軸方向の全幅になり、u = 0 の 1 次元の連鎖に
   なる。
4. **準定常の検定は剥離直後の厚さで閉じる**: 掃流砂が見るのは岩盤源の後の
   H* = Hⁿ + B_p なので、保存される Hⁿ(更新の末尾)で F_s を評価すると 1 更新の剥離分
   (B_p/H* ≈ 1e-3)だけずれる(漸化式との差 4 % → 3.7e-4)。
5. **下刻量と勾配の変化**: 準定常の検定では、被覆の応答時間のあいだの下刻量が
   E·T ≈ 5Δq H*/(q_c − q)(Δq は剥離による流砂の増分)で、上下流の差が勾配を変える。
   Δq = 0.3 q_c・H* = 2 cm の試行では 4000 s で 4〜8 cm 下刻して勾配が数 % 変わり、
   準定常にならなかった(Δq = 0.15 q_c・H* = 1 cm に下げた)。
6. 検定の実行環境の注意: root で mpirun するには OMPI_ALLOW_RUN_AS_ROOT=1 と
   OMPI_ALLOW_RUN_AS_ROOT_CONFIRM=1 が要る(コンテナ環境。Run_MPI.sh は設定しない)。
   コア数を超えて走らせる(他のジョブと並べる)ときは OMPI_MCA_mpi_yield_when_idle=1 を
   付ける。付けないと待ち合わせのランクが空回りし、3 × 60 セルの np = 4 が 25 分で終わらず、
   付けると 19 秒だった。

### 89.5 研磨(tools 効果。第 2 コミット)

- 式: E_a0 = f_r β q_c F_s(H^n)(q_c はセルの掃流砂容量 = 単位幅の固体流砂量。q_c F_s は
  そのセルから出る掃流砂 = 床を叩く礫の量)。dR/dt = −(E_p0 + E_a0) P_r、dH/dt = E_p0 P_r
  (研磨の細粒分は被覆に加えず系外へ。台帳「abraded … m3」)。GravelBedrockEroder の
  「研磨 = β × 流砂量 × 露出率」と同じ形で、定常では E = β q_s (1 − q_s/q_c) の山形になる
  (plan §4.3)。
- 時間積分: F_s(H^n) と水理を更新の頭で固定し、露出率の積分を剥離と共有する
  B_a = (E_a0/E_p0) B_p(E_p0 > 0)、E_a0 dts e^{−H/H*}(E_p0 = 0)。研磨は z を書くので、
  研磨があるとき(β > 0。判定は namelist 由来)だけ末尾で z のハロも交換する。
- パラメータ: rock_beta(1/m。既定 0 = 研磨なし)。rock_kp の既定も 0(剥離なし)にし、
  少なくとも一方が正であることを init で検査(両方 0 なら停止)。rock_tauc・rock_m の検査は
  rock_kp > 0 のときだけ(plan §8 の判断 4)。
- 検証(test/rockinc。gfortran 13.3 / Open MPI 4.1):
  - T3 の山形(hump_r02・r05・r08・r12): 剥離なし・研磨だけ(β = 0.005 1/m、H* = 1 cm)、
    北端の流入セルに一定の給砂 q_in = r q_c(q_c ≈ 1.81e-3 m²/s)。内部のセル(j = 21〜50)の
    最後の 1000 s(地形の時間)の Ri の増分から求めた下刻速度が β q_in (1 − q_in/q_c) に、
    被覆率が q_in/q_c に、r = 0.2・0.5・0.8 で 6.0e-5・4.5e-6・6.5e-4 と 7.9e-5・1.9e-4・
    2.3e-4 で一致。r = 1.2 は全被覆で下刻速度が山の頂点の 0.013 倍、被覆は厚くなり続ける
    (流入セルから出るエッジの容量は一様勾配の地形で内部の 0.72 倍なので、r > 0.7 では
    入口に盛り上がりができ、容量が上がる(r = 0.8 で 0.88 倍)まで溜まる。検定は内部の
    セルで行う)。
  - T4 の箱に β = 0.05 1/m を加え、Σ(z − z0) A = −研磨量、Σ(sd − sd0) A = 剥離量、
    Σ Ri A = 剥離量 + 研磨量が台帳と 2e-9 以内(台帳の印字 9 桁)で一致。
  - -fcheck=all の逐次と np = 2、-Ofast の np = 1, 2, 4 が全 11 構成で逐次とバイト一致。
  - 無効時: -O2 厳密数学で bankface・bedfines・fluvial・wave・creep・splash が変更前と
    バイト一致(保存時刻を除く)。

### 89.6 分布隆起 fn_uplift と隆起下の定常縦断形(第 3 コミット)

- fn_uplift(handoff 1n の既存項目): 隆起速度 uplift0 に掛ける倍率の分布。rank0 が全域を
  読み帯±ハロへ配る(read_cellmap = 方式 2)。指定時だけ gm%upmap を確保し、calc_uplift は
  倍率つきのループを別に持って early return する(一様隆起のループは変更しない = 無効時の
  演算は不変。-O2 厳密数学で、test/fluvial の箱に一様隆起とクリープを足した構成が変更前と
  バイト一致)。f_uplift なしの fn_uplift は停止。出口のセルを 0 にすれば基準面の固定、
  負にすれば基準面の低下。
- T8(test/rockinc の uplift): 幅 1 セルの水路を U = 1e-5 m/s で隆起させ、出口のセルだけ
  fn_uplift・fn_rock = 0(基準面の固定)。裸岩から剥離だけ(k_p = 6e-6 m/s、H* = 5 cm、
  morfac = 50 で地形の時間 7.5e4 s)。定常では隆起した岩がすべて剥離されて運ばれるので
  q_j = (1 − λ) U Δy j、各セルで E_p0(S)(1 − q_j/q_c(S)) = U。等流の水理でこれを解いた
  勾配(準解析解)と比べ、j = 15〜58 で S = 0.00768〜0.00861(準解析解 0.00785〜0.00879)、
  max 相対差 2.1 %、下流ほど急になる傾き S(58)/S(15) は準解析解と 0.16 %、定常性
  max|dz/dt| = 4.6e-3 U、局所の釣り合い B_p/(U dts) = 1 ± 2.6e-3。地形の時間刻みを半分
  (morfac 50 → 25、流れの時間 2 倍)にしても勾配は 1e-4 しか変わらないので、2 % の差は時間の
  離散化によらず、勾配が下流へ増える縦断の漸変流(水深が等流水深より 0.7 % 浅く流速が
  速い)を等流で近似した分と見られる(局所の水理での釣り合いは 2.6e-3 で閉じる)。格子幅を
  変えた比較は T10 と合わせて未実施(plan §4.9 の「差が縮む」の確認は残り)。
  → §89.10(T10)で確かめた: Δx = 0.5 m でも準解析解との差は 2.14 % のまま縮まない(準解析解の側の差)。
- **流入セル直下の減衰する段差**: 流入セル(水を源として入れるので流速が低い)の直下で、
  縦断の 2 階差分が +0.237, −0.176, +0.098, −0.055, … と 1 セルごとに約 −0.7 倍で減衰する
  2 セル周期の段差が育つ(地形の時間とともに範囲が 3 → 8 セルに広がり、振幅は飽和に
  向かう)。内部では滑らかなので、局所の τ_b に応じた下刻が入口の非一様な流れに応答した
  もので、内部の不安定ではない。実地形への適用では、流入境界の数セルの扱い(侵食性倍率
  0・隆起 0 で固定する等)に注意する(handoff)。
  → 2026-10-28: 流入セルの流速が低いのは区間流入の流入面の水深の床(通過幅あたりの限界水深)が
  流れの水深を上回っていたためで、床を流れの水深までにした §89.25 で段差は消えた(2 階差分
  0.2 mm 以下)。

### 89.8 深さ依存クリープ creep_hstar(山地渓流の第 2 段)

- **決定**(plan §5.1・§8 の判断 9): f_creep のオプション creep_hstar = H_c(m)。既定 0 は
  従来の z の線形拡散(sd に触れない。ビット一致)。H_c > 0 で
  q = −D (1 − e^{−H_up/H_c}) ∇z、z と sd を共動更新する(土層だけが動き、岩盤面 z − sd は
  不変)。Landlab の DepthDependentDiffuser の q = K H* (1 − e^{−H/H*}) S と同じ形で、
  D = K H* = creep_d の意味は変えない(出典は Johnstone & Hilley 2015。式の形は Landlab の
  説明で確認、論文本文は未照合)。H_up を各エッジの供給側(高い側)のセルの sd で評価するのは、
  供給量の上限(風上の土層)と整合させるための本モデルの選択。
- **実装**: calc_creep の冒頭で分岐し(従来のループは不変)、calc_creep_soil がエッジ流量を
  書く。かさ体積の流量に供給側の利用可能率 rock_avail(sd, 1/H_c)(f_rockinc と共有の
  1 − e^{−x}。x < 0.01 は級数)を掛け、poroi で割って固体体積にし、共有の apply_edge_flux
  (供給量制限 fdon → 発散 → z・sd の共動更新 → 地下水容量の整合。細粒分の帳簿・崖錐の搬出も
  共有)に渡す。域外に向く面スロットは 0(§19.10 と同じ書き手の契約)。実効の拡散係数は D 以下
  なので init_creep の安定条件の検査をそのまま使う。
- **初期化**: creep_hstar < 0 と、f_creep なしの creep_hstar > 0 は停止。H_c > 0 は「河床の
  物性(共有)」の分岐に入り(poroi・sgrav、setup_sd で sd を確保。土層厚の指定がなければ
  m_geoinfo_require_sd が停止する)、掃流砂が無効なら fdon をここで確保する(側岸侵食と同形)。
- **ハロ**: calc_creep_soil は供給側の近傍の sd を読む(帯界面のエッジは行 je+1 で冗長計算)。
  先行のプロセスがあるときクリープの前に z と並べて sd のハロも交換し、地形更新の末尾の
  sd のハロ交換の条件にも H_c > 0 を加えた(クリープだけの構成では末尾の交換がないと、
  次の更新で帯界面の sd が古いまま読まれる)。
- **診断**: 供給量制限の発動数は掃流砂と共有の警告「fluvial supply limiter」に数える
  (既存の出力の文言は変えない。ユーザーガイドに明記)。
- **検証**(test/creep の hstar_thick・thin・lim・bare。gfortran 13.3 / Open MPI 4.1):
  厚い土層(sd0 = 10 m、H_c = 5 cm)は従来の線形拡散と max|Δz| = 1.8e-15 m(固体体積への
  換算の往復の丸め)、プローブの解析解誤差は従来と同じ 7.76e-5 m。全構成で岩盤面の不変
  (≤ 4.4e-14 m)・土層の総量の保存(倍精度の和で一致)・sd ≥ 0。薄い土層(2 cm、H_c = 0.1 m)
  は頂部が剥がれ(sd = 9.6e-7 m)脚部に溜まる(3.66 cm)。供給量制限の構成(sd0 = H_c = 2 mm)
  は 226300 セル更新で発動し、その下でも保存と sd ≥ 0 が成り立つ。裸岩(土層厚 0 の分布)は
  z が不変。test/fluvial の creep_hs(掃流砂 + 深さ依存クリープ。H_c = 20 m で利用可能率が
  sd に敏感)は体積保存 3.5e-17 m·cell・共動更新 1.4e-14 m。-fcheck=all の逐次と np = 2 を
  先に実行して境界違反なし・バイト一致、-Ofast の np = 1, 2, 4 も逐次とバイト一致。
  2 つの sd のハロ交換はそれぞれ外したビルドで確かめた: クリープの前の交換を外すと
  fluvial の creep_hs が、末尾の交換の条件から H_c > 0 を外すと creep の thin・lim が、
  np = 2 で逐次と一致しなくなる(各検定がそれぞれの交換を見張る)。
- **無効時(creep_hstar = 0)**: -O2(厳密な数学)の A/B で、test/creep・fluvial・sedfeed・
  dissol は第 2 段の前(113cce6)と、bankface・bedfines・splash は岩盤下刻の前(358295d)と
  出力がバイト一致(save_info.txt の日時と、test/creep の result/ に写る param.txt の
  f_state_save の行を除く)。
  トップレベルの make(utils の追随)も通る。
- **残り**: 土層生成 f_wthr と組んだ定常斜面(土層厚 H_ss と放物線形)は、クリープの出口
  (斜面脚部の渓流)が要るので連成実験(plan §5.3)で確かめる。
  → §89.15(C2。test/hillsoil)で確かめた。

### 89.9 例題 examples/bedrock_cover(第 1 段の仕上げ)

- **構成の工夫**: 幅 1 セルの掘り込み水路(T3・T8 と同じ断面。長さ 100 m、勾配 0.01)を東西に
  2〜6 本並べ、水路ごとに区間流入の給砂(inflow_qb)か初期の土層厚だけを変えて 1 回の計算で比べる
  (乾いた岸で隔てられ互いに影響しない。剥離・研磨の係数は全域共通なので、モデルの違いは別の計算)。
  7 構成・約 2 分(4 並列)。入力と param は make_init.py が生成する。
- **A(給砂の量)**: 剥離だけ・研磨だけ・両方 × r = 0〜1。定常の下刻速度は
  E = (1 − q/q_c)(E_p0 + β q)(剥離物の自己供給 q(x) = q_c − (q_c − q_in) e^{−(1−λ)E_p0 x/q_c}
  を区間で平均)と 2.3 % 以内(0 < r < 1)、被覆の厚さは H* ln(1/(1 − r)) に一致。両方のモデルでは
  r = 0 でも剥離物が道具になる(剥離だけの 1.2 倍)。
- **B(給砂の時期)**: 平均 0.35 の一定給砂と、半分の時間だけ 0.7 のパルス。研磨だけでは周期
  12000 s(地形の時間)で 0.49 倍(準定常の予想 0.46)、600 s で 0.77 倍、剥離だけでは 1 % 以内で
  同じ。plan §4.9 の「研磨ありなら一定給砂がよく削れる、被覆だけなら線形で時期の効果は貯留の
  遅れから」を確かめた。パルスの r_on を 0.7 にしたのは、流入セルの容量(内部の 0.72 倍。§89.4)を
  超えて入口に溜まる効果を避けるため。
- **C(初期の被覆)**: 10 cm の被覆は約 1.5e4 s 下刻を抑え、3e4 s の累積は裸岩の 0.71 倍。
- **D(段差)**: 0.3 m の段差は上流へ後退しながら緩み(3e4 s で 70 → 61 m)、直下に深掘れができる。
  給砂 r = 0.4 の被覆は一様な区間の下刻を 1 − r 倍にするが、段差の後退はほとんど変えない。
  段差の水理は静水圧の近似なので定性的な目安(README に明記)。

### 89.10 T10 格子の解像度と向き(記録。合否なし)

- **解像度**: T8(隆起下の定常縦断形)を Δx = 0.5 m(水路幅も 0.5 m、単位幅流量は同じ、

  向きにも依存するので、剥離の係数の校正は対象の格子の向きでも確かめる(handoff の T9 の
  議論に含める)。

### 89.12 開境界を通った掃流砂の台帳(P0a。§89.11 の 7)

- **量**: 開境界を通った掃流砂の正味の固体体積(流出 − 流入)。終了時に
  「geomorph: net bed load out through open boundaries (out - in) X m3 (solid)」(全域の
  決定的な総和。0 なら表示しない)。容量給砂(f_bcfeed)の流入は差し引かれ、入口の
  「持ち出し」(負の給砂)は流出に入る。掃流砂だけが河床を動かす構成では
  (1 − λ) Σ(z − z0) A = inflow_qb の給砂 − この値 で閉じる。
- **正味にした理由**: 最初に流出だけ(正の流量)を数えたところ、容量給砂の倍率 0.5 の構成で
  収支が 0.081 m³ ずれた。feed_pass は入口のセルが正味で堆積しているとき負の給砂
  (入口の面から持ち出す)を書き、その分は既存の台帳 vcfeed にも負で入るため、流出と
  二重に数えていた。ループ 2 と同じ重み(流出は q × fdon、流入は q)で正味を数えると、
  給砂なし・倍率 0.5・倍率 1 の 3 構成で収支が相対 1e-10 で閉じた(表示の 10 桁の丸め)。
- **実装**: apply_edge_flux の末尾で、開いた面がある(bcs%have_open_bc)ときだけ、領域の枠に
  接するセル(枠の行は全列、ほかの行は i = 1 と nx_g)の、枠外に向く面の流量を数える
  (開いた面は bc_open_face で枠にしかない。壁の面のスロットは書き手が 0 にしている。
  §19.10)。行ごとの部分和 voutrow(real64。js..je)を par_sum_rows で集計する(決定的)。
  確保は掃流砂の有効時(init_fluvial。m_geomorph の init は m_swflow の bc_init より前に
  走るので have_open_bc では決められない。行の数だけの配列)。結果は変えない
  (既存のループに手を入れず、末尾の別の短いループ)。他のプロセス(側岸侵食・崩落・
  沿岸漂砂・深さ依存クリープ)の apply_edge_flux では面のスロットが 0 なので 0 を足す。
- **表示**: 既存の給砂の台帳(vcfeed・vfeed)はランク局所の警告(rtoa の 5 桁)だが、
  この台帳は収支の検算に使うので全域の総和を 10 桁(es16.9)の情報で出す。
- **検証**: test/sedfeed の検定 7(nofeed・feed1・feed05 で相対 1e-8)。

### 89.13 土層生成速度の分布 fn_wthr(P0b。§89.11 の 11)

- **量**: 土層生成速度 W = W0 × m(i, j)(W0 = wthr_p0、m = fn_wthr の倍率、m >= 0)。
  減衰深 sd* は全域で共通。m = 0 のセルは ln(1 + 0) = 0 で厳密に不変(渓流の岩盤など、
  岩盤面を風化でなく流水の下刻で下げたいセル)。未指定なら全セル 1 と同じ式で、配列を
  確保しない。
- **実装**: fn_rock・fn_uplift と同じ型。wmap(帯±ハロ。指定時のみ確保)を read_cellmap
  (rank0 が全域を読み、par_scatter_cell で配る。方式 2)で読み、陸のセルで m >= 0
  (負値と非数)を検査する(判定は par_allreduce_max で全ランク集約 = collective。負のセルを
  持つランクだけが検出しても全ランクが同じ停止に入る)。f_wthr なしの fn_wthr は停止。
  calc_wthr は wmap があるときだけ別のループを通って return し、未指定の経路は従来の
  ループのまま(無効時のビット一致)。倍率は (W0 dts/sd*) の後ろに掛けるので、全セル 1 の
  分布は未指定とビット一致する(-O2 で確認。x × 1 は厳密なので、積の並べ替えでも
  崩れにくいが、規格の保証ではないので検定には入れない)。
- **ついでの整理**: m_geomorph_dispose で upmap(fn_uplift)も解放する(確保だけで解放が
  なかった。init の gm は intent(out) なので再初期化の実害はない)。calc_uplift の見出しと

### 89.14 C1: 谷頭の給砂の下の渓流の定常勾配(P1。test/rockinc の T11)

- **構成**: T8 と同じ幅 1 セルの水路(長さ 60 m、出口のセルは隆起も侵食もしない、一様隆起

### 89.18 第 3 段: 土石流による岩盤侵食の決定事項(2026-10-27 合意。plan §12.8 の 11 項目)

単一イベントでの候補則の比較(plan §12.4。後処理でコードは変えていない)を踏まえて合意した。

1. 侵食則は準静的な駆動応力の超過形:
   τ_d = ρ(1 + sC) g_e h_t tanθ_f、E_d0 = f_r k_d max(τ_d/τ_cd − 1, 0)^{m_d}。
   - θ_f は流向の河床勾配(下りのみ)、g_e は運動方程式と同じ有効重力。
   - 抵抗則の底面せん断は、イベントの積分では同じ値になるが、薄い前縁・尾部の特異値を
     持ち込む。粒子の慣性応力は単層混合体では頑健でない。固体流束は閾値と勾配を持たない。
2. 係数は流水の剥離と別にする(rock_kdb・rock_taucdb・rock_mdb)。k・τ_c は既定なし、m は 1。
3. 被覆の長さ H*(rock_hstar)と侵食性倍率 fn_rock は流水と共有する。
4. 生成物は 1:1 で可動層 sd へ入れる(z は不変)。取り込むか被覆になるかは E-D が決める。
5. 適用するのは、濃い混合体(C ≥ db_cmin)が流れている(|V| ≥ db_vstop)湿潤セルだけ。
6. 土石流の構成では、流水の剥離・研磨を使わない(rock_kp = rock_beta = 0 を要求)。
   暦の勘定が出水の計算と混ざらないようにするため。
7. 有効化は f_rockinc = 1 の中の任意項(rock_kdb > 0)。f_rockinc は f_fluvial か f_debris を
   要求し、f_debris との併用の停止は外す(f_bedslide は残す)。
8. 交互計算で、h_s を運ぶ過程のない構成に h_s > 0 の save を復元したら、その場の河床に
   堆積させる(固体の台帳は変えない。挙動変更なので別コミット)。
9. イベント計算では隆起・風化・クリープを無効にするよう利用者ガイドで案内する(強制しない)。
10. 名称と置き場所: rock_kdb・rock_taucdb・rock_mdb、検定 test/dbrock、例題 examples/debris_bedrock。
11. 段取り: P1 則・被覆・台帳と DB1〜DB4・DB6・DB7 → P2 残留土砂の規約と DB5 → P3 例題 →
    P4 長期の連成(土石流を挟む V 字谷)は P3 の結果を見て判断する。

合意時の訂正: plan §12.7 の DB2 の式。剥離は z を変えないので、全固体
Σh_s + (1 − λ)Σ(z − z0) は 0 のまま。岩盤起源のかさ体積の (1 − λ) 倍だけ増えるのは、可動層の固体
Σh_s + (1 − λ)Σ(sd − sd0) である(§4.1 の 2 つの不変量と同じ)。

### 89.19 土石流による岩盤侵食の実装(P1。§89.18 の 1〜7・10)

- **入力**: list_geomorph に rock_kdb(k_d、m/s。既定 0 = 項なし)・rock_taucdb(τ_cd、Pa。
  rock_kdb > 0 で必須)・rock_mdb(m_d。既定 1)。H* と fn_rock は流水と共有する。
- **組合せと検査**(判定はすべて namelist 由来で全ランク同一):
  - m_geomorph_init: f_rockinc の要件を「f_fluvial か f_debris」に緩め、f_debris との併用の
    停止を外した(f_bedslide は残す)。
  - init_rockinc の f_debris の構成では、次を要求する: rock_kp = rock_beta = 0、rock_kdb > 0、
    rock_taucdb > 0、rock_mdb > 0、db_cmin ∈ (0, C*)(0 なら清水も土石流の係数で削るため)。
  - init_rockinc の f_fluvial の構成では、rock_kdb > 0 を停止にする。流水の項
    (rock_kp か rock_beta)は従来どおり 1 つ以上を要求する。
- **計算**(calc_debris の 2 パス。§28.2 の構造をそのまま使う):
  - パス 1: 時刻 n の場から E_d0 を作業配列 gm%rk%edb(ish:ieh, js:je)に書く。勾配は
    f_dbed = 2 と同じ slope_flow(近傍の z。ハロはステップ頭で最新)、g_e は m_swflow_enc の
    opt%f_gravity_correction に合わせて g/(1 + tan²θ) か g(2026-11-04 に g/(1 + |∇z|²) へ。§91)、
    門は C ≥ db_cmin・|V| > 0・
    |V| ≥ db_vstop・f_r > 0・tanθ > 0。
  - パス 2: E-D を適用した後の自セルの sd で、被覆を伝播子 rock_cover_inc
    (H* ln(1 + (E dts/H*) e^{−sd/H*}))で積分し、sd・s%ri に足す(z は不変)。
  - 堆積層を剥がした同じ更新で岩盤が削られる順になる。z を書かないので z のハロ交換は
    増えない。sd のハロは、§28.13 の交換と geomorph の末尾の交換が担う。
  - パス 2 の `if (fx == 0.0) cycle` は、岩盤侵食を E-D のないセルでも適用するため
    `if (fx /= 0.0) then … end if` に変えた。演算は変わらない。
- **流水の項の呼び出し**: calc_rockinc は流水の項がある構成(rk%fl)だけで呼ぶ。土石流の
  構成では呼ばない(§89.18 の 6)。dispose の流水の台帳行も rk%fl のときだけ出し、土石流の項は
  「rock erosion by debris flows: eroded … m3」と最大増分 / H* を出す。
- **落とし穴**: 共有スクラッチのセル面積の逆数 gm%wrk%ainv は require_work(掃流砂・クリープの

### 89.23 長い連鎖の 2 セル周期の段差の原因(調査。2026-10-28。コードは変えていない)

§89.22 の隆起ありの連鎖で谷頭と基準面の近くに育つ 2 セル周期の段差を、スクラッチの計算で切り分けた
(1 セル幅の水路に小さな河床の波を与えた応答、スクラッチの実行ファイルでの連鎖。落ち口はそのまま)。

- **結論**: 種は境界、増幅は土石流の流向の勾配の中央差分(格子の大きさの数値的な不安定)。両方を
  外したスクラッチの実行ファイルでは、0.28 の 150 サイクル(4530 年)で段差はまったく出なかった
  (勾配は谷頭まで 0.28、水路全体の勾配の縦断の 1 次元の予測との rms 差 0.0027)。
- **増幅(土石流)**: 土石流の岩盤侵食と f_dbed = 2(江頭・芦田)の侵食・堆積が使う流向の河床勾配
  slope_flow は、y 方向を中央差分 (z_{j−1} − z_{j+1}) / 2Δy で求めるので、2 セル周期の凹凸が見えない
  (f_dbed = 3 は流動面の勾配 slope_flow_surf を使う。初めは「f_dbed = 2・3」と書いた誤りを §89.24 で
  訂正)。土石流は凸部で
  浅い(2 セル周期で h'/z' = −0.22)ので、駆動応力 ∝ h_t tanθ_f は凸部で小さく、凸部ほど削れない。
  - 1 回の土石流(勾配 0.28、振幅 2 mm)で、2 セル周期の波は 2.8 % 育つ(Δy = 1 m で 3.5 %)。3 セル
    1.9 %、4 セル 1.1 %、8 セル 0.15 %、16 セル以上はほぼ 0。成長は物理の波長ではなく、波長のセル数で
    決まる。
