## 104. examples/benchmark の再構築(2026-11-10。利用者の指示「完全に再構築」「STG を使わず ENC の p_diagratio で 4 近傍に」)

**経緯**: 旧 benchmark(h-plane・v-shaped・v-valley)は README がなく、Fortran の mkdata とその生成物・
ビルド済みバイナリ・手読みの理論値の xlsx を含み、設定は非既定(f_gravity_correction = 0、p_diagratio = 0.4、
旧 namelist の名前)で、h-plane の hp10x は FPE で止まる既知の問題があった(handoff「既知の壊れている例題」)。
h-plane と mkdata を廃止し、v-shaped(Tada 2026 の検証問題)と v-valley(ゼミ資料の仮想谷)を、他の例題と
同じ型(README 日英・Python の入力生成・注釈付き param・check.py・図化スクリプト)で、既定の設定のまま作り
直した。旧 benchmark にあった STG との比較は行わず、4 近傍は ENC の `p_diagratio = 0` で表す。

**設計**:
- 幾何は流域に沿う座標 (s, n) の式をセル中心で評価する(debris_fan と同じ。Tada 2026 の「セルは水路か斜面に
  丸ごと割り当てる」)。45° では格子の原点を 2 条件で決める(make_inputs.frame): (1) 水路(谷底)の軸 n = 0 が
  セル中心を通る(ox + oy = mΔx)、(2) 出口の計測面 s = L − Δx/(2√2) がセル中心の斜めの列に重なる
  (oy − ox = √2 L − (p + 1/2)Δx、m + p は奇数)。これで 20 m の水路は斜めの 1 列(Tada 2026 で STG が止まった
  構成)、10 m は 3 列、5 m は 5 列になり、計測面の下流側(B 側)に流域のセルが入らない(面を横切らずに海へ
  出る水がない)ことを生成時に確かめた。
- 出口: 辺境界条件は回転した流域では使えない(出口が領域の内部にある)ので、水路の延長(3 セル)の先に海域
  マスクのセルを置く吸い込みにした(debris_fan の下流端と同じ)。**海セルの水深は 0 でなく 1 m**(fn_hinit で
  海セルだけ)。水深 0 では落差の辺の水深が両側平均の上流側による頭打ち(f_hcap_upwind = 1)で上流の半分に
  絞られ、落差の手前に水が溜まる(20 m・0° で延長部の水深 0.94 m、出口のセルの水深が理論の +9 %)。1 m なら辺の
  水深は上流側の水深そのものになり、延長部の水深は等流水深に近い(0.46 m)。海の水位 1 m は延長部の末端の床
  (20 m で 1.8 m)より低く、背水はない。潮位の hsea0(海セルの見かけの水柱)と同じ考え。
- 計測: 出口は流域の下流端の列を右岸側の尾根から左岸側の尾根まで横切る 1 本(セル番号指定 = エッジ流量方式
  §24.2)。面の A 側は流域全体、B 側は延長・海・領域外だけなので、面を通った量が出口の流量に等しい。全幅に
  するのは、短い測線では踏面の列の範囲の外にあるセルへの斜めのエッジを数えないため(水路だけを横切る測線では
  出口の角の斜めのエッジを落とす)。斜面の脚の計測線は左岸側の斜面の水路に接する列(45° では斜めの列)で、
  下流端のセルから延長部へ向かう斜めのエッジが列の範囲の外になるので、平衡で理論より 0.6〜1.1 % 低い(線の
  端の性質。§24.3)。
- 理論解(analytic.py): 斜面は運動学的波の閉じた式(Overton & Brakensiek 1973)、水路は側方流入つきの運動学的波を
  特性曲線に沿って数値積分する(Di Giammarco ら 1996 の解法に対応。時間刻み 0.5 s、特性曲線の間隔 2 s)。水路の
  径深は h(広幅)を既定にした。ENCflow の水路のセルも底面の摩擦だけで岸の摩擦を持たないため。矩形の径深
  (`--rect`)では立ち上がりが最大 2 % 遅い。旧 benchmark の手読みの理論値(図から読んだ値)と比べると、立ち
  上がりで 1〜3 %、ピークと平衡は一致(手読みの精度の範囲)。斜面の脚の等流水深は 5.3 mm、出口の等流水深は
  0.443 m、出口のピーク 4.86 m³/s = i(2BL + WL)。
- 降雨の時系列: prval は直線補間で、値は 1 分ごとにステップの終わりの時刻で評価されるので、(90, 10.8),
  (90.001, 0) と書くと 91 分降る。(89.99, 10.8), (90, 0) で 90 分 − dt(1 ステップ分 0.02〜0.04 % 不足)。
- 合否(check.py): v-shaped の主ケース(8 近傍・既定の 6 ケース)に NRMSE ≤ 0.04、|格子比 − 1| ≤ 0.01、
  |t50 − 理論| ≤ 3 分、|収支 − 1| ≤ 0.01 の目安を置く。格子比 = ピーク / (降雨強度 × 格子上の集水面積)で、
  45° の面積のずれ(最大 0.8 %)を除いた量。v-valley は理論解がないので、45° の 8 近傍に 0° の 8 近傍との差で
  目安を置く(NRMSE ≤ 0.05、ピーク比 ±5 %、収支 ±1 %)。いずれも test/ へ昇格するときの種(§10。handoff)。
- 収支の読み方: Log の S は延長部を含む全有効セルの平均なので、流域だけの収支は終了時の H9998 を流域のセルで
  足して使う。面の流量の積分 + 流域の残留 = 流域の雨 が 0.2 % 以内で閉じる(不足の内訳は降雨の 1 ステップと
  1 分ごとの標本の台形積分)。

**モデルの性質として README に書いたこと**(限界の明記。§0 方針 13):
- 20 m・45° の斜めの 1 列の水路は、幅 Δx/√2 = 14.1 m の水路として振る舞い、水深が理論の 1.8 倍になる(流量は
  正しい)。10 m の 3 列では 0.99。
- 斜面(n 0.015)と水路(n 0.15)の間の辺の粗度は両側の平均 0.0825 で、脚のセルから水路へ落ちる辺の流速が遅く
  (0.3 m/s。斜面の等流なら 1.8 m/s)、脚の 1 セルの水深が理論の 1.1〜1.5 倍になる(流量には効かない)。
  f_gravity_correction・f_advection_scheme・f_govequation・f_dry_head_cap・f_exflux_reduction を変えても
  変わらず、f_hcap_upwind = 0 では逆に 1 mm まで薄くなってピークが 1.2 % 過大になることを試して確かめた。
- 限界水深 dd = 1 mm を切ると斜面の流れは止まるので、斜面の逓減は 130 分ごろに切れ、理論の長い裾は出ない。
