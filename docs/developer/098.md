## 98. 地下水の層が共有する通過幅: 管路層の分離と斜めの配分の不一致の検出(2026-11-05)

**経緯**: §96 の続きで、地下水の側方流(`gw_diagratio`)の斜めの配分の等方性を計測した(下)。その途中で、
層1(土層)・層2(風化基岩層)・管路層・淡塩2層の塩水 zone が共有する幾何 t_gwlat が「最初の呼び手の d だけを
採用する」作りであることに気づいた。初期化の順は層1 → 層2 → 管路層(m_gwflow_init)→ 塩水(m_main)なので、
土層の側方流が有効だと `gwc_diagratio` と `salt_diagratio` は**黙って無視**されていた(test/salt の param_sea で
`salt_diagratio = 0` にしても出力が全ファイル既定と一致することで確認)。既定は 3 つとも 2/(2+√2) で同じなので、
これまでの計算には影響していない。

**計測(作業領域。既存のパラメータを変えただけ。コード変更なし)**: 中心から同じ距離の格子軸寄りと斜めの
セルの差(r² = 25: (5,0)・(4,3)、r² = 50: (7,1)・(5,5) など)。

| 量 | d = 0 | d = 1/3 | d = 0.586(既定) |
|---|---:|---:|---:|
| 地下水のマウンド(σ = 2Δ、81 × 81、D t = 4Δ²)、r² = 25 / 50 | −0.45 / −1.77 % | +0.00 / +0.01 % | +0.37 / +1.42 % |
| 井戸 1 セルの水位低下の円錐(Q = 1e-4 m³/s、600 s)、r² = 25〜125 | −1.1〜−0.6 % | ≤ 0.02 % | +0.8〜+0.5 % |

側方流は線形化するとクリープと同じ 9 点の拡散演算子(係数 K_sh h̄/s_y)で、§96 の解析どおり 1/3 が等方。

**既定を 1/3 にした場合の影響(試験ビルド。gw・salt・gwc の既定を 1/3 にして回した)**:
- 陽解法の安定条件の上限が 15 % 下がる(Σ l_k/dr_k = 4 − 2d が 2.83 → 3.33)。例題の余裕は estuary_barrage で
  約 185 倍、catchment_metal で約 2 × 10⁴ 倍。管路層の sewer_hybrid は 1.25 倍(超えると自動でサブサイクル)。
- 河床交換能(`f_gwbed`)の上限は通過幅に比例するので、1 セル幅の河道の両岸の合計 2(1 − d + d√2)Δ が
  2.49Δ → 2.28Δ(−8.4 %)。test/gwbed の交換量が −3.1 %。
- reference との差: gwseep の wq.csv 最大 0.8 %、gwsect の湧出量 4.1 %、gwwidth 4.0 %、coastal_drain 1 %、
  管路層の sewer_wq の wq.csv(管路層への移動量)48 %。自己検証の gwtani・gwdefault は合格のまま。
  gwlateral・gwbed は検定スクリプトに d = 0.586 を書き込んでいる(gwlateral の帯の減衰比は実測 0.888 で
  d = 1/3 の予測 0.889 に一致)。
- 地下水の水質(cg)の 1 次風上の横断の数値拡散(物理の分散の代役。users_guide/diagonal_diffusion.md §3.4)が、
  軸の向きの流れで 0.29 → 0.17 uΔ、45° で 0.15 → 0.24 uΔ に入れ替わる。

**管路層は 0.586 が正しい**: 管路層のエッジの通水係数は cnd_k = min(両セルの密度) × 通過幅 wl_k で、振り替え
(f_gw_opening)の対象外。1 セル幅の管路の通水能(同じ勾配での流量)の斜め/軸の比は (d/√2)/(1 − d) で、
0.586 で 1(8 本の通過幅が等しい)、1/3 で 0.35、0(4 近傍)で 0。下水道の幹線のようにラスタを 1 セル幅で
たどる管路は、物理の能力が向きによらないので、等長の基準(素の通水能を向きによらず等しくする)が当てはまる。
上の sewer_wq の 48 % はこの差による。

**決定(2026-11-05。利用者「3で」)**:
- 管路層は自分の `gwc_diagratio`(既定 2/(2+√2))で通過幅を作り、側方流の d と独立にする。
- 通過幅を共有する層(層1・層2 = `gw_diagratio`、塩水 zone = `salt_diagratio`)は同じ帯水層の連続体なので
  同じ値を要する。後の呼び手の値が違えば(差 > 1e-6)停止する。List_samples の 7 桁の 0.5857864 は既定と
  3.8e-8 違うだけなので通る。
- 側方流の既定を 1/3 にするかは、クリープ・曲率の既定変更(§96)と同じ回にまとめて判断する(handoff 00m)。

**実装**:
- 等価変換(コミット A): gwflow_lateral_geom_init を、d によらない部分 gwflow_lateral_geom_init_base(距離・
  面積逆数・エッジ作業領域・eps。base_ready)と、通過幅の部品 lateral_widths(diagratio → wl(1:8) と軸・斜めの
  シェア)に分けた。式は従来と同じで、どの設定でも結果は変わらない。
- 修正(コミット B): t_conduitlayer%wl(1:8) を管路層の init が lateral_widths(gwc_diagratio)で作り、
  conduit_build_cnd が glt%wl の代わりに使う。管路層は共有の幾何のうち base だけを初期化する(距離・作業領域は
  共有のまま)。gwflow_lateral_geom_init は通過幅を作った d とパラメータ名(任意引数 name)を記録し、後の
  呼び手の d が違えば停止する。geom_ready は「通過幅まで含めた初期化済み」、base_ready は「d によらない部分」。
  eps は従来どおり最初の呼び手の値(層1・層2 が管路層より先なので gw_eps)。

**検証(2026-11-05。gfortran 13.3 / Open MPI 4.1.6)**:
- 等価変換(コミット A): 地下水の層を使う 13 の test(gwlateral・gwdefault・gwbed・gwseep・gwsect・gwwidth・
  salt・dissol・conduit・coastal_drain・wqstruct・sewer_wq・gwtani)の全 Run*.sh と、d を既定から変えた
  3 構成(側方流 + 管路層で gw_diagratio = 1/3、salt_diagratio = 0、側方流だけの gw_diagratio = 1/3)の
  出力・save 計 91 ディレクトリが変更前の実行ファイルとバイト一致(不具合も同じに再現 = 等価)。
- 修正(コミット B): 同じ 91 ディレクトリのうち、既定の設定の 89 は変更前とバイト一致(reference の比較も
  すべて PASS)。違うのは意図した 2 つだけ: 側方流 + 管路層(gw_diagratio = 1/3)では管路層の安定条件の
  表示が 0.457 s(管路層が側方流の 1/3 の通過幅を使っていた)から 0.518 s(管路層自身の 0.586。側方流なしの
  模式実験 B と同じ)に変わり、salt_diagratio = 0 は停止する。新しい検定は test/conduit の模式実験 C
  (param_latgw.txt。管路層の安定条件の表示が B と一致、B と同じ自己検定)と test/salt の Run_sea.sh の
  不一致の停止で、変更前の実行ファイルでは C の表示が 0.457 s になって検出できる。MPI np = 2・4 で B・C の
  Log が逐次と一致、不一致の停止も MPI で働く。トップレベルの make が通る。
