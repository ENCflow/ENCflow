## 51. 溶岩流モジュール m_lavaflow(fn_lavaflow。2026-08-23 実装)

噴火口セル群からの湧き出し・深さ平均 Bingham 粘性重力流・停止セルの
固化(→ s%z)を担う独立モジュール。設計の正本は docs/lava_plan.md
(方式選定の理由 = debris 援用が不適な4点、スコープの線引き、段階2
〔温度1変数〕の将来枠を含む)。利用者向けは users_guide/lavaflow.md。

### 51.1 構成(合意事項の要約)

- **独立モジュール(glacier 型)**: 状態は s%hl(m 溶岩柱。有効時のみ
  確保)。fn_lavaflow / &list_lavaflow で有効化、無効時はメモリ・CPU
  追加ゼロ。等温モードは他モジュール依存なし(温度モードは fn_meteo があればその
  気温を読む。§51.7)。
- **定式(等温 Bingham 潤滑流)**: 溶岩面 s = z+hl、面勾配 S、
  降伏最小厚 h0 = τ_y/(ρgS)。エッジ単位幅フラックス
  q = (ρgS/6η)(he−h0)²(2he+h0)(he = エッジ平均厚。τ_y=0 で
  q = ρgS he³/3η の Newton 極限)。拡散形 D = (ρg/6η)(he−h0)²(2he+h0)
  として SIA と同族の非線形拡散になり、§0-5「水平は SWE+1方程式拡散が
  上限」の範囲内。離散化は m_glacier tick_flow と同型(保存形2ループ・
  4近傍 Mahaffy 型・エッジ反対称・ドナー律速 1/4・適応サブサイクル
  〔D_max allreduce_max = 全ランク同一〕)。S はエッジの勾配の大きさ
  (法線・接線の両成分。2026-11-03 に法線成分だけの評価から変更 — §51.4)。
- **噴火口ソース**: モジュール私有(&list_lavaflow 内。水の
  &list_bound_source は流用しない。私有ソースの前例は m_gwflow_pump で、
  書式・検証・セル集合への均等分配も同じ)。運動量なし(拡散型に
  運動量入力は存在しない)。時系列は m_boundary の interp_series /
  read_cell_file2 / read_val_file2 を再利用。
- **固化(数値的閉包)**: エッジ深さ平均速度 u = D・S/he の最大が
  lv_vsol 未満の「停止セル」の hl をレート lv_wsol で s%z へ転換。
  **速度閾値+レートは f_dbstop=1(db_vstop/db_wstop)と同じ閉じ方**。
  当初案の「フラックス厳密 0 の不動セル」判定は、Bingham の停止が
  漸近的(q ∝ (h−h∞)² → 0 だが有限時間で 0 に達しない)なため実際には
  発火しないことが実装中に判明し、速度閾値方式へ変更した(2026-08-23。
  lava_plan.md §5 も同時改定)。判定はパス1が時刻 n の場から行い
  パス2が適用する(tick_erosion と同型の競合対策)。z のみ増加
  (**sd は増やさない** = 固化溶岩は侵食されない岩盤。f_dbstop の
  z・sd 共動〔可動堆積物〕とは意図的に異なる。固化したセルにあった
  土層は溶岩の下に埋める = sd → 0。§51.6)。再流動なし。
  e 回復と z のハロ交換まで行う。速度の S も勾配の大きさ(§51.4)。数えるのは
  溶岩が動けるエッジ(溶岩面の高い側 = 送り手に溶岩がある)だけ(§51.5)。
- **実行順序**: geomorph_calc・driftwood_calc の後(z 更新プロセスの
  末尾)、calcstat の前。init は geomorph の後(morfac=1 検査に
  s%geo_morfac を参照)。STG 非対応・morfac>1 非対応(イベント計算)。
- **水理との関係**: 地表水は流動中の溶岩に不可視で z の上を流れる
  (glacier §5 と同じ割り切り)。海セルとは無フラックス。固化面の
  粗度は既存分布のまま(段階1の割り切り。lava_plan.md §7)。土層は
  埋めるので、土層を層とする地下水モデルでは溶岩の上にしみ込まない(§51.6)。
- **台帳・リスタート**: 場出力 Hl。S_total に算入しない(水柱でない。
  噴出・固化・残存の体積台帳を dispose で allreduce_sumr し root 表示)。
  リスタートは私有 lavaflow.dat(契約5)。

### 51.2 パラメータ(&list_lavaflow)

lv_rho(ρ)・lv_visc(η。必須)・lv_tauy(τ_y。0 = Newton)は直接入力
(§0-12)、**レオロジーはラン全体で1組**(噴火口別の粘度は不採用 —
合流時に混合則=粘度の移流場が必要になる複雑化に見合わない。粘度差の
実体は温度・組成で、段階2の温度従属+噴火口毎の噴出温度で表現する。
2026-08-23 討議)。固化は lv_wsol + lv_vsol(§51.1)。噴火口は
lv_cell / lv_q0 / lv_val / fn_lv_cell / fn_lv_val(pump と同じ様式。
最大 20 噴火口・番号連続・負率は par_stop・海セル/域外は par_stop)。
dt_lavaflow_c 未指定は毎ステップ。温度モード(§51.7)は f_lvtemp・lv_temp0(噴火口ごと)・lv_tref・
lv_bvisc・lv_btau・lv_tsol・lv_emis・lv_hconv・lv_cp・lv_tair(fn_meteo がないとき)を
加え、すべて既定なしの明示指定。

### 51.4 降伏と停止の判定を勾配の大きさで行う(格子の向きによる歪みの修正。2026-11-03 挙動変更)

- **現象**: 平坦床の 1 火口から噴出して降伏応力で止まった溶岩(塑性ドーム)が、
  格子軸の方向に伸びたひし形になる。test/lava 構成 4(下記)を修正前のコードで
  回すと、格子軸の方向と斜めの方向の扇形の面積等価半径の比が 0.860、前縁までの
  距離が格子軸の方向 19.0 m・斜めの方向 14.1 m(比 0.74)、中心厚が解析解より
  +9.5%。溶岩流の例題(楯状火山)の検討で、複数回の噴火を重ねた試算の等高線が
  ひし形になって見つかった。
- **原因**: 降伏最小厚 h0 = τ_y/(ρgS) の S に、エッジの法線方向の勾配
  |Δs|/dist だけを使っていた(Mahaffy 型の簡略版)。溶岩面が格子に対して 45° に
  傾くと、各エッジの法線勾配は |∇s|/√2 に見えるので、降伏応力が実質 √2 倍になり、
  静止形の半径は 1/√2 ≈ 0.71 倍になる(実測 0.74)。landslide_tsunami_plan.md §11
  が「Bingham なら対角の降伏厚 h0 が √2 倍」と予告していた歪み。
- **修正**: 係数 D(= 降伏最小厚 h0)をエッジの勾配の大きさ S = √(Sn² + St²) で
  評価し、エッジの向きは線形項 Δs/dist(法線勾配 Sn)の射影にだけ使う(同 §11 の
  「真の Mahaffy 化」。氷床モデルの Mahaffy (1976) がスタガード点で両成分から
  |∇s| を作るのと同じ考えの 4 近傍版 — Mahaffy, M. W. (1976): A three-dimensional
  numerical model of ice sheets: Tests on the Barnes Ice Cap, Northwest Territories.
  J. Geophys. Res., 81(6), 1059–1066。接線勾配の取り方は本プロジェクト独自)。
  接線勾配 St は、エッジ両側のセルのうち溶岩のある(hl > 0)セルに
  ついて、エッジに沿う方向の溶岩面の差分を求めて平均する。差分は、その方向の両隣が
  溶岩のある有効セル(領域内・海でない)なら中心差分、片方なら片側差分、なしなら 0。
  乾いたセルの地盤高は溶岩面ではないので使わない(谷壁に接する溶岩で、壁の勾配が
  降伏と停止判定に入らないように)。固化の停止判定に使う流速 D・S/he も同じ S で
  求める(法線成分だけでは斜め方向の流れが 1/√2 に見えて早く止まる)。
- **決定の理由**:
  - 4 近傍のまま直す。8 近傍化(*_diagratio)は landslide_tsunami_plan.md §11 の
    別項目として残す。hb の処方(セルの 8 近傍最急降下勾配で速度を一度だけ決め、
    下り方向へ配分)は風上型の輸送のためのもので、エッジ反対称の拡散型である
    溶岩流には、エッジで両成分から |∇s| を作る形が素直。
  - 既定を切り替え、旧方式に戻すスイッチは置かない。旧方式は格子の向きによる
    離散化の誤差で、選ぶ理由がない(§0-6)。τ_y = 0(Newton)では h0 = 0 で係数が
    勾配によらないので、流動は変わらない(接線勾配も求めない)。変わるのは τ_y > 0
    の流動と、固化ありの停止判定(τ_y = 0 を含む)。
- **ステンシルと並列**: 接線勾配は東西のエッジ(パス A・B の k=4)で行 j±1 を
  読むので、書き手の行 je+1 では je+2 まで読む(ハロ幅 2 の内側。全域端の外は
  x = 0 で読まない)。帯界面のエッジは両ランクが同じ入力から同じ式で冗長計算し、
  接線勾配は 2 セルの値の加算の交換だけで対称(IEEE で厳密)なのでビット一致する。
- **計算量**: τ_y > 0 ではエッジごとに 2 セルの接線勾配を求める。test/lava
  構成 4(4 スレッド)で 4.4 s → 5.1 s(サブサイクル数は係数が変わるため
  12,647 → 12,199)。
- **検証**(gfortran 13.3 / Open MPI 4.1.6、Ubuntu 24.04):
  - **test/lava に構成 4 を追加**(param_dome.txt。平坦床・中央 1 セルから
    2 m³/s を 900 s、τ_y = 10⁴ Pa、固化なし、6000 s)。止まった形を、平坦床上の
    Bingham 流体の静止形(塑性ドーム。降伏の釣り合い ρg h |∇h| = τ_y から
    h(r)² = (2τ_y/ρg)(R − r)、体積 V = (8π/15)√(2τ_y/ρg) R^{5/2}。溶岩ドームの
    粘塑性モデル Blake (1990)・Balmforth ら (2000) の静止形。出典の書誌は
    users_guide/lavaflow.md の参考文献)と比べる。検定: (1) 台帳が機械精度、(2) 扇形の面積等価半径の比
    (斜め/格子軸)が 1 に 5% 以内、(3) 中心厚と面積等価半径が解析解に 5% 以内、
    r < R の断面の RMS 誤差が中心厚の 5% 未満。修正後は比 1.014、中心厚 +1.2%、
    面積等価半径 −1.5%、RMS 2.1% で PASS。修正前のコードでは比 0.860、+9.5%、
    −5.1%、12.5% で FAIL(検出器として働く)。粘度は静止形に効かないので、
    検定時間内に止まる値(η = 10⁶ Pa s)にした(3000 s と 6000 s の静止形の差は
    中心厚で 1.6%)。
  - 構成 1(Huppert)と構成 2(Bingham の斜面)の save(state.dat・lavaflow.dat)は
    修正前とバイト一致(構成 1 は τ_y = 0、構成 2 は幅方向に一様で接線勾配が 0)。
    構成 3(既定値の同値)も PASS。
  - -fcheck=all(-Og)の MPI np=2・np=4 で構成 1・2・4 がクリーン(最適化ビルドの
    検証より先に実行。絶対規律 3)。
  - -O2 厳密数学ビルドで、逐次 = MPI np=1, 2, 4 の state.dat・lavaflow.dat が
    構成 1・2・4 でバイト一致。リスタート往復(構成 4: 3000 s で save → restore →
    6000 s)もフル計算とバイト一致。通常の -Ofast ビルドでも Run_MPI.sh の
    np=2・4 が 3 構成とも逐次とバイト一致。
  - 溶岩を使わないケースは計算の経路が変わらない。reference を持つ CI の高速セット
    16 件(wave・dambreak・frost・pump・conduit・salt・vzcol・vzzone・prmap・
    wfshoal・wfshadow・wfcurrent・wfsed・wfswash・gwlateral・gwtani)が逐次で PASS。
  - 新規コンパイル警告なし。
- **残る限界**: 1 セル幅の細い流れでは、接線方向の両隣に溶岩がなく、法線勾配だけの
  判定に戻る。流束は 4 近傍(5 点)のまま。溶岩の縁の接線勾配は片側差分。
- **関連して見つかった既存の問題**: 溶岩より高い乾いたセルに接するセルが固化しない
  不具合(この修正の前からある)。同日に §51.5 で修正した。

### 51.5 停止判定に溶岩の動けないエッジを数えない(壁に接する溶岩が固化しない不具合の修正。2026-11-03 挙動変更)

- **現象**: 溶岩より高い乾いたセル(谷壁・段・先に固まった溶岩の縁)に接する溶岩の
  セルが、止まっていても停止と判定されず、いつまでも固化しない。test/lava 構成 5
  (下記。高さ 10 m の段の前にたまった溶岩)を修正前のコードで回すと、壁に接する列
  (i = 30)の全行が溶けたまま(hl 0.98 m)残り、固化率 0.869。§51.4 の検討中に
  見つかった(§51.4 の修正の前のコードでも同じ)。なお、楯状火山の例題の試算
  (20 回の噴火を重ねる)の終了時に残った溶岩(噴出量の 0.4%)は、この不具合では
  なく、最後の噴火の溶岩がまだ流れている途中のものだった(終了前の 10⁶ s にも
  厚さが最大 9.5 m 変化。この修正の前後で残る量はほぼ同じ)。
- **原因**: 固化の停止判定(tick_solidify)は、セルの 4 エッジの深さ平均流速
  D・S/he の最大を見るが、エッジの勾配の向きを見ていなかった。壁へ向かうエッジは
  隣の溶岩面(= 壁の地盤高)のほうが高い「流れ込み」のエッジで、送り手の壁に溶岩が
  ないので、流動(パスB)ではドナー律速で流量が厳密に 0 になる。ところが停止判定は
  このエッジも、両セル平均の厚さ he と壁の急な勾配から流速を求めて数えていた。壁の
  勾配が急なほど h0 = τ_y/(ρgS) が小さく hf = he − h0 > 0 になり、流れるはずのない
  エッジの流速が閾値 lv_vsol を大きく超えたままになる。
- **修正**: 流れ込みのエッジ(ds = s_c − s_n < 0)は、送り手である隣に溶岩がなければ
  (hl_n <= 0)数えない。流出のエッジ(ds > 0)の送り手は溶岩のあるセル自身なので
  これまでどおり数える。パスB のドナー律速(送り手の溶岩体積で流量を抑え、溶岩が
  なければ 0)と同じ考えで、停止判定と流量の扱いをそろえた。
- **決定の理由と範囲**:
  - 流量が厳密に 0 のエッジだけを除く。流量のあるエッジは数え方を変えないので、
    動いている溶岩を早く止めることはない。
  - 送り手にごく薄い溶岩しかない流れ込みのエッジは、これまでどおり数える(流量は
    ドナー律速で小さく抑えられるが 0 ではない)。薄い溶岩は流れ出して消えるので、
    その後に判定が変わる。閾値を置いて「薄い」を決めることはしない(数値の任意性を
    増やさない。§0-6)。
  - パスA(安定条件の D_max)は変えない。流量 0 のエッジの D が D_max に入っても
    サブサイクルが少し細かくなるだけで、結果の正しさには影響しない。
- **検証**(gfortran 13.3 / Open MPI 4.1.6、Ubuntu 24.04):
  - **test/lava に構成 5 を追加**(param_wall.txt・make_init.py wall。40 m × 8 m の
    平坦な床の東端に高さ 10 m の段、壁から 3 m の列に計 0.2 m³/s を 300 s、
    τ_y = 2000 Pa、固化あり、4800 s)。検定: (1) 台帳 Σhl + Σdz = 注入量が機械精度、
    (2) 固化率 > 0.999、(3) 壁に接する列の全行で hl = 0 かつ dz が最大厚の半分超。
    修正後は固化率 1.0000、壁際の dz 0.978 m(最大 1.076 m)で PASS。修正前の
    コードでは固化率 0.869・壁際の hl 0.978 m で FAIL(検出器として働く)。壁際以外の
    堆積の形は修正の前後で同じ。
  - 構成 1〜4 の save(state.dat・lavaflow.dat)は修正前とバイト一致(構成 1・4 は
    固化なし。構成 2・3 で溶岩より高い乾いたセルへ向かうのは上流端の緩い斜面の
    エッジだけで、もともと hf <= 0 で数えられていなかった)。
  - -fcheck=all(-Og)の MPI np=2・4 で構成 1・2・5 がクリーン。
  - -O2 厳密数学ビルドで、逐次 = MPI np=1, 2, 4 の state.dat・lavaflow.dat が
    構成 1・2・4・5 でバイト一致(構成 1・2・4 は §51.4 の版とも一致)。通常の
    -Ofast ビルドでも Run_MPI.sh の np=2・4 が 4 構成とも逐次とバイト一致。
  - 溶岩を使わないケースは計算の経路が変わらない。CI の高速セット 16 件が逐次で
    PASS。新規コンパイル警告なし。

### 51.6 固化した溶岩の下の土層を埋める(2026-11-03 挙動変更)

- **現象**: 固化は z を上げるだけで土層厚 sd を変えなかったので、土層のあるセル
  (地形変化 fn_geomorph や、土層を層とする地下水 fn_gwflow の計算)では、溶岩の下に
  埋まるはずの土層が溶岩の上に残った(岩盤面 z − sd が上がり、土層ごと持ち上がる
  扱い。隆起と同じ)。その後の雨・流れは、新しい溶岩の上に残った土を削り、土にしみ
  込んでいた地下水もそのまま残った。test/lava 構成 6(下記)を修正前のコードで回すと、
  溶岩の下の 80 セルで sd = 1 m・地下貯留 hg ≤ 0.059 m が残った。溶岩流の例題(溶岩流
  → 降灰 → 侵食の繰り返し)の検討で、灰の上に溶岩が乗ると灰が溶岩の上に残ることから
  見つかった。
- **修正**: 溶岩が固化したセル(転換量 w > 0)に土層(sd > 0)があれば、その土層を
  溶岩の下に埋める。
  - sd を 0 にする。埋まった土は岩盤 z − sd の内側に入り、以後の侵食・浸透の対象から
    外れる(岩盤侵食 f_rockinc の対象にはなる)。
  - 土層の内数である動く底層 hb・細粒分 sf・崖錐 ht と、土層の定着度 fx(植生)も 0 に
    する(新しい溶岩の上に植生はない)。
  - 地下水計算が有効なら、容量 sd × sy0 を失った分の地下貯留(sd = 0 なので全量)を
    地表水へ移す。水の総量は保存する。土石流の侵食で土層が減ったときの扱い
    (f_dbwet=2 と同じ容量超過の規則)と同じ。河道幅セルでは地表の水深を §26.1 の
    換算(gw_to_h)で増やす(2026-11-03、§26.1 のブランチとのマージ後に追加。報告する
    量は地下の側の水深で数える)。
  - 台帳: 埋めた土層の体積と、地表へ移した地下水の量を dispose で報告する
    (「lavaflow: soil buried under solidified lava … m3, groundwater moved to the
    surface … m3」。土層を確保している計算のときだけ)。
  - 近傍を読む次の過程(地下水の側方流・地形変化)のために、sd と内数のハロを交換する
    (確保の有無は全ランク同一。h・hg は次ステップの頭で swflow・gwflow が交換する)。
- **決定の理由と範囲**(利用者と合意。2026-11-03):
  - 既定で埋め、切り替えは置かない。土層が溶岩の上に残るのは物理的に誤りで、選ぶ
    理由がない。土層を確保しない計算(溶岩だけ、test/lava の構成 1〜5)は何も変わらない。
  - 流れている溶岩の下の土層は埋めない(固化して地形になった時点で埋める)。
  - 土層は 1 層しかないので、埋まった土は後で侵食で掘り出されても岩盤として扱われる。
  - **浸透への影響(限界)**: 土層を地下水の層とするモデル(Green-Ampt・側方流)では、
    溶岩が固化したセルの容量が 0 になり、溶岩の上に降った雨はしみ込まずに流れる。
    実際の新しい溶岩(とくに玄武岩質)は割れ目が多く水を通すことが多いので、浸透を
    過小に見積もる。灰などが積もって土層ができれば、その厚さの分だけしみ込む。溶岩の
    透水性の表し方は未設計(handoff の溶岩流の項)。
  - 塩水(fn_salt)の地下の塩水貯留 hgs は動かさない(地下貯留が減ったときの扱いは
    m_saltwater の上限処理に任せる。土石流の侵食と同じ)。
- **検証**(gfortran 13.3 / Open MPI 4.1.6、Ubuntu 24.04):
  - **test/lava に構成 6 を追加**(param_bury.txt。構成 5 の地形に土層 sd0 = 1 m と
    Green-Ampt の地下水、初期の地表水 5 cm を土層へしみ込ませてから 15〜20 分に溶岩を
    噴出)。検定: (1) 溶岩の台帳が機械精度、(2) 固化した溶岩のある全セルで sd = 0 かつ
    hg = 0、ほかのセルの sd は 1 m のまま、(3) 水の総量 Σ(h + hrs + hg) が初期の地表水に
    相対 1e-9 以内。修正後は埋めた土層 80 m³、地表へ移した地下水 5.65 m³、水の差
    −5.3e-13 m³ で PASS。修正前のコードでは (2) が FAIL(溶岩の下に sd = 1 m が残る)。
    溶岩の堆積(z・hl)は埋める前後でバイト一致(土層と水だけが変わる)。
  - 構成 1〜5 の save は修正前とバイト一致(土層を確保しない)。
  - -fcheck=all(-Og)の MPI np=2・4 で構成 5・6 がクリーン。
  - -O2 厳密数学ビルドで、逐次 = MPI np=1, 2, 4 の state.dat・lavaflow.dat が
    構成 2・5・6 でバイト一致。通常の -Ofast ビルドでも Run_MPI.sh の np=2・4 が
    5 構成とも逐次とバイト一致。

### 51.7 溶岩の温度(段階2。f_lvtemp = 1。2026-11-04 機能追加)

lava_plan.md §8 の設計(2026-11-03 起案)を、§8.13 の 5 点を推奨どおりとする利用者との
合意(2026-11-03)で実装した。設計の考え方・式の導出は lava_plan.md §8、利用者向けは
users_guide/lavaflow.md の「温度モード」。

- **合意事項(5 点)と理由**:
  1. 冷却は案 A(深さ平均温度から有効放射率 ε で放射。表面の殻の断熱は ε を下げて表す)。
     パラメータが 1 つで、MAGFLOW と同じ型。案 B(FLOWGO 型の殻の被覆率と殻の温度)は
     結果を見てからの拡張。
  2. 固化は温度だけで判定する(Tl ≤ lv_tsol のセルの溶岩を柱ごと z へ)。速度閾値の閉じ方
     (lv_wsol・lv_vsol)は温度モードでは使わない(lv_wsol > 0 との併用は par_stop)。
     止まっても熱いうちは固まらず、冷えてから固まる。
  3. 結晶化の潜熱・地面への熱伝導・粘性発熱は入れない(潜熱は有効比熱 lv_cp に含めて
     与えてよい)。
  4. 既定値は置かない。溶岩の種類で桁が変わる値(噴出温度・基準温度・温度感度・固化温度)は
     明示指定。放射率・対流係数・比熱は原典を確かめてから既定を決めるが、この作業の
     ネットワーク制限で原典の全文を確認できなかったため、当面は同じく明示指定(未指定は
     par_stop。handoff の溶岩流の項)。
  5. 最小版 → 検証 → 文書の順。例題は後日。
- **状態と保存量**: s%tl(深さ平均温度 °C。帯+ハロ。f_lvtemp = 1 のときだけ確保。溶岩の
  ないセルは 0)。移流で保存する量は熱量 hl·Tl(0 °C 基準の顕熱。× ρc_p × 面積 = J)。
- **tick の順序(契約)**: (1) 注入(熱量で混合 Tl ← (hl Tl + dh T_v)/(hl + dh))→
  (2) hl・tl のハロ交換 → (3) 流動のサブサイクル → (3') 冷却 → (4) 固化。
  - パス A・B: エッジの温度 T_e = (hl_c Tl_c + hl_n Tl_n)/(hl_c + hl_n)(hl ≤ 0 の側は重み 0。
    c・n の入れ替えで同じ値 = 帯界面の冗長計算がビット一致)から
    cf = (ρg/6η_r) exp(β_η (T_e − T_r))、ty = τ_r exp(−β_τ (T_e − T_r))(edge_rheology)。
    指数の引数は ±50 で打ち切る(異常な入力での桁あふれ防止。通常の溶岩の範囲では効かない)。
    β = 0 なら exp(0) = 1 で等温と同じ値。パス B で熱のエッジ流量 qt = q × 送り手の温度(風上)。
  - パス C: 温度モードは先に熱量を同じ保存形で更新し、新しい温度を作業領域 tw へ置く
    (近傍の旧温度を読むため)。hl の更新は等温と同じループで、両モードが同じコードを通る
    (β = 0・冷却なしで hl が等温とビット一致する条件。-Ofast の再結合で両モードの和の順が
    分かれないように、hl のループを複製しない)。最後に tw を tl へ写し、hl・tl のハロを交換。
  - 温度の範囲: ドナー律速(1 エッジの持ち出し ≤ 送り手の 1/4)で、新しい熱量は自セルと
    流れ込みの送り手の温度の凸結合になる。新しい Tl をこの範囲に収める(範囲外は丸めか、
    hl がほぼ 0 になったセルの桁落ちで、収める操作の熱量の差は丸めの大きさ)。hl ≤ 0 に
    なったセルは Tl = 0。
  - 冷却(tick_cool・cool_be): セルごとに後退 Euler。H(T) = h (T − T_n) + (dtw/ρc_p)
    [ε σ (T_K⁴ − Ta_K⁴) + h_c (T − Ta)] = 0 の根を [Ta, T_n] でニュートン法により求める
    (式に h を掛けた形なので h → 0 でも桁あふれしない)。H は単調増加かつ凸で
    H(Ta) < 0 ≤ H(T_n) なので、T_n から始めると単調に根へ下がり行き過ぎない(Ta を
    下回らない)。|ΔT| ≤ 4ε T_K で打ち切り(上限 50 回。実測 3〜8 回)。気温以下の溶岩は
    冷えも温まりもしない。失った熱量 h (T_n − T) を、新しい温度での放射と対流の比で台帳の
    内訳に分ける(合計は失った熱量そのもの)。tl のハロは次 tick 冒頭の交換が配る(固化は
    自セルの温度だけを読む)。
  - 固化: パス 1 で Tl ≤ T_sol のセルに sdz = hl(柱ごと)、パス 2 は等温と共通(土層の埋没
    §51.6 も同じ)に、固化した溶岩の熱量を台帳へ移して Tl = 0。
- **気温**: fn_meteo があれば meteo_temp_cell(セルの標高 z + hl で評価。減率も効く。
  meteo_temp_set は collective なので全ランクが呼ぶ)、なければ lv_tair。fn_meteo と lv_tair の
  併記は par_stop(どちらを使うかの曖昧さを避ける)。lv_tair ≥ lv_tsol は par_stop
  (固まらない)。
- **公開インターフェース**: m_lavaflow_init・m_lavaflow_calc に t_meteo を加えた(m_main の
  呼び出しを更新。init は meteo の後)。utils は m_lavaflow を使わない(トップレベル make で
  確認)。
- **出力・台帳**: 分布 Tl(°C。溶岩のないセルは 0。f_lvtemp = 1 で自動)。dispose で熱の台帳
  (噴出・放射・対流・固化・残存、リスタートで復元した開始時の熱量)と、残差
  (開始時 + 噴出 − 放射 − 対流 − 固化 − 残存)を表示する。台帳は allreduce_sumr で集める
  診断(計算の状態には使わない)。
- **リスタート(設計案 §8.9 からの変更)**: 温度は別の私有ファイル lavaflow_temp.dat に置き
  (f_lvtemp = 1 のときだけ)、lavaflow.dat の形式と save_version は変えない。設計案は
  lavaflow.dat に Tl を加えて save_version を上げるとしていたが、save_version は全モジュール
  共通で、上げると既存のすべての保存が読めなくなる。温度の有無で lavaflow.dat の形式を
  変えると、等温で保存したものを温度モードで再開したときに読み終わりの実行時エラーになり、
  わかりやすい停止にならない。別ファイルなら、温度モードの再開でファイルがなければ明確に
  停止できる。等温の保存では保存先の古い lavaflow_temp.dat を消す(同じ保存先を後で温度
  モードで再開したときに古い温度を読まないように)。
- **計算量**: 温度モードだけの追加(tl・qt・tw の確保、サブサイクルごとの熱量のループと
  写しと tl のハロ交換 1 本、エッジごとの exp 2 回、セルごとのニュートン法)。等温モードは
  何も確保せず呼ばない。冷却は実時間で進むので、等温の例題のように粘度を大きくして時間を
  縮めることはできない(lava_plan.md §8.11)。
- **限界**(users guide にも記載): 1 つの有効放射率で動いている溶岩と止まった厚い溶岩を
  表すので、厚い溶岩だまりは実際より早く冷える(固化の時刻は当てにならない。校正の対象は
  流れの長さ)。深さ平均温度 1 つなので殻と内部の区別・溶岩チューブは出ない。後退 Euler は
  1 次精度(刻みが冷却の時定数 ρc_p h/(dF/dT) に比べて大きいと冷え方が遅めに出る)。
- **検証**(gfortran 13.3 / Open MPI 4.1.6、Ubuntu 24.04):

      (出力は小数 4 桁)、(2) 温度の低下が厳密解(RK4)に相対 9.4e-4、(3) 漸化式で
      T ≤ 800 °C になる 499 回目の更新(t = 4990 s)で全セルが固化(hl = 0、dz = 1 m)し、
