## 27. 蒸発散(&list_evap。2026-08-09 実装)

### 設計

- **加算的プロセス**(独立フラグの重ね合わせ方式)。有効化は fn_evap の
  指定(f_evmodel=0 で一時無効化)。新モジュール m_evap / list_evap。
  適用は run_main の時間ループで gwflow の後(浸透後の状態に作用)。
- **PET の決定法(f_evmodel。排他切替)**: 1=一定速度 evap0(mm/day)、
  2=月別気候値 evap_monthly(12)、3=Hamon、4=Thornthwaite。式の追加は
  pet_mmday に case を足す。全モード共通の換算係数 evap_kc(既定1)。
  - Hamon: 0.1651·(N/12)·216.7·es/(T+273.3)(es は Tetens 式, hPa)
  - Thornthwaite 日割り: 16·(10·max(T,0)/I)^a·(N/12)/30。熱指数 I は
    平年月平均気温 temp_normal(12) から init で計算(高温域 >26.5℃ の
    修正式は省略=既知の妥協)
  - 可照時間 N: Cooper 近似の太陽赤緯+日出角(白夜・極夜はクランプ)
- **暦**: date0_c(t=0 の暦)は &list_sysparam が正本(p%jdn0/sec0/
  has_date。当初 evap 私有だったが水質等の第2利用者の出現に伴い昇格。
  §29)。グレゴリオ暦⇔ユリウス通日は m_util の Fliegel & Van Flandern
  (整数演算、うるう年規則込み。Python 対照で往復・2100年平年を検証済み)。
- **評価粒度**: 暦日ごとに1日1回、「日の先頭」の気温で PET を更新し
  日内一定。気温式は本来日平均気温の式のため、入力は日平均系列を推奨
  (時系列の時刻単位は「日」。疎な点でも線形補間・端値保持)。
- **気温入力**(モード3,4): m_meteo(&list_meteo。§29)が提供する。
  fn_meteo が必須(一様定数/一様時系列/分布時系列+標高減率の仕様は
  §29 を参照。当初 evap 私有だった入力機構を移設)。
- **減算順序**: 樹冠保水 → 地表水 h → ため池 hrs → 地下水 hg の順に
  「あるだけ引く」(供給制限のみ。土壌乾燥による抑制なし=RRI 同等。
  evap_hglim を与えたときだけ地下水の段を土の乾き具合で抑える。§27.2)。
  - 樹冠: t_intercept に draw 口を追加(貯留型モデルのみ束縛。現状
    initloss の st を減じる=遮断容量の乾き戻り。蒸発散無効なら従来
    どおり回復なし)
  - 地表水: 水面の面積の分だけ蒸発する。σ 有効セルは dV=σ(h)dh の関係に
    より「真水深から引く」こと自体が現在の水面幅に比例した体積減(§26 と
    整合)。次の段へ渡す要求は実際に減った体積の分だけ減らす(河道幅・σ の
    セルの陸の部分・河岸は hrs・hg から。§27.1)
  - ダム・湖沼: 捕捉集合の貯留 hrs からため池と同様セル面積分ずつ引く。
    湛水面積=捕捉セル数×セル面積(湖面をラスタで塗れば実面積。§22)。
    旧 dam_area(E×面積の一括評価+捕捉帯スキップ)は 2026-08-20 廃止
- **save/restore**: PET は t の純関数で履歴状態なし=保存不要(復元後は
  現在時刻の暦日で再評価)。樹冠 st は intercept 私有 save、h/hrs/hg は
  state.dat が既に保存。**save 形式の変更なし**。
- **診断**: result/evap.csv(rank0、dt_recrd 間隔)に基準 PET(mm/day。
  分布気温時は使用セル平均気温で評価)と累積蒸発体積(樹冠/地表/hrs/
  地下、m3。旧ダム列 ev_dam_m3 は dam_area 廃止に伴い 2026-08-20 削除)。
  体積の面積基底は樹冠=セル面積、h=af、hrs・hg=gv。
  累積はラン先頭からの積算(restore でリセット=既知の妥協)。
- **MPI**: PET は (t,z) の純関数で全ランク同値。累積診断は行部分和+
  par_sum_rows(決定的)。

### 27.1 河道幅・断面形のセルでの地表水の段(2026-11-04 修正)

**発見**: examples/catchment_metal に蒸発散を入れる設計の試算(ステップ 4 + 一定
4 mm/day)で、河道幅のセルの要求の差し引きに単位の取り違えを見つけた(§26.1・
§26.2 と同じ「河道の平面の水深とセルの平面の水深の取り違え」の型)。

- **不具合**: 地表水の段で引いた水深 w は、河道幅のセルでは河道の平面(セルの
  wfrac の部分)の水深、σ のセルでは水位の低下なのに、セルの gv 面積あたりの
  要求 dem からそのまま差し引いていた。河道に水がある間(w = dem)は要求が 0 に
  なり、河道幅のセルの陸の部分(1 − wfrac)と、σ のセルの水面の外の河岸
  (1 − σ(h))が hrs・hg から蒸発しなかった。台帳(evap.csv)は実際に減った体積で
  数えていたので水は保存し、蒸発散が少なく出るだけ。
- **規則(修正後)**: 地表水は水面の面積の分だけ蒸発する(水深から
  w = min(h, dem) を引く)。次の段へ渡す要求は、実際に減った体積をセルの gv 面積で
  割った水深だけ減らす: 河道幅だけのセルは w·wfrac、σ のセルは
  sect_dvh(hb, ha)·wfrac(wfrac は wfr_of)、どちらもないセルは w(wfrac = 1 なので
  従来の式とビット一致)。
- **採らなかった案**: セル全体の要求を河道の水から引く(河道の水深を dem/wfrac
  下げる)案は、水面の蒸発の速さが 1/wfrac 倍(幅 15 m・格子 250 m で 17 倍)に
  なり物理的でない。雨は陸の部分に降った分も河道へ入れる(§18)が、蒸発散は陸の
  部分の土から起きるとみなす非対称は意図的。セルの中の陸の部分と河岸の蒸発散を、
  セルで共有する hrs・hg から引くのは独自の簡略化(users guide の forcing_models
  §3 に明記)。
- **検証**:
  - test/gwwidth の param_evap.txt(河道幅のみ)、test/gwsect の param_evap.txt
    (σ + 河道幅)・param_evap_nowidth.txt(σ のみ): 側方流なしの閉じた谷で土層を
    満たし、余った雨を谷の河道に溜めて、PET 48 mm/day を 4 時間。助走 30 分の後の
    蒸発散の増分 = PET × 面積 × 時間 のずれ(記録時刻ごとの最大)が、修正後は相対
    4e-16(河道幅のみ・σ のみ)・6e-8(σ + 河道幅。evap.csv の es15.7 の精度)、修正前は
    6.9 / 7.3 / 6.3 % の不足。
    総水量 + 蒸発散 = 雨(相対 3e-9)と水質の台帳(蒸発では物質が残る)は修正の
    前後とも閉じる。助走を除くのは、雨の降り始めの数ステップで河道セルの地下が
    まだ空で、要求を満たせないため(σ + 河道幅で相対 2e-5 の不足。不具合ではない)。
  - MPI: 上の河道幅のみ・σ + 河道幅の構成を np = 1, 2, 4 で実行し、Log.txt・
    evap.csv・wq.csv が逐次とバイト一致(-Ofast)。
  - 既存の回帰: 蒸発散を使う test/icevap の構成 g(河道幅・σ なし)が、修正の前後で
    Log.txt・evap.csv・save の全ファイルともバイト一致(幅も σ もないセルは従来の式の
    まま)。test/gwwidth・test/gwsect の param.txt(蒸発散なし)は reference と ULP = 0。
  - 全回帰(test の 91 件、-Ofast、4 スレッド。reference は更新しない): 90 件合格。
    nhshelf は Log の最終桁が 2 量子ずれる箇所が 5 か所で不合格になったが、既知の
    NH ソルバの 4 スレッドの実行間非決定(handoff の (g))。1 スレッドでは修正の前後で
    Log.txt がバイト一致し、reference に合格する(ULP = 1)。
- **例題への影響**: examples/catchment_metal のステップ 6(ステップ 4 + 一定 4 mm/day)を
  修正前の実行ファイルの試算と比べると、180 日の蒸発散は 433 → 444 mm(+2.5 %)だが、
  乾季も本川を河口近くまで流れていた鉱山の排水(G5 で 0.03 m³/s・200 µg/L)が、修正後は
  T1 を約 3 km 下ったところで途切れ、本川は 118〜122 日目に干上がる。海への物質の流出は
  93 → 17 kg。河道セル(陸域の 6 %)の陸の部分の蒸発散が、基底流を出す谷底の地下水を
  引くため、流域全体の水収支では小さな差でも乾季の川の結論が変わる。

### 27.2 土の乾き具合による地下水の段の抑制(evap_hglim。2026-11-04 合意・実装)

**背景**: §27 の「あるだけ引く」(RRI 同等)では、hg が残る限り地下水から可能蒸発散の
速さで引く。examples/catchment_metal のステップ 6(一定 4 mm/day)で、蒸発散の 97 % が
地下水から引かれ、乾季に 4 m の土層の水が尽きて基底流がほぼ消えた(乾季の流量の
少なめ側の端。§27.1 の例題への影響)。

- **比較した案**(利用者と合意。推奨どおり):
  - A 貯留による線形の低減(採用)。
  - B 消散深さ(MODFLOW の EVT。地下水面の深さで線形に減らす): Green-Ampt は hg を
    「上からしみ込んだ水」、側方流は「底からの地下水面」として読むので、深さの解釈が
    割れる。底からの地下水面で読むと、斜面の雨の後の蒸発散がほぼ消える。
  - C 根群域の貯留を別に持つ 2 層: 新しい状態(保存・再開・水質の質量・浸透との結合)
    が要り、方針 5・6 に照らして重い。
- **式**: 地下水の段だけ E_g = Ks·E_rest、Ks = min(1, hg/h_lim)。FAO-56 の
  Ks = (TAW − Dr)/((1 − p)TAW) で、残りの有効水分 TAW − Dr を hg、(1 − p)TAW を
  h_lim と読んだもの(HBV の土壌水分による低減 LP と同じ形)。evap_kc を作物係数 Kc と
  読めば Ks·Kc·ET0 の組み立てになる。樹冠・地表水・hrs(水面)は抑えない。河道幅・σ
  のセルで陸の部分・河岸の要求が地下水の段へ回る規則(§27.1)はそのまま。
- **パラメータ**: evap_hglim (m。&list_evap。全モード共通)。容量に対する割合
  (HBV の LP·FC)でなく絶対量にしたのは、割合だと土層が厚いほど同じ雨の後の Ks が
  小さくなるため(4 m・容量 0.4 m で 60 mm の雨の後に Ks ≈ 0.2)。方針 12 に従い直接
  与える(p・TAW からの換算は利用者の前処理。目安の式は users guide の forcing_models
  §3)。既定値は置かない(土と植生の与件・校正値)。未指定(番兵 −9999)なら抑制なしで、
  分岐により従来の行そのものを通る(ビット一致)。0 以下は停止。分布(土地利用別。
  fn_evap_hglim)は第 2 段の候補(未実装)。
- **時間積分**: ステップの中で要求の速さ E = dem/dt を一定として
  dhg/dt = −E·min(1, hg/h_lim) を厳密に解く(m_evap の hg_draw。hg − dem ≥ h_lim なら
  dem、さもなくば h_lim までの線形分 lin = max(hg − h_lim, 0) と、残りの指数減衰
  (hg − lin)(1 − exp(−(dem − lin)/h_lim)) の和)。1 − exp(−x) は x < 1e-2 で級数
  (打ち切り誤差は相対 x^5/720 以下)にして桁落ちを避ける(典型の dem/h_lim は 1e-5
  程度)。厳密な流れの写像の合成は厳密なので、時間刻みによらず解析解に一致する。
- **状態・保存・MPI**: 状態を持たない(hg の純関数)ので save の形式は変わらない。
  セル内で閉じるので通信もない。無効時の追加は論理値の分岐 1 つ。
- **限界**(users guide に明記): hg は層 1 全体の貯留で鉛直の分布を持たない。根の深さ・
  土の保水性を直接は表さない。雨の直後に表層だけ湿った状態や、裸地の蒸発と蒸散の
  違いを表せない。h_lim は乾季の流量の観測などで校正する。
- **検証**:
  - test/evapdry の 3 構成(evap_hglim 0.02 m・0.1 m・なし): 雨の後の地下の貯留が
    解析解に一致(1.5 時間の値に対して 1e-13 = Log の印字の桁)、総水量 + 蒸発散 = 雨
    (相対 2e-8 以下)、水質の台帳が閉じる(蒸発では物質が残る)。
  - MPI: test/evapdry の param.txt を np = 1, 2, 4 で実行し、Log.txt・evap.csv・wq.csv
    が逐次とバイト一致(-Ofast)。
  - 未指定時: 蒸発散を使う既存の構成(test/icevap の g、test/gwwidth・test/gwsect の
    param_evap*.txt)が、新旧の実行ファイルで全出力ファイルともバイト一致。
  - 全回帰(test の 92 件。evapdry を含む。-Ofast、4 スレッド。reference は更新しない):
    全件合格(既知の 4 スレッドの非決定がある nhshelf も今回は合格)。
- **例題**: examples/catchment_metal のステップ 6b(ステップ 6 + evap_hglim 0.05 m)。
  180 日の蒸発散は 444 → 431 mm(3 % 減)、本川の干上がりは 118〜122 日目 → 126〜128 日目
  (1 週間遅れ)、海への物質の流出は 17 → 77 kg。補給のない土の水が減る時定数
  h_lim/PET = 12.5 日が乾季(80 日)より短いので、結果は抑制なしの端に近い。時定数は
  h_lim に比例するので、乾季の基底流の残り方は h_lim の校正しだい(README に明記)。
