## 87. 鉛直不飽和浸透(VZ)流出モデル m_vzflow(fn_vz。2026-10-26 設計合意)

谷(2023)の VZ 流出モデル(十分深い参照土壌柱の鉛直不飽和浸透を解き、各地点の
土層厚の深さの下向き流束を読み出して流域面積で積分する)を、**共有参照柱**・
**VZ 区画**・**明示的な出口**として ENCflow の格子に載せる。設計の正本は
docs/vz_plan.md(添付の設計文書 2 点はリポジトリ外。plan が ENCflow 側の正本)。

### 87.1 決定事項(2026-10-26 合意)

- **方針の例外**: §0-5 に「共有参照柱に限る 1 次元 Richards」の例外、§1 に
  「柱の状態・台帳は real64 固定」の例外を追記した(plan §2)。
- **独立モジュール**: m_vzflow(管理)+ m_vzflow_column(1 本の柱の計算核。
  水平格子・区画・出口を知らない)+ list_vz。fn_vz で有効化。gwflow の鉛直
  モデル切替(f_gwvertical)には入れない(貯留が hg と別物、空間的に一部の
  区画だけに適用、雨の入口が違う)。
- **雨の受け渡し**: swflow の直後に、VZ セルに降った雨の分
  `s%pre·dt/s%gv` を s%h から回収して柱の上端流束にする(地下水と同じ
  「swflow の後に s%h から取る」結合型。浅水流ソルバーと s%pre は無改修)。
- **並列**: 全ランクが全柱を冗長に解く(§11「冗長計算=配布機構」)。
- **界面 K** は算術平均が既定(HYDRUS-1D と揃える。要照合)、調和平均は比較用。
- **時間精度**はステップ二分比較、非線形は修正 Picard+失敗時の刻み半減から
  始める(L スキーム等は単体試験で必要が示されたら)。
- **初期版の併用制限**: fn_gwflow・fn_snow・fn_glacier・fn_geomorph・fn_wq・
  fn_salt・fn_nest・STG は init で停止(plan §4.10)。
- **小杉パラメータの既定値は置かない**(原論文と照合できるまで必須入力。照合の結果、
  試験地ごとの値なので既定にしないままとした。§87.5)。→ 2026-10-27 改定: 試算用の
  既定(竜ノ口山 TY の組と q0 = 0.1 mm/h)を置いた(§87.7)。

実装・検証の記録は以下の小節に追記する。

### 87.2 実装(2026-10-26。P1・P2)

- **構成**: src/m_vzflow_column.f90(計算核。t_vzctl 数値制御 / t_vzgeo 幾何と
  物性 / t_vzwork 後退 Euler 1 歩の作業領域 / t_vzcol 柱の状態)、
  src/m_vzflow.f90(管理。t_vzflow を t_encflow の成分に持つ。モジュール変数の
  状態なし = Check_modstate.py で検出なし)、src/list_vz.f90(&list_vz・
  &list_vz_column・&list_vz_zone。グループがなければ既定のまま。値の解釈と
  検証は m_vzflow_init)。各ヘッダが実装契約の正本。
- **呼び出し位置**: init は m_swi_init の後(併用検査に他モジュールの fn_*、
  VZ セル・出口の検査にゾーン2の全域マスクと境界の一覧を使う)。calc は
  m_swflow_calc の後の par_allreduce_maxi(ierror) の直後(gwflow より前。
  初版は併用不可)。record は do_recd、outprof は do_file、dispose は
  m_swi_dispose の後。
- **仮引数の重なり**: 計算核の初稿は作業配列を「派生型の成分」と「別の仮引数」の
  両方で渡しており、Fortran の別名規則(重なる実引数への書き込みは未定義)に
  反していた。t_vzgeo(intent(in))と t_vzwork(結果 psi・th・f も含む)を分け、
  呼び出し側が枝の配列へ写す形にした。
- **時間誤差の判定**(既定値は vzcol での試行で決めた):
  - 積算流束の相対許容 vz_tol_q = 1e-2。1e-3 との 12 h の累積流束の差は
    0.05 %、費用は 1/7。
  - 相対尺度の下限 q_floor = 柱内の最大流束の 1 %(独自)。下限がないと
    毛管上昇と重力排水の境目の「流束がほぼ 0 の界面」で相対判定が極端に
    厳しくなり、試行刻みが 0.2 s 程度に張り付いた。
  - θ・ψ の許容 1e-3、非線形許容 = 時間許容 × 1e-2、Picard 上限 25、
    刻み 1e-3〜3600 s、増加率 1.5、水収支予算 mb_rate = 1e-11 m/s。
    Richardson 外挿はしない(細かい枝の状態と流束を一組で採用)。
- **同期間隔 dt_vz の既定 60 s**(vzcol、120 層、12 h、dt = 5 s、1 スレッド。
  VZ なしの同条件 0.25 s に対する増分): dt_vz = 0(毎ステップ)1.7 s・受理
  12854 歩、60 s で 1.0 s・6252 歩、600 s で 0.7 s・5676 歩。12 h の累積排水の
  差は 0 と 60 s で相対 1.1e-4(時間許容の規模。tight 検定の 2.56e-4 と同程度)。
  排水の受け渡しの遅れ(最大 dt_vz)は山地の応答時間(数十分〜数時間)に比べ
  無視でき、毎ステップ同期の費用増は利点に見合わないため 60 s を既定とした
  (plan §5.6 の見積りの実測)。
- **層厚**: 層数は入力の精度(既定 real)で nz = nint(depth/dz) と判定し、
  層厚は depth/nz を real64 で作る(単精度ビルドで 0.025 を real64 に広げると
  端数が出て「整数倍でない」と停止していた。2026-10-26 修正)。
- **土層厚 0**(2026-10-26 追加。谷 2023 の線形分布は 0 cm 区分を含む): VZ セルの
  土層厚は 0 以上を許す。界面 0 で読み出すので排水 = F_0、貯留 = 0(W(0) に入り
  層重み M には入らない)で、読み出しの式の特別扱いは要らない。負と非数は停止。
  検定は test/vzcol の param_sd0.txt(Check_vzcol.py sd0)。
- **静水圧の初期条件 vz_wt0**(2026-10-26 追加。谷 2023 の KIEX は下端 ψ = 0・地表
  ψ = −50 cm の線形分布で始める): 初期地下水面の深さ d_wt を与え、層中心で
  ψ = ζ − d_wt(下は正 = 飽和)。vz_q0_mmh・vz_psi0 と排他。下端固定圧 ψ_b の柱で
  d_wt = L − ψ_b なら流束 0 の静止解(test/vzcol の param_hydro.txt で ψ が 5.6e-17 m、
  累積流束が 1.6e-17 m の範囲で保たれることを確認)。
- **雨の回収**: dh = pre·dt/gv を s%h から引く(VZ セルは河道セルでないので
  wfrac なし)。**0 で切らない**: 連続式は前ステップの水深で流出を決め負の
  水深を 0 にしないので、run-on のある VZ セルでは雨を加える前の水深が微小な
  負になりうる。初稿の max(h − dh, 0) は CFL 超過の試行(急斜面・初期水深
  0.1 m・dt = 5 s、Cn 最大 1.6)で S_total の収支誤差 8.9e-3 m を作った
  (修正後 3.8e-5 m。残りは CFL 超過下の浅水流側。dt = 1 s では修正前後で
  ビット一致)。回収した雨は s%vzp(セル、m)に積み、同期で 0 に戻す。
- **柱の入力の揃え方**: 厳密一致モード(f_vz_rain = 0)はステップ × 柱の局所
  max と −min を区間末に 1 回の allreduce(max)で揃え、柱内で不一致なら全ランク
  同時に par_stop。面積平均モード(= 1)は局所の行部分和が変わったステップ
  だけスナップショットを積み(容量は倍々)、区間末に par_sum_rows で決定的に
  総和する(ランク数によらずビット同一)。
- **集約と出口**: 排水 ΔV_g = Σ_j W F と貯留 V_g = Σ_k M θ。丸め規模の負の
  排水は 0 に切って vcorr に記録し、有意な上向き流束(読み出し深さでの
  毛管上昇)は適用外として停止する。出口セルへの加算は所有ランクだけが
  V/(dx·dy·gv·wfrac) で行い、h に実際に加わった量との差を real64 の繰越
  ocarry で次回に回す(単精度ビルドで微小な量が丸めで消えない)。
- **重み W・M**: 初期化時に全ランクが区画番号マップと土層厚の全域を持ち
  (rank0 読み → bcast、sd は gather → bcast。初期化の一時配列)、界面区間の
  整数ヒストグラム+部分層で O(セル数 + 層数) に作る。Σ W = A_g、
  Σ M = Σ A d を相対 1e-10 で内部検査する。時間ループは帯の zid だけ。
- **台帳**: s%vzstore(Σ V_g、real64)と s%vzp を calcstat が S_grnd に算入する
  (既存の総和ループとは別ループ+par_sum_rows。VZ 無効時は既存の総和の
  演算順を変えない = ビット一致の条件)。
- **保存・復元**: 私有ファイル vzflow.dat(save_version = 20261026。§87.9 で 20261027)。rank0 が
  書き、全ランクが読む(柱は冗長)。柱の ψ・試行刻み・累積流束・区画の累積
  診断・出口の繰越を持つ。繰越は所有行だけ非 0 の行部分和を par_sum_rows で
  集める(real64 のまま。初稿は既定 real の allreduce を経由して単精度で
  丸めていた。2026-10-26 修正)。同期区間の途中で保存するときは dispose で
  残りのステップを同期してから書く(回収済みの雨を捨てない。連続計算と
  一致するのは同期時刻で保存したとき)。

### 87.3 検証(2026-10-26。gfortran 13.3 / Open MPI 4、既定の -Ofast ビルド)

- **test/vzcol**(1 柱・1 区画・系外流出。Check_vzcol.py): 定常期(雨 = q0)の
  F = q0·t と貯留不変、各深さの ΔS = F0 − D(残差予算比 2.4e-4)、小杉式の
  θ・K が Python の math.erfc と一致、区画の量 = セルごとの読み出しの和、

### 87.4 落とし穴と記録

- **FFLAGS だけの変更は再ビルドを起こさない**: スタンプが追うのは MODE・
  MPI・PREC だけ。-fcheck 等の検証ビルドは別ディレクトリの複製か、全
  オブジェクトの削除で行う(逐次と MPI の結果が食い違って見えた原因が
  これだった)。
- **モード切替後の libencflow.a**: `ar rcs` は既存のメンバーを残すので、MPI
  ビルドの後に逐次へ戻すと MPI 版のオブジェクトが残りうる。切替時は
  src/libencflow.a を消してから make する(トップレベルの make で utils の
  リンクを確かめる)。
- **既存の不具合(2026-10-27 に修正。§88)**: m_precip で dt_mapunit_c が
  既定分岐で上書きされて効かない、dt_mapunit(文書は分)が秒として
  使われる、dt_maplist_c が idt_maplist の計算より後に適用される。vzzone は
  既定(prtype = 2 の mm/day)だけを使って回避した(修正後もビット一致)。

### 87.5 谷(2023)の再現例題 examples/vz_tani2023(2026-10-26。P4 の一部)

- **データの扱い(利用者の判断)**: 論文の降雨・観測・計算流出強度は図にしかない。
  数値はリポジトリに置かず(再配布しない)、利用者が J-STAGE の PDF を入手して
  `extract_tani2023.py` が図のベクトル描画(pdfminer.six で矩形・線・曲線の座標)
  から `data/` に取り出す。目盛りの線から軸を較正し(日付の軸は 0 時の主目盛り。
  日付のラベルは日の中央に置かれている)、表−1 と照合する(最大時間雨量は KIEX・
  TY1・TY2・KI1 が表と一致、総雨量は KIEX +0.1 %・TY1 +0.6 %・TY2 +0.4 %・
  KI2 −0.2 %・MREX −2.0 %(図は 12 時間平均の棒))。PDF の SHA-256 を記録。
- **対象**: 全 7 事例(KIEX・MREX・MR1・TY1・TY2・KI1・KI2)。設定は論文の本文と
  表−2 のまま(柱 10 m・2.5 cm・自由排水、KIEX は 50 cm・底面 ψ = 0・静水圧の初期
  条件。土層厚の線形分布を 1 区分 = 1 セルの区画で表す。TY は 3 流域が柱を共有)。
  論文がモデルの外で行った後処理(KI: 排水の 1/2 を深部浸透、MR: 排水 − 0.3 mm/h を
  1/2 ずつ堰へ、MREX: 降雨の 20 % を蒸発散)は、入力(降雨の係数)と比較スクリプトで
  同じように適用し、本体には足していない。そのために土層厚 0(線形分布の 0 cm 区分)と
  静水圧の初期条件 vz_wt0(KIEX)を足した(§87.2)。
- **降雨の時刻の割り当て(推定)**: 図の 1 時間の棒は正時を中心とし、正時の前後
  どちらの 1 時間かは図から決まらない。論文の計算値が大きい範囲での
  |log10(ENCflow/論文)| の 90 % 値で ±0.5・±1.0 h を比べ、TY1 は +0.5 h(正時から
  始まる 1 時間)、TY2・KI1・KI2・MR1 は −0.5 h(正時までの 1 時間)を採った。
  TY1 だけ向きが違う理由は不明(README に明記)。ピーク時刻の差は採用した割り当てで
  −0.1〜+0.15 h。
- **結果**: KIEX・MREX・MR1・TY2 は論文の計算値(HYDRUS-1D)にほぼ重なる(大きい
  範囲の 90 % 値 0.021〜0.085 = 5〜22 %、ピーク差 2.3 % 以内)。TY1・KI1 は 90 % 値
  0.060〜0.097、ピーク差 4 % 以内で、低流量期の差は論文が計算値に加えた分離基底流に
  当たる。KI2 は ENCflow が中央値で約 3 割低いが、差(論文 − ENCflow)は時間に
  ほぼ比例して 0.1 → 0.6 mm/h と増え、観測の最初と最後を結ぶ直線を足すと中央値
  +0.001・90 % 値 0.080・ピーク差 +2.4 % になる(風化花崗岩の桐生の大きい基底流。
  直線は論文の分離線そのものではない近似)。MR1 は論文の計算の開始時刻が不明で、
  図の左端(11/16)から初期条件で始めた。独立な実装との一致として、計算核(混合形・
  修正 Picard・ステップ二分比較)、区画の読み出し、柱の共有、下端固定圧、静水圧の
  初期条件の検証になる。
- **小杉パラメータの既定値(§87.1 の保留の解決)**: 原論文の値は試験地ごとの現場の
  土壌の値(表−2。竜ノ口山・桐生・Mettman Ridge で Ks が約 40 倍、σ が 2 倍違う)で、
  一般の既定にはならない。照合の結果として**既定を置かない**ままとし、利用者

### 87.8 土性クラス別の試算値(Carsel and Parrish 1988 の換算。2026-10-27)

利用者が提供した原論文(Carsel and Parrish 1988, WRR 24(5), 755–769、
doi:10.1029/WR024i005p00755、paper number 7W4964。PDF はリポジトリに置かない)の
表 2〜5 の土性クラス(米国 SCS の 12 区分)の平均値 θs・θr・α・N・Ks を、
Kosugi (1996) の式 (24)〜(26)(σ² = (1 − m) ln[(2^{1/m} − 1)/m]、
ψm = −(2^{1/m} − 1)^{1−m}/α、m = 1 − 1/N)で小杉式に換算し、利用者ガイドの
「既定値を見直すときの手がかり」に試算値の表として載せた(コードは変えない)。

- **原論文の値の性質**: 保水曲線の測定値の当てはめではなく、SCS の土壌調査報告
  (42 州・42 冊)の砂・粘土の割合とかさ密度(θs はかさ密度から)から
  Rawls and Brakensiek (1985) の回帰式で推定した値のクラス平均(図 1・図 3)。
  農地の土壌、埴土は粘土分 60 % 未満。Ks の単位は cm/h(表 4。式 (2) の定義も cm/h)で、
  クラス内の変動係数は 52〜453 %(平均は中央値より大きい)。
- **換算の確認**: 換算した ψm で van Genuchten 式の S_e = 0.5、小杉式の変曲点
  ψm exp(−σ²) が van Genuchten 式の変曲点 −m^{1−m}/α と一致(式の構成どおり。
  12 区分とも数値で確認)。二つの式の違いの大きさ(ψ = −1 cm〜−100 m の S_e の
  最大差、K_r ≥ 10⁻³ での K の最大の比)は砂 0.05・1.3 倍〜壌土 0.10・2.7 倍、
  シルト・埴壌土で 0.14〜0.15・5〜7 倍、シルト質埴壌土・砂質埴土で 15 倍、
  N = 1.09 のシルト質埴土・埴土で 0.18・400 倍(使えない値と明記)。
- **ENCflow での確認**: test/vzcol の格子(柱 10 m・2.5 cm、q0 = 0.1 mm/h の既定)で
  12 区分とも雨 = 0.5 Ks を 3 時間与えて計算できる(時間刻みの棄却 2〜12 回)。
  雨 > Ks では湛水で停止する(壌土に 20 mm/h で停止、砂壌土は計算可)。細かい
  土性は湛水時の境界切替(P4)が入るまで弱い雨でしか使えないことを文書に書いた。
- 値の丸め: Ks は表 4 の値を 10 倍(mm/h)、θs・θr は原表のまま、ψm(m)・σ は
  有効数字 3 桁。森林流域の試算には谷(2023)の 3 組を勧める(森林土壌の表層の Ks は
  これらよりずっと大きいことが多い)。

### 87.9 区画の基底流(vz_base / fn_vz_base。2026-10-27 合意・実装)

谷(2023)は観測のハイドログラフから基底流を直線で分離し(流出の立ち上がりと
終わりを結ぶ。論文 Ⅲ.1 が引く角屋 1979 の方法)、その基底流出強度を VZ の計算
流出強度に加えて観測と比べた。添付の設計文書(リポジトリ外)の §11.5 は「物理計算に
基底流を無条件で加えない。モデルに加える場合は明示的な外部供給として水収支へ
入れる」としており、その形で入れた。

- **決定(2026-10-27 合意)**: 方式は「VZ 区画ごとの時系列」(案 A)。不採用案 B は
  コードを変えず出口セルに既存の内部ソース `&list_bound_source` を置く使い方の
  文書化で、地表出口(kind 1)にしか使えず、谷(2023)の再現に使う系外流出(kind 2)
  で使えない。単位は区画面積あたりの mm/h(論文の基底流出強度・vz_ks_mmh・
  vz_q0_mmh と揃える。体積への換算はモデルが区画面積を掛ける)。方針 §0 との関係:
  基底流は直接与える量で、分離の方法(どの線を引くか)は利用者の前処理(方針「変換は
  前処理で」)。物理的な地下水からの基底流は地下水モデルの範囲(初版は VZ と併用不可)。
- **入力**: `&list_vz_zone` の `vz_base(1:2, k, z) = 時刻(分), mm/h`(1 区画 100 点まで。
  vz_nbasemax)と `fn_vz_base(z)`(dir_data 起点、1 行「時刻(分) mm/h」。m_boundary の
  read_val_file2 で読む = 境界の時系列と同じ書式。ファイルが namelist より優先)。
  線形補間・範囲外は端の値を保持(境界の時系列と同じ規約)。時刻は減らないこと
  (同じ時刻の 2 点で段差)、値は 0 以上を setup_baseflow で検査して停止。時刻の
  秒換算は既定 real の `t*60` をファイルと namelist の両方で同じ演算にした。
- **計算**: sync_interval の区画集約で、区間 [t0 + dt·(it − nk), t0 + dt·it](s%t と同じ式。
  隣の区間と継ぎ目が一致)の区分線形の厳密な積分(base_integral。端の外の保持区間・
  段差の 0 幅区間を含む)× 区画面積を dvb とし、出口へ dv + dvb を渡す
  (kind 1 は同じ配分率で出口セルの水深、kind 2 は vext)。基底流は柱・区画の貯留に
  入らない外部供給: vdrain・vstore・residual は不変、vint・vext は排水 + 基底流、
  新しい累積 vbase。kind 1 の基底流は S_total を増やし、kind 2 の基底流は系外から
  系外へ出るので S_total に現れない。基底流のない区画は dvb = 0 で、x + 0 = x
  (dv ≥ 0)なので演算はビット不変。区画ごとの時系列(数点の real64)以外のメモリを
  足さない。
- **出力**: vz_zone.csv の最後に vbase(m3) 列(基底流を与えた区画があるときだけ =
  無効時はヘッダ・行とも従来とバイト一致)。区画確認表に基底流の点数と最初・最後の値。
- **保存・復元**: 区画の行に vbase を追加し vzflow.dat の save_version を 20261027 に
  更新(§7)。版の不一致は構成の不一致と分けて「state file format version」で停止する
  ようにした(従来は構成の不一致の文言で止まっていた)。基底流の時系列は入力なので
  保存しない(再開時に変えてよい)。
- **検証**(test/vzzone の param_bflow.txt。Check_vzzone.py bflow と base): 区画 1
  (kind 1)に namelist の系列(同期間隔 60 s の途中の区切り 30.5・300.25 分、90 分の
  段差)、区画 3(kind 2)にファイルの系列(最初の点より前の保持)。累積 vbase と
  Python の分数による厳密な積分 × 面積の差は相対 2e-14、出口の量 = 排水 + 基底流は
  相対 2e-14、VZ 側の列と vz_column.csv は基底流なしと一致、受水セルの水深・地表水の
  総量(相対 8e-14)・S_total の収支(2e-11 m。基底流を入れて拡張)。sed で作る
  保存 → 再開(6 h)が連続計算と完全一致、時刻が減る系列は停止(MPI でも全ランク)。
  `-Og -fcheck=all` の逐次で実行時検査に掛からない。release の MPI で np = 1・2・4 の
  Run_MPI.sh が合格、np = 1 と 4 の基底流の全出力(プローブ含む)がバイト一致。
  基底流のない既存の vzcol・vzzone は Log.txt・vz_zone.csv・vz_column.csv とも
  reference とバイト一致(機能追加の規律)。
- **例題**: examples/vz_tani2023 の KI2 は、それまで比較の後処理で足していた
  「観測の最初と最後を結ぶ直線」(論文の分離線そのものではない近似)を、
