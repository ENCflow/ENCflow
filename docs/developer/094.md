## 94. セルの流出の合計による過大な流出の抑制(辺ごとの抑制の取りこぼしによる負の水深の修正。2026-11-05 不具合修正)

**現象**: 既定を f_gravity_correction = 2 にしたところ、test/gwwidth の自己検定「雨の後の総水量が
一定」(相対 1e-10)が河道幅なしの対照(param_nowidth.txt)で落ちた(最大相対 6.4e-5)。総水量 S_total が
約 4 分ごとに 3e-6 m ほど跳ね上がり、2〜3 分で厳密な値に戻る鋸歯状。1 のまま粗度を 2 倍にしても同じずれが
出て、適応的ルンゲクッタを切る(f_adaptive_runge = 0)と消える(§93)。

**原因**(計測を入れた作業用の版で特定。コミットしていない):
- 跳ね上がりは S_surf に出る。1 分ごとの地表の水深 H に負の値があり(河道の隣の斜面の列。最小 −1.3e-4 m)、
  その合計が跳ね上がりと合う(71 分: 2 セルで計 −2.5e-4 m ÷ 有効 96 セル = 2.6e-6 m、跳ね上がりは
  2.65e-6 m)。地下水の貯留 hg に負の値はない。m_state の集計は h > 0 のセルだけを足すので、負の分だけ S が
  多く見える。状態としての総量は保存されていて(連続式は辺ごとに対称)、負の分が後の湧出・流入で埋め戻
  されると厳密な値に戻る。§68.29 の「S の漂いは負水深が集計から外れる見かけの量」と同じ見え方。
- 連続式の直後に水深が負になったセルの 8 辺の流量を出す計測で、最初の事象(t = 3285 s)は、河道(列 10)の
  隣の斜面のセル (9,2)。水深 7.67e-5 m(dd = 1 mm 未満)の水膜が、水深 5.2 cm の河道へ軸の 1 辺と斜めの
  2 辺から同時に流れ出す。これらの辺は前ステップの流量が 0(流速 0)なので、エッジ水深の上流側の頭打ち
  (f_hcap_upwind = 1。上流側を前ステップの流速の向きで決める)が掛からず、エッジ水深が両側の平均
  (2.6 cm、水膜の約 340 倍)になる。陽解法の流量(斜め 3.97e-3、軸 5.61e-3 m²/s)はどの辺も単独で水膜を
  超えるので、辺ごとの抑制が流量を 0 にする(dd 未満なので残す量がない)。流量が前ステップの 0 から変わった
  ので適応的ルンゲクッタが再計算し、仮の水深の減少で流量が少し小さくなる(斜め 3.60e-3)。斜めの 2 辺は
  単独ではそれぞれ水深 7.46e-5 m 分で水膜をわずかに下回って抑制に掛からず、軸の辺だけが 0 になる。2 辺の
  合計は水膜の 1.95 倍で、水深が −7.26e-5 m になる。
- 辺ごとの抑制は、その辺の流出だけを水量と比べるので、複数の辺の合計が水量を超えることを防げない(利用者
  ガイド encgrid.md §5 に「エッジごとに順に判定するため負水深が完全には防げず」と既知の限界として書いて
  いた事象)。陽解法だけ(f_adaptive_runge = 0)ではどの辺も単独で超えて 0 になるので負にならない。2 は
  摩擦をわずかに変えて再計算の流量の当たり方を変えただけ(1 でも粗度 2 倍で同じことが起きる)。
- 発生範囲(-O2 の計測版で、reference を持つ非静水圧以外の 34 ケースの主設定と副設定): 連続式の直後に水深が
  負になったのは damwq(2 ステップ・延べ 4 セル、最小 −3.1e-5 m)・gwsect(372・1,246、−6.4e-4 m)・
  gwwidth(本体 851・2,520、−2.2e-4 m。対照 8,555・18,986、−2.2e-4 m)・sewer_wq(67・140、−1.4e-7 m)
  だけで、いずれも時刻 n の水深が dd 未満のセル。非静水圧のケースは計測していないが、修正の回帰で nhbreak の
  ex_flux が 1 行変わった(合計が水量以上のセルがあった)。
- ex_flux の内訳(-O2 の計測版で累計を数えた): 深い水に接する薄い水膜のある計算では、ex_flux のほとんどが
  上の「前ステップの流速が 0 の辺で、送り手が dd 未満、流量 0」の繰り返し(流量 0 → 次のステップも流速 0
  から → また 0)。examples/ashfall_lahar の param_water(浸透のある降雨流出。後半に ex_flux が増える)で
  49,446 回のうち 49,430 回、damwq で 71,704 回の全部、gwwidth 本体で 12,678 回の全部、gwsect で 7,904 回の
  全部、sewer_wq で 496 回の全部。浸透のあるほかの検定 12 ケース(深い水に接しない)と chichibu_icmap・
  dambreak は 0 回。時間刻みの大きさの問題ではないので、利用者ガイドの「ex_flux が増え続けるなら dt を
  小さく」という読み方には合わない。

**対策の案**(2026-11-05 に比較した。作業用の木の試作で):
- (P) セルの流出の合計による抑制: 連続式の直前に、連続式と同じ換算でセルの流出の合計を求め、水量以上の
  セルの流出の辺を同じ率で縮める。負の水深を防ぐ保証になり、超えるセルがなければ結果は変わらない。
  辺ごとの抑制とその ex_flux はそのまま残る(水膜が止められて毎ステップ抑制が発動する挙動も残る)。
- (U) 前ステップの流速が 0 の辺は、新しい流速の向きの上流側の水深で流量を頭打ちする: 上の繰り返しを断つ
  (ex_flux が ashfall_lahar で 49,446 → 180、damwq・gwwidth・gwsect・sewer_wq で 0。負の水深は試した範囲で
  0)。ただし合計の判定がないので負の水深を一般には防げない(ashfall_lahar で残る 180 回は静止からの流れ
  出し 110・流れの続く辺 70・向きの反転 0)。堰の公式・境界面など運動方程式の外で流量を決める経路にも
  効かない。最小の形は流速を両側平均の水深の摩擦で求め、流量だけを水膜の水深で求める 1 ステップの不整合を
  残す。半陰解法の分母 1 − tfe Δt_l は 1 以上なので、新しい流速の向きは分子 uve0 + (tae + tge) Δt_l の
  符号で摩擦より先に決まり、これでエッジ水深の上流側を決める形(U″)なら不整合がなく向きの反転も同じ扱いに
  なる。dd 未満の水膜が深い側へ流れ出るようになる(今は止められて浸透・蒸発するか dd を超えるまで溜まる)
  モデルの挙動の変更で、結果の変わる範囲が広い。
- (S) S の集計で負の水深も数える: 見かけのずれは消えるが、負の水深が残るので修正にならない。

**決定**(2026-11-05。利用者「提案で進めてください」): P を不具合の修正として入れる。U は U″ の形で P の上に
試作し、全ケースと例題で影響を見てから既定を判断する(handoff 00l。既定 2 の後の全例題の再計算の前に
決めると再計算が 1 回で済む)。U″ は同日に既定の挙動として入れた(§95)。ex_flux の表示は残す(利用者の指摘「U を既定にしたら ex_flux の表示の意味が
なくなりそう」への回答): 今の ex_flux の大半は上の繰り返しの回数で、本来の警告(1 ステップでセルの水を
使い切ろうとした。時間刻みが大きすぎる、§68.29 の堰の 2Δt 振動のような振動)が埋もれている。U″ を既定に
すればふだん 0 になり、0 でないときは本当に水を使い切ろうとした辺がある(P が働いた回数も同じ列に入る)
という警報として読める。

**実装**(m_swflow_enc。連続式 continuous と scale_cell_outflow):
1. continuous のセルのループで、連続式と同じ辺・同じ換算の流出(dh > 0)を h1 とは別に足して合計 O を
   求める。水量 h(σ 有効時は矩形換算水深)について h − O ≤ 0 なら率 rout = max(h − dd, 0)/O(辺ごとの
   抑制と同じく dd を残す。辺の向きによる偏りを作らないよう、流出する辺はすべて同率)、それ以外は 1。
   率が 1 未満の自帯のセルの数を返す。
2. 率の配列 rout を par_halo_cell で交換する(帯の境界の辺は風上のセルが隣のランクのことがある)。
3. scale_cell_outflow: 率が 1 未満のセルが自帯かハロ行にあれば、エッジ行 js−1..je の辺ごとに、風上(流出
   する側)のセルの率を流量 mn1 と流速 uv に掛け、連続式を解き直す。辺の両側で同じ値になるので保存は
   保たれる。各辺を書くのは 1 反復だけ(OpenMP の競合なし)。解き直しは縮めた流量で 1 回だけ解くのと同じ
   結果になる(continuous は h1・u・v・m・n・流向をセルごとに作り直す)。解き直しで求め直す率は使わない。
- 縮めたセルの数を ex_flux に加える。
- f_exflux_reduction > 0 のときだけ(rout もそのときだけ確保。判定は namelist 由来で全ランク同一なので、
  ハロ交換の有無が全ランクで揃う)。0 のときは確保・計算・通信とも従来どおりゼロ。
- 抑制が働かないステップの追加の計算は、連続式のループの中の足し算と判定、ハロ交換 1 回だけ。辺の走査と
  連続式の解き直しは縮めるセルがあるステップだけ。最初の形(2026-11-05 の 8e76524)は連続式の前に流出の
  合計を求める走査を毎ステップ別に持っていて、chichibu の逐次(OpenMP 2、2 時間分)が 115.2 → 120.7 秒
  (+4.7 %)遅くなったので、同日に結果を変えずに連続式のループへ移した(等価変換。別コミット)。
- 範囲外: 流れの計算の後に水深を変える処理(境界の水位、ダム、地下水・蒸発散など)は対象外。S の集計が
  正の水深だけを足すのは変えない。スカラーの柱状量 c1 の非負は保証しない(既定の MUSCL の面の濃度は
  供給元のセルの平均を超えうる。advect_scalar の契約の注を更新)。
- **検証**(2026-11-05。gfortran 13.3 / Open MPI 4.1.6):

    param_nowidth.txt)・gwsect・damwq・sewer_wq を np = 2・4、nhbreak と chichibu(1 時間まで。静的データ)を
    np = 2 で回して実行時エラーなし。MPI の出力は逐次と全ファイル一致(再帰的に比較)。
  - 回帰(-Ofast の逐次、reference を持つ 42 ケース): 値が変わったのは damwq・gwsect・gwwidth・sewer_wq・
    nhbreak の 5 ケースだけ(負の水深が出ていたケース)。ほかの 37 ケースは PASS で、一致・許容内の内訳も
    修正前と同じ。ただし wfdoppler の wavefield.csv が 1 値の最終桁(−6.0037614E−07 → −6.0037613E−07)で
    許容内になった。-O2(厳密な数学。§28.3)のビルドでは、抑制が働かない 9 ケース(wfdoppler・wfcurrent・
    wfsed・wave・tracer・chichibu_icmap・nhcurrent・nhwave・chichibu。OpenMP 1 スレッド)の全出力が修正前と
    バイト一致したので、-Ofast の差はビルドの差(コードを足したことによる最適化の違い)。
  - MPI: -O2 のビルドで、変わる 5 ケース(gwwidth は 2 設定)の np = 1・2・4 の全出力が逐次とバイト一致。
  - 自己検定: gwwidth の全検定が PASS(雨の後の総水量の最大相対ずれ: 本体 2.0e-13、対照 0、管路層 0)。
    gwsect(本体 3.9e-13、幅なし 5.9e-13 ほか)・damwq も PASS。対照を 1 分ごとの Log で見ると、雨の後の
