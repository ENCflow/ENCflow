## 28. 土石流・地滑りモデル(f_debris / f_release / f_slide。2026-08-09 実装)

設計全文と合意の経緯は docs/debris_plan.md(文献照合の残作業もそちらが
正本)。単層混合体方式: 土石流を「地表水 h + 土砂柱状量 s%hs」の単層で
表現する(Kanako 系と同じ定式化水準。別層 ENC は作らない — 土石流は
移流項が本質で、別層は第二の浅水ソルバ+層間交換になるため)。

### 28.1 構成(4つの部品と担当)

- **f_debris(m_geomorph_debris)**: 高橋型平衡濃度 C∞(θ) への緩和で
  侵食・堆積(E-D)。C は混合体積濃度 hs/(h+hs)、C* = 1−λ
  (fluv_porosity から導出。新パラメータにしない)。勾配は8近傍への
  最急降下(流向非依存 = 速度 0 でも定義される。開いた辺の外の近傍は
  辺の法線方向の線形外挿で補う。§28.15)。勾配領域:
  石礫型(tanθ>0.138)/未成熟(6.7C∞d²。0.03<tanθ≤0.138)/
  掃流域(C∞=0 = 堆積側に一本化。第3領域式は文献照合後)。
  閾値・係数は【要文献照合】マーク付きで原式固定(§19.8 原則2)。
  停止条件は f_dbstop で切替(0:なし、1:低速凝集 = vv<db_vstop で
  平衡までの超過濃度を db_wstop レートで河床へ。数値的閉包であり
  文献式ではない)。f_suspend と排他(同一 hs 上の E-D 二重計上防止)。
  morfac=1 必須(イベント計算)。sed_active は f_debris でも立つ
  (移流は共通の advect_scalar)。
- **抵抗則と運動量結合(m_swflow_enc)**: s%debris_active(t_state。
  m_geomorph_init が設定)で有効化。パラメータは init_debris が
  m_swflow_enc_set_debris で渡す(geomorph init は swflow init より前)。
  - 運動量への hs 算入: 圧力・重力項の水面 = z+h+hs(tgs は RK 内
    不変の前計算)、摩擦水深 = 混合流動深 h+hs。水フラックス
    mne1 = uve1・he(水柱)は不変 = 固液同速の単相近似。
  - f_dbres=1(クーロン+マニング合成): 降伏減速度
    a_y = ge・tanφ・sC/(1+sC)(水中固体重量の底面摩擦の加速度形。
    経験定数なし。ge は correct_ge の cos²θ を共有)を半陰解法に合成
    (÷max(vve, p%vv))。低速(|uve0|<db_vstop)かつ駆動 ≤ a_y なら
    明示的に静止維持(動き出しと停止を同じ式で表現)。C→0 で
    マニングへ連続に退化(閾値なし)。
  - f_dbres=2(高橋ダイラタント)は par_stop 予約(係数の文献照合待ち)。
- **f_release(瞬時流動化。地滑り型の初期条件)**: fn_dbinit(崩壊深
  分布)の指定で有効化。db_reltime に発火(t0 以前なら最初の geomorph
  更新)。発火は時刻交差判定で1回だけ — geomorph 呼び出しは it の
  絶対格子上にあるためリスタート後も再発火しない(新規保存状態なし。
  往復検証で確認: 差は既存機構と同水準の ULP のみで O(1) の再発火なし)。
  転換: hs += (1−λ)D、z −= D、sd −= D(固体台帳が構造的に閉合)。
  間隙水は gw_active なら容量超過引き渡し(hg から出る)、無効なら
  h += λ・relsat・D。
- **f_slide(無限長斜面安定判定。発生の自動判定)**:
  Fs = (c′ + (γt・sd − γw・hw)・cos²θ・tanφs) / (γt・sd・sinθ・cosθ)
  (有効応力・斜面平行浸透。導出式)。hw = min(hg/sy0, sd) — gwflow の
  浸透進行が発生時刻を決める。Fs<1 で全層流動化(sd=0 = 岩盤露出。
  堆積で sd が再生すれば再判定 = 進行性崩壊)。近似: セル独立
  (側方支持なし = SHALSTAB 系と同水準)、浅層限定、γt 一律。

### 28.2 【実バグ】勾配を読むプロセスのその場更新は OpenMP データ競合

calc_debris の1パス実装(セルループ内で slope8 が近傍の s%z を読み
ながら自セルの z を更新)は、スレッド境界の行で「近傍 z の読み vs
他スレッドの書き」の競合になり、np=4 の state.dat が run ごとに変わる
非決定で実検出した。**suspend/wash は近傍を読まないため1パスで安全 —
近傍参照を持つ地形プロセスは必ず2パス(パス1: 時刻 n の場から交換量、
パス2: 適用)にすること**。f_slide の Fs 評価も同じ理由で E-D と同じ
時刻 n の z から評価する(パス1群 → 適用群の順序を calc_debris 内で
保証。加えて calc の適用順で debris を先頭に置き、他プロセスの帯内
z 更新とハロの不整合も避ける)。

### 28.4 既知の制約・観察(受容の上で記録)

- リスタートの継続等価(0→T vs 0→t→restore→T)は ULP 一致まで。
  これは f_debris 固有でなく既存 suspend でも同じ(-O2 でも観測)。
  文書化されている往復検定(save→restore→save)とは別物であることに
  注意。発火機構の再発火なしは確認済み
- S_grnd の画面表示は h=0 のセルの hg を集計しない(m_state_calcstat
  の h≤0 cycle が hg 加算より前にある既存仕様)。強浸透で全量が
  hg にあるとき S_grnd/S_total が過小表示される(状態は正しい。
  診断のみの問題)
- 乾いた薄層流(降雨ランオフ)にも E-D が働くため、急斜面では
  シート侵食的な低下が出る(δe の校正で管理。wash との役割分担の
  議論は §19.6 と同型)
- f_slide の進行性崩壊(堆積した飽和土の再崩壊)は物理的に妥当だが
  転換回数が多くなる(診断カウントの解釈に注意)

### 28.5 江頭構成則(f_dbres=2)と江頭・芦田 E-D(f_dbed=2)(2026-08-16 実装)

ユーザー提供の文献(江頭進治: 土石流の停止・堆積のメカニズム(2),
新砂防 46(2), 1993 / Morpho2DH ver.2 Solver Manual, iRIC)により、
§28 で保留していた抵抗則スロットを**江頭構成則**として実装した
(高橋1977 ダイラタント則は sinα_i の値が未確定のため引き続き保留)。
式・係数の確定内容は debris_plan.md §1(2026-08-16 照合更新)が正本。

- **f_dbed=2(E-D 式の選択制)**: 江頭・芦田(1992)
  E = |V|・C*・tan(θ−θe)、tanθe = sC/(sC+1)・tanφs。
  - 流向の河床勾配(Morpho2DH 式(6): sinθ = (u sinθx + v sinθy)/|V|)を
    中央差分で評価(片側フォールバック)。|V|=0 は E=0(f_dbstop の
    判定勾配は最急降下にフォールバック)
  - 侵食・堆積が1本の式で連続 → 高橋型で保留していた緩勾配の
    第3領域式が不要になる。**追加パラメータなし**(δe/δd 不使用。
    φ・C* は共有)
  - f_dbstop=1 の平衡濃度は平衡勾配式の逆関数(= 石礫型 C∞ 式と同形。
    独立導出の一致を確認)
- **f_dbres=2(江頭構成則)**: τ_b = τ_y + ρ・f_b・V² を加速度形で
  半陰解法に合成。
  - τ_y/(ρm h_t) = ge・tanφ・sC/(1+sC)・(C/C*)^{1/5}
    (= f_dbres=1 のクーロン降伏 × (C/C*)^{1/5}。n=5 は原式固定)
  - f_b = (25/4){k_f(1−C)^{5/3}/C^{2/3} + k_d(σ/ρ)(1−e²)C^{1/3}}(h/d)^{−2}
    (k_f=0.16, k_d=0.0828 原式固定)。減速度 = f_b・V²/((1+sC)h_t)。
    C ≥ db_cmin(既定 2%)でマニング則を置換、未満はマニング
    (層流則は C→0 で発散するための数値的切替 — 独自の閉じ)
  - 新パラメータ: db_d50(粒径)、db_erest(反発係数 e。文献に既定なし
    = 必須入力)、db_cmin。h_t(混合流動深)・C は時刻 n のエッジ値で
    RK 内固定(hse と同じ近似)
- **【実バグ】`.and.` の短絡評価は保証されない**: slope_flow の近傍
  マスク読み `if (g%x(..) > 0 .and. g%sw(..) <= 0)` が x 番兵ガードの
  外で g%sw を評価し得る(-fcheck np=2 が域外読みを実検出)。
  マスク近傍読みは必ず x ガードの**ネストした if の内側**で(§12 の
  帯確保規則の系。既存 slope8 は cycle 分離で安全だった)
- **検証(2026-08-16, gfortran 13.3/OpenMPI)**: 既定値(f_dbed=1,
  f_dbres 既定)で全10テスト PASS = 既存挙動不変 / -fcheck np=2 先行
  (上記バグを捕捉)/ 江頭構成の固体台帳 1.9e-13・共動更新 4.7e-14
  (test/debris param_eg.txt)/ **-O2 厳密数学(make clean 後)で
  逐次 = np1 = np2 = np4 の state.dat バイト一致(高橋・江頭両構成)**
- **-Ofast のビルド間差の整理(§28.3 の続報)**: -Ofast では逐次↔MPI
  ビルド間で ULP レベルの fast-math 最適化差が出る(マージ直後に観測
  した「過渡的な不一致」もこれ)。**単一ビルド内のランク数不変・
  run 間決定性は -Ofast でも常に成立**。test/debris・test/slide の
  Run_MPI.sh のビルド間ビット比較は警告扱いに変更(偽 FAIL 防止)。
  ビット検証は -O2 厳密数学で行う。**注意: make のスタンプ機構は
  FFLAGS の変更を検出しない — 精度検証のビルド切替は必ず make clean を
  挟むこと**(これを怠り -Ofast 残骸と比較する誤検証を実際にやった)

### 28.6 高橋・中川(1991)則(f_dbed=3 / f_dbres=3。2026-08-16 実装)

ユーザー提供の高橋・中川(1991)新砂防 44(3), 12-19(§28 で保留した
閉じ式の原典)により、高橋系の E-D・抵抗則を実装した。式・係数の確定
内容は debris_plan.md §1(照合更新3)が正本。

- **f_dbed=3**: 飽和床侵食(式(12)→ 単一粒径で
  δe(C∞−C)/(C*−C∞)・q_T/d_L)+慣性係数付き堆積(式(27):
  δd(1−V/(p・v_c))⁴(C∞−C)/C*・q_T/d_L。v_c=式(15)、tanθc=式(16))。
  θ は流速ベクトル方向の流動面(z+h+hs)勾配(式(26))。
  定数: a_i sinα_i=0.02・p=1/3 は原式固定、δe/δd は namelist
  (洞谷適用値 δe=0.0001, δd=0.5)。db_d50 必須(q_T/d_L)
- **f_dbres=3**: 石礫型 = 降伏(tanα'=0.45)+ダイラタント項
  (A'=4, {(1−C)/C}^{2/3}(d_L/h)²)。C ≤ 0.4C* は掃流状
  ((ρT/0.49)(d_L/h)V²)、C < db_cmin(2%)または h/d ≥ 30 は
  マニング — 泥流域のマニング切替と 2% 閾値が原式で確定
  (db_cmin 既定の典拠になった)。全定数原式固定
- **【実バグ】f_dbed=3 の流動面勾配は近傍の h・hs を読む** — 両者の
  ハロはステップ頭交換のままで swflow が帯内を更新済み = 帯界面で
  古い(np=2 の state.dat 不一致で実検出)。calc_debris 冒頭の
  par_halo_cell(h, hs) で最新化(calc_fluvial の冒頭交換と同じ構図。
  §19.2 の再演 — **時刻 n+1 の水理量の近傍を読む地形プロセスは
  冒頭ハロ交換が必須**)
- **検証(2026-08-16)**: 既定値で既存テスト PASS(挙動不変)、
  -fcheck np=2 先行、固体台帳 1e-13・共動更新 3e-13、np=1,2,4
  バイト一致(上記ハロバグ修正後)、-O2 厳密数学(make clean 後)で
  逐次 = np1,2,4 バイト一致。挙動: 慣性係数による堆積遅延と走行距離、
  遷緩点の扇状堆積(tt=25 で +0.5 m)を確認。test/debris に構成3
  (param_tk.txt)を追加(3構成: 簡易/江頭/高橋・中川)
- 未実装(残作業): 不飽和床侵食(式(10)。gwflow 飽和度との結合が
  自然)、掃流状域の堆積式(28)(c_LS∞ 未記載)、多粒径2成分

### 28.7 間隙水連行オプション f_dbwet(2026-08-16 実装)

E-D の河床交換 Δz に伴う間隙水の授受(**高橋・中川1991 式(5)**
全容積連続式の源泉 i{c* + (1−c*)s_b}。Kanako 式(1)の源泉 i は
s_b=1 の特別形、Morpho2DH の E/c* 台帳も同等)をオプション化した。
既定(f_dbwet=0)は従来どおり無視で挙動不変。

- **f_dbwet=1**: calc_debris の第2パス(z/sd 共動更新の直後)で
  水柱を交換する。侵食(Δz<0): h += λ・s_b・|Δz|、
  堆積(Δz>0): h −= λ・s_b・Δz(h の残量でクランプ=間隙埋没が
  地表水を超えて奪わない)。s_b = db_satbed(堆積層の飽和度 0〜1、
  既定 1.0。洞谷適用値は勾配 21°以上で 0.8、以下で 1.0)
- **gwflow と排他(init で par_stop)**: gwflow 有効時は河床間隙水が
  hg の台帳(容量 sd・sy0 の共動縮小と超過引き渡し)で既に管理されて
  おり、f_dbwet の解放と二重計上になるため。両立(不飽和侵食式(10)と
  合わせた飽和度結合)は残作業
- **位置づけ**: 侵食卓越の渓床では正味の増水(bulking)であり、
  δe の校正では吸収できない一次効果。Kanako・Morpho2DH の標準台帳に
  合わせるにはこのオプションを有効化する
- **検証(2026-08-16)**: 既定 f_dbwet=0 で全10テスト PASS(挙動不変)、
  -fcheck np=2 先行(TK91 スモークケース+f_dbwet=1)、np=1,2,4
  state.dat バイト一致、OpenMP 4スレッドの run-to-run 決定性を確認。
  固体台帳は f_dbwet=1 でも 3.6e-13(水交換は固体台帳に触れない)。
  挙動: TK91 スモーク(渓床飽和 s_b=1)で Σh 90 → 130 m³ の増水と
  侵食深の増大(−0.45 → −0.72 m)= bulking の正のフィードバックを確認
- **恒常検定**: test/debris に構成4(param_tkwet.txt = 構成3 +
  f_dbwet=1)を追加。Check_debris.py の wet モードが**水台帳**
  |Σh − 降雨総量 + λ・s_b・Σdz| < 1e-9 を検定する(閉領域では
  機械精度 2.5e-13 で成立。降雨のみの構成3は Σh = 降雨総量 = 4.0
  m*cell に対し、構成4は Σh = 7.53・Σdz = −8.83 — 連行水が侵食を
  加速する正のフィードバックが恒常的に確認される)
- **f_dbwet=2: gwflow 併用の間隙水(2026-10-30 追加)**。gwflow 有効時、
  侵食側は容量超過引き渡し(hg > sd・sy0 の超過を h へ)があるのに、堆積側に
  対になる処理がなく、堆積物の間隙は空のまま z が上がっていた(水は保存
  されるが、間隙が空気のまま水中に積もる)。水たまりの中の堆積はその間隙の
  分だけ水を押し出す。examples/ashfall_lahar の砂防堰堤の上流で、越流の
  流量が清水の対照より毎秒約 0.2 m³ 多くなり(堆積のかさ体積の増加 0.41 m³/s
  の間隙分 0.20 m³/s と一致)、検出した。
  - **規則**: calc_debris の第2パス(z/sd 共動更新の直後、容量超過引き渡しの
    前)で、堆積(Δz > 0)のとき Δh = min(sy0・Δz, sd・sy0 − hg, h) を h から
    hg へ移し(空き容量・地表水の範囲でクランプ。流れの下に積もった土砂は
    飽和するという独自の簡略化)、侵食(Δz < 0)のとき min(sy0・|Δz|, hg) を
    hg から h へ戻す(地下貯留は上から満たされる = Green-Ampt のピストン近似
    と同じく濡れた上部から削られる)。水の総量は保存される。bedslide の
    プランジ引き渡し(§61.5)は堆積側だけ(引き渡しは侵食しない)。
    面積率は §26.1 の換算(gw_to_h)で地表と地下の単位をそろえる(2026-11-03。
    当初は「af/gv は掛けない(既存の容量超過引き渡しと同じ扱い)」としていた)
  - **侵食側を容量超過だけにしない理由(実装中に検出)**: 初版は侵食側を既存の
    容量超過引き渡し(hg > sd・sy0 の超過だけ戻す)に任せたが、不飽和の層
    (hg ≪ sd・sy0)では侵食で水が戻らず、急斜面で E-D がステップごとに

### 28.8 火山流動の等価流体モード(f_dbed=0 / f_dbres=4,5。2026-08-16 実装)

火山災害の密度流系(山体崩壊=岩屑なだれ、dense な火砕流、それらの
堆積)を、土石流の部品の上に**等価流体**として表現する
(設計・スコープの線引き・Phase 2a(疑似間隙水近似)の合意は
debris_plan.md §5 が正本。Titan2D / VolcFlow / RAMMS と同じ
SWE+粒状体抵抗則の水準 = §0 の範囲内)。

- **f_dbed=0(交換なし)**: E-D をスキップし移流・停止のみ
  (河床侵食を持たない火砕流・岩屑なだれ)。乾燥セルの全量繰り入れは
  従来どおり。f_dbstop=1 の平衡濃度は 0 扱い = 低速セルの hs 全量が
  db_wstop レートで河床へ固定。db_phi・δe/δd は f_dbed=0 では不要
  (init の必須判定を f_dbed>=1 / f_dbres=1,2 に条件化)
- **f_dbres=4(Voellmy)**: 降伏 a_y = ge・μ + 乱流項 ge・V²/(ξ・h_t)。
  乱流項は既存の fbe 機構に fbe = ge・rme/ξ で載せる(rme が相殺して
  −ge・vve/(ξ・h_t) 形。マニングは置換)。μ(db_mu)・ξ(db_xi)は
  直接入力(体積依存の見かけ摩擦低下は μ で表現 — §0)
- **f_dbres=5(一定停止応力)**: a_y = τ_y/(ρm・h_t)+マニング合成
  (VolcFlow 型)。ρm = ρw(1+sC)、ρw=1000 は module 定数 db_rhow。
  τ_y(db_tauy、Pa)は直接入力
- 両則とも C < db_cmin でマニング(+降伏なし)に退化(希薄側の閉じ。
  下流の清水域に降伏を適用しない)。降伏零化・f_dbstop の枠は
  f_dbres=1 と共有
- **検証(2026-08-16, gfortran 13.3/OpenMPI)**: 既定で全10テスト
  PASS(挙動不変)、-fcheck np=2 先行、np=1,2,4 state.dat バイト
  一致(両構成)、-O2 厳密数学(make clean 後)で逐次=MPI バイト一致。
  **test/volcano 新設**: 構成1 = Voellmy 定常等流ベンチマーク
  (等勾配斜面+混合体区間流入。解析解 h_t = (q_m²/(ξ(tanθ−μ)))^{1/3}
  に誤差 0.04%。水・固体台帳は機械精度)、構成2 = τ_y ランアウト
  (f_release → 斜面流下 → 平坦部堆積 0.59m → 停止・河床固定
  99.7%)。**注意**: 解析解比較は p_diagratio=0(4近傍化)で行う —
  8方向配分では斜めエッジの「勾配低下×降伏 μ」の非線形により実効
  通水能が下がり、1次元解析解と 24% ずれる(スキーム特性であり
  バグではない。実地形計算では既定の8方向のまま使う)
- **領域の制約(実検出)**: 帯分割はランクあたり2行以上が必要 —
  ny=3 の細長領域は np=2 で par_stop(test/volcano 構成1を ny=8 に
  設計変更した経緯。狭幅ベンチマークを組むときは ny >= 2・np に)
- **雪崩(流れ型)への適用(2026-08-21 ガイド化)**: 同じ等価流体
  構成が流れ型雪崩の標準定式化(Voellmy は元来雪崩の抵抗則。力学は
  密度非依存のため雪でも成立)。利用者ガイドは users_guide/geomorph.md
  の「雪崩(流れ型)」(設定の型・μ/ξ の慣用域・db_relsat 小の
  疑似間隙水運用・限界: 煙型対象外/発生はシナリオ/
  衝撃圧は雪密度で換算)。README・用途集・comparison から誘導
- **f_dbed=4: 速度比例連行則(2026-08-21 実装)**: E = δe・|V|
  (連行のみ・堆積なし=停止は f_dbstop。雪崩・岩屑なだれの走路連行の
  簡易則)。連行可能層は既存の土層厚 sd を読み替えて与える(雪崩では
  走路の雪厚。z は雪面込み・z−sd が地山 — 共動更新・台帳・クランプは
  既存機構を全て再利用し、新規状態・新パラメータなし(δe は db_delte を
  共用)。積雪モジュール(SWE)との結合はしない設計判断 — イベント計算に
  気象・度日機構と密度換算を持ち込まないため。SWE→sd は前処理で変換)。
  **希薄な裾の暴走防止**: 連行は C >= db_cmin の「密な流動体」セルのみ
  (移流の微小 hs 裾が全速で削るのを防ぐ閾値。φ・δd は不要 = 必須判定を
  f_dbed=1,2,3 に条件化)。
  **検証(2026-08-21)**: test/avalanche 新設(slope_break + 放出 D=0.5m
  + 走路雪 sd=0.5m + Voellmy)— 固体台帳 1.7e-14・共動更新 5.4e-14、
  連行の活性(走路で min Δsd = −0.46m)、成長(連行固体 = 放出の 1.5 倍)、
  全停止。既定で全21テストビット一致、-fcheck np=2 先行、np=2,4 で
  state.dat 逐次ビット一致
- **今後の課題として記載(2026-10-29。利用者の指示)**: Hungr (1995) の経験的な連行則
  E = E_r h_t |V|(DAN3D など。Qiao ら 2023 の式 (14)・(15))を、既定を変えない f_dbed の選択肢と
  して足す方針を users guide の解説 massflow.md §3(日英)に記載した。f_dbed = 4(E = δe|V|)との
  違いは流動深の因子で、体積が走行距離に対して指数的に増える。新パラメータは E_r(1/m)の
  1 個(δe と単位が違うので共用しない)。連行のみ・sd の連行可能層・C ≥ db_cmin の門は f_dbed = 4 と
  同じ。かさ体積の連行に合わせるため f_dbwet = 1 と組む。検定は一様斜面・一定速度で
  V = V0 exp(E_r x)。入れる時期は欧州の実務モデルとの比較・連行の大きい実事例(Cancia 2015)を
  扱う段(handoff 1j)。
- **設計判断: 雪崩は土砂流動モデルの「援用」であり、入れ物を読み替えて
  使う(2026-08-21 討議の記録)**。対応: sd = 連行可能な雪の厚さ、
  hs = 流動中の雪の実質体積、z = 雪面込み標高(z−sd = 地山)、
  fluv_porosity = 雪の空隙率解釈、fn_dbinit の D = 破断深、
  f_dbstop の河床固定 = 停止デブリの堆積。
  - **援用の根拠**: 密実流雪崩と土砂の密度流は同じ「粒状体の浅水流」で
    あり、定式化として同一(Voellmy 力学が密度非依存であることが
    それを支える)。見かけの流用ではない
  - **利点**: 検証済みの台帳機構(共動更新・固体総量保存・可動層
    クランプ・2パス MPI 構造)がそのまま雪に効く。専用モジュールを
    新設すれば同じ機構一式の再実装・再検証になる
  - **受容した割り切り**: パラメータ名が土砂の語彙のまま(fluv_porosity
    に雪の空隙率を入れる等)という「名前のねじれ」。雪崩用の別名
    パラメータは、同じ実体に二つの名前を与える複雑化に対して得るものが
    表記だけなので**見送り**(§0)。読み替えはユーザーガイド
    (geomorph 章の雪崩の項の対応表)で吸収する
- **設計判断: 土圧係数 k_ap(主働・受働。Savage–Hutter 型)は導入を
  見送る(2026-09-30 討議の記録)**。実装自体は容易(`tge` の深さ勾配
  部分に辺ごとの k を乗じ、両セル流速の辺方向射影の差の符号で主働/
  受働を切替。30〜50 行・無効時ビット一致も容易)だが、次の理由で
  現行の定式化とは整合しない:
  - **混合体との矛盾**: k_ap は粒子接触による有効応力の異方性を表す
    係数であり、間隙水圧は等方(k=1)。本モデルは水+固体の単層混合体
    (§28.1)なので、正しく入れるには圧力を「間隙水の静水圧」と
    「固体の有効応力」に分解し後者のみに k を乗じる必要がある
    (Iverson–Denlinger 型。C 依存の分解で、係数追加では済まない)。
    乾式流動モードも無い(疑似間隙水近似。debris_plan.md §5.2)
  - **等価流体との流儀の違い**: k_ap は Coulomb 連続体(δ・φ_int を
    物理定数として持つ枠組み)の一部。Voellmy の μ は見かけ摩擦で δ と
    解釈できる保証がなく、φ_int は新パラメータかつ φ_int ≥ δ の制約を
    伴う。等価流体系(RAMMS の標準設定・VolcFlow)は k=1(等方)が一般的
  - **数値的な難点**: 発散の符号による不連続切替は停止域・堆積縁で
    振動しやすく、受働側の k 増大で波速 √(k g h) が上がり時間刻みが
    縮む。ENC の辺ごと・8方向の歪み判定は検証例のない独自定式化になる
  - **§0 との関係**: 鉛直・水平応力比は鉛直構造の情報であり、k=1 で
    抽象化する現状が「鉛直は抽象化」「徐々に精緻化」に整合する
  - **将来の順序(必要になった場合)**: 曲率項(遠心加速度による
    垂直応力の増減。**§28.10 で実装済み**)→ 乾式流動の扱い(debris_plan.md §5.2 の案b)→
    それを前提とした Mohr–Coulomb 抵抗則 → その付属としての k_ap。
    乾式モードなしに k_ap だけを入れると物理的根拠を説明できない
  - **比較研究での扱い**: Titan2D との比較は Mohr–Coulomb モデルでなく
    Titan2D の Voellmy–Salm と共通条件で行う(Titan2D 側の k の扱いは
    比較前に要確認)。k_ap の効果は主に乾いた粒状体の崩壊初期の
    広がりと堆積形状で、到達距離への影響は相対的に小さい

### 28.9 土砂災害の危険度出力(f_out_fs / dmax / fmax / hs、f_slide=2。2026-08-20 実装)

土砂災害の危険度を表す状態量の出力群。ハザードマップ整備・被害想定の
実務指標(浸水深・流体力・安全率)に対応する。全て f_out_* 指定時のみ
確保・更新(無効時ゼロコスト。§0)。

- **f_out_dmax / f_out_dmaxt**: 最大**流動深** max(h+hs) の D9999 と
  発生時刻 Dt9999(min)。土石流・火山流動の「浸水深」実体は混合深
  h+hs であり、既存 hmax(水柱のみ)では過小になるため。
  土砂モジュール(f_suspend/f_debris)必須(でなければ hmax と同値 =
  par_stop で案内)
- **f_out_fmax**: 最大**流体力** max((ρm/ρw)・(h+hs)・V²) の F9999
  (m³/s²。**清水密度で規格化した密度込みの流体力** =
  (h + (1+s)hs)・V²。2026-08-20 に密度なし (h+hs)V² から定義変更)。
  - 水のみ(C=0)では実務慣行の **u²h と厳密に同一**(氾濫想定の
    家屋倒壊等判定の閾値がそのまま使える)
  - 混合流では密度比 ρm/ρw = 1+sC が入る(C=0.6, s=1.65 で約2倍)。
    **C は場所・時間で変わるため、密度なしの最大値とは発生時刻・順序が
    異なり得る = 後処理のスケーリングでは直せない**(密度込みで内部
    積算する理由。hmax×vvmax の積が作れないのと同じ同時性の問題)
  - ×ρw(1000)で N/m(単位幅の作用力)、÷(h+hs) で RAMMS 型の
    衝撃圧 ρmV²(Pa)を後処理導出できる
  - s は m_geomorph_init が s%sed_sgrav で通知(土砂モジュール無効時は
    0 のままだが hs=0 なので影響なし = 水のみケースは厳密に不変)
- **f_out_fs**: 斜面安全率 **Fs の分布**(フレーム Fs0001…)と
  **期間最小 Fs9999**(危険度マップの本体)。f_slide(1 or 2)必須。
  slide_pass1 が dt_geomorph 周期で s%fs / s%fsmin へ書く(t=0 フレームは
  全域 -1)。**-1 = 評価対象外**(無効セル・海・岩盤 sd=0・勾配なし)の
  番兵。崩壊済みセル(sd=0)は以後 -1 に戻る(危険が顕在化した履歴は
  Fs9999 に残る)
- **f_slide=2(判定のみ)**: Fs を評価するが**流動化しない**診断モード。
  地形を乱さない素の危険度マップを作る用途(f_slide=1 は崩壊が地形・
  地下水を変えるため、以後の Fs 場が変わる)。パラメータ要件は 1 と同じ
- **f_out_hs**: 土砂柱状量のフレーム Hs0001…(濃度 C = hs/(h+hs) や
  堆積の時間発展の可視化。土砂モジュール必須)
- 飽和度(崖崩れの先行指標)は追加しない: f_out_hg(Hg)と Sd 出力から
  hg/(sy0・sd) を後処理で導出可能(派生量は内部生成しない — §0)
- **リスタート**: 全て save 対象外(hmax 系と同じ意図的仕様。§7)。
  再開後は再開時点からの統計になる。s%fs は次の slide_pass1 で再構成
- **検証(2026-08-20, gfortran 13.3/OpenMPI)**: 全11テストで既定
  (スイッチ全OFF)ビット一致。出力ONでも state.dat が OFF とビット
  一致(統計は物理に影響しない)。-fcheck np=2 先行(新規帯配列)。
  np=1,2,4 で state.dat と**出力ファイル自体**(Fs9999/D9999/F9999)が
  逐次とビット一致(統計は save に入らないため、ランク数不変の検証は
  出力ファイルで行うこと — test/slide の Run_MPI.sh が恒常化)。
  test/slide に構成3(param_fs2.txt = f_slide=2 診断)を追加:
  無流動化(z・sd・hs 不変)+ Fs9999 の危険検出(min 0.943 < 1)を検定。
  構成2は出力一式を有効化し Fs9999 min 0.455・D9999 ≥ H9999 を検定。
  **F の密度込み化の検証(2026-08-20)**: 火山 τ_y ケース(C≈C*=0.6)で
  F9999 max 40.9 → 81.4 m³/s²(ρm/ρw ≈ 2.0 倍 = 期待どおり)、
  既定・水のみは不変(全テスト PASS)、np=2 で F9999.txt 逐次一致

### 28.10 曲率項 f_dbcurv(遠心加速度による降伏摩擦の増減。2026-09-30 実装)

Titan2D / RAMMS との比較検討(comparison.md)で、ENCflow の等価流体に
欠けていた**曲率項**(Fischer ら 2012 が RAMMS に入れた、地形の曲率による
遠心加速度を垂直応力に加える効果)を追加した。RAMMS の μ・ξ 表は曲率項を
含むモデルで校正されているため、同条件比較の前提になる。

- **定式化**: 降伏減速度 a_y = ge・(摩擦係数) に倍率 F = max(0, 1 + a_c/g_n)
  を乗じる。a_c = uᵀHu/√(1+|∇z|²)(H = z の Hessian、u = セルの水平流速
  ベクトル)。これは地表面(z のグラフ曲面)の流向法線曲率 κ_n と表面速度
  V_s の積 V_s²κ_n を水平投影量で書いたもので、1 次元では u²z''/√(1+z'²)
  = V_s²κ に一致する。g_n = 垂直方向の重力 = √(g・ge)(f_gravity_correction
  の ge = g cos²θ のとき g cosθ。補正なしなら g)。凹地形(谷底・屈曲部の
  外側)で a_c > 0 = 減速、凸地形(遷急点・尾根)で a_c < 0 = 摩擦低下。
  F < 0(地面から浮く条件)は 0 に切る(飛び出しは表現しない)
- **適用先は降伏項のみ**(f_dbres=1〜4)。Voellmy の乱流項・圧力項には
  掛けない(RAMMS と同じ扱い。Savage–Hutter 型で圧力項にも入れる案は
  乾式流動・k_ap と同じ順序で後回し)。f_dbres=5(τ_y 一定)は垂直応力に
  依存しないため f_dbcurv=1 との組合せは init で par_stop
- **評価位置と時刻**: a_c はセルごとに時刻 n の u, v, z(ステップ頭で幅 2
  交換済み)から 3×3 中心差分で前計算(curv_prepare。RK 内不変 = hs と
  同じ近似)し、辺では両セルの平均(c/n 対称)。隣セルの Hessian が
  ±2 行の z を読むが、ハロ幅 2 で閉じる。領域外・海域(x<=0, sw>0)を

### 28.11 【実バグ】降伏停止判定の成分ごとの適用が横断方向の質量交換を凍結(2026-09-30 修正)

- **現象**: f_dbres>=1 の一方向定常流(test/curvature の Voellmy 等流)で、
  行ごとの流動深が下流まで揃わない(ny=8 で壁際 0.563 m・内側 0.66 m、
  ばらつき 16%。ny=16 では中央が薄い波状)。全行平均は等流深に一致する
  ため 1 次元ベンチマーク(test/volcano)では検出されなかった(§28.10)。
- **原因**: calc_kth_momentum の降伏停止判定
  `abs(uve0) < db_vstop .and. |tae+tge| <= aye → uve1 = 0` が、辺の
  **法線方向成分** uve0 で低速を判定していた。速い一方向流の横断方向の辺
  では法線成分 ≈ 0 で常に db_vstop 未満、横断駆動(行間のわずかな水面差)
  も a_y 未満なので、横断速度が毎ステップ零化され、行間の質量交換が
  凍結する。流入部・壁際の移流ステンシル切れで生じた数 % の行間差が
  そのまま下流へ運ばれていた。Manning(a_y = 0)では零化がないため
  横断圧力勾配で均される。摩擦項自体は `aye/max(vve, p%vv)` の半陰形で
  |V| に基づく共線形になっており正しかった。問題は零化の条件だけ。
- **修正**: 低速判定を辺の**速さ** |V|(両セルの vv の平均。下限 p%vv の
  適用前の値 vv0e)で行う。Coulomb 降伏は速度ベクトルの大きさに対する
  条件で、動いている流れの一成分には掛からない。静止からの動き出しと
  停止(|V| < db_vstop)の判定は従来と同じ。
- **効果(test/curvature、定常 Voellmy 流)**: 斜面 B の行のばらつき
  16.0% → 0.0%(全行 0.637 m = 等流深 0.6376 m)、ny=16 でも 0.1%。
  発達区間に残る数 %(x=45 で 2.2%、x=100 で 6.2%)は壁際の移流ステンシル
  切れの過渡で、下流で均される。曲率項の ODE 比較は直線部 B 0.14% →
  0.05%、on/off 差 0.10% → 0.01%、円弧上の厚化の比 1.03 → 1.05。
- **影響範囲**: f_dbres>=1 の全ケース(debris・volcano・avalanche・
  bedslide の混合体構成、examples/landslide_tsunami B/B0)の結果が変わる
  (横断方向の広がりがやや増える、物理的に正しい向き)。reference 13
  ケースは土石流を含まず不変。
- **検証(2026-10-01)**: 全 30 ケース PASS(reference 13 ケースはビット
  一致、土石流系の自己検定は台帳・活性・停止とも PASS)。MPI np=2 で
  debris PASS、curvature は on/off とも state.dat が逐次とバイト一致。
  examples/landslide_tsunami を再計算: A・C(底層のみ)は不変、B は
  湖底堆積 17,866 → 18,077 m³・汀線 165 → 199 m³、B0 は汀線 11,843 →
  11,401 m³(横断方向に広がったぶん)。先頭波は ±0.04 m 以内。README の
  表と図を更新。
- **教訓**: 成分分解された運動方程式に「ベクトルの大きさに対する条件」を
  入れるときは、成分ではなく |V| で判定する。同型の判定は f_dbstop の
  低速凝集(セルの vv で判定 — 問題なし)と bedslide の停止(セルの V —
  問題なし)。

### 28.14 斜面のシート流での格子スケールの縞(移動限界水深 dd。2026-10-30 記録)

examples/ashfall_lahar(降灰の急斜面 0.35 に 25 mm/h の表面流)で、侵食域に流れの向きに
沿う格子 1 つ分の縞(行ごとに侵食と堆積が交互)が出た。原因は数値設定で、コードの
不具合ではない。

- **機構**: 斜面上部のシート流の深さ 0.7〜1.3 mm が移動限界水深 dd = 1 mm(既定)と
  同程度で、セルごとに「流れる・止まる」が入れ替わり、h ≤ dd のセルは calc_debris の
  乾燥セル規則で hs を全量河床へ置く。少し低い行に横(谷壁の横断勾配)から水が集まって
  h > dd を保って削り続け、水を取られた隣の行が土砂を置いて高くなる正のフィードバック。
  勾配 0.35 では平衡濃度 C∞ が上限 0.9C* に張り付き(tanθ > 0.25 で飽和)、窪みの下流
  勾配が緩んで埋め戻す負のフィードバックも働かない。河床の横方向の平滑化がないので、
  成長の最も速い最短波長 = 格子スケールが選ばれる(§48 の f_splash と同じ無限波数の
  型)。振幅は可動層厚(灰を削り切る)で頭打ち
- **確認**: dd だけを 0.2 mm にすると(谷壁の横断勾配 0.12 の作成途中の地形で)、40 分の時点で行方向の 2Δ 成分が 0.099 → 0.004 m に
  下がり縞が消えた(侵食量は縞のぶん約 2 割過大だった)
- **対処**: 例題は dd = 0.2 mm。ユーザーガイド(geomorph の「ラハール」の段落)に、侵食
  起動でシート流を扱うときは dd を流れの深さより十分小さくする注意を追加。既定値は変えない
  (既定 1 mm は浸水計算の経験値で、薄い前縁の計算コストと摩擦の感度とのかね合い。
  encgrid.md の dd の行)

### 28.15 斜面等流の平衡濃度の検定と、開いた境界の行の最急降下勾配(2026-10-30 記録・同日修正)

handoff 1j の残「斜面等流の平衡濃度」の解析検定を test/debris 構成 7(param_eq.txt・

### 28.16 降伏の静止判定を駆動の大きさで行う(格子の向きによる動き出しの歪みの修正。2026-11-04 挙動変更)

- **現象**: 降伏(f_dbres >= 1 の a_y)による静止と動き出しの閾値が、斜面の向きと近傍の組で
  変わり、本来の勾配 μ = a_y/g_e より高く出る(最大で約 √2 倍)。格子を細かくしても変わらない。
  examples/debris_fan(格子への依存の例題)の作成中に、一様な斜面に円盤の崩壊深を置く試験で
  見つけた(動き出す G/μ が、4 近傍で 0°: 1.09〜1.21、22.5°: 1.21、45°: 1.44、8 近傍で 0°: 1.44、
  22.5°: 1.21、45°: 1.32〜1.44。Δx 1 m と 0.5 m でほぼ同じ)。下の test/dbonset を修正前のコードで
  回すと、1.1 μ の 2 s 後の内部の速さ(解析解 0.683 m/s)が、8 近傍の 0°・22.5°・45° で 0.005・
  0.009・0.007 m/s、4 近傍で 0.683・0.459・0.000 m/s だった。1.3 μ(2.048 m/s)でも、8 近傍の
  0°・45° と 4 近傍の 45° は 0.01 m/s 未満だった。
- **原因**: calc_kth_flux の静止判定 `vv0e < db_vstop .and. |tae + tge| <= aye → uve1 = 0`
  (§28.11 で低速の判定だけ辺の速さ |V| にした)が、駆動を辺の法線成分 tae + tge(移流+重力。
  辺の差分)だけで a_y と比べていた。下り向きと角 α をなす辺の駆動は G cos α に減るので、斜面に
  斜めの辺は G > μ でも止められる。止まった辺を含めて組み立てたセルの速さ |V| が小さく出て、
  動いている辺の降伏の摩擦 aye·u_n/max(vve, vv) が a_y を超えて効くため、層全体が動かないか
  遅れる。止められる辺の組は斜面の向きと近傍の組で変わる(4 近傍の 0° は、止まるのが駆動 0 の
  横断の辺だけなので正しく動く。1 次元の検定 test/volcano・curvature は 4 近傍の軸の向きなので
  検出されなかった)。§28.11 の教訓(ベクトルの大きさに対する条件は成分で判定しない)の、駆動の
  側の取り残し。溶岩流の §51.4 と同じ型の歪み。
- **修正**: 静止判定の駆動を、法線成分と接線成分を合わせた大きさにする:
  (tae + tge)² + tte² ≤ aye²。接線成分 tte は、流動面 η のセルの勾配 (∂η/∂x, ∂η/∂y) の両セル
  平均を辺の接線へ射影し、重力項と同じ係数 ge·gve を掛けたもの。η は辺の重力項と同じ定義
  (z + h + hs。圧力項なし(f_pressure_term = 0)は z)。セルの勾配は、濡れた(h + hs > dd)有効
  セル(領域内・海でない)だけで差分する: その方向の両隣が濡れていれば中心差分、片方なら片側
  差分、なしなら 0(乾いたセルの地盤は流動面でないので使わない。谷壁の勾配が静止判定に入らない
  ように。§51.4 と同じ)。勾配は yield_prepare がステップごとに前計算する(曲率項の
  curv_prepare と同じ置き場。配列 gsx・gsy は f_dbres >= 1 のときだけ確保する)。動いている辺
  (|V| ≥ db_vstop)の扱いと摩擦の式は変えない。移流の接線成分は入れない(静止判定は
  |V| < db_vstop の低速でだけ働き、移流は小さい)。
- **決定の理由**(2026-11-04 合意):
  - 接線成分は、セル中心の勾配の両セル平均で取る。軸の辺と斜めの辺を同じ式で扱え、辺ごとに
    周囲のセルの差分を組むより簡単。濡れたセルだけで差分するのは §51.4 の溶岩流と同じ考え方。
  - 既定を切り替え、旧方式に戻すスイッチは置かない。旧方式は格子の向きによる離散化の誤差で、
    選ぶ理由がない(§0-6。§51.4 と同じ)。
  - 検定は test/dbonset を新設する。修正の正しさ(閾値が μ、速さが剛体の滑りの解析解)と、

### 28.17 間隙水の一貫化: 保持水の授受 f_dbwet = 3 と層1の初期地下水 gw_sat0(2026-11-22 合意・実装)

天然ダム例題の検討(docs/landslide_dam_plan.md §11。2026-11-22 再開)で合意した追加機能の 1 つ目。
同メモ §5.1 の A2 案を採った。

- **きっかけ(試算)**: 支流の土石流が本川をせき止める通しの試算(格子 10 m、Green-Ampt + 側方流、
  λ = 0.4)で、f_dbwet = 2 の結果が比湧水量 sy0 で大きく変わった。
  - sy0 = 0.4(= λ)では、地下水なしの f_dbwet = 1 とほぼ同じ結果になる(土石流の直後の下流の
    流量 425 対 405 m³/s、越流の開始 31 対 32 分)。
  - sy0 = 0.2 では、土石流の直後の下流の流量が 2.6 倍(1118 m³/s)になる。堆積物が間隙の半分
    (sy0 の分)しか水を取らず、残りの (λ − sy0)·Δz(約 1.8 万 m³)が地表に余るためである。
  - 崩壊(slide_pass2)と瞬時流動化(release_debris)は地下貯留 hg しか出さないので、飽和した土層が
    崩れても混合体の濃度は C = (1 − λ)/((1 − λ) + sy0) で、sy0 < λ なら充填濃度 C* を超える。
  - 層1に初期地下水の口がなく、崩壊土塊の間隙水を地下水の側から与えられない。
- **考え方**: 土層厚 sd の柱には 2 つの水があるとみなす。
  - 明示の**排水可能水** hg(容量 sy0·sd)。f_dbwet = 2 が授受する。
  - 暗黙の**保持水** w_r·sd(w_r = λ − sy0)。常に存在し、土と一緒に動く。状態量は持たない。
    Green-Ampt の水分不足量 Δθ = sy0 は、初期含水率 θ_i = θ_s − sy0 を意味する。θ_s = λ とすれば
    θ_i = λ − sy0 = w_r である(独自の整理)。
- **f_dbwet = 3 の規則**(2 の授受に保持水の授受を足す)
  - 堆積(Δz > 0): w_r·Δz を地表水から取る。地表水が足りなければ hg から取り(乾いた土砂が層の水を
    吸う)、それも足りない分は不足として数える。そのあと 2 と同じく、増えた容量を残りの地表水で満たす
    (保持水が先)。
  - 侵食(Δz < 0): w_r·|Δz| を地表水へ戻し、2 と同じく min(sy0·|Δz|, hg) を hg から戻す。
  - 斜面崩壊と瞬時流動化: w_r·D を地表水へ戻す(既存の容量超過引き渡しが hg の分を出す)。飽和した
    土層なら合わせて λ·D の水が出て、濃度は C* になる。
  - 動く底層への引き渡し(plunge_cells)の堆積側でも、保持水を水柱から取る。
  - 台帳: 土石流の交換について Σh + Σhg + w_r·Σ(z − z0) − 不足 が保存される。不足は行ごとの
    部分和(gm%dbr%wdrow)に積み、dispose が par_sum_rows の決定的な総和で
    `retained pore water shortfall in deposition (f_dbwet=3)` として 1 行表示する。
  - 検査: gwflow が要る(2 と同じ)。sy0 ≤ λ(= fluv_porosity)を要求する。sy0 = λ なら w_r = 0 で 2 と同じ。

- **不飽和床の侵食式(f_dbunsat = 1。f_dbed = 3 が要る)**

    (c_T∞ − c_L) h/d_L。導出は年報 式(8)〜(11)(不飽和の層は、表面に露出した粒子だけが間隙流体のせん断応力で
    取り込まれる。i = K(τ*f − τ*fe)√(τf/ρm))。年報は最後の因子を c_L∞ − c_L に直したと書いている
    (「文献1), 3) では τfe に対応する濃度は後出の c_T∞ であるとしたが、このように修正する」)。単一粒径(細粒なし。
    ρm = ρ)では c_T∞ = c_L∞ なので、2 つの論文の式は同じになる。
  - 実装の形: 単一粒径では tanφ/tanθ − 1 = 1/(s c∞)(c∞ は石礫型の平衡濃度)なので、
    i = (K/s)√(g h_t) sin^{3/2}θ (1 − C/c∞)^{1/2} (C∞ − C)/c∞ · h_t/d_L と書ける。gm%db_kuns = K/s を
    前計算する。h は混合流動深 h_t = h + hs、θ は飽和床の式と同じ流動面の勾配(slope_flow_surf)。
    流速を含まない(飽和床の式は q_T/d_L に比例する)。
  - 定数: K = db_kunsat(0 なら既定 0.01 = 新砂防の洞谷への適用値。「従来の実験結果を参考に」)。
    年報に K の値はない(検証実験は飽和床)。
  - 飽和の判定(bed_unsat): 地下水計算ありは、地下貯留が容量に届いていない(sy0·sd − hg > 1e-9·sy0·sd)
    セルを不飽和とする。飽和帯は土層の底から積もると読むので(f_slide・側方流と同じ)、容量に届いた =
    飽和帯が地表に届いた、である。1e-9 の余裕は、授受の丸めで 1 ulp 欠けた飽和のセルを不飽和と読まない
    ため。地下水計算なしは db_satbed < 1 なら全域が不飽和(新砂防は洞谷の計算で、勾配 21° 以上の区間の
    飽和度を s_b = 0.8、それ以下の区間を 1.0 としている。どちらの式をどの区間に使ったかは書いていないが、
    2 つの式の見出しが「堆積層が不飽和である場合」「堆積層が飽和である場合」なので、s_b < 1 を不飽和と読む)。
  - 独自の閉じ: 平衡濃度が上限 0.9C* で頭打ちになる急勾配でも、頭打ちした c∞ を上の形のまま使う。
    年報は「およそ 0.9c* 程度で流れる。その際、i = 0 である」とだけ書き、この領域の C < 0.9C* の侵食速度を

### 28.19 斜面安定判定 f_slide の選択子: 浸透力 f_slide_seep・間隙水圧の崩壊に限る f_slide_wet・流動中のセルを外す f_slide_noflow・深さの上限 slide_dmax(2026-11-22 合意・実装)

既定は無効で、従来の経路だけを通る(結果は不変)。最急勾配の関数を配列を受ける形に分ける等価変換は
別コミットにした。

- **きっかけ(検討メモ §3.2〜§3.4 の試算)**
  - 湖の下の斜面: 従来の式は斜面に平行な浸透を仮定し、駆動に土塊の全重量を使う。静水の下では浸透力が
    なく、c′ = 0 の本来の値は Fs = tanφs/tanθ である。従来の式はこれを γ′/γt(およそ 0.46)倍に見積もり、
    湛水域の安定な斜面(勾配 0.33)が湖水の浸透で崩れた。
  - 段差の連鎖: 全層を流動化してできた段差の隣の乾いたセルが Fs = tanφs/tanθ < 1 で崩れ、乾いたセルの
    土砂はその場に戻ってまた崩れる。40 分で流動化 14 万回(640 セル)。
  - 動けない土塊の往復: 崩れた濃い土塊が動けずに河床へ戻り、飽和して再び流動化する(周期 2 更新)。
  - 厚い堆積層(天然ダムの堤体)が全層で崩れる。
- **等価変換(別コミット)**: 最急勾配 slope8(D∞)の本体を、帯確保の面を受ける steep8(gm, g, a, i, j)に
  分け、slope8 は steep8(…, s%z, …) を呼ぶだけにした。全水頭の面にも同じ演算を使うため。
- **f_slide_seep = 1(浸透力を全水頭の勾配で入れる)**
  - 式: Fs = [c′ + (γt·d − γw·hw)·cos²θ·tanφs] / [cos²θ·{(γt·d − γw·hw)·tanθ + γw·hw·J}]。
  - 導出(独自の整理。標準的な無限長斜面の有効応力と浸透力のつり合い): 単位の平面積の土柱で、土粒子の
    骨格に働く力を、不飽和部の重量 γt(d − hw)、飽和部の水中重量 (γt − γw)hw、浸透力(単位体積あたり
    γw × 動水勾配)で書く。水平距離あたりの水頭の低下を J、流れを斜面に平行とみなすと、斜面に沿う
    動水勾配は J cosθ、浸透力は γw·hw·J·cosθ。斜面に沿う力は (γt·d − γw·hw) sinθ + γw·hw·J cosθ、
    斜面に直角な有効な力は (γt·d − γw·hw) cosθ。すべり面の面積 1/cosθ で割って上の式になる。
  - J は全水頭 H = (z − sd) + hw の最急降下勾配(D∞。steep8)。土層が地表まで飽和したセル(地下貯留が
    容量に届いている。gw_full)は地表水の水深 h を足す(側方地下水の水頭と同じ読み方)。土層のない
    セルは H = z + h。
  - 極限: 土層厚と飽和厚が一様な斜面は J = tanθ で従来の式に一致する。静水の下は J = 0 で
    Fs = tanφs/tanθ(c′ = 0)。堤体の下流側の湧出部は J > tanθ になりうる。
  - 近似: 浸透力の向きを斜面の最急勾配の向きとみなし(J の向きが斜面の向きと違っても大きさをそのまま
    使う = 安全率は小さい側)、斜面に直角な成分は入れない。
  - 地下水計算(fn_gwflow)が要る(なければ間隙水圧が 0 で式が変わらないので、停止して知らせる)。
  - ハロ: 全水頭は近傍の h・hg・z・sd を読む。z・sd は geomorph の末尾の交換で最新だが、h は swflow が、
    hg は地下水計算が帯内を更新済みなので、calc_debris の冒頭で交換する(f_dbed = 3 の h・hs と同じ構図。
    判定は namelist 由来で全ランク同一)。全水頭の面 gm%dbr%hd は帯とハロ(ish:ieh, jsh:jeh)で確保し、
    評価のたびに作り直す。
- **f_slide_wet = 1(間隙水圧で起きる崩壊に限る)**: Fs < 1 のセルで、間隙水圧なし(u = 0)の安全率も
  1 未満なら流動化しない(幾何的な不安定。安息角崩落 f_repose の担当)。Fs の出力と最小値の診断は
  変えない。流動化しなかった回数(セル × 評価)を終了時に表示する。
- **f_slide_noflow = 1(濃い混合体が載るセルを判定しない)**: hs > 0 かつ hs/(h + hs) ≥ db_cmin のセルは
  判定しない(Fs の出力は未評価の −1)。河床と流れの交換は侵食堆積式の担当。判定しなかった回数を
  終了時に表示する。
- **slide_dmax > 0(判定・流動化する深さの上限)**: 上から d = min(sd, slide_dmax) だけを判定し、流動化
  する。飽和厚は hw_d = max(0, hw − (sd − d))(飽和帯は土層の底から積もる)。流動化のあと、残った土層の
  容量 sy0·(sd − d) を超える地下貯留を地表へ出す(全層のときの「容量 0 = 全量」の一般化)。残った層は
  次の更新でまた判定されるので、飽和が続けば上から順に崩れる。handoff 1j の「斜面崩壊の部分深さ化」。
- **採らなかった案**
  - 崩壊の発生域をマスクで限る(fn_slide 等): シナリオの制御としては簡単だが、物理を直さない。
  - 浸透力の向きまで扱う(水頭の勾配ベクトルを斜面に沿う成分と直角な成分に分ける): セル独立の
    無限長斜面の近似の範囲では、向きを斜面に合わせる方が式が閉じる。必要になれば別に検討する。
  - f_slide_wet・f_slide_noflow を既定にする: 既存の計算(test/slide 構成 2、examples)の結果が変わる。
- **整合する設定**(検討メモ §3.2。独自の整理): 飽和した土層(hw = sd、c′ = 0)は tanθ > (γ′/γt)·tanφs で
  崩れる。γt = ρw·g·(1 + sC*) とすると γ′/γt = sC*/(1 + sC*) で、濃度 C* の混合体のクーロン降伏
  (f_dbres = 1)の係数と同じになる。slide_phi = db_phi、slide_gamma = ρw·g·(1 + sC*)(λ = 0.4・s = 1.65 で
  19,500 N/m³)、崩壊土塊の濃度 C*(地下水計算と併用するなら f_dbwet = 3)の 3 つをそろえると、
  「飽和して Fs < 1」と「混合体が降伏して動き出す」が同じ条件になる。f_dbres = 3 は降伏が
  tanα′ = 0.45 なので、slide_phi ≥ 24.2° なら崩れた飽和土塊は動ける。
- **既知の制約(受容の上で記録)**
  - 薄い堆積の往復: 急な基盤の上に薄く残った堆積は、低速で止まって河床へ戻り(f_dbstop)、雨や流れの水で
    飽和してまた流動化する、を繰り返す。f_slide_noflow が外すのは濃い混合体が載っているセルだけなので、
    河床に戻ったあとの薄い層は判定に戻る(往復の周期は延びるが、なくならない)。終了時に表示する流動化の
    延べ回数(fluidized cells)は、この往復も数える。崩壊の規模は土層厚の変化(Sd の出力)で見ること。
    天然ダムの試算(検討メモ §11)では、土層のある崩壊斜面 500 セルに対して延べ回数が 10⁶〜10⁷ セル回に
    なった。
  - f_slide_seep の全水頭は、土層の飽和帯の水頭と、地表まで飽和したセルの地表水だけで作る。土層のない
    セル(基盤)の中の水頭や、被圧の状態は表さない。浸透流が堤体を抜けるまでの時間は地下水計算
    (側方流の透水係数)で決まり、透水係数が小さければ、計算の時間のうちに下流の法面まで浸潤面が届かない。
- **落とし穴(検定の作り方)**
  - 湖の下の検定(test/slide 構成 5 の `_l0`・`_l1`)は、湖のセルと陸のセルの境で全水頭の勾配が中間の値に
    なる。判定は、自分と 8 近傍がすべて湖か、すべて陸のセルに限る。湖が狭いと対象のセルがなくなる。
  - 構成 7・8 の縁のセルは、領域の外の近傍を除くので最急勾配が内部と違い、内部とは別の判定になる。
    2 回の更新を比べる構成 8 は、1 回目に流動化しなかった縁のセルの隣で 2 回目の勾配が変わるので、縁から
    2 列を除いて比べる。
  - 小さい格子(60 × 20 など)のテストを、ほかの計算で CPU が埋まった状態で OpenMP の既定のスレッド数の
    まま流すと、並列領域ごとの待ち合わせで進まなくなる(10 秒の構成が 10 分たっても終わらなかった)。
    検証を並べて流すときは OMP_NUM_THREADS を空いているコア数に合わせる。
- **検証**(gfortran 13.3。2026-11-22)
  - 等価変換(slope8 → steep8): 変更前後の実行ファイル(-Ofast・逐次)で、12 のテスト(slide・debris・

  - 無効時の不変: 等価変換だけの実行ファイルと、選択子を入れた実行ファイルで、同じ 12 のテストの
    state.dat 232 個がバイト一致。
  - 安全率の式(test/slide 構成 5・6。40 × 30 セルの平らな斜面と、その下流側を湖にしたケース): 出力の安全率が式の

    同じ。土層の底が地表と違う勾配の斜面は J = 0.4405 で従来の式より 3.2 % 小さい。静水の下は

### 28.20 【実バグ】湖の下の飽和した斜面が流動化する: 地表水の水頭の接続と、河床の飽和の判定の余裕(2026-11-22 修正)

§28.19 の f_slide_seep = 1 を入れたあと、天然ダムの例題(§28.22)の 5 m 格子のケースで見つけた。§28.18 の
f_dbunsat の飽和の判定にも同じ原因の誤りがあり、同じコミットで直した。どちらも同じ日に追加した選択子の
修正で、既定(選択子なし)の計算は変わらない。

- **症状**
  - 高さ 13 m の飽和した堤体(法面の勾配 0.12)の湖側の法面が、湖(静水)の下で流動化する。5 m 格子では、
    計算の開始から 30 秒で 2.0 万 m³、60 秒で 5,600 m³ の土砂が動いていて、8 分で天端が 2 m 下がった。
    決壊は遅れ、45 分でもピークに達しなかった(10 m 格子は 29 分)。10 m 格子でも 60 秒で 450 m³ が
    動いていた。
  - 6 秒の診断(5 m 格子): 開始 1 秒の湖の下の安全率は 5.84(= tanφs/tanθ。正しい)。そのあと、安全率が
    0〜1 のセルが 2 → 9 → 20 → 34 と増える。
  - 飽和した堤体のピーク流量(290 m³/s)が、不飽和の堤体(401 m³/s)の 0.72 倍になる。侵食式の切り替え
    (f_dbunsat)の差は 2 % で、理由がつかなかった。
- **原因 1(f_slide_seep の全水頭)**: slide_head は、地表水の水深 h を「地下貯留が容量に届いたセル」だけに
  足していた(gw_full。容量の 1e-9 倍の余裕。側方地下水の水頭と同じ 2 値の読み方)。
  - 側方の地下水流は、流れのある所の貯留を 1 回ごとに容量の K·J·Δt/(Δx·sy0) 倍だけ動かす。例題の値
    (K = 100 mm/h、Δt/Δx = 0.01 s/m、sy0 = 0.2)で J = 0.1〜1 なら 1e-7〜1e-6。鉛直の浸透が次の
    ステップで埋め戻すが、地形の更新は側方流のあとに来るので、流出のあるセルは「わずかに欠けた」状態で
    判定される。
  - 欠けたセルの全水頭は水深 h だけ下がり、届いている隣のセルとの間に h の段差ができる。全水頭の勾配は
    J ≈ h/Δx。飽和した土層(c′ = 0)は J > (γ′/γw)(tanφs − tanθ) で Fs < 1 になり、例題の値
    (γt = 19,500 N/m³、φs = 35°、tanθ = 0.12)では J > 0.57、すなわち水深が 5 m 格子で 2.9 m、10 m
    格子で 5.7 m を超える所で流動化する。細かい格子ほど浅い所から起きる。
  - 側方地下水の側も同じ 2 値で読むので、欠けたセルには隣から水が押し込まれ、今度は押し込んだ側が欠ける。
    欠けたセルは湖の下を動き回り、数が増える。
- **原因 2(f_dbunsat の飽和の判定)**: bed_unsat も gw_full を使う。1e-9 の余裕は丸め(1 ulp)だけを見込んで
  いて、上の欠け(1e-7〜1e-6)より小さい。飽和した堤体(gw_sat0 = 1)の 60 分の計算で数えると、侵食の
  計算 6,800 万回のうち 270 万回(3.9 %)、侵食量では 28 % が、「不足が容量の 0.1 % 以内なのに不飽和」と
  判定されたセルで、不飽和床の式で計算されていた(本当に不飽和 = 不足が 0.1 % を超えるセルは 38 %、
  飽和と判定されたセルは 34 %)。
- **修正**
  - 飽和とみなす不足の幅を gw_wfull = 1e-3(容量に対する比。独自。原式固定の定数と同じく namelist に
    しない)とし、2 か所で使う。
  - slide_head: H = (z − sd) + hw + κ·h。κ = clamp(1 − (cap − hg)/(gw_wfull·cap), 0, 1)(cap = sy0·sd)。
    地表水の水頭を、貯留が容量の 99.9 % から 100 % までの間で連続につなぐ。容量に届いたセルは κ = 1 で
    従来と同じ値、土層のないセルは κ = 1、地下水計算なしは κ = 0(gw_full と同じ)。
  - gw_full: 不足が gw_wfull·cap 以内なら飽和(1e-9 → 1e-3)。
  - 幅の根拠: 欠け(1e-7〜1e-6。K が 10 倍でも 1e-5)より 2 桁以上広く、土層に対しては薄い(3 m の土層で
    飽和厚 3 mm、粒径より小さい)。κ が連続なので、欠け δ は水頭を h·δ/gw_wfull しか変えない(δ = 1e-6、
    h = 10 m で 1 cm。全水頭の勾配で 5 m 格子なら 0.002)。
- **採らなかった案**
  - slide_head の 2 値の余裕だけを広げる: 余裕の境で水頭が h だけ跳ぶ形が残る。
  - 地表水があれば必ず足す: 乾いた河床を流れる土石流の流動深を、土層の間隙水圧として数えてしまう。
  - 側方地下水の水頭の読み方を連続にする: 揺らぎの元を断つが、地下水計算の既存の reference が変わる。
    水量は保存していて、揺らぎは容量の 1e-6 の桁なので、ここでは変えない(handoff 1j に残す)。
  - 2 つの侵食式を κ で連続に混ぜる: 原論文は「不飽和である場合」「飽和である場合」の 2 つの式で、
    中間を与えていない。判定の境を揺らぎの外へ出すだけにした。
- **落とし穴**
  - 判定の余裕は、丸めではなく、物理過程が毎ステップ作る揺らぎの大きさから決める。丸めだけを見込んだ
    1e-9 は、側方流のある計算では余裕として働かなかった。
  - §28.19 の湖の検定(test/slide 構成 5 の `_l1`)は、貯留がちょうど容量の初期状態を 1 回判定するだけ
    だったので、この誤りを通した。貯留をわずかに欠いた湖のケース(`_lq1`・`_le1`)を足した。静的な検定は、
    境の値だけでなく、境からわずかに外れた値でも行う。
  - 5 m 格子で初めて目立った。格子を細かくすると変わる結果は、収束の問題とは限らない(段差の勾配が
    h/Δx で、判定の閾値をまたぐ水深が格子間隔に比例していた)。
  - gfortran は、標準エラー出力もファイルへ向けるとバッファする。診断の write(0,*) は計算が終わるまで
    出てこない(逐次確認するなら flush を呼ぶ)。
  - MPI の検査を、ほかの計算で 4 コアが埋まった状態で流すと、4 ランクの小さいテストがランクの待ち合わせで
    進まなくなる(10 分でログが 11 行)。ほかの計算を止めてから流す(§28.19 の OpenMP の落とし穴と同じ)。
- **検証**(gfortran 13.3。2026-11-22)
  - 検定の追加(test/slide 構成 5): 湖の下で地下貯留を容量の 2.5e-4・1e-6 だけ欠いたケース `_lq1`・`_le1`。
    湖の下の全水頭の勾配は J = (1 − κ) tanθ(κ = 0.75・0.999)で、安全率の式の値は 0.9431・1.1928。
    修正前の実行ファイルはどちらも 0.578(従来の式の値。式の値との差は相対 0.39・0.52)で FAIL、修正後は
    相対 3e-9・3e-8 で PASS。貯留がちょうど容量の `_l1`(1.1941)と陸の側は、修正の前後で同じ値。
  - 症状の解消(5 m 格子の堤体。修正後): 動いている土砂は 60 秒で 3 m³、120 秒で 4 m³(修正前 5,632・
    3,956 m³)。7 分までの標高の低下は、天端より下流の法面(越流による侵食。最大 0.40 m)だけで、湖側の
    法面は変わらない。
  - 10 m 格子の飽和した堤体のピーク流量は 290 → 397 m³/s(ピークの時刻 29 → 27 分)。全水頭の接続だけを
    直した試験ビルドは 398 m³/s・25.5 分で、飽和の判定の余裕の効果は時刻に 1.5 分。不飽和の堤体
    (401 m³/s。この修正で変わらない設定)とそろった。
  - 無効時・無関係な設定の不変: 修正前後の実行ファイル(-Ofast・逐次)で、12 のテスト(slide・debris・
    dbslope・splashslide・volcano・avalanche・dbrock・curvature・rockinc・repose・bedslide・dbonset)の
    state.dat 232 個がバイト一致(f_slide_seep = 1 の test/slide 構成 5 と、f_dbunsat = 1 と地下水計算を
    併用する test/debris 構成 9 を含む。どちらも、貯留の不足が幅 1e-9〜1e-3 の間に入るセルがない)。
    コメントと地下水計算なしの分岐を整えた最終の実行ファイルでは、うち 4 テスト(slide・debris・
    splashslide・dbslope)の 66 個を確かめ直した。
  - 並列: nightly の debug-fcheck と同じフラグ(-Og -fcheck=all)の逐次と MPI で、test/slide(構成 5〜8 は
    16 ケース)と test/debris が np = 1・2・4 とも逐次とバイト一致。実行時エラーなし。
  - リリースビルド(-Ofast・逐次)で test/slide(42 項目)・test/debris・test/splashslide・test/dbslope が

### 28.21 【実バグ】流動化が湖の下で連鎖する: 全水頭を流動面で読む(2026-11-22 修正)

§28.20 の修正のあと、例題(§28.22)の 5 m 格子の堤体のケースが 10 m 格子の半分のピークになり、調べると
f_slide_seep = 1 の全水頭にもう 1 つ誤りがあった。§28.19 の選択子の修正で、既定の計算は変わらない。

- **症状**(5 m 格子。高さ 13 m の飽和した堤体、湖は天端まで)
  - 決壊のピークは 191 m³/s・37 分(10 m 格子は 397 m³/s・27 分)。流動化の延べ回数は 300 万セル回
    (10 m 格子は 24 万)。
  - 19〜20 分の 1 分間に、128 セルが 0.8 m 以上下がる。湖側の法面の裾(天端から 40〜90 m 上流、水深
    5〜10 m。勾配 0.12)が一様に 2.1〜2.4 m 下がっていて、かさで 6,000 m³。その 1 分前の安全率は 5.8
    (= tanφs/tanθ)。動いた土砂は湖側と決壊口に積もり、決壊を遅らせる。
  - 10 m 格子では起きない。10 m 格子の同じケースは、流動化を止めても(f_slide = 2)ピークが 397 m³/s の
    ままで、安定判定は決壊に関わっていない。
- **原因**: slide_head は地表の水頭に水深 h だけを使っていた(H = (z − sd) + hw + κ·h)。流動中の土砂が
  載ったセルの流動面は z + h + hs で、間隙を満たす水の水面もそこにある。h だけで読むと、そのセルの水頭は
  hs だけ低い。
  - 飽和した土層を深さ D だけ流動化すると、地盤は D 下がり、水 λ·D と土砂 (1 − λ)·D が載る(f_dbwet = 3)。
    流動面は変わらないが、h だけで読んだ水頭は (1 − λ)·D 下がる。
  - 隣のセルから見ると、地形の段 D/Δx と水頭の段 (1 − λ)·D/Δx が同時にできる。飽和した土層(c′ = 0)の
    安全率は Fs = γ′tanφs/(γ′tanθ + γw·J)。D = slide_dmax = 3 m、λ = 0.4、例題の値(γ′/γw = 0.99、
    tanφs = 0.70)で、Δx = 5 m は tanθ = 0.6・J = 0.36 で Fs = 0.73、Δx = 10 m は tanθ = 0.3・J = 0.18 で
    Fs = 1.45。5 m 格子では、1 セルの流動化が隣を流動化させ、飽和した法面を伝わっていく。水頭の段が
    なければ(J = 0)Fs = 1.17 で、伝わらない(安息角を超える段は f_repose が崩す)。
  - 間隙水圧なしの安全率は tanφs/tanθ = 1.17 で 1 を超えるので、f_slide_wet = 1 は止めない。
- **修正**
  - slide_head: H = (z − sd) + hw + κ·(h + hs)。流動面 z + h + hs は f_dbed = 3 の勾配と同じ読み方。
  - ハロ: 全水頭は近傍の hs も読む。calc_debris の冒頭の hs の交換を、f_dbed = 3 に加えて
    f_slide_seep = 1 でも行う(swflow が帯内の hs を更新済みなので、交換しないと帯の境界で古い)。
- **落とし穴**
  - §28.19・§28.20 の検定は、流動化の前の状態(地表に水だけ)しか判定していなかった。流動化のあと
    (土砂が載ったセルの隣)の判定を足した。判定の式が読む状態量は、その判定自身が作り変える状態でも
    検定する。
  - 10 m 格子で「流動化を止めても結果が同じ」ことは、安定判定が正しいことを意味しなかった。誤りの出方が
    D/Δx に比例していて、格子を細かくして初めて閾値を超えた。格子を変えて結果が大きく変わったら、収束の
    問題とみなす前に、変化の出方を見る(勾配 0.12 の水没した法面が 1 分で一様に 2.3 m 下がるのは、侵食の
    速さではない)。
  - 1 分おきの出力の安全率は、連鎖の前後の値しか写さない。出力の安全率が大きいことは、その間に流動化が
    なかったことを意味しない。地盤高の変化の出方と、流動中の土砂の量を見る。
- **残る格子への依存: 1 回の流動化でできる段(既知の制約。受容の上で記録)**
  - この修正のあとも、5 m 格子・slide_dmax = 3 m の堤体のピークは 204 m³/s・25 分で、10 m 格子の半分の
    ままだった(19〜20 分の連鎖は消えた: 0.8 m 以上下がったセルは 128 → 9、動いた土砂は 5,900 → 70 m³。
    22 分から先に、決壊口の頭のまわりで 3 m ずつの流動化が続く)。
  - 決壊口へ向かう流れのある所では、水面が下がっていて全水頭の勾配 J が 0 でない(誤りではなく実際の
    浸透力)。1 セルを D だけ流動化してできる段 D/Δx と重なると、隣の飽和したセルは
    γ′(D/Δx + tanθ) + γw·J > γ′tanφs で崩れる。D/Δx = 0.6(5 m 格子・3 m)は J > 0.1 ほどで、0.3(10 m
    格子・3 m)は J > 0.4 ほどで崩れる(tanθ = 0、φs = 35° として)。段の急さが格子間隔に反比例するので、
    同じ slide_dmax でも細かい格子ほど連鎖しやすい。
  - 5 m 格子で slide_dmax を 1.5 m(D/Δx = 0.3)にすると、ピークは 433 m³/s・28 分。安定判定による流動化を
    止めた計算(f_slide = 2)は 5 m 格子で 385 m³/s・27 分、10 m 格子で 397 m³/s・27 分(流動化ありの
    10 m 格子と同じ)。越流による侵食そのものは 2 つの格子で 3 % しか違わず、差を作っていたのは流動化の
    連鎖である。
  - 目安として、slide_dmax は格子間隔の 0.3 倍程度までにする(利用者ガイド massflow.md §4 に書いた)。
    流動化の深さを格子間隔によらない形にする(段をならす、斜面のまとまりで崩す)のは、モデルの設計の
    課題として handoff 1j に残す。
  - 側方地下水の水頭も、容量に届いたセルに水深 h だけを足す(hs を含まない)。流動中の土砂が載ったセルの
    水頭を低く読むので、隣のセルから地下水を引き込み、まわりの飽和を崩す。側方流の水頭も流動面で読む
    試験ビルドでは、5 m 格子・slide_dmax = 3 m の湖側の流動化の始まりが 22 → 24 分に遅れただけで、
    なくならなかった。地下水計算の本体に関わる変更なので、ここでは入れていない(handoff 1j)。
