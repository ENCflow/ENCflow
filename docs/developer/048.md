## 48. 乾式斜面侵食 m_geomorph_splash(f_splash。2026-08-20 実装)

表面流のない高透水斜面(バッドランド・火砕丘の海食崖)の谷形成を扱う
geomorph の加算成分。動機は新島南部火砕丘の観察(台地上に谷ゼロ・
地下水面なし・端部に深い谷)で、「移流(表面流)なしの谷形成」を
サブグリッド効果のパラメータ化で表す(Howard 1994/1997 の枠組みの外。
雨滴転動の実験的裏付けは Trottet et al. 2025, PNAS の sandball 機構)。
**詳細(定式化の根拠・離散化・試行錯誤の全記録・文献)は
docs/splash_plan.md**。

- **設計判断**: 独立モジュールではなく **m_geomorph の加算フラグ**
  (creep/wash/debris と同型)。z・sd の所有・e=z+h 回復・リスタート・
  MORFAC 台帳・可動層クランプの契約を単一実装のまま継承するため。
  名称はプロセス名 splash(badland は現象名なので usecases 側で案内)。
- **浸食則**(固体体積 m/s。P = s%pre、S = |∇z| 中央差分、
  κ = max(∇²z, 0) 5点ラプラシアン=凹で正):
  E = P・[spl_kr・(1+spl_ca・κ) + spl_kt・(1+spl_cb・κ)・S^spl_h]。
  第1項が雨滴(台地上でも働く加算項)、第2項がサブグリッドリルの
  乗算構造(S→0 で消える)。**適用は乾燥セル(h <= dd)のみ** =
  f_wash(湿潤)と相補で二重計上しない。rw>0・海セルは対象外だが、
  海セルの z は勾配・曲率の近傍としては読む(海食崖の縁が対象)。
- **開いた系**: 剥離土砂は hs に注入せず(無流水では移流できない)
  **系外排出**。台帳 spl%vout(固体 m3、ランク局所)を dispose で報告。
  z・sd 共動更新+gwflow 容量引き渡しは calc_wash と同一規約。
  sd=0 で岩盤露出・停止(f_wthr と収支が閉じる)。
- **MPI(2パス構造)**: 近傍 z を読むため、評価(eval_splash → spl%fx)は
  **calc_debris の適用より前**(全プロセスが時刻 n の z を見る)、
  適用(apply_splash、局所)は debris の後。これで帯界面がランク数
  不変になる(debris の fx と同じ理由)。排出台帳の集計は行別部分和 →
  逐次総和(スレッド数によらず決定的)。
- **安全弁**: spl_dzmax(1セル・1更新の上限。0=無効)。正のフィード
  バックの暴走をクリップし、発生数を dispose で報告する。
- **既知の性質(理論どおり)**: 平滑化なしの凹地形フィードバックは
  最短波長が最速成長する(Smith & Bretherton 1972 の無限波数問題)ため、
  単独では格子スケールの市松状凹凸が出る。初版はこれを**弱い f_creep の
  併用**で抑え「間隔は増幅(spl_cb)と拡散(creep_d)の比で決まる」と
  していたが、**2026-10-19 に改定**: 拡散項は成長の符号を変えるだけで
  間隔を選ばず、クリープは力学的モデルでもないので併用しない。間隔は
  曲率の相関長 spl_lc が決める(§48.3)。
- **定式化の出典(2026-11-02)**: この侵食則(凹地形増幅・曲率の相関長を含む)は開発者
  (利用者)の独自の定式化で、論文としては未発表(利用者の説明)。sediment.md §6 と例題の
  README に明記した(§0 方針 13)。Trottet et al. 2025・Gabet 2003 などは表そうとする現象の
  例で、式の形と係数の出典ではない。
- **例題の説明の組み直し(2026-11-02)**: badland・badland_round・badland_storm・mesa・karst・
  tower_karst の README(日英)を estuary_barrage と同じ構成(実際の現象 → 再現に必要な機構
  → 幾何と設定 → 実行方法 → 結果 → 表せないこと → 注意 → 感度実験の入口 → 参考文献)に
  組み直した。ケース・param の値は変えていない(param はコメントだけ直した)。結果の図と数表は
  利用者の依頼で再計算して合わせた: badland・mesa(表面流なし)は README の値を再現した(mesa の
  plot_results.py は崖錐の総量・段の面積に Δx² を掛けておらず、Δx = 4 m の系列の値を直した)。
  badland_storm・karst・tower_karst は main の既定 f_opening_dynamic = 3(§68.41〜§68.43)で計算し
  直して値を更新した。湿潤侵食のケースは -Ofast の最適化の差(§10 と同型)が流れの集中の正の
  フィードバックで数 % に増幅される(当時と現行を -O2 で作るとバイト一致。handoff 00g、README の
  「注意」)。各例題の Makefile に make run 等を足し、画面出力は `2>&1 | tee` で Screen*.log に
  残す(排出量・上限の回数・崩落量の台帳は par_warn = 標準エラーで、plot スクリプトがログから
  読むため)。機構の模式図と設定の図は計算結果を使わない各例題の plot_setup.py で描く
  (plot_results.py は結果を前提にしたモジュール直書きなので分けた)。新島の谷形成の仮説
  (研究の文脈)は README から外し、モデルの中での結論として書いた。他文書が参照する節の名前
  (badland_storm の「結果 4・5」、mesa の「崩落と崖錐」「窓版」「支え方式」「張り出しによる
  崩落」)は残した。組み直しで見つけた数値・図の題の食い違いと再計算の候補は handoff 00g。

### 48.3 曲率の相関長 spl_lc と侵食基準面 spl_zbase(2026-10-19 実装)

**経緯**: 移流項の改定(§68.38・§68.39)が一段落したのを機に、乾式斜面侵食の
テストと例題を再検討した(新島南海岸型の「鋭い稜線・深い谷」の形成と発達、
白色雑音からの谷の自己形成、谷間隔の決まり方、バッドランド的地形の再現)。
f_splash は無流水(h = 0)の過程なので移流項の改定の影響はなく、test/splash・
splashslide・examples/badland は改定後の木でビット一致・PASS を確認した。

**現行モデル(格子の κ)の再検討で分かったこと**(examples/badland の旧構成
80 × 60 m、崖縁の白色雑音、T_geo = 1.8e6 s。2026-10-19):
- 谷間隔は格子幅に張り付く: Δx = 0.5 / 1 / 2 m で 2.8 / 3.1 / 7.1 m
  (= 5.6 / 3.1 / 3.6 Δx)。起伏の成長率も Δx で 1.5 / 3.3 / 2.8 倍と収束しない。
- creep_d を 0 → 2e-6 m²/s に増やすと間隔は 2.7 → 8.7 m に伸びるが成長率が
  8.1 → 0.65 倍に落ちる(§48 の「窓」)。これは選択ではなく**符号の切替**で
  ある: 線形化すると増幅(κ フィードバック)も拡散(creep)も k² に比例し、
  成長率 σ = (D_a − D) k² は D_a > D なら全波数で正(最短波長が最速)、
  D_a < D なら全波数で負。比 c_b/creep_d は谷が生じるか否かだけを決める。
- spl_cb を 4 → 32 に変えても間隔(4.2 → 3.8 m)・成長率(1.8 → 1.9 倍)が
  ほとんど動かない: V 字谷底の格子の κ は 2S/Δx(Δx = 1 m で 3 /m)に達して
  Φ_B ≫ 1 となり、**spl_dzmax のクリップが谷の深化速度を決めていた**
  (1 更新あたり 190 セル超がクリップ)。dzmax を 0.05 → 0.5 m にすると最大
  下刻が 6.7 → 24 m と dzmax に比例する = 暴走をクリップが隠している状態。
- 崖下に基準面がないため谷底が海面下 5 m まで下刻する。

**設計判断**: Phase 2 として予告していた「κ 評価の平滑化 = 有限の相関長」を
**spl_lc**(m)として実装した。z を標準偏差 ℓ のガウス核で平滑化した zs から
κ を取る(勾配 S は生の z から)。線形化した成長率は

  σ(k) = D_a k² exp(−ℓ²k²/2),  D_a = P k_t c_b S^h

で、有限の波数 k* = √2/ℓ で極大を持ち、谷間隔 λ* = 2πℓ/√2 ≈ 4.4 ℓ が
ℓ(サブグリッドリルの集水スケール)だけで決まる物理量になる。V 字谷底の
κ̃ も ~2S/ℓ に有界になる。Perron ら(2009)の λ ∝ √(K_s/K) が増幅と拡散の
比で間隔を決めるのに対し、ここでは平滑化のスケールそのものが間隔を決める。
**クリープ(f_creep)は併用しない**(利用者の指示 2026-10-19: 力学的モデル
でない)。旧版(§48・splash_plan §6.2)が「弱い creep の併用が要る」とした
のは格子の κ の市松を抑えるためで、間隔の選択には不要。参考: 拡散項 D を
足すと σ = k²[D_a e^{−ℓ²k²/2} − D] となり λ* は 4.4 ℓ(D_a ≫ D)〜 6 ℓ
(D_a = 4D)へ動くだけ(初版の creep 併用実験で 5〜6 ℓ が出た理由)。
**spl_zbase**(m)は侵食基準面(崖下が海なら海面)。sd で基準面を与える
方式(sd = z − 0 で岩盤露出として止める)も試したが、土層が 0 に近づいた
セルの地下水容量 sd·sy0 が貯留 hg を下回って地表へ溢れ(calc_wash と同じ
引き渡し規約)、無流水の前提が崩れて発散した(Δx = 0.5 m)。基準面は
地下水と独立に与えるべき量なので別パラメータとした(既定 −9999 = なし)。

**実装**(m_geomorph_splash): init で N = 4(ℓ/Δmin)² パス・重み
w = ℓ²/(2NΔ²)(Δx = Δy で 1/8)を決め、zs・zt(ish:ieh, jsh:jeh)を確保。
eval_splash の先頭で smooth_z: zs = z を N 回 5 点核で更新し**各パスの後に
par_halo_cell(zs)**(N は namelist 由来の静的量で全ランク同一 = collective
安全)。無効な近傍は自セル値で鏡像(κ と同じ規約)、海セルの z は実地形。
- **市松モードの教訓(実検出)**: 初版は w = 1/4(中心重み 0)の核で、伝達
  関数 1 − 2w_x(1 − cos k_xΔ) − 2w_y(1 − cos k_yΔ) が格子の角(市松)で −1 に
  なり、偶数パスで市松が**そのまま保存**されて κ̃ に残り、崖面全体が市松で
  覆われた。核が市松を減衰させるには w_x + w_y ≤ 1/4 が必要で、w = 1/8
  (N を 2 倍)に改めた。平滑化核の伝達関数は必ず非負に設計すること。
- spl_zbase: z ≤ zbase のセルは対象外、fx ≤ z − zbase にクランプ。
- 無効時(spl_lc = 0・zbase なし)は配列確保も計算もなく、既存経路と同一。

**検証(2026-10-19)**:
- 無効時: test/splash・test/splashslide が PASS、examples/badland の旧構成の
  Z9998・Log がビット一致。
- 有効時の MPI: 80 × 60 m・spl_lc = 1 m・zbase = 0 の構成で np = 2, 4 の
  Log.txt・Z9998.txt が逐次とビット一致。gfortran -fcheck=all の np = 2 が
  クリーン完走し Log が一致。
- **test/splashlc(新設)**: 崖縁に 2 波長(4 m・20 m)の正弦擾乱。格子の κ
  では 4 m が ×4.3(20 m は ×2.1)、spl_lc = 2 m では 4 m が ×0.43 に減衰し
  20 m が ×4.9 に成長(ガウス核の伝達 0.007 / 0.82 のとおり)。np = 2, 4 の
  state.dat が逐次とバイト一致。
- **間隔の選択則**(examples/badland の系列。100 × 240 m、白色雑音、c_b = 32、
  拡散項なし): 崖面帯の起伏が 2 m に達した時刻の地形変化 Δz の重心波長は
  ℓ = 1 / 2 / 4 m で 5.4 / 10.1 / 25.5 m(≈ 5〜6 ℓ。理論 4.4 ℓ。ℓ = 4 m は到達
  までに谷の併合が進む)、格子の κ は 3.3 m(≈ 3 Δx、市松)。ℓ が大きいほど
  成長は遅い(σ_max ∝ 1/ℓ²。ℓ = 4 m は 2 m の約 10 倍の時間)。拡散項を
  使わないので初期の白色雑音は減衰せず中立に残り、z そのもののスペクトルを
  汚すため、波長・間隔は Δz から測る。種を変えても統計は同じで位置だけが
  変わる(初版 creep 併用時に確認。Perron & Fagherazzi 2012 の「統計は
  自己組織化・配置は初期条件」)。初版(creep 5e-7 併用)の系列では線形段階の
  波長が ℓ = 1 / 2 / 3 m で 6.4 / 11.5 / 16.1 m と拡散項の分だけ長く、以後
  7〜8 ℓ に粗大化した(上の参考式のとおり)。
- **格子収束**(ℓ = 2 m、拡散項なし): Δx = 0.5 / 1 / 2 m で線形段階
  (T_geo 1.8e6 s)の波長は 9.2 / 10.1 / 11.3 m、平均低下は 5.3 / 4.7 / 2.4 m
  で、Δx = 0.5 と 1 m は一致する(間隔の選択則は格子によらない。
  **ℓ/Δx ≥ 2 が目安**)。しかし谷が深くなってからの発達速度は収束しない
  (最終の平均低下 9.8 / 5.4 / 3.0 m、谷頭の後退 33 / 12 / 1 m)。原因は
  **谷壁の垂直化**: モデルは勾配に上限を持たず谷壁は 1 セル幅の段差になる
  ため、勾配の 99 % 点が 17 / 8 / 4 と Δx に反比例し、S^h の侵食率が細かい
  格子ほど大きい。谷頭の κ̃ も深さ/ℓ² で
  増え続けるので、深い段階の速さは spl_dzmax のクリップが決める
  (dzmax 0.1 / 0.2 / 0.5 m で T_geo 3.6e6 s までは 10 % 以内で一致、9e6 s の
  谷頭の位置は 33.5 / 6.5 / 0.5 m)。安息角崩落 f_repose(φ = 56.3°)を
  重ねる試行(creep 併用時)では勾配は有界(max 1.7〜2.7)になり格子依存は
  縮むが、崩落土砂が谷を埋める(保存形)ため起伏が 1〜2 m にとどまり、鋭い
  稜線の深い谷にならない(固結物質の崖は安息角より急な壁を保つ)。固結物質向けの勾配の飽和
  (S の上限)または Φ_B の飽和形が次の課題(splash_plan.md §8)。

### 48.7 崩落と崖錐 f_rockfall(2026-10-22 実装)

**動機**: examples/mesa で「垂直な崖 + 幅のあるベンチ」が増幅の飽和(§48.6)だけ
では両立せず、崖を急に保つ機構が崖の基部の増幅しかないため。実際のメサの崖は
軟層の掘り込み → キャップの崩落 → 崖錐の保護で垂直面を保ったまま後退する。
「崩落(キャップの落下と崖錐)の機構を入れて試して」(利用者 2026-10-22)。

**設計**: submodule m_geomorph_rockfall(加算フラグ f_rockfall。creep/repose と
同型)。ラスタではオーバーハングを表せないので 3 つの規則で近似する:
(1) 崩落 — 隣接セル間の高さ差(自由面)が限界高さ H_c(rf_hc。構造的な量で
既定なし)を超えた分を、安息角崩落(calc_repose)と同じ数値形(1 更新に
relax·excess/2/8。8 方向の合計 ≤ relax·excess_max/2)で高い側から低い側へ
移す(wrk%q → apply_edge_flux。供給量制限・dzmax クリップ・共動更新を共用)。
(2) 崖錐 — 低い側に移った体積を崖錐の厚さ ht(s%ht。出力 Ht。私有 save
geomorph_rockfall.dat)として積む。ht の収支は apply の発散と同じ式(風上の
fdon を乗じたエッジ流量)で流出(ht から。0 でクランプ)と流入(ht へ)を分けて
求める。崖錐に覆われたセルが供給側のエッジは安息角 φ_t(rf_phi。既定 35°)を
超えた分も動き、1 エッジの移動高さは ht/8 まで(崖錐の分だけ)。(3) 保護 —
崖錐に覆われたセル(ht > 0)の乾式侵食を rf_ftalus 倍(既定 0.3。> 0 を要求)にし、
剥離分を ht から先に減らす(eval_splash / apply_splash)。崖錐の安息角での移動は
h_min(rf_hmin。既定 0.01 m)以上の厚さだけ。崖錐の除去速度が崖の後退を律する。
- 試行の記録(examples/mesa): (a) 「ht > 0 で全面保護」+ rf_ftalus = 0(不侵食の
  崖錐)では、崖錐の再移動で散らばった微量(1e-6 m)が斜面全体を永久に止めて崖の形が
  人工物で変わった → rf_ftalus > 0 を要求し(微量は消耗して消える)、h_min 未満の
  崖錐は動かさない。(b) 被覆率 c = min(ht/h_cov, 1) の線形則(h_cov = 0.2 / 0.02 /
  0.002 m)では、緩和形の崩落が運ぶ到着分(1 更新に 10⁻⁵〜10⁻³ m)が被覆厚に届く前に
  部分被覆のまま削られ、崖錐の総量が常に数 m³(落下量の 10⁻⁴)にとどまった →
  「落下した岩屑は着地セルを覆う」全面保護に戻した。
- H_c はセル間の段差に対する閾値: ラスタでは 20 m の崖も 4〜5 セル幅の 3〜4 m の段の
  列なので、H_c = 18 m では崩落が一度も起きず、H_c = 4 m で段が対象になる(Δx に
  依存する較正量)。→ **窓版 rf_rc(2026-10-22 追加)**: 自由面の高さを nint(r_c/Δx)
  セルの正方形窓内の最低点との落差 H_w で測る(3×3 の min フィルタを npass 回、
  各パスの後にハロ交換 = パス数は静的で全ランク同一)。崖錐の安息角より急なエッジで
  H_w > H_c の超過分を移し、そのエッジの安息角超過を上限にする(内部の平らな
  セルは対象外、崩落は面を安息角より緩くしない)。rf_rc = 0 で従来の規則と
  ビット一致。test/rockfall に param_rc.txt(r_c = 3 m)を追加: 終端で「急なエッジを
  持つセルの窓内落差 ≤ H_c」、体積保存、崖錐の収支、共動更新、MPI np = 2, 4 の
  state.dat 一致。**海セルへの崩落(2026-10-22 追加)**: 供給側が陸で受け手が海セル
  (sw > 0)のエッジも対象にし(海セルは供給側にならない)、apply_edge_flux が海セルの
  z を更新しない性質で落下分を系外へ出す(台帳 vsea。「rockfall exported to sea cells」)。
  海食崖で崖錐が波に除去される極限 = 乾式侵食の排出と同型。test/rockfall に
  param_sea.txt(台地の西壁が海に面する): 陸の体積減少 = 台帳 vsea(相対 1e-4)、
  海セルの z 不変、ほかの検定は同じ。MPI np = 2, 4 の state.dat 一致。窓版
  (rf_rc > 0)の最低点 zmin は s%z から取るので海セルも入るが、海セルの z は
  読み込みで 0(§23.1)、fn_tide ありでは潮位 − hsea0(§47)で利用者は置けない。
  文書は「標高基準を海面 = 0 に取る/fn_tide では窓の下端が潮位 − hsea0」と案内
  (2026-10-22 訂正。旧文「海セルの z を海面に置く」は不可能だった)。
  examples/mesa(README「窓版」の節): Δx = 1 m でも H_c = 15 m・
  r_c = 8 m で崖の面全体が崩落の対象になり、崖錐のリング(1300〜2100 m³。段差規則では
  2 m³)と 30〜40° の崖錐斜面が Δx = 4 m と同じ型で現れる(下の崖 30〜38°、縁の後退
  1.7〜1.9e-7 m/s)。崖錐の総量は格子依存(粗い格子は帯を 1〜2 セルで解像)。保護を
  強くすると台地が崖錐の円錐に近づく = 「垂直な崖 + 崖錐律速」は崩落規則(安息角より
  急な面は崩れる)の帰結として得られず、面の侵食を崖錐の除去に律速させる規則が別に要る。
- **支え方式 rf_fface(2026-10-22 追加。「項目 1: 崖の面の侵食を崖錐の除去に律速」)**:

  またぐ状態 = 私有 save geomorph_rockfall.dat に ht の後ろへ追加。face のみ): 面の頂

  セルがあれば始まり(face_start。前回のフラグで判定 = 評価順に依存しない。colt →

  エッジへ落差そのもの(excess = drop)を落とし、1 エッジ・1 更新の移動は tanφ_t·dist/32
  まで。窓版の崩落 (1') は使わない(崖錐の安息角の規則 (2) はそのまま)。
