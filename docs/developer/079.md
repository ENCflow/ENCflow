## 79. 領域マスク外の計算負荷の削減: 行窓 wy のマスク化とエッジ流量・動的開口表の窓限定(2026-10-15 実装)

### 背景(運用と報告)

全域の共通データセット(例: 日本全域 250 m 格子 6080 × 8960 = 5,450 万
セル)を保持したまま、領域マスク(fn_mask)だけを流域ごとに差し替えて
計算する運用で、「マスクの外接矩形が x, y とも全域の 1/10 程度でも、
計算時間・メモリが全域計算とほとんど変わらない」という報告があった。
これは §0 の「ラスタ純化・単純な入出力」を利用者側で活かす自然な使い方
(前処理で流域ごとに切り出さない)なので、本体側で「毎ステップの負荷を
マスクの窓の面積に比例させる」ことを設計目標に置いた。

### 調査結果(2026-10-15。main の静的読解)

計算範囲を絞る仕組み自体は以前からある: 行ごとの列窓 `g%wx(1:2, j)`
(有効セルとその近傍を含む範囲。calc_wxy)、行窓 `g%wy(1:2)`、帯分割の
全域窓 `dcp%jw1/jw2`(= g%wy)。セルループの大半は
`do j = dcp%js, dcp%je; do i = g%wx(1,j), g%wx(2,j)` の形で、窓の外は
走査しない。しかし次の 4 点が全域サイズのまま残っていた:

1. **`g%wy` が常に 1..ny**(calc_wxy が固定値を置いていた)。時間ループの
   行ループは全行を回り(内側の x 窓が空なので中身は走らないが、
   OpenMP の schedule(dynamic) の配分コストは行数に比例)、MPI の帯分割も
   全行を分けていた。
2. **エッジ流量のコミット(m_swflow_enc `complete`)**: 行 js−1..je の
   `sx%mn(:,:,j) = sx%mn1(:,:,j)` が行の全幅 4 × (nx+1) を毎ステップ複写。
   上の格子・倍精度では 1.74 GB の読み + 1.74 GB の書きが毎ステップ。
3. **動的開口表の構築(`build_fwd`。f_opening_dynamic ≥ 1 で有効。既定は 2
   (2026-10-18 までは 1。1 は fn_rw があるときだけ働く。§68.38))**: 毎ステップ `chn%fwd(:,:,j) = 1.0` を確保範囲の
   全行・全幅で初期化(1.74 GB の書き)し、セル走査も `i = 1, nx`
   (5,450 万セルの fwd_cell 判定)。
4. 任意機能の全幅走査: `curv_prepare`(土石流の曲率項)、`build_cwd`
   (サブグリッド幅の動的通水率)、`m_swflow_enc_sdep_update`(σ 断面の
   D 更新)。いずれも先頭の有効セル判定で cycle するが、走査自体は全幅。

2 と 3 は 1 ステップあたり数 GB のメモリ転送で、有効セル数(1/100)に
比例する本体の計算(数十 ms)を 1 桁以上上回る。報告された「マスクを
小さくしても速くならない」の主因はここにある。メモリ(確保範囲)の方は
逐次版が全域 1..ny、MPI 版が帯±ハロ(§11 第二段)で、x 方向は両者とも
全幅 1..nx のまま(第二段以降。下記)。

### 設計(第一段 = 計算時間。等価変換)

配列の形・添字・入出力を変えず、**毎ステップの走査と転送を窓に限る**
だけの等価変換とした(合否 = 既存 reference とビット一致。規律 2)。

- **wy の定義**: x 窓が空でない行(`wx(1,j) <= wx(2,j)`)の最小・最大。
  wx は近傍 (i±1, j±1) まで見るので、wy = 有効セルの行とその上下 1 行。
  有効セルが 1 つもなければ wy(1) > wy(2)(空窓)だが、直後の n_valcells
  検査(同じ m_geoinfo_init 内、par_decomp_init より前)で停止する。
- **等価性の根拠**: 時間ループの行ループはすべて (a) 先頭で有効セル判定
  (x <= 0 等)により cycle するか、(b) 確保時の値(0 または 1.0)へ書き
  戻すだけ(taxy・td のクリア、fwd の 1.0)である。窓外の行は (a) では
  何も書かず、(b) でも確保時の値と同じ。したがって窓外の行を走査しなくても
  結果は同値。全域窓の端を 1 行縮める定型 `max(js, jw1+1)..min(je, jw2-1)`
  (§11)は、窓の端の行(= 有効セルのない行)を外すだけで、そこでは
  上の (a)/(b) が成り立つ。MPI では帯分割が窓の中で行われ帯境界の位置が
  変わるが、分割位置によらずビット同一(§11 の設計)。
- **mn のコミット列範囲 `edge_row_span(g, j, i1, i2)`**: エッジ行 j の
  スロットはセル行 j(k=4。dje=0)とセル行 j+1(k=1..3。dje=−1)が書き、
  die(k) ∈ {−1, 0} なので、列は各セル行の x 窓を西へ 1 列広げた範囲の
  和集合に収まる。境界条件(boundary_uvmn)・NH 射影・構造物の mn1 書き
  込みも有効セル由来なので同じ範囲。窓外のスロットは mn, mn1 とも書き手が
  なく確保時の 0 のままなので複写不要。**die/dje を変えたら更新**(§11 の
  esync と同じ注意)。
- **fwd**: 全域初期化を廃し、走査する各スロット (:, i, j) を計算の直前に
  1.0 へ戻す。スロット (k, i, j) の書き手は行 j のループの反復 (i, j) だけ
  なので OpenMP の競合はない。走査は行 jlo..jhi の x 窓に限る(書き込み
  条件 fwd_cell(i,j) または fwd_cell(i+1,j) はどちらも窓の中)。窓外・
  行範囲外のスロットは確保時の 1.0 のまま。restore で復元した表のハロ行
  (jsh−1..jlo−1, jhi+1..jeh)は以前は毎ステップ 1.0 に戻していたが、
  読み手(js−2..je+1)の範囲外なので結果に影響しない。
- **任意機能**(curv_prepare / build_cwd / sdep_update)の走査も x 窓に
  限った。先頭の判定(valid / is_channel / screst)は窓外で常に偽。
- **出力への影響(挙動変更ではないが注意)**: 分布ファイルの gather は
  帯 js..je の行だけを全域バッファ(確保時 0)へ写す(§11)。従来は帯 =
  全域だったので、マスク外セルの内部値(例: E = z + 0 = z)が窓外の行にも
  出ていたが、今後は窓外の行は 0 になる(Z0000 も s%z の gather なので
  同じ。埋め込みケースでは Z0000 の窓外 20 行 × 560 列だけが改修前後で
  異なり、それ以外の分布・Log・CSV は同一)。窓内の行のマスク外セルは
  従来どおり内部値。マスク外セルの出力値を一様に定める(0 か nodata か)
  のは別途の判断(§82.1)。回帰テストが比較する Log.txt・CSV には
  影響しない。

### 計測(2026-10-15。gfortran 13 / Ubuntu 24.04、4 スレッド、-Ofast 倍精度)

秩父 100 m ケース(560 × 300、有効 71,486 セル)を、そのまま(small)と、
5600 × 3000 の格子の中央に埋め込んで(big。マスク面積 1/100)30 分
(720 ステップ)計算した。入力は埋め込み以外同一(プローブ・測線は平行
移動)。

| | small | big(改修前) | big(改修後) |
|---|---|---|---|
| 所要時間(30 分 = 720 ステップ) | 14.9 s | 134.1 s | 73.3 s |
| うち初期化(1 分の計算との差分から推定) | ≈ 1 s | ≈ 59 s | 59.4 s |
| 時間ループ 1 ステップ | ≈ 19 ms | ≈ 108 ms | 20 ms |
| 最大 RSS | 83 MB | 7.8 GB | 7.8 GB |

- 改修前の big は 1 ステップ約 108 ms(small の約 5.5 倍)で、上記 2・3 の
  全域転送がそのまま時間になっている。改修後は 20 ms で small と同じ
  (**毎ステップの負荷は窓の面積だけで決まる**という目標を達成)。
- 残る差は初期化の約 59 s(全域の text ラスタ 3 枚 = 5,040 万値の書式付き
  読み込みが大半。bil なら桁違いに速い)と最大 RSS 7.8 GB(確保範囲が
  逐次版で全域 1..ny、x 方向は全幅のため。第二段以降の対象)。
- **結果のビット一致**: big の Log.txt・probes・fluxes・分布ファイルは
  改修前後で同一。small と big の Log.txt・probes・fluxes も同一(埋め込み
  不変性: 窓の外は結果に一切影響しない)。
- 回帰テスト(規律 2・3): reference を持つ全 24 ケースの逐次 Run.sh が
  PASS(等価変換なので identical。chichibu は ULP=1 設定)。自己検証型の
  nest_identity・nest_twin・bmi_nest・bmi_vars・gvchange も PASS。MPI は
  wave・chichibu・tide・salt・coastal_drain・nhbottom の np=1, 2, 4 が PASS。
  確保範囲(MPI の jsh/jeh が窓に従う)に触れるので、-O0 -fcheck=all の
  MPI ビルドで秩父 30 分の np=2, 4 と埋め込み big の np=2 を先に実行し、
  境界検査なしで完走・Log と CSV が逐次 -Ofast と同一であることを確認した。
  トップレベル make(utils の追随)も通る。

### 第二段 (B): 逐次版の確保範囲を全域窓±ハロに(2026-10-15 実装)

par_decomp_init(逐次版)の jsh/jeh を MPI 版 band_range_h と同じ規則
(`max(1, jw1 − nhalo)..min(ny, jw2 + nhalo)`)にした。確保・ダミー引数・
gather/scatter・帯縮小は元から `dcp%jsh:dcp%jeh` で書かれている(単一
ソース)ので本体の変更は 2 行で、「逐次では全域」と書いたコメントを
整理しただけ。可読性は下がらず、逐次だけ別規則という例外が消えた。
窓 = 全行のケース(回帰テストの大半)では従来と同じ確保になる。
埋め込みケース(5600 × 3000、窓 280 行)の最大 RSS は 7.8 GB → 1.8 GB、
所要時間は 73 s → 49 s(全域確保の零埋めが消えた分)、結果は分布ファイルを
含めて同一。残る 1.8 GB は窓の行 × 全幅の帯配列(約 0.5 GB)と rank0 の
全域配列(入力地形 g%z・出力バッファ)、入力読み込みの一時領域で、
x 方向の確保範囲(第二段 (C))の対象。

検証(2026-10-16): -O0 -fcheck=all の逐次ビルドで全ケース(reference 付き
24 + 自己検証型。BMI の 2 ケースは -fPIC なしの試験ビルドでは共有ライブラリが
組めないため release で実行)を走らせ、境界エラーなく完走することを確認した。
同ビルドでは culvert・gwseep(最終桁 1 量子)、tracer・sewer_wq(wq.csv の
台帳 1e-5〜1e-8 相対)、nest_identity の two-way wave・wave_fb3 の
swflow_enc.dat と nest_twin wave が reference / single と一致しないが、
いずれも §79 変更前のコミットを同じフラグで組んでも同じで、-O0 と -Ofast の
丸めの違い(§28.3)。nest の 3 件は検証ドライバ nestcheck・twin だけが
make.inc の -Ofast(FTZ/DAZ)のままだったことによる(2026-10-16 調査。§72
落とし穴。本体とドライバを揃えて -O0 で組めば nest_identity・nest_twin とも
一致する)。release ビルドでは
reference 付き 24 ケースと nest_identity・nest_twin・bmi_nest・bmi_vars・
gvchange がすべて PASS(等価変換 = identical)。同ビルドの -fcheck 実行で
test/nhshelf が m_swflow_enc_nh の slope_coef の範囲外読みで停止する
既存バグも見つかった(本変更とは無関係。同日 §69.5 で修正)。
