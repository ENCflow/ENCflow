## 127. 連行則の改良: Hungr の則(f_dbed = 5)・連行する流動深の下限(db_hent)・取り込んだ質量の運動量(f_dbmom)(2026-11-25。利用者の決定。既定は変えず、無効時はビット一致)

利用者の指示「連行則の改良をしたい」を受け、§126.12 の試作の比較を示して決めた(2026-11-25)。利用者の決定は
「Hungr の則・運動量のスイッチ・流動深の閾値の 3 つを入れる」「例題 snow_avalanche の基本ケースは、運動量あり・
速度比例にする」。速度比例連行 f_dbed = 4 の 2 つの限界(§126.4: 連行できる層を全面に置くと取り込む量が限界水深で
決まる。§126.5: 取り込んだ質量の運動量を数えない)に、選択子で応える。既定(f_dbed・`db_hent = 0`・`f_dbmom = 0`)は
従来のままで、指定しなければ結果は変わらない。

### 127.1 仕様

- **f_dbed = 5(Hungr の連行則)**: 河床(雪面)の低下速度 E = E_r·h_t·|V|(h_t = h + hs。E_r = `db_er`、1/m、> 0 必須)。
  固体の交換量は fx = C*·E_r·h_t·|V|·Δt(f_dbed = 4 の δe を E_r·h_t に替えた形)。連行だけで堆積は f_dbstop、
  連行できる層は sd(可動層クランプ)、C >= db_cmin のセルだけ、は 4 と同じ。massflow.md §3 の「今後の課題」
  (§28.8)の実装で、DAN3D の形(E_t = E·h·v、E = ln(V_f/V_0)/S。GEO Report No. 367 と Qiao ら 2023 の記述で確認。
  Hungr 1995・McDougall & Hungr 2005 の原論文は読めていない)。`db_delte` の正値の検査は、δe を使う 1〜4 だけにした
  (5 は使わない。1〜4 の挙動は同じ)。
- **db_hent(連行する流動深の下限)**: f_dbed = 4・5 で、h_t < db_hent のセルは連行しない(既定 0 = 下限なし)。ほかの
  式(0〜3)で正の値が与えられたら止める。降伏応力の閾値(RAMMS::Extended の既定 300 Pa)を流動深で置き換えた
  独自の簡略化で、換算 τ_c/(ρ g μ cosθ)(密度 300 kg/m³・μ = 0.25 で約 0.4 m)を目安として文書に書いた。応力の
  閾値そのものにしなかったのは、土砂流動モデルの混合密度 ρ(1 + sC) が雪の密度を表さず、応力(Pa)で与えるには
  密度のパラメータを足す必要があるため。
- **f_dbmom(取り込んだ質量の運動量)**: 1 で、侵食・連行で加わった質量を静止から流速まで加速する分を流れから引く。
  calc_debris が、交換の前後の質量 m = h + (1 + s)·hs(水の厚さに換算)の差から、相対的な増加率
  ṁ/m = max(m′ − m, 0)/(max(m, dd)·Δt) をセルごとに `s%dbmr` に書く(侵食 fx > 0 のセルだけ。堆積は 0)。質量の差で
  数えるので、一緒に地表へ出る間隙水(f_dbwet = 1〜3)も含む。次のステップの運動方程式(calc_kth_flux)が、辺の
  両セルの平均を半陰の抵抗に足す(tfe ← tfe − ṁ/m。u ← u/(1 + ṁ/m·Δt) = u·m/(m + Δm))。f_dbed = 1〜5 に共通で、
  f_dbed = 0 と組むと止める。斜面崩壊の流動化(f_slide)と瞬時流動化(fn_dbinit)の質量には掛けない(その場で
  静止して動き出すので、加速は運動方程式がそのまま解く)。

### 127.2 実装で決めたこと

- **流速を直接掛け直さず、抵抗に足す**: 連行の直後に辺の流速 uv を m/(m + Δm) 倍する形は、新しい状態量が要らないが、
  uv のほかに前のステップの流量 mn・書き込みバッファ mn1・セルの流速と流量を同じ倍率でそろえる必要があり、ENC の
  内部状態の扱いに踏み込む。半陰の抵抗に足す形は、calc_kth_flux の抵抗の組み立てに 1 文を足すだけで、無条件に
  安定(ṁ/m·Δt が 1 を超える薄い先端でも u·m/(m + Δm))。連行は 1 ステップ遅れて効く。
- **状態量 `s%dbmr` と私有 save**: 値は前のステップの calc_debris が書くので、リスタートをまたいで同じ結果にするには
  保存が要る。共通の保存形式(state.dat・swflow_enc.dat)は変えず、私有ファイル geomorph_debris.dat に書く
  (契約 5。bedslide・bedmix と同じ型。`f_dbmom = 1` のときだけ。復元で見つからなければ止める)。確保は帯 + ハロ
  (dcp%ish:ieh, jsh:jeh)で、`f_dbmom = 1` のときだけ(init_debris_state)。ハロは、流木の集積 s%wj と同じく
  m_swflow_enc のステップ頭で交換する(復元の直後の 1 ステップ目にも効く)。
- **運動方程式の側**: `emr`(両セルの平均)を、降伏 aye と同じく RK の段の外で 1 回求め、段の中で
  `if (emr > 0.0) tfe = tfe - emr`。土石流が無効(have_db が偽)なら配列の確保の判定にも入らない。
- モジュール変数は足していない(型の成分だけ。Check_modstate の対象外)。

### 127.3 検証(2026-11-25、gfortran 13.3)

- **無効時**: 変更の前後で、土石流モジュールを使う検定 9 本(avalanche・debris・volcano・slide・curvature・dbrock・
  bedslide・splashslide・driftwood)の保存と出力 2,270 ファイルがバイト一致(保存時刻の行だけが違う save_info.txt
  150 個を除く)。CI の回帰テスト 30 本と、夜間の一覧の残り 10 本(coastal_drain・damwq・gwseep・kdpart・sewer_wq・
  splash・tide・wfdoppler・chichibu・chichibu_cond)がすべて PASS(reference と一致)。トップレベルの make(utils を
  含む)が通った(src の警告は 20 件のまま)。
- **新しい検定**(test/avalanche の構成 2〜5。Check_sheet.py): 勾配 0.5 の一様な斜面の一斉発生で、8 秒後の流速・
  流動深が常微分方程式の解に、速度比例・運動量なしで 14.260 / 14.301 m/s・1.752 / 1.759 m、運動量ありで
  9.309 / 9.328・1.433 / 1.438、Hungr の則(E_r = 0.02)・運動量ありで 8.819 / 8.828・1.293 / 1.299(体積の成長
  ln(h_t/D)/E_r = 47.52 m、進んだ距離の解 47.73 m)、流動深の下限 0.6 m で 10.989 / 11.001・0.500 / 0.500(連行なし。
  残りの雪の厚さの変化 0)。固体の台帳は初期の雪の 1e-14 倍以下。構成 3 を 4 秒で保存して復元すると、最後の
  state.dat・swflow_enc.dat・geomorph_debris.dat が通しの計算とビット一致。構成 1 は従来と同じ(成長 1.81)。
  停止・堆積(f_dbstop)を入れたままだと、動き出しの低速の 4 ステップで 2 mm が固定されて流動深が 0.5 % 小さく
