## 127. 田んぼダムの評価機能 m_paddy(fn_paddy): 落水口の装置則とサブグリッドの水田タンク・区画の解像(2026-11-24 設計合意・段 1 実装、2026-11-25 段 2 実装・段 3 例題・段 4 水質と土砂・集水面積率)

設計の正本は docs/paddy_plan.md(検討メモ。文献 29 件の一覧と、確認の程度を含む)。利用者向けは
users_guide/paddy.md(日英)、検定は test/paddy。残りの作業は handoff 00ai。

### 127.1 決定(2026-11-24。利用者の依頼と「全て推奨で進めてください」)

利用者の依頼「田んぼダムの効果を評価できる機能を実装したい。chichibu のような 100〜200 m のマクロなモデルから、
5〜10 m で個々の田んぼを解像するスケールまで、必要な機能と実装方向を検討して」に対し、比較と推奨を示して、
次の推奨案で合意した(paddy_plan.md §9)。

1. **表現は 2 つ**。A = セルの水田面積率のサブグリッドのタンク(20〜200 m)、B = 区画番号ラスタの境の畦畔を
   仮想壁面、落水口を壁の切欠き(出口エッジの装置則)にする区画の解像(5〜10 m)。落水口の装置則と台帳は共通。
   `fn_paddy` 1 つで有効化し、入力(面積率か区画番号ラスタ)で選ぶ。同じ格子では併用しない。
2. **段の順序は A が先**(浅水流の本体に触れないので危険が小さく、chichibu の型のモデルにすぐ使える)。
3. **A の第 1 段は片方向**(浸水が水田に入る流れは表さない。下流の水位は潜りで流出を絞るだけ)。双方向にすると、
   地表水 h(セル全面)とタンク(水田の面積)が同じ水位になったとき貯留を二重に数える(面積率 0.8・畦畔 0.3 m で
   浸水深を約 0.24 m 過小)。正しい双方向化には、水田セルの連続式を開いた面積の割合で割る(河道幅の wfrac と
   同型)必要があり、浅水流の本体に触れる(段 4)。
4. **堰の潜り**は本間公式の形を流量係数で一般化して連続にする: 自由 (2/3)C√(2g)B h1^1.5、h2/h1 ≥ 2/3 で
   √3 C B h2 √(2g(h1 − h2))。C = 0.525 で本間公式(0.35・0.91。§17)に一致する。独自の一般化。
5. 例題は合成地形(段 3)。
6. 名前は fn_paddy・&list_paddy・分布 Hpn/Hpd・台帳 paddy.csv。

方針との突き合わせ: ラスタだけ(方針 2)、鉛直・サブグリッドは概念タンク(方針 5)、有効化は fn_* の有無で無効時は
メモリ・CPU ゼロ追加(方針 7・8)、物理量は直接与え、土地利用からの面積率の集計・区画の平坦化・出口の配置は前処理
(方針 12)、出典・解析解の検定・限界の明記(方針 13)。方針に反する点はない。

### 127.2 段 1 の実装(2026-11-24)

- **構成**: src/m_paddy.f90(装置則・タンク・台帳・保存)、src/list_paddy.f90(&list_paddy を読むだけ。§12)。
  t_paddy を t_encflow の成分に持つ(モジュール変数の状態なし)。fn_paddy を list_sysparam・m_sysparam に足した。
- **呼び出し位置**: init は m_sfm_init の後(VZ・貯留関数の区画との重なりの検査に両者の zr を受け取る)。calc は
  m_sfm_calc の後・地下水の前(swflow の直後の「s%h から取る」結合。VZ・貯留関数と区画が重ならないので順序は結果に
  影響しない)。record は do_recd(集計は collective)、dispose は m_sfm_dispose の後(save は dispose で。契約 5)。
- **雨の回収**: 水田面積率 a のセルで a·pre·dt/gv を s%h から引く(zr_recover_rain と同型)。boundary_h は連続式の
  後に雨を足す(m_swflow_enc_bc.f90 の「降雨を加えて次ステップの水深を初期化」)ので、回収した後の h は
  (1 − a)·pre·dt/gv 以上で負にならない。この前提のため、水田のセルは境界・ソース・構造物のセル(boundary_h が雨の後に
  h を変える)と河道セル(河道幅の wfrac で雨を割る)に置けない(init で停止)。
- **装置則**(paddy_plan.md §5): 円の穴の自由流出の正規化した積分 G(η) は、init で全ランクが同じ演算で表にする
  (η ≤ 4 を 8192 区間。各点は u = (1 − cos θ)/2、θ = θm(1 − v²) で端点の特異性を除き、複合 Simpson 256 区間)。
  η > 4 は (π/4)√s(1 − 1/(128 s²) − 20/(65536 s⁴) − 140/(4194304 s⁶))(s = η − 1/2)。展開は
  √(s − v) の偶数次の項を円の重みで積分したもので、η = 4 で表との差は相対 2×10⁻⁸。
- **陽解法の上限**: 1 ステップの落水は「流れ始める高さまでの貯留」と「下流との水位差の半分を埋める量
  0.5(H − h_D)/(1 + a/gv)」で上限する(§68.29 (C') の堰越流の追い越し禁止と同じ考え方)。
- **台帳**: 雨・落水・越流・減水深の累積は行ごとの部分和(real64。行は 1 つのランクだけが持つ)を毎ステップ足し、
  記録時に par_sum_rows で集める(ランク数・スレッド数によらない)。累積は計算開始・再開から(蒸発散の
  evap.csv と同じ扱い)。S の台帳は s%pdv(セル面積基底の貯留)を calcstat が別ループで足し(無効時は何もしない)、
  printstate が S(S_surf)と S_total に加える。
- **状態と保存**: s%hpn・s%hpd(その種類の水田がある格子だけ確保)と s%pdv は fn_paddy のときだけ確保。保存は
  私有ファイル paddy.dat(版 2026112401・格子・種類の有無 + m_restart の restart_write_cell)。無効なのに paddy.dat が
  残っていれば再開を停止する(§16.2 の門番と同型)。
- **併用の停止**: ENC のみ、ネスト・水質・淡塩とは停止。水田のセルは海・河道・境界・ソース・構造物・VZ と貯留関数の
  区画のセルに置けず、面積率は空隙率 gv を超えない(rank0 が全域で見つける誤りは rank0 の値を全ランクへ
  allreduce してから、帯で見つける誤りは誤りの種類とセルを 1 つの整数にまとめた allreduce の最大で、どちらも
  collective に par_stop)。
- **既定値**(param_default で "(default)" 付きで表示。出典は users_guide/paddy.md の根拠の表): 区画 3000 m²・畦畔
  0.30 m・減水深 5 mm/d・水位調整板 0.03 m × 0.30 m・穴 φ50・三角 60°・係数 0.6(農林水産省の手引き 2026 の例と
  水田流出簡易計算プログラムの既定)。型の既定は種類 1 = 0、種類 2 = 1。事前の湛水深の既定は種類ごとの流れ始める高さ。
  装置の既定は、その種類の水田がある格子でだけ表示する。

### 127.5 雨滴侵食から水田の部分を外す(2026-11-24。利用者の決定)

paddy_plan.md §12.4 の 2(段 1 の小修正)。利用者の決定「雨滴浸食は早めに外す」(paddy_plan.md §12.5)で、
ほかの連携より先に入れた。

- **内容**: 地形変化(fn_geomorph)と併用するとき、m_paddy_init が水田面積率 a = fr1 + fr2(セル面積基底)を
  s%pdfr に置き(確保はこのときだけ)、m_geomorph_wash の雨滴の項 k_r·P と、m_geomorph_splash の E(雨滴の項・
  リルの項とも P に比例)に 1 − a を掛ける。根拠: 水田の上の雨は m_paddy がタンクへ回収し、地表の水 h に届かない。
  湛水は雨滴の飛沫による侵食をほぼ止める(Nouhou Bako et al. 2016。paddy_plan.md [34])。タンクが空でも外す
  (独自の簡略化)。a はセル面積基底なので 1 − a とした(家屋の面積は、既存の侵食と同じく区別しない)。
- **変えないもの**: 面状侵食の項・浮遊砂の巻き上げ・掃流砂(段 1 では地表の水がセル全面に広がるので、流れの侵食も
  セル全面。二室化(paddy_plan.md §12.3・§13)で見直す)と、溶食(f_dissol)の水量。タンクは土砂を運ばない。
- **無効時**: s%pdfr は未確保で、ループの外で allocated を 1 回見るだけ(pdx)。pdx が偽なら式に触れない。
- **検証**: test/paddy に param_wash.txt(湿った斜面の侵食の雨滴の項だけ。浮遊砂の沈降を susp_wf = 1e-30 で
  事実上止め、地盤の下がり = 侵食の積算)と param_splash.txt(Green-Ampt で全セルが乾いたままの、乾いた斜面の侵食の
  雨滴の項だけ)を足した。列ごとの a = 0〜1 の全セルで z − z0 = −(1 − a)·k·P·T が、地盤高を単精度で書き出す丸めの
  範囲(相対 4.7×10⁻⁸・2.7×10⁻⁸)で一致し、a = 1 のセルは侵食なし。修正前のビルドでは不合格(水田の部分も削れる)
  になり、検定が修正の有無を見分ける。MPI np = 1・2・4 で合格し、地盤高(Z0001.bil)・paddy.csv・Log.txt が np = 1 と
  バイト一致。-Og -fcheck=all でも 2 つの検定が合格し、np = 2 が debug の逐次とビット一致。
- **無効時の一致**: f_wash・f_splash を使う既存のケースを、変更前(HEAD の worktree)と変更後の同じ release のフラグの
  ビルドで回し、全ファイルがバイト一致した(wash・splash・splashsat・splashstrata・wetlw の 2 つ・rockfall の param_uc の
  7 構成と、入力を Run.sh・make で作る splashlc・splashslide・stencil9 の 3 件。計 443 ファイル。保存の見出し
  save_info.txt の時刻の行だけが違う)。


### 127.6 双方向(二室化。f_pd_exchange = 1)の実装(2026-11-24。利用者の決定「全て推奨で進めてください」)

設計と合意は paddy_plan.md §13(§13.9 が合意の記録)。手順 0 の MPI の実バグは §128 で、σ の関数の準備(床の割合 f)は
§26.3 の等価リファクタで、それぞれ別のコミットにした。

- **入力**: `f_pd_exchange`(0 = 片方向。既定、1 = 双方向。list_paddy・m_paddy の setup_scalars。既定は
  "(default)" 付きで表示)。
- **断面の登録**: m_paddy_init の setup_twoway が、水田のセルに遷移深さ D = 畦畔高・床の割合 f = 1 − a/gv の
  階段形の σ を、m_swflow_enc の新しい手続き m_swflow_enc_set_step_sect で登録する(帯 + ハロ。河道の σ がない
  計算では sct の配列をここで作る。D は河床変動に追従しない = screst を持たない)。登録の最後に update_af
  (§128 のハロ交換を含む collective)。貯留・面の流束(u·vh)・過大流出の上限・ルンゲクッタ・物質の濃度・浅水流の外
  との体積での受け渡し・貯水量の台帳は、既存の σ の経路がそのまま働く。
- **1 ステップ**(calc_twoway。片方向のコードとは別の手続きで、片方向の演算列は変えていない): (1) 雨の回収を
  矩形換算水深で(sect_vh・sect_h_of)、(2) 落水口は両向き(水位の高い側を上流として dev_q。上限は水位差の半分を
  両側の貯留(タンク a、地表 gv·σ(h))で)、地表の水位が畦畔高以上なら落水口のやり取りはしない、(3) 畦畔: タンクの
  畦畔高を超えた分は地表へ、地表の水位が畦畔を越えたら畦畔より上の地表の水 gv·(vh − vh(D)) で満ちていない水田を
  瞬時に満たす(足りなければ空きの比)、(4) 減水深。地表へは vh の正味の変化で戻す。
- **検討の途中で直したこと**: 初版は「タンクと地表がともに畦畔高以上」のときだけ落水口を止めていた。外水の検定で、
  減水深で湛水深が畦畔高をわずかに下回ると毎ステップ落水口から流入して越流で戻る空回り(流入・越流の台帳が数千 m³ に
  膨らむ。水は保存)が出たので、地表の水位が畦畔高以上なら止めるようにした(水田は (3) で満ちる)。
- **台帳と保存**: paddy.csv の末尾に inflow(落水口からの流入)・levee_in(畦畔を越えた流入)の列を足した(片方向では
  0。残差の式も流入を数える。片方向の値は x − 0 で変わらない)。qsurf は正味の値(双方向では負になりうる)。
  paddy.dat の見出しにやり取りの方式を足して版を 2026112402 にし、保存時と方式が違えば停止する。
- **停止**(setup_twoway): 家屋破壊の空隙率の帰還(s%gv_active)、浮遊砂(s%sed_active)、非静水圧
  (m_swflow_enc_nh_active)、ため池のセル(rscap > 0)、水田でない面積の割合 1 − a/gv < 0.05。帯で見つける誤りは
  誤りの種類とセルを 1 つの整数にまとめた allreduce の最大で collective に止める。
- **検証**(test/paddy に追加。reference 非依存):
  - param_tw_back.txt(落水口からの逆流): 同じ陽解法の参照解(階段形・両向きの装置則・上限を 1 区画で解く)と
    相対 8.9×10⁻¹⁶、S の保存、平衡の水位 0.06 m。
  - param_tw_fill.txt(畦畔を越える浸水での瞬時の満水): 湛水深 = 畦畔高、地表の水深 0.338 m、畦畔を越えた流入
    1296 m³(理論値)、S = 一体の水の水深(二重計上なし)。
  - param_tw_flood.txt(外水の流入): S の増分 + 減水深 = 流し込んだ外水 0.9 m(差 8.3×10⁻¹⁴ m)、終わりに全て満水。
  - param_tw_drain.txt(浸水が引いた後): 湛水深 ≤ 畦畔高で単調に下がり、通常の落水口(12 h で 60 mm)が田んぼダム
    (262 mm)より速い。
  - 保存 → 再開(tw_drain を 6 h で保存し 12 h まで)が連続計算とビット一致。停止 5 種(水田でない面積の割合・
    ため池・浮遊砂・非静水圧・方式の違う再開)。既定値の構成に `f_pd_exchange = 0` を明示しても既定とビット一致。
  - 片方向の reference(param.txt の Log.txt)は release で一致(機能を足した後も片方向の結果は変わらない)。

### 127.8 区画の解像(表現 B。fn_pd_plot)の実装(2026-11-25。利用者の指示「その他は推奨で進めてください」)

設計は docs/paddy_plan.md §14(推奨案のまま実装)。5〜10 m の格子で区画をセルの集まりとして解き、畦畔を仮想壁面、
落水口を壁の切欠き(装置則)として浅水流のエッジを上書きする。区画の湛水は h そのもので、新しい状態量はない。

**入力**(&list_paddy): `fn_pd_plot`(区画番号。0 = 水田でない、整数 ≤ 2²⁴ − 1。単精度の実数で読んでも正確な範囲)、
`fn_pd_outlet`(出口セルに向き 1〜8。浅水流の din/djn と同じラスタの並び)、`fn_pd_class`(区画のセルに種類 1・2。
未指定は全て 1)。`fn_pd_plot` を与えると B(m_paddy の `pd%rep = 1`)。A だけの入力(面積率・取組率・代表区画面積・
f_pd_exchange)との併用、B なしの `fn_pd_outlet`・`fn_pd_class` は停止。

**浅水流の本体**(m_swflow_enc と submodule m_swflow_enc_channel):

- 状態は変数群 chn の成分(have_pwall、帯 + ハロの pid・pod・pcl・pzl、装置 pdev(1:2)・円の表 pgt)。chn ごと
  文脈の付け替え・dispose に乗るので、群を増やしていない(Check_modstate.py の対象外の追加なし)。装置の型は葉の
  モジュール m_paddy_law から(§127.7。本体 → m_paddy の逆向きの依存を作らない)。
- 登録 `m_swflow_enc_set_plot_walls(g, pid, pod, pcl, hlev, dev, gt)`(公開。m_paddy の init が呼ぶ): pzl = 初期の
  地盤 g%z + 畦畔高(区画のセル)/ g%z(ほか)を作り、落水口のエッジを帯で検査し(通過幅ゼロの対角 skip8・堤防の壁
  との重なり・天端より高い先は collective に停止)、セルの壁エッジの本数 nwall(堰の追い越しの上限 cap_overshoot の
  分母。§68.29 (C'))に畦畔・落水口のエッジを足す。nwall は堤防がなくてもここで確保し、堤防の壁と重なるエッジは
  bank_init が数えたので足さない(和集合)。数える行は bank_init と同じ jsh..jeh(使うのは js−1..je+1)。
- 述語 `pwall_kind`(静的。pid・pzl・g%z だけ): 区画番号が違う 2 セルの全エッジが畦畔(落水口なら種類 2)。区画番号が
  同じ 2 セルの対角でも、両脇の 2 セルが同じ別の区画(> 0)なら畦畔(市松の角。区画のくびれを横切る流れを止める。
  両脇も両端も区画なら両方の対角が壁になり、くびれでつながる区画は 2 つに分かれる)。天端は両端(市松の角は 4 セル)の
  pzl の最大、天端が両側の初期の地盤以下なら壁でない(is_wall と同じ考え方)。区画の水が出入りするのは区画のセルを
  端に持つエッジだけなので、これで区画は水密(検定 b_tight)。
- 上書き `pwall_apply`(calc_kth_momentum の seawall_wall の後、pwall_kind > 0 のエッジだけ): 畦畔は bank_weir_flux
  (本間公式。中心を堤内地側の引数、向きの符号 +1)、落水口は畦畔の越流に装置則の流量 Q を足す。装置則の基準は出口セルの
  初期の地盤、水位の高い側を上流として dev_q(H = 上流の水位 − 田面、h_D = 下流の水位 − 田面)。単位幅流量は
  Q/(l8(k) × frw × fwd)(連続式と測線で Q がちょうど移る)、流速は単位幅流量/max(上流の水深, dd)。上限は
  cap_overshoot と同じ式(nwall は和集合)。その後の過大流出の抑制・連続式は既存のまま。
- 適応ルンゲクッタの判定から外す(wall = pwall_kind > 0。堤防の壁と同じ理由。§68.29 原因 2)。堤防の壁のエッジは
  bank_edge が先に立つので pwall_kind を呼ばず、bank_wall が天端を max(堤防の天端(破堤後を含む), 畦畔の天端) に
  する(区画のセルが堤防のある河道セルに接するとき。破堤しても畦畔は残る)。無効時(have_pwall = .false.)の追加は
  整数 1 つの初期化と比較だけ。
- 海・海側との重なり、開いた境界面(格子の外周)は区画のセルの置き場所の検査で排除する(rivermouth_drop・
  seawall_wall・開境界と干渉しない)。非静水圧は B と停止(壁を非静水圧の補正から外す除外を入れていない)。

**m_paddy**(init_plots・setup_plots・calc_plots・plot_rows・plot_store): rank0 が 3 つの分布を全域で読み、整数・
範囲・区画のセルの置き場所(海・河道・境界・ソース・構造物・外周・海の隣)・区画の中の種類の一致(8 近傍の同じ番号)・
落水口(区画のセルの上、領域の中の有効なセルを向く、同じ区画でない、向かい合わない)を検査し、par_scatter_cell_i で
帯 + ハロへ配る。帯の検査はため池・VZ・貯留関数の区画・海側(ssw)の隣。区画番号の数・落水口のない番号の数を画面に
出す(rank0 の全域の配列を整列して数える)。事前の湛水深は新しい計算の開始で区画のセルの h を max(h, h0) に(帯 +
ハロ。全ランクが同じ規則)。毎ステップ(浅水流の後)、区画の境のエッジの確定した流量を測線と同じ観測口
m_swflow_enc_edge_flux で読んで台帳(落水口と畦畔、出と入り)に積み、減水深を h から引いて e を回復する。台帳 paddy.csv は
A と同じ列(意味は利用者ガイド)。区画どうしの流れ(田越し)は出る区画の流出と入る区画の流入の両方に数えるので、全区画の
残差は閉じる。S の台帳(pd_active)・Hpn・Hpd は使わない。paddy.dat はヘッダに表現の印を足した(save_version
2026112402 → 2026112501。A のタンクの面は今までどおり)。B はヘッダだけを書き、A と B を取り違えた再開・B を無効に

**併用の停止**(B の初版): A と同じ(ENC のみ・ネスト・水質・淡塩)に加えて、地形変化(掃流砂が畦畔を越えない除外

### 127.9 例題 examples/paddy_dam(段 3。2026-11-25。利用者の指示「その他は推奨で進めてください」)

設計は docs/paddy_plan.md §15。合成地形の低平地の排水区(630 m × 960 m、152 区画、排水機場のポンプだけで域外へ)に
一様な雨 207 mm/24 h を与え、10 m の B で落水口の 4 通り(N・D・Du・Dd)と、同じ地区を 30 m の A で片方向・双方向 ×

**作る途中で変えたこと**:

- **格子**: §8 の 5 m は B の 1 ケースが 2 時間を超える見込み(dt 0.5 s)だったので 10 m・dt 1 s にした(区画の幅 3
  セル = B の下限。開発の 4 コアの VM で 2 スレッドの 2 ケースを並べて 1 ケース 20 分前後。30 m の A は 2 分前後)。
- **支線排水路の位置**: 30 m のセル(3 × 3)に支線排水路と区画が同じセルに入ると、A で河道のセルと水田のセルを

- **農道の高さ**: 初めの農道(田面 + 0.25 m)は畦畔の天端(田面 + 0.30 m)より低く、区画の端の畦畔の壁は天端 =
  田面 + 0.30 m で働くが、農道に降った雨と農道を越える流れが西の区画に入って、区画の貯留を見誤らせた。農道を
  田面 + 0.45 m に上げて全ケースを回し直した(天端が両側の地盤以下のエッジは壁にしない規則(§127.8)により、農道と
  区画の間は地盤の段差として流れる)。それでも農道と台地に降った雨の一部(約 1.1 万 m³)は隣の区画に入り、

**教訓**:

- 閉じた排水区の浸水は、排水路の水位が集落の地盤を越えるかのしきい値で決まるので、田んぼダムの効果は取組率に
  比例しない(半分の取組は 0.10〜0.18 m の低下、全ては浸水なし)。
- 取組の位置: この地区では上流側の半分のほうが効いた。24 h に Du の通常の区画(下流側)は 93 mm を貯めていたのに、
  Dd の通常の区画(上流側)は 73 mm まで抜けていた。下流側の区画は排水路の水位で落水が自然に絞られ(Du の逆流
  1,031 m³)、田んぼダムを足す効果が小さい。
- 双方向の A は、落水口からの逆流(1.37 万 m³。B は 1.15 万 m³)と水田の平均水深(最大 143 mm。B は 135 mm)を
  B に近く表した。片方向は地表の水が水田の部分の上にも広がるので浸水を低く出した(ユーザーガイドの限界のとおり)。
- 田んぼダムでの B と A の違い(B は浸水なし、A は浸水)は、30 m で表さない 2 つの経路による: 10 m の小排水路の
  貯留(田面より下に約 1.36 万 m³。実際の幅 1〜2 m の 5〜10 倍)と、農道・台地の雨が区画に入って田んぼダムに
  貯まる経路。田んぼダムで浸水を防げるかの判定はこの表し方に敏感で、README の限界に書いた。

**確かめていないこと**: 小排水路を河道のセル(サブグリッド幅 1〜2 m)にした B(落水口が堤防のない河道セルを向く
経路。§127.8 で確かめていない経路の 1 つ)、流域スケールの補足(手引きの概算式との比べ)。handoff 00ai に残した。

**README の書き直し(2026-11-25。利用者の指摘)**: 「10 m の B と 30 m の A」のような書き方では、同じ地区を 2 つの
表現で解いていることが伝わらないとの指摘を受け、表し方を全編で「表現 A(Δx = 30 m)」「表現 B(Δx = 10 m)」と書き、

### 127.10 水質との併用(段 4a。2026-11-25。利用者の指示「その他は推奨で進めてください」)

設計は docs/paddy_plan.md §16.1(物質を決めない汎用の形。利用者の決定 §12.5 の 3)。水を動かすモジュールが同じ割合で
物質を動かす既存の契約(取水・ポンプ。§30.10)に合わせ、m_paddy が水の移動と同時に物質を動かす。

**状態と契約**(m_state。全て m_paddy_init が水質の有効なときだけ確保。m_wq_init が先に走って s%wq_active を立てる):

- `s%cpn`・`s%cpd`: 種類ごとのタンク(A)の物質のプール(g/m²。セル面積基底 = ため池の crs と同じ)。濃度は
  cpn / (fr1 · hpn)。その種類の水田がある格子だけ。
- `s%pdfa(:,:,1:2)`: 種類ごとの水田面積率(A)。m_wq が水田の上の雨の物質をプールへ入れるのに使う。**設計からの
  変更**: 設計は s%pdfr(雨滴侵食の合計の面積率。§127.5)を種類ごとにする案だったが、地形変化の既存の契約を
  変えないよう、水質のときだけの別の配列にした。
- `s%fmpd`: 減水深で系外へ出た物質(g/m²。セル面積基底。A・B とも)。m_paddy が足し、m_wq が台帳(vrow の 22 列目)に
  積んでゼロに戻す(fxr と同じ「記録して読んでゼロに戻す」契約)。

**m_paddy**:

- 片方向(m_paddy_calc): tank_step の後に pool_move が、雨を足した後の湛水深 h1 から落水 + 越流の割合
  (dv + sp)/h1 の物質を地表へ(cq += msur / gv。cq は h と同じ基底)、残りから減水深の割合を fmpd へ動かす。
- 双方向(calc_twoway): 水と同じ順に、落水口(タンク → 地表はタンクの濃度、地表 → タンクは地表の濃度 cq / vh。
  vh は階段形の断面の体積)、越流(タンクの濃度で地表へ)、畦畔を越える満水(地表の濃度でタンクへ)、減水深
  (タンクの濃度で fmpd へ)。
- B(calc_plots): 減水深 pc に cq · min(pc / h, 1) を同伴させ、fmpd へ(× gv でセル面積基底)。
- 事前の湛水の濃度 `pd_wq_c0`(list_paddy。mg/L。既定 0。水質が無効なのに与えると情報を出す): A はタンクの初めの
  プール = c0 · h0 · fr、B は pd_h0 まで満たした水の分を cq に足す(初期条件の地表の水の濃度は wq_c0 のまま)。
- 保存: paddy.dat のヘッダに水質の印を足し(8 語。版 2026112502)、A はタンクの後にプールを m_restart で書く。
  保存したときと水質の有無が違う再開は停止する。paddy.csv に種類ごとの平均濃度 c1・c2(物質の総量 / 水の総量。
  A はタンク、B は区画のセルの水)を足す(水質のときだけ)。
- fn_paddy と fn_wq の併用の停止(check_combinations)を外した。

**m_wq**:

- 雨の物質: pdfa のあるセルでは、地表へは (1 − a1 − a2) の分だけ、プールへ a1・a2 の分を入れる(台帳の in_rain_g は
  セルの全部のまま)。m_wq は m_paddy の後に走るので、m_paddy の雨の回収は水だけを動かす(そのステップの落水の濃度は
  雨の水の分だけ薄い。1 ステップの分割の誤差)。
- プールの一次減衰(fdec。decay_g へ)と単相の沈降(wq_vs だけ。湛水深 hpn・hpd で割る。settle_g へ数え、
  f_wq_settle = 1 でも表面蓄積プール bp には入れない = 消失)。wq_kd の二相分配はプールでは扱わない。
- wq.csv: 田んぼダムを指定した計算(fn_paddy が空でない)だけ、末尾に mass_paddy_g(プールの現在質量)と
  out_paddy_perc_g(減水深の持ち出しの累積)を足す。指定のない計算の wq.csv は 1 バイトも変えない(既存の水質の
  reference を保つ)。

**既知の簡略化(既存)**: m_wq の初期濃度は柱状量 = wq_c0 × h(矩形の換算。m_wq_init の時点では断面の σ がまだ
ない)なので、双方向の水田のセルに初期の水深と wq_c0 を与えると、初めの地表の濃度は wq_c0 × h / vh になる

### 127.11 土砂との併用(段 4b。2026-11-25。利用者の指示「その他は推奨で進めてください」)

### 127.12 双方向の水田でない面積の割合の下限を 0.01 に(2026-11-25。利用者の問いと「全て推奨で進めてください」)

**問い**: 例題 paddy_dam の水田面積率の頭打ち 0.95 は双方向のためとあるが、0.99 などは駄目か。

**事実**: 0.95 は、双方向の水田のセルに求めていた「水田でない面積の割合 s = 1 − a/gv ≥ 0.05」(pd_smin。§127.6、
paddy_plan.md §13.4。独自の目安)に合わせた値で、数値計算の限界ではなかった。下限を 0.01 にした試しの版で例題の
双方向(30 m)を頭打ち 0.99 で解くと、正常に終わり、クーラン数(0.24。0.95 で 0.25)・計算時間・水田の収支の残差
(1.4×10⁻⁷ m³)は 0.95 と同じ程度だった。s が小さくても、σ の階段形の断面の波速は √(gh) のままで CFL を悪くせず、
落水口のやり取りは陽解法の上限(両側の貯留で水位差の半分)で行き過ぎない。

**決定**: pd_smin を 0.05 から 0.01 に下げる(起動時の停止を緩めるだけで、これまで動いた計算は 1 ビットも変わらない)。
0.01 も独自の目安で、落水口から出る水の行き場(セルの水田でない部分)を残すためのもの。面積率は畦畔・農道・水路を
除いた田面の割合を与える(ユーザーガイド)。下限を入力にする案は、物理的な意味の薄い設定が増えるので採らない。

**検定**: 停止の検定 tw_smin は面積率 1.0(s = 0)のセルを持つ frac_mix.txt を使うので、引き続き停止する(下限の値を
含む文言「below 0.01」)。test/paddy の逐次の全検定が合格し、reference の Log.txt と一致した(停止を緩めるだけで、
これまで動いた計算は変わらない。MPI の経路には触れない)。

**例題への反映**(examples/paddy_dam。利用者の指示「全て推奨で進めてください」): 水田面積率の頭打ちを 0.95 から
0.99 にした(表現 B の区画は畦畔を厚さのない壁にした面積なので、1 に近いほど B にそろう)。あわせて、利用者の問い
「農道・台地の雨が区画に入る経路の問題は、ユーザーが考慮・対処する方法はあるか」に答えるため、水田へ流れ込む面積
(集水面積)を面積率に足した双方向のケース A30_N2c・A30_D2c を足した。集水面積は make_district.py の catchment() が
10 m の地形でたどる(区画でも排水路でもないセルから 8 近傍の最急の下り。区画のセルは畦畔の天端を高さとする。区画に
着いたら、着いた区画を含む 30 m のセルの面積率に足し、0.99 で頭打ち。独自の簡略な前処理で、浅水流の分流は表さない)。
4.39 ha(農道 304 セル・台地 135 セル)が区画へ流れ込み、3.75 ha を面積率に足した(0.64 ha は頭打ちで足せない)。
表現 B の入力と結果は変わらない。

結果(集落の最大浸水深 m / 排水機場の前の最高水位 m。集落の地盤 0.185 m):

| | N | D |
|---|---|---|
| 表現 B | 0.510 / 0.695 | 0.011 / −0.094 |
| 表現 A 片方向 | 0.439 / 0.624 | 0.006 / 0.181 |
| 表現 A 双方向 | 0.524 / 0.709 | 0.070 / 0.255 |
| 表現 A 双方向・集水面積を足す | 0.515 / 0.700 | 0.004 / 0.008 |

頭打ち 0.95 のときは、片方向 0.442 / 0.628(N)・0.080 / 0.265(D)、双方向 0.537 / 0.722(N)・0.163 / 0.348(D)。

**教訓**:

- 浸水の判定はしきい値に近い: D の表現 A の最高水位は集落の地盤の前後にあり、頭打ちの 0.95 → 0.99(水田 +1.4 ha、
  水田の上の雨 +0.3 万 m³)で、双方向の浸水深は 0.163 → 0.070 m、片方向は 0.080 → 0.006 m に変わった。§127.9 の
  訂正では頭打ちの影響を量(0.35 万 m³)だけで書いたが、判定への影響は大きかった。
- 片方向が表現 B に近く見えるのは打ち消し合い: 片方向は地表の水をセル全面に広げるので、15 h に水田のセルの上に
  1.0 万 m³(双方向は 0.35 万 m³)が留まり、農道の雨が区画に入る経路がない分を埋める。15 h に支線・幹線排水路の外に
  ある水は、片方向 9.10 万 m³、表現 B 9.13 万 m³、双方向 8.72 万 m³。片方向に集水面積を足すと効きすぎる(D の最高水位
  −0.185 m)。
- 集水面積を足した双方向が N・D とも表現 B に最も近い(D の 15 h の水田の貯留 8.91 万 m³ 対 表現 B 8.92 万 m³)。
  副作用(タンクの面積と落水口の数が増え、穴の落水口の流出が √(1 + 0.083) ≈ 1.04 倍)は README の目安と限界に書いた。
  雨を受ける面積を貯留の面積と分けて与える入力は拡張の候補として handoff 00ai に残した。

### 127.13 A の集水面積率 fn_pd_catch(段 4c。2026-11-25。利用者の問いと「推奨で合意します」)

**経緯**: 例題 paddy_dam では、表現 A と B の差の主因は、区画より高い農道・台地の雨が畦畔を越えて区画に入る経路
(表現 B で 1.07 万 m³)が A にないことだった(§127.9 の訂正・§127.12)。面積率にこの面積を足す近似(例題の
A30_*2c)で A は B に近づいたが、タンクの面積と落水口の数も増え(湛水深 −7 %、穴の落水口の流出 +4 %)、水田だけの
セルには頭打ちで足せない(0.64 ha)。利用者の問い「この経路を利用者が考慮・対処する方法はあるか」に答えて、雨を受ける
面積を貯留の面積と分けて与える入力を提案し(paddy_plan.md §17。案 1〜5 の比べ)、推奨案に合意を得た: 名前は
fn_pd_catch、地形変化の雨滴侵食との併用は初版で停止、片方向でも使える、例題の A30_*2c を置き換える。

**実装**:

- list_paddy に fn_pd_catch。m_paddy の setup_maps で rank0 が全域で読み、0 ≤ c ≤ 1 と「c > 0 は a > 0 のセルだけ」を
  検査して帯へ配る(par_scatter_cell。pd%fc は与えたときだけ確保)。帯の検査で a + c ≤ gv。B とは a_only で停止。
- 雨: 片方向・双方向とも、回収を (a + c)·pre·dt/gv、タンクの雨を rk = rain·((a + c)/a) にした。(a + c)/a を先に
  計算するので c = 0 でちょうど rain になり、与えないときは分岐で rk = rain(式を変えない)。
- 水質: s%pdfa を (a + c)/a 倍にした(m_wq は変えない。集水面積の雨の物質も水と同じ割合でプールへ)。雨滴侵食の

### 127.15 集水面積の雨を 3 × 3 の近傍のタンクへ配る(2026-11-25。利用者の問い「推奨は？」と「推奨で進めてください」)

**経緯**: §127.14 の切り分けで、集水面積率の「同じセルのタンク」の決まりは、区画が 30 m のセルの境をまたぐ所で
集水面積の雨を一部のタンクに集めて越流を多く出し、例題 D の表現 A と B の差の最大の要因(約 −0.17 m)だと分かった。
利用者に、近傍へ配る形を fn_pd_catch の決まりそのものにする(切り替えは作らない。fn_pd_catch は入れたばかりで
まだ使われていない)ことと、例題の入力を直すことを勧め、合意を得た。設計は paddy_plan.md §17.1。

**実装**:

- m_paddy の setup_catch(起動時): 雨の降るセル m の係数 c_m/A_m を帯で求める。A_m は m を中心とする 3 × 3 の
  セルの水田面積率の和で、配布済みの帯 + ハロの面積率を固定の順に足す(確保範囲は全域の端だけで切れるので、
  ランク数によらない)。c > 0 は a > 0 のセルだけ(§127.13 の検査)なので A_m ≥ a_m > 0。
- catch_spread(毎ステップ。片方向・双方向の先頭。collective): w = pre·dt·c/A_m を帯で求めて par_halo_cell で
  交換し、水田のセルが受ける水深 s%pdcr = Σ_{3×3} w を行、列の順に足す(pre はハロの行で計算されていない)。
  タンクの雨を rk = rain + s%pdcr にした(§127.13 の rain·(a + c)/a を置き換え)。地表から回収する (a + c)·rain/gv
  と台帳の catch は雨の降るセルのまま。
- 状態: s%pdcr(fn_pd_catch のとき)と s%pdfc(fn_pd_catch と水質のとき)を m_state に足した。
- 水質(m_wq の雨の物質): s%pdfa を f_k に戻し(§127.13 の (a + c)/a 倍をやめた)、地表に残す割合を
  1 − a − c(s%pdfc)にして、配られた雨の物質 濃度 × s%pdcr × f_k を受けるセルのプールへ入れる(そのセルの雨が
  0 でも)。s%pdcr = 0 のセルは足さないので、集水面積率 0 の分布は与えない計算とビット一致のまま。
- 停止のメッセージ(水田のないセルの集水面積)の括弧書きを新しい決まりに合わせた。入力・検査・出力・paddy.dat は
  変えない(版はそのまま)。
