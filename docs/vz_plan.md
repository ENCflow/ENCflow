## 1. 結論(要約)

1. **方針 5 と衝突する**。鉛直を 1 次元 Richards 式で解くのは「鉛直方向の
   プロセスは抽象化・概念化して簡便に実装」(§0-5)の外にある。実装の前に、
   非静水圧(§69)と同型の**限定的な例外**を方針に足すかを決める(§2.1)。
   推奨は「少数の共有参照柱に限る」例外。
2. 例外を認めるなら、親設計の骨格(共有柱・VZ 区画・明示的な出口・保存的な
   深さ補間・`hg` と別の所有・無効時ゼロコスト)は ENCflow の型にそのまま
   乗る。独立モジュール **m_vzflow(fn_vz で有効化)** とする。
3. 結合は既存の地下水と同じ「**swflow の後に s%h から取る**」型にする
   (§4.3)。VZ セルに降った雨は浅水流ソルバーが通常どおり s%h へ加え、
   swflow の直後に m_vzflow がその雨の分だけを回収して柱の上端流束にする。
   浅水流ソルバー(ENC・STG)と s%pre は無改修で済む(親§9.5 の「雨を
   地表流の前で分岐」からの変更)。
4. 並列化は**全ランクが全柱を冗長に解く**(§11「冗長計算=配布機構」)。
   柱の解は全ランクでビット同一になり、出口への加算だけを所有ランクが
   行う。親§13.2 の「rank0 が解いて配布」より通信が少なく、np=1,2,4 の
   ULP=0 がそのまま成立する。
5. 計算核は解法補足の骨格(混合形・有限体積・後退 Euler・修正 Picard・
   Thomas 法・ステップ二分比較・巻き戻し)を採り、**L スキーム・残差の
   直線探索・Newton は後回し**にする(単体試験で必要が示されたら足す。
   §0-6「徐々に精緻化」)。
6. 初期版は併用できない機能を init で停止する(地下水・積雪・氷河・
   土層厚を変える地形変化・水質・淡塩・ネスト。§4.10)。モザイク運用
   (VZ と既存地下水の同居)は所有マスクを入れる段で解く。

## 2. 先に決めること: 方針との関係

### 2.1 方針 5(鉛直は抽象化・概念化)

| 案 | 内容 | 評価 |
|---|---|---|
| **A(推奨)** | 方針 5 に限定的な例外を足し、共有参照柱上の 1 次元 Richards を認める | 谷(2023)の VZ モデル(HYDRUS-1D と小杉式の参照柱)をそのまま再現できる。状態は O(柱数 G × 層数 Nz) でセル数に比例しない。「鉛直の抽象化」の趣旨(セルごとに精緻な鉛直構造を持たない)は保てる |
| B | 方針を変えず、鉛直を概念化して入れる(運動波近似の不飽和流 = 重力流だけの特性曲線解、または貯留関数) | 方針内で完結し安い。ただし毛管拡散による応答の減衰・遅れを落とすため、谷(2023)の参照柱の再現にはならない(Tani 2021 が示す「貯留関数が鉛直不飽和流を表す」関係を使えば流出応答は近似できるが、それは別モデル) |
| C | 入れない | — |

案 A の例外文案(§0-5 の非静水圧の例外の直後に置く):

> (例外 2026-xx-xx 合意: 鉛直不飽和浸透の応答そのものが研究対象となる用途
> (谷(2023)の VZ 流出モデル)に限り、少数の**共有参照柱**上で 1 次元
> Richards 式を解くことを認める。条件: (1) 鉛直格子をセルごとに持たない
> (鉛直の状態は柱数 × 層数。セル側は区画番号と土層厚の読み出し重みだけ)、
> (2) 側方の地下流は解かず、区画の排水を明示した出口へ移す(水平方向の上限は
> 不変)、(3) fn_vz 未指定ならメモリ・CPU・通信ゼロ追加、無効時は既存
> reference とビット一致。設計の正本は docs/vz_plan.md、決定の記録は
> developer.md §87)

方針 4(精緻な物理プロセスの再現は目的外)との関係: 水平方向は区画単位の
集約と瞬間排水で、プロセスとしては「概算」の側にある。柱の Richards は
谷モデルの仮説(鉛直不飽和浸透が流出応答を支配する)を検証できる最小限の
物理として位置づける。

### 2.2 実数精度(§1)

§1 は「精度はコンパイルフラグで指定、状態は PREC」。例外は診断集約の
real64 だけである。小杉式の誤差関数の尾部、含水率の差、層ごとの水収支残差は
単精度では判定が破綻しやすい(解法補§4.2)。**柱の状態・係数・残差・積算
水量は real64 固定**とする例外を §1 に足すことを提案する。状態が
O(G·Nz)(例: 10 柱 × 400 層 = 4000 値)なのでメモリ増は無視できる。
倍精度ビルドでは real64 = 既定 real なので単一実装で、既存とビット同一。
単精度ビルドで地表の s%h(PREC)へ渡す境界では、実際に加わった量と要求量の
差を出口ごとの繰越として持ち、台帳・再開の対象にする(補§12.2)。

### 2.3 その他の方針との整合(問題なし)

- 方針 2(ラスタ純化): 区画は整数ラスタ、出口はセル群指定(構造物と同じ)。
- 方針 7・8: fn_vz の有無で有効化。無効時は配列未確保・呼び出しなし。
- 方針 10: 誤差関数は Fortran 2008 の組込み erfc、三重対角は自前。外部依存なし。
- 方針 12: 区画・出口・土層厚・小杉パラメータは直接与える。最寄り河道探索や
  斜面法線→鉛直の換算は前処理(utils)側(親§12.3 と一致)。
- 方針 13: 出典(Tani 2023、Kosugi 1996、Celia ら 1990、HYDRUS-1D)を
  developer.md と users guide に、独自の簡略化(瞬間排水・柱内面積平均・
  §4.3 の回収方式)は「独自」と明記。解析解のある挙動は Check_*.py で検定(§6)。

## 4. ENCflow への組み込み

### 4.1 モジュール構成

```
m_vzflow.f90          管理(t_vzflow。区画・重み W/M・出口・雨の回収・
                      地表への供給・台帳・診断・save/restore)
m_vzflow_column.f90   計算核(t_vzcol。1 本の柱の状態と、指定した同期区間を
                      進める手続き。小杉式は私有手続き。水平格子・区画・出口を
                      知らない)
list_vz.f90           namelist を読むだけ(§12 の層契約)
```

- t_vzflow は m_main の t_encflow の成分として持つ(状態をモジュール変数に
  置かない。§71 の A 群)。init に早期 return 経路があるので全成分を
  デフォルト初期化する(§13)。
- 計算核は MPI を知らない。OpenMP は柱のループ(柱ごとに作業配列を所有)。

### 4.2 入力(namelist 案。名前は仮)

```
&list_vz
  f_vz        = 1            ! 0 で書いたまま一時無効化
  fn_vz_zone  = 'vzzone.asc' ! 区画番号ラスタ(整数。0 = 適用外)
  dt_vz       = 0.0          ! 同期間隔 (s)。0 = 毎ステップ
  f_vz_rain   = 0            ! 0: 柱内で地上雨量が一致しなければ停止 / 1: 柱内面積平均
  f_vz_kface  = 1            ! 界面透水係数 1: 算術平均 / 2: 調和平均
/
&list_vz_column               ! 柱ごと(1:ncol)
  vz_ks_mmh(1) = ..., vz_thetas(1) = ..., vz_thetar(1) = ...,
  vz_psim(1) = ...(m。負), vz_sigma(1) = ...,
  vz_depth(1) = 10.0, vz_dz(1) = 0.025,     ! 計算柱の深さ L と層厚(原論文の出発値)
  vz_q0_mmh(1) = ...                         ! 初期条件(§5.5)
/
&list_vz_zone                 ! 区画ごと(1:nzone)
  vz_zone_col(1) = 1                         ! 参照する柱
  vz_out_cell(:,:,1) = 120,80                ! 出口セル(インライン)/ fn_vz_out_cell(1)
  vz_out_w(:,1) = 1.0                        ! 配分率(1 セルなら省略可)
/
```

- 土層厚 d_i は geoinfo の sd(f_sdtype / sd0 / fn_sd)を使う
  (m_geoinfo_require_sd の遅延確保口)。初期化後は VZ 用に固定。
- 数値制御(反復上限・許容誤差・dt_min/dt_max)は既定値を置き、採用値を
  "(default)" 付きで表示する(architecture.md §5 の 6)。ただし解法補§13.1 の
  候補値は**未検証**なので、§6 の試験で確かめてから既定として文書化する。
- 物性(小杉パラメータ)に既定を置くかは §8 の判断事項。

### 4.3 時間ループ上の位置と水の受け渡し(案 D)

```
... intercept → snow → swi → glacier → boundary_makebdc → tide
swflow_calc           VZ セルにも雨は通常どおり入る(boundary_h が
                        h1 += pre·dt/gv)。VZ セルは前ステップ末に乾いて
                        いるので流出はなく、ステップ末の h はちょうど雨の分
★ vzflow_calc         (1) VZ セルから雨の分 pre·dt/gv を s%h から回収し
                          柱の入力に積算(e を回復。毎ステップ・セル局所)
                      (2) 同期時刻なら全柱を進め、区画の排水体積を W で集約、
                          出口セルの s%h へ加算(所有ランク。e を回復)
gwflow_calc ...       (初期版は併用不可)
```

- **浅水流ソルバーと s%pre は無改修**。土壌雨量指数(s%pre を読む純診断)も
  影響を受けない。地下水(gwflow)が「swflow の後に s%h から取る」のと同じ
  結合型で、architecture.md §3 の「実行順序が結合仕様」に従う。
- 回収量は boundary_h と同じ式 `s%pre(i,j) * p%dt / s%gv(i,j)` で計算する
  (h が前ステップ末に 0 なら、回収後の h は厳密に 0 に戻る)。VZ セルの
  上流から流れ込んだ水(run-on)は回収しない = 地表流のまま流れる
  (一方向の近似。§4.9 で VZ セル上の最大湛水深を診断として出す)。
- 出口への供給は体積を雨と同じ換算 `V / (dx·dy) / gv / wfrac` で s%h に
  加える(積雪・氷河の融解水、境界ソースと同じ)。σ 断面のセルでは S 台帳の
  既知の妥協(§18)をそのまま継ぐ。同期区間の排水は区間末にまとめて渡す
  (dt_gwflow の間引きと同じ意味論。未来の雨は使わない)。
- 同じ出口セルに複数区画から渡る量は先に合計して一度だけ加える。

### 4.4 区画の集約(親§6 のとおり)

- 初期化で、区画ごとに界面重み W_{g,j} = Σ A_i b_{i,j}(m²)と層重み
  M_{g,k} = Σ A_i clip(d_i − ζ_{k−1}, 0, Δζ_k)(m³)を作り、Σ_j W = A_g・
  Σ_k M = Σ A_i d_i を検査する。
- 時間ループでは ΔV_g = Σ_j W_{g,j} F_{c(g),j}、V_VZ,g = Σ_k M_{g,k} θ_{c(g),k}
  で集約し、セル走査をしない(O(G·Nz))。
- 初期化での重み作成は決定的に行う: sd を窓形に gather して rank0 が j 昇順に
  組み立て、rank0 だけが非零のベクトルを par_allreduce_sumr で共有する
  (§11 が許す「寄与ランクがちょうど 1 つ」の使い方)。

### 4.5 共有条件と雨の平均化

- f_vz_rain = 0(既定): 同期区間ごとに、柱ごとの地上雨量の最小・最大を
  par_allreduce_max(順序不変)で集め、一致しなければ停止する(メッセージで
  f_vz_rain = 1 か区画の分割を案内)。
- f_vz_rain = 1: 柱の入力を柱内セルの面積平均にする(入力体積は保存。
  行部分和 → par_sum_rows で決定的)。**「平均入力への置換」という独自の近似**で、
  平均入力の応答と個別応答の平均は一般に一致しない(親§9.5)と文書に明記する。

### 4.6 水収支台帳

- 区画の VZ 貯留 Σ_g V_VZ,g を calcstat の S_grnd・S_total に算入する
  (t_state に vz_active と柱状換算のスカラーを置く。gw_active と同型。
  無効時は Log の列も値も不変)。
- 共有柱の d_i より深い部分の水は数えない(親§5.2・§6.3)。
- 系外流出(出口セル未指定)の累積は VZ の診断 CSV に出す。

### 4.7 並列化

- 全ランクが全柱を同じ入力で冗長に解く(柱の解は全ランクでビット同一)。
- 通信は同期区間ごとに柱の入力を揃える 1 回(§4.5)だけ。
- 出口セルへの加算は所有ランクだけ。区画総量を全ランクで再総和しない。
- 柱数が数百を超えて冗長計算が効かなくなったら、柱のランク分散を後段の
  最適化として検討する(結果は不変にできる)。

### 4.8 保存・復元

- 私有ファイル `vzflow.dat`(契約 5: dispose で保存、init で復元。
  stop_if_orphan_state と同型の逆向き検査も入れる)。
- 中身: 全柱の ψ(θ は ψ から再計算して照合)、次の試行刻み、同期区間内の
  入力の積算と記録、出口ごとの繰越(§2.2)、区画・柱の構成の識別(区画数・
  柱数・層数・土層厚の総和などの指紋)。
- 柱のベクトルはセル配列ではないので m_restart のセル口は使わない。rank0 が
  書き、復元は全ランクが同じファイルを読む(初期化の冗長実行の規約)。

### 4.9 出力・診断

- 区画確認表(初期化時に Log へ): 面積、セル数、柱、土層厚の最小・平均・
  最大、出口と配分率。
- `fluxes/vz_zone.csv`: 区画ごとの入力体積・貯留・排水・内部移送・系外流出・
  残差(区画の物理的水収支。親§14.3)。
- `fluxes/vz_column.csv`: 柱ごとの上端入力、選んだ深さの ψ・θ・F、反復数・
  棄却数・最小刻み、柱全長の水収支(計算核の診断。区画の収支とは別欄)。
- 分布: VZ セル上の最大湛水深(run-on の大きさ。§4.3)。セル別 S_i の
  分布出力は P3 で。

### 4.10 初期版の併用制限(init で停止)

| 組み合わせ | 理由 |
|---|---|
| fn_gwflow | 同じ土層の所有が重なる(VZ セルの run-on を鉛直モデルが浸透させ、側方流が VZ セルを通る)。モザイクは所有マスクの段で |
| fn_snow・fn_glacier | 融解水が s%h に直接入り VZ を素通りする。上端入力への算入は柱内一致の検査とあわせて拡張で |
| fn_geomorph で土層厚・標高が変わる過程 | 深さの参照が動くと貯留が増減する(親§11.4) |
| fn_wq・fn_salt | 雨の溶質・塩水層を VZ が運ばない |
| fn_nest | ネストの重複領域と面積重みの規約が未定義 |
| STG | 回収式(boundary_h と同じ式)の照合を ENC だけで行う |
| VZ セルが海セル・河道セル(rw)・境界/ソース/構造物のセル | 雨の回収量が boundary_h の式と一致しなくなる |
| 出口が VZ セル・海セル・水位強制セル | 投入水が上書きで消える/VZ 内の地点別湛水になる |

## 5. 計算核(m_vzflow_column)の仕様

解法補足を土台に、初版で入れるものだけを書く。

### 5.1 離散化

- 有限体積(層平均の含水率、界面の流束)、下向き正の深さ ζ。
- 混合形の元の残差 R_k = Δζ_k (θ(ψ_k) − θ_k^old) + δt (f_k − f_{k−1})
  を収束判定の正本にする(Celia ら 1990 の保存形を有限体積で書いたもの。
  独自の展開)。
- 小杉式(Kosugi 1996)。x = (ln|ψ| − ln|ψ_m|)/σ、θ = θ_r + (θ_s − θ_r) Q(x)、
  K = K_s Q(x)^{1/2} Q(x+σ)²、C = dθ/dψ。erfc を直接使い、ψ ≥ 0 は θ_s・K_s・C = 0。
- 界面 K は算術平均(既定)/ 調和平均。1 実行の中で変えない。

### 5.2 反復と時間刻み

- 修正 Picard(K を固定、貯留を C で線形化)→ Thomas 法。
- 収束: 元の残差が局所予算以内(補§8.1 の b_k。同期区間の予算を層厚と
  試行刻みで配分)かつ Δψ・Δθ が許容内。小さい更新だけでは受理しない。
- 失敗(反復上限・非有限値・ピボット異常)→ 旧状態へ戻して刻みを半分。
- 時間誤差: 同じ旧状態から粗い 1 歩と細かい 2 歩を解き、ψ・θ・全界面の積算
  流束 F の差で判定(補§9.2〜9.3)。合格なら**細かい枝の状態と流束を一組で**
  採用。刻みの増加は 1.5 倍程度まで(候補値)。
- 内部刻みは同期時刻と入力の変化時刻をまたがない。
- 最小刻み・再試行回数の上限で停止(無限ループにしない)。

### 5.3 受理した解だけを積算

- 区間の積算流束 F_j には受理した細かい枝だけを足す。全柱が同期時刻に
  到達した後で区画集約と出口への供給を確定する。1 柱でも失敗したら停止
  (初期版は同期区間を不可分にする。補§11.3)。

### 5.4 境界

- 上端: 規定流束 = 地上雨量。収束解で地表面圧力の再構成(補§5.2)が正を
  要したら「湛水が必要 = 適用外」で停止。
- 下端: 自由排水 f_N = K(ψ_N)。
- 有意な上向き流束を読み出し深さで検出したら停止(直接排水の適用外。
  max(D, 0) で隠さない)。
- 検証用に下端の固定圧力境界を持つかは §8 の判断事項(§6 の定常解検定に使う)。

### 5.5 初期条件

- 既定: **定常重力排水** — 一様な ψ₀ を K(ψ₀) = q₀ から二分法で求める。
  自由排水の下端では一様 ψ が厳密な定常解なので、q₀(初期の流出率)を与えれば
  初期状態が一意に決まる。
- 直接 ψ₀ を与える指定、スピンアップ → save → restore(§16.2 の流儀)も可。

### 5.6 計算負荷の見積り(要実測)

Nz = 400(L = 10 m、Δζ = 2.5 cm)、Picard 3〜5 回、二分比較で 3 回の
後退 Euler とすると、受理 1 歩あたり物性評価は約 5000 回(誤差関数・指数・
対数を含む)。外側 dt ≈ 1 s に毎ステップ同期すると 1 柱あたり 1 ステップ
0.5 ms 程度、10 柱で 5 ms 程度になりうる(地表流の 1 ステップと同程度の
桁になりうる)。dt_vz を 30〜60 s にすれば無視できる大きさになる見込み。
§6 で実測し、既定の dt_vz の推奨を決める。

## 8. 合意が必要な判断

1. **方針 5 の例外**(§2.1): 案 A の文案でよいか。
2. **§1 の例外**(§2.2): 柱の状態・台帳を real64 固定にしてよいか。
3. **雨の受け渡し**(§4.3): 「swflow の後に s%h から回収」(推奨。浅水流
   ソルバー無改修)か、親設計どおり boundary_h で VZ セルの雨を加えない
   (ENC・STG の両方に分岐を入れる)か。
4. **雨の共有条件**(§4.5): 厳密一致を既定にし、面積平均を P2 で入れて
   よいか。
5. **界面 K の既定**: 算術平均(HYDRUS 準拠)でよいか。
6. **時間誤差制御**: ステップ二分比較を P1 から入れるか(推奨)。
7. **小杉パラメータの既定値**: 原論文の使用値を照合して既定にするか、既定を
   置かない(与件扱い)か。
8. **初期版の併用制限**(§4.10)の範囲。特に gwflow のモザイクを P2 に
   含めるか、P5 に回すか。
9. **湛水**: 初期版は停止、境界切替は P4 でよいか。
10. **検証用の固定圧下端**(§5.4): 定常解の検定のために入れるか。
11. 添付の設計文書 2 点をリポジトリに収めるか(収めるなら docs/ に原文のまま、
    本書から参照する)。
