## 0. 結論(要約)

- **実現の可否: 可**。受け皿は既に揃っている — m_geomorph は「フラグ+
  パラメータ+サブルーチン1本」で閉じる重ね合わせ骨格、s%z は動的状態、
  ハロ交換と e 整合回復は calc 末尾に実装済み、エッジ流量の MPI 定型は
  m_gwflow_lateral が見本、加速(実効時間刻み dts)は gwflow の
  dts = dt × idt の慣習をそのまま拡張できる。
- **段階実装を推奨**: F1 掃流砂(平衡 Exner。輸送状態なし)→
  F2 浮遊砂(柱状量 hs の移流+浸食・沈降)→ F3 斜面浸食(雨滴・
  面状侵食が hs へ供給 → 移流が自動的に河道へ運ぶ)→(必要になったら)
  F4 混合粒径。クリープ(実装待ちの TODO)を F0 として先行し、
  加速係数と解析解ベンチマークの足場を最小コストで確立する。
- **土層厚 sd を動的共有状態 s%sd に昇格し、z と同じ Δz で共動更新する**
  (§2.5)。これ1つで (a) 浸食の可動層クランプ(sd ≥ 0)、
  (b) 地下水の貯留容量 sd·sy0 の減少=飽和・流出の早期化、
  (c) 帯水層底 (z − sd) の自動固定(岩盤は動かない)の3つが同時に
  成立する。
- **抗力への密度の影響: 一次近似では不要**(§3)。二次流体力学効果
  (沈降遅延・レオロジー・乱流減衰)が効き始める高濃度域(体積濃度
  数%超)は警告で検出し、扱うなら別の流れモデル(排他切替)として設計する。
- **加速係数(morphological acceleration factor, MORFAC)は妥当な標準手法**
  (Delft3D 等で実績)。地形更新側だけに乗じる。安定性ガード
  (1回の Δz 制限)と「N 倍実行との等価性検証」をセットで導入する(§4)。

## 1. 対象とする物理と状態量(質問1への回答)

### 1.1 輸送の2形態と必要な状態

河床変動は輸送形態で必要な状態量が全く異なる:

- **掃流砂(bedload)**: 底面近傍の平衡輸送。局所の水理量(τ*)から
  平衡流砂量 q_b を毎回計算する(芦田・道上、MPM 等)。
  **輸送そのものの状態量は不要**(q_b はエッジのスクラッチ)。
  河床変動は Exner 式:
  (1−λ) ∂z/∂t = −∇·q_b
- **浮遊砂(suspended load)**: 水柱内を移流する。**輸送状態が必須**。
  保存量は「柱状換算の土砂量 hs [m](単位床面積あたりの固体体積)」を
  正準とし、濃度 C = hs/h は導出量とすることを推奨する。理由:
  - 乾湿遷移で C は特異(h→0 で発散)、hs は連続
  - 保存則を直接離散化できる(h1 と同じ流儀)
  - s%hg の「柱状換算契約」と揃い、質量台帳・出力・計測が同型で書ける
  発展式: ∂hs/∂t + ∇·(u hs) = E − D、
  河床側: (1−λ) ∂z/∂t = D − E
  (E: 浸食(entrainment。板倉・岸等)、D: 沈降 w_f·c_b(w_f: Rubey 等))

### 1.2 hs 以外に必要な状態量・係数(質問1の本体)

| 量 | 種別 | 理由・備考 |
|---|---|---|
| s%z | 状態(既存) | 動的状態化済み。save 済み。浸食で下降・堆積で上昇 |
| **s%hs**(浮遊砂柱状量) | 状態(新規。F2) | t_state 共有を推奨(§5.1)。save 対象 |
| **s%sd**(土層厚=可動層厚) | 状態(新規。F1) | **動的共有状態**。初期値は g%sd(既存の静的入力)。z と共動更新し、浸食限界(sd ≥ 0)と地下水容量(sd·sy0)を兼ねる(§2.5) |
| **代表粒径 d50** | 静的係数 | geoinfo 所有を推奨(sd/sy0 と同じ「土地固有量」。§16 の境界規則)。f_*type 3状態(未確保/固定値/分布)+方式2配布 |
| 空隙率 λ | パラメータ | 一様値で十分(~0.4) |
| 沈降速度 w_f | 導出 | d50 から Rubey 式等で init 時に導出 |
| 限界掃流力 τ*c | パラメータ/導出 | 一様 0.05 か岩垣式 |
| (混合粒径: 交換層の粒度分布) | 状態(F4) | 平野の交換層モデル。粒径階×層の大配列+私有 save が必要。**当面繰り延べ** |
| (診断: 累積変動 Δz) | 出力オプション | 初期 s%z の控え1枚で z − z_init を出力できる。必須ではない |

境界条件の追加: 上流からの**土砂供給**(区間流入への Qs(t) 付加、または
「平衡給砂」= 流入エッジで輸送能力ぶんを自動供給)。開境界からは hs が
移流で自然流出。Exner の境界セルは勾配片側差分で閉じる。

## 2. 実装案

### 2.1 掃流砂(F1: f_fluvial)— 平衡 Exner

新しい輸送状態は s%sd のみで「河床の浸食・堆積」が動く。

- **離散化は m_gwflow_lateral の8近傍 FV・2ループ構造をそのまま踏襲**:
  ループ1で各セル所有エッジ k=1..4 の q_b を計算(界面エッジは
  ハロ行まで冗長計算=ビット厳密な配布。§16.1 の実例第3号)、
  ループ2で発散を取り z と sd を共動更新(§2.5)。エッジ配列はスクラッチ
  (無履歴・save 対象外・par_halo_edge 不要)。
- q_b の向きは**流れの向き(エッジの mn または u,v の面法線成分)**、
  大きさは平衡流砂量式。式は f_qbform で選択(1: 芦田・道上, 2: MPM 等。
  排他選択だがプロセス内の式切替なので select case で十分。
  モデル群に育ったら手続きポインタへ昇格)。
- 底面せん断力はエッジ両セル平均の (h, vv, rn) から
  τ* = n²·vv²/((s−1)·d50·h^{1/3}) で毎回導出(スクラッチ)。
  ※摩擦項(calc_kth_flux の tfe)と同じ閉じ方を使い、流れと整合させる。
- **クランプ2種を必ず入れる**:
  (1) 可動層クランプ: 浸食は s%sd ≥ 0 の範囲(流出エッジ按分で減量)。
      sd=0 は岩盤露出=それ以上掘れない
  (2) 安息角リミッタ: 更新後の隣接勾配が安息角超過なら崩落再配分
  (または q_b の勾配補正項)。急勾配 DEM での暴走防止。
- 更新は dt_geomorph 間隔 × 加速係数の実効刻み(§4)。

### 2.2 浮遊砂(F2: f_suspend)— hs の移流+浸食・沈降

- **状態 s%hs を t_state に追加**(§5.1 の設計判断)。
- **移流は m_swflow_enc がステップ内で実行する(s%sed_active フラグ方式。
  改訂1)**。理由:
  - continuous の水深更新は
    `dh = mne * mn2dh(k) * fw * winv / g%gv(i,j)`(エッジ流量×換算係数×
    通過幅係数×平面積率逆数÷空隙率)。hs の移流は
    `Δhs = Σ mne · C_donor · mn2dh · fw · winv / gv`(C_donor = 風上セルの
    hs/h)と**完全に同じ係数**で書かないと整合せず、整合すれば
    「一様濃度は一様のまま」が式の形で保証される
  - 風上濃度には**時刻 n の h** が要るが、m_geomorph_calc の時点では
    complete が h1→h をコミット済みで旧 h は消えている
  - 移流は毎ステップ起きる物理であり、dt_geomorph の間欠実行に
    載せると中間ステップの mn を取りこぼす
  よって m_geomorph_init が s%sed_active を立て(s%gw_active の前例)、
  m_swflow_enc_calc が continuous の直後(h_n・mn1・係数一式がスコープに
  ある場所)で毎ステップ s%hs を風上移流する。mn1 は par_edge_merge 済みの
  行 js−1..je を読むため h と同じ理屈でランク数不変。geomorph は
  E−D 交換と Exner だけを dt_geomorph×morfac の周期で担当する
  (演算子分割)。無効時は分岐1個で完全不活性=無効時ビット一致で検証。
  STG は実装せず f_suspend×STG は geomorph init で par_stop(凍結方針)。
- 交換項(同一セル内の鉛直移動): gwflow_bucket 契約1と同じ反対称適用
  「fx を hs から引き (1−λ)Δz に足す」で質量保存を構造的に成立させる。
- **乾燥時の強制沈降**: h < dv になるセルの hs は河床へ全量繰り入れる
  (水のない浮遊砂を残さない。乾湿の激しい氾濫原で必須)。
- save/restore: hs を state.dat に追加(save_version 更新、
  utils/ の追随確認。§10)。

### 2.3 斜面浸食と河道への土砂供給(F3: f_wash)

- 雨滴侵食+面状侵食: 供給源項 E_hill = f(降雨強度, 地表流せん断力) を
  **hs へ注入し z(と sd)から差し引く**だけでよい。**河道への土砂流入は
  移流(F2)が自動的に実現する** — 斜面→河道の受け渡しに専用機構は不要。
  これが hs を共有状態にする最大の理由(§5.1)。
- **斜面の表層浸食は s%sd を直接減らすので、「土層が薄くなり早く飽和して
  流出が早まる」過程(ユーザー要件)がモデル構造上そのまま現れる**(§2.5)。
  sd → 0 まで削れたセルは岩盤露出となり浸食が止まる(badland の挙動)。
- 独立フラグの重ね合わせ(f_creep + f_fluvial + f_suspend + f_wash)で、
  既存プロセスに触れず追加できる(m_geomorph の設計方針どおり)。
- 崩壊性浸食(badland)・浅層崩壊はさらに将来(必要時に別フラグ)。

### 2.5 土層厚の動的化と地下水モデルとの結合(改訂1。ユーザー要件)

**要件**: 斜面の表層浸食で土層厚が減ると飽和が早まり流出が早くなる。
この過程は重要なので、浸食モデルと地下水モデルの結合を保つ。

**設計: sd を動的共有状態 s%sd に昇格し、geomorph が z と同じ Δz で
共動更新する(z が ΔZ 動けば sd も ΔZ 動く。下限 0)**。

- 初期化: s%sd = g%sd のコピー(g%sd は「初期土層厚の静的入力」として
  存続。f_sdtype の3状態・方式2配布・遅延確保口 require_sd はそのまま)。
- gwflow の g%sd 参照(3カーネル)を s%sd に置換する。結合は既存の式が
  そのまま実現する:
  - 貯留容量 cap = sd·sy0(greenampt:114, lateral:290)→ 浸食で減少
    =**飽和の早期化・浸透の早期停止=流出の早期化**(要件の本体)
  - 全水頭の帯水層底 (s%z − sd)(lateral:233)→ z と sd が同じ Δz で
    動くため **(z − sd) は自動的に不変=岩盤標高が動かない**。
    静的 z_rock を別配列で持つ必要がなく、浮動小数の再構成誤差もない
    (共動更新は「同じ量を両方に足す」だけ)
  - 飽和判定 hg ≥ sd·sy0(lateral:234, 244)→ 同上
- **容量縮小時の超過引き渡し**: 浸食で cap が現在の s%hg を下回ったら、
  超過分を s%h へ渡す(反対称適用+e 回復。gwflow_bucket 契約1・2と同じ。
  物理的には「飽和した表土が削られ、含まれていた水が地表に出る」)。
  側方流動のループ2にも超過引き渡しがあるが、鉛直のみの構成でも成立する
  よう **geomorph が sd 更新と同じループで自前処理する**。
- **ハロ**: 側方流動が近傍セルの sd を読む(lateral:244)ため、
  geomorph calc 末尾の交換に par_halo_cell(s%sd) を z と並べて追加。
- **save/restore**: s%sd を state.dat に追加(hg と同様、機能無効時も
  ゼロ/コピーを保存する一律扱い。save_version 更新は hs と同時に1回で
  済ませる)。
- **検証の段取り(規律4: 等価変換と挙動変更のコミット分離)**:
  1. コミットA(等価リファクタ): s%sd 導入(= g%sd のコピー)+
     gwflow の読み替え。値はビット同一なので**逐次ビット一致(ULP=0)**
     で検証
  2. コミットB(機能追加): geomorph の共動更新。f_fluvial/f_wash
     無効時ビット一致で検証
- **既知の近似・注意**(受容の上で文書化):
  - 堆積側: 新しい堆積物にも同じ sy0(スカラー)を適用=直ちに土層に
    算入される近似。sy0 分布が必要になったら §16 の方針どおり
    f_sytype を追加
  - 側方流動の陽解法安定条件(init の静的検査。lateral:167-181)は
    **init 時の max(sd) に基づく**。堆積で sd が初期最大値を超えて
    成長すると検査が非保守側になるため、geomorph 有効時は
    「init 時の検査値+成長余裕」を静的に見込むか、sd 最大値の超過を
    par_warn で監視する(dt_geomorph 周期の allreduce_max 1回で安価)
  - バケツモデル(f_gwvertical=1)は sd 非依存(gw_capacity 直接指定)の
    ため結合しない。もともと側方と組めない実験用であり、浸食との併用も
    「容量は不変」と明記するのみ
  - gwflow 無効で浸食のみ有効の場合も s%sd は可動層クランプとして機能する
    (require_sd を geomorph も呼ぶ=第2の利用者。無制限に掘らせたい
    ケースは sd0 を大きく取る)

## 3. 高濃度時の密度と抗力(質問2への回答)

**結論: 運動量方程式は加速度形なので、二次抗力則の密度は分子分母で
相殺し、一次近似では修正不要。**

- 混合密度 ρm = ρw(1 + (s−1)C)(s ≈ 2.65)。運動量式を ρm h で割った
  加速度形では:
  - **底面摩擦**: τb = ρm·g·n²·vv²/h^{1/3} → 加速度 τb/(ρm h) から
    ρm が消える。現行 tfe(calc_kth_flux)は正にこの形で、
    濃度が入り込む場所がない。
  - **建物抗力**: F = ½·ρm·Cd·A·vv² → 慣性も ρm 倍なので同じく相殺。
    現行の p%kk·cd·h/bb·(1−gv)·vv/2 も加速度形で不変。
- **密度が本当に効く経路**(いずれも C が数%を超える高濃度域):
  1. **密度勾配項** ∇(ρm h²) — 濁流(turbidity current)的な駆動。
     通常洪水の C ~ O(10⁻³〜10⁻²) では無視できる(Delft3D/Nays2DH/
     Telemac 等の標準実装も流れ側は清水のまま)
  2. **沈降遅延**(hindered settling): w_f×(1−C)^n — 沈降側の修正で
     抗力ではない。F2 のオプションで安価に入れられる
  3. **乱流減衰・成層**: 実効摩擦がむしろ**低下**する(黄河の
     高濃度流で既知)。閉じた補正は確立しておらず当面対象外
  4. **レオロジー変化**: C > 10〜20% で Bingham/Herschel-Bulkley 化
     (泥流・土石流)。これは摩擦係数の補正ではなく**別の流れモデル**。
     扱う日が来たら t_swflow の排他切替(手続きポインタ成分)として
     別スキームを立てるのが本コードの流儀
- **推奨**: F2 で C の診断監視を入れ、閾値(例: 2%)超過セル数を
  par_warn(または sp 統計)で報告する。「適用範囲外に入ったことを
  黙らない」だけ担保し、モデル自体は清水流+受動輸送で確定させる。
- 輸送式側の密度は水中比重 (s−1) として最初から入っており(Shields 数)、
  これは流れの抗力とは別物(混同しない)。

## 4. 加速係数(質問4への回答)

- **方式: 地形更新だけを N 倍する(MORFAC 方式。Lesser et al. 2004)**。
  実装は gwflow の実効時間刻み dts の慣習をそのまま延長:
  dts_morph = p%dt × idt_geomorph × morfac を各プロセスの calc に渡す。
  - クリープ(線形拡散)は時間線形なので厳密に「N 倍長く回した」と等価。
  - 掃流砂 Exner も流れが準定常なら同様(古典的手法)。
  - 浮遊砂は**河床側(E−D の z への反映)だけに乗じ、水柱側 hs の
    発展には乗じない**(標準の MORFAC 分離)。水柱と河床の台帳が
    「水理時間 vs 地形時間」に分かれることを台帳出力に明記する。
  - **sd の共動更新(§2.5)も同じ dts_morph で動く**ため、地下水容量の
    減少も「地形時間」で加速される(要件の長期過程がそのまま加速対象)。
- **解釈**: 洪水イベント計算に morfac=N は「同じ洪水が N 回来た時の
  地形変化」を1回で得る意味になる。長期解析は代表ハイドログラフ
  (または年間流況の代表イベント列)× morfac の組み合わせで構成する。
- **安定性ガード(必須)**:
  - 1回の更新の |Δz| に上限(例: α·h または絶対値 dz_max)を設け、
    超過はクリップ+カウント(n_exfluxes と同じ報告様式)。
    地形波の CFL(河床波速 × dts_morph / dx)が実効的な制約で、
    morfac を上げるほど破りやすい。
  - 安息角リミッタ(§2.1)はガードの第2層。
- **検証**: 定常流+morfac=N の結果が morfac=1×(N 倍時間)と
  一致(許容差内)することをベンチマーク化する。加速の妥当性そのものを
  回帰可能にする。
- morfac は**geomorph 全プロセス共通の1個**を推奨(プロセス別だと
  「地形の時間」が分裂し、プロセス間の相互作用— 斜面供給と河床変動 —
  の同時性が壊れる)。
- リスタート: morfac はパラメータであり新規状態なし。

## 5. 事前に合意したい設計判断

1. **s%hs の置き場**: t_state 共有(s%hg 同型。推奨)か geomorph 私有か。
   共有の根拠: (a) 斜面(F3)と河床(F2)の結合点、(b) m_state の
   save/出力/プローブ/台帳に自然に乗る、(c) swflow_enc のステップ内
   移流(§2.2)が読む。契約文言も hg に倣う。
2. **移流の実装(改訂1)**: swflow_enc のステップ内輸送
   (s%sed_active フラグ。s%gw_active の前例)を推奨。
   手続きポインタサービス方式は「時刻 n の h が geomorph 時点で消えて
   いる」「間欠実行が中間ステップの mn を取りこぼす」の2点で不採用。
3. **土層厚の動的化(改訂1。ユーザー要件により方向決定)**: s%sd を
   動的共有状態に昇格し z と共動更新(§2.5)。残る論点は
   超過引き渡しの置き場(geomorph 自前案を推奨)と save の一律扱い。
4. **段階の順序**: F1(掃流砂)先行を推奨。新規輸送状態最小で Exner・
   クランプ・ベンチマーク・morfac の骨格を確立できる。ただし対象河川が
   細粒支配(ウォッシュロード卓越)なら F2 を主戦力として先行する
   判断もあり得る — 対象問題の想定を確認したい。
5. **サブグリッド河道幅セル(§18)の扱い**: W < セル幅のセルでは
   浸食・堆積は河道断面内に集中するべきで、Δz を 1/wfrac 倍するか
   (河道底のみ変動)、F1 では fn_width セルを対象外にするか。
   前者は掘り込み暴走(wfrac 小で dt 制約悪化)のリスクがあり要検討。
6. **既知の静的量との不整合の受容**: 堤防天端 zbank・破堤基準 zgnd0 は

## 6. 影響範囲・落とし穴の監査(規約との突き合わせ)

- **ハロ**: s%z の交換は m_geomorph_calc 末尾に実装済み。s%sd を同所に
  追加(側方流動が近傍 sd を読む)。F2 の hs はステップ頭の交換リストに
  追加(swflow_enc の移流が読む。sed_active 時のみ)。
- **collective**: enabled / idt / morfac / sed_active は namelist 由来で
  全ランク同一。台帳総和は par_sum_rows(決定的)。クリップカウントは
  整数和。sd 成長監視の allreduce_max は dt_geomorph 周期(全ランク同一
  判定)。
- **規律3**: 新規帯配列(hs、sd、エッジスクラッチ)を足すコミットは
  最適化ビルドより先に -fcheck np≥2(chichibu 級の静的データケースで)。
- **規律4**: gwflow の g%sd → s%sd 読み替え(等価リファクタ=逐次
  ビット一致)と、geomorph の共動更新(機能追加=無効時ビット一致)は
  コミットを分ける(§2.5 の段取り)。
- **検証階段**: fn_geomorph 未指定/全フラグ0 で既存 reference と
  ビット一致 → 各フラグ単独疎通 → np=1,2,4 ULP=0 → リスタート往復
  (hs・sd 追加後)→ 解析解ベンチマーク:
  - F0 クリープ: ガウス丘の拡散(解析解。TODO 記載済み)
  - F1: (a) 平衡勾配到達(等流×給砂平衡)、(b) 給砂遮断の河床低下
    (線形化 Exner の解析解 or 水路実験)、(c) morfac 等価性
  - F2: 定常巻き上げ・沈降の平衡濃度プロファイル(1D)
  - 結合(§2.5): 一定雨×斜面浸食で、飽和到達時刻が sd 減少に応じて
    早まることの疎通確認(要件の直接検証)
- **save_version**: hs・sd 追加時に更新+utils/ の読み書きツール確認(§10)。
- **出力**: 時間発展する z(と dz、hs、sd)の dt_file 出力を
  output_matrix で新設(§11 の浸食 TODO (2))。プローブは z 対応済み、
  hs・sd を追加(m_record の「計測量の追加手順」)。
- **乾湿・特殊セル**: 乾燥エッジは τ=0 で q_b=0 が自然に成立。
  stage 規定セル・湧き出しセルは強制された h から τ を計算(受容)。
  海セル(sw)は対象外(海域の土砂は当面扱わない。gwflow と同じ整理)。
  gv < 1(建物)セルの浸食は床面積率 gv を乗じるか — 要検討(小項目)。
- **fill_depression との関係**: 初期地形は窪地処理後(s%z)。浸食は
  新たな窪地を作り得るが、動的計算では水が溜まるだけで破綻しない
  (初期化専用の fill と役割が違うことをコメントで明記)。
- **STG**: 全フラグで par_stop ガード(凍結方針。s%z の init 時コピーの
  ため構造的にも非対応 — コード内に明記済み)。
