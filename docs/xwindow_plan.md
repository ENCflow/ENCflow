## 1. 現状と目標

| 方向 | 計算範囲 | 確保範囲(現状) |
|---|---|---|
| y | 全域窓 jw1..jw2 = g%wy(有効セルの行±1)の中の担当帯 js..je | jsh..jeh = 帯±nhalo(逐次・MPI とも。§79 (B)) |
| x | 行ごとの列窓 g%wx(1:2, j) | **1..nx(全幅)** |

埋め込みケース(秩父 560×300 を 5600×3000 に埋め込み、マスク 1/100)の
最大 RSS は (B) で 7.8 GB → 1.8 GB。残りの内訳(概算)は

- 帯配列(窓の行 284 × 全幅 5600 × 8 B ≈ 12.7 MB/枚 × 約 40 枚)≈ 0.5 GB
- rank0 の全域配列(入力地形 g%z 134 MB、出力バッファ wk_out・wk_out_i 201 MB)
- 初期化の全域一時(入力読み込み・ts 系)のピークと、text 読み込みのバッファ

x 方向の窓(列 1/10)で帯配列は約 1/10 になるが、**rank0 の全域配列は残る**
(第二段 (D) の対象)。全国 250 m(6080 × 8960、倍精度)で見積もると

| 段階 | 帯配列 | rank0 全域(z, wk_out) | 合計の目安 |
|---|---|---|---|
| 改修前(全域確保) | 約 20 GB | 0.6 GB + 初期化ピーク | 23.5 GB |
| (B) y 窓(1/10) | 約 2 GB | 同上 | 約 3 GB |
| (C) x 窓(1/10)も | 約 0.2 GB | 同上 | **約 1 GB(全域配列が支配)** |
| (D) 全域一時の窓化 | 同上 | 窓読み込みなら ≈ 0 | 約 0.3 GB |

(C) 単独の効果は「y 窓で残る帯配列 2 GB → 0.2 GB」で、(D) と合わせて初めて
ノート PC 級(数 GB)に収まる。**(C) と (D) はセットで価値が出る**ことを
先に確認しておく(着手順は §6)。

## 2. 方式の比較

### 案 C1: 帯確保と同じ型で x にも確保範囲を持つ(推奨)

`dcp%ish/ieh` を新設し、帯配列を `a(dcp%ish:dcp%ieh, dcp%jsh:dcp%jeh)` で
確保する。**添字は全域のまま**(帯確保と同じ考え方: 配列の下限を変えるだけで、
セル (i, j) の番号・入出力・namelist の意味・save/restore の形式は不変)。

- 規則: `ish = max(1, iw1 − nhalo)`, `ieh = min(nx, iw2 + nhalo)`。
  iw1/iw2 = 窓の行 jw1..jw2 にわたる `min g%wx(1,j)` / `max g%wx(2,j)`
  (wx は有効セルの ±1 を含むので、ish..ieh は有効セルから 3 列の余裕)。
  番兵つき配列(g%x, g%sw)は j と同じく `ish−1..ieh+1`、エッジ配列
  `(k, 0:nx, jsh−1:jeh)` は `(k, ish−1:ieh, jsh−1:jeh)`。
- 窓 = 全幅(回帰テストの大半)では ish = 1, ieh = nx で従来と同じ確保。
- 検証の道具がそのまま使える: 1 始まりを仮定した箇所は `-fcheck=all` が
  必ず捕まえる(§79 の検証で使った埋め込みケース + np=1,2,4)。
- ランク間で ish/ieh は同一(x は分割しない)。MPI の halo 交換は行単位で
  `size(a, 1)` を使っているので不変。

### 案 C2: 入力時に格子を切り出す(不採用)

m_geoinfo_init で全域ラスタを読んだ後、窓の外接矩形に nx, ny, 原点を
付け替え、以降のモジュールには小さな格子として見せる。物理モジュールは
無変更で済むが、

- namelist で与えるセル番号(プローブ・測線・境界・構造物・湧出・ため池・
  規定底面運動の窓・ネストの子の位置・BMI の格子形状)を全てオフセットで
  読み替える必要があり、各 list_*/init に散らばる(漏れると**無言で位置が
  ずれる**。-fcheck では見つからない)。
- save/restore・分布出力は全域の形式を保つために埋め戻しが要り、
  リスタート時にマスクを変えると形状不整合になる。
- 「添字 = 全域のセル番号」という現在の不変条件(§11・§12)を壊す。

C1 は失敗が境界検査で機械的に見つかるのに対し、C2 の失敗は意味的で
見つけにくい。採らない。

### 案 C0: 確保はそのまま、窓の外に触らない(不採用)

`allocate(..., source = 0.0)` の零埋めをやめ、窓の中だけ初期化すれば、
Linux の mmap 確保は未アクセスページを物理メモリに割り当てないので
RSS は窓に比例する。しかし

- 全幅の書き込み(`s%e(:,:) = s%z + s%h`、`sx%mn1 = sx%mn`、scatter の
  `a(:, jsh:jeh) = buf(...)`、帯の切り出し `s%h(:,:) = ts%h(1:nx, …)`)が
  1 つでも残ると、そのページ群は全て実体化する。監査の対象は C1 と同じ
  だが、**漏れを検出する道具がない**(境界検査は効かない)。
- Fortran の規格上、未初期化確保の値は不定で、零初期化に依存するコードを
  OS の挙動で支えることになる(§0 の「言語標準のみ」に反する)。

## 3. C1 の変更点(機械的な置換と、意味を伴う箇所)

### 3.1 窓の決定と保持

- `calc_wxy`(m_geoinfo): wy と同時に iw1/iw2 を求め `g%wxg(1:2)` に置く。
- `par_decomp_init(nx, ny, jw1, jw2, iw1, iw2, rowwork, align)`: 引数を
  2 つ足し、`dcp%ish/ieh` を上の規則で設定(逐次・MPI とも同じ式)。
  **公開インターフェースの変更**なのでトップレベル make で utils の追随を
  確認する(§10)。`t_decomp` に ish/ieh を追加(ctx swap は型ごと写す)。

### 3.2 機械的な置換(件数は 2026-10-16 の grep)

| 型 | 件数 | 置換 |

| `allocate(a(1:g%nx, dcp%jsh:dcp%jeh))`(帯配列) | 約 160(m_state 36、nh 20、wq 12、enc 11、conduit 11、bldgdebris 9、bedslide 8、他) | `(dcp%ish:dcp%ieh, dcp%jsh:dcp%jeh)` |

| 帯の切り出し `s%h(:,:) = ts%h(1:g%nx, jsh:jeh)` | m_state の 8 行ほか | `ts%h(ish:ieh, jsh:jeh)` |

全域一時配列と帯配列の区別は `1:g%ny` か `dcp%jsh` かで機械的に判別できる
(上の grep の分け方そのもの)。

### 3.3 意味を伴う箇所(設計が要る)

1. **gather/scatter(並列層)**: 全域バッファ `buf(1:nx, 1:ny)` と帯配列の
   第 1 次元が違うので、`MPI_Gatherv` で buf の部分ブロックへ直接受けられない
   (受信は連続領域)。rank0 に窓形の受信用一時 `wbuf(ish:ieh, jw1:jw2)` を置き、
   受けてから `buf(ish:ieh, jw1:jw2) = wbuf` と写す(窓形なので小さい)。
   scatter は送信側が `buf(ish:ieh, jsh_r:jeh_r)` の部分配列を送る(非連続
   部分配列の copy-in は初期化 1 回きりなので許容)。逐次版は
   `buf(ish:ieh, js:je) = a(ish:ieh, js:je)` の 1 行。エッジの gather/scatter も
   同形。par_edge_merge の一時 `buf(size(a,1), size(a,2))` は不変。
2. **全幅ループ `do i = 1, g%nx` で帯配列に触るもの**: 時間ループ側は §79 で
   x 窓に揃えたが、初期化・補助の経路に残る(nh 33、channel 9、conduit 6、
   bldgdebris 5、snow 3、…。全域一時に対するものは除く)。
   `do i = dcp%ish, dcp%ieh` か `g%wx` に揃える。漏れは -fcheck が検出する。
3. **edge_row_span のクランプ** `max(i1, 0)` / `min(i2, nx)` →
   `max(i1, ish−1)` / `min(i2, ieh)`(wx は窓の中なので実質不変)。
4. **ネスト(m_nest)**: 子格子の作業配列 `n%inband(1:gc%nx, jlo:jhi)`、
   `n%ev(2, 4, 0:gc%nx, jlo−1:jhi)` と `m_swflow_enc_nest_import(nx, ny, jlo, jhi, …)`
   は子の全幅を仮定している。子にも ish/ieh(子の dcp 文脈)を通す。子の
   マスクが全域なら ish = 1 で現状と同じ。
5. **BMI get/set、record、output、save/restore**: いずれも gather/scatter 経由か
   全域添字のセル指定なので、1. が済めば無変更。窓外の値は gather の対象外 =
   バッファの確保時の 0(§79 と同じ挙動)。
6. **user フック**(user_geoinfo / user_initial)は全域一時に対する全域添字の
   契約のまま。帯配列に書くフックはない(§11)。
7. **窓外のセルを読むカーネルはないか**: y と同じ ±nhalo(2)の余裕を取り、
   番兵つきは +1。y の規則で足りているなら x も足りるはずだが、保証は
   -fcheck=all の np=1,2,4 で行う(規律 3)。

### 3.4 規約の追記(developer.md §11・§12)

- 「帯確保の配列を渡すダミーは assumed-shape+下限指定」を
  `a(dcp%ish:, dcp%jsh:)` に改める(§12)。
- 「ゾーン 2 で全域なのは z, x, sw, rw のみ」は不変。帯化の対象配列は
  x, y とも窓±ハロ(§11)。
- 帯の列範囲の規則(ish/ieh)と番兵・エッジの +1 の対応表を §11 に置く。

## 4. 検証計画

- 等価変換(規律 2): 既存 reference(窓 = 全幅が大半)はビット一致。
- 窓 ≠ 全幅の検証は §79 の埋め込みケース(scratch の生成スクリプト 1 本で

- 常駐メモリ: 埋め込みケースで 1.8 GB → 帯配列分の減少(目標 ≈ 1.3 GB。残りは

## 6. 着手順の提案

1. (C) を実装(本書)。効果は帯配列の 1/10 だが、(D) の前提になる(窓形の
   gather 用一時を rank0 に置く設計は (D) の「窓だけ読む I/O」と同じ形)。
2. (D) 初期化の全域一時の窓化: m_fileio に行・列範囲つきの読み込み

   形を保つ §0)ので、出力時だけ全域の一時を確保して書くか、窓を埋め込んで
   書く I/O を足す。
3. 前処理の切り出しユーティリティは (C)(D) と排他ではなく、データ配布の
   道具として別途あってよい。

## 7. 第二段 (D): 初期化の全域一時と rank0 全域配列の窓化(設計案。2026-10-16)

(C) の計測(developer.md §80)で、時間ループ中の常駐は 0.38 GB(帯配列は数十
MB)、初期化ピークは 1.2〜1.4 GB だった(埋め込みケース 5600 × 3000)。残る
全域配列の棚卸しと、どこまで窓化するかの案を示す。

### 7.1 棚卸し(2026-10-16 の grep。N = nx·ny、全国 250 m なら N = 5,450 万)

| 区分 | 配列 | 大きさ(倍精度・全国) | 寿命 |
|---|---|---|---|
| A. 時間ループ中も常駐(rank0) | 入力地形 g%z(`if (.not. is_root) shrink` の例外) | 8N = 416 MB | 常駐 |
| | 出力バッファ o%wk_out(real)・wk_out_i(int) | 12N = 624 MB | 常駐 |
| | 降水分布 pr%prmap(prtype=2) | 8N = 416 MB | 常駐 |
| B. 初期化の全域一時(全ランク) | マスク類 g%x(番兵つき)・g%sw・g%rw(int) | 12N = 650 MB | band_shrink まで |
| | 状態の全域一時 ts(h,u,v,z,hrs,hg,sd,hs) | 64N = 3.3 GB | m_state_init の間 |
| | 各モジュールの読み込み一時 wk(1 枚ずつ) | 8N | 読み込み中 |
| C. 初期化の全域一時(rank0 のみ。方式 2) | 係数 rn, gv, bb, lm, rscap(+sd, zbank, zswall, wrw, drw) | 5〜10 × 8N = 2〜4 GB | scatter_coeffs まで |
| D. save/restore(rank0) | m_state の wk(…, 6)、swflow_enc の wuv/wmn/wfd(4 × (nx+1)(ny+1)) | 48N + 3 × 32N ≈ 7.8 GB | save/restore の間 |
| E. BMI get/set の dest/src | 呼び出し側が全域形で渡す(API) | — | 外部 |

全国 250 m の初期化ピークは B + C(+ ts)で **6〜8 GB**、save 時に D の
7.8 GB が加わる。ノート PC(8〜16 GB)で「全域データ+流域マスク」を回すには、
時間ループの常駐(A)だけでなく初期化ピークと save/restore(B〜D)を落とす
必要がある。

### 7.2 方式

共通の考え方: **窓形の配列 = 下限 ish/jw1 の配列に、全域の添字で読み書き**
(帯配列と同じ型)。全域の形式を保つ入出力(§0)は、ファイル側を全域のまま
**行ストリーミング**で読み書きし、メモリには窓だけを置く。

- **D1. 常駐の窓化(A 区分)**
  - g%z: rank0 も band_shrink で窓へ(「入力地形の正本を rank0 が持つ」決定
    §11 を改める。初期地形との比較が要るときは、その処理が自分で窓を読む)。
    使う側は record の probe z・fill_depression・s%z = g%z・conduit の zbot で、
    いずれも窓内の全域添字 → 無変更。
  - 出力バッファ wk_out・wk_out_i: 窓形 `(ish:ieh, jw1:jw2)` にし、
    `fileio_write_matrix` に**窓つき書き出し** `(fname, nx, ny, i1, i2, j1, j2, a, fill)`
    を足す。text・GeoTIFF の書き出しは既に行ループ(GeoTIFF は無圧縮単一 strip の
    行書き)なので、窓外の行は fill 行、窓内の行は fill + 窓の値 + fill を 1 行の
    バッファで書く。bil は現状 real32 の全域一時に変換して一括 write しているので
    行ストリーミングに直す。gather は窓形へ直接受けられる(窓形の受信一時が
    そのまま出力バッファになり、§80 の「受けてから写す」1 回分が消える)。
    窓外の値は現状どおり 0(= §79 の挙動を仕様に格上げ。nodata にするかは
    handoff の別項目)。
  - prmap(prtype=2)・timap 系・tmap 系: 帯確保に(読み込みは D2 の窓読み)。
- **D2. 入力の窓読み(B・C 区分)**
  - 窓はマスクから決まるので、**読む順序を「マスク類 → 窓確定 → 実数ラスタ」**に
    する。m_geoinfo_init は現在 sw → mask → z → rw → 係数 の順で、calc_wxy は
    末尾。これを sw → mask → (adjust と user フックのうちマスクを変えるもの) →
    calc_wxy → z・rw・係数 の順に並べ替える。rw はマスクに影響しない
    (adjust_rw は z を掘り下げる)ことを確認して窓読みへ。
  - `fileio_read_matrix` に**窓つき読み** `(fname, nx, ny, i1, i2, j1, j2, a)` を
    足す。text は行バッファ(nx)に 1 行ずつ読んで窓の列を写す(全行を読む時間は
    変わらない)。bil は行オフセットで窓の行だけ読む(ストリーム access の pos=)。
    GeoTIFF は decode_blocks が strip/tile 単位で復号しているので、ブロックから
    窓に重なる部分だけ写す(窓に重ならないブロックは復号を省ける)。
  - 係数(方式 2)は rank0 が窓形で読み、scatter_band_r は窓形→帯で従来どおり。
  - **マスク類(x, sw, rw)は全域のまま読む**(int。窓を決めるために全域が要る。
    全国でも 650 MB)。band_shrink までの寿命は変えない(ゾーン 2 の「z, x, sw, rw は
    全域添字で参照できる」契約 §11 は、x・sw・rw について維持し、z は窓形に
    変わる)。z を全域で参照するゾーン 2 の処理は fill_depression(窓ループ)と
    probe の z 取得(窓内)だけで、どちらも窓形で足りる。
  - **ts(状態の全域一時)**: 窓形 `(ish:ieh, jw1−2:jw2+2)` にする(全ランク同形
    のまま → par_bcast_cell の契約は保てる)。fill_depression・adjust_h0rw・set_uv
    は wy/wx の窓ループなのでそのまま。user_initial / user_geoinfo フックは
    「全域添字で書く」契約のまま、**ループ範囲を配列の lbound/ubound で回す**
    (現状 `do i = 1, g%nx` が 26 箇所。理想化ケースの窓は全域なので値は不変)。
  - 読み込み一時 wk(各モジュールの初期分布・パラメータ分布)は窓読みに
    置き換える(型は同じで 40 箇所ほど。1 枚ずつなのでピークへの寄与は小さく、
    後回しでもよい)。
- **D3. save/restore のストリーミング(D 区分)**
  - save: ゼロ抑制 RLE の符号化を「窓形配列 + 全域寸法 + 窓外は 0」から直接
    行う(窓外は長いゼロ連になるだけ)。gather は窓形へ。
  - restore: 復号を run ごとに進め、平坦添字から (i, j) を求めて窓内だけ格納する
    (時間は O(N)、メモリは O(窓))。全ランク同形の全域一時 ts への Bcast 配布は、
    ts が窓形になれば同じ経路のまま。swflow_enc の wuv/wmn も同形(エッジ配列は
    `(k, 0:nx, 0:ny)` → 窓形 `(k, ish−1:ieh, jw1−1:jw2)`)。
  - ファイル形式(全域の要素数・run 表)は不変 = 旧 save との互換を保つ。
- **D4. マスクの全域読みの回避(任意。全国級・多ランク向け)**
  - 行ストリーミングで x・sw を走査して窓だけ決め、x・sw・rw も窓形で読む。
    ゾーン 2 で x・sw・rw を全域添字で読む箇所(境界・湧出・プローブの位置検証、
    count_valcells、row_ncells、output_maskfile)を窓内判定つきに直す必要があり、
    件数が多い。多ランク/ノードでマスクの冗長読みがボトルネックになってから。

### 7.4 変更範囲と順序

1. **D1**(効果が大きく局所的): band_shrink の rank0 例外を外す(1 行)、

### 7.5 決めておきたいこと

- g%z の「rank0 が入力地形の正本を持つ」(§11)をやめること(D1)。
- 窓外セルの分布出力値を 0 に**仕様として**定めるか、nodata(例 −9999)を
  導入するか(D1 の fill 引数で切り替え可能にしておけば後から選べる)。
- user フックの契約文言を「全域添字で、配列の範囲(窓)の中に書く」に改めること(D2)。
- text 形式の入力は窓読みでも全行の読み時間が残る(全国 text 3 枚 ≈ 60 s)。
  これは形式の性質で、大規模運用は bil/GeoTIFF を推奨する旨を利用者ガイドに書く。
