## 1. 要件の整理(発端の要望)

1. ダムを拡張して「ダム・湖沼」とする。**名称は dam_ のまま**、
   ドキュメントで「一般の湖沼も同機構」と明記する。
2. ラスタで湖形状が解像している場合: **湖沼番号で水面を塗った
   ラスタファイル**を読み、namelist で該当番号の詳細(現行ダム諸元を
   含む)を指定する。
3. 水位を共有する湖沼群(飛び地の水面が1つの水位を持つ)を表現できる
   こと(現行実装でも可能だが、ダム湖ではありえない状況なので
   湖沼としての明文化)。
4. ラスタで解像しない場合: 現行ダムと同様の**捕捉ライン**状の湖面を
   指定する(斜め透過に注意)。指定はラスタファイルでも行えること。
5. **dam_area(湛水面積の直接指定)は廃止**し、セル数×セル面積に統一。
   蒸発はセル毎。
6. 放流セルは現行と同じ指定法。複数セル(離れていてもよい)は
   セル数で等分配。
7. 一つの湖沼に運転モードの異なる**複数の放流セル群**を設定できるか
   — 要検討。
8. **放流セルを設定しない湖沼**: 流入水は全て消失、水位は指定水位で
   一定(蒸発でも減らない)。
9. 一般湖沼の**水位の指定法**: 湖水面標高は資料から入手可能。
   ダムの HV 指定とどう整合させるか。HV 無指定なら放流率 1.0 か?
10. 琵琶湖級の大湖沼で「流入即流出」として問題が生じないか。
    遅延の実装は影響が大きすぎるか?
11. 湖沼と隣接するセルの**地下水位への水位強制**は難しいか — 要検討。

## 2. 現行実装の確認(拡張の土台)

- ダムの状態は **s%hrs のみ**(捕捉帯セルへ体積等分・save/restore は
  既存機構で完結。developer.md §22)。捕捉帯は「到達水を毎ステップ
  全量吸収」、放流は dam_operate が V(決定的総和 par_sum_rows)から
  引き落とし体積を決め、担当帯の hrs を比例縮小 → 放流セルへ
  **セル数等分**(m_swflow_enc_bc の dam 節。要件 6 は実装済み)。
- 捕捉帯セルは複数・飛び地可(cin リスト)。**要件 3 は現行機構で
  既に成立**しており、仕様化(ドキュメント明記+検証ケース)だけが残る。
- HV 曲線は入力必須(地形は貯水池を表さないため。§22)。
  dam_h_of_v / dam_v_of_h は折れ線の相互補間。
- ため池(g%rscap>0)は「セル毎の限界貯留高までの吸収+あふれ」の
  独立機構。ダム捕捉帯とは併用不可。
- 海域マスク(sw>0)は「解かない・水位を強制する」無限容量リザーバ
  (§23)。**要件 8 の放流なし湖沼は、これの内陸版**にあたる。
- 整数ラスタの読み込み先例: fn_mask / fn_sw / fn_rw(方式は §11 の
  ライフサイクル。全域リストの抽出は rank0 で行い既存の cin/cout
  リスト機構へ落とせる)。
- 地下水(fn_gwflow)は hg(柱状換算水量)を状態とし、側方流
  (Boussinesq 8近傍 FV)は全水頭 H = (z − sd − dbot) + hg/sy [+ s%h]
  で駆動される(m_gwflow_lateral ヘッダ)。

## 3. 基本設計: 湖沼=「捕捉集合が水面全体に広がったダム」

拡張の核はただ一点で、**捕捉集合の指定法にラスタ(湖沼番号)を
加える**ことである。バケツ表現・hrs 共有・運転ルール・放流分配・
MPI の決定的総和は現行のまま使う。湖面の力学(吹送流・セイシュ・
背水)は解かない(バケツの湛水面非表現は湖沼でも同じ。§0 の
「鉛直・サブプロセスは抽象化」の水平版として明記する)。

### 3.1 湖面・捕捉集合の指定(3方式の択一。構造物番号ごと)

| 方式 | パラメータ | 用途 |
|---|---|---|
| (a) namelist セルリスト | dam_in_cell(:,k,n) | 現行。少数セルの捕捉ライン |
| (b) セル一覧ファイル | fn_dam_in_cell(n) | 現行。長い捕捉ライン |
| (c) **湖沼番号ラスタ(新設)** | fn_dam_map(1枚) | 解像湖面・捕捉ライン共用 |

- fn_dam_map は領域全体で1枚の整数ラスタ。値 0 = 湖沼なし、
  値 n = 構造物番号 n の湖面(捕捉集合)。1つの番号が飛び地でもよい
  (=水位共有湖沼群)。同一セルに複数番号は物理的に書けないので
  重複検査は不要。番号は現行どおり 1 からの連番。
- ラスタに現れる番号は namelist 側に対応する定義(運転モード等)が
  必要(不在は par_stop)。逆に namelist だけの番号は (a)(b) で
  捕捉集合を持つこと(3方式のいずれも無ければ現行どおりエラー)。
- 実装: rank0 が全域を読み、番号別セルリストへ抽出して既存の
  cin 機構に接続する(ゾーン1の全域前処理。m_geoinfo_init 内でなく
  init_structure 側で読む — 構造物ファイル群の一部のため)。
  既存の検証(領域内・ため池/河道幅との併用不可・海域除外)を通す。

**解像湖面の地形との関係(既知の妥協として明記)**: DEM が湖水面標高を
持つ場合、湖面セルは「その標高の乾いた平地」として扱われ、流入は
河道水位が湖面標高を上回った分だけ湖面セルへ進入 → 即吸収される。
流入判定の実効しきい値が DEM の湖面標高で固定され、貯留水位
(H = HV⁻¹(V))とは連成しない。バケツ近似の範囲内として許容する
(前処理での湖底掘り込みは不要 = 「物理量は直接与える」)。

### 3.2 捕捉ラインの斜め透過(要件 4)

ENC 格子は対角リンクでも水をやり取りするため、捕捉集合が対角接続
だけでつながる箇所では、**両端とも集合外のセルを結ぶ対角リンク**が
帯をすり抜ける(堤防の対角エッジ問題と同根。users_guide/channel.md)。
吸収はセル到達水に対して働くので、壁と違いエッジ側での対処はできない。

- **仕様(2026-08-20 決定)**: 捕捉集合は4近傍連結で指定する(斜め
  接続の角を作らない)。**プログラムでは検査しない — 利用者の責任**とし、
  ドキュメント(構造物章・サンプル)に注意書きを明記する(堤防の
  fn_bank と同じ「角接触の漏れ」系の注意として記述)。

### 3.3 HV の整合(要件 9)

| 指定 | 挙動 |
|---|---|
| dam_hv あり | 現行どおり(ダム。資料の HV 曲線) |
| dam_hv なし+湖面指定あり | **線形 HV を自動構成**: A = 捕捉セル数×dx×dy、V(H) = A×(H − dam_hmin)。dam_hmin(計算下限水位=死水位、標高 m)が必須。dam_hsur(サーチャージ相当)は任意 — 未指定なら上限なし(スピルなし)。ただしモード 1, 2(但し書きランプが Vmax を要する)では必須 |
| dam_hv なし+dam_hmin なし | par_stop(現行どおり。黙って既定値をでっち上げない) |

- 水位はすべて**絶対標高**(現行 HV・dam_h_init と同じ基準)なので、
  資料の湖水面標高(平常水位)は dam_h_init にそのまま入る。
- **dam_hmin はダムでは不要**: dam_hv を与える構造物では HV の第1点が
  最低水位そのものであり、dam_hmin は「dam_hv を書かない場合の代替」
  専用。dam_hv と dam_hmin の同時指定は par_stop(二重指定の矛盾を
  知らせる)。
- **水深不明の湖沼こそ自動線形 HV の想定対象**で、水深・湖盆形状の
  情報は不要。線形 HV では力学が A·dH/dt = Qin − Q(H) となり
  dam_hmin に依存しない(V の定数シフト=「放流で引き落とせない床」の
  位置を決めるだけ)。平常水位より確実に低い値(例: 平常水位 − 5 m)を
  置けば、床に当たらない限り結果は dam_hmin に厳密に無感度 —
  この設定指針をドキュメントに明記する。
- **平常水位の入り先**(指定値ではなく初期値+維持機構、という整理):
  - 水位固定湖沼(放流なし): dam_h_init がそのまま固定水位。
  - 貯留湖沼: 初期水位 dam_h_init = 平常水位。定常の平常水位は
    H-Q rating との釣り合いで決まる(rating の Q=0 水位=流出敷高を
    平常水位付近に置けば平水時にそこへ落ち着く)。資料で得られる情報
    (湖水面標高+流出河川の敷高または H-Q)だけで設定が閉じる。
  - 素通し湖沼(rate 1.0): 水位という状態を持たない(指定不要)。
- 自動線形 HV は「湖岸勾配を無視した鉛直壁の湖盆」近似。水位変動幅が
  湖の深さ・湖岸幅に比べ小さい一般湖沼では十分で、ダム湖のように
  変動幅が大きい対象は従来どおり dam_hv を与える、という住み分けを
  ドキュメントに明記する。
- 「HV 無指定なら放流率 1.0」の暗黙既定は**採らない**(推奨)。
  素通し湖沼は `f_dam_mode = 2, dam_rate = 1.0` の2行で明示する
  (§0「黙って既定値をでっち上げない」の系。誤って HV を書き忘れた
  ダムが無減衰素通しになる事故を防ぐ)。素通し指定時は貯留が動かない
  ので、HV・dam_hmin なしでも受理する(V ≡ 初期値、CSV の H は
  dam_hmin 未指定なら欠測値)。

### 3.4 放流なし湖沼=水位固定湖沼(要件 8)

dam_out_cell / fn_dam_out_cell とも未指定(現行はエラー)を
「水位固定湖沼」として受理する:

- 流入(捕捉帯吸収)は**全量消失**(貯留しない)。蒸発・降雨も湖水位を
  動かさない(湖面セルの hrs は常に 0 のまま=個別蒸発の対象外)。
- 水位は dam_h_init で与える固定値(現状この値を使う計算はないが、
  CSV 出力と第3弾の地下水強制(§7)の水頭源になる)。
- HV・運転モード不要(指定されていたら par_stop で矛盾を知らせる)。
- CSV には Qin(消失量)を記録し、収支監査を可能にする。
- 意味論は海域マスクの内陸版(流入=消滅)だが、sw と違い momentum は
  湖面セルを普通に解く(即吸収なので実質乾燥面)。「解かない大水面」
  として琵琶湖を隣接流域の計算から除外する、といった用途にも使える。

### 3.5 複数放流セル群(要件 7。第2弾を推奨)

1湖沼に運転モードの異なる複数の放流工(例: 琵琶湖の瀬田川洗堰+
琵琶湖疏水+宇治発電所取水)を許すには、「貯留体(湖)」と
「放流工(運転)」を分離する必要がある。namelist の配列次元を増やす
(dam_out_cell を rank-4 化)のは書式が壊滅するので、**参照方式**を
提案する:

- `dam_lake(n) = m` : 構造物 n は自前の捕捉集合を持たず、湖沼 m の
  貯留から n 自身の運転モード・放流セル群で引き落とす。
- 吸収・貯留・HV は m だけが持つ。引き落としは番号順に逐次適用
  (順序固定=決定的。同一ステップ内の競合は「先の構造物が先に取る」
  と仕様化し、死水下限は共通に効く)。
- CSV は構造物ごとに出す(湖の V・H は共通値)。

最小の namelist 変更で表現力が足り、第1弾(1湖沼=1放流群)とは
独立に追加できるため**第2弾に回す**ことを推奨する。

### 3.6 dam_area の廃止(要件 5)

- 蒸発は「捕捉帯セルのセル面積分ずつ」(現行の dam_area 未指定時の
  挙動)に一本化する。解像湖面なら セル数×セル面積=湛水面積 なので
  旧 dam_area の存在理由(捕捉ラインでは湛水面積を過小評価する)は
  「湖面をラスタで塗る」ことで解消される — これが廃止の正当化。
  捕捉ライン型のまま湛水面蒸発を評価したい場合も、湖面を塗る方式に
  移行してもらう。
- 互換処理(2026-08-20 決定): **namelist から削除するだけ**でよい。
  旧入力に dam_area が残っていれば namelist 読込エラー(iostat>0)で
  par_stop する(旧 f_gwmodel 廃止と同じ検出方式。専用の移行案内は
  作らない)。
- m_evap の dam_area 系機構(skip マスク・vdam・E×面積の比例配分)は
  削除する。m_wq のダム台帳は dam_area 非依存(全ダム対象)なので無変更。

## 4. 大湖沼の「流入即流出」問題(要件 10)

結論: **遅延ルーティングは導入しない**。理由は3点。

1. 洪水応答の第一支配項は**貯留減衰**であり、これはバケツ+
   自動 HV(A=湖面積)+水位依存放流(モード3の H-Q rating)で
   自然に表現される: A·dH/dt = Qin − Q(H)。琵琶湖(A ≈ 670 km²)なら
   流入 1,000 m³/s の超過で水位上昇は約 13 cm/day であり、
   「流入即流出」にはならない。即時なのは湖内の水の再配分だけである。
2. 湖内の重力長波は √(gD)(D = 40 m で約 20 m/s、湖長 60 km を
   1時間弱)で伝わり、日単位の洪水波に対して十分速い。伝播遅れを
   無視する誤差は貯留減衰に対して二次的。
3. 遅延(湖内ルーティング)の実装は履歴状態(save 形式変更)と
   パラメータ(伝播時間の同定)を持ち込み、§0「過度に複雑化しない」に
   反する。どうしても必要な事例が出たら、**湖を複数の湖沼+接続
   構造物に分割**すれば既存機構の組合せで表現できる(新機構不要)。

ドキュメント側の注意書き: 大湖沼に素通し(rate 1.0)を使うのは
不適切(無減衰で洪水波が透過する)。素通しは滞留の無視できる
小湖沼・遊水地の連絡水面用とする。

なお水質(m_wq)のダム台帳は放流濃度 0 の清水放流であり、湖内滞留
時間・混合は表現しない。湖沼でも当面同じ扱い(将来課題として台帳に
濃度状態を持たせる案だけ記す)。

## 5. パラメータ仕様案(&list_struct_dam の増減分)

| パラメータ | 既定 | 意味 |
|---|---|---|
| fn_dam_map | "" | **新設**。湖沼番号ラスタ(1枚。0=なし、n=構造物 n の湖面)。番号ごとに (a)(b)(c) 三方式の択一 |
| dam_hmin(n) | — | **新設**。自動線形 HV の下限水位(標高 m)。dam_hv 未指定の貯留湖沼で必須 |
| dam_hsur(n) | なし | **新設**。自動線形 HV のサーチャージ水位(標高 m)。未指定=スピルなし(モード 1, 2 では必須) |
| dam_lake(n) | 0 | **新設(第2弾)**。>0 で湖沼参照(自前の湖面を持たず番号 m の貯留から放流) |
| dam_area(n) | — | **廃止**。指定されていたら par_stop で移行案内 |
| dam_out_cell / fn_dam_out_cell | 変更 | 未指定を「水位固定湖沼」として受理(現行は必須) |
| その他(dam_hv, f_dam_mode, dam_q0/rate/hq_rule/ori_*/qmax/zbase, dam_tadashigaki, dam_h_init) | 不変 | 現行どおり |

ドキュメントは章題を「ダム・湖沼(&list_struct_dam)」へ改め、
冒頭で「ダム湖に限らず一般の湖沼(自然湖・潟湖・調整池群・水位共有の
湖沼群)を同機構で扱う」と明記する(要件 1, 3)。

## 6. 実装しないこと(明示)

- 湖面の力学(吹送流・セイシュ・背水・湖内水位勾配)— バケツの範囲外。
- 湖内ルーティング(遅延)— §4。
- 湖内の水質滞留・混合 — 現行台帳のまま。
- ゲート開閉速度・予備放流等の時系列運用 — ダム第2弾課題のまま不変。

## 7. 地下水位への水位強制(要件 11。第3弾を推奨)

湖沼に隣接する帯水層の地下水頭を湖水位に固定する Dirichlet 境界。
干拓地・湖岸低地の内水解析で意味を持つ。

- **定式**: 湖面セル(捕捉集合)で全水頭を湖水位 H_lake に固定する。
  側方流カーネルの水頭は H = (z − sd) + hg/sy [+ s%h] なので、
  セル規定値方式では hg_forced = min(cap, sy·(H_lake − (z − sd)))
  を毎(サブ)ステップの前後に設定し、差分体積を交換量として計上する。
- **段階 (i)(推奨)**: hg ≤ cap の制約から、H_lake > z の過圧
  (湖水深分の押し込み)は表現できず「全飽和=水頭は地表面まで」で
  頭打ち。**カーネル(lateral_core)は不変**なので、無効時のビット
  一致が構造的に保証され、実装は小さい。
- **段階 (ii)(必要なら)**: カーネルに optional の強制水頭配列を
  追加して過圧も表現。侵襲的(層1・層2・conduit の3カーネル共通部に
  触れる)なので、(i) の効果を見てから判断。
- **質量計上**: Δhg×gv×セル面積 を行部分和 → par_sum_rows で湖沼へ
  (貯留湖沼: V から加減。死水下限と衝突したら強制を縮める。
  水位固定湖沼: 計上のみ=消失/湧出)。CSV に Qgw 列を足す。
- **時相**: gwflow は dt_gwflow のサブサイクル、ダム操作は dt。
  強制は gwflow 側の周期で適用し、湖水位はステップ開始値を使う
  (他の時系列境界と同じ時相)。
- **有効化**: 湖沼別フラグ(例 dam_gw(n) = 1)。無効時は配列を確保
  しない(§0 方針8)。gwflow 無効時に指定されたら par_stop。
- **難易度評価**: 「難しくはないが独立に検証すべき」。危険箇所は
  (a) 決定的総和の順序(§11 の par_sum_rows 定型で回避)、
  (b) restore 整合(強制は毎ステップ再適用の純関数=履歴なしで安全)、
  (c) 乾いた隣接セルへの急勾配(既存の exflux 縮小が効くが、
  dtcheck の層厚上界に H_lake − (z−sd) を含める必要)。
  第1弾に混ぜず**第3弾**として分離する。

## 9. 要決定事項(全項決定済み 2026-08-20)

1. **素通しの明示指定**: `f_dam_mode=2, dam_rate=1.0` の明示。

   実装しない。— 承認。
