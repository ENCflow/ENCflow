## 0. 結論(要約)

- **オイラー的な「流木量のラスタ場」方式**: 流木を個別の剛体として
  追跡せず、セルごとの柱状材積(m3/m2 = m。貯留の意味論は h・hs と
  同一)として概算する。個別流木のラグランジュ追跡は §0 方針2
  (ラスタ純化)により持ち込まない(§1 で対象外を明言)。
- **3つの台帳**で流木のライフサイクルを表す:
  **立木ストック wst**(不動。入力ラスタ)→ 流木化 →
  **流動流木 s%hd**(水・土石流と同速で移流)→ 接地・乾燥 →
  **堆積流木 dep**(不動。再流動あり)。
  総和 Σwst + Σhd + Σdep + 系外・施設捕捉 が機械精度で閉じる。
- **輸送は既存 advect_scalar の流用**(新規の輸送コードなし)。
  水柱と同じエッジ流量 mn1 が運ぶ = 固液同速の単相近似(f_debris の
  hs と同水準)。土石流時は h+hs の混合体と同速で hd も流下する =
  「土石流と流木の混合流れ」は追加実装なしで成立する。
- **発生(流木化)は2経路**: (a) 水理的流失(浸水深×流速の閾値
  超過で立木が倒伏・流失)、(b) 侵食連行(河岸・渓床の侵食深が
  根系深を超えたセルの立木が土砂もろとも流失)。(b) は z の低下と
  いう事実だけを見るため、f_fluvial / f_debris / f_slide / f_release
  のどの侵食・崩壊とも**専用フックなしで自動連動**する。
- **停止は接地判定**: 喫水 hf = dw_sglog・dw_dlog(円柱の浮力平衡。
  経験定数なし)を下回る水深で堆積台帳へ(f_dbstop=1 と同型の
  レート式 = 数値的閉包)。再流動はヒステリシス付きの閾値則
  (既定は再流動なし = 安全側)。
- **運動量・抵抗への流木の算入はしない**(第1段)。§0 方針4
  (複数プロセスの同時概算)に従い、まず「どこから発生し、どこへ
  どれだけ到達・堆積するか」の面的評価を成立させる。
- **新モジュール m_driftwood**(fn_driftwood で有効化。加算的
  プロセス = 独立フラグの重ね合わせ。実装様式は m_wq に倣う)。
  無効時はメモリ・CPU ゼロ追加(方針8。無効時ビット一致で検証)。

## 1. スコープの線引き(有効化しないものの明言。debris_plan §5.1 と同型)

- **対象内**: 洪水・氾濫・土石流に同伴する流木量の面的な発生・
  輸送・堆積・再流動。流木の到達範囲・堆積量・通過量(被害
  ポテンシャル)の分布評価。砂防施設・遊砂地の流木捕捉効果の
  「施設あり/なし」2ケース比較(捕捉の上限側評価。ビット再現に
  よる差分の切り分けは users_guide/geomorph.md の砂防施設の流儀)。
- **対象外(有効化しない)**: 個別流木の軌跡・配向・回転・相互作用
  (ラグランジュ剛体追跡 = ベクトルベース。§0 方針2。iRIC の
  Nays2D 系流木モジュールや IberWood の領域 → 必要なら外部連携)。
  橋梁・スリット堰堤での幾何的閉塞判定(部材長 vs 開口幅の選択
  捕捉 — 透過型堰堤で既に「表現できません」と明言している線と同じ)。
  流木の衝突力評価。閉塞に伴う水位上昇の動的連成(第1段では対象外。
  閉塞の効果は開口を狭めた地形・カルバートのシナリオ与件 =
  2ケース比較で近似する。動的閉塞則は §6-6)。
- **抽象化(当面定数)**: 流木は単一の代表諸元(代表直径 dw_dlog、
  材比重 dw_sglog)で表す(径級・樹種の多クラス化は将来。土砂の
  多粒径と同じ扱い)。流動流木の移流速度は鉛直平均流速と同速
  (share=1。表層集中による増速は表現しない — 固液同速と同水準の
  近似として文書化)。流木相互のジャミングなし。

## 2. 文献照合の状態(§19.8 の方針の適用)

**照合更新(2026-08-21)**: ユーザー提供の Braudrick & Grant (2000,

  円柱浮力平衡(円形セグメント面積の超越方程式)を init の二分法で
  解く。当初の線形近似 hf = sg・D は sg=0.5 でのみ厳密だった

- **裏付けを得たもの**: 接地判定(h < 喫水 = buoyant depth 概念)、
  長さ非依存の抽象化(L < 川幅では部材長は移動限界に有意に効かない
  — 理論・水路実験の両方)、堆積流木の既定不動(rootwad 付き・
  流向平行の安定性と整合)
- **校正のまま残るもの**:
  - 再流動の dw_rfloat・dw_vfloat(同論文式(4)は μ_bed・Cd・配向
    依存で単一閾値に還元不能。実測の目安: 平行・rootwad 付きは
    d/d_b ≈ 1.2 で移動、斜交は d_b 未満でピボット移動)
  - 水理的流失の閾値(dw_hrec, dw_vrec)と流失レート(dw_wrec)—
    立木の倒伏・流失は同論文の対象外。候補: 国総研の流木対策計画
    関連資料・砂防学会の流木研究(治水経済調査・家屋流失基準の系譜)
  - 根系深 dw_droot と侵食連行の関係(全量流失は単純化)
- 未照合分は §28 と同じ運用(コードコメントと本書に【要文献照合】を
  明記し、人間の文献確認後に確定)。

## 3. 設計

### 3.1 状態量と台帳

- **s%hd**(t_state に追加): 流動流木の柱状材積 (m3/m2 = m)。
  advect_scalar の契約どおり柱状量(セル内材積 = hd×gv×wfrac×A)。
  **fn_driftwood 指定時のみ確保**(s%sd と同じファイル指定判定。
  方針8)。ハロ交換はステップ頭の s%hs / s%cq と同じ並びに
  `if (s%dw_active) call par_halo_cell(s%hd)` を追加。
- **s%wd**(t_state に追加): 堆積流木 (m3/m2)。m_output がフレーム
  出力を読むため t_state に置く(swe/swi と同じ理由。更新・保存の
  所有は m_driftwood)。確保は fn_driftwood 指定時のみ。
- **モジュール私有の帯配列**(m_driftwood 内。dw_active 時のみ確保):
  - wst: 立木ストック (m3/m2)。入力ラスタ fn_dwstock(全域 matrix。
    fn_hinit と同形式)を rank0 が読んで scatter(方式2。§11)。
    森林簿・林相図からの材積換算は前処理(§0 方針11・12。
    utils/GIS 側)。
  - zref: 侵食連行の基準地形(init 時の s%z の写し)。
- **s%dw_active**(logical。m_driftwood_init が設定。sed_active /
  wq_active と同じ様式)。
- 単位は材積のみ(単一クラス)。本数・質量への換算は後処理
  (派生量は内部生成しない — §0 方針12)。

### 3.2 モジュール構成(m_wq 様式の加算的プロセス)

- **m_driftwood**: 発生・停止・再流動・台帳・診断を担う。移流本体は
  m_swflow_enc のステップ内輸送(advect_scalar)が担う分担
  (m_geomorph_suspend / m_wq と同じ頭書きの分担)。
- **有効化**: fn_driftwood の指定(&list_driftwood。f_dw=0 で一時
  無効化)。ENC 格子のみ(wq と同じ)。
- **list_driftwood.f90**: namelist を読むだけ。解釈・検証・導出は
  m_driftwood_init(§12 の層契約)。
- **m_swflow_enc への追加は分岐2つのみ**:
  ステップ頭ハロ交換(上記)と、hs/cq/hss の並びに
  `if (s%dw_active) call advect_scalar(p, g, s, sx_mod, s%hd, sx_mod%hd1)`
  (書き込み先 sx%hd1、complete で s%hd へ確定 — hs1/cq1 と同じ
  意味論)。境界流入濃度(上流域からの流木流入)は第1段では持たない
  (cbin なし = 清水流入。区間流入の流木時系列は将来。§6-7)。
- **m_driftwood_calc の呼び出し位置**: 時間ループ内、geomorph calc の
  **後**(同一ステップの z 更新を見た侵食連行にする。1ステップ遅れでも
  可だが、順序を決めて文書化する)。周期は毎ステップ(セル局所の
  閾値判定のみで軽量。dt_dw の間引きは不要と見込むが計測で確認)。
- **更新は自帯 js..je のみ(owner-compute)**。発生・停止・再流動は
  すべてセル内交換(hd ⇄ wst/dep)で近傍を読まないため、
  **エッジ・ハロ・collective 一切不要**(suspend と同型。§28.2 の
  2パス規約の適用外であることを明記)。

### 3.3 発生(流木化)

- **(a) 水理的流失**: wst > 0 かつ h+hs > dw_hrec かつ vv > dw_vrec の
  セルで、wst → hd をレート dw_wrec (m3/m2/s) で移す
  (fx = min(wst, dw_wrec・dt)。レート式は数値的閉包【独自】、
  閾値は【要文献照合】)。判定水深を h+hs(混合流動深)とするのは
  f_out_dmax と同じ理由(土石流では h のみだと過小)。
- **(b) 侵食連行**: ecum = max(zref − z, 0)(累積侵食深)が
  dw_droot(根系深)を超えたセルで wst 全量 → hd。z の低下という
  事実だけを見るため、掃流(f_fluvial)・土石流(f_debris)・崩壊
  (f_slide / f_release)のいずれが原因でも自動で効く
  (モジュール間フックなし。geomorph 無効なら z は不変で発生しない =
  水理的流失 (a) のみが働く)。
  - 全量/比例の選択は §6-2。叩き台は「全量」(根系より深く抉られた
    立木は根系ごと流失する、の単純化)。
  - 発生済みセルは wst=0 なので再判定は自然に停止(発火フラグ不要)。
- **乾燥セルの繰り入れ**: h ≤ dd のセルの hd 全量を dep へ
  (suspend の乾燥繰り入れと同型)。

### 3.4 停止・堆積・再流動

- **喫水**: hf = dw_sglog・dw_dlog(導出。§2)。
- **接地堆積**: h+hs < hf または vv < dw_vstop のセルで、
  hd → dep をレート dw_wstop で移す(f_dbstop=1 の低速凝集と同型の
  数値的閉包【独自】。瞬時全量にしないのは、通過中の浅瀬で全量が
  落ちる過敏さを避けるため)。
- **再流動**: h+hs > dw_rfloat・hf(浮遊余裕率。既定 1.5 目安)かつ
  vv > dw_vfloat のセルで dep → hd をレート dw_wfloat。
  **既定 dw_wfloat = 0 = 再流動なし**(安全側 = 捕捉・堆積の上限側。
  ヒステリシス(rfloat > 1)は接地⇄浮遊の毎ステップ振動を避ける)。
- **dep は z に足さない**(第1段)。流木堆積厚は土砂に比べ薄く、
  地形としての固定(通水阻害)は動的閉塞(§6-6)と一体で議論する。

### 3.5 構造物・境界との関係(既存機構の挙動を確認して文書化)

- **ダム捕捉帯**: 毎ステップ全量吸収に流木も同伴し、ダム別台帳へ
  移す(m_wq のダム同伴と同じ契約。放流流木 0 = 既知の妥協)。
- **カルバート・ポンプ**: 清水のみを転送し流木を運ばない(既存仕様の
  帰結)→ 施設上流に滞留 = 捕捉の上限側評価。透過型堰堤の近似
  (users_guide/geomorph.md)と同じ流儀で文書化する。
- **堤防(bank)・越流**: hs と同様、越流時は実フラックスで hd も
  一緒に越える(advect_scalar が mn1 で運ぶ帰結。追加実装なし)。
- **開境界からの流出**: advect_scalar の系外流出として台帳に残差
  計上(§3.6)。流入は清水(hd=0。§3.2)。

### 3.6 出力・診断

- フレーム出力(f_out_* 指定時のみ確保・出力。§28.9 と同じ
  ゼロコスト様式):
  - f_out_hd: 流動流木 Hd0001…
  - f_out_wd: 堆積流木 Wd0001… と期間最大の到達量
    Wd9999 = max(hd+dep)(流木ハザードの本体。被害想定の一次指標)
- **result/driftwood.csv**(rank0、dt_recrd 間隔): ストック残・
  流動・堆積・ダム捕捉・系外流出(収支残差として台帳化)。
  総和は par_sum_rows(決定的。§11)。
- 測線の流木フラックス列(m_record)は将来(§6-7)。
- **save**: モジュール私有 driftwood.dat(hd, wd, wst, zref の4成分。
  §7 契約C。state.dat の形式・save_version は不変。台帳 CSV の累積は
  ラン先頭からの積算 = restore でリセット(wq.csv と同じ))。
  ※ s%hd を state.dat でなく私有ファイルに置くのは s%cq(wq.dat)の
  前例に合わせる。restore では自ファイルの有無のみ確認し、無ければ
  par_stop(版・格子・精度の検証は m_state が済ませている)。

### 3.7 排他・ガード(init)

- ENC 格子のみ(STG は par_stop。wq と同じ)。
- f_debris / f_suspend / f_fluvial / gwflow との**併用可**(排他なし。
  hd は独立台帳で、hs の E-D とは相互作用しない)。
- **morfac ≠ 1 は par_stop**(流木ストックの消費はイベント実量で、
  地形加速と整合しない。f_debris と同じ理由)。
- fn_dwstock は必須(ストックなしの流木計算は無意味)。
  dw_dlog・dw_sglog も必須(喫水の実体)。0 < dw_sglog < 1 を検証
  (沈む材 ≥ 1 は浮遊流木の前提が崩れるため par_stop で案内)。

## 4. 検証計画

- **無効時ビット一致**: fn_driftwood 未指定で全既存ケース
  (wave / chichibu / creep / fluvial / suspend / wash / debris /
  slide / volcano 等)の Log / state がバイト一致。
- **規律3**: 新規帯配列(hd, wst, dep, zref)を足すコミットは
  gfortran -fcheck=all の np=2 を最適化ビルドより先に実行。
- **np=1, 2, 4** の state.dat と出力ファイル(Hd/Wd9999)が逐次と
  バイト一致(統計が save に入らない場合の検証は出力ファイルで行う —
  §28.9 の教訓)。
- **保存則**(test/driftwood): 閉領域で
  Σwst + Σhd + Σdep(+ダム捕捉+系外流出)= Σwst0 の機械精度保存。
- **疎通(2構成)**:
  1. 土石流混合: 渓床ストック+f_debris(test/debris 地形の拡張)→
     侵食連行で流木化 → 混合体と同速流下 → 勾配緩和点の停止域で
     hd → dep(土砂堆積域と流木堆積域の重なりを目視確認)
  2. 洪水氾濫: 氾濫原ストック+破堤氾濫(または wave 系)→
     水理的流失 → 浅水域・乾燥域での堆積分布(Wd9999)
- **2ケース比較の実演**: 遊砂地(掘り込み地形)あり/なしで
  下流到達流木量の差分 = 施設の流木捕捉量(ビット再現による
  切り分け。ユーザーガイドの例題化まで)。
- **リスタート往復**: save → restore → save のバイト一致
  (発生済み wst=0 状態を含む)。

## 6. 論点と合意結果(2026-08-21 合意。全て推奨案で確定)

1. **クラス数**: 単一代表諸元(dw_dlog・dw_sglog の1クラス)で開始。
   多クラス化は多粒径土砂と同時期の将来課題。【確定】
2. **侵食連行の形**: 根系深超過で**全量流失**(根系より深く抉られた
   立木は根系ごと流失する、の単純化)。侵食増分比例は将来の追加候補
   (パラメータ1個の追加で足せる)。【確定】
3. **dep の地形固定(z への算入)**: 第1段では見送り(§3.4)。
   固定するなら動的閉塞(論点6)と一体で再議論。【確定】
4. **運動量・抵抗への流木算入**: 見送り(§0 方針4・6)。流木
