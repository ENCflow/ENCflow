## 0. 結論(要約)

- **実現の可否: 可。既存の骨格を壊さない**。蛇行の発達に必要な 3 過程
  (外岸侵食・内岸堆積・短絡)のうち、現行コードに無いのは
  (a) 流砂の向きが水深平均流向と一致するため**横断方向の土砂移動が
  生じない**こと、(b) **河岸(水面より高い隣接セル)を削る機構が無い**こと、
  の 2 点に集約される。(a) は `calc_fluvial` の流向射影 1 行の一般化、
  (b) は河岸エッジの追加フラックス 1 本で、いずれも**固定格子上の保存形
  エッジフラックス**として既存の 2 ループ構造(m_gwflow_lateral 型)に乗る。
  河道中心線・格子再生成・三日月湖生成アルゴリズムは**導入しない**
  (方針 §0-2 ラスタ純化)。短絡は乾湿処理と地形変化の帰結として現れる
  ものだけを採用する。
- **段階は 6 段(0〜5)**。各段で動く例題と検定を残し、次段へ進む。
  「蛇行が育つ最小構成」= 段 0〜2 を先に完成させ、実務向けの精緻化
  (非平衡二次流・有効掃流力・給砂時系列)は段 5 に置く
  (メモの最終回答と同じ順序。中間回答の「実務整備を先に」は採らない)。

  | 段 | 追加するもの | 到達目標 | 新規状態(save) |
  |---|---|---|---|
  | 0 | 保存型の供給量制限(fluvial の挙動変更)+河岸エッジの掃流遮断 | 長時間計算で vleak が出ない | なし |
  | 1 | 掃流砂の方向補正: 河床勾配項+平衡二次流項(`fluv_slope`, `f_secflow=1`) | 固定岸の湾曲水路で外岸洗掘・内岸堆積 | なし |
  | 2 | 側岸侵食(`f_bank`)+安息角崩落(`f_repose`) | 外岸後退+内岸堆積で河道が横移動 | なし |
  | 3 | 内岸の定着(`f_fixation`。段 2 の結果で要と判明 → §3.4 改訂版) | 拡幅で止まらず単一流路が蛇行し続ける | 定着度 a(s%fx)+基準高 1 面(私有 save) |
  | 4 | 短絡・三日月湖の検証例題(機構追加なし。f_suspend 併用) | 頸部短絡→旧河道閉塞 | なし |
  | 5 | 非平衡二次流(`f_secflow=2`)、有効掃流力 `fluv_taufac`、掃流砂給砂時系列 | 精度・実務適用範囲の拡大 | 二次流強度 1 面(t_state) |

- **メモリ・CPU**: 無効時ゼロ追加(方針 §0-8)。段 1 はセル配列 1 面
  (二次流強度のエッジ補間元)+勾配のその場計算、段 0・2 はセル配列 1 面
  (供給制限係数)。段 5 の非平衡二次流だけが水理時間の輸送 1 本
  (advect_scalar の利用者第 5 号)で、hs と同程度の増分。
- **方針との整合**: 鉛直構造(螺旋流)は「セルスカラー 1 個」に抽象化する
  (方針 §0-5 の鉛直の抽象化そのもの。NH の例外条項を使わない)。
  流線曲率は流速場から内部導出する(§0-12 の「明確な理由」: 河道が動くので
  静的な入力にできない)。侵食係数・限界掃流力・安息角・定着時間は与える。
- **検証の柱**は CLAUDE.md の規律そのまま: 無効時ビット一致 / np=1,2,4
  ULP=0 / -fcheck np≥2 先行 / 土砂体積保存の機械精度。これに
  **格子回転(0° と 45°)での傾向一致**(test/bedslide と同型)を加える。

## 1. 位置づけと方針適合(developer.md §0)

| 方針 | 本案の対応 |
|---|---|
| 1 シームレス | 蛇行→短絡→三日月湖→氾濫時の流路変化を、流出・氾濫・浮遊砂・流木と同じ格子・同じ時間発展で追う。専用の蛇行モデル(中心線追跡)とは違う価値 |
| 2 ラスタ純化 | 河道中心線・河岸線のベクトル表現を持たない。河岸は「水面より高い隣接セル」という**セル間関係**で認識し、後退は**セル平均標高の低下**で表す(CAESAR-Lisflood 型)。サブグリッドの河岸位置(セル内面積率)は導入しない(必要になったら別途議論) |
| 4・5 概算・SWE+1 方程式・鉛直の抽象化 | 二次流は鉛直多層化せず、河床近傍流向の偏り r = u_bn/u_bs をセルスカラーで表す。段 5 の非平衡輸送も「1 方程式モデル」の範囲(スカラー輸送 1 本) |
| 6 徐々に精緻化 | 平衡二次流→非平衡、一様係数→分布ファイル、定着なし→定着、の順。各段で「無いと蛇行しない」ことを確かめてから足す |
| 7・8 fn_* 有効化・無効時ゼロ追加 | 既存の fn_geomorph の中の独立フラグ(f_bank 等)。無効時は配列未確保・呼び出しなし・ハロ交換なし・既存 reference とビット一致 |
| 9・10 単一ソース・Fortran のみ | 既存の 2 ループ・owner-compute・冗長計算の型に乗る。新規ライブラリなし |
| 11 単純な入出力 | 追加入力は namelist の係数と、必要なら侵食係数の分布ラスタ(z と同形式) |
| 12 物理量を直接与える | 与える: K_b, τ*c,b, φ_r, T_fix, N*(既定あり)。内部導出: 流線曲率 κ(動的量のため) |

## 2. 現行コードの前提(2026-10-17 時点で成立していること)

実装の土台として確認した事実(行番号は当日の main):

- **掃流砂 `calc_fluvial`(m_geomorph_fluvial.f90)**: ループ 1 がエッジ
  流量 `gm%wrk%q(k, …)` を所有者一意で書き(帯界面は je+1 行の冗長計算)、
  ループ 2 が反対称集計で z・sd を共動更新。流砂量 qb は両セル平均の
  (h, vv, rn) からマニング閉じの τ* で評価し、**向きは水深平均流速の
  エッジ法線射影 `gq = qb * (ue / vve) * wl(k)`**。`if (ue /= 0.0)` が
  流砂計算の入口条件(= 法線流速ゼロのエッジは土砂が動かない)。
  クランプ 3 層(エッジ別可動層・エッジ別 dzmax・ループ 2 の岩盤床クリップ
  → vleak 計上)。幅河道(frw・fwd・1/wfrac)と堤防エッジ(bank_active 時の
  rw 不一致 = 遮断)に対応済み。
- **河岸に相当する処理は無い**。水面より高い乾燥セルに向かうエッジでも、
  両セル平均の vve・hhe が正なら流砂が計算され、流向が向いていれば
  **乾いた高いセルに掃流砂が堆積しうる**(陸上に砂が「登る」)。
  現状はダムブレイク型の検定では顕在化していないが、段 0 で塞ぐ。
- **勾配の既存部品**: `slope8`(8 近傍最急降下。debris)、`slope_flow`
  (流向の河床勾配。中央差分+片側フォールバック。Morpho2DH 式(6))、
  `calc_bedslide` のパス B(8 方向の勾配比例配分+ドナー律速 fdon。
  **安息角崩落の雛形**)。
- **セル公開量**: s%u, s%v, s%vv, s%h, s%z, s%sd(帯±ハロ 2)。エッジ流量
  mn は swflow_enc 私有(掃流砂は使わない。§19.2 の決定)。
- **スカラー輸送 `advect_scalar`** は線形・単位不問・**符号の仮定なし**
  (負値のクリップなし)。符号付き量(二次流強度 h·I)をそのまま運べる。
- **geomorph は swflow の後**(§2.2)。`calc_fluvial` 冒頭で h, u, v, vv の
  ハロ交換(§19.2 の実バグ対策)。dts = dt·idt·morfac。
- **移流項**: f_advection_term と f_advection_scheme(§68.19)。湾曲流の
  主流再配分は移流項が担うため、蛇行計算は**移流項あり**が前提
  (メモの指摘と同じ。局所慣性近似では二次流補正だけで補えない)。
- **NH(§69)**: f_nh_bottom は geomorph の z 更新にも反応する。蛇行の
  長期計算は NH off・morfac=1 を基準にする(メモの注意を採用)。
- **土石流 f_debris の曲率項 §28.10** は降伏摩擦の遠心加速度補正で、
  ここでいう二次流とは別物(流用しない)。

## 3. 物理モデルの選定(段ごとの定式)

記号: t̂ = 水深平均流向の単位ベクトル、n̂ = t̂ を左 90° 回した単位
ベクトル((−v, u)/|V|)、κ = 流線曲率(左曲がり正。κ n̂ = (t̂·∇)t̂ は
曲率中心向きで、座標系の向き〔行順 北→南〕によらない)、
τ* = n²V²/(s d50 h^{1/3})(既存)、q_b = 平衡流砂量(既存)。

### 3.1 段 0: 保存型の供給量制限(fluvial の挙動変更)と河岸エッジの掃流遮断

(1) **供給量制限**: ループ 1 の後に「セルごとの総流出要求 Σ_k max(q_k·出る向き, 0)·dts
が供給可能量 sd·A/(poroi·winv) を超えたら、縮小係数
f_don(i,j) = min(1, 供給可能/要求) をそのセルから出る全エッジ流量に乗じる」
パスを入れる(bedslide のドナー律速と同じ)。f_don は自帯で計算して
**par_halo_cell で 1 回交換**し、ループ 2 では各エッジの風上セルの f_don を
両側が同じ値で使う(反対称性 = 保存を保つ)。既存のエッジ別可動層クランプは
残す(sd=0 の早期打ち切り)。岩盤床クリップは丸め誤差の最終防衛として残すが、
**発動すれば vleak が出る = 以後は「設定の誤り」の意味**になる。
- メモとの差: 同じ提案(「総流出に対する保存型の供給制限」)。
- 検証: test/fluvial・test/wash 等の既存ケースで vleak=0 のものはビット
  一致のはず(縮小が発動しなければ f_don=1 の乗算で不変)。発動したケースが
  あれば reference の差として報告し、人間が妥当性を確認する(規律 1)。
  **挙動変更なので単独コミット**(規律 4)。

(2) **河岸エッジの掃流遮断**: エッジの一方 c が湿潤、他方 n の地盤
z_n ≥ e_c(c の水面)なら、そのエッジは河床面ではなく**河岸面**であり、
掃流砂は通さない(n→c も c→n も 0)。河岸面の交換は段 2 の側岸侵食だけが
担う。既存結果への影響: 平坦床のケースでは z_n = z_c < e_c で発動しない。
段差地形(test/bendloss 系は geomorph なし)では乾いた堤内地への堆積が
消える。これも挙動変更として単独コミット+回帰で影響ケースを特定する。
- 代替案: f_bank 有効時だけ遮断する(既定挙動を変えない)。
  → **推奨は既定挙動の変更**(「陸に砂が登る」は f_bank の有無によらず
  非物理)。ただし reference に差が出たケースの妥当性確認が前提。

### 3.2 段 1: 掃流砂の方向補正(河床勾配+平衡二次流)

流砂ベクトルを

  **q⃗_b = q_b · ( t̂ + r n̂ − γ ∇z )**

とし、エッジ k の流量は gq = wl(k) · (q⃗_b · ê_k) とする(ê_k は既存の
`flv%ex/ey`)。r=0, γ=0 で現行の `qb·(ue/vve)·wl(k)` に厳密に戻る
(ue/vve = t̂·ê_k·(|V_c|+|V_n|)/2÷vve の現行定義をそのまま使う。
メモの指摘どおり vve の定義は変えない)。

- **河床勾配項 γ∇z**: 長谷川(1981)型 γ = √(τ*c / (μ_s μ_k τ*))
  (Nays2DH の河床勾配補正。μ_s = 1.0, μ_k = 0.45 が慣用【要文献照合】)。
  流向成分(縦断勾配)は q_bs を増減し、横断成分は下り斜面向きの流砂を
  与える。∇z は両セルの中央差分勾配(片側フォールバックは slope_flow と同じ)
  の平均をエッジ値とする(帯±ハロ 2 の中で閉じる: je+1 行の冗長計算が
  je+2 行の z を読む)。勾配配列は持たず、エッジごとにその場で計算する
  (メモの「16 MB か CPU か」はここでは CPU を選ぶ。勾配は 2 セル×2 成分の
  差分で軽い)。
  - 代替案(メモの第一回答): 方向だけ変えて大きさを保つ正規化形。
    → **非正規化(長谷川)形を推奨**。文献の裏付けがあり、縦断の上り勾配で
    流砂量が減る効果(堆積側)も含む。正規化形は係数の物理的根拠が薄い。
- **平衡二次流項 r n̂**: r = N* h κ(Engelund 型。Nays2DH は N* = 7
  【要文献照合】)。κ は水深平均流速場の幾何学的流線曲率
  κ = (u² v_x − v² u_y + u v (v_y − u_x)) / |V|³ を中央差分で評価する。
  - 評価セルの条件: h > dd かつ |V| > sec_vmin(既定: dd 相当の微小値。
    流向が定まらない場所で数値雑音から大曲率を作らない)。近傍が乾燥・
    領域外・海なら自セル値で代用(勾配 0 側に倒す)。
  - 上限: |r| ≤ sec_rmax(既定 1.0 = 45°。急湾曲での h/R 比例則の破綻を
    止める。Blanckaert 型の非線形補正は入れない)。
  - **r はセル配列 `flv%rsec(ish:ieh, jsh:jeh)` に自帯で評価し、
    par_halo_cell で 1 回交換、エッジ値は両セル平均**。これで帯界面の
    冗長計算が同じ入力を読む(fdon と同じ型)。段 5 ではこの配列が
    非平衡強度 I の受け皿になる。
  - 符号: κ n̂ は曲率中心向きなので、r>0 の補正は常に湾曲内側を向く。
    格子の行順(北→南)や左手系の心配は不要(ê_k も同じ添字空間)。
- **入口条件の変更**: 現行の `if (ue /= 0.0)` は「補正後の法線成分
  (q⃗_b·ê_k) ≠ 0」に移す(メモの指摘。水の法線流速ゼロのエッジでも横断
  流砂が通る)。流砂量 qb の評価条件(vve>0, hhe>dd, okbank)は不変。
  r=γ=0 なら補正後成分 = 現行の ue·qb/vve なので判定は同値 → ビット一致。
- **供給元**: 補正後の gq の符号で風上を決める(現行の構造をそのまま使う)。
- **開境界面**(k≥5 の面スロット)は補正なし(一方側値で容量輸送。
  面法線は固定なので横断成分は面を通らない)。
- **幅河道(fn_width)**: 河道幅セルの横断方向は「河道内の横断」ではなく
  セル間の横断なので、frw·fwd の乗算を補正後にも適用し、それ以上は
  しない。蛇行計算は解像河道(fn_width なし)が前提(メモと同じ)。
- **有効掃流力の分離 `fluv_taufac`**(τ*_grain = f_τ·τ*。既定 1.0 =
  ビット一致)は入力 1 行で済むので段 1 で同時に入れてよい(段 3 で定着の
  粗度増を使う場合の前提)。

### 3.3 段 2: 側岸侵食と安息角崩落

(1) **側岸侵食 `f_bank`**(submodule m_geomorph_bank.f90)
- **河岸エッジ**: c(湿潤 h_c > dd)と n(z_n ≥ e_c)。段 0(2) で掃流を
  遮断したエッジそのもの。n は乾燥でも冠水でもよい(洪水時に冠水した
  河岸も対象。メモの注意)。
- **水没河岸高** H_b = min(z_n − z_c, h_c)。
- **後退速度** E_b = K_b · max(τ*_c / τ*c,b − 1, 0)^m [m/s]。
  τ*_c は河岸脚部セル c のセル値(既存の τ* 式。近傍流速の代理。
  メモの α_b は K_b に吸収する)。m は既定 1。
- **体積** ΔV = E_b · dts · H_b · wl(k)(ENC の通過幅 wl(k) の 8 リンク
  合計は周長 2(dx+dy) を超えない〔既定の fluv_diagratio で約 0.83 倍、
  diagratio=0 で等しい〕ので、斜めリンクを含めて合算しても河岸長を
  過大評価しない。メモの懸念はこの性質で解消)。
- **適用**: n の z・sd を −ΔV/A、c の z・sd を +ΔV/A(河岸脚部へ崩落土砂
  として保存的に移す。以後の掃流砂が運ぶ)。実装は**ループ 1 の後・ループ 2
  の前に、河岸エッジへの追加フラックス(n→c)を `gm%wrk%q` に加算する
  パス**(所有者一意・je+1 行冗長の同じ型)。ループ 2 は既存のまま。
  供給制限 f_don は n 側の sd(河岸の可動層)に対しても効く。
- **河岸脚部の被覆効果**(崩落土砂が運び去られるまで侵食が止まる)は
  入れない(最初の版)。必要になれば「c の z が前回の河岸脚部高より
  上がっていれば E_b を減じる」で足せる。

### 3.4 段 3: 内岸の定着 f_fixation(2026-10-17 改訂)

**前提の更新(改訂の理由)**: §84.5 の所見「外岸の後退が止まる」は旧移流
(斜め副格子モードを避けるためスキーム 1)での結果だった。main の §68.36
修正(側方面の副格子結合)後の運動量保存形(スキーム 3)で examples/meander
を同条件で再実行すると、市松はスキーム 1 より小さく(相対振幅 0.021 対
0.040)、外岸は湾曲頂部の下流側で最大 9 m(4〜5 セル)後退し、外岸沿いの
淵(−2 m)と内岸の砂州(+0.5 m)が同時に現れる(幅 20 → 27 m。崩落土砂量
2650 m³ 対 929 m³)。つまり**外岸後退の駆動力の問題(§84.5 の候補 (a)(b))は
移流項の修正で解消**し、候補 (a)(b) は採らない。残る課題は、内岸の砂州が
供給セルの水面までしか堆積せず(§84.2 R2)陸地にならないため、横移動が
「拡幅」で止まることであり、これが本節の定着そのもの。原案(段 2 の結果が
「拡幅するだけ」なら導入)の条件が成立した。

- **状態**: 定着度 a(i,j) ∈ [0,1] は t_state の柱状量 `s%fx`(出力 Fx。
  f_bedslide の hb と同じ扱い = geomorph が確保し、m_output は allocated で
  出す)。基準高 zref(i,j)(定着面が形成されたときの地盤高)は geomorph
  私有。私有 save `geomorph_fixation.dat`(契約 5。a と zref の 2 面。
  m_restart の restart_write/read_cell 経由。§83)。
- **発展**(地形時間 Δt_m = dts·morfac で評価する。植生の定着は地形変化と
  同じ時間軸にある過程なので、morfac で加速した地形時間に合わせる):
  - 乾燥(h ≤ dd): a ← 1 − (1 − a)·exp(−Δt_m / T_fix)(厳密解)、zref = z。
  - 湿潤(h > dd): zref = max(zref, z)(定着面への堆積は表層を更新する)。
    zref − z > dz_reset なら a = 0、zref = z(表層が剥がれて定着が失われる。
    原案の「1 更新の浸食深」は dts が小さいと発火しないため、定着面からの
    累積浸食深に替えた)。
- **効果**: τ*c,eff = τ*c·(1 + c_τ·a) を
  (i) そのセルを**供給(風上)側**とする掃流砂に適用する(閾値判定と流砂量
  式の両方。受け手側の a は見ない = 定着面への堆積は妨げない)、
  (ii) 側岸侵食の河岸セル b に適用する(τ*c,b·(1 + c_τ·a_b))。
  安息角崩落と浮遊砂 E-D には効かせない(最初の版。崩落は安息角の幾何
  そのもので、植生による見かけの安息角上昇は必要になってから。浮遊砂は
  段 5 の課題)。**標高・体積には触れない**(原案どおり)。
  永久不侵食にはしない(再侵食を許す)。
- **namelist**: `f_fixation`(0/1)、`fix_tfix`(定着時間 T_fix。h、地形時間)、
  `fix_ctau`(定着時の τ*c の増分比 c_τ)、`fix_dzreset`(定着面からの累積
  浸食深のリセット閾値。m)。T_fix・c_τ は文献照合待ちのため既定を置かず
  **必須**(N*・μ と同じ扱い。§19.8)。dz_reset は構造的パラメータ(定着面
  = 根系層の厚さの目安)なので既定 0.1 m を "(default)" 表示で置く。
- **例題**: 一定流量では砂州は水面までしか育たず露出しないので、流量変動
  (低水 ↔ 出水)を与える。低水期に露出した砂州に定着が進み、出水時に
  抵抗して河道が片側に寄る = 横移動。examples/meander の param_fix.txt。
- 検定 test/fixation: 無効時ビット一致、定着の成長則(乾いたセルの a の
  解析解)、効果(低水期に露出 → 出水で浸食が抑制。c_τ 大で浸食ゼロ)、
  リスタート往復ビット一致、np=1,2,4 一致。

### 3.4b 段 3b: 定着の植生効果 — 浮遊砂の捕捉と粗度(2026-10-17 合意・実装済み = developer.md §84.8)

**動機**(§84.7 末尾の緩い減水期の試行): 掃流砂の堆積は供給セルの水面で
頭打ちになるので、砂州の天端は出水ピークの水位で決まり、減水期を長くしても
高くならない。実河川で砂州を氾濫原の高さまで育てるのは、出水時に植生の
生えた砂州の上で流れが遅くなり、浮遊砂(細粒分)が沈んで積もる過程(垂直
堆積)である。現行の f_fixation は τ*c を上げるだけで、浮遊砂と粗度には
効いていない。f_fixation は本ブランチで新設した機能なので、定義を広げても
互換性の問題はない。

**設計**(定着度 a はそのまま。効果を 2 つ足す):

(i) **浮遊砂の再浮上抑制**(m_geomorph_suspend の E-D): 浸食項(平衡濃度
  ceq)を定着で減らし、沈降項(β c)は変えない。
  - f_esform = 1(超過掃流力線形): τ*c,s を τ*c,s (1 + c_τ a) に上げる
    (掃流砂と同じ規則・同じ c_τ)。
  - f_esform = 2(板倉・岸。τ*c を持たない): ceq に 1/(1 + c_τ a) を乗じる。
  - 乾燥セルの「浮遊分を全量河床へ」は不変。沈降で上がった z は定着面 zref
    を押し上げる(既存の max 規則)ので、出水のたびに細粒分が積み増される。
  - 掃流砂だけ・a = 0 のセルは厳密に不変。
(ii) **粗度の増加**(流れの摩擦項): 定着セルの Manning n を
  n_eff = n (1 + c_n a) にする(`fix_cn`。0 = 効果なし = 既定)。
  - 受け渡しは t_state の柱状量 `s%rnv`(動的粗度。geomorph が確保・更新し、
    update_fixation の末尾で n_eff を書いてハロ交換)。m_swflow_enc の摩擦項は
    `allocated(s%rnv)` なら rne = (rnv_c + rnv_n)/2 を使い、未確保なら g%rn
    (厳密に不変)。hb・fx と同じ「所有者が確保し利用者は allocated で見る」様式。
  - 流砂の τ*(掃流砂・浮遊砂・側岸侵食)は **g%rn のまま**にする。植生の
    抵抗は形状抵抗で粒子にかかるせん断ではない(fluv_taufac の有効掃流力の
    分離と同じ考え)。流速が落ちる分だけ τ* は自然に下がる。
  - save/restore: n_eff は a の純関数なので保存しない(restore 後の最初の
    update で再構築。それまでのステップは init で a から作る)。
  - 代替案(不採用): 既存の抗力項(p%cd・gv)で植生抗力を表す。gv は建物の
    占有率で貯留体積も変えるため、植生には合わない。

**パラメータ**: 新設は `fix_cn` だけ(定着時の粗度増分比。既定 0)。浮遊砂の
効果は f_fixation と f_suspend の併用で自動的に有効(別フラグを置かない。
併用する reference は存在しない)。c_n の目安は Chow の表(草地 0.03〜0.035、
低木・樹木の氾濫原 0.05〜0.15)から 1〜3 だが、§19.8 の原則で既定値には
しない(利用者が明示)。

**検証**(test/fixation に構成を足す):
- 浮遊砂: 幅 10 セルの水路の砂州(fixation の既存地形)に、出水時に
  `inflow_cs` で細粒分を供給。定着あり/なしで、砂州上の正味堆積(Δz > 0)が
  定着ありで大きく、河道内の Δz は同じ桁。f_esform = 1 と 2 の両方。
- 粗度: `fix_cn = 2` で定着した砂州を水没させた等流で、砂州上の流速が
  c_n = 0 より下がり、断面流量は同じ(質量保存)。
- 無効時ビット一致: 既存の fixation 構成(掃流砂のみ、fix_cn = 0)と
  suspend・wash の reference。np=1,2,4 一致、-fcheck np=2。

**例題**: examples/meander の定着構成に浮遊砂(細粒 0.1〜0.2 mm)と出水時の
給砂濃度 `inflow_cs` を加える(param_fixsusp.txt)。見るもの: 出水を重ねる
ごとに定着砂州の天端が出水ピークの水位を超えて上がるか(§84.7 では 0.86 m
で頭打ち)、河道本体が無給砂の懸濁で低下しないか(給砂濃度は河道の平衡濃度に
合わせる。段 5 の給砂と同じ問題)。

**規模**: 浮遊砂の抑制 10 行、動的粗度 60 行程度(t_state の配列 1 面、
m_swflow_enc の摩擦の読取 1 箇所、geomorph の書き手)、検定 2 構成、
文書(users_guide geomorph・sediment・params_index・List_samples・§84.8)。
MPI はハロ交換 1 回の追加。

**要合意事項**: (1) 浮遊砂の抑制を f_fixation の定義に含める(別フラグなし)、
(2) 粗度は τ* に効かせない(形状抵抗の分離)、(3) `fix_cn` の既定 0、
(4) 植生の季節性・成長段階は入れない(a の 1 面で表す)。

### 3.5 段 4: 短絡・三日月湖(機構追加なし)

  短絡が「1 セル早く」起きる方向の誤差で、必要解像度(河幅 ≥ 8 セル)の

- 例題は 2 本: (a) 小振幅の正弦波状初期河道から育てる(振幅の成長・

### 3.6 段 5: 精度向上(非平衡二次流・有効掃流力・給砂)

段 5 は「5a 給砂」と「5b 非平衡二次流」に分け、5a を先に行う(§84.5〜84.8 の
例題がすべて無給砂の河床低下に妨げられているため)。有効掃流力 fluv_taufac は

#### 3.6a 段 5a: 給砂(2026-10-18 合意・実装済み = developer.md §84.9。容量給砂の定義は実装時に「流入セルの正味流出 × 倍率」に改めた)

**現状と試行**:
- 開境界面(自由流出・区間流入面を含む bc_open_face)の掃流砂は、流出が常に
  容量輸送、流入は `fluv_bcfeed = 1` のとき容量供給(§19.4)。区間流入面も
  開面なので例題にも効く。浮遊砂は区間流入に濃度 `inflow_cs(t)` または流砂量
  `inflow_qs(t)`(= Qs/Q の等価濃度。§19.7)を与えられるが、平衡濃度を与える
  手段はない。掃流砂の流砂量時系列を与える手段はない。
- examples/meander(一定 Q)を fluv_bcfeed = 1 で再実行すると、上流端の河床
  低下(x = 50〜150 m で 200 h に −0.85 m)は消えるが、**過給砂**になる
  (同区間 +0.80 m、河道が氾濫原へ溢れて湿潤セル 8,525 → 17,931)。流入面の
  容量は流入セル(直線・水深 0.8 m)の水理で決まり、下流の蛇行区間の輸送
  容量より大きいため。「平衡給砂 = 流入面の容量」は下流区間と釣り合う保証が
  なく、実務でも給砂量は与件(上流からの供給、ダムの捕捉、置き土)である。
  したがって**容量給砂に倍率**と、**流砂量の直接指定**の両方が要る。

**設計**(いずれも標高・体積の保存形。台帳で収支を閉じる):

(1) **容量給砂の倍率 `fluv_bcfeed_fac`**(既定 1.0。fluv_bcfeed = 1 のとき
  有効): 流入面の容量供給 gq(<0)に fac を乗じる。0 = 無給砂、1 = 現行、
  0.5 = 半給砂(ダム下流の河床低下の再現)、>1 = 過給砂(置き土・土砂還元)。
  calc_fluvial の開境界ループで 1 行。流出側には掛けない。
(2) **掃流砂の流砂量時系列 `inflow_qb`**(&list_bound_inflow。(min, m3/s 固体
  体積)/ fn_inflow_qb。inflow_qs(浮遊砂)と同形): 区間流入の各セルの河床に
  Δz = Qb·dts·poroi / (A·n_cell)(水の按分と同じ重み。inflow_dist)を加える
  源泉。流入セルは容量輸送でこれを運ぶ(容量を超えれば盛り上がる = 実河川の
  置き土と同じ)。fluv_bcfeed = 1 と併用可(容量供給+追加注入)だが、通常は
  どちらか。geomorph の更新ごとに calc_fluvial の前(供給を可動層に入れてから
  運ぶ)に適用し、z・sd の共動更新。台帳 vfeed を dispose で報告。
  区間流入のセル一覧は m_boundary の b%inflow(ifl)%cell から init で帯内の
  リストに写す(geomorph → m_boundary の読み取り依存を 1 つ追加。逆向きは
  作らない)。
(3) **浮遊砂の平衡濃度給砂 `inflow_cs_eq`**(&list_bound_inflow の区間ごとの
  整数 0/1。既定 0): 1 なら流入濃度 = fac_s × C_eq(流入セルの τ* から
  f_esform の式で評価)。inflow_cs / inflow_qs と排他。倍率 `susp_bcfeed_fac`
  (既定 1.0)。C_eq の評価は m_geomorph_suspend の式を pure 関数
  `suspend_ceq(gm, taus)` に切り出して公開し、m_boundary の makebdc が
  b%csin を書くときに呼ぶ(m_boundary → m_geomorph の読み取り依存。
  (2) と逆向きになるので、**(2) の流入セル一覧は m_boundary が公開する
  読み取り専用の表とし、geomorph は m_boundary を use しない**ことで循環を
  避ける = 依存は m_boundary → m_geomorph の一方向。要確認: m_boundary の
  init 順序(geomorph init より前なら C_eq の係数は calc 時にしか要らないので
  問題ない))。
(4) **例題**: examples/meander の給砂は、まず (1) の fac を 0.3〜0.7 で振って
  上流区間の河床が 200 h で ±0.1 m に収まる値を探す(無給砂の試行で x = 150 m
  の通過流砂量を測って与えてもよい = (2) の使い方)。浮遊砂併用は (3)。
  実務向けの使い方(ダム捕捉 fac = 0、置き土 inflow_qb の時系列)は
  users_guide の geomorph 章「給砂」に小節を起こす。
  → 実施結果(2026-10-18、developer.md §84.9 末尾): 容量給砂の定義を
  「流入セルの正味流出 × 倍率」に改めたため倍率の校正は不要(倍率 1 で入口
  固定)。流量変動+定着に入れた param_fixfeed.txt は河道の河床が平衡になり
  定着が進む。浮遊砂の平衡濃度給砂を加えた param_fixsuspfeed.txt は砂州が
  氾濫原の高さまで育つが、倍率 1.0 で過給砂(避難)、0.5 で河道が −2〜3 m
  低下する。原因は河床の粒径組成がなく浮遊砂の浸食が掃流砂の河床を細粒分の
  速さで削ること(README 限界 7)。

**検証**(test/sedfeed 新設): 直線水路(test/uniflow の地形に土層あり)で
(a) 無給砂: 上流端から河床低下波、(b) fac = 1: 上流区間の河床が ±1 cm で
安定、(c) fac = 0.5: 低下量が (a) の約半分、(d) inflow_qb = 一定: 台帳
Σ(z − z0)(1 − λ)A + 流出量 = ∫Qb dt が機械精度、(e) inflow_cs_eq = 1:
流入濃度が流入セルの C_eq に一致(出力 Hs/H で確認)。無効時ビット一致、
np=1,2,4 一致、-fcheck np=2。

**規模**: (1) 数行、(2) 100 行(namelist・読み込み・補間は inflow_qs を複製、
源泉の適用 1 ループ、台帳)、(3) 80 行(関数の切り出し、makebdc の分岐、
namelist)。文書: users_guide boundary(区間流入)・geomorph・sediment・
params_index・List_samples、developer.md §84.9。

**要合意事項**: (i) 容量給砂の倍率は流入側のみ(流出は常に容量)、
(ii) inflow_qb は河床への源泉(hs への注入ではない)、(iii) 平衡濃度給砂の
依存方向は m_boundary → m_geomorph、(iv) 例題の給砂は倍率の校正で与える
(「正しい平衡給砂」は定義できない)。

#### 3.6c 段 5c: 河床の細粒分の帳簿 f_bedfines(2026-10-18 合意・実装)

**動機**(§3.6a の実施結果): 浮遊砂の浸食は土層 s%sd をそのまま細粒分として
巻き上げるため、掃流砂の河床(1 mm)が細粒分(0.2 mm)の速さで削られ、平衡
濃度給砂の倍率のわずかな不足が −2〜3 m の河道低下になる。砂州を出水位より
上へ育てる過程(出水時の堆積 → 露出 → 定着 → 氾濫原に同化)を給砂の調整なしに
再現するには、「河床のうち浮遊砂として動く成分がどれだけあるか」の帳簿が要る。

**方針との照合**: 一般の混合粒径(Hirano 型の交換層 × 粒径階。geomorph_plan.md
F4)は §0「過度に複雑化しない」に反するので採らない。既存の 2 成分の区別
(掃流砂 = fluv_d50 の 1 粒径、浮遊砂 = susp_d50 の 1 粒径)を河床側にも持たせる
だけ: 新しい状態は細粒分の厚さ s%sf(m、≤ s%sd)1 枚。無効時は未確保・
呼び出しなし(既存 reference 不変)。遮蔽・露出関数や粒径別の掃流砂式(文献係数)は
入れない。

**定式**(f = min(1, sf/L_a)。L_a は交換層厚 = 細粒分の利用可能率を決める
数値的な混合厚。f は「交換層に占める細粒分の割合」):
- 浮遊砂 E-D(calc_suspend): 浸食 E = f·w_f·C_eq(在庫で制限。D = w_f β C は
  不変)、浸食量は sf を超えない。沈降・乾燥時の全量堆積は sd・sf を同じ Δz で
  増やす。
- 掃流砂・側岸侵食・安息角崩落・容量給砂(apply_edge_flux。wrk%q の発散):
  流出 q は供給側の交換層の組成で割れる = 細粒分 f_own·q はその場で懸濁
  (hs へ。高い τ* の掃流砂浸食面で解放された細粒分は浮遊する)、粗粒分
  (1 − f_own) q だけが隣接セルの河床に届く。供給側の z・sd は q の全量ぶん
  下がり、sf は f_own·q ぶん減る。域外(開境界)からの流入は粗粒(f = 0)。
  f_own はループ 1.5(供給量制限)で vout から決め、細粒分の流出 ≤ sf かつ
  粗粒分の流出 ≤ sd − sf を満たす範囲に入れる(fdon と同じく ff をハロ交換)。
  これで 0 ≤ sf ≤ sd が丸めを除いて構造的に成り立つ。
- 斜面浸食 f_wash: 浸食率に f を乗じ sf から減らす(斜面の土層が粗粒だけなら
  洗い出しは起きない = fines_frac0 を 1 にして従来どおり)。
- 乾式斜面侵食 f_splash・動く底層 f_bedslide・風化 f_wthr: 粗粒として扱い、
  不変条件 sf ≤ sd のクリップだけ入れる(併用は想定外。文書に明記)。
- 土石流 f_debris は f_suspend と排他なので対象外。区間流入の掃流砂源泉
  inflow_qb は粗粒(sd のみ)。

**状態と入出力**: s%sf(帯±ハロ。更新は自帯。出力 "Sf")。初期値は
`fines_frac0` × sd(一様割合。分布ファイルは要るときに fn_sf として足す)。
私有 save geomorph_fines.dat(契約 5。restart_write_cell 1 面)。作業配列
ff(帯±ハロ)は有効時のみ。台帳 vfree(掃流砂浸食で懸濁化した細粒分の固体体積)。

**namelist(&list_geomorph)**: `f_bedfines`(0/1。f_suspend = 1 必須)、
`fines_la`(交換層厚 m。必須 > 0)、`fines_frac0`(初期の細粒分割合 0〜1。
既定 0 = 粗粒のみ)。3 つだけ。無指定なら従来どおり。

**限界**: 鉛直の層序を持たない(sf は柱の合計。粗粒が厚く積もって細粒分が
埋没しても利用可能として扱われる。要るときは交換層内と下層の 2 枚に分ける)。
解放された細粒分の「その場で懸濁」は仮定(掃流砂に同伴させる案より単純で保存が
閉じる)。L_a に結果が弱く依存する。粗粒側は 1 粒径のまま。

**検証**(test/bedfines): 閉領域ダムブレイク(test/suspend と同じ)で
(a) 無効 off、(b) 細粒 100 %(fines_frac0 = 1、浮遊砂のみ)は off と state.dat
ビット一致、(c) 掃流砂+浮遊砂で fines_frac0 = 0.5: 0 ≤ sf ≤ sd、固体総量
Σhs + (1−λ)Σ(z − z0) と細粒分 Σhs + (1−λ)Σ(sf − sf0) がともに機械精度で 0、
(d) 粗粒のみ(frac0 = 0): hs が厳密に 0 のまま河床は動く、(e) リスタート往復
ビット一致、(f) 直線水路に細粒分を給砂(粗粒河床、浮遊砂のみ): z − z0 ≥ 0
(河床は削られない)かつ sf = z − z0(堆積した分だけが在庫)。無効時ビット一致、
np = 1, 2, 4 一致、-fcheck np = 2。

#### 3.6b 段 5b: 非平衡二次流(未着手。原案のまま)

- **非平衡二次流 `f_secflow=2`**: 強度 I(符号付き。河床近傍の横断流速比
  r と同じ無次元量で定義)の輸送
  ∂(hI)/∂t + ∇·(h u I) = h (I_eq − I)/T_I、I_eq = N* h κ。
  柱状量 h·I を t_state に持ち(s%si。hs と同型の sec_active 通知)、
  移流は swflow_enc の advect_scalar(符号付きで可。§2 で確認済み)、
  緩和は geomorph 側でセル局所の厳密更新(I ← I_eq + (I − I_eq)e^{−dt/T_I}。
  短い T_I で dt を縮めない)。T_I は適応長 L_I = sec_lad·h から T_I = L_I/|V|
  (sec_lad の既定は文献値【要文献照合】。de Vriend 系の λ_sw ≈ 1.2 h ×
  (1/κ_f 比)等)。save_version 更新。段 1 の rsec 配列を I から埋めるだけで
  掃流砂側は不変。
- 浮遊砂への二次流効果、混合粒径(F4)、運動量フィードバックは本案の外
  (comparison.md の位置づけ上も専用モデル領域)。

### 4.3 作業配列・通信・順序

- 追加配列(有効時のみ確保): `flv%fdon`(段 0。セル、帯±ハロ)、
  `flv%rsec`(段 1。同)、`bnk%a`(段 3。同、私有 save)、`s%si`(段 5。
  t_state、save)。エッジ量は既存の `wrk%q` を共用(段 2 の河岸パスは加算)。
- ハロ交換の追加(有効時のみ): fdon(段 0)、rsec(段 1)、z・sd(段 2 の
  崩落前。splash と同じ理由)。いずれも geomorph 更新ごと(水理ステップ
  ごとではない)。段 5 の si は swflow_enc のステップ頭交換に追加。
- `m_geomorph_calc` 内の順序(既存の後ろに足す):
  ```
  eval_splash → calc_debris → apply_splash → [z/sd halo]
  → eval_secflow(rsec 評価+halo。f_secflow>0)          ← 段 1
  → calc_fluvial(ループ 1〔方向補正〕 → 河岸パス〔f_berode〕
                  → 供給制限〔fdon+halo〕 → ループ 2)     ← 段 0・1・2
  → [z/sd halo] → calc_repose(f_repose)                   ← 段 2
  → calc_fixation(a の更新。f_fixation)                   ← 段 3
  → calc_suspend → calc_wash → calc_creep → …(既存)
  ```
  河岸パスと供給制限を calc_fluvial の内側に置くのは、同じ `wrk%q` を
  1 回のループ 2 で集計し保存則を 1 箇所で閉じるため。
- collective の判定(f_* の有無・配列確保)は全ランク同一(§5)。
- OpenMP: 各パスは既存と同じ owner-compute の並列 do。曲率・勾配の近傍
  読みは時刻 n の配列(ハロ交換済み)だけを読み、書きは別配列(rsec, fdon,
  wrk%q)なので競合しない(§28.2 の教訓)。

### 4.4 既存機能との整合

- fn_width・fn_channel(壁付き)との併用は蛇行計算では想定しない(解像
  河道が前提)。併用時の挙動は「補正後の流砂に frw・fwd を乗じる」だけ。
- f_debris との併用: 流砂方向補正は f_fluvial の中なので無関係。河岸侵食は
  f_debris 下では無効(土石流の河岸は E-D が担う)。
- gwflow 併用時の容量引き渡し(§19.2)は z・sd の共動更新に自動で乗る。
- BMI(§76): rsec・fdon は作業量なので非公開。段 5 の si は状態量として
  機能依存変数表に載せる。
- restart: 段 0〜2 は無状態(リスタート往復ビット一致は既存検定で十分)。
  段 3・5 で save 形式が変わる(契約 5・§7)。

## 7. 要合意事項(実装前に決める)

1. **段階順序**(§0 の表)。特に「段 0 を独立の挙動変更コミットとして
   最初に行う」こと、「段 3(定着)は段 2 の結果待ち」にすること。
2. **方向補正の定式**: 非正規化の長谷川型 q⃗_b = q_b(t̂ + r n̂ − γ∇z) を
   採る(正規化形は採らない)。
3. **流線曲率は流速場から内部導出**(§0-12 の例外。理由: 河道が動く)。
   平滑化は入れず、sec_vmin・sec_rmax の二つのガードで始める。
4. **河岸エッジの掃流遮断を既定挙動にする**(f_berode の有無によらず)。
   reference に差が出たケースは目視確認を経て更新する。
5. **二次流強度の受け皿**: 平衡(段 1)は geomorph 私有の作業配列、
   非平衡(段 5)は t_state の柱状量 s%si(hs と同型)。
6. **namelist 名**: berode_*(堤防 bank_* との衝突回避)、f_repose、
   f_fixation、f_secflow、fluv_slope。
7. **係数の扱い**: N*(sec_nstar)は namelist に出す、μ_s・μ_k は原式固定。
   既定値は文献照合の上で §62 方式(採用値を表示)。
8. **文献照合の責務**: §19.8 の原則どおり、N*・μ_s・μ_k・適応長・定着時間の
   既定値は原著(Engelund 1974、長谷川 1981、Nays2DH Solver Manual v4、
   de Vriend 1977/Struiksma ら 1985)で確認してからコードに入れる
   (記憶からの埋め込みはしない)。
9. **決定後の正本**: developer.md に新 §(「蛇行・河岸侵食・流砂方向補正」)
   を起こし、本書は段階ごとに消し込む。利用者向けは users_guide/geomorph.md
   の掃流砂節に「方向補正」「側岸侵食・崩落」の小節、sediment.md に式。
